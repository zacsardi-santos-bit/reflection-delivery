I'm hitting spurious validation errors in the tensor comparison debug utility I use for distributed model inference, and it's basically unusable in any mixed-parallelism setup. The problem is data parallelism. Since DP just splits the batch across workers instead of sharding a tensor dimension, it gets handled upstream before anything reaches the comparison logic, but the validator has no clue about that and keeps yelling that the data-parallel axis is "undeclared" whenever I combine it with tensor parallelism or context parallelism. It's intentionally excluded from the comparison, so it shouldn't be complaining at all. What I want is for the tool to recognize when a data-parallel axis has been filtered out upstream, skip validation for it, and just not emit any plan for that axis while still producing plans for the genuinely sharded axes.

There's a related thing too, oh and this one's annoying. Some sub-parallelism axes are mathematically derived from a parent axis, like the attention-specific or mixture-of-experts-specific variants of tensor parallelism where the rank is always determined by the parent tensor-parallel rank. They don't need separate declaration, but the validator treats them as independent undeclared axes and errors out anyway. I want it to automatically detect that a candidate axis is uniquely determined by a declared parent and treat it as implicitly handled instead of raising. Genuinely independent undeclared axes (ones not dependent on any declared parent and not filtered by the upstream DP pass) should still raise the validation errors like before, don't loosen that.

Also the parallel axis enumeration needs extending to cover the data-parallel axis plus the various attention-specific and MoE sub-axis variants so I can actually reference them when configuring these mixed setups. Net effect I'm after: DP combined with tensor and/or context parallelism works, and tensor parallelism together with dependent attention or MoE sub-axes works, across the full range of real multi-dimensional parallel configs.
