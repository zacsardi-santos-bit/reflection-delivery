I'm working on Presto's file-based security access control and I need to add schema-level ownership rules. Right now when someone tries to create, drop, or rename a schema the system only checks whether they have full access to the containing catalog, so there's no way to say "this user can only manage schemas matching this pattern" or "this schema is protected and nobody can touch it." That makes the catalog the only real security boundary, which kills any multi-tenant schema governance inside a single broadly accessible catalog.

What I want is to extend the JSON config format to support a section for schema ownership rules. Each rule should be able to match on a user identity (regex pattern) and a schema name (regex pattern) and carry an ownership flag marking the combination as owned or not owned. Rules get evaluated in order, first match wins, so an admin can drop a blocking "not owner" rule at the top to protect a specific schema from everyone, then list permissive rules below for regular users. That explicit not-owner flag needs to block access even for otherwise privileged users as long as it sits before any permissive rule.

When schema rules are present, use them for all three ops (create, drop, rename). If no rule matches the requesting user and schema combo, deny access. For renames specifically the user has to count as owner of both the old schema name and the new one. And when there aren't any schema rules configured at all, fall back to the existing catalog-level access check so we keep backward compatibility. Also the schema rules work alongside the existing catalog rules, a user still needs catalog-level access before schema ownership even gets checked.
