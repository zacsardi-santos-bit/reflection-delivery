I'm building long-running agentic loops with some Anthropic models and I want to hand the model a loop-wide token budget so it can pace itself and wrap up gracefully as the budget runs low. Anthropic has a task budget feature in beta where you tell the model its total token allowance for the whole task (thinking, tool calls, tool results, output, all of it), but right now there's no way to pass that through our model settings and I really don't want to be juggling the required beta headers by hand.

What I want: let me specify a token budget config in model settings with a total budget, and optionally a remaining budget for tracking spend client-side across multiple requests. When I set a budget, flip on the required API beta header automatically for me. It should also compose cleanly with the existing effort settings so both land in the same output config object we send to the API. If I try this on a model that doesn't actually support it, raise a clear descriptive error rather than letting it slip through.

There's a tricky conflict I need caught before the request goes out. If I set a remaining-budget value while server-side context compaction is in play, that combo is incompatible because the server tracks the budget itself, so reject it early with a descriptive error. And this check has to fire not just when compaction is explicitly configured for the run, but also when the message history already contains a compaction summary, since that implicitly triggers server-side compaction too.

Oh and one more annoyance: when the same sampling parameter shows up in both the main settings and the extra body overrides on models that don't support those params, I keep getting separate warnings. I'd rather have a single deduplicated warning listing all the unsupported parameters together. The wiring for this lives around the Anthropic model settings and request-building code, so weave the budget config, header toggle, and validations in there.
