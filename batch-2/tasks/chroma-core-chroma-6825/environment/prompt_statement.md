I'm building out a sparse vector similarity index in our Rust index layer and right now there's just nothing there for it. The idea is documents come in as sparse weighted vectors, so each doc only has non-zero weights on a handful of dimensions, and I want fast top-k similarity lookups against a query vector. This shows up all over retrieval and search work, and without it callers would have to scan every doc on every query which obviously doesn't scale.

What I need built: an index that takes a collection of docs, each a list of (dimension, weight) pairs, and lays them out as per-dimension posting lists in a block-based file format. Weights get stored as 16-bit floats to keep things compact, so scores will drift a tiny bit from exact 32-bit math and tests should tolerate that at tied boundaries, that's expected. For dimensions that span multiple blocks I want a per-dimension directory recording max offset and max weight per block, kept under a separate key prefix from the actual data blocks, so we can do max-score pruning and skip whole blocks when their best possible contribution can't beat the current top-k heap.

Incremental updates matter too. I want to fork an existing snapshot, apply additions, deletions, and per-doc weight updates, and commit a new snapshot without rewriting the untouched parts. The suffix-rewrite trick is that for each dimension only the blocks at and after the first affected block need rewriting, earlier ones carry over as-is.

Queries take a sparse query vector and return the highest scoring docs with scores sorted descending, and they need document filters, an allow-list mode (only these docs) and a deny-list mode (exclude these) done through a signed bitmap. Oh and I want a cursor abstraction over the posting list blocks with methods to advance to a target offset with mask filtering, compute the max weight in an offset window, accumulate dimension scores into a flat array over a window of offsets, and score a specific set of candidate docs.

Please handle the edge cases cleanly: empty indexes, dimensions not in the query, k bigger than the number of matches, everything filtered out by the mask, zero-weight entries, and docs with tons of dimensions.
