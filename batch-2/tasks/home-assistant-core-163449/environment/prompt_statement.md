I'm building a Home Assistant integration for Zinvolt smart balcony battery storage systems and I need it from scratch since there's no way right now for folks to monitor their Zinvolt battery inside Home Assistant. I want users to add it through the standard guided config flow by entering their email and password, and once auth succeeds I want the integration to discover the user's battery and register it in the device registry keyed by the battery's serial number with manufacturer name "Zinvolt".

Also I need a sensor that reports the battery's current state of charge as a percentage. It should be a diagnostic entity, its unique id should be the serial number plus a fixed sensor-specific suffix, and the displayed name should be "Battery" (derived from its device class).

The config flow needs real error handling too, so authentication failures, connectivity problems, and unexpected errors each surface a different error message on the form so the user can fix their credentials and retry without losing what they typed. Oh and if someone tries to add the same account twice, detect that duplicate and abort gracefully. The config entry's own unique id should come from the authenticated user's identity embedded in the access token the service returns.

Wire this up with the usual integration layout under `@homeassistant/components/zinvolt/`, so the config flow logic in `@homeassistant/components/zinvolt/config_flow.py`, setup in `@homeassistant/components/zinvolt/__init__.py`, and the state of charge sensor in `@homeassistant/components/zinvolt/sensor.py`. The whole point is Zinvolt battery users want to see their energy storage alongside the rest of their home automation data.
