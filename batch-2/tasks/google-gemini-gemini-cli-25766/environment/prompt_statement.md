I'm poking at the plan mode stuff in our CLI and the file path handling is kind of a mess. Right now when the AI writes or edits a plan file it has to give the path relative to the workspace root, so it has to know to stick the plans directory prefix on the front, which is awkward and easy to get wrong. I want the AI to just hand over a filename, or a nested subdir path inside the plans directory, and the tool figures out where it actually lives. So paths for plan ops should be treated as relative to the plans directory itself, not the workspace root. Nested subdir paths need to work too, and if the parent dirs don't exist yet they should get created automatically.

Also, when the AI gets its instructions in plan mode, the system prompt that tells it where to write plan files currently shows the full absolute path to the plans dir on my machine, which is noisy and leaks local filesystem structure. I'd rather it show the relative path from the project root to the plans directory instead.

Oh and the path traversal security check (the thing that stops writes escaping outside the plans directory) needs to keep working with these relative paths, and when it does reject something the error message should report the relative path, not the resolved absolute one.

Last thing, actually the root cause of a bunch of this: our app config object has no way to expose the project root directory, so the relative path computation can't be done consistently in all the spots that need it. That's missing from the config interface and it's breaking stuff. Add a way to retrieve the project root off the config so relative paths can be computed the same way everywhere.
