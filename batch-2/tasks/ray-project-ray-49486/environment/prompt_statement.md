I'm working on Ray's C++ core and want a proper result type that can hold either a valid computed value or an error `Status`. Right now functions that might fail lean on output params or separate error-code checks or other ad-hoc patterns, and it's inconsistent all over the place. I'd like a generic wrapper (think the classic "result type" pattern from other C++ systems) so a function can just return either the value or the error, and callers handle both cases cleanly.

So the wrapper needs construction from either a value or an error status, plus copy and move semantics, and safe value access. It should let callers check whether it holds a value or an error and retrieve the value safely. I want equality comparison too, so two wrappers holding equal values compare equal, and two error wrappers with the same error code compare equal. Also a "value or default" fallback for when there's an error. And chaining, one variant that applies a function to the value when it's successful and just passes the error through otherwise, and another that applies a function to recover from an error and passes the value through when it's fine. Oh and it should allow implicit conversion between compatible types in a class hierarchy, so a result holding a derived type can go into a result holding a base type.

On top of that I want a small shared test utility header giving macros to conveniently assert that a `Status` or a result is successful in test code, and wire up the corresponding build targets so everything actually compiles and links.
