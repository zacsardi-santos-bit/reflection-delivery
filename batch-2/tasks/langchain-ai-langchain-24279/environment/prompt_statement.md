I'm building out our tool-calling layer and hit a gap around arguments that my app supplies at runtime, stuff like a user ID or session token that the model should never generate. Right now those args just show up in the schema we hand to the model, so it happily tries to fill them in with garbage values, which is exactly what I don't want. I need a first-class way to mark an argument as injected so the framework knows to hide it from the model but still track it everywhere else.

What I'm after is a dedicated annotation I can slap on specific tool arguments to say "this one comes from the application at runtime." When an arg is marked like that, the schema used for model tool-calling should automatically drop it from both the properties and the required list so the model literally never sees it. But the full input schema that the app itself uses should still include everything, injected args included. And when I convert that tool-calling schema into an OpenAI-compatible function description, the injected args need to be absent from the parameters there too.

The tool itself still has to work normally when my app invokes it directly and passes the injected value in, it should accept and process it fine. But if I call the tool without providing a required injected argument at all, it should raise an appropriate error rather than silently doing something weird. Oh and this annotation needs to behave the same whether I define the tool with the decorator pattern or by subclassing the base tool class directly, and it should work whether or not I supply an explicit schema class. Basically I don't want to end up maintaining two separate tools or hand-hacking schemas just to keep the model from touching values the application controls.
