## Description

When building tools for language models, developers sometimes need certain arguments — like a user ID or a session token — to be provided by the application at runtime rather than generated by the model. There is currently no standardized way to annotate these parameters, so they appear in the schema exposed to the model, which then tries to fill in values it should never control.

## Expected Behavior

- Developers should be able to annotate specific tool arguments as "injected at runtime" using a dedicated annotation.
- When a tool argument is marked this way, the schema used for model tool-calling should automatically exclude that argument from its list of properties and required fields.
- The full input schema (used by the application) should still include all arguments, including injected ones.
- When the tool-calling schema is converted to an OpenAI-compatible function description, injected arguments should be absent from the parameters.
- The tool should still accept and process injected arguments when invoked directly by the application.
- Attempting to invoke the tool without providing a required injected argument should raise an appropriate error.

## Why This Matters

Without this mechanism, developers must manage two separate tools or hack the schema by hand to prevent the model from generating values that should be controlled by the application. A first-class annotation keeps tools clean and ensures the correct schema is automatically used in every context — both when calling the model and when executing the tool.
