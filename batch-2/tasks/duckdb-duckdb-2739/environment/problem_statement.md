I'm hacking on DuckDB and I want a built-in table function, no args needed, that spits out sample data covering every data type we support. The idea is one column per type and exactly three rows: first row has the minimum representable value for each type, second row has the maximum, third row is all NULLs. Right now there's no clean way to write tests that hit all types at once, everybody hand-rolls per-type queries and coverage ends up spotty, so this'd be a single fixture for storage round-trips, compression checks, and type-correctness stuff.

Columns need to span the whole spectrum: all integer widths signed and unsigned, the date and timestamp variants including timezone-aware ones, floating point, decimals at several precision levels, UUID, interval, varchar, blob, enum types of different sizes, lists, nested lists, structs, structs containing arrays, arrays of structs, and maps.

Also, while I'm in here, the existing helpers that compute min/max representable values are just wrong for a bunch of types and I need those fixed. The minimum date and minimum timestamp aren't actually the smallest representable values in DuckDB's format, the maximum time is off by one, and max boolean is returning false when it should be true. Decimals are broken too because they compute min/max off the underlying integer bounds instead of the decimal-precision-aware bounds, so those need to respect precision. Enum min/max should return the first and last enum entry by index, not the underlying integer min/max.

Once the function plus these fixes are in, I want to be able to create a real table from its output, store it to disk, restart the database, and read back byte-for-byte identical data. That's the whole point, it makes this thing usable as a comprehensive fixture. So the persisted data has to survive a full restart unchanged.
