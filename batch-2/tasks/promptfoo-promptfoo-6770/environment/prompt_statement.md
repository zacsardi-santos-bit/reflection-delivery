I'm trying to eval AI agents built on n8n workflows using promptfoo and there's no native way to point at an n8n webhook as a provider, so I'm stuck wiring up the generic webhook provider by hand every time, which doesn't understand n8n's response shapes or quirks. I want a dedicated n8n provider where I specify the webhook URL as the provider path behind a workflow-platform prefix (like an n8n: prefix before the URL) and promptfoo just routes prompts to it.

The tricky part is these workflows return responses in a bunch of shapes and it needs to handle all of them: some return a direct output field, some a response field, some nested message content, and some an array of items with JSON payloads. Tool calls coming back from agent workflows show up in either of two schema formats these workflows may use, and I want those extracted and surfaced as structured metadata on the response. Session IDs from multi-turn workflows should get exposed on the response too so multi-turn eval strategies can scope conversations right.

Config-wise I want to set the HTTP method, custom request body templates with variable and env var interpolation, and custom headers. For POST and other non-idempotent methods, retries should be off by default so I don't accidentally trigger a workflow twice and re-deliver side effects. Also the provider's display id should be a safe fingerprint, not the raw webhook URL, so creds baked into URLs don't leak into logs, result files, or the web UI. Two providers with the same URL but different config should get distinct fingerprints, but rotating an API key in a header shouldn't change the fingerprint (so historical results don't fragment). And webhook URLs, credentials, and prompt/response content should never hit debug logs, only that fingerprinted id.

Oh and there's a related security thing that hits all providers, not just this one: when HTTP requests fail and get retried, or when connection errors happen with a proxy URL set, the full URL including basic-auth credentials and sensitive query-string tokens shows up in the debug logs. I want those stripped before anything's written to logs while keeping the hostname visible for debugging, since we share debug logs in bug reports and CI.
