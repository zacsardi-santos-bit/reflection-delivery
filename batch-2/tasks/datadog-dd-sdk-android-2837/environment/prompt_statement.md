I'm in the RUM SDK and need to move how we attach context metadata onto uploads. Right now the upload URL only adds a `tags` query param when there's retry info to report, and the actual context attributes (service name, app version, SDK version, environment, build variant) are baked into every single event payload instead. That's redundant and it means the backend can't reliably filter RUM events by these standard dimensions at the transport level, plus it bloats every event with duplicated data.

What I want is for the request builder to always emit a `tags` query parameter on the upload URL, not just conditionally when retry tags exist. That param should always carry the four standard context tags (service, version, sdk_version, env style attributes pulled from the SDK context), and it should also include the build variant as a tag but only when the variant is non-empty (omit it when empty). Retry-related tags (retry count, last failure status) should still get appended after these context tags when applicable, so ordering matters, context first then retry.

As part of this I want the per-event tags field that used to hold this same duplicated context removed from all the RUM event types since it's no longer needed. There's also a standalone helper that was responsible for building that per-event tags string, kill that too since the logic now lives in the request URL builder. Moving context tags up to the request URL keeps metadata consistent on every upload even when events get processed or filtered before storage, and it slims down the event data model.
