I'm working on an npm registry proxy that rewrites upstream tarball URLs to point back at itself so clients always pull through the proxy, and I've hit a real problem with how we generate those rewritten URLs. Right now when we rewrite, we ignore the actual filename the upstream declares and instead build a new one by combining the package name and the version string in a predictable pattern. That falls apart for packages with non-standard naming, like some older or forked packages that use zero-padded or otherwise weird tarball filenames that don't match the declared version. We "normalize" the name and clients end up pointed at a URL that doesn't exist upstream, so installs break.

What I want is for the proxy to preserve the exact tarball filename from each version's distribution metadata so non-canonical upstream names survive into the client's lockfile and the cache instead of getting reconstructed. Also, if the upstream URL has a query string or a URL fragment (think signed or expiring CDN URLs), those need to get stripped so only the path basename shows up in the rewritten URL, otherwise time-limited URLs leak into lockfiles and the public route stops being stable.

For this I need a small helper that pulls the bare filename out of a URL, dropping any query string or fragment, and returns nothing when there isn't a usable filename, like when the URL ends in a trailing slash pointing at a bare directory. When that helper gives back nothing for a version's declared tarball URL, fall back to constructing a conventional filename from the version info rather than passing through something unusable.

Oh and there's a safety thing too. If two different versions in the same package declare the same tarball filename, it's impossible to know which version's integrity check applies to the downloaded bytes, so the proxy has to reject requests for that filename outright rather than silently binding the wrong version's checksum to the response. That closes off a subtle integrity bypass where bytes from one version could get verified against another version's checksum.
