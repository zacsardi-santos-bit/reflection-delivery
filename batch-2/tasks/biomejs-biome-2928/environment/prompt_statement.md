I'm hacking on the GraphQL parser in Biome and it doesn't handle object type extension statements yet, which is a real problem because federated and composed schemas lean on these all the time to add fields to an existing type, hang directives off it, or declare it implements more interfaces. Right now any document with one of those just fails to parse, so formatting, linting, all of it breaks for a huge swath of real-world schemas.

What I want is for the parser to accept every valid shape of this thing: extending a type with only a fields block, only directives, only an implements clause, and all the combos (implements plus directives, directives plus a fields block, and all three together). Each of these should build a properly structured node carrying the extend keyword, the type keyword, the type name, an optional implements clause, a directives list, and an optional fields definition block.

On the error side, if someone writes an extension but includes none of the three (no directives, no implements, no fields), so basically an empty extension, I need a clear diagnostic saying at least one directive, implements clause, or fields definition is required. And if there's a fields block but the opening brace is missing, report that the brace was expected, point at the unexpected token found instead, and suggest removing it. In both cases don't bail, recover and keep parsing the rest of the document. The parser work lives around `@crates/biome_graphql_parser/src/parser`, oh and the syntax node definitions in `@crates/biome_graphql_syntax` too.
