## Description

URLs that contain nested parentheses — such as those generated by analytics or search tools that encode complex query state directly in the URL — are being clipped to an incorrect, shorter form when displayed as clickable links in the code editor. The link detection mechanism stops too early when it encounters what it thinks is the end of the URL, leaving unmatched open parentheses behind and producing a broken or incomplete link.

## Expected Behavior

- When a URL contains nested or multiple groups of parentheses, the clickable link in the editor should span the full URL, with all open parentheses properly closed.
- If extending the URL would require crossing a whitespace character, the link should stop at the whitespace (not continue past it).
- If the next available character in the text would cause the closing parentheses to outnumber the opening ones, the extension should also stop rather than over-extend.
- Deeply nested parentheses structures (multiple levels of nesting) should be handled correctly, not just simple single-level cases.

## Why This Matters

Developers frequently paste long, complex URLs into API request fields in Bruno. When those URLs contain nested parentheses, the editor currently makes an incorrect portion of the URL clickable, forcing the developer to manually copy-paste the full URL instead of simply clicking it. Proper parenthesis-balancing logic would make these links work correctly out of the box.
