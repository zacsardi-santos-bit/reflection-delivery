I'm working on the link-aware bits of Bruno's code editor and I keep hitting a bug where URLs with nested parens get chopped off when they're rendered as clickable links. Think of the long query URLs that tools like Kibana or other analytics/search stuff spit out where they encode complex query state right in the URL. The detection stops too early the moment it thinks it found the end, so it leaves unmatched open parens behind and the link points at an incomplete, broken address. Devs paste these into API request fields all the time and right now they have to manually copy-paste the whole thing instead of just clicking, which is annoying.

What I want is a utility function that takes the initially detected (possibly truncated) URL, the full line of text it came from, and the index/position where detection stopped, and then walks the URL forward through the line extending it until all open parens are properly closed. It should stop at any whitespace character, and also stop if the next character would make closing parens outnumber opening ones (so it doesn't over-balance when the URL is just wrapped in surrounding prose like "(see http://foo/bar)"). It returns an object holding the corrected URL string.

Make sure it handles the edge cases: a URL that's already balanced so no extension is needed, a URL sitting inside parens in the surrounding text where extending would over-balance, and deeply nested paren structures with multiple levels of nesting, not just simple single-level ones.
