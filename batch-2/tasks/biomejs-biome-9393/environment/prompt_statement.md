I want to add a new lint rule to our JS/TS analyzer that enforces putting lifecycle hooks before test cases in the same block. The idea is readability: when someone opens a test file, hooks that do setup and teardown (think beforeAll, beforeEach, afterEach, afterAll and the like) should sit at the top of a describe block, before any actual test cases, so you immediately see what runs around each test instead of scanning through a pile of test definitions to find the setup.

Right now the linter doesn't catch this, so people accidentally drop a hook below a test and the setup/teardown flow becomes invisible. So the rule should flag when a lifecycle hook shows up after a test case in the same scope, and that scope is either a describe block or the top level of the file. Each nested describe block is its own independent scope, so a hook placed correctly in an outer block doesn't excuse a misplaced hook in an inner one, and vice versa, ordering gets checked at every nesting level independently.

Only flag hooks that come after at least one test. Hooks that come before any test are fine. If a block has both a valid hook (before a test) and an invalid one (after a test), only the invalid one gets flagged. Each misplaced hook should produce its own diagnostic that points at both the hook and the test case it incorrectly follows, with a message suggesting the hook be moved above all the test cases in the block. Oh and it needs to recognize hooks from popular JS testing frameworks plus the equivalent setup/teardown hooks from built-in test runners. Put the rule in the nursery group.
