I'm cleaning up how we handle impression-level first-party data during an auction in the prebid server and the current approach is bugging me. Right now the auction code has inline logic that strips contextual data off impressions when a bidder doesn't have FPD permission, and it's fragile and not composable at all. I want to move that into the existing first-party data resolver class as a new method that takes three things: the original impression extension, a partially-constructed updated extension, and a boolean saying whether FPD is permitted for that bidder. The method figures out what the context section and data section of the result should be. When FPD is permitted it merges contextual data (the data sub-object nested under context) with the top-level impression data, so if both are present as objects their fields get combined into the result's data field. When FPD isn't permitted it strips the data sub-field out of context and omits the top-level data entirely, and if stripping that leaves context empty then context itself gets dropped too. Important bit: it should deep copy the data nodes rather than sharing references, and it needs to tolerate non-object values (like arrays) for context or data by passing them through unchanged instead of crashing or corrupting them.

Also there's a bug in the user data normalization step. If user data comes in as a non-object (say an array) the normalization currently tries to process it like an object, which is wrong, it should just skip normalization in that case.

Last thing, the Rubicon adapter picks the ad unit code from impression data to populate targeting, and the priority order needs updating to check both contextual data and top-level impression data in this sequence: first the GAM adserver slot from the contextual data adserver entry (only when the adserver name is "gam"), then the GAM adserver slot from the impression-level data adserver entry (again only for "gam"), then the prebid ad slot field from contextual data, and finally the prebid ad slot field from impression data. Non-GAM adserver names shouldn't produce an ad unit code at all. This keeps contextual and impression-level FPD in their distinct standard locations while giving the auction a clean way to decide what each bidder is allowed to see.
