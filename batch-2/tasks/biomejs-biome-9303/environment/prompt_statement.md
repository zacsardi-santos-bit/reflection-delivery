I keep hitting an idempotence bug in the JavaScript formatter around switch statements with trailing comments on case clauses. Here's the setup: I've got a switch where several fall-through cases each have a trailing line comment (you know, annotating the case value on the same line), and the last of those fall-through cases is followed by a block statement. First format pass looks totally fine, comments stay put on their case lines. But if I run the formatter a second time it moves one of those trailing comments off the case line and down into the opening of the block below, so the output changes between pass one and pass two. That breaks format-on-save because my code gets rewritten every time I save, which is really disruptive and not what anyone expects from a formatter.

What I want is for trailing comments on a case clause line to always stay attached to that line after formatting, even when the case or a whole fall-through sequence is followed by a block statement, and I want the output to be stable no matter how many times I run it. Idempotence is kind of the whole point of a formatter, running it repeatedly should never change the code. So formatting the output a second time needs to produce exactly the same result as the first pass. Trailing comments on cases are a super common pattern so this needs to be rock solid.
