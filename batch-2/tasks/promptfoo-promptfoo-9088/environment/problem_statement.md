I'm cleaning up the Media Library section and it's kind of a mess on phones and narrow browser windows. First the layout stuff: the page header doesn't stack vertically on very narrow screens, it just overflows instead of wrapping, so I want it to stack and then flip to a side-by-side layout once we hit a small viewport width threshold. Same deal with the selection controls toolbar and the header action area shown during a bulk download, those should wrap to new lines when there's not enough horizontal room. Error messages in the page use a fixed side-by-side layout that breaks small, so make those responsive (stacked then side-by-side too).

Accessibility on the type filter controls is off. The filter labels are fully hidden at small sizes which means screen readers lose them, so hide the text visually but keep it readable to assistive tech, and the currently selected filter needs to expose its selected state through the right aria attribute so it gets announced.

The audio preview overlay is buggy, it intercepts pointer events even while invisible which blocks clicks behind it, so it should be fully non-interactive when hidden and still show reliably on hover. And on touch-only devices it's always invisible so previews can never fire, it should always be visible and interactive there.

On the media cards, clicking anywhere on the preview image should navigate to the detail view, right now only a tiny invisible overlay catches the click. Also the video play button accidentally triggers the card navigation, it shouldn't. And the card download button is too small to tap on touch, needs to meet minimum touch target size.

The detail modal has problems too, its inner container can't shrink below its content so it overflows on narrow screens (let it shrink), the action buttons (close, download, copy permalink) are too small for touch and need to hit minimum target sizes, and there's no dedicated mobile action area for download and permalink copy separate from the desktop footer, so add one that's mobile-only. Files live under the Media Library components, roughly `@components/media`. Point is it should just work across screen sizes and input methods.
