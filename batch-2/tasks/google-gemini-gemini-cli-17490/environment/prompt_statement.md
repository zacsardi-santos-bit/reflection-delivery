I'm cleaning up our CLI tool that enables and disables feature types across config scopes (per-user settings and per-workspace settings). Right now the agent toggling and skill toggling live in separate utility files and they're basically copy-paste of each other: iterate the relevant scopes, check if a change is needed, apply it, return a structured result saying which scopes got modified and which were already how we wanted them. Every time we add a new toggleable feature we duplicate all that boilerplate again, which is annoying.

What I want is a shared generic toggle utility that both agents and skills (and future feature types) delegate to. The caller hands it a strategy object with methods for checking whether a given scope needs enabling, performing the enable, checking whether a scope is already explicitly disabled, and performing the disable. The generic bit owns the scope iteration, the result object construction (including the file path of the settings file for each affected scope), and the error handling like being asked to disable in a scope that isn't valid for persistent settings.

For enable, iterate over both the user and workspace scopes and apply the change to any scope that needs it. For disable, target one specified scope and either report a no-op if it's already in the desired state, actually apply the change if needed, or return an error when that scope isn't a valid persistent settings scope. And the results need to clearly distinguish scopes that were actually modified from scopes that were already in the desired state, plus surface whether the whole thing was a no-op, a success, or an error. The agent and skill utilities should end up as thin strategies on top of this so adding a new feature is just implementing the four checks/actions rather than re-deriving the iteration and result plumbing.
