I've got a nested editor setup, a parent editor with a child editor inside it, and command delegation is just broken. When I dispatch a command from the child, the parent editor's command handlers never fire. The command gets swallowed by the child and never bubbles up, so anyone who registers command listeners on the parent can't see events that started in a child. That kills keyboard shortcuts, undo/redo integration, and basically any cross-editor coordination where you'd want to catch a command at the parent level.

What I want is proper propagation through the hierarchy. After the child runs its own handlers, the command should flow up to the parent editor too. There's a timing wrinkle though: if the parent's idle (not mid-update) when the child dispatches, the whole thing should be synchronous, both child and parent listeners finish before the dispatch call returns. But if the parent's actively in the middle of its own update at the moment the child dispatches, the child's handlers still run immediately, and the propagation to the parent gets deferred until the parent's current update wraps up. Don't drop it, just wait.

One more detail on context: when the parent handler runs for a command that originated from a child, it should receive the child editor as the originating editor, but the active editor context inside that handler should reflect the parent editor, not the child. Originating is child, active is parent.

Can you implement this command delegation in the nested editor extension so commands flow child up to parent the way you'd expect from a real editor hierarchy?
