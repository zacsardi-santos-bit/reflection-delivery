I'm building out a memory pool configurator for hybrid sliding window attention models and I keep hitting the case where we already know the max number of concurrent requests but there's no configurator that uses that to compute a tight token cap for the sliding window cache. Right now we either lean on a ratio-based heuristic or just don't account for the precise per-request footprint, so we're either over-provisioning and wasting memory or under-provisioning and risking OOM in production. I want a new specialized configurator that, when a maximum running request count is explicitly set, sizes the sliding window pool from the actual worst-case per-request token footprint instead of guessing.

The footprint per request should cover the sliding window size itself, plus an eviction buffer proportional to how often out-of-window tokens get flushed (the eviction interval), plus page alignment, plus whatever extra decode tokens speculative decoding needs. For spec decode without overlap scheduling, compute the decode allocation from the steps and draft token counts with page alignment, and when overlap scheduling is on, double that allocation since we've got two decode passes running at once.

Also it needs to handle disaggregated deployments right. Decode-only nodes should skip the global prefill budget entirely. Decode nodes that pre-allocate slots for in-transfer requests should charge only window size plus page size for those slots, not the full trailing footprint with the eviction buffer. Prefill and standard nodes should include a global budget for in-flight chunked prefill tokens, one chunk's worth when overlap is off and two when it's on.

Oh and the factory function that picks the configurator should auto-select this new one whenever the max request count is explicitly set and the model is a hybrid sliding window attention model, otherwise fall back to the existing configurator. The whole point is precise, safe allocation for bounded-concurrency deployments so we're not guessing with speculative decoding or disaggregated setups.
