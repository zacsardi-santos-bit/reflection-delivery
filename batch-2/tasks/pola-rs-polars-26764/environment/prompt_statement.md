I'm hitting a nasty file size problem when writing Parquet. If I have a string column with a giant value in it, like a single row where the string is a million characters long, the output file balloons to megabytes even though the actual data compresses fine. I dug into it and it's the column statistics metadata, the min and max values we store per column chunk include the full untruncated string, so that's what's bloating everything.

What I want is for us to automatically truncate the stats we store for string and binary columns down to a sensible max byte length, 64 bytes by default feels right. For text (Unicode) columns the truncation has to respect character boundaries so the stored values stay valid UTF-8, don't split a multi-byte char partway through. So the truncated min should be the longest valid prefix that fits under the limit, and the truncated max should be that same prefix but with its last character incremented so it's still a valid upper bound (greater than or equal to the real max). For raw binary columns truncation happens at the byte level, and the max bound comes from incrementing the last byte that isn't already at its maximum value. Oh and short values that already fit under the limit should just be stored as-is, no changes.

Also I want to be able to control this, so an environment variable that lets me set a custom truncation length, or disable truncation completely by setting it to zero for the cases where I actually need exact stats. The point is statistics are still valid bounds after truncation (just less precise), so correctness holds and the files get way smaller, which is standard practice in Parquet implementations anyway.
