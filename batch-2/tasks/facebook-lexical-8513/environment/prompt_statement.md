I'm cleaning up two things in the Lexical editor codebase and could use a hand. First off, our shared test utilities have a pile of hand-rolled mock classes standing in for native browser stuff like keyboard events, clipboard data transfer objects, and clipboard/drag-and-drop events. We only wrote those because the test env didn't support these APIs natively, but they've gone stale and diverge from real browser behavior in subtle ways that can actually hide bugs. I want them gone entirely from the shared test util file, and instead register lightweight polyfills in the global test setup so the native constructors just work in tests. So the clipboard data, clipboard event, and drag-and-drop event APIs all need polyfills registered globally, and after that every test should be using the real browser constructors directly, same API surface as production, no more mocks.

Second thing, I want a paste-to-link feature in the link extension. When someone selects text in a normal paragraph and pastes a URL, that selected text should get wrapped in a hyperlink pointing to the URL (like Google Docs or Notion do it). Oh and this has to be context-aware, actually important: if the selection is inside a code block, the paste should just be treated as plain text, don't create any link node, leave the code block unchanged. Code isn't prose so wrapping it in a link would be wrong. So pasting over paragraph text makes a link with the right URL, pasting over code-block text does nothing linky.
