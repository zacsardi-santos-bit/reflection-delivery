I'm poking at tinygrad's device management in `@tinygrad/device.py` and want to simplify how the default device gets picked. Right now it's derived from a context variable at runtime, which means I can't just assign to the default device directly, I have to wrap everything in a context manager block to temporarily change the active device. That's way more indirection than I want for this.

Two concrete things bug me. First, switching or overriding the default should be a plain attribute set, so I can stash the original, assign a new default, do my thing, and put the old one back without any context magic. Second, the deprecation check for old-style device env vars (like when someone sets a device name as its own separate environment variable) currently seems tied to whether the context variable is explicitly present or absent, so the warning doesn't fire reliably. I want that deprecation error to raise on its own whenever an old-style device env var is set, regardless of whether some device context variable is around or not.

So basically: rip out the context-variable-based device switching entirely since it's not needed anymore, make the default device a directly-assignable attribute on the device manager, and make sure it still canonicalizes right, meaning if I set it to a lowercase device name it should come back correctly uppercased when canonicalized. And that deprecation path should just work everywhere now.
