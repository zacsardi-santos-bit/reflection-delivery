I'm hitting a bunch of sandbox problems on Linux and they all trace back to how my host user gets mapped into the container. First off the distro detection is way too narrow, it only knows a handful of distributions so NixOS and Arch Linux (and stuff derived from recognized distros like Ubuntu-based variants) get treated wrong. It should recognize those as supported and use the host user identity inside the container. Also the parser reading the OS identification file (the os-release style file) chokes when the distribution ID value is wrapped in quotes, single or double, which tons of distros actually do, so please strip those quotes and match correctly.

Second thing, when the distro isn't recognized and my host UID doesn't line up with what the sandbox expects, there's just silence, it plows ahead in a broken state without telling me anything. I want a clear warning logged in that case so I know what's going on. Oh but if the host user is root (UID 0) then don't warn, that's fine.

Third, the shell script the sandbox generates to create a matching user inside the container is fragile. It assumes the user-creation tooling always exists, but minimal images (distroless, NixOS-based) don't have it, so check for that first. It also hardcodes a username instead of looking it up dynamically by UID, which breaks when the UID is already mapped to some other name. And when any of that fails it should print an informative error message and exit non-zero instead of just carrying on.

Last one, if my home directory path has spaces or shell-special characters (backticks and friends) it gets embedded unquoted into the entrypoint command, which either breaks the sandbox or opens a shell injection hole, so quote the path properly wherever it lands in the generated shell commands. Without these fixes folks on NixOS or Arch just can't use the sandbox, and anyone with a funky home path hits failures or security risks.
