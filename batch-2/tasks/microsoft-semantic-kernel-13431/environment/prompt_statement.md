I'm working on Semantic Kernel and I keep hitting a gap around what happens when a kernel function returns an image as its result. Right now the framework doesn't handle this consistently across backends, it either crashes or shoves invalid data at a model that can't take multimodal content in tool results, so I want proper support end to end.

First, for the providers that don't support images inside tool call results, meaning OpenAI's chat completion, the Assistants API, and the Responses API, I need those to gracefully substitute a clear, human-readable error message into the tool response telling the model image content isn't supported, instead of throwing an unhandled exception or serializing the image into garbage. And it has to be the exact same standardized error message text reused across all of those backends so behavior stays consistent, don't invent a different string per backend.

For the Gemini backend, which does actually support multimodal content in tool results, when a function returns an image with binary data I want the raw bytes encoded inline and transmitted as part of the tool response. But if the image is missing the actual binary data (say it only carries a URL reference), or if the MIME type is absent, raise a descriptive exception rather than silently emitting malformed output, one clear error for the no-binary-data case and one for the missing-MIME-type case.

Also, the function result processing layer needs updating so that when a function result is an image it's passed through as-is instead of being serialized to a string, that way each backend gets to decide how to handle it rather than the processing step destroying the image data before it ever reaches them. The whole point here is that folks building apps where AI functions capture or generate images should have a reliable way to feed those results back into the conversation loop no matter which provider they're on.
