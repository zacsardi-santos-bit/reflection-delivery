I ran into something annoying with windowed expressions in polars. When I do an `over(...)` and accidentally pass the same column name more than once as a partition key, it just silently accepts it and computes a result off the redundant grouping spec. No error, nothing. That's confusing because grouping by the same column twice is almost always a typo or a real bug in my code, and I'd rather get told about it right away than trust a result that came from a partition spec I didn't actually mean.

What I want is for polars to detect duplicate column names in the partition keys of a windowed expression and raise a clear duplicate-key error. It should fire at evaluation time so I get immediate, actionable feedback about the mistake instead of silently proceeding. The error message needs to make it obvious that the same key got specified more than once so I can go fix the typo.

Obviously windowed expressions with distinct, non-duplicate partition keys should keep working exactly as before, no regressions there. It's only the repeated-column case that should start erroring out. This makes it way easier to trust windowed results and catch accidental repetitions early.
