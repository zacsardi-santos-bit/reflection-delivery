I'm building out evals for an agentic system and right now I can only assert on the final output, which is useless when the agent gets the right answer via a broken or inefficient path. The runs are recorded as distributed traces, spans with attributes that mark what each step was, some are tool calls, some command executions, some searches, others reasoning steps, and I want new assertion types in promptfoo that let me check what the agent actually did along the way.

First thing, before any assertion logic runs I need the raw trace spans normalized into typed steps: tool calls, command executions, searches, reasoning steps, and a generic span fallback for anything that doesn't match. And since trajectories get long, I want them compacted and summarized into something useful to hand to an LLM judge.

Then the assertions themselves. I want to assert a specific tool was used, or explicitly not used, with glob pattern matching on the tool name and count-based constraints (like it was called at least/at most N times). I want to assert tools were called in a particular order, either a loose subsequence (other stuff can happen in between) or an exact sequence. I want to count steps of a given type or matching a pattern and assert that count lands within expected bounds. And I want a goal-success assertion that uses an LLM judge to decide whether the agent actually accomplished its stated goal.

For that goal one specifically, it should render the agent's goal, the trajectory summary, and the final output into a grading prompt and call a judge provider. Oh and it needs to protect the core context vars from being clobbered, if a caller passes extra template vars they shouldn't be able to override goal/trajectory/output by accident. It should support inversion too (checking the goal was NOT achieved), and respect a score threshold when deciding pass vs fail.
