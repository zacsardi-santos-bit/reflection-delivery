I'm building out the GCP Enrichment and Remediation content pack and I need a new automation script that figures out which firewall rules in a GCP environment might be letting in the traffic we're seeing during an investigation. The idea is, when an alert fires on a GCP IP, I've got the port, the protocol, and the VM's network tags handy, and I want to feed those in and get back the rules that could be permitting that inbound traffic from the internet. Right now the enrichment playbook has no way to cross-reference observed traffic against actual firewall rules, so analysts end up eyeballing rules by hand which is slow and error prone during incident response.

So the script should take a GCP project ID, a network URL, a port, a protocol, and optionally the network tags on the target VM instance, then evaluate the firewall rules against that criteria and hand back the names of rules that could be allowing it. It needs to handle a few cases correctly, like rules that allow all protocols, rules matching an exact port or a port range, and rules that restrict to VMs with specific target tags (and also rules with no target tags at all). Oh and it's gotta exclude the stuff that shouldn't match, so disabled rules don't count, rules whose target tags don't line up with the VM's actual tags don't count, and rules covering a different port or protocol don't count either. When it does find matches, I want the output to be a clean readable summary listing those offending rule names so an analyst can glance at it and know which rules may be exposing the VM. Drop it into the GCP-Enrichment-Remediation scripts directory so it plugs into the existing enrichment workflow.
