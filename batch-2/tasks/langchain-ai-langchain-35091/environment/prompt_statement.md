I'm building on langchain-anthropic and I need to add support for running Claude through AWS Bedrock. Right now the library only talks to the Anthropic API directly, but my org requires Bedrock for compliance, regional data residency, IAM-based auth, that kind of enterprise stuff, so I want a first-class chat model class I can import straight from the top level of the package as a drop-in alternative to the existing Anthropic chat model.

It needs the same capabilities as the current one: tool binding, structured output, streaming, and async calls, just routed through Bedrock instead. For creds, I want to be able to pass AWS access key, secret key, and optionally a session token as constructor args (stored securely as secret values) or have them picked up automatically from the standard AWS environment variables. Region should work the same way, pass it explicitly and it wins, otherwise fall back to whatever the environment specifies. Explicit always overrides env, both for creds and region.

Couple more things. It should report itself correctly in LangSmith tracing as a Bedrock-backed provider, not the direct API, and it's gotta be serializable with a stable LangChain namespace so saved chains and agents keep working. Also Bedrock throws a bunch of model name formats at you, plain short names, vendor-prefixed identifiers, and the cross-region inference profile IDs, and I need all of those to resolve correctly to a model profile that carries stuff like the max input token limit.

Oh and I want the credential and client-param plumbing pulled out into a reusable utility module, one function to resolve AWS credentials from optional secret values and another to build the full set of client initialization params, so it's not all tangled inside the model class.
