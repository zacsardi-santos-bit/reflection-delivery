I'm chasing down a bunch of author attribution bugs in how we tag evaluations and it's making a mess in team setups. The core thing I want is a clear resolution hierarchy: if someone's logged into a cloud account, that cloud identity has to win over everything else, environment variables, local config overrides, anything set programmatically. Right now that priority isn't enforced and the cloud user gets ignored, which is bad for auditability when multiple people share evals.

Related to that, I want a way to pass an author through as a suggestion, like when a test suite specifies one (handy in CI). That hint should feed into the author resolution logic so it's used locally, but it still yields to the cloud identity when cloud auth is active. Currently there's no path to pass such a hint at all. Oh and the author field on a test suite config should only ever be a resolution hint, don't persist it directly into the stored eval config.

There's also a nasty regression on import. If I import an eval that someone else originally ran, their author gets clobbered with my current identity, which is wrong, especially when I'm authenticated as a different cloud user. The original author from the imported data needs to be preserved always, no matter who's doing the import.

Last thing, when sharing an eval that already has an author set on the record, the code still goes through the motions of looking up a user email, which is pointless. It should just skip that email collection step when an author's already present. Net goal is evals are attributed correctly no matter how they were run or imported.
