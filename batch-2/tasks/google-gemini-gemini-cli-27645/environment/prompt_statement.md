I'm chasing down some model routing and stats display bugs in our CLI tool and they're all tangled together so I want to fix them in one pass. The core issue is the routing that kicks in when a newer GA flash model gets unlocked via an experiment flag, it doesn't account for how the user authenticated. Right now the logic just uses a single hardcoded GA model string for everybody, which is wrong. Folks authenticating with a standard API key should have flash selections route to the published GA model string, but users coming in through other auth paths need a different model identifier that their backend actually understands, even though it resolves to the same underlying model server-side. So I need the routing to check whether the GA flash model is accessible and branch on the auth method.

Also, and this is important, an API-key user who has access to both the GA model and the preview variant should be able to explicitly pick the preview flash model and stay on it, we can't silently promote their explicit selection to the GA version. That override-respecting behavior is just missing today. All four of the routing strategies that do model classification need this same accessible-check-and-route treatment.

Second thing, the auto mode description should reflect the GA flash model name when the experiment's active and the user has preview access, so it shows what'll actually run.

Third, the usage stats display is leaking raw internal model identifiers. When a session runs on one of these flash variants the stats table and the per-model stats display show a backend string nobody recognizes from the selection menu, I want those translated to the human-friendly published names instead. Otherwise people get confused seeing an unfamiliar identifier, and the mis-routing for non-API-key users could fire requests at the wrong endpoint and cause errors.
