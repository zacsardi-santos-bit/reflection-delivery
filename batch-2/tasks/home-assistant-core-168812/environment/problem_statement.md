I hit a security gap in the Home Assistant WebSocket auth flow. We've got this "local only" flag on user accounts, the whole point being those users should only be able to log in from inside the local network, but that restriction just isn't being checked when someone authenticates over the WebSocket endpoint. So right now a local-only user can connect from any remote IP outside my network and still authenticate fine through the WebSocket API, which totally defeats the purpose, oh and it means if a remote attacker grabs an access token for one of those accounts they can get in anyway.

I want the WebSocket auth to enforce the same local-only rule that applies elsewhere. So when a local-only user tries to authenticate from a remote (non-local) IP address, they should get rejected with an authentication failure response whose message indicates they can't authenticate remotely. Also that failed attempt from the remote IP needs to be recorded the same way other bad login attempts get tracked, so it flows through the normal invalid-auth handling. And to be clear, a local-only user connecting from a local network IP should still authenticate successfully like normal, don't break that path.

The relevant logic lives in the auth handling for the WebSocket component, around `@homeassistant/components/websocket_api/auth.py`, where the token gets validated during the connection handshake. The local-only determination and remote-vs-local IP check should hook in there before the connection is considered authenticated.
