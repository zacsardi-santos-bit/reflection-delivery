I'm hitting two gaps with MLflow's third-party evaluation scorers, the wrappers we have around external eval libraries. First off they can't be serialized or deserialized at all, which means a configured scorer (which library class it wraps, the metric name, the LLM model it's pointed at, plus any extra constructor kwargs) just lives in memory and can't be saved or shared or reloaded. I want to call the standard serialization method on one of these and get back a dict that captures all of that, then hand that dict to the standard deserialization method and get back a fully working scorer of the correct type with everything restored, model URI, threshold, kwargs, the lot. Oh and if the scorer was given a custom registered name, that display name needs to survive the round trip too.

The deserialize path has to be careful since it's reconstructing objects from a payload, so only reconstruct from a known set of trusted modules, and reject anything missing the class or metric name fields. Give clear errors when the underlying library isn't installed, when the class can't be found in the module, when the stored metric name doesn't match what the class actually declares, or when instantiation blows up for any reason. Also don't let a payload combine multiple scorer type fields at once, that format should be exclusive.

Second thing, right now registration is blocked unconditionally for these, but I want it allowed on open-source MLflow backends. Only block it when the active backend is Databricks, and in that case raise a clear error saying these scorers can't be registered on Databricks and pointing people to use them directly in evaluation calls instead.

Last bit, the utility functions that pull out and update the model URI from a serialized scorer representation need to understand this new third-party serialized format too.
