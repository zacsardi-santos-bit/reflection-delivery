I'm trying to wire up a bunch of editors that the Gemini CLI just doesn't know about right now, Sublime Text, Lapce, Nova, BBEdit, emacsclient, and micro, and when I set any of these as my preferred editor it flat out refuses because they're not recognized as valid choices. I need them added as first-class editor options so that whole cast of editors becomes settable.

Beyond just recognizing them there's a bunch of behavior to get right. Sandbox mode compatibility matters too, emacsclient is a terminal editor so it should be allowed in the sandbox, while the new GUI ones should not be.

I also want a utility to validate whether a given string is a recognized editor identifier (handy for checking user config), plus a case-insensitive lookup that resolves an executable command name to its canonical editor type. And for the editors that support it I need to pull the right wait flag (Sublime Text uses a different wait flag than the other GUI editors) along with any extra startup arguments, like whether to open in a new window based on the user's settings. Oh and the text input hook should read that new-window preference from the settings context when it decides how to invoke the editor.
