I'm building an agent that uses PII middleware to protect sensitive info, and I've hit a real gap: when I consume the agent's output as a stream, raw personal data still leaks through in the live chunks even though the middleware correctly redacts it in the final assembled state. Same deal with tool call arguments and tool outputs, so if a tool returns an email address or a credit card number or an IP address, those show up in the real-time stream events before any middleware hook gets a chance to catch them. The existing middleware only intercepts fully assembled messages in agent state, which means anyone watching the stream live (a chat UI, a log aggregator, a monitoring dashboard) sees the raw sensitive data as it arrives. That defeats the whole point for real-time use and it's a compliance and security hole in production.

What I want is an in-flight stream interception layer that sits directly in the stream pipeline and scrubs sensitive data as it flows through, before anything gets projected. It needs to cover model-generated text including reasoning traces, tool call arguments (even when they arrive incrementally across multiple chunks so you have to buffer partial args), tool outputs (both delta updates and final results), and error messages from failed tool invocations. And it has to handle all the shapes these events take, structured deltas, finalized block snapshots, and legacy whole-message payloads.

For redact mode, matched PII should be swapped out for clear placeholder markers in both the live deltas and the finalized snapshots. For block mode, the stream should hold everything back and raise an error the moment PII is detected, with zero sensitive characters reaching the consumer through any projection (text, tool calls, values, or raw events). Oh and concurrent runs sharing the same transformer instance can't cross-contaminate their per-run buffering state, and it should clean up that internal state when a run completes or gets abandoned. Also important: this in-flight transformer needs to be installed and active whenever tool results are being protected, not only when model output redaction is on, and it's gotta be registered in the right order relative to other stream processors so redaction happens before any projection snapshots the data.
