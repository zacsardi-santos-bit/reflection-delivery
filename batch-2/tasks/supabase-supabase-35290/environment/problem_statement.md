I'm building out the GraphQL API for the Supabase docs site and right now it only does schema introspection, there's no way to actually search docs content, so any internal tool or dev hitting the API has zero way to find pages programmatically. I want to add a search query field that takes a plain text string and returns matching documentation pages. The relevance should come from AI-generated embeddings (semantic, not just keyword matching) which then get looked up through the existing database search function we already have.

The field needs a required query string plus an optional limit for capping how many results come back, and when that limit's passed it should get threaded through to the database call so the count is actually capped. Each result should carry at least a title and a URL, and callers should be able to optionally ask for the full page content too, oh and important bit here, the underlying db call should only fetch the full content when it's genuinely requested, don't pull it otherwise.

Error handling matters a lot. If embedding generation blows up for whatever reason, I want the response to come back with a generic non-revealing internal error message instead of leaking any implementation details. And if someone leaves out the query argument entirely, that should surface as a validation error saying the field is required.

Also the server-side-only OpenAI client needs to be structured so it can be mocked in tests, specifically I need the OpenAI client interface exported from the library module so the tests can use it to build a typed mock. Make sure that export is actually there.
