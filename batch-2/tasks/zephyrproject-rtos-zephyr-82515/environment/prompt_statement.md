I'm adding toolchain tracking to the Twister test runner and right now there's just no concept of which toolchain a given test instance was built with. It gets determined implicitly by the environment at run time but never stored anywhere, so build dirs collide when I run the same suite against multiple compilers (think GCC vs LLVM vs some vendor toolchain), the lookup keys get ambiguous, and I can't tell results apart in reports or saved plans. Today I have to run Twister separately per toolchain and juggle output dirs by hand, which is miserable.

So what I want is for a test instance to accept a toolchain identifier when it's created and store it. That toolchain needs to become a distinct directory level in the build path so builds with different toolchains land in separate directories instead of stomping each other. It should also flow into the instance lookup keys used all over the test plan, including quarantine matching, and get serialized and deserialized when plans are saved to or loaded from disk. When cmake configures the build, pass the active toolchain through to the build system. And in the progress log output, show the toolchain right next to the timing info for completed tests so it's obvious which one produced each result.

Also, oh, I want test YAML config files to support declaring a list of toolchain variants the test should run against. When that list is there, the runner should automatically expand the matrix to cover every platform and toolchain combination, and this always applies, no special command-line flag needed to turn it on.
