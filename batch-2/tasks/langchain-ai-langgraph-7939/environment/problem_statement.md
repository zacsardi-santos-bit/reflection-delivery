I'm adding a feature to the LangGraph CLI so we can actually track which specific third-party packages (from a curated set we care about) are bundled at a given deployment revision, and at what versions. Right now when we update a deployment there's no way to record any of that, so we can't audit what dependencies were live for a given revision. I want a new module that scans a project's dependency files and pulls version info for those packages of interest.

It needs to handle all the common formats, lock files with resolved versions, manifest files with declared constraints, and plain requirements files. Lock files win: if there's an exact resolved version there, use it, otherwise fall back to the manifest or requirements constraint. If a package shows up with no version info at all it should still get recorded but tagged with an "unknown" marker, and same deal for a package that's only referenced as an extras specifier on another package, that's unknown too. Packages that don't appear anywhere shouldn't show up in the result at all.

Also needs to be graceful about edge cases: dependency paths that escape outside the project directory get silently skipped, non-path dependency entries get ignored, and very large files should read up to some size cap without blowing up. When I point it at multiple dependency directories it should scan them in order and the first match for each package wins.

Then once I've got the detected list, I want to pass it into the deployment update methods so it gets forwarded to the backend as a top-level field in the request body, not nested inside any existing config sub-object. And if no package list is given, that field just shouldn't appear in the request body at all.
