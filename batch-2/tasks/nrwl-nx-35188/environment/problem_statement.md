I'm hitting a TOML formatting problem with our Nx setup for a monorepo that's got Rust packages in it. When Nx runs the release versioning process and rewrites Cargo.toml files, everything comes out with single-quoted strings, the package name, the version, the dependency version refs, all of it. That's wrong per the TOML spec since single quotes mean literal strings that suppress escape sequences, and the normal default for ordinary string values is double quotes. So the manifests Nx spits out are technically non-standard and other TOML-aware tooling and linters in the Rust ecosystem might misread them or display them oddly. I want the serializer to consistently emit double-quoted strings for all these string values instead.

Same bug shows up in the AI coding agent config files Nx generates too, the command arguments inside the MCP configuration entries are getting written with single quotes when they should be double-quoted, so please fix those the same way.

Oh and there are two related output glitches while you're in there. The serialized Cargo.toml content starts with a spurious blank line before the first section header, which makes the file look malformed, so it should start directly with that first header, no leading blank line. Also, dependency entries that were originally inline tables aren't being expanded into the readable explicit section-header form when the file gets re-serialized, so those inline dependency tables need to expand into standard section form on write-out. Basically anyone using Nx to bump Rust package versions or set up an AI coding agent is currently getting files that drift from standard TOML conventions, and that causes confusion or downstream tooling failures, so I'd like the whole TOML output path cleaned up to handle all of this.
