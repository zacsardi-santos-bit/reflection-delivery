I'm building out the new frontend pipeline for our model conversion tool and I want to add a model analysis mode so tooling can inspect a model's structure before running a full conversion. Right now there's no way to get the names, shapes, and data types of a model's inputs and intermediate tensors without actually converting it, and integrations that need to query that stuff programmatically are stuck.

Here's what I want: when a specific environment variable is set to turn on an analysis transform, the pipeline should look at the model's graph and print a structured, JSON-compatible description instead of doing the conversion. The description needs to cover all input parameters plus all intermediate tensors, which is the output of every op in the graph. For each tensor I need its name, its shape, its data type, and a value placeholder (value isn't supported yet so it should always report a sentinel).

Shapes have to handle dynamic dims properly, so a static dim is just the integer, a dynamic dim inside a statically-ranked shape reports as zero, and a tensor with fully dynamic rank reports its shape as a special sentinel value. Data types report as their string form when known, otherwise a sentinel.

Timing matters here: this analysis has to run early, before any user-specified input shape or type settings get applied, and once it's printed the output the pipeline should exit cleanly without continuing the conversion. Oh and I'd like the actual print/output step to be its own separate callable so other tools can swap it out or intercept it easily. Put the analysis functionality in a new module inside the existing frontend pipeline package.
