I'm hitting a weird styling bug with Vite's dep optimizer during pre-bundling. I've got a CJS package that internally does a require on another package, and that second package's entry point (its main field in package.json) points at a CSS file instead of a JS file. When I run the dev server with dependency optimization on, the styles from that nested CSS-only package just never show up in the browser, like the stylesheet gets silently dropped somewhere in the pre-bundle step.

The frustrating part is a directly imported CSS file works totally fine. It's specifically the case where the CSS file is the resolved entry of a package that gets pulled in transitively through a CommonJS require call. Feels like the optimizer isn't detecting non-JS assets correctly when they come in through a CJS dependency chain. Some real npm packages do ship CSS as their main entry, so when a CJS dep requires one of those, the CSS vanishes and there's no obvious way to figure out why the styles are missing.

I want this handled so the CSS gets detected during pre-bundling and actually loaded by the browser, with the page reflecting every rule from that transitively required stylesheet-only package, same as if I'd imported the CSS directly. To prove it out, I'd like a playground case over in the optimize-deps playground that sets up exactly this scenario: a CJS package that requires a sub-package whose main field is a CSS file, imported into the page, with some element that should turn a specific color once the CSS actually loads. Oh and it should just work with the normal dev server flow, no extra config on my end.
