I'm cleaning up the tool interface in our language server crate and the way we pass document info around is driving me nuts. Right now every diagnostic and formatting method takes a file's location (URI), the optional text content, and for formatting a language identifier, all as separate loose params. That means anytime we add a new bit of per-document metadata (like the language id, which we keep needing more of) we have to touch every call site and every impl by hand. It's fragile and super repetitive since these args get threaded from the backend down through the worker layer into each individual tool.

I want to introduce one unified document object, defined in the language server crate and exported publicly, that bundles the file's URI, its language identifier, and its optional text content into a single value, with a constructor that takes all three fields. Then update all the tool interface methods, the diagnostics ones that run on open, on change, and on save, plus the formatting one, so they accept this document object as their sole document-related parameter instead of the loose URI/content/lang args. The worker methods that aggregate diagnostics and formatting across tools need to move to the same object too, and the backend that orchestrates everything should construct and pass this document rather than threading separate arguments.

Oh and the internal file system helper that currently hands back a tuple of language id and content, switch that to build and return the document object directly. Also migrate any existing tool implementations over to the new parameter shape so everything's consistent. The point is a cleaner API that cuts down on parameter mismatch bugs and lets us add new per-document fields later without rewriting every signature again.
