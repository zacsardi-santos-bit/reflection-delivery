I'm extending the error feedback system in our testing tool, the part that reads validation error responses from an API, pulls out field-level constraints, and feeds that back into test generation so future inputs get tightened automatically. We already handle Java/Spring and Pydantic-based APIs, but there's a gap: nothing understands the error format that Django REST framework APIs return, so when one of those rejects a request we learn nothing and never refine the test cases. I want a new parser for the DRF format, registered so it runs automatically alongside the existing ones.

It needs to handle flat field error dicts and nested serializer errors, plus list-of-dicts where serializer list errors come back with integer-indexed positions. It should recognize required/blank/null field messages, format errors (email, URL, UUID, date, datetime, time), string and array size constraints, and numeric bounds (minimum and maximum, both inclusive and exclusive). Type mismatch messages that assert a primitive type name should be picked up too. Object-level / non-field errors that can't be pinned to a specific field should just be silently skipped. Oh and for GET/DELETE/HEAD requests, field errors should get attributed to query parameters instead of the request body, which is why the observation-extraction method needs the full operation object passed in rather than just the operation label string, so parsers can look at the HTTP method.

Also there's a naming thing that's been bugging me: the data structure carrying type mismatch info has a field named after a Java concept, which makes no sense for non-Java backends. Rename it to something language-neutral that works for both Java fully-qualified class names and simple JSON Schema type tokens, and update every spot that constructs or reads it. And the schema adjustment logic that acts on those type mismatches currently only deals with Java class names, so when a simple primitive type name comes through it should update the schema's type constraint directly instead of ignoring it.
