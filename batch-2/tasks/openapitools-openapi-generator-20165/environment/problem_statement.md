I'm hitting a gap in the OpenAPI generator when it comes to webhooks. I've got an OpenAPI 3.1 spec that defines webhooks with inline request body schemas (that's a legit feature of the 3.1 spec), and when I generate a Java client off of it, the model classes for the webhook payload just aren't there, and neither is the API handler class for the webhook operations. The frustrating part is the generator handles inline schemas in regular paths totally fine, it extracts and names them and spits out model classes plus API code, but when those same inline schemas show up inside the webhooks section it silently skips them during model resolution. So anything referencing those generated types fails to compile, which forces people into manual workarounds or external schema refs instead of the inline schemas 3.1 is supposed to let you use.

What I want is for inline schemas defined in the webhooks section to be handled the exact same way as inline schemas in regular API paths. Concretely, for a webhook POST operation whose inline request body has a timestamp field, an event type field, and a nested event subobject that itself carries an identifier field, I'd expect the generator to produce a model class for the request payload, a nested model class for the event object, and an API class with a method for that webhook endpoint. Right now nothing gets generated for webhooks at all.

So please fix the code generator so webhook inline schemas get resolved and named just like the ones in regular paths, and also update the generated Java client sample so it includes the expected model and API classes for that webhook case.
