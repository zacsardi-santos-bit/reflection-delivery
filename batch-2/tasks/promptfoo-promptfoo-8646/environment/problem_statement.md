I'm seeing our Azure Assistant provider leak sensitive stuff straight into cache keys and debug logs, which is bad. Right now when a call goes through, the cache key it builds ends up embedding the full prompt text, the assistant system instructions, the auth credentials (API keys included), and the Azure endpoint hostnames all as raw plaintext strings. So anyone who can read the cache storage or tail the debug logs can just see all of it, secrets and all. Users are storing prompts with confidential business info in them, and Azure credentials are obviously sensitive, so this is a real security and privacy hole.

What I want is for the cache key construction to become opaque. Take all the sensitive inputs (the prompt, the assistant config/instructions, the authentication credentials, and the Azure endpoint URL), combine them and hash them so the resulting key reveals nothing about what went in. The hash portion of the key should be exactly 64 lowercase hex characters. It's gotta stay unique per combination of inputs so cache hits still work, and it has to be deterministic, same inputs always give the same key even after a process restart or a module reload, otherwise caching breaks. Also different Azure accounts or different endpoints need to produce distinct keys even for an identical prompt, but again without any of those values showing up in the key itself.

Oh and the debug log messages that currently dump a snippet of the prompt text, those need fixing too so they don't expose the prompt. Log non-sensitive metadata instead, like how long the prompt is.
