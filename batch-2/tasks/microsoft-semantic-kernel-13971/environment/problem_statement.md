I'm hitting a wall with the Azure AI Search vector store connector. When I build a store by handing it my own pre-built search index client (I do this to customize retry policies and share one client across components), I can't get a working collection back out of it afterward. Digging in, the code is reaching into private internal attributes on the Azure SDK's search index client object to pull the endpoint and credential, which is fragile and just breaks when those internals aren't there because I brought my own client.

What I want is for the store and collection objects to explicitly expose the service endpoint and the credential as proper publicly accessible attributes on the object itself, rather than fishing them out of internal SDK state. That way when a store gets initialized with a custom client, pulling a collection from it resolves the connection details independently and just works.

Also, the credential resolution logic is currently buried inside the client creation function, which makes it hard to test and reuse. I'd like a dedicated, publicly exported credential resolution helper that cleanly picks between key-based and token-based credentials and raises a clear error when nothing valid can be resolved. Right now if there's neither an explicit credential nor an API key, the failure isn't obvious. Oh and the token credential path should specifically use the async token credential interface (the asynchronous one), not the sync version.

This all lives in the Azure AI Search connector code, so the store, the collection, and the new exported helper should live and be reachable from there.
