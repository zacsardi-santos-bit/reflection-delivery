I'm poking at the marimo notebook server and there's a gap I want to close around language server context. Right now the page config we embed into every served notebook page doesn't carry any workspace info, so the LSP integration has no idea where the project root is or which file is actually being edited, which kills accurate completion, navigation, and diagnostics. I want the server to compute a workspace when it serves a notebook and stuff it into the mount configuration JSON that gets injected into the HTML.

Concretely the workspace needs a root URI (the project root, found by walking up from the notebook's directory scanning ancestor dirs for a project configuration file) and a document URI (the full path of the notebook file). When a specific notebook file is served, root comes from ancestor-walking that file's directory and the document URI is that file's full path. When we're serving from a directory instead (browsing or making a new notebook), find the root the same way but use a default notebook filename for the document path. If neither a file nor a directory is available, fall back to the current working directory as the root. And for static exports, or when the page doesn't map to an active notebook session, or the workspace just can't be determined, the workspace field should explicitly say there's no workspace available (not present / none), don't fake it.

Also while I'm in there, the test helper that swaps the file router on the test client is currently inlined inside a decorator, and it's annoying to reuse. I'd like it pulled out into a proper reusable context manager so tests can call it directly alongside fixtures like temp directories.
