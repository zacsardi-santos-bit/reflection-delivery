I'm running into a server crash in ClickHouse with the "single value or null" aggregate function (the singleValueOrNull one) when it's used over the semi-structured document column type, the JSON/Object-style column you get when the semi-structured document feature is enabled. In memory everything's fine, the function does what it should, returning the shared value when every row has the same value and NULL when they differ. The problem shows up the moment I persist the aggregate states. If I create an AggregatingMergeTree style table with an aggregate-function column holding singleValueOrNull states over document values, insert with the -State combinator, then read it back with the -Merge combinator, the server segfaults during deserialization of those states, a memory access violation reading the persisted state for the document type.

So what I need is for persisting and reading these states back to not crash the server, ever. It's totally fine if the merged result after deserialization comes back NULL, that's a known pre-existing limitation because the serialization path doesn't persist the internal state flags, so I'm not expecting the real value to survive a round trip. I just can't have the segfault. To be clear the in-memory behavior has to stay correct too (value when all inputs match, NULL when they differ), and the deserialize-then-merge path over document-typed columns needs to complete cleanly and return NULL instead of blowing up.
