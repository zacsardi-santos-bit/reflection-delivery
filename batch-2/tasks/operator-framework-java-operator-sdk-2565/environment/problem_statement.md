I'm hitting a nasty reconciliation loop in our Kubernetes operator that uses server-side apply to manage workloads. The problem is Kubernetes stores resource quantities like CPU and memory in its own canonical string format on the server, so when my operator specifies CPU as "2000m" but the server normalizes it to "2", the next reconcile sees a mismatch and fires an unnecessary update, which normalizes it back, and round and round it goes. Same deal with memory where "4096Mi" and "4Gi" are numerically equal but a plain string compare treats them as different. So basically every reconciliation detects "drift" that isn't real drift, applies a pointless update that Kubernetes rewrites into its canonical form, and the next pass finds the same fake difference again.

What I want is for the comparison logic to detect when an actual resource quantity is numerically identical to the desired one but just formatted differently, and treat that as a match so no update gets triggered. This needs to cover both resource requests and limits, and it has to apply across regular containers and init containers both. Oh and it can't be StatefulSet-only, it should work for all the workload types we manage, so ReplicaSets and DaemonSets too.

Important caveat though: if the values are genuinely different numerically, that still has to register as a mismatch like before. And when the workload structures don't actually line up (mismatched container counts, different container names, missing resource specs, or a different number of resource keys), don't try to normalize anything, just fall back to the normal comparison behavior. For StatefulSets there's already logic that handles volume claim template comparisons and I need that preserved, so the quantity normalization should layer on top of the existing volume claim template handling rather than replacing it. btw the whole point here is to kill that infinite loop for operators that specify resources in standard unit formats.
