I'm building an integration that records coding agent sessions from the Qwen coding agent as JSONL transcripts, and I want to feed those recordings into MLflow's tracing system so I can actually see and analyze sessions in the UI. Right now nothing converts these transcript files into structured traces, so completed sessions are invisible to our observability tooling, no visibility into token costs or tool usage patterns, etc.

What I need is a transcript processor that reads a JSONL file where each line is a conversation record (user messages, model replies which may include internal reasoning that shouldn't be shown, tool invocations, and tool results) and produces an MLflow trace. The trace should have one root agent span for the whole conversation, a separate model-call span per assistant response, and a separate tool span per tool invocation. The root span holds the raw user prompt as input and the final assistant reply as output. Each model-call span should carry the conversation history reconstructed into a standard chat-completion request format and output the assistant's reply in the standard response format, excluding any internal "thought" reasoning content from the rendered output. Tool spans get labeled with the tool name and call identifier, carry the call arguments as inputs and the tool output as the result, and get marked with an error status when the tool call was cancelled by the user.

Token usage needs to be accurate at both levels. Each model-call span gets the counts from its own API call, while the overall conversation span should use the last call's prompt-token count rather than summing all prompt counts (summing would double-count the growing context), plus the sum of all output token counts. Oh and all span timings should come from the transcript timestamps, recorded as start and end in nanoseconds reflecting actual wall-clock intervals. Also, when no transcript path is provided, the processor should do nothing and not flush any traces.

Alongside the main processor I want a set of lower-level utility functions for individual transcript records: reading and parsing a JSONL file into typed records, finding/slicing the last conversation turn, extracting text with control over whether internal reasoning is included, pulling out function call parts, building a lookup table of tool results keyed by call ID, normalizing tool result displays to strings, and reading token usage from a record's metadata into token counts.
