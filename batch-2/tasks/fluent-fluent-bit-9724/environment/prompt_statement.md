I'm hitting a data loss bug in the OpenTelemetry input plugin in Fluent Bit. When logs come in over OTLP, the resource and scope metadata from the payload just gets dropped on the floor. OTLP logs are a three-level hierarchy where resource logs contain scope logs which contain the actual log records, and each level carries its own attributes. Right now only the raw log record bodies make it through to the output, so the resource attributes (service identity stuff) and the scope metadata (instrumentation library name, version, attributes) vanish entirely. Downstream consumers lose all OTLP provenance and can't correlate a log record back to the service or library or version that produced it, which kind of defeats the point of structured OTLP instrumentation in a multi-service pipeline.

What I want is for the plugin to preserve the full context by grouping the output. Each resource-scope combination in the payload should emit a group header record into the output chunk. That header needs to identify the OTLP schema, carry integer indices for the resource position and the scope position within the payload, and include the resource attributes plus the scope metadata (name, version, and its attributes). Then the individual log records, with the actual message body, should follow the group header in the same chunk.

Oh and separately, the embedded library output plugin (the `lib` output) needs a new delivery mode that forwards complete raw event chunks, group headers included, straight to callback functions instead of only passing individual decoded records one at a time. That way an embedded consumer or an integration test can read back and validate the whole grouped structure including all the header metadata, not just the flat record bodies.
