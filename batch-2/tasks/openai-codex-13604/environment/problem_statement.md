I'm cleaning up the feedback consent flow in our terminal UI and there's a transparency gap I want to close. Right now the consent popup that asks whether to share feedback logs just takes a boolean saying "yes there's a connectivity diagnostics file attached," so users get told the file exists but never actually see what's inside it. That's bad because they have to agree to share environment data (proxy settings, base URL overrides, which env vars are set and their values, that kind of thing) without reading it first.

What I want is to refactor the consent popup builder so it accepts the full connectivity diagnostics data instead of that boolean flag, and then render those details inline right in the popup header. Each diagnostic headline plus its detail lines should show up in the popup so folks can read exactly what will be uploaded before they consent. Also, the popup should keep listing the connectivity diagnostics attachment in the set of files to be uploaded, but only when there's actually diagnostics to include (don't show it when empty).

Oh and the other half of this: the feedback note entry view currently previews the connectivity diagnostics too, and that's the wrong spot since the user hasn't been asked to consent yet at that screen. So strip that preview out of the note view and simplify it to just show the title, and move all the diagnostic detail over to the consent popup where the actual consent decision happens. Basically the connectivity info should live only in the consent popup now, nowhere earlier in the flow.
