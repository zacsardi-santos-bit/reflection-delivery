I'm seeing a real security gap in our backfill listing endpoint and I want to close it. Right now when I query the list of backfills, I get everything in the system back regardless of whether I'm actually allowed to see the associated workflows. Any authenticated user can observe backfill operations for workflows they've got no business seeing, which is bad news in a multi-tenant or permission-controlled deployment where folks are normally scoped to a subset of workflows. Every other listing endpoint in this API already filters based on what the current user can access, but the backfill listing skips that check entirely, so I'd like to bring it in line with the rest.

What I want is for the backfill listing to consult the authorization system to figure out which workflows the current user is allowed to see (a read permission check on the workflows), and then only return the backfills whose associated workflow lands in that authorized set. Backfills tied to workflows I can't access shouldn't show up at all. Oh and the total count in the response needs to reflect only the authorized subset too, not the full unfiltered count, otherwise the number lies about what I can actually see. Basically make access control here consistent with the rest of the API.
