I'm building out tracing for the MLflow TypeScript package and right now it's missing the foundational entity classes and helpers we need to represent traced operations, so developers can't create, mutate, or serialize spans at all which means no way to capture inputs, outputs, timing, status, or events of a traced call.

What I want first is a factory function that builds span objects from an active telemetry context. When the context is active it should hand back a live, mutable span that lets me set inputs, outputs, arbitrary attributes, events, and status, and once the span has ended it returns a read-only version exposing those same values but with no mutation methods. If there's no context available at all it should give me a no-op placeholder with fixed neutral values.

The span entity needs to serialize to and from the JSON format the MLflow backend uses, and the timestamps there should be nanosecond-precision stored as exact integers, not floating point, so a full round-trip faithfully preserves every property. Also I need a span event entity for attaching named events to a span, including a way to capture exceptions with their type, message, and stack trace, and its attributes should handle string, number, boolean, and array values. Then a span status entity supporting the three standard states that can convert to the format the underlying telemetry library (OpenTelemetry) expects.

Last thing, some utility functions: converting between the high-resolution time format the telemetry lib uses and raw nanosecond integers both directions, plus encoding and decoding span and trace identifiers between hex and base64. The encode side should pad short ids with leading zeros and be case-insensitive, and decode should correctly reverse it. This all has to interoperate cleanly with both OpenTelemetry and the backend's wire format since it's the base for everything higher-level in TS, matching what Python already has.
