I'm working on the Concerto model linter and it's got a gap that's driving me nuts: it doesn't flag any naming problems at all. When I run it against a model, declaration names, property names, enum constants, none of that gets checked for style, so inconsistent naming silently passes and we're stuck catching it in manual review which is slow and error-prone. I want to add naming convention rules so this stuff gets caught automatically.

Three checks I need. First, all the type declarations (concepts, assets, participants, transactions, events, and enum types too) should be camelCase, meaning the name starts with a lowercase letter. Anything starting with an uppercase letter is a violation, one per offending name. Second, the properties/fields inside non-enum declarations should be PascalCase, starting with an uppercase letter, and correctly named ones produce zero violations while each wrongly-cased one gets flagged individually. Third, enum constants (the values listed inside an enum) should be all-uppercase with words separated by underscores, and anything that deviates gets its own violation.

Behavior I'm expecting: a fully compliant model gives zero violations, a model with six badly-named declarations gives exactly six, and three enum constants that break the uppercase style give exactly three. Btw this all lives in the concerto-linter package, so wire the new rules in there.
