I'm cleaning up how MCP tool progress shows in the CLI and it's bugging me. Right now when a tool reports progress we just tack text onto the description line, like "My Tool (Downloading... - 42%)", which looks messy and doesn't match how other progress renders elsewhere. I want a real visual progress bar built out of block characters that sits below the tool header instead.

The bar needs two modes. When the tool knows its total expected work it should compute a percentage and show that label, clamped to 100% even if the reported value somehow goes over. When there's no total it should just show the raw count as an indeterminate indicator with no "%" sign at all. Oh and there should be room for an optional status message from the tool to show up alongside the bar.

The data pipeline has to change to feed this. Instead of pre-computing a percentage upstream and passing that around, I want the raw progress value plus the optional total to flow through so the display layer decides how to render. Anywhere the UI data structures still reference that old pre-computed percentage field, swap it out for these raw current/total values.

Also I want us way stricter about junk progress events. The event emitter should validate incoming values and silently drop anything that's NaN, negative, or infinite. The scheduler's progress handler should skip events for calls that aren't actively executing, so unknown calls or ones already in a completed state get ignored, and it should stop listening entirely once the scheduler's been disposed. Btw when the state manager updates an executing call with partial data (say it's only updating the live output) it needs to preserve whatever progress fields were already stored rather than clobbering them. Net effect: readable determinate/indeterminate bars, and the UI never gets fed impossible values.
