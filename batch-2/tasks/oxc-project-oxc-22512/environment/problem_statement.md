I'm hitting a nasty panic in the oxc formatter when I turn on both JSDoc comment formatting and import sorting at the same time. Any file that has JSDoc comments sitting before the import block crashes it, and it happens with both single-line and multi-line JSDoc. My read is that the import-sorting pass is choking on the internal line breaks that JSDoc formatting introduces inside multi-line comments, it's treating those newlines as real source line boundaries and ends up in some inconsistent state that trips a panic. There's also a separate but related crash: even with JSDoc formatting off, if a regular trailing single-line comment shows up after the import block while sorting is on, it blows up too.

What I want is for these two features to just play nice together. When both are enabled the formatter should run to completion without panicking, single-line JSDoc before imports gets formatted normally and the imports still come out sorted alphabetically, and multi-line JSDoc (including the ones with doc tags like `@param` etc) before imports also formats fine with imports sorted. And that trailing comment after the import block should be preserved correctly instead of crashing when sorting is active.

Oh and while you're in there, it'd be great to expose JSDoc formatting through the public options API so I can flip it on alongside the existing import sorting option. Right now I can't cleanly enable both from the outside. The fix should live in the formatter crate where the import sorting logic lives (see `@crates/oxc_formatter/src`), making sure the sorting logic counts actual source lines rather than getting confused by newlines that come from reformatted comment content. Basically nobody who wants tidy JSDoc plus sorted imports should have to pick one or the other.
