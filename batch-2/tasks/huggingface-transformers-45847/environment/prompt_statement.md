I'm dealing with chat models whose templates pre-fill the start of the assistant turn right in the prompt, like opening a reasoning block so the model starts generating inside it. The problem is my response parser only ever sees the tokens the model actually generated, not what the prompt already wrote, so if the prompt opened a thinking section the parser never sees that opening and dumps everything into the wrong field. Reasoning and chain-of-thought models silently misparse this way, which breaks tool-call detection, thinking extraction, and anything downstream that relies on structured fields.

I want a new declarative response parser I can hand a prefix, meaning "here's what the prompt already wrote," so it establishes the right initial state before it reads any model tokens. It should also stream, emitting incremental open/chunk/close events as tokens arrive instead of forcing me to wait for the whole response. It works off a declarative template describing delimiters and field types for a given model's output format, and it should handle literal and regex delimiters, plain text fields, integer fields, JSON blobs, structured key-value content, repeating fields (like tool calls), optional fields, and value transformations. Oh and it needs to validate the template at load time and raise clear errors for misconfigured templates, things like an unsupported version, an unknown field content type, or ambiguous implicit fields.

Also please wire the existing text generation and multimodal chat pipelines to pass the rendered prompt as a prefix to the parser whenever the chat template pre-fills the assistant turn, so the final parsed output reflects the section the model was actually writing into. The template config should be saveable and reloadable alongside a tokenizer, and the tokenizer itself should expose a helper to spin up a streaming parser in the correct initial state given a prefix.
