I'm using the Gatsby Less plugin over in `@packages/gatsby-plugin-less` to compile my Less stylesheets, and I've hit a wall: there's no way to override Less variables at build time. I'm theming a component library that exposes its design tokens as Less variables (colors, font sizes, that kind of thing) and right now my only options are patching the compiled CSS after the fact (gross and fragile) or forking the plugin outright. Neither is great.

What I want is for the plugin to accept an optional theme config when I register it in my gatsby-config. I should be able to pass the theme two ways: either as a plain JavaScript object with key-value pairs where each pair is a Less variable override, or as a string file path pointing to a JS file that exports such an object (handy for sharing the theme definition across the project). When a theme's provided, those variable values need to get applied during the Less compilation step, basically merged into every Less file being compiled through the loader's modifyVars (or equivalent) so the overrides actually take effect.

Couple of important things to keep in mind: when no theme is configured at all, the plugin should behave exactly like it does today, no changes to existing behavior. And source maps should keep working in development mode whether or not a theme is set, so don't break the sourceMap enablement in dev. Basically make this first-class so folks using Less-based component libraries with Gatsby can customize look-and-feel through the official mechanism instead of hacking around it.
