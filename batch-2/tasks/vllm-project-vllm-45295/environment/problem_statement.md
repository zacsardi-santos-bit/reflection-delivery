I'm hitting a wall serving a big quantized model (Nemotron-Super-120B specifically) with tensor parallelism, and the issue is that after sharding weights across GPUs the per-device matrix shapes stop satisfying the Marlin quantized GEMM kernel's tile alignment. Like a projection layer that's totally fine at TP=1 will produce a per-shard shape of something like (4640, 512) at TP=4, which is tile-misaligned, and the Marlin layer check rejects the whole layer outright even though only a tiny bit of zero-padding would make it compatible. Falling back to slower paths or erroring out is rough when the full-model shapes were valid to begin with.

What I want is transparent padding of those misaligned dims up to the nearest valid boundary before the quantized compute runs, where the padded regions contribute nothing to the output (zero-filled) and there's genuinely zero overhead when the shape is already aligned. So I need a utility that computes the minimal (padded N, padded K) that's at least as large as the original unaligned shape, where valid means it hits the tile alignment requirements and is also divisible by the quantization group size, and shapes already aligned pass straight through unchanged. I also need a companion that recovers those padded dimensions back out of an already-repacked quantized weight tensor so downstream code doesn't have to re-derive them, plus helper functions that actually apply the zero-padding to the packed weight tensor and to the scales tensor so the padded columns carry zero weight.

Last thing, the layer compatibility check needs an opt-in mode that allows tile-misaligned shapes when padding can fix them, but it should still reject cases where the group size doesn't evenly divide the rank-local K dimension, since that means quantization groups would straddle the TP shard boundary and padding alone can't correct it. This unblocks models producing non-tile-aligned per-GPU shapes at common TP configs while keeping numerical accuracy intact.
