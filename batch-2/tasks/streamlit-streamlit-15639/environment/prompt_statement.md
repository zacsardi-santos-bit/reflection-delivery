I'm hitting a really annoying bug in my Streamlit selectbox and I think it's in the widget value-resolution path. My options are custom objects defined inline in the app script, and I pass a custom display function (format_func) that looks each option up in a dict built from the current run's instances to produce a label. Trouble is every rerun creates fresh object instances, so whatever the user picked last time is now a stale object the lookup can't find, the display function throws, and the widget silently snaps back to the first option like it ignored my click entirely. I need it to survive that. When format_func fails on the stored value, don't just bail to the default, instead fall back to the serialized wire label of the stored selection and match that against the current options, and only reset to the default index if the label doesn't map to anything either.

Same thing bites me with enum-type options plus a custom display function when the automatic enum coercion is turned off, because the serialized label gets thrown away during coercion so there's no fallback left and the selection is lost again. So when enum coercion runs it needs to carry that serialized label through so the fallback still works.

Also I want this resolution logic pulled out into a standalone reusable utility so it can be tested on its own. Given a stored value, the current list of options, an options-to-index mapping, a default index, and optionally a format_func and the serialized label, it should return the resolved option value plus a flag saying whether a reset happened. It needs to handle all the cases: there's no value at all, the value resolves normally, the display function fails but there's a recoverable wire label so we keep the choice, and the display function fails with no recoverable label so we fall back to default. Apps that define option classes inside the script body or use dict-keyed display funcs are just broken right now since any selection gets undone on the next run, so getting this right is what makes the widget actually respect user input.
