I'm hitting an inconsistency with sparse arrays in pandas. When I call mean on a `SparseArray` and pass `skipna=False`, it just gives me back the plain numeric mean as if I'd left skipna on, totally ignoring the flag even though the array has NA values in it. That's wrong, I'd expect a missing result to come back whenever skipna is False and there's at least one missing value present. Sum, min, and max already do the right thing here (they propagate NA when skipna is disabled and NAs exist), so mean is the odd one out and it can quietly hand people the mean of just the non-missing values, which is a silent correctness bug if you're relying on consistent reduction semantics across array backends (dense vs sparse should match).

So what I want, in the mean implementation for sparse arrays (look at `@pandas/core/arrays/sparse/array.py`), is: when skipna is True (the default) keep computing the mean over the non-missing values only, that part's fine. But when skipna is False and the array contains any missing values, return the missing sentinel instead of a number. Oh and separately, if the underlying element dtype doesn't actually support arithmetic (say the array holds strings mixed with missing values), I want a clear TypeError raised, and that should happen no matter what skipna is set to. Basically make sparse mean behave like its dense counterpart.
