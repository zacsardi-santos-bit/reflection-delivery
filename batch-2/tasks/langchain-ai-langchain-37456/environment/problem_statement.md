I'm hitting a wall with the message conversion utility in LangChain core, specifically the `_convert_to_message` path in `@libs/core/langchain_core/messages/utils.py`. When messages get serialized into the standard internal wire format (the dicts with `lc` version markers, `type` metadata, an `id` path pointing at the message class, and a `kwargs` payload of constructor arguments), passing those serialized dicts back into the conversion function just fails instead of reconstructing the original messages. It doesn't recognize the envelope at all right now.

What I want is for it to detect that standard serialization envelope and rebuild the right message type, human, AI, system, tool, or function, from the kwargs, preserving all the original fields. So a serialized human message comes back with its content and any stored id, an AI message keeps its tool call list exactly, a tool message restores both the status field and the artifact payload, and a function message gets its name set correctly. Streaming chunk variants matter too, like a HumanMessageChunk stored in the envelope should collapse to its finalized parent type (plain HumanMessage), not stay a chunk.

Couple of edge cases I care about. If the envelope refers to an unknown or unsupported message class, I want it to fail with the same error that other unrecognized input formats already raise, no silent misrouting into the wrong type. Plain dicts with a role or type field should keep working exactly like they do today. And a dict that only partially looks like the envelope (missing some of the required keys) shouldn't accidentally trigger the new handling, it should fall through to the existing path unchanged.

The reason this bites is the persistence flow, people serialize conversation history to save it and deserialize on load, and without this they've gotta manually convert the wire format before handing messages to the conversion utils, which is friction and a bug magnet.
