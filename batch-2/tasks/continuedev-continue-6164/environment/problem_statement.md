I'm working on a networking library that fires off outbound HTTP/HTTPS requests and I've got two related things I want cleaned up.

First is certificate handling. Right now we read the cert files off disk synchronously every single time we build agent options, no caching at all, and the cert content is embedded straight in the agent options logic which makes it a pain to test and just wasteful in practice since the same file gets re-read over and over. I want cert loading pulled out into its own dedicated module that caches what it loads so repeated requests don't keep hitting disk for the same file. The cache should lazily initialize on first access, and it needs to honor the standard Node env var that points at extra trusted CA certs (the NODE_EXTRA_CA_CERTS one) so it picks those up when it initializes. Since the agent options builder now has to delegate to this async cache, go ahead and make that agent options function async too so it can await the cache.

Second is proxy bypass, which needs two fixes. Right now there's no concept of ports, so a bypass rule for a hostname applies no matter what port you're hitting, and I actually need port-aware matching so a rule like "bypass the proxy for this host but only on port 8080" works and doesn't leak onto other ports. Also the bypass logic only reads from env vars today, and I want to be able to pass proxy bypass patterns programmatically through request options too, not just the env var route. When both the env var list and the programmatic list are present, check all of them together, don't make me pick one.

Without this every outbound request re-reads certs from disk and proxy bypass ignores ports entirely, so fine-grained proxy config is impossible. These changes make it more efficient and give better control over both cert handling and proxy routing.
