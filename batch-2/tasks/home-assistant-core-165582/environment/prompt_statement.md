I'm cleaning up validation in the energy config module and hit a real gap. Some integrations (think utility company stuff) feed us "external" statistics, meaning energy data that doesn't come from normal HA entities but from provider-specific sources with their own ID format. The thing is those external stats usually already bundle their own cost data, so pairing them with a price entity or a fixed numeric price in the energy dashboard config is just wrong and gives inaccurate cost tracking. Right now the schemas happily let people save that combo and there's no check stopping it at config save time.

I want the energy source config schemas to reject that combination at validation time. So if an external statistic is used and there's also a price entity or a numeric price configured but no corresponding cost statistic, validation should fail with an error saying price configuration isn't supported for external statistics. But here's the nuance: if a cost statistic is already provided alongside the external statistic, then any price fields should still be accepted, because the cost statistic takes precedence and the price fields just get harmlessly ignored in that case.

This needs to cover all the relevant source types, so grid import and grid export flows, plus gas and water. The energy config schemas live under `@homeassistant/components/energy/data.py` (that's where the grid/gas/water source schemas and validators are), so the external-statistic detection and the price-vs-cost-statistic logic should hook in there. Basically catch the bad setup early and hand back a clear error that points people toward a valid config, while not breaking the legit case where they've got their own cost statistic doing the work.
