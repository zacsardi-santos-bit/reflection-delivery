I'm hitting a nasty retry bug with the Databricks operators in Airflow, the ones for creating jobs, submitting runs, and running now over in the databricks provider. Right now when I pass both a raw JSON payload and separately-named parameters on the same operator, it merges them together at init time and writes the result back onto itself. Problem is that clobbers the original template field, so on a retry or after a deferred execution resumes Airflow can't re-render from the original templates anymore, it just reuses the stale already-evaluated value from the first attempt. Silent data corruption basically, tasks quietly run with wrong param values on their second and later attempts.

I want the merge and normalization to happen lazily at execution time instead of eagerly in the constructor. Give me a method that computes and returns the merged payload on demand, combining the JSON field with the named parameters, without touching any stored state. The execute path should do all the merging and validation at run time. After execute finishes, or even if it raises, every original template field has to stay exactly in its pre-execution state so a retry re-renders from scratch. Params injected into the payload (like Airflow task params) still need to reach the Databricks API call, but they must not get written back into the operator's template fields.

Also the validation is in the wrong place, it currently fires inside the constructor which means building an operator with a bad payload blows up immediately and I can't even serialize it. Move that out so payload validation failures (invalid types, conflicting argument combos, malformed JSON strings, missing required fields) all raise before any Databricks API call is made and before the API client is even instantiated. Oh and for repair runs after a deferral, rebuild the merged payload including named params fresh from the template fields rather than reading some field that may have been mutated. Net effect I'm after is correct retry semantics plus operators that are safe to construct and serialize without side effects.
