I'm cleaning up the findings section of our security dashboard and there's a cluster of related issues I want to knock out together. First up, we've got sort parameters for two different API families that behave in totally opposite ways, plain findings sort by database declaration order so ascending gives you the most critical and failing stuff first, while grouped findings use numeric-weighted computed columns so you actually need descending to get that same ordering. Right now these token strings are defined ad-hoc scattered all over the place with no clear labelling, and it's already bitten us because the wrong family's tokens get mixed in, so we either end up with results in the wrong order or the backend throws an invalid-sort-parameter error that's a pain to track down. I want all of these pulled into one dedicated standalone server-free module that anything can safely import, with clearly named constants keeping "Family A" (plain findings) and "Family B" (grouped findings) separate so callers can't accidentally cross them, plus preset composite sort strings for the common cases.

Second thing, a bunch of filter utility functions like parsing multi-value comma-separated filter strings, checking whether muted findings should be shown, and applying a combined failing-and-non-muted filter to a set of URL params are currently buried in a module that also imports server-only authentication code. That means I can't import them in the test environment at all, which is breaking a cascade of tests whenever those modules get mocked. I need those helpers moved out into their own server-free module so they're directly importable without dragging in server-only auth stuff.

Last thing, I want the findings page and the resource-drawer hook to both go through that shared helper for applying the default muted-findings filter, so behavior stays consistent across the UI, muted findings hidden by default unless the user explicitly opts in. Keeping sort and filter utils out of server-entangled modules is really the whole point here, it's what makes the action layer actually unit-testable again.
