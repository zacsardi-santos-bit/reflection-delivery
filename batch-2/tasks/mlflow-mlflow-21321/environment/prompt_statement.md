I'm poking at the conversation simulator in MLflow's GenAI module and the way it attaches simulation metadata to traces is bugging me. Right now it wraps each call to the user's prediction function in a tracing decorator, which spins up an extra root span in every simulated trace. That span doesn't reflect any real prediction logic, it's just the wrapper the simulator adds, and when I look at traces in the UI I see this bonus span I never wrote. On top of that, simulation context like goal, persona, and session info is getting stored on span attributes and in a deprecated metadata field that's inconsistent with how the rest of our tracing features stash data.

What I want instead is for the simulator to use the tracing context mechanism to inject the metadata (goal, persona, turn number, session ID, and guidelines when they're provided) straight into whatever traces the prediction function already creates, no wrapper spans at all. The metadata should land in the standard trace-level metadata location, not on root span attributes. The tracing context should get opened once per simulation turn, and the session ID needs to go through the context's session parameter so it shows up under the standard session metadata key. Also long strings like goal and persona should still get truncated to the max metadata length limit, don't lose that. Net result, my traces only contain spans from my actual prediction function and the simulation context sits where it belongs.
