I'm building out the admin controls for our CLI tool and hit a gap. Right now admins can define an allowlist of permitted MCP servers that filters out anything a user configured that isn't on the list, but there's no way to go the other direction and mandate that certain servers are always present no matter what. That's a problem for compliance-critical or infra servers, they can just be missing because the user never added them, or worse the user has a conflicting local entry with the same name.

So I want admin settings to support a set of "required" servers that get automatically injected into every user's effective config. These should take full precedence over any locally configured server with the same name, meaning completely replace the local entry rather than merging into it. They should default to trusted status when injected. Any auth config on them (credential provider type, OAuth scopes, target audience, custom headers) needs to be preserved as-is, and same for tool allow/deny filters. Also I need the names of the injected required servers tracked separately so the rest of the system knows which ones were admin-mandated versus user config.

On the settings plumbing side, the JSON admin MCP settings format needs a dedicated field for these required servers, separate from the existing allowed-servers field, and when remote admin settings come in carrying required server definitions those need to flow through the settings pipeline and show up in the effective merged config the CLI actually uses. Basically without this admins can't guarantee critical tooling is always available in every session, so I want to close that gap.
