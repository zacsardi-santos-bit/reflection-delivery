I'm hitting a wall connecting to remote agents that need auth. Right now whenever the system loads a remote agent it just slaps on a hardcoded default credential flow and completely ignores whatever authentication I've put in my agent definition file, so anything sitting behind a secured endpoint just fails to load. I want the auth config I actually specify to be respected when loading and invoking a remote agent.

Concretely I need a few modes supported. Bearer token auth, and the token should be resolvable from an environment variable so I'm not hardcoding secrets in config files. HTTP basic with username and password. And a generic raw-value mode where I can pass raw credentials through for other standard HTTP schemes like Digest or custom proprietary ones. The secret resolution (env var lookup) should work across these so nothing sensitive lives in the file itself.

Also the failure behavior matters a lot. If auth can't be set up, like the config is invalid or creating the auth handler fails, don't silently fall back to an unauthenticated attempt, just refuse to load the agent and surface a clear warning instead. And the flip side, when I haven't configured any auth at all, please don't inject a default handler, it should connect without one. This gap makes the whole remote agent feature basically unusable for any protected or production deployment, so getting the configured auth path wired through end to end is what I'm after.
