I'm adding data integrity checks to the incremental snapshotting path in rqlite. Right now when we do an incremental snapshot we collect the WAL (Write-Ahead Log) files and move them into the snapshot, but there's zero validation on the way in, so a corrupt or missing WAL file can silently pollute a snapshot and then you're stuck debugging data loss or weird failures way later. I want to catch that at commit time instead.

The idea is each WAL file staged for an incremental snapshot should have a companion checksum file sitting alongside it, and when the snapshot sink gets closed it should verify each WAL file's actual computed checksum against the stored one. If the checksum file is missing, or if the stored value doesn't match the file's real contents, the close/commit should fail with an error rather than quietly committing bad data. So only verified, intact WAL data makes it into snapshots.

To pull this off I also need a small utility that compares a file's computed checksum against a stored checksum file and returns true or false (or an error if either file can't be read). And the existing checksum-writing utility should get an option so callers can opt into flushing the file fully to disk right after writing it.
