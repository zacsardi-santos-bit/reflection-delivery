I'm adding a new gRPC-only service to Qdrant that lets authorized clients read raw files straight out of a collection's on-disk storage. Right now there's just no way through gRPC to check whether a file exists, see how big it is, or pull its bytes, and I need all of that. The motivation is internal stuff like shard transfers and remote storage inspection where one node has to grab specific files from another node's collection storage without going through the higher-level collection APIs.

Operations I want: check existence returning a plain bool, list files under a given path prefix returning paths relative to the collection directory, get a file's byte length, read a contiguous byte range given offset and length, stream a large read as a sequence of fixed-size chunks over a streaming response, read a whole file in one response, read multiple non-contiguous byte ranges from a single file returning each slice in order, and read byte ranges across multiple files in one call returning slices in request order.

Security's the critical part. Any path with parent-directory components (like `..`), special relative-path prefixes, or that resolves through a filesystem symlink to somewhere outside the collection's storage directory has to be rejected, and empty path values too. Also it needs to respect the existing collection-level access control so a caller only touches files in collections they're allowed to read.

On errors: path validation failures return invalid-argument, and the traversal case should carry a message about the invalid path component. Symlink escapes return permission-denied, hitting a collection you're not authorized for also returns permission-denied, missing files or collections return not-found, and out-of-bounds read requests return out-of-range. Oh and the streaming endpoint should split any read larger than the defined chunk size into appropriately sized pieces, and it still has to validate that the file exists even when the requested length is zero.
