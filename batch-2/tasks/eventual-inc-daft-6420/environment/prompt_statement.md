I'm messing with Daft's subscriber system and want a way to dump query lifecycle events straight to disk so I can dig through them after a run. Right now there's no built-in subscriber that persists these events anywhere, so I can't actually inspect what happened during a query, when it started, what the plan looked like, whether it passed or blew up, how long each bit took, all of that. Makes debugging and profiling way more annoying than it should be.

So I want a new event-logging subscriber that writes structured per-query log files into a directory I hand it. Each query gets its own subdirectory with a log file, and inside that file it's one JSON event per line. At minimum for a query that runs fine I want a session header event, a query-start event, the unoptimized query plan, and a query-end event that records the final status (did it finish, fail, or get canceled) plus the elapsed duration in milliseconds. Oh and when a query ends for whatever reason, clean up any internal timing state you were tracking for that query, but don't touch state for other queries that might be running at the same time, concurrency matters here.

Also I want dead-simple helper functions to flip this event logging on and off globally whenever. When I enable it, attach the subscriber to the Daft context and stash it in a module-level variable so I can reference it programmatically. When I disable it, close the subscriber and detach it from the context, and if I then try to detach it manually again it should raise an error rather than silently doing nothing.
