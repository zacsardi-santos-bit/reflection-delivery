We run a bunch of Accumulo clusters and I've got two monitoring gaps I need closed. First one: when a tablet server, scan server, or compactor is sitting in a resource group that isn't getting any work, it looks exactly like a busy process in our dashboards, no way to tell it's idle and just eating resources. I want each of those three server types to emit a metric counter that gets incremented once the process has been continuously idle for some configurable stretch of time. The threshold needs to be driven by a new config property so we can tune how long "idle" means before we alert on it. Important detail, this idle metric should not show up at all during normal active operation, it's only supposed to fire when a server is genuinely doing nothing.

Second thing, and this is separate but related, we run multiple instances sharing the same observability infra so I need to attach operator-defined labels to everything. There should be a config property that takes a comma-separated list of key-value pairs, and every one of those pairs gets added as a tag on every metric the cluster emits, so I can filter by environment or cluster name in shared dashboards.

Oh and across all of this, every metric needs to reliably carry a tag identifying which kind of server process emitted it, tablet server vs scan server vs compactor, since right now I can't tell them apart. The idle metric especially should carry that server-type tag so alerts can distinguish the three. Basically I want to be able to automatically surface idle or underutilized processes and cleanly separate metrics per cluster.
