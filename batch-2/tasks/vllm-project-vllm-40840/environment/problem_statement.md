I'm chasing a bug in the Ray-based metrics layer in vLLM, the wrappers we use for observability across distributed inference. When I record a labeled metric under two different label values, say different finish reasons like "stop" and "length", I don't get independent per-label counters, I get shared state. So the second label assignment clobbers the first and the two series bleed into each other, which means my dashboards and alerts are showing wrong aggregated or overwritten values. We run multiple engine replicas and track a bunch of per-label stuff (finish reasons, request types, etc.) so this really undermines the whole pipeline.

There's also a separate thing with unlabeled metrics. Even when a metric has no user-defined label names, it still needs to carry the system-level identifier tag on every update, but right now that tag gets omitted from the call to the underlying Ray metric. Ray requires every declared tag key to be present on every update, so dropping it silently corrupts or drops the measurement.

What I want: the labeling method should return a completely independent child object each time it's called, each with its own isolated tag set, so recording on one labeled child has zero effect on any other. Non-string label values should get auto-converted to strings. And trying to label an already-labeled child a second time should raise a clear error instead of silently doing the wrong thing. Oh and the unlabeled wrappers need to automatically include that required identifier tag whenever any recording method is called on them.
