I'm refactoring beets autotagging so match result objects own their metadata-application logic instead of leaning on some standalone helper that callers have to invoke by hand, passing in the match info and item mapping. Right now that's awkward and the match objects don't encapsulate the behavior most tied to them. What I want is for both album-level matches and single-track (singleton) matches to get constructed with the item-to-track mapping baked in, and each one exposes a method to apply its stored metadata to the associated library items. So instead of gathering everything and calling out to an external function, I just call the method on the match.

The apply method needs to respect the full set of import config options. Specifically there's a "start from scratch" mode that wipes all existing item tags before writing the new ones, a setting controlling whether null or empty values from the new match should overwrite existing non-empty values on a per-field basis (the overwrite-with-null behavior), and a flag to use original release dates instead of the reissue date. All of these should be handled in one place now rather than scattered across call sites.

Separately, there's a utility that reconciles singular vs plural variants of artist fields, like keeping the primary artist name consistent with the list of artists. I want to expand it to cover more field types too, artist sort names, artist credits, and artist IDs, and make it a pure function operating on a plain dict rather than mutating an item in place. Edge cases matter here: if the single value is missing but the list has stuff, derive the single from the list; if the list is empty but the single exists, build the list from the single; if the single is already in the list but not at the front, move it to the front (matching is case-sensitive); and if the single value is a combined featured-artist credit and all its individual component artists already appear in the list, leave the list alone instead of inserting a duplicate combined entry. This reconciliation should also kick in when metadata gets applied so single and list variants stay in sync.
