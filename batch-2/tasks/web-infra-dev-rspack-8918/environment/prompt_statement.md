I'm bumping the bundler dep we use in test tooling and I need it pinned exactly, not left on a loose range. Right now the manifests specify a fuzzy version for the bundler as a dev dependency, but a newer patch release is out and I want to lock to that exact newer patch version. This has to happen in two places, the root package manifest at `@package.json` and the test-tools sub-package manifest at `@test-tools/package.json`, both moved from the range spec to the pinned exact version.

The reason this matters is kind of subtle. When the bundler version changes and packages get reinstalled, the package manager regenerates its content-addressable virtual store paths for every package that lists the bundler as a peer dependency, the CSS loader being the big one. Those store paths get embedded verbatim as source comments inside compiled CSS files whenever the pathinfo feature is on. So if I don't update the manifests, the installed dependency tree drifts away from what the tests expect and the CSS pathinfo output stops matching.

The snapshot expectations for the pathinfo CSS output are already updated to the new paths, so really all the implementation needs to do is pin the bundler to the correct newer version in both manifests so the reinstalled tree lines up with what those snapshots expect. Just the manifest edits, that's it.
