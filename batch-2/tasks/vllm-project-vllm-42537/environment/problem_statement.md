I'm hacking on vLLM's FlashInfer attention path and hit something wasteful. Every time the server boots with FlashInfer kernels it runs autotuning to pick optimal kernel configs for the current hardware, and then it dumps those results into a temp dir that gets cleaned up right after, so the same tuning work gets redone on every single startup even when nothing about the hardware or config changed. I want to make that autotune cache persistent so the expensive tuning only happens once per hardware+config combo, which should cut startup time on later runs.

What I'm after: the autotune results should land in a stable, versioned directory that survives restarts. By default I want it organized under the existing vLLM cache root, with subdirectories keyed by the FlashInfer version, the hardware architecture identifier, and a hash of the relevant runtime configuration, so it's basically content addressed. Also I want an escape hatch, an environment variable operators can set to point the cache at a custom directory (handy for shared or containerized setups). When that override is provided, the cache file should go directly under that directory using just a configuration hash as the subdirectory, skipping the default layout entirely. If the override isn't set, fall back to the default structure I described. And the cache directory needs to get created automatically if it doesn't already exist so nothing blows up on first run.
