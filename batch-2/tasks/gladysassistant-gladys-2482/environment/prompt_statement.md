I'm working on the Zigbee2mqtt integration in Gladys and I need to add a full reset capability. Right now there's no clean way to wipe the integration, so if a user's config gets corrupted or they want to swap their Zigbee coordinator, they're stuck manually deleting files and settings. I want a reset operation that stops and removes all related Docker containers, deletes everything the integration saved in the database, removes the Zigbee2mqtt data folder from disk, clears all the in-memory runtime state back to its initial defaults, and then emits a status update afterward so the UI reflects the clean state. Oh and if there's an active MQTT connection or a scheduled backup job hanging around, those need to get cleaned up too (disconnect the client, cancel the job). If the disk deletion fails, that error should propagate rather than getting swallowed. I also need this exposed through a new API endpoint so the frontend can actually trigger the reset.

Separately, I keep hitting flakiness in our Docker container stop and remove logic in `@server/lib/docker`. When you stop a container that's already stopped, Docker returns a "not modified" (HTTP 304) response and our code throws instead of just succeeding, same deal when you remove a container that no longer exists and Docker sends back "not found" (HTTP 404), we throw for no reason. I want both of those benign cases to resolve without error, while any other Docker error still gets thrown normally. Also the successful return of both stop and remove should be normalized to nothing (undefined) instead of passing through whatever Docker hands back.
