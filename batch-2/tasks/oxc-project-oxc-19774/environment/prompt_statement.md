I'm using the unused declarations lint rule and I want more control over how it hands out auto-fixes. Right now it treats unused imports and unused variables the same, it always emits a suggestion-style fix that I have to manually accept, and there's no way to say "auto-apply import removals but keep variable removals as manual suggestions" or vice versa. This matters because editor integrations and CI tooling often want to treat these categories differently, auto-removing unused imports is usually safe and desirable while auto-deleting unused variables can be riskier, and today I just can't express that distinction.

So I'd like a new config option on this rule that lets me control the fix mode for unused imports and unused variables independently. Each category should support at least three modes: disabled (report the diagnostic with no fix offer at all, no code modification suggested), suggestion (the current default where I manually accept the change), and automatic fix (tool or editor applies it directly without asking me). Oh and when I only configure one of the two sub-options, the other one should keep behaving the way it does today, so it defaults to suggestion-style rather than getting disabled or anything surprising. Also if I pass an invalid value for the fix mode I want it clearly rejected with an error, not silently ignored.
