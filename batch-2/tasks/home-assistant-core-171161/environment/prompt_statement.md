I'm cleaning up the setup flow for the Arcam FMJ integration in Home Assistant and there are two connection-error handling problems that make config a pain. First, for devices we auto-discover on the network, the flow right now pops a confirmation screen before it ever tries to connect, so if the box turns out to be unreachable the user confirms setup and then just eats a failure, total dead-end. I want the connection check moved into the discovery step itself so that if we can't reach the device for any reason (connection refused, an unresolvable host / DNS error, a timeout, or just a general network/OSError type thing) the flow aborts right then without showing that confirm form at all. Second, for manual setup where someone types in a host and port, if the connect fails today the whole flow gets aborted and they have to start over, which is rough. Instead I want the form to stay open and show a specific error depending on what broke, so one message for a hostname that won't resolve, a different one for a refused connection, another for a timeout, and a catch-all generic one for anything else, and then the person can fix their input and complete setup successfully on the next try. This all lives in the config flow at `@homeassistant/components/arcam_fmj/config_flow.py`. Oh and I need the translation strings in `@homeassistant/components/arcam_fmj/strings.json` (and the matching `@homeassistant/components/arcam_fmj/translations/en.json`) updated so every new error code the form references actually has a definition, otherwise the UI shows raw keys. Keep the error codes distinct per failure type so the messages actually mean something.
