I'm extending the Snowflake database connection so it stops being username/password-only. Snowflake supports a bunch of auth methods that enterprise folks actually use, and right now none of them work through the connection editor, so the generated Python connection code doesn't match how people really log in. I want the connection config to let users pick an authentication type and then have the right Python code generated automatically for each one.

There should be four types to choose from. Password is the standard username and password, but with an optional MFA push toggle that, when enabled, works like password auth plus an extra connection argument turning on the MFA push behavior (Duo). SSO (Browser) does browser-based single sign-on by setting the authenticator to the external browser method, and it shouldn't need a password at all. Key Pair is certificate-based auth that passes a path to the private key file and optionally a passphrase via connection arguments, where the passphrase should be stored securely as an environment variable. OAuth / PAT uses a token (OAuth token or personal access token) stored as an environment variable and sets the appropriate authenticator in the URL parameters.

Each auth type needs to emit the correct connection arguments for its method. Oh and the existing fields like warehouse, schema, and role should stay optional, so they only show up in the generated code when someone actually provides them. Also when multiple fields are backed by environment variables, the variable declarations in the generated code should come out in consistent alphabetical order so it's stable. This matters because lots of orgs flat-out don't allow simple password auth and require SSO, MFA, or certs, and without these options they can't generate working connection code straight from the notebook editor.
