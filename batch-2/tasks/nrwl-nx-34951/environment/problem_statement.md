I want to add shell tab completion to the nx CLI because right now you get total silence when you Tab after an nx command, even in a monorepo with 50+ projects, so you're stuck remembering every project, target, and generator name from memory, which is especially painful for flags like projects or focus where valid values are workspace specific.

I need this to cover bash, zsh, fish, and PowerShell, each installable via a wrapper script users source into their shell config. For each shell the install script should set an environment trigger variable to the appropriate shell name, gate verbose error output on a separate verbosity env variable, and walk up the directory tree to find a workspace-local copy of the CLI binary rather than relying only on a global one. The zsh script especially has to handle colon-containing values (like project:target formatted candidates) without splitting them.

The completion logic needs to be context aware. When completing the first positional of the run command, return project names with a trailing colon, then complete to full project:target combinations at stage two. For generate (including its short alias) show plugin names with a colon AND bare generator names from across all plugins so you can type either form, filtered by what's been typed so far, excluding hidden generators, and including workspace-local plugins discovered via the project graph, not just installed node_modules packages. The show project, show target, and show target inputs/outputs subcommands each complete their positional appropriately including special keywords for target inspection, add suggests available plugins filtered by prefix, and typing a target name directly (like a build command) completes project names that have that target.

Flag value completion matters too. Flags like projects, exclude, focus, target and all their short and long aliases should complete to valid workspace project or target names depending on the flag, and aliases for the same option must share one completion handler so new aliases can't silently drift. When a flag is being completed but has no registered handler, return empty results rather than falling through to positional completion which would suggest wrong candidates.

There should be a fast-path entry point taking raw process args, parsing relevant tokens (handling both the standard layout where 'nx' sits between the binary and the command, and the layout without it), writing candidates to stdout one per line, and returning a boolean for whether it handled the request or should fall through to a slower path. Keep it organized around distinct concerns: argument layout parsing, completion metadata registration and lookup, value providers, shell script generation, and per-command wiring. Also it's gotta be resilient to missing workspace data, returning empty suggestions instead of crashing.
