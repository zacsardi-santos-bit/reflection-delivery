I'm updating the OpenCode SDK provider in promptfoo because the SDK now ships a v2 module with a flatter API shape, everything gets passed directly at the top level instead of being wrapped in nested sub-objects, and our provider only speaks the old nested format so it'll break once folks upgrade to SDK versions that only expose the flat API. I want the provider to detect at runtime whether the v2 module is available and, if it is, use the flat parameter format for every session operation (create, prompt, delete) where fields go directly at the top level, otherwise fall back gracefully to the legacy nested shape.

Also the session lifecycle is broken right now, temporary sessions never get cleaned up so we leak orphaned sessions on the server. Non-persistent sessions should be deleted after each call completes, and if deletion fails I want that error silently logged rather than thrown up to the caller. Persistent sessions should get deleted when the provider's cleanup method runs. Oh and session persistence shouldn't require a cache to be enabled anymore, drop that coupling.

There's a batch of new config to wire through too, a workspace field that gets passed to both session creation and prompting (but if neither a working directory nor a base URL is configured, using workspace should raise a clear error), output format plus variant settings forwarded to the prompt call, API key injection into the provider-specific server config, and environment variable overrides for the spawned server process. Finally, when output format is set to expect structured JSON and the response carries a structured payload, use that payload directly as the output, and when there's no structured payload, extract any fenced JSON code block from the text response and normalize it to compact JSON. This all lives in the OpenCode provider code, probably around `@src/providers/opencode.ts` or wherever the provider and its tests sit.
