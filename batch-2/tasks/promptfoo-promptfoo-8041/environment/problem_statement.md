I'm hitting a really annoying bug in promptfoo's assertion checking. When I write a "contains" assertion where the value has a comma in it, like I want to check that the output contains the phrase "hello, world", the value gets split at the comma so it ends up checking for "hello" and " world" as two separate things instead of the whole phrase. This gives me false positives when partial tokens happen to show up in the output, and it also means I straight up can't test for phrases that naturally have commas in them, which is a pain for proper nouns or formatted data.

What I want is to wrap a value in double quotes to stop the comma inside from being treated as a separator, basically the same quoting convention CSV files use. So the parsing that splits these comma-separated value lists needs to respect quoted fields. This has to work for all four variants of the assertion: the case-sensitive and case-insensitive versions of both the "any" mode (passes if at least one value matches) and the "all" mode (passes only when every value matches). They should all parse the list the same way with the quoting.

Also, escaped characters inside quoted values matter, so a literal double quote or a backslash inside the quotes should get unescaped correctly. And oh, whitespace between items like tab characters shouldn't accidentally produce empty tokens that then cause spurious matches. Right now the parser just silently gives wrong results which makes for test failures that are super hard to debug.
