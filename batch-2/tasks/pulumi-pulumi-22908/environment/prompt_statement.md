I'm trying to enrich the HTTP user-agent that the Pulumi CLI sends to the Pulumi Cloud backend. Right now it only carries the CLI version and OS, which means I can't correlate backend API traffic to specific subcommands, or tell whether a human or an AI coding tool triggered the request. As AI-assisted dev gets more common I want both bits of context flowing through.

So in the HTTP client package I need two new exported functions that stash package-level state: one to set the current CLI command name, and one to set the detected AI agent name. The user-agent builder should then fold these into the existing parenthesized comment section, command first then AI agent, and just omit either one if it hasn't been set. If neither is set the user-agent stays exactly in its current format with no new fields. Oh and the command value needs sanitizing to strip characters that'd break the user-agent format, so parentheses, semicolons, and spaces should go.

Also the function that detects which AI coding environment is active currently lives inside its own package and I need it made publicly accessible so it can be called during CLI startup to populate the AI agent state before any HTTP requests fire. It figures out the AI environment from a bunch of well-known env vars across different tools, with an explicit override variable taking highest priority. The set it should recognize includes Copilot, Codex, Cursor, Gemini CLI, Claude Code (with a distinct cowork mode that takes priority over regular Claude Code detection), Replit, Goose, Antigravity, Augment, and OpenCode. This is really about observability on both sides so we can attribute API calls to specific commands and tooling contexts.
