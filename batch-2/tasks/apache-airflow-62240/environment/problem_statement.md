I'm building out Airflow provider components for Amazon SageMaker Unified Studio because there's nothing built-in for it yet, and my team runs notebooks there that we want to orchestrate straight from our DAGs instead of gluing together custom scripts outside Airflow. What I need is the full set: a hook wrapping the underlying cloud APIs, an operator that kicks off a notebook run and can optionally wait for completion, a sensor that watches an already-started run, and a trigger for deferrable execution.

The operator should let me pass instance type, a run timeout, and arbitrary notebook-level key-value parameters, and it needs to work both synchronously (inline polling) and asynchronously via deferral. When it starts a run it should pass the DAG's id along as a workflow label. I want a configurable polling interval and run timeout with a sensible default derived from a 12-hour window. In deferrable mode the trigger has to serialize all the relevant state so it can resume cleanly after a worker restart.

Big one for us is chaining notebooks. When notebook A finishes and produces outputs, those outputs should get pushed to XCom automatically so notebook B can pull them in as input params through Jinja templating. The sensor should also grab notebook outputs once it detects completion so downstream tasks can consume them the same way.

For the hook, it needs to read outputs from a known S3 location and return an empty result gracefully if the outputs file isn't there or can't be parsed, don't blow up. Also if the cloud API isn't available in the current region or endpoint, raise a clear error early rather than failing silently later. Across the operator, sensor, and trigger, please handle the transient in-progress states (queued, starting, running, stopping) properly and raise clear errors on terminal failure states so retries and error handling behave. This all lives under the Amazon provider, so wire the hook, operator, sensor, and trigger into the usual `@providers/amazon/src/airflow/providers/amazon/aws` layout following how the other AWS components are structured.
