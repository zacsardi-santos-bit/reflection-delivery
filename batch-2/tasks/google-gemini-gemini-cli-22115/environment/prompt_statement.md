I'm cleaning up how runtime deps get passed around in our agent CLI and it's kind of a mess right now. Every component (the tool scheduler, the safety checker, the various prompt builders) reaches into the config object with its own getter to grab the tool registry, the message bus, and the AI client. Different call sites use different methods and there's no single contract for what an "agent loop context" is actually supposed to expose, so sharing these runtime dependencies across schedulers and checkers and prompt utilities ends up tightly coupling everything to the full config class.

What I want is one unified context interface that exposes the tool registry, the message bus, the AI client, the config object itself, and the current session/prompt identifier as direct properties, not methods. The main configuration class should implement that interface so it's assignable to it directly without any casting, which means it needs to surface those same deps as direct properties on top of (or instead of) the existing getters. Oh and the tool registry itself should expose the message bus as a direct property too.

Then update the tool scheduler's constructor so it takes this unified context interface as its primary input instead of the full config param it used before (under whatever key it was passing that in). Also the safety checker's setup method needs renaming so it reads like it accepts a context object rather than plain config. The point is all these consumers can talk to agent loop state through one consistent property-based interface, less coupling, clearer contract, easier to extend later.
