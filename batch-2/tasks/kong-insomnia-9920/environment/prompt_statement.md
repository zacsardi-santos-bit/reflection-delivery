I'm extending Insomnia's OpenAPI linting so custom Spectral rulesets work everywhere, not just git-connected projects. Right now cloud-synced and local projects can't apply custom validation rules to their specs, and that's too limiting. I also need extends-referenced local files resolved and bundled at upload time so a saved ruleset is self-contained. Oh, and the current remote-reference handling is unsafe since nothing stops a ruleset from pointing at internal hosts or declaring custom JS execution.

Three pieces here. First, a utility that tells me whether a hostname or IP is private or loopback. It's gotta cover localhost and its subdomains, all the standard private IPv4 ranges, IPv4 and IPv6 loopback (including IPv6 bracket notation), link-local addresses, and IPv6 private ranges. Public addresses and generic/unrecognized hostnames shouldn't get flagged, treat those as safe.

Second, a validator for Spectral ruleset content. It takes YAML text, parses it, and returns either a success result or a failure result carrying an error message. It should reject empty content, anything that isn't a YAML object, unsupported top-level keys (custom function declarations especially), and security stuff inside rule definitions: prototype-polluting property names or path expressions, unsafe URL schemes on documentation links, dangerous/path-traversal characters in field specifiers, and any function that isn't in the allowed built-in set.

Third, a bundler that takes a path to a Spectral ruleset file, recursively resolves local file references in the extends list, and returns one merged YAML string. Built-in spectral identifiers should pass through unchanged and get deduplicated. It needs to detect cycles, enforce a sane maximum nesting/extends depth, and reject unsafe configs. For remote HTTPS references it should fetch the content, validate it but not merge it into the output (keep the URL preserved instead), and do DNS resolution to confirm the resolved hostname isn't a private or internal address. The point of all this is any project type gets custom linting while neither uploaded nor remote rulesets can probe internal infra or run arbitrary code.
