I'm poking at Ray Serve's controller health monitoring and hit two gaps I want closed. First one, the health metrics snapshot tracks how many control loops have completed but not when the last one actually ran, so I can't tell a healthy controller that's churned through loops from one that ran a handful ages ago and has since stalled. I want to add a last control loop time field to the health metrics snapshot, defaulting to 0.0 when nothing's run yet, and the tracker that collects these metrics needs to expose that timestamp as a settable attribute so the controller can update it at the end of each control loop. When metrics get collected off the tracker, the returned snapshot should reflect whatever the most recent recorded timestamp is, not some stale value.

Second thing, right now to grab these health metrics I have to make a separate call straight to the controller, which is clunky. I'd rather the top-level serve instance details response carry the controller health metrics directly as a top-level field, so one API call gives me both deployment state and controller health in a single snapshot of the cluster.

Oh and one more, the health metrics classes are only importable from an internal private module today. I want them exposed from the public schema module too so external consumers and tooling can reference them without reaching into private internals.
