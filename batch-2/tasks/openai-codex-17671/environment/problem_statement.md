I'm knee-deep in the integration test infra for our Rust file system project (the one that tests fs ops in both local and remote containerized environments) and I hit two things that need fixing.

First problem: when the test suite spins up a remote containerized environment, we only copy the main binary into the container. The sandboxing binary never gets deployed, so any sandbox enforcement test running in remote mode is basically lying to us, the sandboxing component just isn't there so it either silently skips enforcement or tests the wrong thing. I need the remote exec server startup to also deploy the sandboxing binary alongside the main one, make it executable, and actually verify it works before any tests run. On top of that I want dedicated remote integration tests for sandboxed file ops: reading within allowed directories should succeed, path traversal attacks via symbolic links and parent-directory (`..`) references should get rejected, removing a symlink inside a sandbox should remove only the link and not the file it points to, and copying a symlink should create a new symlink rather than copying the pointed-to target. Oh and the tests that used to run in both local and remote modes, their remote variants should be properly split out into the remote test suite.

Second problem: the boilerplate that lets a test binary act as multiple helpers (dispatching to different roles based on how it's invoked at startup) is copy-pasted into every test crate that needs it. Each crate keeps its own version of the same init logic and it's fragile and a pain to keep in sync. I want to pull this shared dispatch logic into a new reusable library so each crate can set it up with one concise call, passing in a small classification function that says what should happen for each recognized invocation mode. Centralizing it cuts the maintenance burden and keeps behavior consistent everywhere.
