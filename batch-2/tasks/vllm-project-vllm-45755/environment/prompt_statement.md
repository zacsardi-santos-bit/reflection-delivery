I'm adding a new model family to our vLLM engine-based streaming parser infra and I could use a hand. Right now this family isn't wired into the token-aware engine parser path, so streaming outputs don't get split cleanly into reasoning traces, tool calls, and content, and users lose out on precise special-token detection. The good news is this model uses the same tool-call XML format as an existing parser, so I want to reuse that tool parsing logic (parallel tool calls included), but there are two model-specific behaviors I need to get right.

First is a reasoning/content swap. Normally text before the reasoning-end delimiter is reasoning and text after is content, but when thinking mode is disabled via the request config, or when the content after the delimiter is empty or whitespace-only, I need to swap the fields so the reasoning text becomes the content and whatever whitespace followed the delimiter becomes the reasoning. If thinking mode is explicitly enabled, or there's real non-whitespace content after the delimiter, keep the normal classification. And if there's no relevant config set or no request context at all, just behave normally, don't swap.

Second, this model sometimes explains tool-call syntax inside its thinking output, so I only want to trigger tool-call parsing when the actual special token IDs show up, not when the same text appears with regular token IDs. So a model can discuss tool-call syntax in reasoning and then make a real call afterward and both need to parse correctly.

Also the existing reasoning adapter for this family is a standalone class today, I need to migrate it to the newer engine-based adapter system. The engine parser should be registered and auto-discovered by the existing replay test infra, I don't want to manually add it to lists in test files. Oh and if a parser is registered but has no corresponding test builder, please raise a clear error for that case.
