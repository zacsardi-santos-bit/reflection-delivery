I'm adding a binary archival format for MLflow trace data. Right now trace data only lives as JSON text, but I want a compact binary option based on the OpenTelemetry protocol's standard wire representation so long-term archival is more space-efficient and interoperable with systems that consume the OTLP binary format. It also gives us richer round-trip fidelity, preserving resource metadata, span events, status codes, that kind of thing.

So I need a new serialization module that converts a list of trace spans into a binary protobuf payload using the OTLP wire format and back again. On the serialize side it should validate before writing: reject an empty span list, reject spans that span more than one trace, and reject spans carrying inconsistent resource metadata, all with helpful error messages when those constraints get violated. One subtlety, resources that have identical attributes but in a different key order should count as equivalent, don't false-positive on that. The deserialize side needs its own validation, reject empty or unparseable bytes, reject payloads with multiple resource-span groups or multiple scope-span groups, reject payloads mixing spans from different traces, and reject payloads that contain no spans at all. Oh and the archive filename should be a fixed constant defined inside the module.

Then on the artifact repository side I want three new operations each on the local filesystem and S3 repos: upload raw protobuf bytes, upload a trace data object (accepting either the native object or its JSON string representation), and download the archived trace data back as a trace data object. For Databricks-backed repositories these three archival ops aren't supported yet, so each should raise a clear, informative error saying archive-repo operations aren't supported yet instead of silently failing or doing something wrong. The point of all this validation is that corrupt or malformed archive files get caught early with clear messages rather than blowing up in confusing ways downstream.
