I've got a table with a struct column that's dictionary-encoded, the kind of thing you get out of Parquet or Arrow IPC where repeated struct values get deduped and stored once with integer keys pointing back at the dictionary entries. When I try to pull a field off that struct with the normal field access syntax, the query blows up. The exact same query against an equivalent struct column that isn't dictionary-encoded works totally fine, so this looks specific to the dictionary-encoded representation, DataFusion just isn't handling it transparently.

What I want is for field extraction to work regardless of whether the struct column is dictionary-encoded, so extracting a named field returns the correct values either way. Oh and ideally the result keeps the dictionary encoding too, so if I extract, say, a text field from a dictionary of structs I get back a dictionary of that field's type rather than a fully materialized column, that keeps the efficiency of the original layout. Also nulls need to behave: any row where the dictionary key is null should produce null for the extracted field.

Once that works I'd expect the extracted fields to play nice with the usual SQL stuff, filtering on a struct field, grouping/aggregating by it, and ordering by it should all work. And accessing a field name that doesn't actually exist in the struct definition should still error out like it does today, don't want that silently returning garbage. Basically make dictionary-encoded structs behave consistently with their non-encoded equivalents.
