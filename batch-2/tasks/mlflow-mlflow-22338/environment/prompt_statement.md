I'm building a TypeScript integration that bridges Claude Code session transcripts into MLflow's tracing system so teams can actually see what happened during an AI coding session, which LLM calls fired, what tools ran, what sub-agents did, and how long it all took, right inside MLflow's tracing UI. Right now there's no way to observe any of that.

The core of it is a function that reads a Claude Code JSONL transcript file (these record every user message, assistant response, tool use, and sub-agent bit) and builds an MLflow trace with a nested span hierarchy. I want a root agent span for the whole conversation carrying the initial user prompt and the final assistant response, child LLM spans per assistant turn with the input message history plus output in the expected AI provider format and the message format attribute set right, and child tool spans per invocation capturing tool name, tool id, inputs, and outputs. Sub-agent activity should nest as agent sub-spans whether it comes through as inline progress events in the main transcript or lives in separate JSONL files on disk. Parallel tool calls in one turn need to work too.

Token usage goes on the LLM spans, and here's the gotcha, cache-creation tokens count toward input tokens but cache-read tokens don't. Trace metadata should carry session id, current user, working directory, the AI tool version, and the permission mode, and request/response previews come from the first user message and the final assistant text. When a tool use gets rejected, record it as an exception on that tool span. Oh and "steer" messages the user injects mid-conversation should show up as user messages in the following LLM span's input history.

I also need the transcript parsing utilities: reading and parsing JSONL lines into typed objects, converting timestamps (ISO strings, Unix seconds, ms, or ns) all to nanoseconds, pulling plain text out of message content whether it's a raw string or an array of content blocks, finding the last meaningful user message while skipping tool results, compaction summaries, and skill injection messages, and finding the final assistant text response.

Edge cases matter: an empty file, a file with no real user messages, or a path to a file that doesn't exist should all be handled gracefully without creating any spans. And everything should finish by flushing traces.
