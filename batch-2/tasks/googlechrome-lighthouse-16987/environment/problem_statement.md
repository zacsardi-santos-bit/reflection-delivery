I'm cleaning up our model context protocol audits (the ones that check MCP support on web pages) and there's a cluster of failures when the feature just isn't there. Right now if the browser doesn't support the underlying protocol, the gatherer throws an unhandled error and the whole audit run dies instead of quietly reporting the feature as unsupported. I want it to catch that specific protocol-not-supported failure when the enable command fails and continue gracefully, reporting the feature as unavailable rather than crashing.

Also the gatherer assumes support as long as the enable command succeeds, but that's wrong, a page might not expose the model context interface even when the browser supports the protocol. So I need a page-level check for whether the interface is actually exposed, and if it isn't, mark the feature unsupported too. The artifact the gatherer produces should bundle both pieces together in one structured object, the support status and the tools list side by side (fixture file that records expected artifact shapes needs updating to match this new structure).

Then on the audit side, all three related audits should read that support status and mark themselves not applicable when the feature's absent. And a couple of them also need to return a proper not-applicable result when there's genuinely nothing to evaluate, like no forms present or all forms already annotated (or no tools), instead of handing back a plain passing score. Right now users can't tell "everything looks good" apart from "this audit didn't apply here," which is misleading, so please make that distinction real.
