I'm trying to fix token cost tracking for AI agents that route through OpenRouter as the model provider. Right now if a model gets accessed via OpenRouter and it's not in our local pricing database, the whole thing just returns no pricing data, which is useless for models that only exist on OpenRouter or newly added ones we haven't recorded locally. What I want is a fallback: when the cost tracker can't find pricing for a model in the local file, it should automatically go fetch pricing from OpenRouter's own API instead of giving up.

For that to work I need a utility that takes OpenRouter's metadata format and converts it into the internal pricing structure we use, and it's gotta support all the cost fields including cache read and cache write pricing, not just the basic prompt and completion rates. OpenRouter publishes separate prices for cache-read tokens versus fresh prompt tokens, so the cost calculation actually needs to use those distinct rates instead of applying one flat rate across all prompt tokens, otherwise cached-token savings show up wrong in the reports.

Also the model identifiers coming through carry a provider prefix, and that needs handling transparently, so strip the prefix when doing the actual lookup but keep it preserved in the returned pricing record. And one more thing, when I register an OpenRouter-backed LLM with the cost tracker, I want later cost calculations to always pull that model's pricing from OpenRouter's API using the provider-prefixed identifier, overriding any local entry that happens to exist under the same name. Don't fall back to local data in that case, OpenRouter is the source of truth once it's registered that way.
