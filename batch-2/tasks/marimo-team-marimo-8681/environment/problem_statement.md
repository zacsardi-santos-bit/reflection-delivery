I'm hitting a data-loss bug with marimo notebook exports. My notebooks carry inline package dependency declarations in the file header (the self-contained script standard for Python, that little metadata block that lets a notebook run in a sandboxed environment with automatic dependency management). Problem is, when I export one of these sandboxed notebooks to standalone script format, the whole inline dependency block just vanishes. The exported script has all the cell code but none of the dependency metadata, so it can't be used as a self-contained script anymore, which totally defeats the point of the sandboxed workflow when people share or deploy these things.

What I want is for the script export to include the full inline dependency block exactly as it appeared in the original notebook. So when I convert the notebook intermediate representation to script format, extract and preserve that inline dependency header.

Oh and it needs to survive a format conversion round-trip too. Like if a Python notebook gets converted to Markdown first and then exported back to script, the dependency info is stored differently in that intermediate representation, so you'll need to handle both the Python-origin case and the Markdown-origin case correctly. Either way the final script output has to contain the complete inline dependency block, nothing dropped. Right now exporting a sandboxed notebook to script silently strips all of it and the result can't be run without me manually adding the dependencies back, which is exactly what I'm trying to avoid.
