I'm updating the Groq LLM instrumentation so it lines up with the current generative AI observability conventions, because right now our spans use a legacy provider-prefixed name and stuff message content into flat string attributes, plus streaming status and token counts use old attribute names that dashboards and other OpenTelemetry gen-ai tooling can't read correctly. What I want is for chat spans to be named by operation and model (operation, then a space, then the model name) instead of the old provider-prefixed format, and every span should carry the standard provider name, operation name, and request model attributes. Input and output messages need to be stored as structured JSON arrays where each message has a role and a list of typed content parts, so plain text, images (both regular URLs and data URLs), tool calls, and tool call responses all get represented properly, and the old flat prompt/completion string attributes should be gone entirely. Also the streaming status and total token usage attributes should switch to the current standard names, and finish reasons should be gathered and recorded as a list attribute on each span when not in legacy mode. Oh and the finish reason value Groq returns for tool invocations comes back plural and needs mapping to the singular form the standard expects. Log events emitted during tracing should carry the provider name attribute rather than the legacy system attribute.

On the code layout, I want the internals split into separate modules: one for span attribute utilities (functions for converting content to parts, recording input and output attributes, handling token histograms), one for event emission (message and choice events with correct content-tracing behavior), one for the event data models, and a shared utilities module with helpers for safe exception handling, error metrics attributes, and model-to-dict conversion, plus a config module. The public wrapper functions also need to handle the edge cases right: suppress instrumentation when the appropriate context keys are set, still record duration metrics even if an API exception fires, swallow errors coming out of the response handling step, cleanly end spans even when stream processing fails, and skip status updates when a span isn't recording anymore.
