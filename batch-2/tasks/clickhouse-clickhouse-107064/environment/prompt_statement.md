I'm hitting a nasty bug in ClickHouse when I do a compound column rename that swaps names between two columns of different types. Say I've got a table with an integer IP column and an IPv6 column and I want to swap their names in one ALTER, renaming the integer one to a new name while renaming the IPv6 one into the old name. The data files get renamed fine, but the resulting storage part ends up with the wrong type in its column metadata, so the column that should now be typed IPv6 is recorded as the integer type instead. When I read from it I get a type conversion error or an assertion failure. The type declarations are being inherited from whichever column previously held that name rather than from the actual source of the rename, which is the real bug.

Same thing happens when I drop a column and rename a different column (of a different type) into the freed name in the same ALTER, and also in the case where one of the involved columns was added to the schema but never materialized with real data. In that unmaterialized case it's actually worse, the operation throws an internal error instead of just gracefully default-filling the missing column data. What I want is for the mutation logic that builds part metadata during a rename to correctly assign each column its own type, the type it's being renamed from, instead of picking up whatever the old name's type was. So the swap should record each column's own actual type, the unmaterialized column should end up absent from the part and default-filled at read time without erroring, and dropping plus renaming into the freed name should assign the right type too. Oh and this needs to work for both compact and wide storage formats, with and without materialized data for the renamed column, and it's gotta hold up when combined with other mutations like an UPDATE in the same ALTER statement. Folks doing multi-step schema migrations with compound RENAME COLUMN hit this constantly, in-place type changes and role swaps, and right now they silently get corrupted parts that crash or return wrong results on read. Please fix the metadata assignment so the stored data and declared type line up.
