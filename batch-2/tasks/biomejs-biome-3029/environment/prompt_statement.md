I'm wiring Biome into our CI two different ways and hitting friction with how it emits diagnostics today. Right now if Biome detects it's running under GitHub Actions (via an env var) the default terminal reporter auto-emits annotation lines mixed in with the normal output, which makes our snapshot tests flaky since the same command gives different results depending on where it runs, and the test setup has to strip those lines out. I want to kill that auto-detection entirely so the default reporter never emits annotation lines based on environment, and instead add an explicit reporter option I can opt into when I actually want annotations.

So basically two new `--reporter` values across the check, ci, lint, and format commands. One is a GitHub-style annotation format that emits one line per diagnostic carrying the rule category (the rule name), the file path, and the position (line and column). The other is JUnit XML for our test reporting dashboard, standard format with the aggregate counts up top (total tests, failures, errors, elapsed time) and per-diagnostic test case entries grouped per file, where each diagnostic shows up as a test case failure.

Both reporters need to plug into all four of those commands the same way. The annotation one just gives us reliable inline PR annotations when we ask for them, and the JUnit one lets us feed lint and format results into the dashboard alongside our regular test results. Wiring lives around the CLI reporter code in `@crates/biome_cli`, oh and make sure removing the env detection doesn't leave annotation output happening anywhere implicitly, it should only ever show up when explicitly requested.
