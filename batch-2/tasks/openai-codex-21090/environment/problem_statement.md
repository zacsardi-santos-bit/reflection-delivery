I'm poking at the TUI chat app and the conversation history is getting really noisy because of these fallback warnings. When someone uses a model we don't recognize, we show a warning about falling back to default metadata, which is totally fine the first time, but the thing keeps reprinting the exact same warning every single turn the model gets invoked in a session. In a long session you end up scrolling past the same message a dozen times and it buries the actual chat content.

What I want is dedup on these model-specific fallback warnings so once we've shown one for a given model, any later identical warnings for that same model just get dropped silently. The first occurrence should still render normally, and it needs to include the model's name/identifier in the displayed text so the user knows exactly which model triggered the fallback. The tracking state for this needs to live on the chat widget so it persists across the whole session (not reset per turn).

One thing to be careful about, this suppression should only apply to the model-specific warnings. Generic warning messages that aren't tied to a particular model should keep showing up every time they happen, no dedup, no suppression, since those aren't the ones causing the spam. So the dedup logic has to key off the model identifier and leave everything else alone.
