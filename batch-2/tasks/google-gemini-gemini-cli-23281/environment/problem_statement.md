I'm cleaning up the telemetry tracing in our CLI tool and hit a couple of rough edges. Right now when a traced operation returns a streaming result (an async iterable), the span doesn't close on its own. The caller gets handed some "end span" callback and has to remember to call it once they've drained the stream, and honestly it's fragile, lots of spots in the code wire up that boilerplate and it couples streaming logic to span lifecycle stuff. I want the tracing wrapper to just detect when the return value is a stream and automatically close the span when the stream finishes, whether it completes normally or throws partway through. No more handing back an end-span function for callers to juggle, it should all happen transparently so callers never touch span lifecycle.

While I'm in there, I also want a small utility for safely prepping values to attach to telemetry events. Numbers and booleans should pass straight through unchanged. Objects should get serialized to a text representation first. Then for any string (or serialized object) that's longer than the max length, truncate it and tack on a suffix that shows the original length. Oh and it has to handle multi-byte unicode right, so truncation happens at proper character boundaries and doesn't slice an emoji or other multi-byte sequence in half. For unsupported types like functions or symbols it should just return nothing.

Last thing, I want a config flag that controls whether prompt content (the inputs and outputs) gets included in telemetry spans at all, so folks who don't want their data logged for privacy or compliance can opt out entirely. This matters because unclosed spans leak telemetry, and unbounded prompt payloads bloat trace exports and raise privacy concerns.
