I'm adding a lint rule to our modeling structure linter in the transformers library and want your help wiring it up. The gist: when a model class declares tied weights (two params sharing the same tensor, via a non-empty tied-weights collection), the matching config class needs to expose a flag that lets users turn that tying on or off. Right now there's no check for this, so it's really easy to add tied weights to a model and forget the corresponding config option, and then tying is unconditional, users can't disable it during fine-tuning, serialization round-trips break, and untied-head fine-tuning fails silently. Bad.

So the new rule should only fire when the tied-weights collection is actually non-empty, and when it does fire it emits one violation per affected model class with a message that names both the missing field and the specific configuration class that needs updating (be precise about which config, don't just say "the config"). It should NOT fire in a few cases: when the config class inherits the flag from a parent model config (already handled upstream), or when the model explicitly resolves to a sub-config that already declares the field. Also for multi-component models that ship separate config files per component (audio, text, vision, etc.) it needs to match the right config file by component suffix instead of grabbing some arbitrary one.

Oh and the caching layer needs fixing too. Currently if someone adds the missing flag to a config file, the cache has no idea the modeling file's lint result might've changed, so it serves stale results. I want the cache key to fold in the content of the companion configuration file(s) so editing a config correctly invalidates the cached result for the associated modeling file.
