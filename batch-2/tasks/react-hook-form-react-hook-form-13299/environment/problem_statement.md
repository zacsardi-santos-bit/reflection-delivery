I'm hitting a bug with dirty field tracking in my forms that use dynamic field lists, and it's messing with how I decide what to save. Say I've got a form with a "name" text input, an "age" number input, and a dynamic list of items. If the user only clicks "Add Item" to append a new entry, the dirty fields tracker should just show that list as modified, but instead it's throwing "name" and "age" in there too, like the user changed them, when they didn't touch anything. Same deal happens on remove, not just append.

This actually matters because I use dirty state to gate the Save button and to send only changed fields to the server, so these false positives mean I either submit stuff that never changed or show bogus "unsaved changes" warnings.

What I want: appending an item marks only that list dirty, removing an item marks only that list dirty, and unrelated scalar fields the user never touched never show up as dirty because of a list op. Oh and if the user genuinely modified a scalar field and then does a list operation, both should be dirty, but only those two, nothing else, so scalar dirty state has to survive later add/remove ops. Also for forms with multiple independent dynamic lists, appending to one shouldn't make the other look dirty, they need to track per-list. And for nested dynamic lists (a list nested inside another at a specific index), appending should update only the relevant branch, with the pre-existing items marked not dirty and the newly added item marked dirty, without touching sibling fields.
