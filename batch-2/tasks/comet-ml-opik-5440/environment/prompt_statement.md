I keep running into this annoying thing where we render text all over the app (error messages, log output, config values, random user-generated strings) and any URLs inside just show up as dead plain text, so people have to select and copy them by hand to open in a browser. I want a shared, reusable frontend component I can drop in anywhere we display potentially URL-containing text that scans the text content and turns standard web links into clickable anchors automatically.

Behavior I'm after: any http/https URL embedded in the text becomes a real link that opens in a new tab, styled so it's obviously a link (blue and underlined), and clicking it shouldn't bubble the event up to parent elements (stop propagation). If there are several URLs in one block, each one becomes its own separate link. Also when a URL is followed by punctuation like a trailing period, comma, or wrapped in brackets, the trailing punctuation needs to stay out of the link target so we don't linkify into it.

Be strict about what counts: only standard web protocols get linkified, so other protocols and bare domains without a protocol stay as plain text, never links. This has to be safe with untrusted input too, so dangerous URI schemes (think javascript: and friends) must never become clickable, and any script-like content in the input must never execute. When the text has no URLs at all, just render it as-is with no extra wrapping or markup added. And handle the edge cases without blowing up, oh and that means empty strings, whitespace-only strings, null or undefined content, and even numeric values passed in should all render fine.

Give me this as a shared component so it's reusable across the app wherever we show text that might contain links, error messages, API response previews, docs links, that kind of thing.
