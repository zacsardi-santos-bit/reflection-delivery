I'm deep in the Anthropic integration for Home Assistant and hitting a bunch of related bugs around how the model's thinking (its internal reasoning) gets stored and reused between conversation turns. Right now when we process a streaming response we stash the thinking data as raw API response objects straight into conversation history, and when that history gets converted back into API message format for the next request it doesn't reconstruct right, the thinking signatures and the encrypted reasoning don't map back to the correct params. I want thinking metadata (both regular and encrypted reasoning) stored in a consistent unified shape in history so it round-trips cleanly back to the proper API message format on future calls.

There's also some edge cases that are broken. When the model does a tool call and then emits a thinking block before its next text response (interleaved reasoning), we don't handle it, that reasoning after a tool result needs to actually get recorded as part of the conversation and included when we build messages for later calls. Also when generating structured data with extended thinking on, if the response has a reasoning block plus some extra explanatory text before the structured output tool call, the extraction fails, it should still pull the structured data correctly no matter if extra text blocks show up between the reasoning and the tool output.

Oh and one more, for a simple assistant message that's just a single plain text response with no citations or reasoning, the current code wraps it in a list unnecessarily, it should just be a plain string. This stuff matters because it causes wrong API requests when resuming extended-thinking conversations, broken or missing structured data results, and redundant structures for plain messages. The relevant logic lives in the Anthropic integration under `@homeassistant/components/anthropic/`. Please fix all four.
