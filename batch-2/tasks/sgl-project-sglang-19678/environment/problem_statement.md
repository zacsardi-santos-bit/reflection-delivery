I'm building out a tensor debugging and comparison tool for distributed model training, the kind where people annotate tensor dimensions with how they're sharded across parallel processes, like marking that a hidden-size dim is split across tensor-parallel ranks or a sequence dim uses a zigzag layout across context-parallel ranks. Two things I need sorted.

First, the annotation syntax for these parallel-axis modifiers currently wraps the label in parentheses, and that clashes with other places parens show up in the format so it gets ambiguous. I want to switch the modifier delimiter to square brackets everywhere, in the parsing functions, in anything that constructs or returns dimension strings, and in whatever serializes these annotations internally or on output. All the existing dimension strings should come out using square brackets after this.

Second, I need fused dimensions. Some frameworks store what are logically two separate dims (say attention-head count and per-head feature size) contiguously as one flattened axis instead of two, so when I compare a tensor from a framework that keeps them separate against one that's merged them, the tool can't align them and I get a false mismatch. So introduce a notation where a parenthesized group of sub-dimension names joined by asterisks means a single physical axis that's the product of those logical sub-dims, and fused dims should carry the same square-bracket parallel-axis modifiers as regular ones. It needs to parse alongside regular dims in a full dimension spec.

Each dimension descriptor should expose whether it's fused, what its constituent sub-dimension names are, and a canonical/sanitized name usable as a tensor axis label that joins the sub-names with a triple-underscore separator. And when I compare two tensors that hold the same data but differ on whether those sub-dims are fused or separate, the tool should automatically generate a plan to reshape (flatten) the separate-dims tensor so it matches the fused layout before doing the numerical comparison. Oh and incompatible fused groupings, where the two sides have overlapping but non-identical sub-dimension membership, shouldn't crash, they should produce a warning instead with a category label and a message describing the overlap. Without fused support the tool keeps failing to align tensors from implementations with different memory layouts and flags false mismatches, and the bracket change just kills an ongoing source of parsing confusion for folks writing these strings by hand.
