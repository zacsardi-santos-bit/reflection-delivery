I'm building out a content guardrail layer for the MLflow AI Gateway because right now there's no built-in way to intercept traffic and enforce content policies. Teams can't validate that incoming requests are safe before they hit a model, or check and clean up a response before it goes back to the caller, without writing custom middleware outside MLflow. I want a scorer-driven guardrail that plugs natively into the gateway pipeline and supports both hard blocking and automatic remediation.

Here's what I need. The guardrail should be configurable to run at one of two stages, either before a request is forwarded to the LLM or after the response comes back. And for each stage it should support two modes. In validation mode it invokes a scorer to evaluate the content, and if the content's fine it passes through unchanged, but if the scorer flags a problem it blocks the request/response and raises an informative error that includes the guardrail's name plus the rationale the scorer gave. In sanitization mode it runs the scorer too, and only when content actually fails does it call a secondary LLM endpoint to rewrite it into an acceptable form before forwarding, so passing content is never rewritten. That sanitization call should ask for a structured JSON response matching the expected payload schema.

The scorer can hand back a few different result shapes: a feedback object with a boolean or string value, a plain bool or string directly, or a list of feedback objects. Treat a `true` or a case-insensitive `"yes"` as passing, and `false` or any other string as failing. Unsupported return types like integers should raise a type error saying that value type isn't supported.

Oh and the guardrail needs to be reconstructable from a persisted database entity, with the scorer deserialized from its stored representation. Also when it's running inside the gateway server, any scorer using a gateway-internal model URI has to get that URI automatically translated so inference calls route to the gateway's own endpoint instead of attempting an external resolution that'd just fail in the server context.
