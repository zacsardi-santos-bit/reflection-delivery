I'm hacking on Vite's optimizer and hit a snag with plugins that were originally written for esbuild's plugin API. We convert those over to run inside Vite's own plugin pipeline, and a bunch of them register end-of-build callbacks (esbuild's onEnd style hooks) to inspect or post-process whatever the build produced. Problem is, once converted, those callbacks either never fire at all or when they do fire they get handed a result object that's the wrong shape, so plugins that rely on it to emit files or read metadata just silently do nothing.

What I want is the converter utility that takes an esbuild-format plugin and hands back a plugin that plays nice with Vite's internal system. The key thing is it's gotta preserve the end-of-build notification mechanism through the conversion. So during the setup phase when the original plugin registers its onEnd callbacks, those need to actually get collected and then invoked once the build finishes, every single one of them.

And the result object they receive needs to look right, meaning it carries the fields esbuild plugins expect off a build result, so output files, metadata, and the mangle cache. Those can totally be absent or undefined if nothing populated them, that's fine, but the fields themselves need to be there in the shape the callbacks reach for. Otherwise the callbacks blow up or read garbage. Basically I just need converted plugins to behave the way their authors intended, callbacks called, result well-formed even when empty.
