I'm in the core agent package and the logic for translating between the model's native parts format and our internal content representation is scattered all over, no consistent spot for it, and the edge cases keep biting me (thought parts, media with no MIME type, unknown part types, tool result displays that might be a plain string or a structured object or just missing). I want a dedicated content utilities module under the agent directory that exports four functions and gives these conversions a single tested home so unusual or future content types degrade gracefully instead of silently dropping data.

First function goes from the model's native parts to our internal content parts: plain text, thought content with an optional signature, inline media data, file URI based media, and it should skip function call and function response parts entirely, plus serialize anything unrecognized into a text part with metadata marking it as an unknown type rather than dropping it. Second is the reverse, internal content parts back to the model format, handling text, thought, both kinds of media (default the MIME type to a generic binary type when it's missing), reference parts converted to plain text, skipping media with no payload, and serializing any unrecognized variants to text too. Third, a utility that takes a tool result display value (string, object, or absent) and returns an internal content parts array, or nothing when the display value is absent. Fourth, a utility that builds a metadata record for tool response events from a response object that may have a data payload, an error type, an output file path, and a content length, merging the data payload's fields up into the top level and returning nothing (undefined) when none of those fields are present. Keeping this all explicit and auditable is the whole point.
