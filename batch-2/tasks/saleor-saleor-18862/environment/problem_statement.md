I've got product media records that can point to an external image URL but have no locally stored image, and right now nothing actually pulls those down, so they just sit there unprocessed. I want a background task that fetches the image from the external URL on a product media record, checks it's a real supported raster image, saves it to the record, and clears the external URL once it's stored.

The task needs to bail out cleanly in a bunch of cases. If the record already has an image it should do nothing, if the record doesn't exist it just finishes silently, and if a record has neither an image nor an external URL it should complete without deleting it. Also skip anything that's a non-image media type like video.

Failure handling matters a lot here. Transient server errors (5xx) should trigger automatic retries and the record has to survive those attempts. Permanent failures should delete the product media record, and by permanent I mean unexpected non-5xx HTTP status codes, network errors after retries are exhausted, and invalid or corrupt image data. Content that isn't an image at all, or is an unsupported image type including SVG, also causes the record to be deleted.

Oh and there's a refactor tied to this. There are three MIME utility functions living in the file-upload validation module: one that checks whether a MIME type is an image type, one that checks whether a content type is a supported image format, and one that parses the base MIME type out of a Content-Type header string. I want those moved into a more general-purpose core utilities module so the new task and anything else can share them. They should behave identically after the move, with one change: the supported-image-content-type check now needs to explicitly treat SVG as unsupported going forward.
