I'm hitting a spot in ClickHouse where text search indexes on map columns just don't kick in for IN queries. I've got a table with a map column and I've built text indexes on both the keys and the values of that map. Some query shapes use the index fine, but the moment I filter with map subscript access plus the IN operator, checking whether a specific entry's value is one of several candidates, the index gets totally ignored and every granule gets scanned even though it clearly could skip most of them.

What I want is: when I filter using map subscript with IN against a list of non-empty values, the text index built on the map's values should apply and skip granules that plainly don't hold any of the target values. And when I've got both a keys index and a values index on the same map column, they should cooperate, first the keys index narrows to granules where the queried key is present, then the values index narrows further among those to granules where one of the target values shows up.

There's a correctness thing too that matters a lot. If the IN list includes the empty string, the index must not be used to skip granules at all, because subscript access on a missing key returns the empty string as its default, so skipping based on the index would wrongly drop rows where the key just isn't present. Same no-skip behavior when the empty string is mixed in with real values.

Oh and I'd like this to work when the map subscript access shows up as part of a tuple IN expression alongside other indexed columns, both the map-values index and the other column's index should get applied in those cases. Map columns get used all over the place for variable-length attribute data, so without this these analytical filters keep doing full scans which kind of defeats the point of defining the indexes in the first place.
