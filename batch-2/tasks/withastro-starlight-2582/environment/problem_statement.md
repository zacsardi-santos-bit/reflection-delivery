I'm maintaining the Starlight Tailwind integration package (over in `@packages/tailwind`) and one of the snapshot tests is red. It's the one that checks the full CSS output we produce when Tailwind's default browser reset gets disabled in favour of Starlight's own base styles. Here's the deal: a newer version of the CSS framework changed the order it emits stuff during base-style generation. It used to dump the internal CSS variable declarations (the custom property block that Tailwind uses for its utility classes) at the very end, but now those come first, before the standard reset rules like default border widths and font families, and also before Starlight's own theme colour variables.

Trouble is our dev dependencies still pin to the older version, so the CSS we generate in tests doesn't match what someone running the newer framework in their Starlight project would actually get. So the snapshot expects the variable declarations block up top now and our old deps produce the stale ordering where they land last instead.

I want the dev dependencies bumped to that newer framework version so the generated CSS lines up, and when the integration processes base styles the output should lead with the framework's internal CSS custom property declarations first, then the browser reset rules, then the Starlight theme colour variables in their usual sequence. Basically validate us against the version users are upgrading to.
