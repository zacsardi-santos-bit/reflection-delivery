I'm hitting a crash in the Flutter tool's interactive terminal mode. When I press the platform toggle shortcut (the 'o' or 'O' key that flips the platform rendering mode) while my device's runtime service isn't connected, the whole thing blows up with an unhandled error and my dev session dies. That's rough, because plenty of devices don't support the full runtime service protocol, or the connection just drops sometimes, and I'd still like to keep working instead of getting kicked out.

What I want is graceful degradation. Before the tool tries to do the platform toggle, it should check whether the runtime service is actually available for the current device, and if it isn't, just show me an informative status message explaining that the platform toggle isn't supported for this device, then keep running like normal. No crash, no unhandled exception, just a clear line telling me why the action can't happen so I understand what's going on.

So the fix is basically: in the terminal handler where the 'o'/'O' key gets processed to toggle the platform, guard against the case where the runtime service connection is missing, and when it's missing, print a helpful message rather than attempting the toggle and throwing.
