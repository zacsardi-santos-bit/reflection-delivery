I'm cleaning up the debug comparator utilities where we tag tensor axes with dimension names (token dim, batch, hidden state, that kind of thing) so we can track what each axis actually represents. The problem is our current naming setup rides on that experimental named-tensors framework feature, and it's a pain, tons of ordinary ops (reshape, rearrange, plain arithmetic, passing through some third-party functions) just blow up or refuse to run on a named tensor unless you strip the names first, do the work, then reattach them. That strip-then-reattach dance is scattered all over the place and makes the code fragile and hard to follow.

What I want is to swap the mechanism for one that stashes dimension names without triggering any of those restrictions, so a named tensor just works transparently in any operation, no manual removal needed. The underlying "apply names" helper should move over to this new storage approach, and the resolve-by-name utility should stop poking at internal state and instead go through a new getter.

On that note I need a proper public "get names" function added to the module namespace that reads the names back off a tensor, returning a tuple of optional strings with an entry per dimension and None (absent) for any dimension that has no name, since right now callers just reach into an internal attribute directly which is gross. Also the existing "strip names" function should get renamed to something that better reflects what it does (it returns a new view without names rather than mutating the original), and the old name should be dropped from the exports entirely. Both the new getter and the renamed remover need to be importable from the same module-level public namespace as the rest of the comparator utilities.
