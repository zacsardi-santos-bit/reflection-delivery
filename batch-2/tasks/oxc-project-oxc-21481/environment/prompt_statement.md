I'm working on the language server and hit an annoying gap with formatting. Right now when the server gets initialized with a workspace directory, it only handles format requests for files that actually live inside that directory. If someone opens a file from a parent folder or a sibling dir, the formatter just silently does nothing, no edits come back, no error, nothing. That's a bad experience because devs open files from all over the place, not just under one workspace root, and they get zero indication why formatting didn't fire.

What I want is a dynamic workspace mode where the server can process formatting requests for any file regardless of whether it falls within the workspace boundaries. Files inside the workspace need to keep working exactly like they do today, and files outside should now get the same formatting treatment, same language-appropriate transformations applied.

Along with this I need to refactor the internal structure that manages workspace workers. There should be a new manager type that can be constructed either in a simple default mode or with an explicit operating mode, and one of those modes is the new dynamic one that handles out-of-workspace files. The server backend should accept this new manager type instead of the current builder reference it takes now. Oh and the dynamic mode should also make sure file watching stays efficiently scoped to just the workspace directory rather than watching the whole filesystem, since we don't want to monitor everything. So basically: new manager with default vs explicit-mode construction, dynamic mode that formats files anywhere, backend wired up to the manager, and watching scoped tight.
