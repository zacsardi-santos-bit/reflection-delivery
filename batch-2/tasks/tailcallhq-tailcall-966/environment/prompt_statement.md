I'm working on a GraphQL gateway server in Rust and the caching layer is hard-coded inside the server context constructor. The cache always gets created internally during construction, so there's no way to plug in a different backend depending on where we deploy. A cloud-worker deployment ought to be able to use a cloud-hosted key-value store while the native server keeps using an in-memory TTL cache, but right now that's impossible because the thing is wired in directly.

I want to refactor so the cache is injected as an external parameter instead of built internally. That means defining a shared cache interface as a trait so different environments (native, cloud, whatever) can each supply their own implementation, and then writing a native in-memory implementation for the standard server. I also want a helper function exposed from the CLI module that constructs this native cache so callers can easily create one and pass it in. The server context constructor should then take the cache as an explicit argument rather than making its own.

Oh and the integration test suites for both the GraphQL execution path and the HTTP handling path need updating to build the server context with this new injected pattern, and all the existing end-to-end tests have to keep passing after the change. The whole point is that the same core server logic runs across deployment targets without duplication, cloud deployments bring their own platform-specific backend and native servers use the in-memory one, no changes to the core logic needed.
