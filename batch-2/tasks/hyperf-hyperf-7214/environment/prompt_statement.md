I'm poking at the fluent attribute container in the Hyperf support package (`@src/support/src/Fluent.php` or wherever that class lives) and it's way less useful than it should be. Right now if I call the typed accessors like the ones that pull a value back as a string, boolean, integer, float, array, or collection, nothing sensible happens, the magic `__call` handler just treats them as attribute setters and swallows my intent. Same deal with setting an attribute via a dot-notation path, the bulk-fill method, and the scoped-data method. I want real implementations so each of these returns the correct native type instead of quietly assigning an attribute.

A few specifics I care about: the date-retrieval method should return a parsed date object (Carbon-style) or null when the value is missing or null, and it needs to throw when it hits a genuinely invalid date string or an invalid format pattern. The enum-lookup methods should handle both single and array retrieval, returning null or an empty array for invalid cases, and they should only work with backed enum types.

Also I need dot-notation to work when setting attributes so nested keys land in the right place, a fill method that merges in extra attributes and returns the container itself so I can chain, and a scope method that returns a brand new container wrapping whatever value sits at a given path. Oh and the class should support dynamic macro registration so I can tack on custom methods and call them on instances. Basically I don't want to keep grabbing raw attributes and casting by hand, that defeats the whole point of a fluent API.
