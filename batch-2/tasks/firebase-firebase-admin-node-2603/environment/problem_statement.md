I'm migrating the internal hashing library that Remote Config's condition evaluator uses in the Firebase Admin Node.js SDK. The library we're on now (farmhash, roughly) has compatibility problems with modern Node.js and I want to swap it for the newer maintained alternative (farmhash-modern) that'll hold up better long term. This is all about the percent-condition evaluation, the bit that decides which slice of users matches a targeting condition based on a hash.

The catch is the new library's hash function returns a native 64-bit integer (bigint) instead of a string, so anywhere we hand that hash value off to the downstream numeric processing (the code in `@src/remote-config/condition-evaluator-internal.ts` that compares the hash against percent thresholds) I need to convert the type correctly before doing the numeric comparisons. All the existing percent operators (less-or-equal, greater-than, and the between operator) have to keep producing exactly the same results after the migration, no observable change to user targeting.

Since the modern library doesn't support older Node.js runtimes, any tests that call the actual hash function rather than a mock should skip gracefully on those unsupported versions. And the mocked hash values in the tests need updating to match the new bigint return type instead of strings. Oh and don't forget the dependency config in `@package.json` needs to point at the new library instead of the old one.
