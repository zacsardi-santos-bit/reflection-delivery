I'm in the engine tree's state caching layer in the Reth codebase and right now all account storage entries get stored together under one shared cache with a flat composite key, which makes per-account storage management annoying to reason about and extend. I want to add a dedicated per-account storage cache type in the existing cached-state module (the same module where the rest of the caching infrastructure lives) so storage slots for each account can be managed independently. The whole point is a cleaner abstraction for organizing storage slot data at the account level, it lets us invalidate an entire account's cached storage in one shot and makes the caching hierarchy easier to test on its own.

The new type should be constructable by passing in a maximum capacity, meaning the largest number of storage slots it's allowed to hold. When it's freshly created it should be empty and able to report that it currently holds zero slots. Oh and it needs to be accessible from within the crate through that existing cached-state module's path, so wire up the visibility accordingly. Keep it in that same module alongside everything else so it fits naturally with the current caching setup.
