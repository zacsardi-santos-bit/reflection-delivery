I'm building a new feed integration for Google Threat Intelligence so we can pull their curated threat indicator lists straight into our security platform instead of having analysts track this stuff by hand, which is slow and error-prone. The feed's gotta handle four indicator types (files, domains, URLs, and IP addresses) and each one converts into a platform-standard indicator object with a type, a value, a severity score, and enriched type-specific metadata.

For files the indicator value is the file hash, and the fields should carry the various hash types (MD5, SHA1, SHA256, and the fuzzy hash), file properties, detection counts, and timestamps. Domains use the domain name as the value, and I need admin, registrant, and registrar contact details parsed out of the WHOIS text plus detection stats and timestamps. For URLs, use the actual URL string as the value, not whatever internal hash identifier the API hands back, along with timestamp and detection fields. IPs use the IP as the value and should include the country code, detection stats, and timestamps.

All four types also need the Google Threat Intelligence assessment fields (threat score, severity, verdict), and the verdict maps to a numeric score like this: malicious is 3, benign is 1, suspicious is 2, and anything else including undetected is 0. Indicators can also have malware families and threat actors linked through relationships data, so pull those in too.

I want three commands: a connectivity test that verifies config, an on-demand command that retrieves indicators taking optional feed type, filter, and limit from the command arguments, and an automated fetch-indicators command that reads feed type, filter, and limit from the integration parameters instead. Oh and I need test fixture files for each indicator type structured right so they actually exercise the mapping logic in the tests.
