I'm cleaning up the plotnft command-line stuff in the Chia codebase and the whole thing is a pain to test. The commands over in the pool NFT tooling (creating NFTs, showing status, joining and leaving pools, claiming rewards, inspecting state, changing payout instructions, and grabbing pool login links, so eight commands total) are written as plain functions that spin up the entire async event loop internally, which means you can only exercise them through the full CLI runner. Because of that the tests for all of these got skipped entirely, and I want them actually runnable.

So the main thing I want is to refactor each of these eight commands into its own instantiable class with an async run method, so a test can construct an instance with known params and call run directly without going through the CLI entry point. Once that's in place the whole end-to-end flow should be testable across configs (trusted vs untrusted nodes, reuse vs new puzzle hash derivations): making pool NFTs in either self-pooling or join-a-pool state, joining, leaving, claiming, inspecting, showing status, changing payout instructions for a given launcher ID, and getting login links.

The other half is error handling, it's busted right now. When something goes wrong the code just prints a message and silently returns, but I want real exceptions raised so callers can catch them. Specifically it needs to raise when no pool wallet exists, when a given wallet ID isn't actually a pool wallet, when there are multiple pool wallets and no ID was specified (for commands needing a unique one), when the pool URL is plain HTTP on mainnet (should be HTTPS), when the pool's unreachable, when the pool lock height is too high, when the protocol version doesn't match, and when a login link can't be retrieved, all with descriptive messages.

Also the internal helper that creates pool NFTs needs its signature changed to take a wallet client info object directly instead of a port and fingerprint, so tests that already hold a wallet client can call it. And that function should raise exceptions for invalid state values and wallet creation failures rather than printing and returning. Oh and the pool wallet creation logic should respect the reuse-puzzle-hash wallet config when generating puzzle hashes, using the method that takes a boolean param instead of always minting a fresh puzzle hash.
