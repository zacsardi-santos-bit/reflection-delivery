I'm hitting crashes in the AMD GPU profiling timeline analysis on RDNA3 and RDNA4 hardware. When I run timeline validation on a profiled kernel it blows up with an error about a timeline row having an unexpected device type, something that's neither a wave-level instruction row nor an execution row. Digging in, the timeline generator is emitting instruction events from other SIMD units (the ones that share the same execution block as the wave being traced) as their own separate labeled stream. The analysis code used to have a special skip for that stream, but that skip is being removed, so now those events crash the validator because it doesn't recognize the device label.

What I want is for those shared-SIMD instructions to get folded into the normal wave-level stream instead of living in their own stream, labeled by their instruction name so the analysis can identify them and exclude them from the total instruction count. Every range event the generator emits should belong to one of the two valid categories, a WAVE row or an EXEC row, nothing else. After that, for every kernel trace on RDNA3 and RDNA4 the count of execution events should equal the count of counted wave instructions once all the exclusions are applied, and it shouldn't crash on unrecognized device types anymore.

Oh and one more thing specific to RDNA4: the matrix-multiply execution overlap detection should only apply to the dedicated WMMA execution device row, not fire more broadly, and when it does trip it needs to raise an error whose message clearly says it's a WMMA overlap, including the device name and the conflicting timestamps. Right now profiling any RDNA3 or RDNA4 kernel that involves multi-SIMD execution just hard-crashes during analysis, which makes it impossible to validate or visualize GPU timing for a whole class of real kernels, so I need both the folding fix and the RDNA4 overlap scoping to land together.
