I'm adding support for two new OCR model families to our doc conversion pipeline and both spit out their own formats that I need parsed into our standard document representation. First one gives structured HTML where each layout block is a div annotated with a bounding box (four ints in a normalized 0-1000 coordinate space) plus a semantic label, so I want a parser that maps each annotated div to the right document element type (text, table, figure, list item, section header, caption, footnote, page header, page footer, etc.) and scales the bbox coords to the actual page dimensions. It should silently skip divs with missing or invalid annotations, return an empty document for empty input, and expand list-group elements into individual list items.

The second model outputs a JSON array where each entry has a bounding box, category, and text content, so I need a parser for that too. Thing is these models often produce truncated JSON, so it needs a helper that can recover complete elements from a truncated array or strip leading non-JSON preamble text before parsing. Also it should take an optional reference image size so it can rescale bbox coords from the model's input image space to the page dimensions, and skip invalid elements (non-dict entries, missing or malformed bounding boxes).

Oh and I need two general utilities for the VLM pipeline more broadly. One computes correct image dimensions for visual models that need dims to be multiples of a given factor, with a scale multiplier, per-dimension size clamping, and total pixel-budget constraints (both min and max). The other strips model-specific end-of-sequence tokens from a list of decoded outputs, truncating each string at the first complete occurrence of any stop token but leaving it unchanged if only a partial prefix of a stop token shows up at the end. Without these parsers we can't use either model family as a drop-in OCR backend, and since the JSON ones love to truncate, recovering from malformed JSON really matters.
