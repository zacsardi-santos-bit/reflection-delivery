I'm hitting a dedup bug in our product attribute filtering. When I query attributes filtered by a specific category or collection, I get duplicate attributes back if those attributes are shared across multiple product types. Say I've got two different product types that both include the same attribute, and I create one product of each type and drop them both into the same category (or collection), then query the attributes API for that category or collection. The shared attribute comes back twice, once per product type that references it, instead of just once. This shows up for both the legacy filter path and the newer query-style filter, so both need fixing.

What I want is for each attribute to appear exactly once in the results no matter how many product types in that category or collection reference it. And to be clear, the shared attribute shouldn't get dropped or excluded, it just shouldn't repeat. So attributes filtered by category should show up exactly once regardless of how many product types use it, same deal for attributes filtered by collection.

This matters because duplicates leak into any UI or downstream system reading this API, like a storefront faceted search rendering the same filter option multiple times. Can you fix the deduplication so the attribute listing returns unique results for both category-based and collection-based lookups?
