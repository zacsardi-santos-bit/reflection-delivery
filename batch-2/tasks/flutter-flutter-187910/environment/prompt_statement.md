I'm poking at Flutter's Xcode integration tooling, specifically how we resolve the path to the simulator or device management app inside an Xcode install, and I need to update the lookup logic. Right now we only ever look for the traditional iOS Simulator application sitting inside the Xcode Developer directory, but newer Xcode versions ship a separate device management app that lives one level up from the Developer directory, over in the Xcode bundle's Applications folder (same level as Developer, not nested inside it). So what I want is for the lookup to first check whether that newer device management application exists at the parent level of the Xcode Developer path, and if it's there, just return that path. If it's not present, fall back to the old behavior and go look for the traditional Simulator app at its usual location inside the Developer dir. And if neither one exists, or if we can't even figure out the Xcode installation path in the first place, the method should just return null. Basically newer setups should prefer the new app over the old Simulator, since folks on recent Xcode versions have it available and our tooling should detect and use it instead of always reaching for the older one and potentially missing it. Keep the null-return semantics clean for the can't-determine-path and neither-exists cases.
