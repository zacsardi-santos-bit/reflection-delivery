I'm working in Apache Pinot and I need a pluggable validation hook so external plugin code can register custom validators that fire automatically right before instance or table configs get committed to the cluster. Right now there's just no way to intercept an add-instance or update-instance call to enforce our own constraints like required pool tags on servers or tenant disjointness rules, so bad configs sail through the standard add/update lifecycle and land in the metadata store unchecked. What I want is an instance validator registry where any component can register one or more validators, and when an instance is added or its config updated, all the registered ones run in the order they were registered, before anything gets persisted. First failure should short-circuit and abort the whole operation so the bad config never gets written, and the rejection needs to surface back to the caller. Same pattern for table configs too, a separate registry there. One subtlety, when I'm updating instance tags specifically the validator has to see the instance in its final state with the new tags already applied, not the old one.

Also I need a utility that reconstructs a fully typed instance object from its stored cluster representation (the raw ZK/Helix-style record) so validators can inspect typed data instead of raw storage. It's got to handle all instance types (server, broker, controller, minion), strip the legacy hostname prefix for server instances, return sensible defaults for optional ports that aren't stored, and throw a clear error when it hits an unrecognized instance type. Oh and both registries need a reset/clear capability, which matters a lot for test isolation so one test's validators don't leak into another. And when no validators are registered the validate call is just a no-op, does nothing and passes.
