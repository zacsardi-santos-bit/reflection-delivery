I'm chasing down flaky tests in our suite and it keeps coming back to database state leaking between tests. When one test creates a table or a view or a trigger, that stuff sticks around and quietly messes up whatever runs next, so results aren't deterministic and it's a pain to debug. There's no standard way right now to tear down or reset the db between tests, and no way to give separately loaded module instances their own fresh database.

I want a new file at the database layer with a pair of helpers. The first one closes all active test database connections and clears the internal registry that tracks them, so the goal is after I call it and reset the module cache, re-importing the database module gives me a completely fresh, isolated db with zero leftover schema or data from any previous instance. The second takes a single database client and resets it to clean by dropping every user-created table, view, and trigger, but leave indexes alone. Identifiers need to be escaped properly so names with special chars like double-quotes don't blow up, and once everything's dropped it has to re-enable foreign key enforcement as the very last step, even if some of the earlier drops throw.

Also the existing function that opens a db connection needs to register each new connection into that tracking registry whenever we're running in a test environment, otherwise the close helper won't know what to actually clean up. That registration bit is what ties the whole thing together.
