I'm trying to make HTML and CSS actually behave like first-class module types in webpack when the experiments are on, and right now they don't. The big gap: when someone enables the HTML or CSS experiment and points an entry at a bare directory, webpack won't find an HTML or CSS index file the way it happily finds a JS index file by default. So I want enabling the HTML experiment to automatically add the HTML extension into the resolve extension lookup lists, and same deal for CSS adding its extension, so an extensionless entry can resolve to an index.html or index.css. Oh and one priority rule: when a directory has both an HTML index and a JS index sitting there, the HTML one should win over the JS one.

Second thing, when an HTML file is used directly as the entry point and it has references to scripts and stylesheets inside it, webpack needs to run those referenced assets through the normal bundling pipeline and then rewrite the emitted HTML so it points at the actual output chunk filenames instead of the original source paths. That rewriting isn't working correctly today and it should.

Also the CLI flag description for the HTML experiment currently claims the feature doesn't support HTML files as direct entry points, which is backwards from what we're building. Once this is fixed that description needs updating to say HTML files are a first-class module type usable directly as entry points. Developers expect to drop an index HTML into their source dir and have it just get picked up like a JS index does, so let's make it work through the standard resolution mechanism.
