I'm digging through our Java HTTP framework and the load balancing strategies (round-robin, weighted round-robin, weighted random, sticky hashing, and gradual weight ramp-up aka slow-start) are all welded to a specific internal endpoint type inside the client endpoint selection package. I can't reuse any of it elsewhere, like in the xDS/service discovery integration layer that has its own candidate objects, without dragging the whole endpoint selection plumbing along. I want these pulled out into a new generic, type-agnostic package so the algorithms work over any candidate type.

The plan: one factory class exposing static factory methods, one per strategy. Each takes a list of typed candidates. For the weighted variants (weighted round-robin, weighted random) the caller passes a weight-extraction function instead of us assuming an endpoint type; for sticky the caller passes a hash function computed over the request context. The round-robin and weighted ones should share a consistent pick interface that returns null when there are no candidates available, and sticky needs to consistently route the same context value to the same candidate across repeated calls.

For ramp-up specifically I want a builder API that takes the initial candidate list at construction and exposes an explicit method to update the candidate list over time, instead of relying on some side-channel from an endpoint group. Oh and there's a real bug here: right now new candidates get their weight field mutated during the ramp-up window, so if a caller reads a candidate's weight mid-ramp they see a lower value than originally configured, and it stays wrong. The ramp-up logic should track effective weights internally and leave the original candidate's weight untouched the whole time, so after ramp-up completes the reported weight matches what was configured. Also make sure the builders for these new load balancer classes show up in the framework's builder return-type registry. The point of all this is to stop duplicating selection logic across subsystems and make composing new endpoint groups (like xDS-backed ones) easy without reimplementing the algorithms.
