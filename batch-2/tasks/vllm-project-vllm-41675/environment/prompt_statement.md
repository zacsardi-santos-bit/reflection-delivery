I'm working on the ROCm optimized all-reduce path in vLLM and I want to add two config knobs so I stop having to patch source to tune it. Right now the minimum tensor size that flips a tensor onto the optimized path comes entirely from a hardcoded lookup table keyed by dtype, world size, and quant level, and there's no way to override it, plus the quantization codec always runs regardless of tensor size even when the tensor's small enough that the quant overhead probably isn't worth it.

So I want two environment variables driving this. One expressed in megabytes overrides the minimum tensor size needed to use the optimized all-reduce path, and when it's unset the existing built-in threshold table just keeps working like today. The other one, expressed in kilobytes, sets a minimum size below which we skip quantization and send full precision instead, and at or above that threshold we keep using the configured codec. Important thing here: tweaking the quant threshold must not change which tensors are eligible for the optimized path at all, it only controls whether quantization applies once they're on it. So eligibility and the quant decision stay independent.

Both need validation too. Negative values should raise an error, and the megabyte size override should also error out when it exceeds the effective maximum size. Read these values through the existing env-var infrastructure (the same mechanism vLLM already uses for env lookups), and give me a way to clear any cached environment state so tests can reset between runs. When either variable is unset, don't change any current behavior. The point of all this is letting people trade off communication bandwidth against quantization overhead for their own models and hardware without editing code, so a workload with lots of small tensors can drop quantization on those while still riding the optimized all-reduce path for the big ones.
