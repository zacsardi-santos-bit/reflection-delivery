I'm on the Google Chronicle Backstory integration and I want to add content type support to the reference list commands plus a whole new command for validating list content before committing anything. Right now when you create or update a reference list there's no way to say what kind of content it'll hold, even though the API handles different types like plain text, CIDR network address ranges, and regex pattern-based formats. So I'd like an optional content type argument on both the create and update commands, and if someone passes a value that isn't one of those recognized types it should reject it with a helpful error message that actually lists the valid options.

Also the current validation on the lines argument is way too lenient. Stuff that looks non-empty but has no real entries (an empty array representation like brackets with nothing inside, or a string that's just separators) slips through without complaint. I want those caught, so after splitting and filtering the lines input, if there isn't at least one actual entry left it should fail with a clear missing-argument style error. Same content type validation applies here too.

Oh and the new command, it should let users validate their list content against a content type without creating or modifying anything. It takes lines and a content type, calls the API's validation endpoint, and returns either a success message when everything's valid or a table showing which line numbers have issues and what those issues are. The same lines validation and content type checks I mentioned apply to this verify command as well. The integration code lives under the Google Chronicle Backstory pack, so wire all this into wherever the reference list create and update commands already are.
