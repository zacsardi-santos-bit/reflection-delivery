I'm working on snapshot garbage collection in our distributed object store and I keep hitting a race problem. When we process deleted keys or directory entries to figure out if they can be reclaimed from storage, we need to check whether those keys still exist in any of the preceding snapshots in the chain, and right now there's no way to do that atomically. The garbage collector can race with snapshot lifecycle events like additions or deletions, which leads to wrong reclamation decisions and that could mean data loss or plain inconsistency.

What I want is a reusable filter component living in the snapshot filter package that handles this consistently. Given the current snapshot context and the number of previous snapshots to consider, it should decide whether a key is reclaimable, and when it evaluates a key it should automatically load and acquire locks on the required previous snapshots in the chain. I want it generic so subclasses can plug in the logic for pulling the volume and bucket name out of a key, plus the actual reclaimability determination given the loaded snapshot context.

There are a few edge cases it's gotta get right. If the current snapshot's volume or bucket doesn't match the key being evaluated, it should fail with a clear error message that names the mismatch. If any previous snapshot it needs to load is no longer active (say it got deleted), it should fail rather than operate on a stale chain. If any previous snapshot still has uncommitted changes that haven't been flushed to disk yet, it should fail immediately to avoid premature reclamation. And if the snapshot chain changes mid-processing, like a new snapshot gets added while it's working a key, it should detect that and re-initialize before finishing the check. Oh and we also need a brand new lock resource type specifically for this snapshot garbage collection lock, since it's got different characteristics than the existing snapshot lock. The whole point here is giving GC a stable, consistent view of the chain so it doesn't reclaim data an active snapshot still references or fail silently when a snapshot goes away.
