I'm building out a browser automation sub-agent and I need to bolt some safety controls onto the sensitive stuff. Right now the browser agent can fill forms, run scripts, and upload files totally silently with no user in the loop, which feels sketchy for production. I want two new config options. The first requires manual user confirmation before the agent does anything sensitive, meaning form fills, script evaluation, and file uploads all get a confirmation prompt before they proceed. The second one is stricter, it hard-blocks any file upload attempt outright, and when it's blocked the agent should get back a clear error message instead of the upload just quietly going through. Oh and read-only operations like taking screenshots or listing the open pages should be auto-allowed without ever prompting, since I don't want to give people confirmation fatigue on harmless stuff.

There's also a related bug in the permission engine I keep hitting. When a tool permission check comes in using the short unqualified tool name plus a server name, the engine can't match it against permission rules that were registered with the fully qualified naming convention (the one with the server prefix baked in). So right now permission rules for the browser sub-agent tools get silently missed whenever the check hands over the short-form name, which means rules I thought were governing those tools just get bypassed. I want the matching to resolve correctly so a short name plus server name lines up against the qualified-name rule, and sub-agent tools stay properly governed no matter which form the name shows up in during the check.
