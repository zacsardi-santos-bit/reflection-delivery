I'm trying to get us off a few tiny deprecated npm packages we still lean on for terminal stuff, three of them actually, one that detects whether the terminal supports Unicode, one that figures out the terminal's color depth, and one that spits out ANSI/VT100 escape sequences for cursor control, colors, and display manipulation. They're all unmaintained now so they're just sitting there as audit warnings and maintenance risk with no upstream fixes coming, and since the logic is small and self-contained I want to inline them as local TypeScript modules inside the existing gauge directory and then repoint every file that currently imports the external versions at these local ones. Bonus is we can finally add real types too.

For the Unicode one, make it a named export (not default), it should check the OS type and just return false on Windows, otherwise walk the locale env vars in priority order and match the UTF-8 encoding variant case-insensitively to decide if the terminal's on UTF-8.

The color-support module needs to export both the detection function and its result type. The result is a structured object with a numeric level field plus individual boolean flags for each tier, basic color, 256 colors, and 16-million colors. Detection should look at the stream's TTY status, the OS platform, a bunch of env vars for terminal emulators and CI systems, and the TERM variable pattern, and land on one of no color, basic, 256, or 16 million.

The terminal control strings module should export a separate function per operation: cursor movement in all six directions with an optional count, erase operations, hide and show cursor, horizontal absolute positioning which should throw when no column's given, color/style application which should throw on an unknown style name, absolute cursor positioning, moving to start of line, and emitting a beep character. Keep the runtime behavior identical to what the deprecated packages did, just local and typed now.
