I'm building an experimental browser automation subagent for our CLI tool and need it wired up from scratch so users can navigate sites, fill forms, click buttons, and pull data without doing it by hand. The idea is the agent talks to Chrome through a protocol-based MCP server, reads pages via the accessibility tree, and optionally calls a separate visual model to analyze screenshots when something can't be found in the tree (like an element identified by color or position).

I need a browser manager class that launches and manages the MCP server connection, using the raw underlying SDK client directly instead of routing through the main tool registry. It has to support three session modes passing the right flags to the server process: persistent (the default, keeps the profile/cookies/history between runs), isolated (clean temp profile), and existing (attaches to an already-running browser). When connections fail I want clear actionable errors, so if persistent fails because the browser's already using the profile, tell the user to close Chrome windows and suggest isolated mode, and if existing-mode fails, guide them to enable remote debugging (and handle timeouts sensibly too).

Also need a tool wrapper that converts the dynamically discovered MCP tools into the agent framework's format, always adding a composite typing tool on top of the discovered ones, with invocations showing confirmation dialogs that name the browser MCP service and publishing policy updates to the message bus when confirmed. Then a screenshot analysis tool that grabs the current screenshot, sends it to the configured visual model, and returns the result, with distinct descriptive messages for when no image is captured, the model returns empty, the model's unavailable (permission or not-found errors), or any other error.

Wrap it all with a factory function that assembles a complete agent definition; when a visual model's configured it includes the screenshot tool and updates the system prompt to mention visual identification, and without one the prompt and tool list omit visual stuff entirely. Oh and a config method that reads the browser settings section (session mode, headless flag, profile path, visual model) returning defaults of persistent, non-headless, no profile path, no visual model. Finally a simple invocation class wrapping the agent with a default tool name, truncating long descriptions to a reasonable max length, and always reporting an empty set of tool locations.
