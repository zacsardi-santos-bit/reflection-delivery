I'm cleaning up the iOS physical-device debugging setup in the Flutter tools and I keep hitting the version-specific branching that decides which commands to send to the debugger session. Right now the setup code inspects the installed version of the development tools (Xcode basically) and picks one command sequence for older versions and a different one for newer ones. I want to kill that branching entirely and just send a single consistent sequence for everyone, doesn't matter what version is installed.

While I'm in there, there's this annoying upstream bug in the debugger engine where breakpoints intermittently fail to rearm after they fire, so sessions on real devices end up unreliable. The workaround is to send an extra config command during session setup that turns off async execution mode in the debugger, so add that to the setup sequence.

Oh and as part of this, the objects that set up the debug session shouldn't need to know about or carry around the development tool version at all anymore, so drop that dependency (constructor args, fields, whatever's threading the version through). Also the code that detects a successful session start keys off the debugger's output, and since the command sequence is changing the output changes too, so update that detection to match what the new sequence actually produces. Keep it all behaving correctly end to end.
