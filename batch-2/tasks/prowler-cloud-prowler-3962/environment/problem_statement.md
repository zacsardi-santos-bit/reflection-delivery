I'm poking at our cloud security scanner and I've hit two related but separate issues with how we handle internet-exposed firewall rules, and I want both sorted out.

First problem: the check that's supposed to flag any port open to the internet has broken logic. Right now it only fires when all ports are open (basically a wildcard protocol rule covering all traffic), so a security group that opens just a single specific port like port 80 to the internet gets reported as compliant, which is wrong. On top of that its status messages say "all ports open" when the intent is really "at least one port open," so the wording is misleading too. I need that existing any-port check fixed so even one specific port exposed to the internet gets flagged as non-compliant, with messaging corrected to reflect "at least one port" instead of "all ports."

Second, there's no dedicated check for the nastiest case, a firewall rule that opens all ports to the internet through a wildcard protocol setting. That's distinctly more critical than any single port being exposed and security teams need to triage it separately, so I want a brand new check just for the all-ports-open scenario. It should only trigger for rules that cover all traffic, not a single specific port, so a security group with only port 80 open to the internet should pass this new one (while still getting caught by the any-port check).

Both checks also need to respect the "ignore unused services" setting, so when a VPC has no resources attached, its security groups get skipped. Oh and there's supporting utility work too, the helper that decides whether any port is accessible from the internet needs to correctly handle the "all traffic" protocol type so the any-port logic actually works.

The why here is that conflating "all ports open" with "any port open" gives us false negatives (individual exposed ports slip through) plus confusing findings, so splitting them into two distinct checks lets teams hit the worst misconfigs first while still surfacing everything that's internet-reachable.
