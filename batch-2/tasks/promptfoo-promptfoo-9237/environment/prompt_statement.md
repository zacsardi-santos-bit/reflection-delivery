I'm working through our xAI provider integration and hit a few gaps I need cleaned up. First thing, the new Grok 4.3 family (both `grok-4.3` and `grok-4.3-latest`) isn't flagged as supporting reasoning effort control, so when I set a reasoning effort param it gets silently dropped. I want those recognized as supporting it and the effort preserved in the request, but the stuff that genuinely isn't supported on the Grok 4.x line, presence penalty, frequency penalty, and stop sequences, should still get filtered out for 4.3 too.

There's also a pricing bug. A pile of older slugs (various Grok 3 and Grok 4 variants including the fast ones, betas, and some dated slug variants) return wrong or missing cost estimates. I want all of them to fall through to Grok 4.3 pricing, which comes out to about $3.75 per million tokens on both input and output.

On images, xAI shipped new "quality" variants of their image gen models. I need those registered as valid identifiers, and the "latest" plus dated aliases for the quality model should route to the canonical quality slug when we actually make the API call. Anything unknown or future should pass through unchanged instead of getting redirected to a default. Quality costs $0.05 per generation and $0.07 for editing (when there's resolution config or source images), oh and the pro model's edit cost should follow the quality tier at around $0.06.

Last thing, streaming with reasoning models is leaking internal reasoning summaries into the visible output. The output text should only be the final answer, reasoning kept separate. Also, annotations on the completed response event need to show up in the result metadata, non-message tool call items like web search calls should be kept in the output not dropped, encrypted reasoning content should be reachable in the raw response data without appearing in visible output, and if a malformed event shows up mid-stream we should fall back to the completed response text rather than returning truncated output. Token usage from the completed event needs to map correctly onto the result's token usage fields too.
