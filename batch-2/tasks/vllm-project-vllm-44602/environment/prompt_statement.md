I'm poking at the Anthropic-compatible API endpoint in vllm and hit a real problem with how we convert system-role messages that show up inline inside the messages array. Right now when a client sticks system instructions inline in the conversation (instead of the separate top-level system field), the server yanks all those inline entries out of their spots, concatenates them with any top-level system prompt, and jams the merged blob at the very front of the message list. That hoist-and-merge behavior is wrecking KV-cache prefix caching, because reordering and merging changes the conversation prefix between turns so the model loses its cached state and recomputes work it should've been able to reuse. Throughput and latency both suffer.

What I want is for the conversion logic to leave each inline system message right where it is in the conversation, no hoisting. If there are multiple inline system messages they each stay as separate independent entries at their own positions, don't merge them into one. And if a top-level system prompt is provided it should keep showing up first with its content untouched, so don't go appending inline stuff onto it. Oh, and there's billing metadata that gets injected as inline system messages, I need that stripped silently: if an inline entry is only metadata, drop the whole message, but if it mixes metadata with real instructions, just strip the metadata part and keep the real content in place at its original position. The relevant conversion happens in the Anthropic serving path (see `@vllm/entrypoints/openai/serving_anthropic.py` or wherever that request-to-messages conversion lives). Keeping positions stable is the whole point, it keeps the prefix cache effective across turns.
