I'm on the Keras PyTorch backend for training and I'm stuck when it comes to deployment. I need to ship trained models into environments that only have PyTorch available, so what I really want is to export a trained model into PyTorch's native portable program format, a self-contained file that PyTorch can load and run natively with no Keras dependency at inference time. This matters a lot for production where binary size, startup time, and dependency management are real constraints.

So I want the model's export method to accept a new PyTorch format option that writes the model out as a portable program file (the `.pt2` extension), and the artifact should be loadable through PyTorch's own loading utilities and produce outputs numerically identical to the original Keras model. It's gotta work across a bunch of architectures: plain sequential pipelines, functional models including ones with skip connections or multiple outputs, subclassed models, and models with multiple inputs passed either as a list or as a dict of named inputs.

I also need to pass an explicit input shape spec when I want to, plus control whether strict tracing is used (models with data-dependent branching should raise a clear runtime error under strict export), and optionally declare dynamic batch dimensions so the exported thing handles variable batch sizes. Oh and validation matters here, if I pass export arguments that aren't supported it should raise a descriptive error telling me which args are wrong, and if the filepath doesn't use the right portable program extension it should error out too. Also common ops like tensor repetition, tensor slicing, and conv layers need to trace and run correctly through this export path.
