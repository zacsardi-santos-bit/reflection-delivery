I'm wiring up MLflow's automatic tracing for Amazon Bedrock and the spans it records right now use MLflow-specific attribute keys, which makes it a pain to interoperate with other observability tools that expect the OpenTelemetry Generative AI semantic conventions. What I want is a mode where, when Bedrock autolog is on and I've turned on the standard GenAI convention format, the span for a model inference call captures everything under the standard attribute keys instead of the proprietary ones.

Concretely that means the operation name, the model identifier, the inference params (temperature, max tokens, top-p), the input and output messages, and token usage all land under the standard GenAI keys. Input and output messages should serialize as structured JSON arrays where each message has a role plus a list of typed content parts, each part carrying a type indicator and its content value. Text is the easy case. For images in messages I need them converted into a base64-encoded blob representation with modality, MIME type, and content fields, but if the image bytes are already an encoded string it should just pass through unchanged.

Tool calls in assistant messages get their own dedicated content type marking a tool invocation, including the tool's ID, name, and arguments. Tool results similarly get a distinct content type for a tool response, with the tool call ID and the result serialized as a JSON string. Tool definitions sent along with the request should be captured under the right attribute key stored flat, so don't wrap them in an extra nesting layer. System instructions should show up as a serialized array of typed content parts too.

Oh and the important bit: when this standardized mode is active, the span attributes shouldn't include any proprietary MLflow-prefixed keys at all, only the standard GenAI convention keys should appear. The Bedrock autolog integration lives in the aws/bedrock tracing area of the mlflow package, so the changes go there. The point of all this is to line up Bedrock traces with the OpenTelemetry GenAI conventions so teams can run them through standard observability pipelines, compare traces across providers, and keep a consistent telemetry schema in production.
