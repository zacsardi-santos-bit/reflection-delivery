Our CI test runner's failure output is rough to read and I want to clean it up so it's actually actionable. Right now when a batch of tests fails it just references the batch by a number (like "failed test batch 0") without naming the test that actually failed, and it dumps the full raw stdout and stderr. Worse, if the same test fails a few times before a retry succeeds or we give up, the error details get repeated for every attempt, and there's no clear signal about which test caused a timeout or crash.

Here's what I'm after. When a failure happens I want it to name the specific test file that failed instead of a batch number. For wrong-result query failures I want a concise summary line, something like "expected X, got Y; Mismatch on row ..." plus a short snippet of the relevant test code so I can see what was being checked. For timeouts, use progress info if it's available to find the first test that started but didn't finish and call that out as the likely culprit, and if there's no progress info, fall back to naming the last test in the batch. For fatal signal crashes (segfaults and the like showing up in stdout) I want the last test that was in progress named. When a test recovers on retry I want that clearly indicated with the retry count and the failure details shown only once, not once per attempt. And the final failure output when all retries are exhausted should be compact, so no "### failed test batch" header and no "attempts:" header cluttering it up.

Also I'd like the parsing logic pulled out as a standalone function that takes a message, stdout, stderr, and the batch list and returns the formatted lines plus a reproduce batch. And similarly the test snippet rendering should be its own function that reads a test file at a given line number and returns formatted output with the target line highlighted and the blank edges trimmed off. The idea is developers shouldn't have to sift through huge raw output blocks to figure out what broke and which test to rerun locally.
