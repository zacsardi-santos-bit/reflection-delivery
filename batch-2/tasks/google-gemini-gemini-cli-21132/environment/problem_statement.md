I'm building a browser automation agent and I keep hitting this problem where nothing stops a user from clicking around or typing into forms while the agent is mid-action, which corrupts the work and causes race conditions. I want an input-blocking overlay that gets injected into the page right before the agent does any interactive operation, and then removed once it's done. The overlay should show a visible message telling the user that automation is in control so they get a clear signal to keep their hands off.

Couple of important things. The overlay has to be transparent to accessibility tooling, so hidden from the accessibility tree, so it doesn't mess with screen readers or accessibility snapshots. Also the blocking should only kick in for interactive, state-changing actions (clicking, typing, that kind of thing) and not for read-only stuff like taking a screenshot, those shouldn't trigger any blocking at all. I want a new module that owns injecting and removing this overlay, and the blocking wrapper in the tool execution pipeline needs to accept a flag so I can enable or disable the whole feature.

Oh and this is the critical bit: even if the automated action throws or fails partway through, the input blocker must always get removed so the user never ends up permanently locked out of the browser. And failures in the injecting or removing of the blocker itself should be handled silently, they can't crash the agent or interrupt the tool execution flow.
