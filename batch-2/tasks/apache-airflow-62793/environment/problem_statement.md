I'm building an LLM-powered schema comparison feature for the Apache Airflow common AI provider and could use your help wiring it up. The problem it solves: Airflow has no built-in way to detect schema drift when you're migrating or syncing data between different systems (say PostgreSQL to Snowflake, or an S3 Parquet file against a relational table), so teams hit silent failures or data corruption when a column type changes or a column gets added or dropped in one place but not the other. I want a new operator that connects to two or more data sources, any mix of relational databases and file-based cloud storage, introspects their schemas automatically, and delegates to an LLM to spot mismatches.

The operator needs two context modes: a basic mode that only looks at column names and types, and a full mode that also pulls primary keys, foreign keys, and indexes. For database sources users give connection identifiers plus table names, and for file-based sources they pass data source configuration objects, and both can be combined, but there always have to be at least two sources total, so please raise a clear error if fewer than two are given or if required params are missing.

It should build a system prompt that frames the LLM as a schema comparison expert, includes the gathered schema context, and optionally appends extra user-provided instructions, then return a dictionary with fields for compatibility status, a list of mismatches, and a summary string.

Oh and I also want a task decorator form of the same thing so a dev can write a plain Python function that returns the comparison prompt at runtime, and the decorator should validate the function returns a non-empty string and fail with a descriptive error if it returns anything else. This all lives in the common AI provider so put it alongside the other operators there. The whole point is teams can drop schema validation gates into their DAGs without writing system-specific introspection code every time.
