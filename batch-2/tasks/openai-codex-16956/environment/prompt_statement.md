I'm chasing a bug in the security review piece of our Rust codebase, the bit that renders a transcript of recent conversation history so a human or automated reviewer can evaluate what happened. The problem is when a user sends a bunch of large messages, the transcript renderer ends up dropping the most recent tool calls and their results to stay under the token budget, which is exactly backwards. Those tool entries (the last shell command that got run and its output) are the whole point of the review, and yet older user messages get kept while the actual tool activity gets omitted. Security reviewers lean on seeing what the agent actually did to make an approval call, so losing that undermines the whole thing.

What I want is for the renderer to always preserve the most recent tool call and tool result entries, even when the user history on its own is big enough to fill the entire budget. If some entries still have to be dropped to fit the limit, I want a clear message returned saying that omission happened, so nobody's left guessing whether the transcript is complete.

Oh and separately, when the formatted output for a pending action truncates some large string field, I want that truncation point annotated with roughly how many tokens got omitted, so anyone reading it can tell whether a little got cut or most of the content is gone. Right now there's no signal at all, which makes it impossible to gauge how much is missing when debugging or auditing the pipeline.
