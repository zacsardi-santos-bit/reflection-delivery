I'm poking at the CLI's table renderer and markdown in cells is rendering as raw syntax, so instead of seeing styled bold text people just get the literal asterisks, italic shows the underscores, and strikethrough, inline code, links, and underline tags all leak through as raw strings too. On top of that the column widths are computed off the raw markdown string lengths rather than the actual visible text, so once a cell has any markdown in it the layout goes misaligned, columns end up wider or narrower than they should be.

What I want is a standalone utility function that takes inline markdown text and returns a string with proper terminal formatting applied via ANSI escape codes for bold, italic, bold-italic, strikethrough, underline, links (including bare URLs), and code highlighting. It should accept an optional default color for the text, supporting both named colors and hex values, but inline code should always use a dedicated accent color and link URLs should always use the link color no matter what default gets passed in. Markdown syntax that appears inside an inline code span needs to be treated as literal text and not parsed at all. Oh and it's gotta handle nesting, like bold text that contains italic content.

Once that utility exists I want the table renderer to actually use it so markdown in cell content renders properly, and importantly the column width calculation should be based on the visible text length after markdown is stripped instead of the raw markdown string. The point of pulling this out as its own function (not buried in the component-based rendering) is so other non-component parts of the codebase can produce consistently styled terminal output too, not just the table.
