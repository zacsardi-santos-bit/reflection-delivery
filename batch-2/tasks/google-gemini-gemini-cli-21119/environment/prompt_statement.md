I'm working on the browser automation feature and hit a couple of privacy gaps I want to close. Right now the browser agent just launches without ever asking users whether they consent to the data collection and privacy implications involved, there's no notice shown on first run at all. I want to add a consent check that shows a privacy notice before the browser agent starts, something that explains what data may be collected and how it's handled, and includes a reference to the applicable privacy policy so people can actually go read it. Users need to actively accept before the browser agent proceeds. If they accept, save that choice so we don't nag them again on later runs. If they decline, the browser agent shouldn't proceed at all, just stop there. Oh and for non-interactive environments (scripted or headless where there's no UI to show a prompt), the notice should be auto-accepted so automated workflows don't get blocked waiting on input that'll never come.

Also, separate but related, the browser agent needs to respect the existing usage statistics preference. When a user has already opted out of usage stats in their global settings, that choice is currently just ignored when the browser runs, the underlying browser process keeps collecting telemetry regardless. I want it so when someone's opted out, we launch the browser process with the appropriate flags to disable its built-in telemetry and performance data collection, so that privacy preference gets enforced consistently across components instead of browser automation being the odd one out. Basically transparency plus a real point of control, and existing preferences honored everywhere.
