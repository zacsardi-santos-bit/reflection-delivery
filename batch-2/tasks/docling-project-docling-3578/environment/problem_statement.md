I'm building out the high-level document conversion client for our conversion service and hit a wall with external artifact storage. Right now the client only knows how to pull the converted doc inline from the server response body, but when the server is set up to store artifacts externally it hands back temporary pre-signed download URLs instead, and the client just can't deal with those at all. Users on that config basically can't use the high-level API, results are totally inaccessible, so I need to fix this.

What I want is for a conversion submit to try the pre-signed URL path first, and if the server doesn't support it, automatically retry the traditional inline approach. When the server does give back download URLs, grab the most complete artifact available, so prefer a resource bundle (a ZIP with the document plus all its images) over a bare standalone document JSON file. After downloading the bundle, extract it and embed all the referenced images straight into the in-memory document so the caller gets a fully self-contained result. The batch conversion method needs to support this same pre-signed materialization path too, and it's gotta return results in the original input order.

Two security guardrails I really need: reject any download URL pointing at private or internal network addresses (don't want the client acting as a proxy into internal infra), and reject image references inside a bundle that escape the bundle's own directory (prevents arbitrary local file reads). Both of these should turn into a clean failure result with an informative message, not some unexpected exception blowing up.

And generally any failure along the way, a server-side conversion error on a specific doc, a failed download, or a security check violation, should degrade gracefully. When the caller opts out of error propagation the result carries a failure status with a descriptive error message, and when the caller wants strict error handling a conversion error gets raised instead. Basically the client should handle both server configs transparently while keeping those guardrails in place.
