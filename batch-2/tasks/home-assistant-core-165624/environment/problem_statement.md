I've got a Roborock Q10 S5+ that uses the newer push-based protocol and the Home Assistant Roborock integration just doesn't know what to do with it. The device shows up fine in my Roborock account, but no vacuum entity ever gets created in HA, so I can't automate or monitor it at all. I want the integration to add support for this device family so these vacuums register as proper vacuum entities with the right entity ID and capabilities.

It should handle the standard controls, so start, pause, stop, return to base, locate, fan speed, and sending custom commands. The fan speeds I need are off, quiet, balanced, turbo, max, and max plus. If I pass an invalid fan speed or some command it doesn't recognize, I'd want a validation error raised rather than a silent no-op or a crash, and if the device itself fails to respond because of a comms error, that error should bubble up properly.

The whole point of this family is push-based status updates instead of polling, so the entity state should update in real time whenever the device reports a change, showing docked when it's charging, cleaning when it's actively sweeping, and returning when it's heading back to the dock. If the device status isn't available, the entity should just report unknown. Oh and when HA manually requests a refresh, the integration should go ask the device for fresh status data, but the entity state doesn't have to change synchronously off that call.

Also the device should show up in the diagnostics panel like the other Roborock devices, with the sensitive fields (local key, device name) redacted properly. This lets folks with Q10-series vacuums finally pull them into their dashboards and cleaning automations alongside everything else.
