I'm hitting a gap with webpack's HTML entry point stuff plus the experimental CSS support. When I write an HTML file as an entry and one of its script tags points to a JS file that imports CSS, webpack compiles and emits the CSS to disk fine, but the generated HTML never gets a stylesheet link tag for it, so the browser just never loads the styles. What I want is for the processed HTML to include a stylesheet link for every CSS chunk that's associated with a JavaScript entry in that HTML file.

There's a related thing with security attributes too. My script tags carry attributes for content security policy (a nonce), cross-origin mode, and referrer policy, and if webpack's going to auto-generate the stylesheet link tags then those same security and fetch attributes need to copy over to the link tags, otherwise the browser blocks the stylesheet in a strict CSP setup (that missing nonce is the killer). But script-only attributes like deferred loading markers and integrity hashes shouldn't carry over, since they don't apply to stylesheets.

Ordering matters too. When the CSS optimizer splits CSS into multiple separate chunk files, I want one stylesheet link per CSS chunk and they should appear in the same order as the original CSS imports in the JS source. And all the stylesheet links should come before any script tags, since scripts should load after styles.

It gets trickier with mixed entries. If an HTML entry both directly links a stylesheet and uses a script that imports more CSS, the authored link should stay first, the JS-bundle CSS link comes after it, and the script comes last. And when I'm using a separate runtime chunk plus a vendor split chunk, the runtime script needs to be first, vendor second, and the entry chunk last, while all the stylesheet links still precede the scripts. Without this fix, apps on webpack's HTML entry pipeline with JS-imported CSS silently drop their styles from the browser's loading, which is rough.
