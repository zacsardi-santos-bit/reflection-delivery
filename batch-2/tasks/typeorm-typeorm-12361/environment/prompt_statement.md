I'm adding a new v1 codemod transform to our TypeORM codemod package for a breaking change that keeps biting people, the file-based query logger (the file logger you import from TypeORM) now resolves log file paths relative to the current working directory instead of the app root, so any project that isn't started from its root folder will silently write logs to the wrong spot after upgrading and folks won't notice unless they audit every instantiation by hand, which nobody does in a big codebase.

So I want a transform that scans source files, finds every instantiation of that file logger, and drops a warning comment immediately before it, but only when the log path might actually be affected. Concretely that means warn when no log path is given at all, when the path is a relative string, or when the path option is null or undefined. Don't add a warning when the path is already absolute (unaffected), when the options come from a dynamic variable (can't statically tell), or when the options object is only spreads.

Oh and it's gotta handle all the import styles, named imports, aliased imports, namespace imports, and CommonJS require patterns, and it should leave files completely untouched if the logger is imported from some other package entirely (not TypeORM). Also if one statement has multiple logger instantiations, still just one warning comment on that statement, not one per instance.

Please follow the same conventions as the other v1 transforms in the codemod package so it plugs into the existing transform runner and test infrastructure the same way the others do.
