I'm looking at how Storybook's create-story-file feature builds new story files and there's a security-ish bug that's been bugging me. When it generates the TypeScript/JavaScript source it just drops the component's file path straight into the output, so if that path has special characters in it (single quotes, double quotes, backticks, dollar signs, backslashes) they land verbatim in the generated code. That can break the syntax of the file, and worst case it's a code injection vector, like a path with a single quote can close the import string early and then whatever follows gets injected into the generated story.

What I want is a small utility that escapes these characters before they're interpolated into any generated code template. It needs to handle backslashes, single quotes, double quotes, backticks, and dollar signs, and it's got to escape backslashes first, before the other substitutions run, otherwise the backslashes we add for the other characters get double-escaped and everything gets mangled. Normal file paths that don't contain any of those special chars should come through totally unchanged, and it should also handle any combo of multiple special characters together correctly.

Put this in its own module under the server utilities so it can be reused anywhere we embed strings into generated code, not just the story-file path case.
