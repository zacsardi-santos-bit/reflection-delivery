I'm messing with the Noir toolchain, specifically how we control whether circuit execution prints stuff during test runs, and the current setup is way too blunt. Right now it's just a boolean, either everything blasts to stdout or it all gets swallowed, and there's no way to grab that output into a buffer. I need the buffer path because when I run tests in parallel the printed output ends up interleaved and unreadable, and what I actually want is to capture each test's output and show it cleanly after that test's results come in.

So I want to swap that boolean out for a real output-mode type with at least three variants: one that suppresses output entirely, one that sends it straight to standard output, and one that captures into a string buffer the caller hands in (so the type needs to carry that mutable string reference for the capture case). That type has to be publicly re-exported from the library crate so existing callers can import it directly.

Both the default foreign-call executor constructor and the test-running function need updating to take this new type instead of the old true/false. And then go through every existing call site in the codebase and pass whichever variant preserves the behavior it had before, so nothing changes functionally except the ones I'll wire up to capture later. The point is making parallel test output collection actually possible instead of forcing a choice between real-time interleaved spam and discarding everything.
