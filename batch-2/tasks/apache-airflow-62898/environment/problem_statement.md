I'm working in Airflow's AI operator integrations and I need to add a human-in-the-loop approval gate for LLM-generated output. Right now when an operator generates text or a SQL query, the result flows straight to the next step with no chance for human oversight, correction, or rejection, and teams end up building ad-hoc review stuff outside Airflow and losing auditability. I want operators to optionally suspend after generating output and wait for an explicit human decision before the task completes.

Here's the flow I'm after: the approval should be opt-in via a flag on the operator that defaults to off so existing usage is untouched. When it's on, the task pauses and presents the generated output to a reviewer with a subject and body, where the body defaults to something that includes the task name and the original prompt. The reviewer picks from "Approve" or "Reject". Approve returns the output and the task continues normally. Reject fails the task with a message that identifies who rejected it. There's also an optional modify mode where the reviewer can edit the output before approving, and in that case the task returns their modified version instead of the original. Oh and I want a configurable timeout so if nobody responds within the window the task fails with a timeout error.

For the SQL-specific operator, the generated query needs to be safety-validated before it ever gets presented, so an unsafe query fails immediately without going to the reviewer at all. And if the reviewer edits the SQL and submits a modified version, that modified version has to be re-validated too before it's accepted. Also structured outputs like typed data models should be automatically serialized into a human-readable form before being sent for review. Basically this matters most for executable SQL and content that goes straight to end users, so the human quality gate needs to be real.
