I'm using the OpenTelemetry instrumentation for the VertexAI generative AI SDK and I've noticed that tool/function calling interactions are completely invisible in the telemetry. When the model responds by requesting function calls, the emitted telemetry events contain no information about those requests. And when my application sends function results back to the model as part of a multi-turn conversation, no events are emitted at all for those tool responses.

I'd like the instrumentation to capture both sides of the tool use cycle. When the model asks for a function to be called, that request — along with the function name and arguments (when content capture is enabled) — should appear as structured data in the response event. When my application sends function results back to the model, a dedicated event should be emitted for each result, including the function name, a generated identifier, and the response content (when content capture is enabled). Additionally, a turn that consists purely of function results should not incorrectly emit a separate user message event, since it's already covered by the tool message events.

This is important for observability in agent-style workloads where understanding the tool use cycle is critical for debugging.
