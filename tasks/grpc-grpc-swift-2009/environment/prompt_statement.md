I'm working with gRPC Swift's code generator and finding that the generated client code is more verbose than it needs to be. Right now, every time I want to make an RPC call — even a simple unary one — I have to manually construct a request wrapper object, pass it to the method, and then extract the response from the response wrapper. It would be much nicer if the generated code included convenience methods that let me just pass the message directly.

Concretely, I'd like the generator to produce an additional extension on each service's client protocol that wraps each RPC method with a more ergonomic signature. For unary and client-streaming methods that return a single response, the convenience method should have a default response handler that just returns the response value, so I can call the method and get the response back directly. For server-streaming and bidirectional-streaming methods, the handler should be required (since there's no single "message" to return). For methods that accept a stream of requests, the convenience variant should take a producer closure rather than requiring me to build a streaming request object.

The generated extension should carry the same platform availability constraints as the rest of the generated code, use the same access level, and be present even for services with no methods. All generated files across the codebase should be updated to include these new convenience methods. Additionally, the code renderer needs to support rendering dictionary literal syntax so that the empty metadata default can be rendered correctly in the new method signatures.
