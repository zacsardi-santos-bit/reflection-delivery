We have a task scheduling system that manages algorithm containers on a cluster. When the cluster rejects a job creation request due to invalid container configuration — for example when a sidecar container has resource requests that exceed its declared limits — the current code silently discards the error and nothing gets reported. Pipeline nodes that depend on those algorithms just silently fail to start, with no error message anywhere.

I need the system to properly detect when a job creation call returns a failure status code, capture that error, and record it in the unscheduled algorithms tracking data with a user-friendly message. The raw error from the infrastructure layer contains internal path expressions like indexed container references that aren't readable by end users — these should be rewritten to use the actual container name and cleaned up. The failure should also be marked as one that surpasses the scheduling timeout threshold, so the pipeline driver knows to immediately mark the affected nodes as failed rather than continuing to wait.

There's also a related naming issue: a boolean field in the scheduling warning objects was previously called something that implied capacity checking, but it really indicates whether the scheduling timeout has been exceeded. This should be renamed consistently across the codebase, including the API specification.

Finally, any scheduling failure with an invalid volume or a job creation failure should propagate the error message all the way to the pipeline node, so users can actually see what went wrong.
