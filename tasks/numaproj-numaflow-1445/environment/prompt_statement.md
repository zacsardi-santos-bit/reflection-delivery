I'm working on two related improvements to the streaming pipeline framework and need help implementing them.

First, all three windowing strategies — fixed, session, and sliding — need their constructors updated to accept a vertex instance as an additional parameter. Right now each windower is created with just the timing configuration (e.g., window duration or gap), but there's no way to associate the windower with the vertex and pipeline it runs on. I need to add a vertex instance parameter to each constructor so the windower can store that context for use in observability metrics.

Second, the built-in tick-based message generator needs a jitter configuration option. Currently it generates messages with deterministic event times, but for testing how the pipeline handles out-of-order messages, I want to be able to introduce random delays into the event timestamps. For example, setting a 10-second jitter should cause each generated message's event time to be delayed randomly between 0 and 10 seconds, making the messages appear to arrive out of order by up to 10 seconds. This jitter should be an optional field in the generator configuration, and when it is not set, behavior should remain exactly as before.

As part of this, the internal function that converts nanosecond timestamps to time values needs to be updated to accept the jitter duration as a second parameter. When jitter is zero, the function should behave exactly as before — returning the exact time for valid timestamps and the current time for invalid ones. The existing approach of parsing event time from the JSON payload should be replaced with a direct approach where the event time is known at generation time.
