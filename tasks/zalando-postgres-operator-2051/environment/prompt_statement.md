I'm working with the postgres-operator and I need to be able to inject environment variables from a Kubernetes secret into the logical backup cronjobs it generates. Right now there's no way to do this — backup jobs only get a fixed set of environment variables, and I can't pass in cloud credentials or custom values from an existing secret without hacking around it.

I'd like the operator to support a new configuration option that accepts the name of a Kubernetes secret. When configured, every key in that secret should be automatically surfaced as an environment variable in the backup cronjob, with the value pulled from the secret rather than embedded directly. If no secret is configured, the behavior should stay exactly as it is today. If the secret name is set but the secret doesn't exist in the cluster, the operator should report a clear error instead of silently producing a broken job.
