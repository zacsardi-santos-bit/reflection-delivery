I'm working on a gRPC service generation tool that takes a GraphQL schema as input and generates protobuf and mapping files. Right now the tool doesn't validate the schema at all before generating output, which means developers get no feedback when their schema uses patterns that aren't supported. Sometimes generation just silently produces wrong output; other times it fails in a confusing place.

I'd like to add a validation layer that runs before any files are generated. The validation should distinguish between two kinds of issues. Some issues — like nullable items inside list types, or the use of directives that are planned but not yet implemented — should produce warnings and let generation continue normally. Other issues — like nested key references that can't be properly mapped to the generated code — should be treated as hard errors that stop generation entirely, producing no output files at all. If a schema has both warnings and errors, the errors should still cause a full stop.

The validation logic itself should be encapsulated in a dedicated visitor class that takes the schema string, walks it, and returns separate collections of errors and warnings. The generate command should then call into this validator and decide whether to continue or abort based on the result.
