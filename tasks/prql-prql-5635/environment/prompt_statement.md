I'm working with PRQL and ran into a bug where grouping the entire table with no partition columns causes the sort order inside the group to be silently dropped from the generated SQL. When I use a group with no partition and specify a sort along with a row limit inside it, the resulting SQL includes the limit but completely omits the ordering clause. This makes the query non-deterministic, which is clearly wrong. An empty group should treat its inner pipeline as applying to the full table, meaning any sort specified inside should appear as an ORDER BY in the output SQL. Can this be fixed?
