I'm working on refactoring the PowerShell extension's debugger attach feature. Right now, when a user attaches the debugger to a PowerShell host process, the debug configuration resolver handles picking the process and the runspace by dispatching to external VS Code commands registered by two separate standalone classes. This indirection through the command system makes the code harder to follow and particularly hard to test in isolation.

I'd like to consolidate the process-picker and runspace-picker logic directly into the main debug session feature class as private methods, and have the debug configuration resolver call those methods on itself rather than routing through external commands. The two standalone picker classes should be removed once their functionality is absorbed.

The key behaviors to preserve: if no process identifier is specified, the feature should prompt the user to pick one; if the user cancels, the attach should be aborted. Likewise, if no runspace identifier is specified, the feature should prompt with the resolved process ID; if the user cancels, the attach should be aborted. The constructor should also be updated to register the relevant VS Code commands (so that command substitutions in debug configurations continue to work), meaning tests that repeatedly instantiate the feature will need to account for command re-registration.
