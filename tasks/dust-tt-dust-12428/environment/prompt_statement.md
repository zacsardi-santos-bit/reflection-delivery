I've noticed that our file management API doesn't enforce any role-based permissions for write operations. Right now, any authenticated user — even one with the most basic workspace access — can upload content to or delete files that belong to workspace-level storage, like folder documents. This feels like a security gap: those kinds of files should really only be modifiable by users who have builder-level access or above.

Conversation-related file attachments should stay open to everyone since users need to freely attach and manage files in chat, but anything outside of the conversation context should be gated. I'd like the endpoints that handle file uploads and deletions to check whether the caller has builder permissions before allowing the operation on non-conversation files. If they don't have builder access and the file isn't a conversation file, the request should be rejected with an appropriate permission error.

This should apply to both the internal (session-based) API and the external (API key–based) API. For the public API, regular non-system keys should also be blocked from write operations on non-conversation file types, even before the builder check is applied.
