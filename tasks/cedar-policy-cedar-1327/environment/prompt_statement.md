I'm working with Cedar policies and I'd like the policy language to support checking the existence of a chain of nested optional attributes in a single expression — for example, verifying that an entity has a nested attribute path all at once, rather than writing a separate check for each level. The type checker should recognize that such a chained existence check fully guards the entire attribute path, so that subsequent access to that path typechecks cleanly. It should still correctly reject cases where the access goes deeper than what was actually guarded, or accesses a different attribute than the one that was checked, with precise error messages pointing to the problematic access expression.

I'd also like the code formatter to handle this new multi-level existence check syntax correctly — keeping it compact on one line when it's simple, expanding it with appropriate indentation when there are comments between the attribute segments, and wrapping when the attribute names are long.

Additionally, there's a related bug: when a reserved keyword is used as an attribute name in an existence check, the parse error currently points to the wrong source location (the whole surrounding expression) instead of just the reserved keyword itself, and the error message isn't consistent with other reserved-identifier errors. This should be fixed so the error location and message are accurate.
