I'm working on the rust-analyzer parser and running into an issue with how dynamic trait object types are recognized in older Rust editions. In those editions, the relevant keyword isn't reserved, so the parser has to use lookahead to decide when it's actually the start of a dynamic trait type. The current check is too narrow — it only looks for a limited set of following tokens and misses several valid forms: types that begin with a lifetime, types with a question mark prefix, types using a for-binder, and types wrapped in parentheses. Meanwhile, the cases where the keyword acts as a plain identifier (like when it's used as a module name in a path, or when it's followed by generic arguments using angle brackets) should NOT trigger dynamic trait type parsing.

I need to add a dedicated helper that correctly consolidates all of this lookahead logic in one place, so the parser properly classifies each of these syntactic forms. The existing parser test for weak dynamic trait types also needs to be expanded to cover all these cases, and the corresponding test data files need to be updated to reflect the correct parse tree output.
