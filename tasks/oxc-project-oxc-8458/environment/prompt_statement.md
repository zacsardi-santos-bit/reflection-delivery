I'm running into a bug in the TypeScript namespace transformer. When a TypeScript namespace contains an import alias — a local shorthand that points to a member of an outer module — the transformer is dropping these alias declarations completely, even when they are actively referenced as values inside the namespace body. This produces broken JavaScript because the variable no longer exists in the output when the code that uses it runs.

The correct behavior should be: if the alias is actually used as a value in the namespace body, keep it and convert it to a regular variable declaration. Only remove it if it has no value references (i.e., it is unused or only appears in a type annotation context). There should also be a mode where all such aliases are always preserved regardless of usage, controlled by an existing transformer option for preserving non-type imports. In either case, any type annotations on other declarations within the namespace must still be stripped from the output.
