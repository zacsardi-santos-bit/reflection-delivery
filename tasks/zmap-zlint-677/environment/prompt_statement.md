I'm working on a certificate linting tool that validates Tor onion address certificates. We currently have logic to detect version 3 Tor addresses, but there's a bug: when a certificate covers both a version 3 Tor hidden service address and regular domain names (which is totally valid — think of a company that has both a public website and a Tor hidden service), our linter incorrectly flags it as needing the older Tor service descriptor hash extension. That extension is only relevant for version 2 Tor addresses, not version 3.

The fix requires a few things. First, we need to add an explicit check for version 2 Tor addresses (the older format with a 16-character base32 label). Right now there's only a version 3 check. Second, the linting logic that decides whether a certificate needs the descriptor hash should be updated to directly check for version 2 addresses, rather than inferring it from the absence of version 3 addresses. Third, the helper function that checks whether all names in a list meet some condition currently returns false for an empty list — but the mathematically correct behavior for "all items satisfy the condition" over an empty set is true (vacuous truth), so this should be fixed as well.

We also need some test certificates: one representing a real certificate with both a version 3 onion address and regular domain names, and one with an address that is neither version 2 nor version 3 (to confirm errors are still reported for genuinely invalid onion addresses).
