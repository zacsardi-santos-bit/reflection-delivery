I'd like to add a time-to-live (TTL) feature to the analysis controller so that completed analysis runs are automatically deleted after a configurable retention period. Right now, finished runs just pile up in the cluster with no automatic cleanup.

The TTL policy should live on the analysis run itself and support three options: a general retention window that applies to any completed run regardless of outcome, and separate windows that apply only to successful or only to failed runs. When a phase-specific window is configured and the run's outcome matches, it should take precedence over the general completion window. A success window should never cause deletion of a failed run, and a failure window should never cause deletion of a successful run.

The controller should record the completion time when a run transitions to a finished state, and then check on each reconciliation whether the elapsed time since completion exceeds the configured TTL. If it does, the run should be deleted. Runs that are still in progress, have no TTL configured, already have a deletion marker, or have no recorded completion time should be left alone. If a deletion is attempted and the run is simply no longer found, that should be treated as a success. Any other deletion error should be surfaced as a warning log.
