I'm working on adding native histogram support to the querier layer in Cortex. Right now, when native histogram data (both integer and float histogram variants) is stored in block storage and queried through the store gateway path, the results are incorrect. The root issue seems to be in the batch iterator layer — when the query engine asks for a float histogram representation of a chunk that stores an integer histogram, the iterator doesn't handle that case properly and returns wrong data.

I need the query pipeline to fully support native histograms end-to-end: histogram series should be correctly retrieved from store gateways, overlapping histogram series from multiple gateways should be properly deduplicated and merged, and all the existing resource limits (chunks per query, byte limits, series limits, data byte limits) should apply equally to histogram chunks just as they do for regular float sample chunks.

There's also some test infrastructure that needs updating. The chunk generation utility needs to support generating chunks with custom labels so tests can create histogram chunks for specific label sets. There's also an obsolete function in the ingester client compatibility layer that should be removed since it's no longer used.

The querier tests should all run across the three chunk encoding types (regular float, native histogram, and native float histogram) rather than only testing against float encodings. Histogram-specific aggregation queries like summing or counting histogram data should also be covered, and the results should be validated per encoding type.
