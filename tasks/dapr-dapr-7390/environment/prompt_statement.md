I'm working on two related improvements in our runtime codebase. First, the universal API struct currently exposes several of its internal fields as public names, but these are really implementation details that should be private to the package. I'd like to make those fields private so the internal structure is better encapsulated and not part of the external contract.

Second, we have a security issue with how environment variable names are filtered when accessing secret stores. Right now, the checks that block sensitive or reserved variable names only work when the key matches exactly the expected casing — if someone uses a lowercase version of a blocked name like a reserved prefix or a sensitive token identifier, it slips through the filter. The filtering logic needs to be updated to be case-insensitive so that blocked names are denied regardless of how they are capitalized. Similarly, when an allowlist is in use, it should match entries regardless of case.
