I'm using automatic logging to track my Keras model training in MLflow, and I'd like it to automatically capture information about my early stopping configuration when I use an early stopping callback. Right now, nothing about the early stopping behavior shows up in my MLflow runs — no record of what patience setting I used, what metric was being monitored, or even which epoch training stopped at.

What I'd want to see is: when an early stopping callback is used, the patience and the monitored metric should automatically appear as run parameters. When training actually stops early and the best weights are restored, both the stopping epoch and the epoch that was restored should be logged as metrics. On top of that, an extra metric history entry should be appended representing the performance at the best (restored) epoch — so I can immediately compare the final model's quality in the metric timeline. If weights are not being restored, or if training completes all epochs without stopping, the restored epoch and extra entry shouldn't be added, but the stopping epoch (zero if no stop occurred) should still be recorded. And if I'm using a completely different kind of callback that has nothing to do with early stopping, none of this extra logging should happen at all.
