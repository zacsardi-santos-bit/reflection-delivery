I'm working on a monitoring metric in the raftstore layer of TiKV that tracks how many regions are using a feature allowing log entries to be applied before they are fully persisted. The problem is that the current metric is semantically inverted — it counts regions where this feature is disabled instead of where it's enabled, which is confusing for anyone reading cluster dashboards.

I need the metric to be renamed and inverted so it clearly represents the number of regions that have the feature actively enabled. The count should go up when a region enables the feature, and go down when a region destroys or disables it. Specifically, the metric should correctly reflect region lifecycle events: after initial writes, after a region split (where both sub-regions become active), and after a region merge (where one of the regions is destroyed and the count drops accordingly). The metric should also be publicly accessible from the metrics module so it can be referenced and verified from integration tests.
