I'm working on improving the Perseus test suite. A lot of tests that check renderer behavior — things like focus management, input path tracking, serialization, grading APIs, and event callbacks — currently rely on a real production input widget as a stand-in fixture. That creates a problem: whenever the production widget changes, tests that have nothing to do with that widget start failing.

I'd like to introduce a dedicated mock widget specifically for testing. It should be a minimal, self-contained widget that supports all the standard renderer APIs so existing tests can migrate to it, without being tied to any production widget's implementation details. The mock widget also needs to support generating prompt JSON for AI use cases, since we want to be able to test that pipeline too.

Part of this work involves creating the mock widget implementation and its prompt JSON utility, adding the necessary type definitions for its user input, creating test data items that use the mock widget, updating existing test fixtures and test data to use the mock widget instead of the production input widget, and moving related test utilities into a more appropriate location alongside the mock widget code.
