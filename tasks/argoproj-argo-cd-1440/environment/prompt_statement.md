I'm working on the ArgoCD project server and noticed a security gap in how project updates are authorized. Right now, if someone has permission to update a project, they can also remove cluster destinations or revoke source repository access from that project — even if they have no permissions on those clusters or repositories themselves. This effectively lets a restricted user bypass the cluster and repository permission model by going through the project update endpoint.

I'd like the project update logic to enforce proper permission checks before allowing these changes. Specifically, when a project update removes clusters from the allowed destinations, the caller should need cluster-update permission for each removed cluster. When source repositories are removed, the caller should need repository-update permission for each removed repo. And if the project's cluster-scoped resource allowlist or namespace-scoped resource blocklist changes, the caller should need cluster-update permission for each destination cluster in the project.

It would also be helpful to have a utility that determines which items have changed between two lists — specifically, a function that, given a combined list, returns only the elements that appear exactly once (i.e., elements unique to one side of the comparison). Additionally, I need a method on the project spec type that returns the list of cluster server URLs from the project's destination entries, so that destination clusters can be extracted and checked conveniently.
