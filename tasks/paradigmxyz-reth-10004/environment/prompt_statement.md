I'm working on cleaning up the trie layer in reth by moving database-specific implementations to the right package. Right now, cursor types that require direct database access are defined and exported from the general trie library, even though there's already a dedicated package for integrating the trie with the database. This makes the boundary between the two layers unclear.

I'd like to move the database-backed hashed cursor factory (and its account/storage cursor implementations) as well as the database-backed trie cursor factory (and its account/storage trie cursor implementations) out of the core trie library and into the database integration package. After the move, these types should be publicly re-exported from the database integration package so existing callers can update their imports, and they should no longer be available from the core trie library.

The integration tests for these types should also live in the database integration package, since they require an actual database to run. This includes tests verifying that the hashed account cursor correctly merges and orders entries from both the database and in-memory post-state (with post-state taking precedence and deleted entries excluded), that the hashed storage cursor correctly handles wiped storage and zero-value entry filtering, and that the trie cursor implementations work correctly with the trie walker for lexicographical traversal.
