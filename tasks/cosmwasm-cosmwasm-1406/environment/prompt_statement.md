I'm trying to make the CosmWasm VM test suite run on Windows, and one of the blockers is that the cache layer returns error messages that include OS-specific details about why a file operation failed. For example, when a WASM file doesn't exist on disk, the error message currently includes the raw operating system error string, which is different on Linux versus Windows. This means any test that checks the exact error message will fail on one platform or the other.

I need all file-system-related errors in the cache layer to use fixed, platform-independent error messages that do not include any OS-specific text. When a WASM file cannot be opened for reading, the error should say something simple and deterministic; same idea for file read failures and directory creation failures. Any existing code that currently expects the old OS-specific error format should also be updated to match the new standardized messages. The goal is that the error output is identical regardless of which OS the code runs on.
