I'm trying to use the join directive to populate a field on one type by selecting data from another type, but the path I need goes through an intermediate resolver type — not directly to a top-level query field. Right now it seems like joins only work when the target is a single top-level field. I'd like to be able to write a join that first calls an intermediate resolver with arguments taken from the parent object, and then selects a field on the result of that call (also with its own arguments). The variables from the parent object should be usable at any level of this nested path, and literal values should also be accepted as arguments. The final result of the whole chain should be the value returned by the innermost resolver. Is it possible to extend the join directive to support this kind of multi-level field selection path?
