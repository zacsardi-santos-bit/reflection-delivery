I'm working on adding support for listing repository autolinks in the GitHub CLI. Autolinks are reference patterns configured on a repository that expand short identifiers (like ticket numbers) into full external URLs. Right now there's no way to view these from the command line — you have to go to the repository settings in a browser.

I need a new subcommand that fetches and displays all the autolinks for a given repository. In an interactive terminal it should show a nicely formatted table with a header indicating how many autolinks were found, along with each autolink's ID, key prefix, URL template, and whether it is alphanumeric. When the output is being piped, it should produce tab-separated values without a header. There should also be a flag to output the data as JSON (with field selection support for the id, whether it's alphanumeric, the key prefix, and the URL template), and a flag to open the relevant settings page in the browser instead.

When no autolinks exist the command should let the user know nothing was found. When the API call fails due to missing permissions, the error message should mention that admin rights to the repository may be required.
