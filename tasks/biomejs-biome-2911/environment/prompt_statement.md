I'd like to add a new CSS lint rule to biome's nursery group that detects invalid direction values in gradient functions. The standard gradient function requires directions to use a prefix keyword before the directional word, while bare directional keywords without this prefix are non-standard and should be flagged. Angle values also need to include a proper unit suffix — a bare number without a unit is not valid, but one with a recognized unit suffix is. There's also a wrinkle with vendor-prefixed gradient variants: those functions use an older syntax where bare directional keywords are the correct form and using the prefix keyword is actually wrong, so the rule needs to handle them inversely.

The rule should be lenient about cases that are clearly not directions at all — if the first argument is a color value rather than a directional keyword or angle, no diagnostic should be raised. Similarly, directions that include color interpolation syntax should be treated as valid. The function name matching should be case-insensitive. When a violation is found, the diagnostic should tell the developer they have an unexpected nonstandard direction and point them to the relevant specification for reference. The rule needs to work correctly within multi-value background declarations that combine gradient functions with other values like image URLs.
