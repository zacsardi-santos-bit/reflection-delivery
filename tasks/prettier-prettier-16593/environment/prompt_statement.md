I've noticed that Prettier mishandles inline comments when formatting logical expressions inside unary expressions. For example, when I have a chain of conditions joined by OR operators, and each condition is followed by a comment like "// explains this condition", running Prettier moves the last comment away from its condition and wraps the whole thing in extra parentheses. That wasn't there before and changes how the code looks in a confusing way.

It seems like the issue is specific to when the logical expression is the argument of a unary operation. In those cases, trailing inline comments on the last operand end up getting attached to the wrong node during formatting. The fix should ensure that trailing comments stay with the operand they were written next to.

Beyond the basic case, the fix also needs to correctly handle more complex situations — like mixed AND and OR chains where precedence-based grouping is needed, nested parenthesized sub-expressions, and cases where a trailing block comment appears instead of a line comment. All of these patterns should be formatted correctly with comments in the right place, and the behavior should be consistent with and without semicolons across all supported parsers.
