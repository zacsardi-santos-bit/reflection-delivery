I'm working on a CLI tool that connects to external servers using OAuth. Right now the OAuth tokens we get after authenticating aren't saved anywhere on disk — they only live in memory. So every time the CLI restarts, users have to go through the authentication flow again even if their tokens haven't expired yet. This is really annoying when you're connecting to multiple servers.

I need a file-based token storage implementation that encrypts credentials before writing them to the user's home config directory. The encryption should use a key derived from the machine and current user identity, so the file can't just be copied to another machine and read. The storage should handle the full lifecycle: looking up a credential by server name (and returning nothing if it's already expired), saving or updating credentials while keeping other servers' entries intact, deleting individual entries (and removing the file entirely when the last entry is deleted), listing all stored server names, and clearing everything at once.

Error handling matters too. If the storage file doesn't exist when you try to read from it, it should throw a clear error saying the token file doesn't exist. If the file has been corrupted or can't be decrypted, it should throw a clear error saying the token file is corrupted. Clearing all tokens when the file doesn't exist should silently succeed rather than throw.

Also, I realized the base token storage class currently has a default service name, which means subclasses can accidentally end up sharing storage. The base class constructor should require the service name to be explicitly provided — no default.
