I'm working on the OTLP-to-Prometheus remote-write translation layer and need to add proper aggregation temporality support for histograms. Right now, the histogram conversion functions don't take temporality into account at all — they always produce the same output regardless of whether the source metric is cumulative or delta. Delta histograms should be marked as gauge-type in the output (meaning no counter reset assumed), while cumulative histograms should remain marked as unknown-reset counter-type metrics. I need the temporality to be threaded through as an explicit parameter to the internal histogram conversion functions.

Beyond the output format issue, I also need the top-level conversion function to validate temporality before converting each metric. A new configuration flag should be added to the conversion settings to control whether delta-temporality metrics are accepted. When a metric has delta temporality and delta is not allowed by the setting, the metric should be skipped and an error recorded. Metrics with unspecified temporality should always be rejected regardless of the setting. The conversion should continue for any remaining valid metrics in the batch — partial success with errors returned.

There's also a new boolean parameter that needs to be added to the API server constructor to expose a native delta histogram ingestion configuration option.
