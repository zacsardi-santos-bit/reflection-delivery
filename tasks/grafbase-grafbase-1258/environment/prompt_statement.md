I'm working on a federated GraphQL gateway and I've noticed a bug with how mutation errors are handled. When one of my upstream subgraphs returns a failure response for a mutation — null data along with an errors array describing what went wrong — the gateway is sending back two errors to the client instead of just one. One of those errors is a meaningful message from the upstream service, but the other is an internal "missing required field" message that the gateway generates when it tries to deserialize the null data against the expected schema.

This double-error response is confusing and incorrect. The upstream service clearly communicated the failure through its errors array, so there's no need to also report a schema validation issue. The expected behavior is that when an upstream subgraph returns null data together with explicit errors, only those upstream errors should be forwarded to the client. Any internally generated errors about missing required fields should be suppressed in that case.

Can you fix the federation gateway's response handling so that when an upstream mutation returns null data with a non-empty errors list, the response contains only the upstream errors — not additional internal validation noise?
