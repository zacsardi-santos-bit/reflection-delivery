I'm working on a procedural macro that expands a template match arm into multiple arms by substituting a list of type identifiers. It works great for the template arm itself, but I need to also support an optional wildcard arm after the template arm. Right now, if I include a catch-all branch (like one that panics as "unreachable") in my template input, the macro fails to parse it because it only expects exactly one arm.

What I'd like is for the macro to accept either one arm (just the template arm, as before) or two arms (the template arm followed by a wildcard arm). When a wildcard arm is present, it should be left untouched and appended to the end of the expanded match expression. The substituted arms should come first, and then the wildcard arm should follow — exactly as you'd write it by hand.
