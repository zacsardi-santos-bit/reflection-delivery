I'm working on a workflow automation system and running into a problem with how skipped jobs are handled. When a job is supposed to be skipped — because an upstream dependency was skipped due to a false condition — the engine still tries to expand the job's matrix strategy, including evaluating dynamic template expressions in the matrix values. If any of those expressions are invalid or can't be evaluated in the current context, the engine fails with an error instead of cleanly skipping the job. This leaves the workflow in a broken state rather than gracefully propagating the skip to downstream jobs and terminating with a "skipped" status.

I'd expect the system to detect that a job is going to be skipped before doing any matrix expansion work. If a job is being skipped (either because its dependency was skipped or its own condition is false), it should be recorded as a single skipped job entry without evaluating or interpolating the matrix at all. The same should apply when a skipped job references a job template — the template shouldn't be resolved. And if a job's matrix produces zero combinations (an empty list), the job should also be treated as skipped with a single recorded entry. In all these cases, any jobs that depend on the skipped job should also be skipped, and when all jobs are skipped the overall workflow run should end with a "skipped" status.
