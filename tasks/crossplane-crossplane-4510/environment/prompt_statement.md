I'm working on the composite resource definition CRD generation code in Crossplane and I've noticed that if a version's schema validation is nil — for example, if a developer forgets to configure it — the system doesn't handle this gracefully. Instead of getting a useful error message, the code fails in a confusing way. I'd like to add a nil check so that when schema validation is missing, the system returns a clear error that identifies the affected resource definition by name and type. The error should be wrapped with a descriptive message using the existing error format constant in the package. When schema validation is properly provided, including with an empty schema, things should continue to work as before.
