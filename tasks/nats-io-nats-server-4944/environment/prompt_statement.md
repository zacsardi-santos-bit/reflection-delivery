I'm running a NATS cluster with multiple gateway nodes, all configured to enforce certificate validity proofs on their gateway connections. When I rotate the TLS certificates used by the gateway connections on one of the servers and trigger a configuration reload, the gateway mesh stops working — other nodes can no longer connect to the reloaded server, and cross-cluster message routing breaks entirely.

It seems like the certificate validity monitors are not being restarted during the reload when TLS is only configured on the gateway (not on the main client listener). After the reload, the server can't prove the validity of its new certificates to connecting peers, so TLS handshakes fail. The monitors should always restart on any configuration reload so that newly rotated gateway certificates get fresh validity proofs and inter-cluster connectivity is preserved.
