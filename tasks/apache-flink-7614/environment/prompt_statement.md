I'm seeing resource leaks in the Flink Kafka consumer. When the consumer fails — for example, if partition discovery throws an exception, or if creating the internal fetcher fails — the partition discoverer component is never properly closed. The same issue occurs when the consumer is cancelled normally while running: the partition discoverer ends up not being shut down. I'd expect that no matter how the consumer stops (error or cancellation), the partition discoverer should always be closed. Additionally, in the case where the fetcher is actively running when the consumer stops, the partition discoverer should be woken up before it's closed, so any blocking operations are properly interrupted first.
