I'm working on the AI Gateway project and I've noticed the configuration has an inconsistent naming scheme for API schema fields. Right now, the gateway route resource uses one name for its schema field and the backend resource uses a completely different name for the same concept, even though both are just specifying which API schema to use. Inside both of those fields, the identifier is called one thing in Go structs but the naming feels redundant and asymmetric.

I'd like to unify this so that everywhere an API schema specification appears — whether on the gateway route, on a backend, or in the YAML filter config — it always uses the same field names. The containing object should always be called "schema" and the identifier within it should always be called "name". This change needs to be applied consistently across the Go types for both the filter configuration and the Kubernetes API types, the YAML configuration format, and the Kubernetes custom resource definitions including their validation rules. The validation error messages that reference these fields by path also need to reflect the new naming.
