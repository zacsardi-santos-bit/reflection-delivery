I'm working with DataFusion and I've defined some custom logical plan nodes to represent domain-specific query operations. The problem is that whenever I try to convert a logical plan that contains one of my custom extension nodes back to SQL, it fails with a not-implemented error. There's no way to tell the SQL converter how to handle my custom nodes.

I need a way to plug in custom conversion logic so the SQL generator knows what to do with my extension nodes. Specifically, I need to handle two cases: sometimes my custom node represents a full SQL statement by itself, and other times it appears as a relation inside a larger query and should be rendered as a subquery. The mechanism should let me register one or more handlers with the converter, where each handler can either handle the node or pass on it. The first handler that successfully handles the node should be used, and the remaining ones should be skipped. If no handler can deal with a node, the existing error behavior should be preserved.

Additionally, the internal types used to build SQL AST fragments need to be accessible to external code so that implementors can actually construct the SQL representations they need to return.
