I'm working with a tool that generates TypeScript client code from OpenAPI specifications. When the spec defines responses with description or summary text, that documentation doesn't make it into the generated TypeScript types — the response type definitions are emitted without any comments at all. This means developers using the generated client lose all the useful context that was in the spec.

I'd like the generator to carry those descriptions through. Specifically, when a response entry has both a summary and a description, the generated type should be preceded by a documentation comment block with the summary first, then a blank separator, then the description. When only a description is present, the comment should just contain the description. When neither is present, the current behavior should be kept and no comment generated.
