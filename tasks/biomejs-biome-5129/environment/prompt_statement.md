I'd like to add a new lint rule to Biome's nursery category that detects when developers await promises inside loop constructs. This is a common mistake that causes unintentional sequential execution — each loop iteration waits for the previous one to finish rather than running in parallel, which can be a significant performance problem.

The rule should warn whenever an await expression appears in a loop body or condition (including while loops, for-of, for-in, regular for loops, and do-while loops), and also when an async iteration statement is nested inside another synchronous loop. It should suggest using concurrent promise resolution as an alternative.

The rule needs to be smart about scoping: it should not flag awaits that appear inside nested function declarations, function expressions, arrow functions, or class methods defined within the loop body, because those create their own async context. It also shouldn't flag awaits in the iterable expression of a loop, in the initialization part of a for loop, or in the direct body of an async iteration loop (where the async iteration is intentional). When an async iteration loop contains an inner synchronous loop, though, awaits inside that inner loop should still be flagged.
