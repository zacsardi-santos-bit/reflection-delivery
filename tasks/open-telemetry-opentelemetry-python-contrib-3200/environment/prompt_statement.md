I'm using the OpenTelemetry botocore instrumentation with AWS Bedrock, but I'm only seeing telemetry for the higher-level conversational API. When my application calls models directly using the lower-level invocation API, those calls produce no GenAI attributes in my spans — no operation type, no token usage, no inference parameters, no completion reasons. The conversational API path is fully instrumented and shows all of this data, but the direct invocation path appears completely blind.

I use three different model families in my application — Amazon's Titan and Nova models as well as Anthropic's Claude — and each has its own distinct request and response format. I'd expect the instrumentation to automatically handle these differences, extracting the right fields from each model's request body (temperature, nucleus sampling probability, maximum token count, and stop sequences) and response (input/output token counts, finish reasons) to populate the standard telemetry attributes. I also need the response body to remain readable by my application after the instrumentation has processed it, since I use the model output downstream. When a call fails because I use an invalid model identifier, the error type should also be captured in the span so I can alert on it.
