I noticed that the parser doesn't emit any error when I write a binding-with-else statement where the initial value is a struct literal. Since struct literals end with a closing curly brace, the closing brace ends up sitting right before the else keyword — which is an ambiguous and disallowed construct. The parser should catch this and report an error at the position of that closing brace, with a message explaining that a right curly brace before else in a binding-with-else statement is not allowed. Ideally the parser would still recover and produce a valid parse tree even after the error, so that downstream analysis isn't broken. Could you add that diagnostic to the parser?
