I'm working with SeaTunnel's Debezium JSON format support and running into issues where data from several databases isn't being deserialized correctly. When I try to ingest change data capture events from MySQL, SQL Server, Oracle, and PostgreSQL through Debezium, many of the field values come out wrong or fail to parse.

The core problem is that each database connector encodes data types differently in its Debezium JSON output, and the current deserializer doesn't handle all these variations. For example, date and time values might be encoded as days since epoch, or as microsecond counts, or as nanosecond counts, or as ISO 8601 strings with timezone suffixes — and the exact encoding depends on both the connector and the specific column type. Oracle is especially tricky because its decimal/numeric types are represented as a structured object containing a base64-encoded binary value rather than a plain JSON number. Binary and bit fields are also base64-encoded and need type-appropriate conversion.

I need the deserializer to correctly handle all the major type encodings for each of these four databases, converting date and time fields to SeaTunnel's local date, local time, and local date-time types (stripping timezone info from ISO strings), and correctly converting decimal, binary, boolean, and numeric fields according to their source encoding.
