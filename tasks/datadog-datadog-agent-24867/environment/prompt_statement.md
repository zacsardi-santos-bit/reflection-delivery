We currently use a custom wrapper class to interact with the GitLab API through raw HTTP requests. This means we've had to hand-roll retry logic for server errors, manually parse JSON responses, and represent pipeline jobs as plain dictionaries throughout our notification and statistics tooling. I want to migrate this to use the official GitLab Python client library instead.

The migration should introduce a new module in our CI provider utilities that exposes a factory function for creating a configured API client, along with the existing functions for loading and resolving GitLab CI configuration files. The pipeline notification functions (for sending failure messages and stats) and the consistency checker should switch to using the new library client to list pipeline jobs and fetch job log traces, rather than making raw HTTP calls.

As part of this, all the places in the code that treat job objects as plain dictionaries need to be updated to use the library's job objects, with proper attribute access. Note that the job URL field in the library's objects uses a different attribute name than the key previously used in the dictionaries. The statistics update code that extracts job names from the failure list also needs to be updated to use attribute access.
