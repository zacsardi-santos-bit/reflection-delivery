I'm working on the Gleam compiler's JavaScript code generation for bit arrays, and I've discovered that endianness and signedness options don't work correctly when targeting JavaScript. When I write a bit array expression with a little-endian or big-endian qualifier on an integer segment, or use signed/unsigned options, the compiled JavaScript either ignores these qualifiers or generates code that doesn't respect the byte ordering. The same issue affects sized floats: 32-bit floats in bit arrays aren't supported as a general feature, and endianness for floats isn't handled either.

I need the JavaScript target to correctly support the full range of bit array options that work on other targets — specifically: little-endian and big-endian byte ordering for both integer and float segments (in both construction and pattern matching), signed and unsigned integer interpretation (in pattern matching), negative integers in sized segments producing correct two's complement bytes, and 32-bit float support as a standard (not target-specific) feature. The JavaScript runtime helpers that the compiler emits calls to need to be updated to accept and correctly use these endianness and signedness parameters.
