I'm working on a bundler that already has source map generation support, but the test fixture system has no way to opt into it. I'd like to add a simple boolean flag to the test configuration so that individual test fixtures can enable source map output. When a fixture enables this, the generated chunks should include the standard source map URL comment at the end of the code, and the test snapshot should reflect this.

I also need a utility that can take generated code and its source map and produce a human-readable visualization of the token-level mappings. The visualization should group entries by original source file, with each file identified by a header line, and each entry showing how a specific range of source text maps to a corresponding range in the generated output — including both position coordinates and the actual text content. This would let me verify that source maps are correct by reading the snapshot output.

When a fixture has source maps enabled, I want the test snapshot to include a dedicated section showing the sourcemap visualization for that build in addition to the generated code. The snapshot rendering should also be updated so that only chunk outputs appear in the main code section, not raw asset outputs.
