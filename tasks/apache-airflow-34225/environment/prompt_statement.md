I'm working on adding useful monitoring links to the EMR Serverless job operator in Airflow. Right now, when a serverless job starts, there are no clickable links in the task details to help users navigate to the job's logs or application UI. I'd like to add support for automatically generating those links based on what logging destinations are configured for the job.

Specifically, if the job is configured to send logs to S3, there should be a link in the task that takes the user straight to the right location in the S3 console for that job run. Similarly, if CloudWatch logging is enabled, there should be a direct link to the filtered CloudWatch log stream for that job. These should appear automatically without any extra configuration from the user.

I'd also like to add an opt-in feature where the operator can generate one-time live dashboard links — one for the Spark or Tez application UI, and one for Spark driver stdout logs (only for Spark jobs). These should be disabled by default because they are ephemeral and accessible to anyone with DAG access. Users should be able to enable them by passing a flag when constructing the operator.

The link generation for the dashboard and logs requires calling out to an AWS API to retrieve a temporary, authenticated URL. The helper that does this should accept either an existing client object or an AWS connection ID — but not both and not neither — and should raise a clear error if the wrong combination is provided. When a connection ID is given, the helper should create a client configured with a single retry attempt so that link generation fails fast rather than hanging.
