I'm working on a VS Code extension for running tests, and I've noticed that code coverage overlays don't work on Windows. After digging into it, I think the problem is that the extension normalizes file paths to use lowercase drive letters (to match how VS Code represents document paths internally), but this normalization only happens for test result paths — it completely misses the coverage map data. So when coverage comes back with paths like an uppercase drive letter variant, those paths don't match the editor's references and the overlay never displays.

I'd like to introduce dedicated utility functions that handle this path normalization for both the test results and the coverage map, and apply them together before the data gets used by the rest of the extension. On non-Windows systems the data should be passed through unchanged. On Windows, both the test result file names and the coverage map keys and their internal path fields should all be normalized to lowercase drive letters.

While I'm at it, I also want to clean up the module structure: the various test result types and utilities are currently scattered across several separate modules. I'd like to consolidate them into a single unified entry point so everything can be imported from one place. Additionally, the cache reset logic inside the test result provider should be pulled out into its own public method so it can be reused independently.
