I'm working on this build tool library and I'd like to refactor how executors are created. Right now, every call site that needs an executor has to explicitly list every field assignment by name. This is fragile — if internal field names change, or if we want to add defaults for certain fields, we have to touch every call site. It's also verbose, because you always have to list every field even if most of them have sensible zero values.

I'd like to introduce a constructor function that takes a variadic list of named option functions, applies them to a new executor with sensible defaults, and returns the configured executor. Each configuration knob (working directory, stdout/stderr/stdin writers, temp directories, force flags, network settings, verbose/silent/dry-run modes, concurrency, output style, etc.) would have its own dedicated option function with a consistent naming convention.

One specific improvement: right now, enabling verbose logging requires importing an internal logger package and constructing a logger object as a separate step. After this change, verbosity should be just another option function — no separate logger construction or import needed.

The new constructor should be a drop-in replacement for direct field initialization. All existing executor methods must continue to work the same way after it's used. A few fields that are only relevant in special scenarios (like terminal simulation during testing, or user working directory overrides) can remain directly settable on the returned value — they don't need their own option functions.
