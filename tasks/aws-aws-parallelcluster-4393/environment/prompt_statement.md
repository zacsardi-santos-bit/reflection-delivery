I'm working on the cluster update policy system and need to add special handling for managed placement groups. Right now, the update policy doesn't distinguish between placement groups that were automatically created and managed by the cluster versus placement groups that users explicitly provided by specifying a name or identifier. This matters because deleting a cluster-managed placement group while compute nodes are still running can cause serious problems.

I need to add logic that detects when a cluster configuration update would result in the deletion of a managed placement group — that is, one that has been enabled without any explicit user-provided name or identifier. When such a deletion is detected and the cluster still has running compute capacity, the update should be blocked and the user should be informed that all compute nodes must be stopped before the update can proceed.

The detection needs to handle both queue-level and compute-resource-level placement group configurations. The compute-resource-level setting should take priority over the queue-level setting when both are present. Placement groups that have a user-provided name or identifier should continue to go through the standard update strategy and should not be subject to this stricter requirement. When the cluster has no running capacity, the managed placement group deletion should be allowed to proceed normally.
