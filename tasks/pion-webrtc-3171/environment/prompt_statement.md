I'm working with the pion/webrtc library and I need to add support for H.265 (HEVC) video streams. Right now the library has support for H.264, but there's nothing equivalent for H.265. I need two new packages added.

The first is an H.265 bitstream reader that can take a raw Annex B stream as input and parse it into individual network access layer units one at a time. Each unit should have its header fields parsed — including the forbidden zero bit, the NAL unit type, the layer ID, and the temporal identifier. The reader should handle error cases properly: if the stream doesn't look like a valid H.265 stream, it should return an appropriate error; when the stream is exhausted, it should return end-of-file. The reader's internal state should track the current buffer of NAL bytes and the count of consecutive zero bytes seen, since that's how Annex B boundaries are detected.

The second is an H.265 RTP writer that accepts H.265 RTP packets and writes them to an underlying output destination in Annex B format, meaning each NAL unit gets the standard 4-byte start code prepended. The writer should also be able to identify key frames — including when the packet is a fragmentation unit (where the key frame type is encoded inside the fragmentation header) or an aggregation packet (where multiple NAL units are packed together and any one of them might be a key frame). Empty RTP payloads should be silently ignored without error. The writer should also expose a close method that cleans up gracefully even if the underlying destination doesn't support explicit closing.
