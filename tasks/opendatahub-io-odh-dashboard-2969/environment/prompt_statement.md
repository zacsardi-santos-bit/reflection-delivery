I'm working on refactoring the role binding permission management in our dashboard application. Right now, the types and the function that generates role binding objects are buried inside the project-sharing feature, which makes it impossible to reuse them for other permission management scenarios — like controlling access to model registries.

I need to move those shared types into a common concepts directory so other parts of the app can import them without depending on the project-sharing feature. The role binding generator function also needs to be renamed to reflect that it's now a general-purpose utility, and it needs to accept an additional argument for specifying the kind of role reference, since different use cases (projects vs. model registries) need different values there.

On top of that, the UI components that render the role binding tables and inputs need their test identifiers updated to use generic names rather than project-sharing-specific ones — this ensures the same components can be reused elsewhere.

Finally, I need a new page in the model registry settings section where platform administrators can manage which users and groups have access to a given model registry. This page should let admins add new users or groups, edit existing ones, and delete them. It should support table sorting. It must be restricted to admins only — other users should see a not-found page — and if the named registry doesn't exist, it should redirect back to the registry settings list. The role bindings created from this page need model-registry-specific labels and role references.
