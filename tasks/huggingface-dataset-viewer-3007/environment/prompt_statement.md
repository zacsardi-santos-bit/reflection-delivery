I'm working on the dataset viewer statistics feature and need to add support for datetime and timestamp columns. Right now, the statistics endpoint handles numeric, string, categorical, boolean, list, audio, and image columns — but when a dataset has date or timestamp columns, nothing gets computed for them. I'd like to add a new column type for datetime data that computes min, max, mean, median, and standard deviation of the datetime values, along with a histogram of how the values are distributed over time. The min/max/mean/median should be returned as human-readable datetime strings (precision up to seconds), the standard deviation as a time duration string, and the histogram bin edges should also be datetime strings rather than numbers.

Timezone-aware timestamps should preserve the timezone offset in all output strings. Columns where all values are null should return null for all statistical fields.

I also want to handle string columns that happen to contain datetime values. When a string column consistently uses a single recognizable date/time format, it should be automatically detected and processed as a datetime column instead of being treated as generic text. This should be controlled by a feature flag on the string column handler, defaulting to off. If a string column has mixed or unrecognizable date formats, it should gracefully fall back to the regular string statistics.
