I'm working on adding support for self-managed signing keys to the signing configuration workflow in cosign. Right now, if I try to sign a blob or create an attestation using a signing configuration with my own key (from a hardware security module, a key management service, or a key file on disk), the tool immediately rejects it and tells me only ephemeral keys are supported. I need to lift that restriction.

The core piece I need is a new adapter in the internal key package that wraps any existing signer/verifier so it can be plugged into the signing pipeline's keypair interface. The adapter needs to support ECDSA, RSA, and ED25519 keys — returning a clear error for anything else — and expose the key algorithm string, a public key hint (computed from a hash of the public key bytes), the hash algorithm, the PEM-encoded public key, and a way to sign data that returns both the signature and the digest. When the underlying signer returns an error during signing, that error should be passed through unchanged. Errors during public key retrieval should include context about what operation failed.
