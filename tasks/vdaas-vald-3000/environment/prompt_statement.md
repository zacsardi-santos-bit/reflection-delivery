I'm working with our internal JSON path evaluation library and running into some significant limitations. The library can navigate to specific named fields and count elements, but it doesn't support wildcards, numeric array indexing, or aggregation functions, which makes it really painful to work with.

For example, I have nested objects where I want to collect a particular field from every sub-object without knowing the key names ahead of time — like gathering a "stored" count from each entry in a map of items. Right now there's no way to do that in a single path expression. Similarly, I need to access array elements by their position (e.g. the first element) and sum up numeric values distributed across multiple keys in an object.

What I'd like the library to support is a wildcard operator that fans out across all values in an object or array, the ability to chain that wildcard with further path segments, numeric indexing into arrays, and a sum aggregation function. When wildcards produce multiple nested results, they should be flattened into a single flat list. For maps, the wildcard should return values in a consistent alphabetical key order so that results are deterministic regardless of internal map ordering.
