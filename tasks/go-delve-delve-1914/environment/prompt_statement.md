I'm working on adding goroutine listing support to the Delve DAP server. Right now, when a debugging client asks which goroutines are currently running, the server just returns an error saying the command isn't supported. This is a problem because listing active threads is a required part of the debug protocol — even a minimal implementation needs to return at least a dummy placeholder entry when real goroutine info isn't available yet.

I need the server to properly handle these requests: when stopped at a breakpoint it should return the actual goroutines with their IDs and current function names, during early startup when goroutine data hasn't been populated yet it should return a single placeholder entry, and when the program has already finished it should return an empty list.

On the client side, I also need to add the ability to send goroutine listing requests and stack trace requests, as well as methods to read back the corresponding responses. I also noticed that the client's request numbering starts at 0, but VS Code actually starts at 1 — so that needs to be corrected too. And the client is currently logging raw messages to stdout during every send, which should be cleaned up.
