I'm working on improving how Kargo Projects are initialized. Right now, when a Project is created, the reconciler and webhook each handle namespace setup in a single undifferentiated block. This makes it hard to distinguish between transient failures (where a retry could succeed) and permanent failures (like a genuine namespace conflict). The project status doesn't reflect this distinction — everything ends up either ready or in the same generic error state.

I also need to add logic so that when a Project is created, the system automatically grants the Kargo API server permission to manage secrets within that project's namespace. This should happen both in the webhook (synchronously, at creation time) and in the management controller reconciler. The role binding that grants this access should be created idempotently — if it already exists, that's fine.

Specifically, I want to refactor the initialization into two distinct steps: one for namespace setup, and one for setting up secret management permissions. The reconciler's main sync function should orchestrate these two steps and only mark the project as ready once both succeed. The namespace step should NOT mark the project as ready on its own — that final phase transition belongs in the orchestrating function. The namespace step should set the project phase to permanently failed only when there's an unrecoverable conflict, and leave it in the initializing state for any other error.

Both the controller reconciler and the webhook need configuration (specifically, the Kargo system namespace) to know where to bind the service account when creating the role binding. This configuration should come from environment variables.
