I'm working on the Hummock storage test suite and finding that every test function requires a huge amount of repetitive setup code — manually wiring together sstable stores, event handlers, version readers, meta clients, and local storage — before I can get to any actual test logic. It's hard to read, easy to get wrong, and inconsistent across the codebase.

I'd like to introduce a reusable test environment helper that wraps all this standard setup into a single async function and returns a struct that holds the storage instance, the manager reference, and the mock meta client. The struct should provide convenience methods for the most common test operations: registering a table by its numeric ID, registering a table using full catalog metadata, and committing an epoch (which should internally take care of sealing, syncing, committing to the meta service, and waiting for the epoch to be visible). The storage object itself should also expose methods for sealing an epoch with an explicit checkpoint flag, sealing-and-syncing an epoch in one call, retrieving the version reader, and waiting for a given epoch to become observable.

At the same time, I want to rename a few existing test utility functions to follow a clearer, more consistent naming convention that signals they are test-only utilities. The old names like the notification client helper and the table registration helper should be updated everywhere they are used across the test files.

Finally, the existing storage tests should be updated to use the new helper and to operate on a specific non-default table ID so that reads and writes are associated with a properly registered table.
