I'm working on the GC safe point management system and need to add support for per-service safe points. Right now the system only handles a single global safe point, but we have multiple services — like the core GC worker, a change-data-capture service, and a backup service — each with their own minimum data boundary. I need a way for each service to register and update its own safe point so that the system can track which service currently holds the overall minimum.

There are a few important constraints. The core GC worker service is special: it must always be registered with a permanent (non-expiring) duration. If someone tries to register it with a finite duration, that should be rejected with an error. A negative duration should be treated as a removal request — the update should not be applied, but no error should be returned either. Also, trying to register a safe point value below the current overall minimum should be silently rejected, since data at that level may already have been garbage collected.

Additionally, the system should automatically seed the GC worker service with a safe point of zero when the first service registers, so there's always a floor. The constructor for the safe point manager also needs to be exported so it can be used from outside its package.
