I'm seeing a reconciliation loop in our operator on OpenShift. The platform automatically adds image pull secrets to service accounts, but when our operator reconciles those service accounts, it wipes out the image pull secrets that the platform injected. Then the platform adds them back, which triggers our operator to reconcile again, and the cycle continues endlessly.

We already have logic to preserve regular secrets on service accounts during updates — if the existing object has secrets that our desired state doesn't include, we keep the existing ones. I need the same protection applied to image pull secrets: when the current service account has image pull secrets and our desired state has none, we should carry the existing image pull secrets forward instead of removing them. This would prevent the loop and avoid interfering with whatever the platform is managing on those service accounts.
