We're refactoring how authentication state is managed in our app. Right now, the session token, its expiration, and scopes are stored in a centralized application store and components all over the app connect to that store just to check whether someone is logged in or whether an admin is impersonating a customer. It's overcomplicated and makes tests painful — every component test that touches authentication needs a custom store setup.

I'd like to replace all of this with a simple utility module that reads and writes auth token data directly to local storage. The module needs functions to get the current token (returning an object with the token string, expiration, and scopes), set a new token, and clear it — with "clear" meaning all fields reset to empty strings rather than null. There should also be a function that checks whether the currently-logged-in session belongs to an admin impersonating a customer, which can be determined from the token value itself.

The logout component and the OAuth callback component should both be updated to use this new utility rather than dispatching store actions or accepting store-connected props. The logout component should take no props and just clear the session and initiate logout on mount. The OAuth callback component should also take no props — it reads the current URL location when mounted — and on a successful code exchange should store the token (formatted with a bearer prefix), expiration, and scopes via the new utility. On any failure, it should clear the session and send the user to the login server's logout endpoint.

When the API returns an unauthorized response, the error handler should clear the session token and redirect to the login page. After token expiration in the parent/child account switching flow, users should land on the login page rather than the logout page.
