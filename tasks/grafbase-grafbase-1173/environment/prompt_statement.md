I need to implement a GraphQL schema diffing library that can compare two versions of a schema and report the differences in a structured way. The library should take two schema strings as input and return a sorted list of changes, where each change has a kind (what type of modification occurred) and a path (which element in the schema was affected, using dot-separated notation).

The kinds of changes that need to be detected include: adding or removing object types, adding or removing fields on object types, interfaces, and input types, changing a field's type, adding or removing interface implementations on types, adding or removing enum types and their values, adding or removing union types and their members, adding or removing directive definitions, changes to the schema-level root type assignments (query, mutation, subscription), adding or removing the schema definition block itself, adding or removing field arguments, changing a field argument's type, and adding, removing, or changing default values on field arguments.

The sort order for results should prioritize schema-level changes first, then type-level changes, then field-level changes. When a type changes its fundamental kind (for example, when an object type is replaced by an enum with the same name), the diff should report both the removal of the old kind and the addition of the new kind. Field-level changes that belong to a type that was entirely removed should not also be reported as individual field removals — only the type removal itself should appear.
