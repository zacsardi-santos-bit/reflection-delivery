I'm working on hardening our GraphQL server against malicious introspection queries. Right now, we have some basic protections that detect when a client makes the same introspection request multiple times in one query, but there are gaps. For example, a bad actor can bypass the detection by using aliases to repeat the same introspection field — that's currently not caught. Also, we have no way to limit how many fields a query can contain in total, so a client can craft a massive query that bloats memory usage before we even execute it. On top of that, if someone sends a deeply nested introspection query (many levels of nesting, not just a shallow repeated field), we don't stop it hard enough — it just keeps running.

What I need is: a configurable maximum field count when building the normalized representation of an operation, so that if the count is exceeded the process is aborted immediately with a clear message. I'd also like the resulting operation object to expose the total field count and the maximum depth that were observed, so I can use those numbers for monitoring. The existing introspection depth check should also be able to abort execution hard (not just raise a soft validation error) for deeply nested queries. And the alias-based repetition of introspection fields should be treated the same as unaliased repetition when deciding whether a query is acting in bad faith.

There should also be publicly accessible constants that define what the library considers the maximum acceptable field count and depth for a good-faith introspection query, and the standard introspection query shipped with the library should fall within those limits.
