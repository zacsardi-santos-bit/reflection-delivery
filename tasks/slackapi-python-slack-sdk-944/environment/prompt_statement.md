I'm working with the Slack SDK's audit log and user directory (SCIM) response classes and I've noticed that any fields in the API response that the SDK doesn't explicitly model are just silently dropped. This makes the SDK fragile against API evolution — if Slack adds a new field to a response, I have no way to access it until the SDK adds explicit support.

I'd like the response model classes to preserve unrecognized fields in a dedicated attribute, so that developers can still access new or unexpected API data without waiting for an SDK update. This should work for audit log response objects at every level — the top-level response, individual log entries, and response metadata sections.

For the user directory (SCIM) response objects, the same behavior is needed: unknown fields should be captured in a dedicated attribute with the keys stored in the standard Python naming convention (snake_case). Additionally, when converting these objects back to a dictionary, the unknown fields should appear with their original camelCase key names restored, so the output remains compatible with the API format. The existing field that served a similar purpose in SCIM user objects should also be renamed for consistency.
