I'm running into issues with how the multi-stage query engine handles ingest operations (INSERT and REPLACE) that produce zero rows. There are two related problems I need to fix.

The first is that empty ingest queries don't work gracefully. When an INSERT or REPLACE produces no rows — because a WHERE clause filters everything out, or because of a LIMIT that results in zero matches — the operation should complete successfully rather than failing. For INSERT, that means just doing nothing. For REPLACE, it should still delete existing data in the overwrite range by creating tombstone markers, but if there's nothing to overwrite, it should simply be a no-op. I also need a query context flag that users can set to make the system intentionally fail when an empty ingest occurs, for cases where zero rows should be treated as an error.

The second problem is a bug in how tombstone intervals are computed for REPLACE operations when existing segments span all of time. Currently, if an existing segment covers the entire representable time range (eternity) and the replace operation also covers eternity, the code produces wrong tombstone intervals instead of a single tombstone covering all of time. This bug needs to be fixed so that REPLACE operations on such segments generate the correct eternity-spanning tombstone.
