I'm working on the Datadog exporter for OpenTelemetry Collector and I need to add support for an alternative hostname resolution mode. Right now, the exporter determines hostnames from resource attributes using a single fixed strategy for all cloud providers. The problem is that this produces different hostnames than what Datadog's native cloud integrations report, which makes correlating data between the two pipelines very difficult.

I'd like the hostname resolution functions — for the cloud-specific packages (AWS EC2, Azure, GCP) and the top-level resolution logic — to each accept an additional boolean flag that selects the alternative resolution mode. When this flag is enabled, the behavior should change as follows: for Azure and EC2, the host's unique cloud identifier should be used as the primary hostname rather than the human-readable host name; for GCP, the hostname should use a combined format of the short host name and cloud account/project identifier. In all cases when the alternative mode is active, the integration-format hostname should be the primary hostname and should not additionally appear in the host aliases list (since it's already the primary hostname). Container IDs should also be excluded from consideration as hostnames in this alternative mode.

When the flag is not set, all existing hostname resolution behavior should remain unchanged.
