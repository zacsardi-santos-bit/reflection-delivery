I'm working on a distributed tracing library and I've hit a limitation with how spans are parented. Right now, every span I create automatically becomes a child of whatever span is currently executing in the thread context. That means I have no way to create a root span while I'm already inside another span, and I also can't explicitly declare that a new span should be a child of some specific previously-created span other than the current one.

I'd like to add the ability to specify an explicit parent when creating a span. Concretely, I want to be able to say "this span has no parent — it's a root" even when I'm inside another span, and also "this span's parent is this specific span" regardless of what's currently executing. Spans created without any explicit parent specification should keep working as before, inheriting from context automatically.

On the subscriber side, when a new span is being created, the subscriber needs to be able to tell whether the span is an explicit root, has an explicit parent, or is using contextual parenting. The subscriber should receive enough information to distinguish all three cases and, in the case of an explicit parent, to identify which span is the designated parent.
