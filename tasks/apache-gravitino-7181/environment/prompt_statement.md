I'm working on an entity caching layer in Gravitino and need a new cache key class that can represent two kinds of cache entries: one for a directly stored entity, and one for an entity's relational associations (like "which groups does this role have?"). The key needs to hold a name identifier, an entity type, and an optional relationship type together as a single immutable object.

The key should produce a human-readable string that encodes all its components — the identifier parts joined by dots, followed by the entity type's short name, and, if a relationship type is present, also the relationship type's name — all separated by colons. When no relationship type is present, that component should simply be omitted from the string.

When creating the key, it should reject null values for the identifier and entity type by throwing an appropriate exception, but it should accept a null relationship type for entries that represent directly stored (non-relational) entities. It also needs to correctly implement equality and hashing based on all three fields, so that two keys with the same identifier, entity type, and relationship type compare as equal and hash the same way, while any difference in any of those three fields makes the keys unequal.
