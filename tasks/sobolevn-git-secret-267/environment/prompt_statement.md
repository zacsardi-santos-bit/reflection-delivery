I'm working with git-secret and I've noticed that the commands for adding and removing users from the keyring don't properly validate the email address you provide. If I accidentally type just the short username portion of someone's email (without the domain), the command doesn't reject it the way I'd expect — it should fail immediately and leave the keyring untouched, but the behavior is inconsistent. The same issue exists if I pass a partial string that's only a substring of an actual email address in the keyring: the command should reject it outright, but instead it can behave unexpectedly.

I'd like these commands to require an exact, full email address that actually exists in the GPG keyring before making any changes. If a user passes a short name or any partial string that isn't an exact match, the command should exit with an error and not modify the keyring at all. After such a failure, querying who has access should still reflect the unchanged state.
