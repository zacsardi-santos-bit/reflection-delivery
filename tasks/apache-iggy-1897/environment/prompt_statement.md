I'm working on a Go client library for a messaging system, and the message format needs to be updated to match the server's current wire protocol. The old message type is no longer compatible — it used a simple structure with an ID, payload, and a map of typed header entries, but the server now expects messages to carry a fixed-size binary header with fields for checksum, message ID, offset, timestamps, and length metadata for both payload and user-defined headers. User headers should be stored as pre-serialized bytes rather than a map, and messages should be constructible with either no headers or with a map of key-value headers that gets serialized automatically.

The binary serialization of outgoing send-message requests also needs to change: the serialized output should now start with a metadata-length field, followed by the stream and topic identifiers and partitioning info, then a message count, then a block of per-message index entries (one per message, 16 bytes each encoding cumulative size information), and finally the actual message data where each message is its binary header bytes followed by payload bytes followed by user header bytes.

Additionally, the fetch-messages request serialization needs to be fixed so that the consumer identifier is encoded using a full identifier format (type, length, and value bytes) rather than as a plain integer, matching the identifier encoding used for stream and topic IDs.

The response deserialization for fetched messages should also be updated to parse the new fixed-size binary header format from incoming server responses.
