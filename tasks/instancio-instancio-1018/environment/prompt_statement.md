I'm working on a Java test data generation library and I need to add support for generating Unicode strings, not just ASCII. Right now, the library can only produce alphabetic, alphanumeric, hex, or digit strings, which makes it impossible to properly test applications that handle international text, emoji, or multibyte characters.

I'd like the string generator to support a mode where it generates code points from across the full Unicode space, spanning many different scripts and blocks. I'd also like the ability to restrict generation to specific Unicode scripts — for example, only Cyrillic and emoji characters — so developers can test specific internationalization scenarios. When a length is specified for Unicode strings, it should refer to the number of Unicode code points rather than Java character units, since some code points are represented by two Java chars. Generating a Unicode string with length zero should return an empty string.

Additionally, I'd like a global configuration option so that all generated strings in a test session are Unicode by default, without having to configure each field individually. This should be settable both programmatically and via a properties file.

There also needs to be an internal utility for mapping Unicode block names to their corresponding code point ranges, and this mapping needs to be accurate — for instance, the Cyrillic block should map to the correct start and end code points, the Emoticons block to its range, and so on. The new string type setting should also be parseable from the properties file configuration, the same way other enum-based settings already work.
