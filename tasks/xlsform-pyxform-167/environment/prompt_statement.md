I'm working on extending the XLSForm conversion tool to support multiple validators. Right now the tool only runs one validator, but I'd like to add support for a second one (Enketo-based) that can be toggled on or off via command-line flags. The default behavior should keep running only the original validator unless the user explicitly asks for the new one. There should also be a way to skip all validation entirely, and that skip flag should take precedence over any other validator flags.

At the same time, the utility that cleans up error messages from the validator output has a couple of bugs I need to fix. First, when the validator outputs a single-line error message, that message is being silently dropped instead of being passed through to the user. Second, when the error message contains a file system path (like pointing to a missing jar file), the cleaner is incorrectly processing the path and returning a garbled version. Both of these should be fixed so that single-line errors and path-based errors are returned unchanged or in their correct cleaned form.

I'd also like this error-cleaning logic to live in a proper module under a validators package, rather than being buried in the main validate module, so it can be shared and extended more easily.
