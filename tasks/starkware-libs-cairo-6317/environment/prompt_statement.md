I'm working on the Cairo language's documentation extraction system and I've noticed it only picks up the outer doc comments placed before items, but completely ignores the inner comments placed inside item bodies. In Cairo, both comment styles are valid ways to document an item — you can write a comment above a function or inside it — but the current implementation only recognizes the outer style. This means any documentation written using the inner style never shows up in hover tooltips or any other tooling.

Beyond functions, the system also doesn't handle crate-level or module-level documentation at all. When a developer writes file-level comments at the top of a crate root or submodule file, those comments aren't captured anywhere. For non-inline submodules (modules defined as separate files), the docs should combine the file-level comments from the module's source file with any outer declaration comment.

I'd like the documentation system to be extended so that: (1) the extracted documentation for functions and modules combines both outer and inner comments into a single string, with outer comments first; (2) crates report their file-level comments as documentation; (3) non-inline submodules report their file-level comments combined with any outer declaration comment; and (4) the language server's hover tooltip surfaces this complete combined documentation. Items that only support outer comments (like structs, enums, and their members) should continue to work as before.
