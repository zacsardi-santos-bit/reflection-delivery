I'm hitting a crash in the UPnP port mapping code when my Huawei home router is on the network. The router responds to UPnP discovery just fine, but it only advertises service types that are not the standard internet gateway services. When the code tries to do a port mapping against this device, it doesn't handle the case where no usable service was found — it ends up trying to use an absent service reference and crashes instead of failing gracefully.

The fix should make the code handle this situation cleanly: if no supported service type is found in the device's description, the port mapping attempt should return a failure result without panicking. The network probe should still detect that a UPnP device is present on the network even in this case. This affects any router that responds to UPnP discovery with vendor-specific or non-standard service types rather than the expected internet gateway service types.
