I'm working with a validation enforcement library and I want to write custom rules that are aware of their surrounding context. Right now, when I write a custom rule, it only receives the value it's directly validating — there's no way to tell where in the data structure the rule is running, what key or array index is being checked, or what the parent object's values look like.

I'd like there to be a way for custom rules to access a "context" object that tells them what value is currently under validation, what positional information is available (like the field name when inside an object schema, or the index when inside an array), and a reference to the parent scope so I can traverse upward. The parent traversal should be chainable so I can walk multiple levels up the hierarchy, eventually reaching a terminal value when there are no more parents.

This would let me write rules like "ensure no item in this array equals a field from the grandparent object" — essentially enabling cross-field validation by walking up the context tree. Without this, my custom rules are isolated and can't take into account values from sibling or ancestor fields in the same data structure.
