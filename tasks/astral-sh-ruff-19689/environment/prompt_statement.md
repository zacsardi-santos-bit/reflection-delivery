I'm working on a language server that supports pull-based workspace diagnostics with caching. The caching works by having clients send back result identifiers from previous responses, and the server uses those to determine which files are unchanged. The problem is that some clients (like VS Code) percent-encode special characters in file URIs when sending those identifiers back. For instance, if a workspace path contains a colon, the client sends back the URI with the colon encoded as "%3A". Because the server currently matches previous result IDs by exact URI string, it fails to recognize those files as unchanged, and ends up doing full re-analysis even when nothing has changed. I need the server to match previous result IDs by the underlying file path rather than by the raw URI, so that caching works correctly even when the client uses different URL encoding than what the server originally returned.
