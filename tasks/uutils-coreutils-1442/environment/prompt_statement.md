I'm working on a Rust implementation of standard Unix utilities and running into a couple of test failures I need help resolving.

The first problem is that several tests fail when run under Windows Subsystem for Linux. The disk usage command reports different block sizes on WSL compared to a standard Linux kernel, so the tests need to use WSL-appropriate expected values. There's also a group-change test that exercises the reference option — it should be skipped on WSL because WSL has a known bug where non-root users get elevated privileges for group ownership operations, making the test produce unexpected results. To handle both cases, I need a shared utility function added to the test helpers that returns whether the tests are currently running on WSL. On Linux it should check a well-known kernel information file to detect the WSL environment; on other platforms it should always return false.

The second problem is that the file status utility is computing file birth and creation timestamps incorrectly. When I use the format specifiers for human-readable creation time or creation time expressed in seconds, the output doesn't match what the system's own stat command shows. It looks like the implementation is measuring how long ago the file was created (elapsed time from creation until now) instead of when the file was actually created relative to the Unix epoch. I'd like this fixed so the output agrees with the system stat. When birth time isn't supported by the kernel or filesystem, the utility should output the standard sentinel values for "unknown" that the system stat also uses ("-" for human-readable, "0" for the seconds form).
