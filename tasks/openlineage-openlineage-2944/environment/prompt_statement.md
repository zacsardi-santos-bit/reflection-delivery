I'm using the OpenLineage SQL lineage parser to extract table lineage from SQL scripts. Many of our scripts begin with a statement to set the active database or schema before running queries — a common pattern in Snowflake, Databricks, Hive, MySQL, and other systems. The problem is that the parser doesn't track this context, so any table reference that relies on the active context appears without any database or schema qualification in the lineage output.

For instance, if a script switches to a specific database and then inserts into a table by its bare name, the lineage should show that table as belonging to that database. Right now it just shows the bare table name.

I'd like the parser to properly handle these context-switching statements across the dialects it already supports. It should apply the active database and schema to subsequent unqualified table references, and it should respect each dialect's conventions — for example, in some dialects the bare context-switch form sets the schema, in others it sets the database. It should also preserve previously established context when a new context-switch only partially updates the active state (e.g., switching the database without specifying a schema should keep the previously active schema). Finally, context-switching to a special "default" keyword that isn't explicitly supported should be silently ignored rather than causing an error.
