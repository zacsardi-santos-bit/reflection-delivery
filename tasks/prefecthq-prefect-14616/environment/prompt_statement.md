I'm working on the event processing system in Prefect and I'd like to refactor how we handle causal ordering of events. Right now, the logic for tracking which events have been seen, holding events that arrive before their predecessors, and recovering events whose predecessors never arrived is all mixed into the main automation trigger processing module. This makes it hard to test that logic in isolation and impossible to run multiple independent ordering contexts without them interfering with each other.

I'd like to extract the causal ordering system into its own separate module. The new component should be scope-aware — you create an instance with a named scope, and two instances with different scopes operate completely independently without sharing any state. The new module should export the ordering class, the relevant exceptions, and the relevant constants. The triggers module should continue to work as before but should also expose a way for external callers to get a reference to the ordering instance it uses internally, so they can call methods on it directly. The new module needs to handle all the same behaviors: holding early-arriving events until their predecessors are seen, processing followers in causal and occurred-time order, respecting a configurable lookback window so very old events don't get stuck waiting, and raising an appropriate error when recursive follower evaluation goes too deep.
