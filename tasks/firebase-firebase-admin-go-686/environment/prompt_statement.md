I'm working on the Firebase Remote Config Go Admin SDK and I need to add server-side condition evaluation support. Right now, when I call the evaluate method on a server template, it just returns the static default values for every parameter — it completely ignores the conditions defined in the template. I need it to actually evaluate those conditions against a caller-provided context (like a user ID for percentage rollouts) and return the appropriate conditional values.

The conditions in a Remote Config template can include OR/AND logic and percentage-based targeting. The percentage logic works by deterministically hashing a combination of a seed string and a randomization identifier to assign users into percentage buckets. I need the condition evaluator to support "less than or equal to", "greater than", and "between a lower and upper bound" percentage operators. When no valid randomization identifier is present in the context, or when the operator is unrecognized or missing, the percentage condition should evaluate to false.

When a parameter's value is set to use the "in-app default" (rather than an explicit remote value), the SDK should fall back to the default configuration the caller supplied when creating the template, and it should indicate in the result that the value came from the local default rather than from the remote template. If neither a remote value nor a local default is available, it should return an empty string and mark the source as static.

I also need the evaluate method to return an error if no template has been fetched and loaded into cache yet. Additionally, the way default configuration values are stringified needs to be fixed: string values should be stored verbatim rather than being JSON-encoded (which was wrapping them in extra quotes). The JSON serialization of the template also needs a fix — the version identifier field is currently being serialized with incorrect casing in the output.
