I've been looking into how Flink loads user code when a program is submitted, and I noticed that the class loader always uses a fixed child-first resolution order — there's no way to configure this. The class loading order should respect the Flink configuration so that operators can choose whether user code or framework classes take precedence at runtime. The default should stay as it is (user code first), but it should be possible to switch to parent-first loading when needed through configuration. The jar handling component used by the web submission UI also needs to be updated to accept and pass along this configuration. Could you update the packaged program infrastructure to support a configurable class loading order, passing the configuration through so the class loader is built according to the specified policy?
