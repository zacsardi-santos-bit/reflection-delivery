## Description

The cxx library uses a procedural macro to auto-generate Rust boilerplate for C++/Rust FFI bridges. Recent Rust compiler versions introduced new requirements for how certain patterns must be written: foreign function declaration blocks now require an explicit safety marker, and attributes that carry safety implications must be explicitly wrapped to indicate they are intentionally unsafe. When compiling with modern Rust toolchain warnings (especially those previewing upcoming edition requirements) and treating warnings as errors, the build fails because the generated code uses the older, non-compliant patterns.

## Expected Behavior

- The code generator should emit the updated, standards-compliant syntax for foreign function declaration blocks on newer compiler versions
- Safety-implying export attributes generated by the macro should use the updated wrapping syntax on newer compiler versions
- The updated code generation must remain backward compatible with Rust compiler versions that do not support the new syntax
- All existing FFI bridge tests must continue to compile and pass after the fix

## Why This Matters

Projects using cxx that enable strict warning policies (for example, treating all compiler warnings as errors in CI) will see build failures with modern Rust toolchains. Fixing the code generator allows such projects to use cxx cleanly without warnings across different Rust toolchain versions.
