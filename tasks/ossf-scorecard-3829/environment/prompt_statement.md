I'm working on the scorecard project and need to refactor the dependency pinning check to align with the probe-based architecture that other checks already use. Right now, the evaluation logic for pinned dependencies operates directly on raw dependency data — it handles the conversion from raw data to findings and then computes the score all in one place. This makes it hard to test independently and doesn't match how the rest of the system is structured.

What I need is a new probe in a dedicated package that converts raw dependency results into structured findings. Each dependency should become a finding with an appropriate outcome: positive for pinned, negative for unpinned, not-available when no dependencies exist, not-applicable when pinned status is unknown or ambiguous, and error when there are processing failures. If a dependency has neither a location nor a message, the probe should return an internal error rather than silently producing a bad finding. Each finding should carry the dependency type as metadata. The probe should also expose its name as an exported identifier.

The evaluation function should then be updated to accept a slice of pre-computed findings and a logger, rather than the raw data and full check request it currently takes. It should compute scores and log messages based on the outcomes in those findings. The top-level check entry point should just accept the check request and wire everything together.

I also need the text-generation helpers that describe why a dependency is unpinned to live in the probe package, since that's where the findings are created.
