I'm working on adding core functionality to the SQL query receiver. Right now the receiver can parse a basic configuration file but doesn't actually collect any metrics from a database — the metrics receiver creation is a stub that returns nothing. I need to implement the actual metric collection logic so that the receiver executes SQL queries, converts each result row into an OpenTelemetry metric, and streams those metrics to the downstream consumer.

I also need to expand the metric configuration to support more options: each metric in the config should have a data type (gauge or sum), a value type (integer or floating-point), an aggregation mode (cumulative or delta, relevant only for sums), a monotonicity flag, and optional description and unit fields. The existing monotonicity field has been renamed from its old name.

Additionally, the receiver currently has no configuration validation at all. I need to add validation that checks all required fields — driver, datasource, SQL statement, metric name, value column — are present and non-empty, and that the new type and aggregation fields only accept their defined set of valid values. When aggregation is specified but the data type is gauge (which doesn't support aggregation), that should also be caught. Multiple validation errors within a single metric config should be reported together rather than just the first one.

I'll need a set of test YAML configuration files covering valid configs as well as various invalid cases (missing each required field, invalid enum values, incompatible field combinations, and multiple errors in one metric). The collection logic should also handle errors at row-conversion time gracefully, reporting which row failed and why (e.g., a value that cannot be parsed as an integer or float, or a referenced column not present in the result set), collecting multiple row errors together rather than stopping at the first failure.
