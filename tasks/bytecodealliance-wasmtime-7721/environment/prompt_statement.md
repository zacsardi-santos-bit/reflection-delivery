I'm working on adding support for several WebAssembly memory instructions to the Winch baseline compiler. Right now, Winch doesn't handle instructions that fill a memory region with a value, initialize memory from a data segment, copy memory regions, drop a data segment, query the current memory size in pages, or dynamically grow memory. Any WebAssembly module that uses these instructions simply can't be compiled or run under Winch.

I need the Winch compiler to correctly implement all of these memory operations. The behavior should match the WebAssembly specification: fills, copies, and initializations should succeed when the target range fits within the allocated memory and trap with an out-of-bounds memory access error when they don't. Memory initialization from a dropped data segment should also trap. Querying the memory size should return the correct current page count. Growing memory should return the old size on success and negative one when growth would exceed the allowed maximum, and the result should be usable as a value in any expression context. Invalid operand types or references to nonexistent memories or data segments should be caught at module validation time with appropriate type mismatch or unknown memory/segment errors.

This support needs to work correctly with both standard and pooling allocator configurations.
