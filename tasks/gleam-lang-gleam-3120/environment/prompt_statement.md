I'm working on improving the Gleam compiler's error reporting behavior. Right now, when the type checker encounters certain errors in a module — like a function without a body, a return type that doesn't match the annotation, or an invalid external declaration — it stops analyzing the rest of the module. This means I only see the first error each time I compile, which makes fixing issues really tedious.

I'd like the compiler to continue analyzing the entire module even after encountering these kinds of errors, so that all problems are reported in a single pass. When a function has errors in its body but has type annotations, those annotations should still be used for type-checking the rest of the module, so callers get proper type errors instead of confusing "not found" messages. Similarly, a function that isn't supported on the current compilation target should still be known to the analyzer, so that call sites produce a clear "unsupported target" error rather than an "undefined" error.

This same fault-tolerance behavior should also apply to type definitions — for example, a type with duplicate type parameters should report its error but not prevent subsequent type definitions from being checked.
