I'm working on extending our SOFA-RPC plugin to support distributed tracing across thread boundaries when using callback-style asynchronous invocations. Right now, when a remote call is made in callback mode, the response handler runs on a separate thread and has no connection to the original trace — it's completely invisible in our distributed tracing data. I need the trace context from the initiating thread to be captured at the point the callback is registered and then restored when the callback executes on its own thread, so the full call chain shows up as linked trace segments. If an error occurs during callback execution, it should also be recorded as a log entry on that span. Additionally, when the argument passed to the callback invocation method is a recognized callback type, it should be automatically wrapped to enable this context propagation — but if the argument is not a callback type, it should be left untouched.
