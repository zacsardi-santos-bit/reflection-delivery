I'm working on the Cairo compiler and running into issues with the end-to-end test suite. The optimization configuration supports a list of functions that the optimizer is allowed to move around during compilation, but when I set up test databases with the default configuration, it allows too many functions to be moved. This causes the generated code to differ from what the snapshot tests expect, and a large number of end-to-end tests fail as a result.

I need a convenient way to configure the optimization settings for tests so that only a minimal, stable set of functions is considered moveable. Ideally this would be a builder method on the optimization configuration type that I can chain onto the default configuration when initializing my test databases, similar to how other configuration options are set. The minimal set should restrict moveable functions to just one function — the field subtraction primitive — so that test output is consistent and predictable.
