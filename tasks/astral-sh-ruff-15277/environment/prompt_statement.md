I've been using the lint rule that removes unnecessary integer conversions around expressions that already return integers, but I've found it produces broken code in certain multiline situations. When a function call is written with the function name on one line and the opening parenthesis of its arguments on the next line — which is a valid Python style — the auto-fix just strips the outer conversion call without preserving the fact that it's a function call. The result is two separate expressions instead of a call, silently changing what the code does.

The fix should be smarter about this: if the function name and the argument-opening parenthesis are on different lines, it should add wrapping parentheses to maintain the call's semantics. If they're on the same line, no extra parentheses are needed and the current behavior is fine.

There's also an issue with comments. If there are comments sitting between the opening of the outer conversion call and the start of the inner argument, or between the end of the inner argument and the closing of the outer conversion, the fix should be marked as unsafe rather than safe. Right now those cases are being incorrectly marked as safe fixes, which means the tool claims it's harmless when it actually isn't.
