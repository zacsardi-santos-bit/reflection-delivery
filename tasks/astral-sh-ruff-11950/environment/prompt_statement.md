I've been noticing that when I lint a Python file that has a syntax error in it, the linter completely stops reporting other violations after it hits the first bad token. For example, if there's an unclosed bracket or an unterminated string somewhere in the middle of the file, all the other style violations — trailing commas, blank-line issues, invalid characters in strings — just disappear from the output, even for code that's perfectly valid. I'd expect the linter to keep going through the entire file and report everything it finds, presenting both the syntax errors and any rule violations together.

There's also a subtlety around code structure: rules that care about whether code is at the top level versus inside parentheses or brackets need to handle the case where a delimiter was never closed due to a syntax error. In those cases, the linter should treat the recovery point (where parsing resumed after the error) as if the open context has been closed, so subsequent top-level definitions are still recognized correctly.
