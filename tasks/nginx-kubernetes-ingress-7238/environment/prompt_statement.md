I'm working on the NGINX Kubernetes Ingress Controller and need to add support for conditional rate limiting based on JWT token claim values. Right now, rate limit policies can only apply to all traffic uniformly. I want to be able to define rate limit policies that only kick in when a specific JWT claim matches a certain value — for instance, one rate limit for "gold" tier users and another for "silver" tier users, based on a claim in their JWT token.

The feature should work end-to-end: the policy custom resource needs to accept an optional JWT condition (with a claim name and a match value), the configuration generator needs to translate those conditions into the appropriate NGINX configuration structures, and the validator needs to reject JWT conditions when they're used outside of the commercial NGINX version where this functionality is supported. A condition block that's declared but has no JWT sub-condition should also be rejected.

When generating configuration, if multiple rate limit policies reference the same JWT claim on the same virtual server, the output should deduplicate the corresponding configuration entries so the same claim variable isn't emitted twice.
