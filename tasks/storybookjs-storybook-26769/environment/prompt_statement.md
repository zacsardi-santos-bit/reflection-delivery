I'm working on adding a feature to Storybook's core server that lets it automatically generate new story files for existing components. Right now there's no programmatic way to do this — developers have to hand-write the boilerplate every time. I want the server to be able to take a component's file path, its export name, and whether it uses a default or named export, and produce a ready-to-use story file with the correct imports and structure.

The generated file should automatically pick up TypeScript or JavaScript formatting based on the component's extension. For TypeScript files, it needs proper type annotations. For JavaScript files, a plain untyped structure is fine. I also need a utility that can convert arbitrary strings (with leading digits, hyphens, spaces, or special characters) into valid PascalCase identifiers for use in the generated code, and another utility for normalizing path separators to forward slashes across platforms.

Finally, the whole thing should be wired up as a channel-based feature: the server listens for a "create story" request, generates the file, and then emits a result event back — with either the new story's identifier on success, or a clear error message on failure.
