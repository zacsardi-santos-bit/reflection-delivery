I'm working with Apache Pulsar and noticed that when the broker garbage collects a topic, the schema registered with that topic is not being cleaned up. After a topic is fully removed by the GC process — because there are no active consumers and no subscriptions — the schema record remains in the schema registry, creating an orphaned entry.

I'd like schema cleanup to happen automatically as part of the garbage collection process for both persistent and non-persistent topics. The schema should only be deleted when the topic is actually being removed: topics that still have active consumers or existing subscriptions should not be garbage collected, and their schemas should remain untouched. Once those consumers disconnect and subscriptions are removed, then GC should be allowed to clean up both the topic and its schema together.
