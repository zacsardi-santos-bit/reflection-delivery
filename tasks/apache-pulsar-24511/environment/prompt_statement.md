I'm working on the managed ledger module and I need to add a reusable utility for replaying all entries in a managed ledger cursor. Right now, every component that needs to read through a cursor has to write its own batch-reading loop, which is repetitive and inconsistent.

I'd like a component that takes a cursor and a user-provided entry processor, reads entries in configurable batch sizes using a given executor, and returns the last position that was successfully processed. It should handle the case where the processor rejects an entry mid-replay — in that case, it should stop processing and return the last position that succeeded, rather than failing completely. If a lower-level cursor operation itself throws an unexpected error, that error should propagate to the caller through the returned future. The component should also expose a way to check how many entries were successfully processed during a replay, so callers can decide what to do after replay finishes (like taking a snapshot). Entry buffers should be properly released after processing so there are no memory leaks. When there are no entries in the cursor at all, the result should clearly indicate that nothing was processed.
