I'm working with a SQL linter that supports the BigQuery dialect, and I've noticed it's incorrectly parsing type conversion expressions that include a format specifier. When you write a conversion expression where you specify a format pattern — like converting a date to a string with a particular date format template, or converting a string to a time value using a time format pattern — the linter is treating the format indicator as if it were a column name rather than a SQL keyword. This produces an incorrect parse tree.

On top of that, a bunch of valid BigQuery format-conversion patterns aren't supported at all. For example, conversions involving date, time, and timestamp literals with format strings don't parse, neither do conversions using numeric format patterns (including ones with special characters like currency symbols and thousands separators), nor does the optional timezone clause that can appear after a format string.

I'd like the parser to correctly recognize the format specifier as a keyword and the format string as a direct quoted value in the parse tree, and to support all these valid BigQuery conversion-with-format patterns including the optional timezone specification.
