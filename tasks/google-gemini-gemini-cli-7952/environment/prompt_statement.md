I'm working on the Gemini CLI and I'd like to introduce a centralized, reusable service for making structured AI model requests that return JSON. Right now, multiple tools each handle their own retry logic, default parameters, response cleaning, and error handling, which creates duplication and inconsistency. I want a shared component that applies sensible defaults, retries on transient failures, automatically strips markdown code fences from model responses when present (and logs telemetry when it has to do that), and handles errors consistently — including treating aborted requests differently from real failures.

This new service should be initialized as part of the authentication flow and made accessible through the configuration object. Trying to access it before authentication completes should produce a clear error. The service should support optional per-request overrides for generation parameters and allow a system instruction to be included only when needed.

I also need to update the utility that helps fix failed file edit operations to use this new shared service. That utility should read a request-tracking identifier from async context when available, fall back with a logged warning to a generated identifier when not, and cache results so that identical requests don't hit the model multiple times. A way to reset those caches during testing would also be useful.
