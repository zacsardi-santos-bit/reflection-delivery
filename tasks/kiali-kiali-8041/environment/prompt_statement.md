We're using a cryptographically weak hashing algorithm to generate node and edge identifiers in our service graph and mesh graph API responses. This algorithm is considered outdated and produces short identifiers that have a higher chance of collision. I'd like to switch all of these identifier-generation functions to use a stronger algorithm that produces 64-character hex identifiers instead of the current 32-character ones.

The hash functions are used in several places: the graph and mesh Cytoscape configuration layers (for node and edge IDs) and the Istio telemetry processing pipeline (for time series and edge traffic deduplication hashes). All of these should be updated for consistency.

Along with the code changes, all the expected golden test data files in the graph and mesh API test directories will need to be updated to reflect the new identifier values. The golden files should also no longer end with a trailing newline — the last character in each file should be the closing brace of the JSON object. This is connected to a test infrastructure cleanup where the comparison helper no longer strips the last byte from the expected file before comparing it against the actual API response.
