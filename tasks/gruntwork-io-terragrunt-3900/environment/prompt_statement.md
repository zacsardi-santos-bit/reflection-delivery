I'm working on extending Terragrunt's stack configuration system to support nested stacks. Right now, a stack configuration file can only declare individual deployment units, but I need it to also be able to reference entire other stacks as components. This would allow teams to build modular, layered infrastructure where one stack can embed other stacks rather than having to list every unit at a single flat level.

On the validation side, the current validation logic only covers unit blocks. I need the same validation rules applied to stack references too — each stack reference needs a unique, non-empty name, a non-empty source location, and a non-empty output path. If any of those fields are missing or just whitespace, validation should fail with a clear message identifying which stack had the problem. Duplicate names or duplicate paths within the same file should also be rejected. A configuration file that contains only stack references with no unit references at all should be considered valid as long as those references individually pass all the checks.
