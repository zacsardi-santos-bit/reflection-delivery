I'm working with linear combinations of quantum gates and operations in Cirq, and I've noticed that these objects don't support the standard unitary-checking and unitary-extraction protocols. When I have a linear combination that is mathematically unitary, I'd like to be able to ask the library whether it's unitary and retrieve the corresponding matrix — and for non-unitary combinations (like those with non-unit scaling or parameterized terms), I'd expect the library to correctly report that they aren't unitary and raise an appropriate error if I try to extract a unitary matrix. The same is true for sums of Pauli operators: I want to be able to check unitarity and get the matrix when it exists, or get a clear error when it doesn't.

Additionally, I'd like Pauli string objects to support computing their matrix over a user-specified collection of qubits in a given order, rather than only over their own native qubit set. If a qubit I specify isn't part of the string, it should act as identity. The coefficient of the Pauli string should be reflected in the result. This would make it much easier to work with Pauli strings in larger multi-qubit contexts where I need to embed them into specific subspaces.
