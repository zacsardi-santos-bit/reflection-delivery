I'm working on adding support for AWS Wavelength Zones to our Kubernetes cluster networking provider. Right now, the codebase handles standard availability zones and Local Zones, but Wavelength Zones aren't recognized as a distinct zone type, so clusters can't be provisioned with proper networking in those zones.

I need the system to identify Wavelength Zone subnets as a separate edge zone type, with the ability to check specifically whether a subnet belongs to a Wavelength Zone (not just whether it's any kind of edge zone). The subnet collection utilities should include Wavelength Zone subnets when returning edge-inclusive results, but exclude them from standard (non-edge) subnet ID lists. Zone metadata population should work correctly for Wavelength Zones, and it should be possible to check if there are any public subnets in a Wavelength Zone within a given collection.

On the networking side, the VPC configuration needs a place to store a carrier gateway identifier. A carrier gateway should be created when managing a VPC that doesn't have one yet, and deleted when the cluster is torn down. Route table logic needs to know that public IPv4 subnets in Wavelength Zones should use the carrier gateway as their default route, not the internet gateway. IPv6 is not supported in Wavelength Zones and should return an appropriate error. Private subnets in Wavelength Zones should route through the NAT gateway in their parent availability zone, just like Local Zone subnets do.
