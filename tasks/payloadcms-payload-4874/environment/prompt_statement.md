I'm trying to write integration tests for the database migration system, but I'm running into a problem: the "fresh migration" command always pauses and waits for interactive user input before proceeding, which means it completely blocks any automated test run. I need to be able to run migration commands programmatically — creating a migration, applying it, checking status, and doing a fresh reset — without any interactive prompts getting in the way.

Specifically, there should be a way to pass a flag indicating that warnings and prompts should be automatically accepted, so the operation continues without waiting for keyboard input. When a fresh migration runs with this flag, it should drop and reapply migrations and properly record the results in the migrations tracking collection just like it would in a normal run.

I'd also like each test suite to use its own isolated directory for migration files rather than sharing a single global location, so that tests don't interfere with each other. There also seems to be duplicated logic across multiple scripts that sets up environment paths for a test suite directory — that should be extracted into a shared helper function that both scripts can use.
