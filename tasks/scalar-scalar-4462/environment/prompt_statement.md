I'm working on the API reference component and I need to add support for customizable URL fragment generation. Right now, the slugs for sections like models, tags, headings, operations, and webhooks are always generated the same way with no way for consumers to override them. I'd like to be able to pass custom slug-generation functions through the reference configuration so that each section type can use a developer-supplied function instead of the default logic.

On top of that, I noticed that the functions generating IDs for models and webhooks have inconsistent signatures — the model function takes a plain string and the webhook function takes two separate string arguments. I'd like both of them updated to accept a single structured object instead, which is more consistent and makes it easier to extend them with the custom generator support.

When a custom generator is provided for headings, the result should be used as-is without any automatic prefix. For models, the result should be prefixed with the standard section prefix. For tags, the same prefix-based approach should apply. The configuration type should be updated to declare all five optional custom generators (heading, model, tag, operation, webhook) so that TypeScript consumers know what options are available.
