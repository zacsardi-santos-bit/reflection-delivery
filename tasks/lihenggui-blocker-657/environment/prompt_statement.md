I'm working on the Blocker app and need to add a search-and-sort capability for app components. Right now, when a user opens an app's detail screen, all of its components (activities, services, receivers, and providers) are shown but there is no way to filter them by keyword or reorder them based on user preferences.

I need a use case that takes a package name and an optional search keyword, and returns a stream of results where the components are organized by their type. When a keyword is given, only components whose name contains that keyword should appear. When no keyword is given, all components for the package should be returned. The results should be sorted according to the user's configured preferences — either by the component's short name or its fully-qualified name, in ascending or descending order — and should also respect a priority setting that puts disabled or enabled components first. Running services need to be detected and marked as running within the results. If the given package name doesn't match any installed app, the use case should return an empty result.

Additionally, the component-detail repository contract is currently named with an "I" prefix (as in "interface"), which is inconsistent with how other repository contracts are named in the project. It should be renamed to drop the prefix and follow the same naming convention as the other repositories. Any classes that implement or reference this contract need to be updated accordingly, including the test doubles used in unit tests. The test double for the component-detail repository also needs its method for injecting test data updated to accept a list of items rather than a single item, and the fake service controller needs a way to inject a set of running service names so that tests can verify running-service detection.
