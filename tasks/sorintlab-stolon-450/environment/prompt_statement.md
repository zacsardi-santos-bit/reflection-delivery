I'm seeing a bug in the PostgreSQL version parsing logic. When the system reads the version string from the PostgreSQL binary, it sometimes includes a trailing newline at the end — which is pretty normal for command-line tool output. But the current parser can't handle that and just returns an error instead of correctly extracting the major and minor version numbers. For instance, a version string like "9.6.7" with a newline at the end should parse to major 9, minor 6, with no error. Can you fix the parser so it handles trailing newlines correctly, while still working with version strings that don't have trailing newlines and those that include pre-release suffixes?
