I'm working on a Spartacus project that uses NgRx for state management. We have a convention that any action class representing a failure (those with "Fail" in the class name) must implement a specific error-handling interface. This convention is currently not enforced by tooling, so it's easy for developers to forget it and end up with failure actions that don't meet the expected contract.

I'd like to create a custom lint rule that detects these missing interface implementations and can automatically fix them — adding the required interface declaration to the class and inserting the necessary import statement if it's not already there. I also want to extract the underlying logic for checking/modifying interface implementations and checking/adding import statements into reusable utility modules, so they can be used by other lint rules in the future.

The rule should only flag classes whose name contains "Fail" that are missing the required interface. Classes that already implement the interface (in any position in their implements list, with or without other interfaces, with or without a superclass) should be considered valid and not flagged. Classes without "Fail" in their name should not be flagged regardless. When the rule auto-fixes a violation, it should correctly handle all class shapes: classes with no extends or implements, classes with only extends, classes with only implements, and classes with both.
