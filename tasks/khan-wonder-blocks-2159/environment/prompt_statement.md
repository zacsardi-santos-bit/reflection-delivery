I'm working on fixing a keyboard navigation bug in our popover component. When a popover is open and a user presses Tab to move focus out of it into the rest of the page, subsequent Tab presses that wrap around the document (circular navigation) incorrectly land focus back inside the open popover instead of continuing naturally through the page.

The issue is that once focus has left the popover area, the popover's internal interactive elements should be temporarily excluded from the tab order so they don't interfere with the rest of the page's keyboard navigation. Right now they stay in the tab order, which breaks both forward and backward circular navigation.

Specifically, I need the component responsible for managing focus inside the popover to: remove its internal elements from the tab order when focus moves out, and restore them to the tab order when focus comes back. I also need the boundary behavior — pressing Tab on the last element inside the popover should move focus to the next element after the trigger, and pressing Shift+Tab on the first element inside the popover should move focus back to the trigger. Backward circular navigation from outside the popover should also be able to return focus into the popover from the last element.
