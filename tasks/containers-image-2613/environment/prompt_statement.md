I'm working on the storage backend for a container image library and need to make two related improvements.

First, the logic that computes a unique identifier for each layer when it is committed to storage is currently embedded inside a larger function, making it impossible to unit-test in isolation. I'd like to extract it into a standalone function so its behavior can be verified directly with known inputs. The rules are straightforward: for a layer identified by its uncompressed digest, the ID either equals that digest directly (for a root layer with no parent) or is a hash combining the parent's ID with the layer's uncompressed digest. For a layer identified by a table-of-contents digest (used in partial pulls), the ID must always be produced by hashing, and the TOC digest must be incorporated using a distinct prefix so it can never be confused with an uncompressed-digest-based ID.

Second, the system currently allows an image to be written even when the uncompressed-digest values declared in the image configuration don't match the actual uncompressed content of the layers. This ambiguity is especially problematic when a layer can be pulled either via a traditional full-stream path or via a partial-pull TOC-based path, since both paths may produce different "views" of the same blob. The fix should enforce that, when a configuration does declare these values, they must match what is actually being stored — and any mismatch should cause the operation to fail with a clear error.
