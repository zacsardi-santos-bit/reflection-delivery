I'm working with a distributed tracing SDK and I need a way to explicitly specify a parent span when creating new spans. Right now, the only way to make one span a child of another is if the parent is actively set on the current scope — but sometimes I want to attach a new span to a parent that has already ended, or that was created in a different context. I'd like all three span creation utilities (the auto-finishing one, the inactive one, and the manually-finished one) to accept an optional parent span directly in their options, so the parent-child relationship is established based on whichever span I pass in, not whatever happens to be active on the scope at the moment.

Also, for manually-managed spans, I'd like to simplify how spans are finished. Currently there's a separate finish helper passed as a second argument to the callback, but I'd prefer to just call the span's own end method directly. The finish helper parameter should be removed.
