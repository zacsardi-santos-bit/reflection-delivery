I'm working on Modin and want to make the execution engine and partition format settings dynamically reconfigurable at runtime instead of being fixed at import time. Right now these settings are plain module-level strings set once when the library loads, so there's no way for components to react when a user wants to switch backends.

I'd like to introduce a small publish-subscribe utility class that holds a named value, lets you update it, and notifies any registered callbacks when it changes. It should support two subscription modes: one where the callback fires immediately on registration and on every subsequent change, and another where the callback fires exactly once when the value reaches a specific target.

The execution engine and partition format settings should become instances of this utility and be exposed at the top level of the package. The engine dispatcher should subscribe to both so it automatically picks up the correct factory whenever either setting changes. Attempting to switch to an engine name that has no corresponding factory should raise a meaningful error. The new utility class should also be part of the public package API. Additionally, the distributed client variable in the dataframe submodule should be renamed to avoid naming conflicts.
