I'm hitting a bug in the SQL error parsing logic. When a query fails with a duplicate-key constraint violation and the error gets wrapped in an RPC error message, the error is sometimes not being recognized correctly as a constraint violation. After some debugging, I traced the issue to the fact that our query had a bind variable whose value contained an error-like string — specifically something that looked like a MySQL errno/sqlstate pair. The parser seems to be picking up that embedded pattern from the bind variable data instead of the real error code that appears earlier in the message.

The result is that a clear duplicate-key error ends up being misclassified, which breaks any downstream code that checks the error type. I'd expect the parser to always find the first occurrence of the errno/sqlstate pattern in the error message and use that, so that embedded error-like strings in bind variable values don't interfere with the result.
