I'm working with the status reconciler in our Prow setup. Right now, whenever a new required presubmit job is added to our configuration, the reconciler automatically triggers that job for every open pull request across all repositories it manages. This works fine in general, but we're trying to roll out new required checks incrementally — we need a way to tell the reconciler to skip the automatic job triggering for certain organizations or specific repositories, while still letting the normal status cleanup and status renaming operations happen for those same repos.

Can you add support for an exclusion list that the controller can use to decide whether or not to trigger new presubmit jobs for a given org or org/repo? The list should be checked at the point where triggering would normally happen, and if the org or org/repo matches an entry in the list, triggering should be skipped without affecting retirement or migration. When the list is empty, the existing behavior should be completely unchanged.
