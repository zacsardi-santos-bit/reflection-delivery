I'm working on cleaning up the telemetry and tracing configuration API. Right now, when I set up exporting for a foreground command, I have to pass a boolean flag to indicate whether it should run in quiet mode. This feels like an internal detail that shouldn't be the caller's responsibility — the configuration should figure that out on its own. I'd like to remove that parameter so callers can simply request a foreground exporting configuration without needing to know anything about quiet mode behavior. All the existing call sites that currently pass a boolean value to this method would need to be updated to use the new zero-argument form.
