I'm working with the jj version control library and need to expose the file-fixing functionality as a proper library API rather than keeping it buried in CLI-specific code. Right now, there's no way for consumers of the library to programmatically apply content transformations to files across a range of commits without duplicating all the commit-graph traversal and tree-rewriting logic themselves.

What I need is a library module that lets you plug in a custom fixer component — one that receives a set of files and says which ones it changed — and have the library take care of walking the commit graph, calling the fixer, and rewriting any commits whose file trees were updated. The API should support skipping files that haven't changed compared to their parent commit (or optionally including them), and it should return a summary of what was done: how many commits were examined, how many were rewritten, and a mapping from old commit IDs to their new equivalents.

I also need a parallel version of the fixer that can process many files concurrently rather than one at a time. If any file fails during parallel processing, the error should be propagated immediately with no partial results. Errors from the fixer component generally should bubble up cleanly through the top-level API.
