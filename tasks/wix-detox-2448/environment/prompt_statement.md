I'm working with Detox and I want to improve how session configuration is handled. Right now, if I include any session configuration in my project config, I have to specify both the server address and the session ID — otherwise it throws an error. This is too rigid; I'd prefer the system to auto-generate those values when I don't provide them, and only validate them if I do provide explicit values.

I also want to add support for a synchronization debugging timeout as a proper session configuration option. Currently this can only be set through a command-line flag, but I'd like to set it in the project config file so my team doesn't have to pass the flag manually every time. The value should be settable at the global config level or per device, and the CLI argument should be able to override it when needed. The runtime behavior should also pick up this setting from the session config rather than from the command-line argument.

Additionally, it would help to have a utility that validates whether a given value is a proper WebSocket URL, since the server configuration property needs that kind of check — and the error messages for invalid server addresses, session IDs, and the new synchronization debugging property should all be informative and point developers to where the problem is in their config.
