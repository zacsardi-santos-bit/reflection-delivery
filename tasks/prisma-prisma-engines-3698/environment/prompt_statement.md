I'm working on the SQL schema describer library in a Rust database tooling project. Right now, the table data structure uses a simple boolean field to track whether a table is a partition. This approach is becoming limiting — I need to also track whether a table has child tables inheriting from it (relevant for PostgreSQL table inheritance), and using a separate boolean per property doesn't scale well.

I'd like to replace that single boolean field with a proper bitflags field that can represent multiple table properties at once. The new field should use a bitflags enum with at least two variants: one for partition tables and one for tables that have inheriting subclass tables. The serialized JSON output should also change so that instead of outputting a boolean for the old partition property, it outputs a numeric integer representing the combined flags.

All the places in the codebase that currently create partition tables using the old dedicated method need to be updated to use a new, more general method that accepts a set of property flags. The walker methods for reading these properties from a table also need updating — the existing partition-check method should read from the new flags, and a new method should be added to check whether a table has subclasses. The PostgreSQL describer additionally needs to query and populate the subclass flag from the database metadata.
