I'm building a New Relic agent instrumentation layer for the Azure Functions serverless platform, and I need to implement the instrumentation module from scratch. Right now, when Node.js applications run as Azure Functions and register HTTP handlers using the official SDK, the agent has no visibility into those invocations — no transactions are created, no attributes are captured, and nothing shows up in New Relic.

I need to add a new instrumentation module that wraps the handler registration methods provided by the Azure Functions SDK. When a developer registers an HTTP handler (using any of the supported registration methods — generic HTTP, GET, POST, PUT, PATCH, or DELETE), the agent should transparently wrap it to create a web transaction, record the relevant function-as-a-service attributes (including invocation ID, function name, trigger type, and a cloud resource identifier built from the Azure deployment environment variables), and finalize the transaction when the handler completes.

The instrumentation should also handle these details: the first invocation after deployment should be flagged as a cold start, but only the first one; incoming distributed tracing headers should be read and linked to the parent trace; queue time should be derived from request headers when present; the port from the request URL should be captured; and if a handler function is passed directly instead of wrapped in an options object, that should work too.

If the required deployment environment variables are not available or not in the expected format when the instrumentation initializes, it should log a warning with structured diagnostic information — specifically which variables were expected and what values were actually found — rather than throwing an error or silently proceeding.

Separately, I also need the agent's logging utility to support embedding structured data objects under a named key when writing log entries, so that diagnostic data can be attached to log messages in a structured way.
