I'm working on the attribute path resolver in the workflow engine. When a task's output is a binary-encoded dataclass and a downstream task accesses a specific field of that output through a promise, the system is returning the leaf value wrapped in a binary blob instead of giving back a properly typed primitive. For example, if the resolved field is an integer or a float or a boolean, it should come back as a typed primitive literal that the runtime understands natively — not re-encoded back into binary.

The resolver currently only handles a narrow range of numeric types. It needs to be extended to support all common integer widths, both signed (various sizes) and unsigned (various sizes). For unsigned integers that are too large to represent as a signed 64-bit value, the function should return a clear error rather than silently producing a wrong result. For all other in-range integer types, float types (both single and double precision), strings, and booleans, the function should return the appropriate typed primitive literal. Unsupported types should also produce a clear error.

There also needs to be a new named error code for cases where a value cannot be converted to a valid primitive type — this error code string should be present in the returned error so callers can identify the failure reason.
