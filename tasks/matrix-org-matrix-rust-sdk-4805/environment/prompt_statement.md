I'm working on a Rust SDK that handles authentication using an OAuth 2.0 flow, but the public API currently uses naming that references a narrower identity protocol standard instead of the broader OAuth 2.0 terminology. This creates confusion for developers who know OAuth but keep encountering type names, method names, module paths, and error variants tied to the more specific standard.

I'd like to rename the authentication module, its public types, the relevant client method, and all associated error types to use consistent "OAuth" naming throughout. This includes the main authentication struct, the authorization data type, the error enums and their variants (including how they appear in the top-level error type and the token refresh error type), the variant used in the cross-signing reset flow, and the internal caching field and its lookup key. The method for fetching server metadata should also be renamed to drop the narrower standard's name in favor of something more general.

The goal is that any developer looking at the public API surface can immediately understand they're working with an OAuth 2.0 integration, without having to know that it was previously labeled differently. All imports from the authentication module should come from an "oauth" path rather than an "oidc" path.
