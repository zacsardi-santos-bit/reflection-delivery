I've been investigating a scenario where a malicious peer in the block sync network can cause a node to get permanently stuck in block synchronization. Here's what happens: the attacker first reports an extremely large blockchain height — say, the largest value an integer can hold — causing our pool to set that as its target. Then the attacker reports the real, much smaller height. Since our code only updates the maximum tracked height when the peer that reported it is removed with an exact match, the pool never corrects itself and just keeps trying to reach the original fake maximum forever.

I need the block sync pool to detect when a peer reports a height or base that is lower than what it claimed before. This situation should never happen on a legitimate network — a blockchain only grows — so any peer doing this should be treated as malicious: removed from the pool and temporarily banned. Once that peer is gone, the pool should recalculate the true maximum height from the remaining peers and be able to catch up normally.

There should also be a way to query whether a specific peer is currently banned, so that other parts of the system or tests can verify that the malicious peer was correctly identified and excluded.
