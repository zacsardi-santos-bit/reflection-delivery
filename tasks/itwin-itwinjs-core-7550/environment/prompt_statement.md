I'm working on cleaning up the public API surface of our core common library. There are a few related changes I need to make.

First, we have some internal rendering classes — specifically classes for packed feature tables and related model lookup tables — that are currently exported directly from the main public feature table module. These are internal implementation details and shouldn't be part of the public surface. I need to move them to a new internal module under a dedicated internal subdirectory so they're no longer accessible through the main public module.

Second, we have a plan projection settings class that has a constructor that was meant to be internal-only but is still technically accessible from outside. The class already has a static factory method that is the intended creation mechanism. I need to make the constructor private so the factory method is the only supported way to create instances. The factory method should return nothing when given an empty configuration object — this lets callers distinguish "no settings" from "settings with all defaults."

Third, the feature overrides class has some internal backing fields that are currently accessible from subclasses even though the base class already exposes the equivalent data through proper public getter properties. The internal backing fields for the always-drawn and never-drawn element sets, and for per-model appearance overrides, should be made private so subclasses can no longer access them directly. The backing fields for per-element overrides, subcategory overrides, visible subcategories, and per-model subcategory overrides should remain accessible to subclasses as before.
