I'm working with async message-passing channels and I've noticed that the receiver side has no way to inspect the channel state without actually consuming messages. I'd like to be able to check things like: is the channel currently closed? are there any messages waiting? how many messages are currently buffered? These would be really useful for monitoring and conditional logic without disturbing the queue.

Specifically, I'd like the receiver for both bounded and unbounded channels to support three new inspection methods: one that reports whether the channel has been closed (either because it was explicitly shut down or because all senders have gone away), one that reports whether the buffer is empty, and one that returns the exact number of buffered messages. The closed check should correctly handle edge cases — like a channel that still has messages but no senders should be considered closed, a channel with an outstanding reserved permit should not be considered closed, and dropping all strong senders while only weak references remain should still count as closed. The message count should not include any internal sentinel entries that the channel uses to signal closure internally, so an empty closed channel should report a count of zero.
