I'm working on adding a "raw" socket forwarding mode to BuildKit. Right now, the socket forwarding mechanism always wraps forwarded Unix sockets in SSH agent protocol handling — but I want to be able to forward arbitrary Unix domain sockets (like a plain HTTP server listening on a socket) directly into a build container without any protocol wrapping.

I need to extend the socket configuration struct in the SSH provider package with a boolean field for enabling raw mode, and update the provider logic so that when raw mode is on, it connects to the backend socket and proxies bytes directly rather than going through the SSH agent protocol. The command-line argument parser for the build tool also needs to understand a "raw" key-value option that can appear anywhere in the comma-separated socket config string.

For validation: raw mode should only work with a single Unix domain socket path — passing zero paths or more than one path should be an error, and passing a regular file path (not an actual socket) should also be an error. When everything is valid, the provider should transparently proxy bidirectional byte streams between the forwarded connection and the container, handling multiple sequential messages and large payloads correctly.
