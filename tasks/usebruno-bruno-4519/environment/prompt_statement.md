I'm working with Bruno's variable interpolation in request templates. When I set an environment variable to a whole object or an array and then reference it in a template placeholder, I'd expect to see the JSON representation of that value in the output. Instead, the value isn't rendered correctly. The same problem happens with date and time objects — they should serialize to their standard quoted ISO string form, but they don't. I'd like the interpolation system to automatically stringify objects, arrays, and date/time values using standard JSON serialization when they appear as placeholder values, including when those complex types are nested inside other objects.

On top of that, I'm running into a naming collision problem. When an object has a property whose name contains a dot character, I have no way to reference it in a template without it being interpreted as a nested path traversal. I'd like a bracket-notation syntax that lets me explicitly look up a literal key by name inside a parent object, so I can distinguish it from the dot-path traversal syntax. Both notations should work side by side in the same template.
