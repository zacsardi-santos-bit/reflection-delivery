I'm working with the OpenTelemetry C++ SDK and I need to add a way to export log records to an OpenTelemetry Collector over gRPC. Right now the SDK supports exporting traces via gRPC and logs via HTTP, but there's no gRPC-based log exporter available. I want to be able to wire up a log provider and batch processor to send logs over gRPC the same way traces are currently sent.

The new exporter should work with the existing log provider and batch processor: when a logger emits a log record, the batch processor should collect it and pass it to the exporter, which forwards it to the collector via gRPC. The exporter should return a success result when the gRPC call succeeds and a failure result when it doesn't. After the exporter is shut down, any subsequent export attempts should also return a failure.

Log records should support rich context — trace and span identifiers, trace sampling flags, severity level, log name, message body, and key-value attributes with various data types including booleans, integers of different widths, floating-point numbers, strings, and arrays of each. The exporter configuration (endpoint, SSL settings, timeout, metadata headers) should follow the same pattern as the existing gRPC trace exporter options.
