I'm working on a deployment platform that supports multiple deployment plugins. Right now, when you update the deploy targets for an application, the system just takes a flat list of target names. That's a problem because we now have multiple plugins, and each plugin should manage its own set of targets independently.

I need to update the relevant interfaces and their implementations so that deploy targets are represented as a map from plugin name to that plugin's list of targets, rather than a single flat list of strings. This change needs to be reflected consistently: in the core datastore interface, in any local interface wrappers in the API layer, and in the mock implementations used for testing. The test mock file in particular needs to have its method signature updated to use the new plugin-keyed map type.
