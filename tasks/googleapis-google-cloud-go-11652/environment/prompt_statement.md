I'm working on improving the distributed tracing support in the Cloud Spanner Go client library. Right now, when I run a read-write transaction with a transaction tag and execute queries with request tags, those tags don't show up anywhere in the trace spans. The spans are also missing useful context like the database name, instance name, and client library version — things that would make it much easier to investigate issues in production.

I'd like to introduce a set of tracing helper functions in the spanner package that standardize how spans are created and ended, and that automatically extract relevant attributes from the RPC request objects being sent (such as transaction tags, request/statement tags, and SQL text) and attach them to the active span. When tracing is not enabled, these helpers should be a no-op with minimal overhead.

The end result should be that a read-write transaction span carries the database name, instance name, detected region, client version, repository, artifact details, and the transaction tag, while a row iteration span carries the statement tag, SQL text, and the enclosing transaction tag when those are present. A benchmark should also demonstrate that the attribute-setting logic skips unnecessary work for non-recording spans.
