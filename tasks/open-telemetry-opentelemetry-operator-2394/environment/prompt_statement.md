I'm working on the OpenTelemetry Operator and need help adding support for automatically generating Kubernetes cluster-level access control resources based on the collector's configuration. Right now, when users configure the collector to detect and enrich telemetry with information about the underlying infrastructure — for example, by using a resource detection processor that reads from the Kubernetes API or OpenShift API — they have to manually create the appropriate permissions in Kubernetes. This is cumbersome and error-prone.

What I'd like is for the operator to inspect the collector's configuration and automatically determine what cluster-level permissions are needed. If the configuration requires access to Kubernetes node information, it should generate the appropriate cluster role and binding. If it requires access to OpenShift infrastructure data, it should generate the corresponding permissions for that. If no special permissions are required (e.g., the collector only uses basic receivers and exporters), nothing should be generated.

The permission-derivation logic should analyze the collector's raw configuration, and the Kubernetes resource generation (cluster role and cluster role binding) should be built on top of that analysis.
