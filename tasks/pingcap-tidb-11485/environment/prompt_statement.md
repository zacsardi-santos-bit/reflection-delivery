I'm working on the chunk column implementation in our database engine. We currently keep a cached integer on each column to track how many values are null, and we update it manually every time anything touches the null bitmap. This is getting error-prone — there are multiple places that touch the bitmap but don't update the count consistently, and the count can drift out of sync with reality.

I'd like to remove the cached null count field entirely and instead compute the null count on demand from the null bitmap whenever it's needed. That way there's no synchronization to maintain and the count is always correct. All the places in the package that currently read or write this field need to be updated accordingly.

In addition, I want to add a set of bulk pre-allocation methods for fixed-length column types (integers of various sizes, floating-point types, and decimals). Each method should take a length and reset the column to exactly that many null rows — replacing whatever was there before. After pre-allocation, standard append operations should still work and correctly add a non-null row at the end. There should also be a way to mark an individual pre-allocated row as not-null (or null), and the null count returned by the method should accurately reflect the current state of the bitmap at that point.
