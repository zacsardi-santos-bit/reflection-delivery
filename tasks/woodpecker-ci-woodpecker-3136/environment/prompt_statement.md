I'm working on improving how pipeline step errors are reported. Right now, when a step fails with a non-zero exit code or gets killed due to running out of memory, the error message uses the step's display name. This isn't ideal because step names aren't unique — you can have steps with the same name across different pipelines or parallel runs, making it hard to trace which exact step instance failed.

I'd like to change the error types so they use the step's unique identifier instead of its name. The error messages should clearly indicate the unique identifier followed by the exit code for exit failures, and the unique identifier followed by the out-of-memory kill description for memory exhaustion failures. This would make it much easier to correlate errors with specific step instances in logs and debugging tools.
