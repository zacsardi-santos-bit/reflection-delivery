I'm working on making webhook retry and timeout settings configurable on a per-project basis rather than globally. Right now, the server has a single global configuration for how many times to retry auth and event webhooks, how long to wait between retries, and when to time out — and every project is forced to use those same values. I want each project to be able to set these parameters independently through the project update API.

To support this, the webhook client needs to be updated so that retry and timing options are provided at the time a webhook is sent rather than being fixed when the client is created. This way, the correct per-project settings can be applied dynamically for each outgoing webhook call, without needing a separate client instance per project.

On the data model side, the project and its updatable fields need new fields to hold these per-project webhook timing and retry values for both auth and event webhooks. The project update validation logic should also reject invalid duration strings for these new fields, as well as for the client deactivation threshold field. Additionally, the global server configuration should be simplified to remove the webhook timing and retry fields that are moving to the project level, including removing the global client deactivation threshold default. The database layer for creating and initializing projects should also be updated to reflect that these settings are no longer set globally at creation time.
