I'm working on the Cairo language's array library and I want to change how element access by index works. Right now, looking up an element in an array requires passing the array as a mutable/owned value, and the array gets returned alongside the result — even though the lookup doesn't modify the array at all. This is cumbersome and wasteful.

I'd like the array element access operations (both the version that returns an optional result and the version that panics on out-of-bounds) to instead work with an immutable snapshot of the array. That way, the caller doesn't need to hand off ownership, and the array doesn't need to be returned. Since the array is borrowed rather than consumed, the returned element should also be a read-only reference rather than a copy.

This change should propagate through the low-level Sierra intermediate representation as well — the generated code should reflect that the array is no longer returned from the libfunc on either the success or failure branch. Programs that use array element access (such as the Fibonacci array example) should be updated to account for the fact that the returned element is now a reference that may need to be dereferenced when used in arithmetic.
