I'm building a chat pipeline in Haystack and I need a prompt builder component that works with lists of chat messages instead of plain strings. Right now there's a "dynamic" variant, but it's being deprecated and I'd like a clean replacement that handles both static and dynamic use cases in one component.

Specifically, I need a component I can initialize with a default list of chat messages — where user and system messages can contain template placeholders — and have it automatically expose pipeline input sockets for those variables. I also want to be able to pass in an explicit list of variable names if I don't want variable inference from the template, and mark some variables as required so the component raises a helpful error when they're missing rather than silently producing broken output.

At runtime, the component should render each user and system message by substituting the provided variable values, while leaving assistant messages completely unchanged. I also want to be able to override the entire template at runtime by passing a fresh list of messages, which is useful when different pipeline paths need different prompts. The component should raise a clear error when no template is available at all, when the list is empty, or when the list contains non-message objects. It should also catch invalid template syntax as early as possible — either at initialization or when the template is first rendered.
