I'm working on the Sui blockchain's RPC layer and need to add two things. First, I need to expose a new API endpoint that lets clients query the current system state — things like the active validators, staking pools, protocol parameters, and epoch information. Right now there's no way to get this information through the RPC without doing individual object lookups, which is cumbersome for tools that need the full picture.

Second, I've noticed that addresses are being serialized without the "0x" prefix, so they come out as bare hexadecimal strings. They should always appear with the "0x" prefix to match the expected convention. This affects addresses that appear throughout the system state, including validator addresses in staking pool records and validator metadata.

For the new system state endpoint, the response should include the full validator set structure with active validators, pending validators, next-epoch validator metadata, delegation staking pools (with pending delegation and withdrawal entries), system parameters, storage fund, treasury cap, and validator report records. The endpoint should be part of the Full Node API and require no input parameters.
