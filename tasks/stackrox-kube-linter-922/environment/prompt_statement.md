I'm working on adding a new lint check to kube-linter that validates whether the volume claim templates defined in a StatefulSet carry a required annotation. Right now there's no built-in way to enforce annotation policies on StatefulSet storage, so teams can accidentally deploy StatefulSets whose volume claim templates are missing required metadata like backup policy labels or billing tags.

I need a new linting template that accepts a configurable annotation key as its parameter and checks that every volume claim template in a StatefulSet has that annotation present. If any volume claim template is missing the annotation — whether the template has some other annotations or no annotations at all — the linter should produce a diagnostic that clearly states the StatefulSet resource type and names the expected annotation. If all volume claim templates carry the annotation, no diagnostic should be produced. The configuration should also reject setups where the required annotation parameter is not specified.

Additionally, the linting infrastructure needs a utility to extract the spec from a StatefulSet object, handling both directly typed objects and those that embed the spec via reflection (falling back gracefully when the object is not a StatefulSet). There also needs to be a function that returns the API version string for PersistentVolumeClaim resources.
