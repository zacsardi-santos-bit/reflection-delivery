I'm working on a Python interpreter implementation and I've run into a correctness issue with how boolean expressions are evaluated in conditional statements. Python guarantees that each operand in a compound boolean expression (using "and" or "or") has its truthiness checked at most once — this is part of proper short-circuit evaluation. However, the interpreter I'm working on appears to be evaluating the truthiness of operands more than once when they appear as conditions in "if" statements, "while" loops, and "assert" statements.

To illustrate the problem: if I create an object whose truth-check method raises an error the second time it is called, and then use that object inside a compound boolean condition, the error gets triggered even though standard Python semantics say it shouldn't be. The object's truth value should only be checked once per evaluation.

The fix should ensure that each operand in a compound boolean condition has its truth value determined at most once, so that objects with side effects in their truth-checking methods are never called more than once per use. This correctness guarantee should hold for boolean conditions in "if" statements, "while" loops, and "assert" statements.
