I'm working on the outbound routing layer in linkerd2-proxy and I need to add retry support to HTTP and gRPC route policies. Right now the proxy handles per-route timeouts but when a backend returns an error response — a server failure status for HTTP or a failure code in the trailers for gRPC — that error is immediately forwarded to the caller. I'd like route policies to optionally carry a retry configuration: how many extra attempts are allowed, what size of request body we're willing to buffer for replay, an optional per-attempt deadline, and which response conditions (HTTP status codes, or gRPC status codes read from response trailers) should trigger a retry.

The retry behaviour should interact correctly with the existing request-level timeouts. A per-attempt deadline should fire retries when attempts remain. Once retries are exhausted, that per-attempt deadline should be dropped so the final attempt isn't cut short unnecessarily. If an overall request deadline is also active and it expires after retries run out, the caller should receive a deadline-exceeded error rather than a normal response.

The retry configuration needs to live in the client-policy types for both HTTP and gRPC routes so that the outbound stack can read it when building the service for a given route.
