I'm working on the IP pool controllers in Antrea and I'd like to clean up the validation logic. Right now, IP range validation (parsing CIDRs, parsing start/end ranges, checking overlaps, validating against subnet info) is duplicated across the external IP pool controller and the IPAM controller, and the two copies produce different error messages for the same kinds of failures. This makes it confusing for users who get different wording depending on which type of pool they're configuring.

I want to consolidate this shared validation into a common package that both controllers can use, with consistent, user-friendly error messages throughout. For example, when a range overlaps with a range in another pool, the error should name both the conflicting ranges and identify the resource type and name of the other pool. When a range falls outside the configured subnet, the message should be the same regardless of which controller catches it. Prefix length errors should also follow a consistent lowercase style.

There's also one correctness issue: the current code rejects deletion of existing IP ranges in a pool but still allows them to be updated (changed), which should not be permitted. The error message and validation logic should be extended to cover updates as well.
