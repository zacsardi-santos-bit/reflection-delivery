I'm working on improving the endpoint network policy query feature in Antrea. Right now, when you query which network policies affect a specific pod, the response lumps together all applied policies and all policy rules (both ingress and egress) into a flat structure. This makes it difficult to tell at a glance whether a pod is referenced as an ingress source, an egress destination, or both.

I'd like to refactor this so the internal types and the query method return a clearer structure that separately tracks: policies applied directly to the pod, rules where the pod acts as an ingress traffic source, and rules where the pod acts as an egress traffic destination. The response types used by the HTTP handler should also be defined in the handler package itself rather than being borrowed from the controller's internal types.

On the CLI side, the function that formats endpoint query output should become a standalone package-level function in the output package (instead of being embedded as a method on another type), and it should use updated, more descriptive section headers — something like "Applied Policies on Endpoint", "Egress Rules Referencing Endpoint as Destination", and "Ingress Rules Referencing Endpoint as Source" — so operators can quickly understand the output. When a section has no entries, it should clearly show "None". When no pod is found for the given query, the system should respond with a not-found indication rather than returning an empty result set.
