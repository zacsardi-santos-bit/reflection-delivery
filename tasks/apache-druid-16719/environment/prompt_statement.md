I'm working on a system that periodically cleans up unused data segments across multiple datasources. The coordinator runs a scheduled duty that submits kill tasks for these segments, but there's a fairness problem: when multiple datasources all have unused segments, the same datasource keeps getting picked in consecutive cleanup cycles while others are ignored. I'd like the scheduler to rotate through datasources in a round-robin manner so that no single datasource is chosen twice in a row as long as there are other eligible datasources.

To implement this, I need a reusable circular collection that holds an ordered set of elements and remembers its position between traversals — so each time you iterate it, you pick up where you left off and wrap back around to the beginning when you reach the end. It should support checking whether the set of elements it was initialized with matches a given set, so the coordinator can detect when the datasource list has changed and reinitialize the collection.

There's also a related bug: when a datasource has no unused segments in the first cleanup run (e.g., all its segments are currently used), it ends up being skipped in later runs even after unused segments accumulate. This needs to be fixed so that the duty correctly processes such a datasource once unused segments appear.
