I'm using PRQL to generate SQL for Microsoft SQL Server, and I'm running into an issue when I combine deduplication with row limits. When I write a query that groups records to deduplicate them (keeping only one row per group) and then limits the overall result set size, the PRQL compiler generates SQL that MSSQL rejects at runtime.

The problem is that MSSQL requires that any column referenced in an ORDER BY clause must also appear in the SELECT list when DISTINCT is used. The compiler currently inserts a placeholder expression in the ORDER BY clause for cases where no explicit sort order is given — this works on other databases but is invalid on SQL Server when DISTINCT is in play. The fix should make the compiler emit an ORDER BY that references an actual column from the SELECT list when targeting MSSQL with DISTINCT, while still producing the correct FETCH-style pagination syntax for row limiting.
