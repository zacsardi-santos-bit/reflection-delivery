I've noticed that when the Gleam compiler reports an inexhaustive case expression, the missing patterns it suggests don't always match the names I'd actually use in my code. For example, if I import a module under an alias and use that alias in my case expression, the suggested missing patterns still show the original module name — which isn't even valid syntax in my module. Similarly, when I import a constructor with a rename, the error suggests the original constructor name instead of the alias I gave it. And when a local type shadows an imported constructor, sometimes the error suggests an unqualified name that would resolve to the wrong type.

It would be much more useful if the suggested missing patterns always used whatever name and qualifier I'd actually write in code at that point — respecting module aliases, constructor aliases, unqualified imports, and any shadowing. The suggested missing patterns listed in the error should be copy-pasteable directly into the case expression to fix the error.

This should work correctly for all the ways a type constructor can be brought into scope: qualified with the original module name, qualified with a module alias, unqualified via an explicit import, renamed via an import alias, and for both user-defined types and built-in prelude types (including when prelude names are shadowed by local definitions).
