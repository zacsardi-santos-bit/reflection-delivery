I'd like to add a plugin persistence and garbage collection system to nushell's plugin infrastructure. Right now, plugins are started fresh for every invocation and discarded immediately, which wastes time on repeated process startup. I want plugins to stay running between uses so they can be reused, and I want users to be able to see which plugins are running, stop them manually, and configure how long an idle plugin keeps running before it's automatically shut down.

The garbage collection configuration should live under a dedicated section in the nushell config, with both a global default and per-plugin overrides. The timeout should only accept non-negative durations — negative values should be rejected with an appropriate error message. Plugins should also be able to opt themselves out of automatic garbage collection by sending a message to the host, and the host should never stop a plugin while it still has active streaming output.

On the protocol side, there needs to be a new kind of output message that a plugin can send to configure host-side behavior (like disabling garbage collection), and this message type needs to survive serialization and deserialization through both the JSON and msgpack encoding formats.

The type used to track which plugin a custom value originates from also needs to be updated — it should be shared by reference across all values it is attached to, and identity should be determined by whether two values share the same origin object, not by comparing their contents. Plugin custom values should remain usable even after their originating plugin has been stopped — the host should automatically re-spawn the plugin when the custom value needs to be processed.
