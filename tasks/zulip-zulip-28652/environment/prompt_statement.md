I'd like to refactor two functions in our frontend markdown module to have cleaner, more functional APIs. Right now, both functions work by mutating a message object that you pass to them — one parses markdown content and writes the rendered HTML and flags back onto the object, while the other extracts links from the message topic and writes them back onto the same object. This mutation-based style is hard to reason about and makes callers more awkward.

I want to replace these with pure, value-returning functions instead. The content renderer should take a raw text string and return a new object with the rendered output, message flags, and a status-message indicator. The topic-link extractor should take a topic string and return an array of link objects. Neither should mutate any input. The topic-link function should also stop requiring callers to pass the linkifier configuration at every call — it should read that from the module's own initialized state, just like the rest of the module does.

All existing callers (including the local-echo path for stream messages and direct messages) should be updated to use the new signatures — spreading the returned values into their own message objects as needed. When there is no topic (for direct messages), the topic links should be an empty array.
