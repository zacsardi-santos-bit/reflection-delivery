I'm working on the SQL database layer and I'd like to add a general-purpose helper for cursor-based pagination. Right now, any code that iterates over large result sets using a position marker has to manually implement the loop, cursor advancement, and error handling each time. I want a shared utility that handles this automatically.

The helper should accept a starting cursor, a function to fetch a page of results given a cursor and page size limit, a function to extract the next cursor from a returned item, and a callback to process each item. It should keep fetching pages until results are exhausted (either an empty page or a page smaller than the maximum page size), propagating errors from both the fetch function and the item processor. For fetch errors, the error message should indicate which cursor value was being used. For processing errors, the error should wrap the original so callers can inspect it.

At the same time, I want to rename and consolidate the existing batch query configuration type and its associated functions. The current naming only reflects one use case (batch IN-clause queries), but now that we're adding cursor-based pagination support, the configuration should be unified under a single type with separate fields for the batch size and the page size. The existing batch query execution function should be renamed accordingly, and all call sites updated to use the new names. The graph store configuration struct should also be updated to use the renamed field.
