I'm working on Spyder's plugin configuration system and ran into a problem with how shortcut defaults are validated. When a plugin provides default keyboard shortcuts, the keys must follow a specific two-part format with exactly one separator between the context and the shortcut name. Right now, if a key is malformed—either missing the separator entirely or having too many separators—the bad configuration is accepted without any error. This causes confusing issues later when the shortcuts system tries to parse those keys.

I'd like the configuration system to validate shortcut key names at initialization time and raise a clear error if any key doesn't follow the required format. Specifically, a key with no separator and a key with more than one separator should both be rejected immediately when the configuration object is created, rather than silently passing through to cause subtle bugs downstream.
