I'm working with a Rust SQL parser library and I need to add support for table sampling syntax. Right now, any SQL statement that includes a table sample clause in the FROM clause fails to parse — which means I can't use the library with real-world queries from Snowflake, Hive, ClickHouse, and other databases that support sampling.

The feature needs to handle several different forms of sampling: specifying a plain percentage or row count, specifying a sampling method name (like row-based, system-based, or block-based), bucket specifications where you pick a bucket out of a total number of buckets (with an optional column expression for the hash), an optional seed or repeatability value for reproducible samples, and an optional offset. The sampling clause can appear either before or after the table alias, and which position is used should depend on the dialect.

The table reference type in the AST needs a new optional field to carry the sample specification. I also need a helper function for creating a basic table reference from an object name with all optional fields defaulted, since many existing tests construct these struct literals manually and would need to be updated each time a new field is added. The dialect trait needs a new method to control whether sampling syntax appears before or after the alias.

The implementation should be verified by parsing and round-tripping various sample SQL strings for ClickHouse (using the SAMPLE keyword with fractional values and ratios), Hive (using bucket sampling and size-based sampling), Snowflake (using both SAMPLE and TABLESAMPLE keywords with different methods and seeds), and generic dialects.
