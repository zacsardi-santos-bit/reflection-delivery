I'm working on adding proper write-ahead log support for native histograms with custom bucket boundaries in Prometheus. Right now, when these histograms are written to the WAL, their bucket boundary definitions are not included in the encoding — only the bucket counts are stored. This means that when the WAL is replayed after a restart, or when the WAL is tailed for remote write, the boundary values are gone and the histograms cannot be correctly reconstructed.

I need to introduce dedicated WAL record types for custom-bucket histograms (both integer and float variants), separate from the existing standard histogram record types. The encoding for these new types should include the bucket boundary values. The decoder should be updated to handle both old and new record types through the same decoding methods. All places that read from the WAL — head replay, agent WAL loading, checkpoint creation, out-of-order buffer replay, and the WAL watcher — should be updated to recognize these new record types and process them correctly.

I also need test utility functions that generate sequences of custom-bucket histograms for use in tests, similar to the existing helpers that generate sequences of standard histograms.
