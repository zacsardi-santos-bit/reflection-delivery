Our blockchain storage tests require a lot of setup boilerplate: every test that needs a real database backend has to manually create a temporary directory, pass that path into the database constructor, and then clean up the directory afterwards. The cleanup code currently swallows errors silently, so if the removal fails we never find out. I'd like to introduce a temporary database type in our shared test helpers that manages its own storage lifecycle — tests should be able to just call a no-argument constructor and get a ready-to-use database without any path management. The helper function we use to build test blockchains backed by a real database should be updated to use this new type instead, removing the path parameter from its signature entirely. In the few remaining places where tests still manually remove a temporary directory, the cleanup should fail loudly with an error message rather than being silently ignored.
