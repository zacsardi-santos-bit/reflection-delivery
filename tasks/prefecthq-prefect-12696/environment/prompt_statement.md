I'm working on the Prefect server events system and need to implement a database-backed storage layer for events. Right now there's no way to query or count events stored in a relational database — I need to be able to write events to the database, query them with filters (by event name, resource, related resources, labels, wildcards, order), paginate through large result sets with stable page tokens, and count events grouped by time intervals, event types, or resources.

For the querying side, I need support for filtering by event name prefixes and exact names (with exclusion lists), by primary resource IDs and prefixes and labels (with wildcard matching), by related resources matching any of those criteria, and by event IDs. Results should default to descending time order but also support ascending. Pagination needs to produce stable pages using opaque tokens. An empty related-resource filter should be a no-op and not accidentally exclude events with no related resources.

For the counting side, I need to be able to count events grouped by time intervals (seconds, minutes, hours, days, weeks) where the intervals are anchored to a fixed reference point so that different queries over overlapping time windows see consistent bucket boundaries. Empty intervals should be backfilled with a zero count. Counting by event name or by primary resource should also be supported. The system should validate that the requested time interval is not too small (minimum 0.01 units) and that the total number of buckets is within a reasonable limit.

I also need a cross-database-compatible function to extract a JSON field from a column, working with both PostgreSQL and SQLite (including a mode that handles dotted key names by wrapping them in quotes in the SQLite JSON path syntax). And I need to fix an import that checks which version of the data validation library is available — it should use the correct constant from the data validation library's internal compatibility module.
