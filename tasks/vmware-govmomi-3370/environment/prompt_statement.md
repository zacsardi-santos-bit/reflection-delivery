I'm working with the vSphere Go client library's simulator and I've noticed that the virtual machine hardware upgrade operation doesn't validate preconditions properly. When I try to upgrade a powered-on VM, it doesn't fail the way real vSphere would. Same goes for VMs that are templates, VMs whose hosts are in maintenance mode, and cases where the requested version is unsupported or already met. The simulator just accepts the upgrade without checking any of these conditions.

I also need a utility type for working with hardware version strings in the "vmx-N" format — something that can parse them in a case-insensitive way, return the numeric version number, and produce a normalized lowercase canonical form. Right now there's no such helper in the types package.

Could you add the hardware version utility type to the types package, and update the simulator's upgrade implementation to properly reject upgrades when the VM is powered on, when the host is in maintenance mode, when the VM is a template, when the requested version isn't supported by the environment or by the VM's specific host, or when the VM is already at or beyond the requested version? Passing an empty version string should upgrade to the latest supported version. Also, the command-line upgrade tool should fail rather than succeed when the VM is already at the latest hardware version.
