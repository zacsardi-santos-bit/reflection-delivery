I'm working on adding a priority DAG file parsing feature to Apache Airflow. Right now, when I make changes to a DAG file, I have to wait for the DAG processor to cycle through all files before it picks up my changes. There's no way to tell it "please parse this specific file first." I'd like to add a REST API endpoint that lets authorized users submit a request to re-parse a specific DAG file with priority. The endpoint should accept an encoded file path, validate that the file is a registered DAG file and that the user has edit permissions on the DAGs in it, and record the request in the database. If the file isn't known or the user doesn't have permissions, it should return appropriate error responses. Duplicate requests for the same file should be handled gracefully and still return success. On the DAG processor side, at each processing loop iteration, it should check for any pending priority requests and move those files to the front of the parse queue, then clean up the requests. The database table holding these requests should also be excluded from the general database cleanup tool, since the processor manages its own cleanup.
