I'm working on the WildFly Core installation manager and I'd like to add a new option to the installation manager operations. Right now, when running operations like listing available updates, preparing an update, or reverting to a previous server state, administrators can either point to a custom local Maven cache directory or disable cache resolution entirely. But there's no way to say "I want to explicitly use the default local Maven repository" — you just get that behavior implicitly if you leave everything unspecified.

I'd like to add a new boolean option for explicitly opting in or out of the default local Maven repository to those three operations. When enabled, the operation should resolve and cache artifacts using the default local Maven repository. When disabled, no local repository should be configured. This option should also be surfaced on the CLI update and revert commands as a flag.

There are two important compatibility rules: if someone provides both a custom local cache path and the new option enabled, the operation should be rejected with a distinct error. If someone provides both the new option and the older flag for skipping cache resolution entirely, that combination should also be rejected with a different distinct error, since those two intents directly contradict each other. Each option on its own (without the other conflicting one) should continue to work fine.
