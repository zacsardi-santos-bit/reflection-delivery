I'm working on adding host-side support for WebAssembly GC struct types in Wasmtime. Right now there's no way for Rust host code to define struct types, allocate struct instances, or read and write struct fields — the runtime supports the GC proposal at the WebAssembly bytecode level, but there's no public API that lets embedders actually create and manipulate struct values from the host side.

I need a complete set of types and methods that let host code: define a struct type with typed, optionally-mutable fields; allocate a new struct instance with initial field values; read a field by index; write a mutable field by index; retrieve the struct's type; and iterate over all fields. The API should integrate naturally with the existing garbage-collection rooting discipline — operations on unrooted references should return errors, and passing references from a different store should cause a clear panic. Passing an unrooted reference as a field value during construction should return a recoverable error rather than panic.

Beyond basic struct manipulation, struct references need to work end-to-end with WebAssembly: they should survive round-trips through typed and untyped WebAssembly function calls, be storable in and retrievable from WebAssembly globals (set from both host and guest code), and be storable in and retrievable from WebAssembly tables (again from both sides). It should also be possible to check whether a general-purpose heap reference is a struct and downcast it if so, and to instantiate WebAssembly modules with host-provided globals whose value type is a nullable reference to a concrete struct heap type.
