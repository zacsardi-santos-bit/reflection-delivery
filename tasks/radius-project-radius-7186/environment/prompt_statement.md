I'm working on the CLI tool for the Radius platform. When I run the command to deploy and stream logs for an application, it currently only sets up port-forwarding for the application. I'd like it to also automatically detect and port-forward to the Radius Dashboard — a web UI that runs in the cluster — if it's present, so developers can access it immediately without any manual steps.

The detection should check the cluster for a running dashboard deployment. If the dashboard is found, a port-forward session should be established for it alongside the existing application port-forward. If the dashboard is not found, only the application port-forward should run.

As part of this change, the port-forwarding logic needs to be refactored to use Kubernetes label selectors (rather than plain application name strings) as the primary way to identify which pods to forward to. This should apply to both the application port-forward and the dashboard port-forward. There should be dedicated functions for creating the label selector for a named application (using a specific label key for the application name) and a separate function for creating the label selector that identifies dashboard pods (matching on the dashboard component's name and its group affiliation).
