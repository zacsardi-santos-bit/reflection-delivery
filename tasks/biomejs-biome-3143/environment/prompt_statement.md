I'd like to add a new lint rule to the nursery category of the Biome JavaScript analyzer that validates the autocomplete attribute on form input elements. The autocomplete attribute only accepts a specific set of standardized values defined by the HTML specification and related accessibility guidelines, but right now there's nothing catching invalid or misspelled tokens at lint time — browsers just silently ignore them.

The rule should flag input elements whose autocomplete attribute contains unknown tokens, invalid combinations, or improperly ordered values. It should also support a configuration option so users can list their own custom input component names, and those components get the same validation as native inputs. If the autocomplete value is a dynamic expression rather than a static string, or if the element's type is determined dynamically, the rule should skip validation for that element.

The diagnostic should clearly indicate that only a specific set of fixed values is accepted for the autocomplete attribute, and should link to the relevant accessibility and HTML spec references (WCAG 1.3.5, the HTML Living Standard autofill section, and the MDN documentation).

The rule also needs to be properly registered in all the right places — the nursery module declaration, the configuration schema, the diagnostics categories registry, and the options type registry — so it can be enabled and configured via the standard Biome configuration file. Additionally, any internal sorted lookup tables the rule uses should be verified by a unit test to ensure they remain in the correct order for efficient lookups.
