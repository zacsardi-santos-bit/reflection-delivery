I'm working with a GraphQL schema definition library and I need to add support for repeatable directives. Right now, every directive is treated as if it can only appear once per location, and any attempt to apply the same directive more than once at the same location is a validation error — even when the directive is intentionally designed to be used multiple times.

I need the SDL parser to recognize an optional keyword that marks a directive definition as repeatable, and the resulting AST node should carry a boolean flag reflecting this. The type system's directive representation should also expose a boolean property for repeatability (defaulting to false) so that code building directives programmatically can opt in. The SDL printer should include the repeatable marker in its output when the flag is set, so that schema roundtrips work correctly.

Most importantly, the validation rule that enforces directive uniqueness per location needs to be updated: repeatable directives should be exempt from the uniqueness check and allowed to appear multiple times at the same location without generating an error. Additionally, directives that are not defined in the schema should be silently ignored by this validation rule rather than triggering errors.
