I'm running into an issue with the MLflow S3 artifact repository not correctly detecting the bucket's AWS region in certain permission-restricted environments. The way it works today, the region is only extracted when the initial bucket check throws an error — but in our setup, the bucket check returns a normal successful response because our IAM policy allows limited access. The region information is available in the response's HTTP headers, but the current code doesn't look there when there's no exception. As a result, the S3 client ends up configured without the correct region, causing downstream connectivity problems. I'd like the implementation to also handle the case where the bucket check succeeds: if the successful response contains the region in its HTTP headers, that region should be used to configure the S3 client — just as it would be if the check had thrown an error. The error-based path should continue to work as before, and all the other client parameters (credentials, TLS settings, endpoint URL) should be unaffected.
