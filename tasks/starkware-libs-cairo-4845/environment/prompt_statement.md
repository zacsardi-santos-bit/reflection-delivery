I'm working on the gas metadata computation for Cairo programs and I've noticed that the gas solution output is missing several important runtime cost components. Right now, when I compute gas metadata for a program, the output maps for each statement and function only show costs like constant gas, Pedersen, Poseidon, bitwise, and elliptic curve operations — but execution steps, memory holes, and range check operations are not tracked separately.

This means that if I look at the gas solution for a function that does range-check arithmetic, the range check cost doesn't show up as its own field. Same for execution steps and memory holes — they're completely absent from the per-statement and per-function cost breakdowns.

I'd like the metadata computation to support computing and reporting these additional runtime cost components. Ideally there should be a configuration option to enable this behavior, and when it's active (or even in the default case), the gas solution maps should include entries for steps, holes, and range checks alongside the existing cost types. The values should be correctly attributed to each statement and function based on the operations they actually perform.
