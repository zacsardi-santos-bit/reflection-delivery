I need to add a reusable CAPTCHA verification service to the Ghost platform to protect endpoints from bot traffic. The service should wrap an external bot-detection provider and expose a middleware function that can be plugged into any HTTP route.

When a request comes in, the middleware should look for an anti-bot token in the request body. If the token is missing, it should pass an error downstream indicating the token is absent. If the external verification call itself throws or rejects, it should pass a graceful error downstream rather than crashing. If verification succeeds but the returned score is at or above a configurable threshold, it should pass a generic server error downstream (without leaking the actual score or provider details). If the score is safely below the threshold, the middleware should let the request through without any error.

The service should also support being disabled entirely — in that case the middleware should be a no-op that simply calls through to the next handler without performing any check. Configuration should cover at least: whether the service is enabled, the secret key used by the provider, and the numeric score threshold for flagging suspicious traffic.
