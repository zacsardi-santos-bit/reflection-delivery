I'm working on simplifying how snapshot filenames are generated and parsed. Right now, generating a filename for a snapshot segment requires passing in both a block range and a transaction range, but the transaction range shouldn't really be part of the filename at all — the block range is enough to identify a snapshot. I'd like to remove the transaction range from the filename format entirely, so the filename just encodes the segment type and block range (start and end).

This change needs to flow through the filename generation, the configuration-based filename generation (which appends filter and compression info), and the filename parsing — all three should stop using or returning a transaction range. The parser should also accept a plain string rather than the current input type, and return only the segment and block range. It should still correctly reject malformed filenames that are missing the block range numbers.
