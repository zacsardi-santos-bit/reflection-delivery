I'm working on a Tauri app that uses the isolation security pattern. When I send raw binary data from the frontend through the IPC layer, the backend receives it incorrectly — the binary payload ends up being treated as structured data instead of raw bytes, which causes deserialization failures. This seems to happen because the system reads the content type from the outer request headers rather than from inside the encrypted isolation payload, where the actual content type is embedded.

I'd like the IPC request parsing to be fixed so that when using the isolation pattern, the content type that was embedded inside the encrypted payload is used to determine how to deserialize the body. Raw binary payloads should produce a raw binary result, and structured payloads should still produce parsed structured data. The fix should work for both the isolation case and the standard case.

Additionally, it would be helpful if the encrypted isolation payload structure exposed its embedded content type field, and if the encryption key type provided a method to encrypt data so that the isolation flow can be fully tested. The macro used to set up application context for unit tests should also accept a test-mode flag that disables platform-specific code generation (like macOS plist embedding) that interferes with test compilation.
