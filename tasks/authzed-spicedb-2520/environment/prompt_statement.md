I'm working on the SpiceDB permission system and have run into two related issues I need to fix.

The first is a bug in schema change validation. When a relation allows both a plain subject type reference and a subject type combined with a specific sub-relation, trying to remove just one of those allowed variants doesn't work correctly. The system should only block the removal if relationships actually exist for that specific variant being removed — but right now it seems to conflate the two variants. If I have a relation that accepts both a plain type and a type-with-relation, and the only existing relationships use the type-with-relation form, I should be able to remove the plain type without an error, and vice versa.

The second is adding support for three new named query patterns used for relationship lookups. These patterns need to be registered in the list of all known specific query shapes, need appropriate database index hints assigned to them, and need validation rules that enforce which filter fields are required and which are forbidden. Specifically: one pattern finds resources of a given type and relation paired with subjects of a specific type and relation; another finds subjects of a specific type and relation without any resource filter at all; and a third finds resource-relation pairs matching a given subject-relation combination.

I also need to update the integration test infrastructure to support schema-writing operations alongside the existing permissions operations, since the steel-thread tests need to exercise schema writes as well. This means the client bundle passed to each test operation needs to include both permissions and schema service clients.
