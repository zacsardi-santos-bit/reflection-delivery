I'd like to add a new lint rule to catch cases where ARIA attributes are applied to HTML elements that don't actually support those attributes based on the element's implied accessibility role. Right now there's nothing stopping a developer from putting an "aria-checked" attribute on a link element, or "aria-expanded" on a plain list — even though those attributes have no effect because the element's role doesn't include them. This makes it easy to ship incorrect or misleading accessibility markup without any warning.

The rule should look at each JSX element's tag name and relevant attributes (like input type, or whether an anchor has an href) to determine the element's implicit ARIA role, then verify that the ARIA attributes used on the element are supported by that role. When they aren't, it should flag the element with a message identifying which attribute is unsupported. Custom components, elements with spread props, and elements with an explicit presentation role should be skipped since their effective role can't be determined statically.
