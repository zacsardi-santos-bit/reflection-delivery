I'm working on the Ansible operator watches system and need to add support for referencing roles using the fully-qualified collection name format — where a role is identified by three dot-separated parts: the collection namespace, the collection name, and the role name within that collection. Right now, the watches configuration only works with traditional filesystem paths for roles, but Ansible collections are increasingly the standard distribution mechanism for roles.

I need the role path resolution logic to return all candidate paths where a role might be found, rather than just one path, so that it can check multiple locations including the standard Ansible collection installation directories (both the system-wide location and the user's home directory). If a configurable collection path environment variable is set, only those paths should be searched instead of the system defaults. Existing behavior for the roles path environment variable should be preserved, and any paths in that variable should each contribute two candidates per entry.

Additionally, when loading the watches configuration, the system should fail with an error if a collection role is referenced but cannot be found in any of the expected locations. The watches configuration should also support the valid scenario where a collection role is correctly found via the collection path environment variable.
