I'm working on a data pipeline that reads change-data-capture events from multiple Kafka topics at once, where each topic uses a different serialization format. The problem is that when I deserialize rows from these different sources, each row loses track of which table it came from. I need the deserialization components to accept a richer table metadata object — one that encodes not just the schema (field names and types) but also the table's identity (catalog, database, and table name) — so that deserialized rows automatically carry their source table identifier.

Right now, the various deserialization schemas only take a bare schema type object as input. I'd like them to be updated to accept a table metadata object instead, and I need a utility to create these metadata objects from an existing schema type. Once rows are tagged with their table origin, I should be able to run a pipeline that reads from multiple Kafka topics (using different CDC formats on each topic) and correctly merges the results into a single database table, with proper upsert behavior based on row identity.
