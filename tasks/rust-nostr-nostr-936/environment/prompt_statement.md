I'm working on a Nostr library and I want to make the NIP-05 identity resolution logic available independently of any HTTP client. Right now, the NIP-05 support is hidden behind an optional feature flag and requires the library to make network requests internally. I'd like to separate the concerns: I should be able to fetch the NIP-05 JSON myself using whatever HTTP client I want, then pass the raw JSON string to the library to extract the associated public key and relay information for a given identity. The parsing types should be available by default, without needing any feature flags, so that all users of the library can work with NIP-05 identities. Essentially, I need an I/O-free way to parse a NIP-05 address and resolve a profile from a JSON string.
