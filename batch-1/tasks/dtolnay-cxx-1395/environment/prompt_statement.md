I'm working on the cxx Rust/C++ FFI bridge library and we're seeing build failures when running with modern Rust toolchain warnings enabled. The library uses a procedural macro to generate Rust boilerplate, and that generated code uses patterns that newer compiler versions flag as incompatible with upcoming edition requirements. Specifically, there are two kinds of issues: foreign function declaration blocks that are missing an explicit safety marker, and export attributes that need to be wrapped to indicate they're intentionally safety-relevant. Both of these patterns are now warnings (and treated as errors in our CI setup) on newer compiler versions.

The fix needs to update the code generator so it emits the correct modern syntax when running on newer compilers, while still generating code that works on older compilers that don't support the new syntax. After the fix, the entire test suite should compile and pass cleanly without any upcoming edition compatibility warnings, even when those warnings are treated as hard errors.
