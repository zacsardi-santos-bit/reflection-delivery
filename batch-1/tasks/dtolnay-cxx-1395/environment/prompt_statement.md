I'm hacking on cxx, the Rust/C++ FFI bridge crate, and I keep hitting build failures once I flip on the newer toolchain warnings, the ones previewing upcoming edition requirements, with warnings treated as errors in CI. The problem is the proc macro that generates all the Rust boilerplate for the bridges. Newer rustc versions flag a couple of the patterns it emits as not compliant. First, the `extern "C"` foreign function declaration blocks the macro spits out are missing an explicit safety marker, so on modern compilers those need to be written as `unsafe extern` blocks. Second, the export attributes the macro generates that carry safety implications need to be wrapped so they're explicitly marked as intentionally unsafe (the newer wrapping syntax for a safety-relevant attribute). Both of these are just warnings today but our CI denies warnings so they become hard errors and the whole thing won't build.

So what I want is to update the code generator so it emits the modern syntax when it's running under a newer compiler, while still generating the old-style code that keeps working on older rustc that doesn't understand `unsafe extern` or the attribute wrapping. Backward compat matters, I can't break folks on older toolchains. After the change the full test suite should compile and pass cleanly with zero upcoming-edition compatibility warnings even when those warnings are errors. This unblocks anyone using cxx under a strict deny-warnings policy across the range of Rust versions they might be on.
