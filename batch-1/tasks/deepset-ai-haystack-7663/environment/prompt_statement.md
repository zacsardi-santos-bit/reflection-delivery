I'm working on a Haystack chat pipeline and I need a proper chat prompt builder component, one that operates on lists of chat messages instead of plain strings. There's already a "dynamic" chat prompt builder floating around but it's being deprecated and honestly it's cumbersome, so I want a clean unified replacement that covers both static and dynamic (runtime-overridable) use cases in a single component that plugs naturally into the component system.

Here's what I want. I should be able to init it with a default list of chat messages where user and system messages can carry template placeholders, and it should automatically expose typed pipeline input sockets for the variables it finds in that template (only from user and system messages). I also want to optionally pass an explicit list of variable names at construction time that overrides inference from the template, plus a way to mark certain variables as required so that if they're missing at runtime the component raises a descriptive error naming exactly which ones are missing instead of silently producing broken output.

At runtime it should render each user and system message by substituting the provided variable values through the templating engine while leaving assistant messages completely untouched. Runtime should accept both plain keyword arguments and a dedicated template-variables dict, and on collision the dict wins. Oh and I want to override the whole template at runtime by passing a fresh list of messages, which matters when different pipeline paths need different prompts. It should raise a clear error when no template is available at all (neither at init nor at run), when the message list is empty, or when the list contains non-message objects. Also it needs to catch invalid template syntax as early as possible, either at initialization or when the template first renders, so I get a syntax error right away rather than something cryptic later.

This is the kind of first-class building block folks need for RAG and chat pipelines to wire multi-turn prompts straight from pipeline data.
