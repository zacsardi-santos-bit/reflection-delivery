I'm building out the Medplum super admin panel and want to add a section for debugging FHIR search performance, basically letting super admins see how a FHIR search string gets translated into an actual database query plus what execution plan the database comes up with. Right now there's no UI for this at all, and the server endpoint that runs the inspection is pretty limited, it returns just a single raw plan output without the SQL query text or the bound parameter values, and it only does one output format.

What I want is a form where a super admin types in a FHIR search string, optionally ticks a checkbox to enable a more detailed runtime analysis mode (an actual runtime analysis, not just the estimated plan), and submits it to the explain endpoint. On success I want to see three things shown in a modal dialog: the generated SQL query, the bound query parameters, and the database execution plan. So the endpoint needs to change too, it should now return all three (the generated SQL, the parameter bindings, and the plan output) and the plan output has to be available both as human-readable text and as structured JSON depending on the requested format.

Also I need the form to support scoping the query to run in the context of a specific user. That means either picking a project membership directly, or picking a project plus a practitioner or patient and having the system automatically resolve the matching project membership when both a project and a person are selected.

A few edge cases: if the search gets submitted without a query, nothing should happen, just no-op. If the operation fails (say insufficient permissions or whatever), show the error to the user. And if whoever's viewing isn't a super admin, this whole section should show an access denied message instead of the form. This helps us diagnose slow or expensive searches without needing direct database access, which speeds up troubleshooting a lot.
