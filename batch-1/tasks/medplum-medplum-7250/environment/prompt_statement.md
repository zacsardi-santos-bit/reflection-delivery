I'm working on the Medplum super admin panel and need to add a new section that lets super admins inspect how FHIR search queries are translated into database queries and what execution plan the database produces for them. Right now there's no UI for this at all, and the server endpoint that runs these inspections returns only a single raw plan output — it doesn't include the SQL query text or the bound parameter values, and it only supports one output format.

I'd like the admin panel to include a form where a super admin can enter a FHIR search string, optionally enable a more detailed runtime analysis mode, and then see the resulting SQL query, the bound parameters, and the database execution plan. The endpoint should support both a human-readable text format and a structured JSON format for the plan output. The form should also support scoping the query to run in the context of a specific user — either by picking a project membership directly, or by picking a project and a practitioner or patient and having the system resolve the right membership automatically.

If the search is submitted without a query, nothing should happen. If the operation fails, the error should be shown. If the user isn't a super admin, the section should show an access denied message instead of the form.
