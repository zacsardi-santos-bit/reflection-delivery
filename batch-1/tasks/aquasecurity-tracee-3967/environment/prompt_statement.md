I'm cleaning up the event dependencies manager in tracee and hit a few gaps that keep biting me. Right now the manager (see `@pkg/events/dependencies`) only tracks event-to-event dependencies, but events also depend on specific kernel probes, and I've got no way to know which probes are still in use when events get removed. I want it to track event-to-probe dependencies too, plus a probe lookup method that takes a probe handle and returns the probe node along with the set of events currently depending on it. And when an event's removed and no remaining event needs a given probe, that probe should get cleaned up from the manager.

I also need cancellation on the activation path. When I add an event and its deps, a subscriber should be able to return a cancel signal (via the actions it returns) that aborts the whole thing. On cancel the manager rolls back everything added during that call, removes all the partially-added events, fires the right removal callbacks, and returns a distinct error type so the caller knows it was cancelled. This is for graceful degradation, like a missing kernel symbol or a probe that won't attach, so we log a clear message, drop the event cleanly, and leave the rest of the pipeline alone instead of sitting in a half-initialized state.

The boolean returns are annoying too, event exists yes/no doesn't fit Go and can't distinguish failure modes. So event lookup, probe lookup, and event removal should return errors using a sentinel not-found value that callers check with errors.Is. Oh and the subscriber callback signature changes: instead of a void side-effect function, callbacks return a slice of actions so they can influence the outcome (that's how the cancel gets expressed).

Also, small stuff: I want some shared test helpers in a common package so they're reusable across test files, one for building policies from event IDs, one for capturing log output to a channel during tests, and one for asserting specific log messages showed up during a run. And there's a raw number in the policy validation code that should be a named constant instead.
