I'm hacking on the Gleam language server and there's a gap I keep running into. When someone writes a `let` pattern assignment that doesn't cover all possible values, the compiler flags a type error but the language server just leaves you hanging with no automated fix, so you're stuck manually restructuring the whole thing. I want to add a "Convert to case" code action that rewrites the inexhaustive assignment into a complete case expression.

Here's how the conversion should work. It pulls the non-discard variable names out of the original pattern and binds them in the new let. If there's exactly one non-discard variable it binds that directly, if there are multiple it collects them into a tuple binding, and if they're all discards (or there are none) the binding should use a wildcard `_` and the matched branch returns the unit value. The original pattern becomes the first branch returning those bound variables, and then all the missing patterns get appended as extra branches returning a placeholder value. Oh and the generated code needs to match the indentation level of the surrounding code so it doesn't look mangled.

Couple of important constraints: the action should only show up for actually inexhaustive patterns, not exhaustive ones (like a tuple pattern that already covers every case). Also when you've got nested inexhaustive assignments, it should only convert the one the cursor is sitting on, not the others. And it's gotta work across all the pattern kinds, so constructors, lists, tuples, bit arrays, string prefixes, and pattern aliases all need to convert correctly. This lives in the language server code action machinery, so wire it in alongside the other actions there. The point is saving folks time and cutting down mistakes when they turn these unsafe inexhaustive assignments into properly handled cases.
