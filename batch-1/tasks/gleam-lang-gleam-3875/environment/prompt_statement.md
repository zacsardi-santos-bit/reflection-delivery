I'm working on the Gleam language server and I'd like to add a code action that helps developers fix inexhaustive pattern assignments. Right now, when someone writes a pattern assignment that doesn't cover all possible values, the compiler shows a type error but the language server doesn't offer any automated fix. I want the language server to suggest a "Convert to case" action that automatically rewrites the assignment into a complete case expression.

The conversion should extract the non-discard variable names from the original pattern and bind them in the new let assignment — either as a single variable, a tuple of multiple variables, or a wildcard if all variables are discards. The original pattern becomes the first branch of the case expression returning those variables, and all the missing patterns should be added as additional branches that return a placeholder value. The indentation of the generated code should match the surrounding code's indentation level.

The code action should only appear for inexhaustive patterns — it shouldn't show up for patterns that are already exhaustive. When there are nested inexhaustive assignments, the action should only convert the one the cursor is actually positioned on. The action should work correctly for all kinds of patterns, including constructors, lists, tuples, bit arrays, string prefixes, and pattern aliases.
