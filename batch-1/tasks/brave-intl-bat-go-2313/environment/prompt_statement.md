I'm working on adding mobile in-app purchase support for a premium AI assistant subscription product. Right now, when a user makes a purchase through the Android or iOS app store and submits their receipt, we don't have the infrastructure to translate their mobile subscription identifier into the correct internal product definition, build the order, and properly mark it as paid. I need a set of utility functions that handle this entire flow.

Specifically, I need: a way to map mobile subscription identifiers — from various Android build flavors (release, beta, nightly) and iOS — to internal SKU names for both monthly and yearly billing periods, returning a well-defined error for any unrecognized identifier. I also need the product configurations (pricing, credential durations, issuance settings, Stripe product and price IDs) and payment processor redirect URIs to vary by deployment environment, with development/local environments using one set of values, staging another, and production yet another. Unknown environments should fall back to development defaults.

I need a function that validates receipt request data and produces clear, per-field validation error messages for missing required data or unsupported vendor values. I also need a function that maps purchase-specific error states — failed, pending, deferred, and unknown status — to distinct structured error codes that HTTP clients can handle programmatically, with a separate generic code for other validation failures and a 500-level response when the error is unexpectedly nil.

I need a function that assembles order metadata for a mobile purchase, capturing the external ID along with the payment processor and vendor labels appropriate for Android versus iOS origins. I need a function that builds the full new-order data structure from a request and list of items, handling edge cases like zero-total orders (which should be automatically set to paid), single-item orders that inherit the item's location, multi-item orders that have no location, and orders that inherit the validity duration from the first item that specifies one.

Finally, I need a function that orchestrates the full flow: resolving the subscription to a product, creating the order, marking it as paid with metadata, and propagating any errors from each step.
