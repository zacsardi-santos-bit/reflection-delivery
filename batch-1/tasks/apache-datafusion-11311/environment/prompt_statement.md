I'm working with DataFusion's Substrait consumer and running into an issue when trying to convert certain Substrait query plans into DataFusion logical plans. Specifically, any plan that uses an existence-check subquery as part of a filter fails with a "not implemented" error. This pattern is common in analytical queries — for example, filtering a set of orders to only those that have at least one matching line item satisfying some condition. The consumer handles other subquery types (like "value in a subquery result"), but existence-check subqueries are not supported yet.

I'd like to add support for this missing subquery type so that TPC-H-style queries (like Q4, which uses an existence filter over line items, and Q5, which involves joining multiple tables and computing revenue) can be correctly translated into DataFusion logical plans. The fix should handle the case where the existence-check subquery refers to an inner relation that also needs to be recursively translated, and should produce the proper DataFusion expression that represents an existence subquery in the logical plan.
