I'm on CockroachDB with a bunch of schemas in one database and Prisma's multi-schema introspection just isn't playing nice. When I turn on the multiSchema preview feature and introspect, the schema annotations on my models and enums come out wrong, or the whole introspection basically doesn't work for CockroachDB at all. For Postgres this all works fine already, every model gets tagged with the schema it belongs to, duplicate table or enum names living in different schemas each get their own definition, and foreign keys that cross schema boundaries stay wired up correctly. I want that same behavior for CockroachDB so it's at parity with the other supported connectors.

Concretely, when I re-introspect an existing Prisma schema that has bad schema assignments (say a model listed under the wrong schema), the engine should fix those to match where the thing actually lives in the database. If there's a table with the same name in two schemas, both should show up as separate model definitions each with the right schema annotation, and same deal for enums with a shared name across schemas, two distinct enum definitions with distinct annotations. And a foreign key that spans schemas should still be modeled as a proper relation with both sides tagged with their real schema location.

Right now CockroachDB users who spread data across schemas are just blocked from the multi-schema preview, which cuts them off from introspection generating or updating their Prisma schema, and that's a core part of the workflow. So can you add multi-schema introspection support to the CockroachDB connector so it behaves consistently with everything else?
