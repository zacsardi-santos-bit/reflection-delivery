I'm working on the Biome configuration migration tool. When users upgrade to the latest major version, the way file filtering works has changed — the old approach used two separate fields (one for including files and one for ignoring files) that now need to be merged into a single unified field where exclusions are expressed with a negation prefix.

I need a new migration rule that detects when a configuration still uses the old-style separate include and ignore fields, reports a fixable diagnostic, and offers a code fix that merges them into the new single-field format. The rule should apply across all relevant configuration sections — top-level file settings, per-tool sections like the formatter, linter, and assists settings, and items inside the overrides array.

The fix needs to handle several tricky cases: if only the ignore field is present without an include, a catch-all wildcard should be prepended; if some glob patterns use syntax that isn't supported in the new format (like single-character wildcards or character class brackets), those patterns should be skipped with an informational message explaining why each one couldn't be converted; and when the configuration file uses JSONC syntax (with inline comments and trailing commas), the tool should handle it correctly, including removing any comments that appear between the fields being merged.

Additionally, the spec test framework for migration rules needs to be updated to support JSONC input files (not just JSON), parse inputs with comment and trailing comma support, and require a version file alongside every test spec rather than falling back to a default version. All existing test cases that were relying on the implicit version default need explicit version files added.
