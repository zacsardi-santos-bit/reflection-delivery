I'm working on a Solidity ABI encoding library and I keep hitting the same wall: every encode call allocates a fresh heap buffer and hands it back as a vector. That's wasteful when I already know the encoded size up front and have memory set aside, like in embedded or constrained runtime setups, or when I'm assembling a bigger buffer piece by piece. What I want is a non-allocating variant that takes a pre-allocated mutable byte slice, writes the encoded data straight into it, and returns the count of bytes written. The bytes it writes have to exactly match what the allocating version would've produced, otherwise it's useless.

This write-to-buffer flavor needs to exist at every level of the encoding hierarchy, so for individual types, for the general encode trait, and for the parameter sequence encoding function plus its free-function wrapper. For the parameter sequence path specifically, the handling of top-level offsets for dynamic types has to stay consistent between the allocating and non-allocating variants, don't want them diverging on how they lay out dynamic data.

Oh and while I'm in here, I also need encoding and decoding to actually work for nested collection types, meaning nested fixed-size arrays, nested dynamic arrays, and nested tuples. These composite structures should produce standard-compatible ABI output and round-trip cleanly back through decode.
