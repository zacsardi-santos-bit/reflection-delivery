I'm working with Daft and I keep hitting the fact that there's no built-in way to slap unique row IDs onto a DataFrame that spans multiple partitions. I need IDs that are actually unique across all partitions, not just within one, so I can join computed results back to source data or track rows through sorts and joins and whatever transformations happen downstream.

What I want is a new DataFrame operation that generates a column of monotonically increasing unique integer identifiers. The column type should be unsigned 64-bit int. The encoding is the important part: pack the partition number into the upper 28 bits (so shift it left by 36) and put the row's position within its partition into the lower 36 bits. That bit-shifting scheme is what makes IDs unique across partitions without forcing a global sort or shuffle, which is the whole point.

Let me pick the column name too, defaulting to "id" when I don't pass one. Oh and it's gotta work on empty datasets without blowing up. Also the tricky case: when a single partition holds multiple internal tables (data chunks), the IDs still need to run sequentially across all of those tables within that partition, not restart per chunk.

I want this exposed at both levels, the high-level DataFrame API and the lower-level partition layer where I hand it a partition number and a column name explicitly. That way the underlying partition machinery does the real work and the DataFrame method wires it up across the whole distributed dataset.
