I keep hitting a crash in the Mitosis compiler whenever I drop an inline comment next to a state property value. Like if I define state with the store hook (useStore or whatever the store creation call is in the component) and I write a property with a `// comment` right after the value on the same line, the whole compile blows up. If I take the comment out, everything's fine again, so it's clearly about how inline comments inside the state object get handled during parsing. What seems to happen is the comment text bleeds into the property's value representation while parsing, so the internal component model gets corrupted and I end up with broken or invalid generated code for whatever target I pick.

What I want is for the parser to just ignore the comment and treat the property as if the comment was never there, producing identical output to the comment-free version. So the parsed internal representation should hold only the clean property value with none of the comment text hanging off it. Same goes for methods defined in that same store object, they shouldn't get messed up by adjacent comments either. And the component should compile cleanly to all the supported targets (React, Angular, Vue, Svelte, and the rest) with the comment gone from the output.

Honestly people naturally want to document their state props inline, so being blocked from a simple comment is a weird restriction, and worse it silently corrupts the compile instead of giving me a clear error. The parsing logic lives around the component JSON parsing bits, so that's probably where the comment stripping needs to happen when walking the store object properties and methods.
