I'm working on the OpenTelemetry Operator and I want it to stop making people hand-roll cluster RBAC when their collector config actually needs it. Right now if someone sets up a resource detection processor that talks to the Kubernetes API or the OpenShift API to enrich telemetry with infra metadata, they have to go manually create the cluster role and binding themselves, which is error-prone and honestly a terrible experience since they shouldn't need to understand the RBAC model just to get a collector running.

What I want is for the operator to inspect the collector's raw configuration and derive what cluster-level permissions it needs, then generate the Kubernetes resources on top of that analysis. So the permission-derivation logic reads the config first, and the cluster role plus cluster role binding generation builds on what that returns.

Concretely: when the config has a resourcedetection processor using the kubernetes (k8snode) detector, generate a cluster role granting get and list on nodes, plus its binding. When it uses the openshift detector, generate a cluster role with get, watch, list on infrastructures and infrastructures/status (the OpenShift infrastructure resources), plus its binding. And when the config doesn't need any Kubernetes API access at all, like it's just standard receivers and exporters with no resource detection, generate nothing, no role and no binding. That last empty case matters, don't emit stray resources when nothing requires them.
