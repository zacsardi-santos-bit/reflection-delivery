I'm cleaning up the OAuth callback flow in our app and the redirect handler is way too trusting right now. When users come back after logging in, the callback page basically just reads params off the URL and grants a session without verifying anything or exchanging the auth code for real tokens, so I want to tighten that whole path up.

Here's what I'm after. When someone lands on the OAuth callback, I first want to check that the code secret (the code verifier) we generated earlier actually got saved into the browser's local storage before we go any further. Then I want to confirm the state value in the redirect URL matches the nonce we stashed before kicking off the auth flow, since that's our request-forgery guard. Assuming that all lines up, and the authorization code param is actually present in the URL, we should fire a POST to the authorization server to swap the code for real tokens. If any of these steps falls over, the secret's missing, the state doesn't match, there's no code param, or the token exchange call fails, I want to bounce the user straight to the logout page instead of leaving them stuck in a half-broken session.

On the happy path, once we get a good token response back, start the user's session with the returned token details and then redirect them to wherever they were originally trying to go.

Couple more things on the store side. The auth store needs a new field for the code secret, tracked basically the same way we track the nonce today. And importantly, neither the nonce nor this new code secret should get wiped when the user logs out, both need to persist so re-authentication later still works. Oh and the query params type for the OAuth callback should reflect the actual OAuth fields we care about, which are the authorization code, the return destination, and the state value, so update that shape too.

The reason I care: without these checks the callback is exploitable and can hand out invalid sessions, so getting proper code verification plus token exchange in place brings us in line with standard secure auth practice.
