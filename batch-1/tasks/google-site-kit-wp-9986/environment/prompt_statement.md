I'm migrating the consent mode setup banner in Site Kit over to the centralized notification system instead of keeping it as a standalone widget component. Right now it's got its own bespoke visibility logic and gets rendered independently in the dashboard, and I want it registered as a proper notification in the central notifications registry with a requirement check that the notification system can evaluate to decide when to show it, so it gets consistent lifecycle management, dismissal tracking, and requirement evaluation like our other notifications.

The banner encourages users to turn on consent mode when they've got ads connected, so the requirement check should make the notification active (eligible to show) only when the user has ads connected but consent mode isn't yet enabled. If consent mode is already enabled it shouldn't be active even if ads is connected, and if ads isn't connected it shouldn't be active even when consent mode is disabled. Basically only show it when it's actually relevant to their setup.

Also the component itself needs updating so it accepts the standard props the notification system passes in (things like the unique notification id and the wrapper Notification component it hands down) rather than the widget-system props it currently expects. And it should return nothing (render null) when the banner's been dismissed or while dismissal state is still loading. That simplifies the visibility logic a lot and lets the notification infra control when it actually appears.
