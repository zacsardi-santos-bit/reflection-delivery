I'm adding a new nursery lint rule to Biome that catches unnecessary escape sequences inside JavaScript regular expressions. Right now there's nothing that flags this and I keep seeing folks escape characters that don't need it, like escaping a dot or a question mark inside a character class, or escaping a hyphen right at the start of a class where it's already literal anyway. It's harmless but it's noisy and honestly it misleads readers into thinking a char has special meaning when it doesn't.

So the rule should report a diagnostic any time it hits an escape that serves no purpose in its current context, and the message should be clear and actionable that the escape isn't needed. I also want a bit of contextual guidance in there explaining under what conditions that character *would* actually need escaping, stuff like "only outside a character class", or "only in the middle of the class", or "only as the first character". And it should ship a safe automatic fix that just strips the unnecessary backslash.

It's gotta handle all the fiddly context-sensitive cases though, so: the position of a hyphen in a character class (start vs middle where it means a range), characters that are only special outside a class, the caret's position-dependent behavior (a `^` as the first char of a class is negation so don't touch it), escapes like word-boundary assertions that only mean something outside a class, and the newer unicode mode flags which change what needs escaping. Don't flag things that are genuinely needed in their spot, like a hyphen mid-class denoting a range or that leading caret for negation. Oh and one behavioral difference from other JS linters, backreference-like escapes and named backreference syntax that's only meaningful in unicode-aware regex should still get flagged here when used in a non-unicode-aware regex, even though some comparable tools don't flag those. This all lives under the nursery group. The point is cleaner, more readable regex patterns with precise contextual messages so people aren't guessing.
