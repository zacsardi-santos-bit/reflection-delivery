I'd like to add a new lint rule to Biome's nursery group that detects unnecessary escape sequences in JavaScript regular expressions. Right now there's no automated check for this, and developers frequently escape characters that don't actually need escaping — like escaping a dot or question mark inside a character class, or escaping a hyphen at the very beginning of a class where it's already literal. These useless escapes are harmless but noisy and can mislead readers.

The rule should report a diagnostic whenever it encounters an escape sequence that serves no purpose in its current context. It should also include a brief contextual explanation — for instance, explaining that a particular character only needs to be escaped if it appears outside a character class, or only if it's in the middle of one. The rule should also provide a safe automatic fix to simply remove the unnecessary backslash.

The rule needs to handle all the nuanced cases: position of a hyphen in a character class, characters that are only special outside a class, the caret character's position-dependent behavior, escape sequences that only have meaning outside a character class, and the newer unicode mode flags which change what needs to be escaped. There's also a behavioral difference from other common JavaScript linting tools: backreference-like escape sequences used in a non-unicode-aware regex should be flagged here, even though some comparable tools don't flag them.
