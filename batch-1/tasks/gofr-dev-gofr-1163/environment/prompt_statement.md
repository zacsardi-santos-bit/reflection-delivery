I'm building a CLI app on top of the GoFr framework and there's just no built-in way to show users that something's actually happening during long-running work, no spinner, no progress bar, nothing, so everyone ends up rolling their own terminal UI which is inconsistent and duplicated effort. I want to add a terminal output utility inside the framework's command package that gives me ANSI escape sequence helpers for cursor movement, screen control, and line management, and then build two components on top of it.

First an animated spinner that comes in multiple visual styles, runs asynchronously, and stops cleanly when the operation's context gets cancelled. Second a percentage-based progress bar that adapts to the detected terminal width, so on narrow terminals it just prints the plain percentage and on wider ones it draws a full ASCII bar, and it also needs to stop cleanly on context cancellation.

Oh and the command context passed to handlers should carry this terminal output instance so handler functions can use spinners and progress bars naturally without creating their own output streams, and the framework's command runner should get initialized with this output too.

To show it off I want two example subcommands, one that shows a spinner while doing work then prints a completion message, and one that steps a progress bar through several percentages then prints a completion message. Both should handle context cancellation gracefully by returning the appropriate cancellation error.
