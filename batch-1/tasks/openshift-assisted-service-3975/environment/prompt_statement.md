I'm chasing a bug in the bare metal host controller for the assisted installer service, the part that reconciles hosts when the converged deployment flow is turned on. Right now when converged flow is enabled the controller unconditionally slaps a custom deployment method onto every bare metal host it's managing, and that's wrong. It's clobbering hosts it shouldn't touch, specifically ones that have been explicitly detached from management (they carry a detach annotation) and ones that aren't linked to any infrastructure environment at all.

What I want is for the custom deployment config in converged flow mode to only get applied when the host is both associated with an infra env and not in a detached state. So if a host is detached I need to leave its custom deployment method alone and keep the detach annotation intact, don't overwrite either. And if a host has no infrastructure environment association then skip it entirely, don't set the custom deployment method and don't add any new annotations either. Basically gate that one configuration step on those two conditions and skip the detached or unassociated hosts.

This matters because in managed bare metal deployments detached and unassociated hosts are in special states, and overwriting their deployment config can cause unexpected re-provisioning or mess with cluster teardown. Hosts that are properly linked and not detached should still get the custom deployment configuration during converged flow reconciliation like before.
