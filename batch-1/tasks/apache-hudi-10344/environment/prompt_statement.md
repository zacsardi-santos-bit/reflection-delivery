I'm hitting two annoying issues with Hudi's spillable map (the `ExternalSpillableMap` thing under `@hudi-common/src/main/java/org/apache/hudi/common/util/collection/`) that I want fixed together.

First problem: when the map spills to disk it opens up temp files and file handles, but those aren't actually tied to the map's lifecycle in any clean way. There's no reliable way to make sure the disk resources and handles get released when we're done, which bites us hard in error paths where stuff leaks. I want the map to implement Java's AutoCloseable so I can use it in try-with-resources and have close() guarantee the on-disk backing store and its handles get cleaned up. The DiskMap side (see `@hudi-common/src/main/java/org/apache/hudi/common/util/collection/DiskMap.java` and its implementations like the bitcask and rocksdb backed ones) should participate too so closing the spillable map propagates down to whatever disk backend is configured.

Second problem: on a freshly created map that's never had anything inserted, calling basic read-only stuff blows up. So isEmpty(), size(), containsKey(), containsValue(), keySet(), values(), entrySet(), the streams, and the iterator all throw because the disk storage is only lazily set up on first write, but these queries reach for it anyway even when there's nothing there. I need all of those to just work and return sane empty results without exceptions when the map is empty.

Both fixes need to hold no matter which disk map mode is set (bitcask or rocksdb), so please don't special-case one backend.
