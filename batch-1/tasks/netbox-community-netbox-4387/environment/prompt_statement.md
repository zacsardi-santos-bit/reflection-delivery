I'm heads-down on the cable path tracing in NetBox and hit two things that are broken, plus a validation snag.

First, circuits aren't treated as pass-throughs. If I patch a cable from a device interface into a circuit's A-side termination, and another cable from the Z-side termination out to a second device interface, the two interfaces don't show each other as connected. They should, exactly like patching through a patch panel does. The trace needs to follow the path across the circuit (A to Z) to reach the far-end interface, and both ends should report each other as the connected endpoint with a "connected" status. Also when I delete a circuit that's sitting in the middle of a complete path, the endpoint interfaces need their connected endpoint and connection status cleared so the connectivity doesn't linger as stale.

Second, longer chains of patch panels don't resolve. Two panels work fine, but if I route through four in a row it fails to identify the connected endpoint. Feels like it's how position gets tracked as the path traces through each panel, front-port to rear-port and rear-port to rear-port both need to hold up no matter how many intermediate panels there are.

Third thing, I can't create a cable between a rear port and a circuit termination without a validation error. The check that compares position count equality between two terminations is firing when it shouldn't, that constraint should only apply when both terminations are actually rear ports, not when one side is a circuit termination.

Net goal is all the common topologies resolve end to end: direct interface-to-interface, through any number of patch panels, through a circuit, and mixed combos of panels and circuits together. Circuits are how carrier and provider links between sites get documented, so without circuit-aware tracing operators can't actually see true end-to-end connectivity through NetBox, which is the whole point.
