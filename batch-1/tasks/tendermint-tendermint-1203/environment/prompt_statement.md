I'm reworking Tendermint's private validator because right now it's this one monolithic thing that jams key management, signing-state tracking, and persistence together, and it only runs inside the main node process. I want the concerns split apart, and more importantly I want signing to be delegatable to an external process over a network socket so operators can keep signing keys in a hardened isolated process (or dedicated hardware) instead of baking them into the main binary. It also just makes the validator interface cleaner for custom backends like HSMs or encrypted key stores.

So here's the plan. Move the JSON-based validator (the one reading an unencrypted key from a file) into its own new subpackage, with dedicated functions to generate a fresh validator, load one from a file, and load-or-generate. It should still persist to disk after every signing op, and it's gotta track the last signed height, round, and step to stop double signing, rejecting anything that would regress or conflict with already-signed data. Oh and when a vote or proposal comes back at the same height/round/step but with a different timestamp, don't fail, just silently restore the original timestamp and reuse the original signature.

Also I need a socket-based client and server pair. The server wraps an existing validator and handles incoming signing requests over TCP. The client connects and proxies everything: votes, proposals, heartbeats, plus address and public key retrieval. If the client can't connect after all retry attempts are exhausted it should return a specific "max retries exceeded" error, and there needs to be a way to configure the connection timeout on the client. Last thing, the time format string used when generating canonical sign bytes needs to be exported so the new subpackage can use it too.
