I'm building a real-time communication feature that needs to send encrypted messages directly to specific devices — not via a room, but device-to-device. Right now the SDK doesn't expose any way to do this. I need to be able to take a list of devices I already know about, pass in some arbitrary content and an event type, and have the SDK handle encrypting that content individually for each device and sending it via the standard direct device messaging endpoint.

The tricky part is failure handling. If one device can't receive the message — maybe the server rejects it, maybe we can't establish an encrypted session because no one-time keys are available — I don't want the whole call to fail. Instead, I'd like the method to collect all the devices that failed and return them to me in the successful result, as a list of (user, device) pairs, so I can decide what to do about each failure myself.

Since this is a new experimental capability that may change over time, it should be gated behind a feature flag so users can explicitly opt in. The feature flag needs to be wired through all the relevant crates so enabling it at the top level activates the underlying machinery.
