I'm working on a real-time comms feature and I keep hitting a wall: the SDK has no way to send encrypted messages straight to specific devices, device-to-device, not through a room. I need this for stuff like distributing session keys for audio/video calls, where I've got a known set of target devices and just want to push arbitrary encrypted payloads to them without the whole room message dance.

What I want is a single call where I hand it a list of devices I already know about, some arbitrary content, and an event type, and it encrypts that content individually per device using Olm (direct device-to-device encryption) and sends it via the standard direct device messaging endpoint (the to-device send path).

The failure handling matters a lot here. If one device can't receive it, maybe the server rejects delivery, maybe we can't set up an encrypted session because no one-time keys are available (keys exhausted), I don't want the whole thing to blow up with a top-level error. Instead collect the devices that failed and hand them back to me inside the successful result, as a list of (user, device) pairs, so I can inspect exactly which user and device combos failed and decide what to do about each one myself. Partial failure shouldn't block delivery to everyone else.

Since this is experimental and the API may still change, gate it behind a compile-time feature flag so people opt in explicitly. Wire that flag through all the relevant crates so turning it on at the top level actually activates the underlying machinery down in the crypto layer, don't just stub it at one level.
