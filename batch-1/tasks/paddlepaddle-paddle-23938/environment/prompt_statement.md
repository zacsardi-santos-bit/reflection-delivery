I'm filling in some gaps in the mixed-precision and distributed training pieces of our DL framework and hitting two things that need work.

First, in the mixed-precision utility module (the AMP helpers), there's no clean way to navigate the computational graph. I want a helper that takes a block descriptor and an operation descriptor, searches the block, and hands back that operation's index, or -1 if it isn't in there. And a second one that takes a list of operations, a specific operation, and a variable name, then returns the ops that come after the given op and actually consume that variable as an input. If nothing downstream consumes it, it should just return nothing. These lookups are what I'll lean on to get correct ordering and validation of the optimization ops during AMP training.

Second, the collective distributed optimizer wrapper needs tighter validation because right now bad configs either get silently mishandled or blow up deep in the training loop with a useless error. The distributed strategy config object is missing a flag to turn on automatic mixed precision mode, so add that attribute. Also when someone builds a collective optimizer with a recompute strategy but the recompute checkpoint list isn't actually a list type, I want that caught right at construction time with a clear error, not later. Then on the minimize call, if recompute is on but the checkpoint list is empty, raise a clear error before anything runs, and same deal if the base optimizer is already wrapped in a conflicting type (already a recompute or mixed-precision optimizer) while the matching strategy flag is set, since that's a double-wrapping mistake we shouldn't let through. Point is to stop these silent misconfig bugs so nobody burns an afternoon debugging a failure that was really just a setup typo.
