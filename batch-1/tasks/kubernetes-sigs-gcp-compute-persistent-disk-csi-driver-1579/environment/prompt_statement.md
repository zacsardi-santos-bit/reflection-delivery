I keep hitting garbled log output whenever something errors out, and I finally tracked it down. A bunch of our logging calls are using the `%w` error-wrapping verb, which is only supposed to be used when you're actually creating a wrapped error (like with `fmt.Errorf`). When you pass `%w` to a general-purpose logging function, Go doesn't wrap anything, it just dumps some internal representation of the error object into the log line instead of the actual error message string. So when I'm reading logs to figure out what went wrong, I get this useless mangled output instead of the readable error text I need.

Can you hunt down every one of these misused `%w` verbs in logging calls and swap them to `%v`, which is the right verb for printing an error value as a plain human-readable string. This needs to happen everywhere the mistake shows up, so please sweep the production code, the test infrastructure, and any utility or helper files too, not just one directory.

Oh and I also want a way to keep this from creeping back in. Set up some kind of automated check that runs as part of the build or test suite and fails whenever it finds a logging call using `%w`. That way if someone accidentally reintroduces the pattern later, CI catches it right away instead of us discovering it months later while debugging a production incident. The check should scan across all the source directories so nothing slips through.
