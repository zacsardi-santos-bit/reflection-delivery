I'm working with a supply chain planning tool that has released a new version of its data format, and I need to add the corresponding schema to SchemaStore so that users get proper editor validation support. There's already a schema for previous versions of this format in the registry, but the new version is missing.

The new schema should accept well-formed supply plan documents and reject documents that have common data errors. Specifically, it should catch cases where a batch size field is provided as a fractional number instead of a whole number, where a date field is given as a raw numeric timestamp instead of a properly formatted date string, where text identifier fields like material names, order names, or lot numbers are accidentally given as numbers, and where a document includes properties that aren't part of the format specification. It should also require that documents include a reference to the schema itself, rejecting any document that omits this required field.

In addition to the schema file itself, the new version needs to be registered in the catalog as the default version for this schema family, and the schema's custom validation formats and keywords need to be declared in the validation configuration file so the tooling doesn't report false errors about unknown keywords.
