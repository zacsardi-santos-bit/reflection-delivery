I'm adding support for a new version of a supply chain planning file format to SchemaStore so folks get editor validation and autocomplete when working with these files. We already carry schemas for the older versions of this format in the registry, but the latest version just isn't there yet, which means anyone on the new format gets nothing, no type checking, no missing-field warnings, no autocomplete.

So I need the new schema file itself plus a couple of wiring bits. The schema should accept a well-formed supply plan document (all required fields present with correct types) and reject the common data-entry screwups. Specifically it needs to catch when a batch or lot size field comes in as a fractional number instead of a whole integer, when a date field is handed over as a raw numeric timestamp instead of a properly formatted date string, and when text identifier fields like material names, order names, or lot numbers accidentally show up as numbers rather than strings. It should also reject any document carrying extra properties that aren't part of the format spec (so no additional props allowed), and it must require a reference to the schema itself, rejecting anything that omits that required field.

Beyond the schema file, the new version needs registering in the catalog as the default version for this schema family, and the schema's custom validation formats and keywords have to be declared in the validation config file too, otherwise the tooling throws false errors complaining about unknown keywords. Want all three pieces landed together so it actually validates end to end.
