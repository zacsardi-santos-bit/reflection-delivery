I'm working with the Go GitHub client library and I've hit a gap: there's no support for custom deployment protection rules on repository environments. These are third-party app integrations that gate a deployment before it proceeds, things like compliance checks or security approval workflows, and right now I'm stuck making raw HTTP calls which feels wrong. I want to add these operations to the repositories service so I can manage them the idiomatic way.

Here's what I need to do against a given owner, repo, and environment. First, retrieve all currently enabled custom protection rules for an environment, which should come back with a total count plus the list of rules. Also list the available app integrations that can be enabled as protection rules (again with a total count and the list). Then enable a new rule by specifying a particular app integration id, fetch a single rule by its ID, and disable (remove) a rule when it's no longer needed.

The data types should live alongside the rest of the repos environment code (around `@github/repos_environment.go`) and cover the individual protection rule (with fields like its id, node id, enabled flag, and the app details), the app integration itself, and the two list-style wrapper responses. Please give all these types the usual getter accessor methods this library generates (the `GetX()` style helpers that safely handle nil), so they match everything else. The methods hang off the RepositoriesService and should return the parsed type plus the `*Response` and error like the other methods in the service. Keep naming and signatures consistent with how the rest of the library does deployment and environment stuff so it reads naturally.

This brings the Go client to parity with the GitHub REST API for this feature area so teams can automate deployment governance in Go instead of hand-rolling HTTP.
