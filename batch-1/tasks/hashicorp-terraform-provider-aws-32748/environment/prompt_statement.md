I'm cleaning up the CloudFormation stack resource in the Terraform AWS provider and the stack-by-name lookups are a mess right now. They happen in a few different spots via raw API calls, and none of it plays nice with the provider's standard not-found handling, so when someone deletes a stack outside of Terraform our read and destroy paths can throw errors instead of just dropping the thing from state and offering to recreate it.

What I want is one exported function over in the cloudformation service package (`@internal/service/cloudformation`) that takes a stack name, returns the stack details, and when the stack doesn't exist or has been fully deleted it signals a not-found condition using the provider's built-in not-found error mechanism (the retry.NotFoundError style thing) so callers can cleanly remove the resource from state rather than erroring out. Then rip out the old lookup function that was doing this before and update every caller to use the new one, including any other packages that depend on it, not just within cloudformation itself.

Basically consolidate the duplication and make the missing-stack behavior predictable and consistent with the rest of the provider. Once it's wired up I need the package to compile cleanly and all the existing tests in the cloudformation package to keep passing.
