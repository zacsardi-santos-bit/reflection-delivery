I'm messing with the Cairo array library and the way element access by index works is bugging me. Right now if I want to grab an element at some index I have to pass the whole array in as a mutable/owned value, and then the array comes back out alongside the result even though the lookup never touches it. It's clunky and wasteful, forces an ownership handoff on every single index lookup even when nothing gets modified, and the generated code ends up bigger than it needs to be.

What I want is for the array element access ops to take an immutable snapshot of the array instead of consuming it. Both variants, the one that returns an optional element and the one that panics on out-of-bounds, should follow this. Since the array's just borrowed and never modified, there's no reason to return it, so drop that from the signatures, callers keep their original reference and the array's still available after the lookup. And because we're borrowing rather than consuming, the returned element should come back as a read-only reference (snapshot) to the value rather than a copy of it.

This has to flow all the way down through the low-level Sierra IR too, so the generated code should show the array no longer being returned from the libfunc on either the success or the failure branch. Oh and any programs that use array element access, like the Fibonacci array example, need updating since the returned element is now a reference that might need dereferencing when you use it in arithmetic.
