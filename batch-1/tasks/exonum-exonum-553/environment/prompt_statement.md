I'm working on a cryptocurrency service built on a blockchain framework. Right now, when a transfer transaction fails — for example, because the sender doesn't have a wallet yet, the recipient doesn't have a wallet yet, or the sender doesn't have enough funds — the transaction is silently ignored. It gets recorded in the blockchain but there's no way to tell from the outside whether it succeeded or failed.

I need the service to properly report execution errors so that when clients query the blockchain explorer for a transaction's status after it's been committed to a block, they get a structured response indicating whether the transaction succeeded or failed. For failures, the response should include a specific numeric error code that identifies what went wrong (missing sender wallet, missing receiver wallet, or insufficient balance). Successful transactions should be marked as successful.

The wallet API endpoints should also behave correctly: querying for a wallet using a malformed key should return an error indicating the request parameter was invalid, and querying for a wallet that hasn't been committed to the blockchain should return a wallet-not-found error.
