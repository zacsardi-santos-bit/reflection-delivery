I'm working on Kafka's KRaft controller and hit a gap with how we handle brokers that crash while the eligible-leader-replica (ELR) feature is on. Right now when a broker dies and re-registers under a new identity, meaning it didn't shut down cleanly, the controller just leaves it sitting in the ELR for whatever partitions it was tracking. That's bad because a crashed broker might have stale data and shouldn't stay eligible to become leader, which can wreck recovery correctness.

What I want is for the controller to detect this unclean-restart case during broker re-registration and pull that broker out of the eligible-leader set for all affected partitions. Also if the broker happened to be the last member of a partition's in-sync replica set right before it crashed, record it as the last known leader for that partition so we can track which node had the most recent data, and that last-known-leader info needs to survive even if that same broker later goes through its own unclean re-registration.

To make the lookups efficient I need a new reverse-mapping structure from broker IDs to the partitions they show up in within the ELR set, mirroring how the existing ISR tracking works, so we can quickly find which partitions to update when a given broker restarts uncleanly. When a topic gets deleted, all the ELR bookkeeping for that topic's partitions has to be cleaned up so no stale entries linger. And when the sole remaining eligible replica for a partition finally comes back online and unfences, it should get elected as the partition leader with the ELR and last-known-leader state fully cleared.

Oh, and the builder for the cluster control manager (over in `@metadata/src/main/java/org/apache/kafka/controller/ClusterControlManager.java`) needs to take a handler callback that gets invoked with the right broker ID and record list whenever an unclean shutdown is detected, so the replication control layer in `@metadata/src/main/java/org/apache/kafka/controller/ReplicationControlManager.java` can generate the partition change records in the same atomic operation.
