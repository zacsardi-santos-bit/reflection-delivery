I'm working on the GCE cloud provider for the cluster autoscaler. Right now, when the autoscaler lists the nodes in a managed instance group, it only gets back a list of instance ID strings. There's no information about whether each node is running, currently being created, or being deleted — and if a node is failing to be created (for example because we've run out of quota or there's a regional resource stockout), we have no way to surface that error information.

I'd like to change the interface so that listing nodes in a managed instance group returns rich status information alongside each node's ID. Specifically, each returned node should carry its current lifecycle state — whether it's running normally, in the process of being created (including recreated or created without retries), or being deleted. For nodes that are in the creation process and have encountered errors, structured error details should be included: an error category distinguishing resource-shortage errors (quota exhaustion or stockouts) from other errors, a normalized error code, and the raw error messages. When there are multiple errors, resource-shortage errors should take priority in the category and code, and all error messages should be combined. Errors that occur during deletion should be ignored entirely — only creation errors are relevant.

This change is needed at the layer that fetches managed instance data from the GCE API and at the manager interface that consumers call to get node information for a given instance group.
