I'm working on the GCE cloud provider for cluster autoscaler and I hit a gap in how we list nodes in a managed instance group. Right now the code that fetches managed instance data from the GCE API, plus the manager interface consumers call to get node info for a given instance group, just hands back a flat list of instance ID strings. That's not enough. I can't tell whether a given node is actually running, still being created, or getting deleted, and worse, when provisioning fails (say we've blown past a quota or there's a regional resource stockout), I've got no way to surface that error upstream. Those are exactly the signals that'd let higher-level components avoid a bad zone or dial back scale-up aggressiveness or show an actual actionable error to the user.

So I want to change the interface so listing nodes returns rich status alongside each node's ID. Each returned node should carry its current lifecycle state, whether it's running normally, in the process of being created (and that includes the recreated or created-without-retries variants), or being deleted. For nodes in the creation process that have hit errors, I want structured error details attached: an error category that distinguishes resource-shortage errors (quota exhaustion or stockouts) from other errors, a normalized error code, and the raw error messages. When there's more than one error on a single instance, the resource-shortage error should win for the category and code, and all the error messages should get combined together. Oh and errors that happen during deletion should be ignored completely, only creation errors matter here. This needs to land both at the GCE API fetch layer and at the manager interface layer so consumers get the state and error info end to end.
