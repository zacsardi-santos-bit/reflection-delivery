I'm working with a Go dataset library that has several data types with JSON serialization methods. The problem is that some of these types have two possible serialization behaviors: they can produce either a full JSON object (with all fields laid out as key-value pairs), or just a plain string containing a path reference, depending on whether an internal path is set. This inconsistency makes it really hard to write code that reliably processes the output — I can never be sure if I'll get a JSON object or a raw string back.

What I'd like is for each of these types to have a dedicated method that always serializes to a JSON object regardless of any internal path state. I'd also like the regular JSON serialization to be updated so it delegates to this object-serialization method in cases where the type has actual data (non-path-only cases), ensuring the output is always a proper JSON object that can be parsed into a structured map.

The types that need this treatment include the commit, structure, transform, and visualization configuration types in the package. For the transform type specifically, the standard JSON serialization should always produce a JSON object — including when the transform has fields like a syntax specification and associated data.
