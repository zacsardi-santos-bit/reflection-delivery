I'm hitting a really annoying inconsistency in our Go dataset library. Several of the core data types have JSON serialization that behaves two different ways depending on internal state: if the type has a stored path reference but none of its other fields are populated, marshaling gives me back a plain JSON string with just that path, but if it's got actual data it gives me a full JSON object with all the fields as key-value pairs. So downstream I can never trust what I'll get, string or object, and I keep having to write special-case handling to figure out which one came back before I can traverse it.

What I want is for each of these types to expose a dedicated method that always serializes to a proper JSON object no matter what, even when a path is set and everything else is empty. And I want the normal JSON marshaling updated so that in the non-path cases (where the type actually has data) it delegates to that object-serialization method, so the output is always a real JSON object I can parse into a generic map without errors.

The types that need this are the commit, structure, transform, and visualization config types in the package. For the transform one specifically I want the standard JSON marshaling to always produce an object, including when it's got fields like a syntax spec and associated data hanging off it. Basically whatever method you add, and whatever the regular marshal does in the data case, the result should always deserialize cleanly into a plain key-value map structure. That's the whole point, reliable structured output so callers don't have to branch on the shape.
