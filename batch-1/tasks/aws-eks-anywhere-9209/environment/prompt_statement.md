I'm adding cryptographic signature verification for bundle manifests in EKS Anywhere, because right now nothing stops a tampered or forged bundle from being used during cluster provisioning and upgrades, and a silently altered bundle could deploy unintended components with no warning. I want a new package that verifies a bundle's digital signature: take the bundle, serialize it, strip out the volatile or excluded fields (creation timestamps, mutable annotations, and certain per-provider component fields), compute a digest of what's left, then verify the signature stored in the bundle's metadata annotations against a known trusted public key. The verify function should accept the bundle plus a public key and return whether it's valid along with error details for each failure mode, so if the signature annotation is missing the error clearly says it's absent, and if the signature is present but malformed (non-base64, bad base64 decode, invalid key format, etc.) I get a descriptive error per case. I also need a validation function that uses this signature check as part of validating extended Kubernetes version support, it takes a cluster, its bundle, and a client and returns an error if the bundle's signature is missing or invalid. Then the cluster reconciler should call this validation before it proceeds with reconciliation, so if the bundle can't be found or its signature is invalid, reconciliation fails with a clear descriptive error. Oh and the constants for the signature annotation key, the trusted public key, and the set of fields to exclude from the digest computation all need to live in the shared constants package so everything references the same source of truth.
