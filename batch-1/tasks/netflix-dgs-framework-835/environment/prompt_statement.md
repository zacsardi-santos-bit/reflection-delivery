I'm on the Netflix DGS GraphQL framework and our error handling for junk query content is all over the place. When clients POST to the `/graphql` endpoint with empty bodies, whitespace-only content, malformed JSON, or valid JSON that just has a missing or empty query field, we get inconsistent behavior, sometimes unhelpful messages, sometimes straight-up exceptions. I want to make this consistent across both the WebMVC and WebFlux implementations.

Here's what I need. When a POST comes in with an empty or whitespace-only body I want an HTTP 400 Bad Request back with the message "Invalid query - No content to map to input." When the body is malformed JSON (like just `{`), also HTTP 400 but the message should start with "Invalid query -" so we give something helpful rather than blowing up. And when the body is valid JSON but the query field itself is empty or null (e.g. `{ }`), I don't want a 400, I want HTTP 200 OK with a real GraphQL error response in it, the error message being "The query is null or empty." and an error type of "BAD_REQUEST" tucked into the extensions.

Right now the problem is `BaseDgsQueryExecutor.baseExecute()` throws an `IllegalArgumentException` when the query is null or empty instead of returning that proper GraphQL error, so that needs to change to emit the error response path instead. Also the DgsContext namespace key is currently hardcoded as the string "dgs" scattered around, I want that pulled into a well-defined constant so DgsContext is accessible from the GraphQL context via a defined namespace key rather than a magic string. Please wire all this up so both web stacks behave the same.
