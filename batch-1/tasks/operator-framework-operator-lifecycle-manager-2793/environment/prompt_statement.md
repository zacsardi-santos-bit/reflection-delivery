I'm trying to tighten up the security on the pods our operator lifecycle manager spins up, and there's a real gap I hit. When we unpack operator bundles we create these temporary pods, and they've got no pod-level security context at all, so they could run as root, escalate privileges, keep all their Linux capabilities, and have no seccomp profile. That's inconsistent with the rest of the system and it makes pod security admission enforcement basically impossible.

What I want is for every bundle unpacking pod to run as a non-root user, specifically UID 1001 to match the user baked into the operator registry image, and to set RunAsNonRoot along with that. Also the seccomp profile should be the runtime-default type applied at the pod level via the pod security context. Then on the containers, both the main containers and the init containers, I want privileged set to false explicitly, allowPrivilegeEscalation set to false, and capabilities dropping ALL. This is over in the bundle unpacking logic, look at where the unpack pod gets built (something like `@pkg/controller/bundle/bundle_unpacker.go`).

Oh and separately, the catalog source registry pods already have some security fields set but they're missing an explicit privileged: false on their containers, so please add that too wherever those registry pods get constructed (around `@pkg/controller/registry/reconciler`). Basically I want consistent minimal security settings across both the unpacking pods and the catalog serving pods so we can run in strict environments without surprises.
