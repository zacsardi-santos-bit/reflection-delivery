I'm hitting a wall with the end-to-end tests in the Cairo compiler and it's the optimizer config that's biting me. The optimization config type has this list of functions that the optimizer is allowed to freely move (reorder) during compilation, and when I spin up test databases with the default settings it lets way too many functions get moved around. The result is that generated code drifts from what the snapshot tests expect, so a big chunk of the e2e suite fails on me.

What I want is an easy way to lock this down for tests. Basically a builder method on the optimization config type that I can chain onto the default config when I'm initializing test databases, same style as the other config setters (takes self by value, returns the config by value so I can keep chaining). The whole point is it restricts the moveable functions down to a minimal, stable set, and by minimal I mean exactly one function, the field subtraction primitive, so test output stays deterministic and predictable.

Once test databases get built with this minimal config the e2e tests should all produce consistent output matching their snapshots and pass. Right now there's just no convenient knob for tests to opt into a controlled optimization environment, so please add that focused builder method.
