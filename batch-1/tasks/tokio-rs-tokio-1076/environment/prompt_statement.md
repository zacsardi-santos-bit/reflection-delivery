I'm working on a Rust tracing library and the way we enter spans right now is too rigid. The only option is passing a closure to the span's entry method, which ties the span's active period to that single closure call. It's awkward or straight up impossible when I've got code that runs across multiple statements, loops through a body without wanting to nest everything, or hits borrow checker conflicts because the closure captures things it shouldn't, and it also falls apart with early `return` or the `?` operator.

What I want is a guard-based approach like mutex guards. Calling an entry method on the span should hand me back a guard value, and the span stays entered for as long as that guard is alive, then automatically exits when the guard gets dropped (end of a block or function, whatever). That'd let me use spans naturally in loops, inside async blocks, all of it.

While we're at it I want the existing closure-based method renamed so it actually says what it does, that it runs a given function within the scope of the span and returns whatever that function returns (so it still works in value-returning contexts). Both methods should fire the same subscriber notifications, enter on entry and exit on exit, and both need to treat disabled spans as no-ops.
