I've got a database that stores vectors as binary-encoded blobs, and I need to fill in some gaps in our vector SQL functions. Right now we have element-wise multiplication plus a few conversion helpers, but there's no way to subtract two vectors, no way to collapse a single vector's elements into a scalar, and no aggregate that sums a whole column of vectors row-by-row. That's a real pain for ML and similarity-search stuff since users end up pulling raw data out and post-processing it outside the DB instead of just doing the math in SQL.

So I want three new SQL functions. One's a scalar function that takes two vector args and returns a new vector with the element-wise difference. Another scalar one sums all elements inside a single vector and returns a scalar float. And the third is an aggregate function that, applied to a column of vectors, returns one vector that's the element-wise sum across all rows, and it should return null if any row in the group has a null vector.

Also, the internal vector conversion utilities in the function library are currently only visible inside that module, so I can't use them elsewhere. I need those made accessible from other crates in the workspace so I can write integration tests over in the query engine that build binary-encoded test vectors and check the aggregate's element-wise sum is right. The test I've got in mind spins up an in-memory table of randomly generated three-dimensional vectors and runs the aggregation query against it. Oh and the linear algebra library that the function module already uses needs to be declared as a shared workspace dependency so the query crate's test code can pull it in without hitting version conflicts.
