I'm hacking on the Grafbase CLI and hit an annoying thing with the extension init command. When I scaffold a new extension project, whether it's the resolver type or the authentication type, the generated config file (the Cargo manifest template the CLI writes out) pins the SDK library to an old version string. So every fresh extension project starts life already behind the current SDK release, which means subtle incompatibilities or me having to hand-edit the generated file right after creation, kind of defeats the point of scaffolding.

The version reference shows up in two spots in that generated manifest, once under the normal dependencies and once under dev-dependencies, and both need to point at the current SDK release. The embedded template lives in the CLI crate where the extension init logic bakes in the SDK version, so both the resolver path and the auth path should emit the up-to-date version in both dependency sections.

Oh and there's a compilation issue tangled up with this. The SDK library itself, plus the packages that depend on it, don't build cleanly right now, which blocks any extension work. I want the version bump and the compile fix landed together so the generated templates and the actual build system stay consistent. After the changes the whole workspace, SDK and everything downstream, should compile without errors.
