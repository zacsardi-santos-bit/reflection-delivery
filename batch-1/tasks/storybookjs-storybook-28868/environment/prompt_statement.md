I'm cleaning up the Storybook vitest addon and I want to pull its story file transformer out of the addon and into the shared core CSF tooling package so it lives in one place and can reuse the richer CSF parsing that's already there. Right now the addon transformer leans on third-party libs for code manipulation and TypeScript AST parsing that are addon-specific and just add weight, so the plan is to move all that logic into core.

The new shared transformer needs to detect whether the meta has a title, and when it's missing it should call the automatic title utility to compute one. It should handle both inline default exports and const-declared default exports, converting the inline ones into const declarations. For each named story export it generates test wrapper code that respects the tag filter and skips any exports listed as excluded (no test statements for those). It also needs to emit a source map so a failing test points back to the correct line in the original story file. Oh and the generated imports (from the test framework, the preview API, and the test utilities package) should land at the top of the file.

While I'm in here, two related fixes. First, when a story test fails the debug URL in the error message should always include the interactions panel shortcut link, not just when the story has interactive behavior configured, since even non-interactive stories can fail in ways you'd debug through that panel. Second, the helper that runs a story test currently takes raw module info and looks up plus composes the story internally, which is indirect. I want it to accept an already-composed story object directly plus a tag filter instead, moving the composition step to the call site. Keep the skip-tag check inside that function though.

Last thing, the CSF file formatting utility in the core package should gain an option to convert inline default exports to const declarations when formatting, and please export the corresponding options type so callers get proper type checking.
