I'm working on the Storybook vitest addon and I need to refactor the story file transformation logic. Right now, the addon has its own internal transformer that uses third-party libraries for code manipulation and TypeScript parsing. I want to move this transformation into the shared core CSF tooling package so it can be maintained centrally and reused across the codebase.

The new shared transformer should handle story files by detecting whether there's a title in the meta, calling the automatic title utility when it's missing, converting inline default exports to const declarations, and generating the right test wrapper code for each named story export. It should also produce a source map so that when a test fails, the error points back to the original story location. Story exports listed as excluded should not get test statements. The generated code should import from the test framework, the preview API, and the test utilities package — and the imports should be placed at the top of the file.

I also need to fix two related issues. First, when a story test fails, the debug URL in the error message should always include the interactions panel link, not just when the story has interactive behavior configured. Second, the function that runs a story test should be simplified: instead of receiving module information and looking up the story internally, it should accept an already-composed story object directly, along with a tag filter. The logic for checking whether to skip a story based on skip tags should stay in this function, but the story composition step should happen at the call site.

Finally, the CSF file formatting utility in the core package should support an option to convert inline default exports to const declarations when formatting, and the corresponding options type should be exported so callers can use it with proper type checking.
