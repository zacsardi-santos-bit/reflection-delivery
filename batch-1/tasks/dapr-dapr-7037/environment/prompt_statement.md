I'm cleaning up a bunch of legacy backwards-compat stuff in the Dapr security system that stuck around from the transition to the SPIFFE-based mTLS model. These were supposed to be gone an earlier release cycle ago, so let's rip them out.

First thing, the sidecar injector currently pre-signs certs for the pods it injects and stuffs the cert chain plus private key into the container as env vars. Old runtime versions needed that, but not anymore, so the injector should stop entirely, no cert material pre-fetched or injected into the sidecar environment at all.

Second, the Kubernetes identity validator has this special path that lets the injector request certs for arbitrary identities (different namespace, different name than its own pod would be authorized for). That override was so it could grab identities on behalf of pods, but since it's not pre-fetching anymore, kill the privilege completely, the injector should go through the same identity validation as every other component and any attempt to request an identity outside its own should error out instead of succeeding.

Third, the old colon-separated identity format (request ID being namespace and service account joined by a colon) is still accepted in some paths and I want it outright rejected now with a permission denied error. While you're in the validator, also enforce that app IDs are at most 64 chars, reject anything longer with a descriptive error mentioning the length limit, and requests with exactly 64-char app IDs should still succeed.

Also, signed workload certs and issuer certs currently carry DNS Subject Alternative Names (workload gets a DNS SAN from app ID plus namespace, issuer gets a cluster-local DNS name) that were there for older clients matching server identity by DNS name instead of SPIFFE URI. Everything modern does URI-based matching now, so drop the DNS SANs from all signed certs.

Oh and the validator interface needs simplifying too, there's a boolean return that signaled "duration override" and since the whole override mechanism is going away, remove that bool from both the validator and the CA signing interfaces and update everything that threaded it through the stack to a plain two-value return instead. There are TODO comments scattered around pointing at these removals if you want breadcrumbs. Net effect is less attack surface on the injector, consistent identity validation across all callers, and a chunk of version-transition debt gone.
