I'm digging into the type inference layer and hit a real gap. Right now when a function or method has no explicit return type annotation, we just fall back to an indeterminate return type instead of actually looking at what the body returns. That's biting me because the floating promise lint rule can't catch a super common pattern, someone writes an object method that returns an async value (say it calls out to an API that hands back a promise) but they never declared the return type, so the value gets inferred, and the linter misses it entirely. Unhandled async return values slip through silently, which is exactly what that rule is supposed to prevent.

What I want is for the inference to derive the return type from the function body whenever it can be statically analyzed. So a function that never returns anything should come back as an empty/no-value return type, a function with a single return should get that return's type, and a function with multiple return paths should get a union of all the possible return types with the duplicates deduplicated (don't want the same type showing up twice in the union). This isn't just about the promise rule, it's the whole type system being able to reason about return values, but the concrete payoff I care about is that once inference covers bodies, the floating promise rule should flag calls to unannotated object methods whose inferred return type is async, exactly the same way it already does for methods with explicit annotations.

The motivation here is that tons of real TypeScript leans on inference rather than redundant annotations, so if these tools only work on explicitly typed code they're way weaker than they should be. Getting inference to cover function bodies makes the floating promise rule (and other type-dependent checks) actually useful on idiomatic code. Oh and make sure the annotated path still behaves the same, this should be additive.
