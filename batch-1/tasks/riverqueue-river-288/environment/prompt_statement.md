I'm working with River's job queue system in Go and I need to dynamically manage recurring scheduled jobs after the client has already started. Right now all periodic jobs have to be declared upfront when the client is set up, and once it's running there's no way to add or remove them without restarting the whole process. That's a real pain for apps that need to enable or disable background work at runtime, like in response to config changes, feature flags, or tenant provisioning, and being forced to restart just to tweak a schedule is operationally expensive.

What I want is for the client to expose a method that returns a bundle object offering add, remove, and clear operations, and this should also work for the initial set of periodic jobs configured at startup. Adding should let me register one or more new recurring jobs that immediately join the scheduling loop, and if a job is configured to run immediately upon addition it should get enqueued right away. Each add returns a handle (reference) I can use to remove that job individually later, and I also want to remove multiple jobs at once by passing a list of handles, plus clear everything in one call.

One important detail, handles must never be reused, even after a full clear of all jobs, so old references can't accidentally point at newly added jobs. The internal scheduling service should track jobs in a data structure that allows efficient lookup and removal by handle, and the run loop needs to wake up immediately when new jobs are added so they get scheduled or inserted without waiting for the next tick. Oh and all of these operations, add, remove, remove-many, clear, need to be safe to call concurrently from multiple goroutines at the same time.
