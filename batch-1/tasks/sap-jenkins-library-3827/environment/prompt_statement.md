I'm hacking on our Helm deploy helper that runs inside the CI/CD pipeline and I've hit a couple of annoying gaps around how it deals with chart sources and repo operations.

Right now the upgrade and install paths bail out with an error if there's no local chart path configured, which is way too strict. Plenty of our deploys just point at a remote chart registry and use the repo-registered name as the chart reference, no local checkout involved at all. So I want the logic to branch: if a local chart path is set, use it directly and skip the repository registration step entirely. If there's no chart path, then go register the configured remote repository automatically and use the repository name as the chart reference instead. That should cover both the local-checkout workflow and the remote-repo-only workflow without breaking the folks already passing a chart path.

Second thing, uninstall is doing something dumb. It tries to register a chart repository before it uninstalls, and that blows up when repo credentials aren't set up, but uninstall doesn't touch the chart source at all so there's no reason for it. It should just run the uninstall directly, no repo registration. Oh and while you're in there, uninstall should validate upfront that a namespace was actually provided and return a clear error saying the namespace parameter is missing when it hasn't been, instead of letting it fall through to some confusing runtime error later.

Can you fix up the upgrade, install, and uninstall logic in the Helm execution component to handle all this? The whole point is that people deploying from remote chart registries are currently blocked by the mandatory local chart path, and making remote-repo deploys a first-class option makes the tool a lot more flexible.
