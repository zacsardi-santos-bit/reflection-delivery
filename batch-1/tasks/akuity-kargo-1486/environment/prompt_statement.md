I'm cleaning up how Kargo initializes Projects and the current flow bugs me because the reconciler and the webhook each do namespace setup in one undifferentiated block, so there's no way to tell a transient failure (retry might work) apart from a permanent one like a real namespace conflict. Right now everything collapses into either ready or the same generic error state, which makes the Project status kind of useless for debugging. I want to split initialization into two distinct steps, one that handles namespace setup and one that sets up secret management permissions, and I need both the management controller reconciler and the creation webhook to participate in this two-phase setup.

The reconciler's main sync function should orchestrate the two steps and only flip the Project to the Ready phase once both succeed. Important detail, the namespace step should NOT mark the Project ready on its own, that final phase transition belongs in the orchestrating function. The namespace step should only set the phase to permanently failed when there's an unrecoverable conflict, and for any other error it should leave the Project sitting in the initializing state so it gets retried.

The second piece is permissions. When a Project is created I want the system to automatically grant the Kargo API server permission to manage secrets within that Project's namespace, via a role binding created in the namespace. This should happen synchronously in the webhook at creation time and also in the reconciler. Create the binding idempotently, so if it already exists that's totally fine and counts as success. The whole point is dropping the need for cluster-wide secret access and instead giving per-namespace access at Project creation, least privilege basically.

Oh and both the controller reconciler and the webhook need to know the Kargo system namespace so they know where the service account lives when binding it. Pull that config from environment variables.
