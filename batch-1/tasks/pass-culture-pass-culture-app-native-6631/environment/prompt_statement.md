I'm cleaning up how we control monitoring behavior across our error classes and it's kind of a mess right now. We've got a boolean flag, something like "should log as info," scattered across different error constructors, and the naming is inconsistent between error types plus it only really supports two states. It can't cleanly express the difference between ignore this completely versus log it as info versus log it as a real error, so people keep tracking slightly different boolean property names and it's easy to misuse.

What I want is to replace all those boolean flags with one named enumeration that has at least three distinct values, one for regular error capture, one for info-level capture, and one for suppressing the event entirely. Every error class that currently takes the boolean should switch over to accept this new log-type instead. Also the helper that fetches email update status currently takes the boolean directly too, so update that signature to accept the new type as well.

Oh and I need a new reusable hook that reads the existing remote feature flag controlling logging verbosity and translates it into the right value from this enum, so callers don't have to duplicate that translation logic themselves. Any component or function should be able to grab the correct log-type without redoing the mapping. The whole point is a consistent, expressive API where the intent at each call site is explicit and runtime control of monitoring verbosity through remote config lives in one central place.
