I'm adding a way to list repository autolinks in the GitHub CLI since right now there's no command for it and you have to dig through the repo settings page in a browser just to see them. Autolinks are those reference patterns configured on a repo that expand short identifiers like ticket numbers into full external URLs, and teams wiring GitHub up to external issue trackers or docs have no quick way to audit them from the terminal.

I want a new list subcommand that fetches and shows all the autolinks for a given repo. In an interactive terminal it should print a formatted table with a header telling me how many autolinks were found, and then each row shows the autolink's ID, its key prefix, the URL template, and whether it's alphanumeric. When the output's being piped or redirected it should drop the decorative header and just emit tab-separated values instead. There should also be a JSON flag that exports the data in structured form with field selection support across the id, the isAlphanumeric flag, the key prefix, and the URL template, and if someone asks for a field that isn't one of those it should error out and list the valid ones. Oh and a web flag that just opens the repo's autolinks settings page in the browser instead of listing anything.

Couple of edge cases: when no autolinks exist the command should tell me nothing was found rather than showing an empty table. And when the API call fails because of missing permissions, the error message needs to mention that admin rights to the repository may be required, since that's the usual cause. The code lives under the autolink command area (something like `@pkg/cmd/repo/autolink/`) alongside the other repo subcommands.
