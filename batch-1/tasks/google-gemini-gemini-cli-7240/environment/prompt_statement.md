I'm building a CLI that talks to external tool servers over OAuth, and right now the tokens we get back after auth only live in memory, so every restart forces users through the whole flow again for each server even when their tokens are still perfectly valid. Super annoying when you're juggling multiple servers. I want a file-based token storage that encrypts credentials before writing them into the user's home config directory. The encryption needs to be non-trivial and keyed off the machine plus the current user identity, so someone can't just copy the file to another box and read it.

It's gotta handle the whole lifecycle: look up a credential by server name and return nothing if that token's already expired, save or update a credential while leaving the other servers' entries untouched, delete a single server's entry (and when that was the last one, remove the file entirely), list all the stored server names, and wipe everything at once.

Error handling matters here too. Reading from (or deleting in) a file that doesn't exist should throw a clear error saying the token file doesn't exist, and if the file's corrupted or won't decrypt it should throw one saying the token file is corrupted, no silent failures. But clearing all tokens when there's no file should just quietly succeed instead of blowing up.

Oh and one more thing, the base token storage class currently ships with a default service name, which means subclasses can accidentally share storage without realizing it. I want the base constructor to require the service name explicitly, drop the default entirely.
