I'm filling gaps in our SurrealDB integration for the Go framework and it's basically read-only right now, which is killing me. The client can query existing data but there's no way to insert new records into a named table or delete a record by its identifier, and I can't manage schema at the admin level either. So I need Insert (given a table name plus the data, returns the inserted records back), Delete (by table name and record identifier, returns the deleted record if it existed or a clean empty result if it wasn't there), and CreateNamespace / DropNamespace / CreateDatabase / DropDatabase so I can spin up and tear down namespaces and databases programmatically through the client. Oh and every one of these has to fail gracefully with a clear "not connected" error when the connection hasn't been established yet, don't let them panic or do something weird.

The other big thing: our migration system already treats MongoDB, Cassandra, and ArangoDB as first-class citizens but SurrealDB isn't wired in at all, so devs can't run versioned schema changes against it. I want SurrealDB to be a proper participant in that migration lifecycle. That means setting up the migration tracking table (checking/creating it), querying the last applied migration version, committing a completed migration while recording the version, the method, the start time, and the duration, and beginning a transaction with the appropriate log output. Basically the same shape the other databases follow so it feels consistent. Without writes, deletes, schema management, and structured migrations, SurrealDB is stuck on read workloads only and can't back a real app, so I want it usable end to end.
