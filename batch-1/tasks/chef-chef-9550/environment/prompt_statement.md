I'm on the macOS side of the build tools resource and hit two things I want fixed. First, the method that checks whether the Xcode Command Line Tools are installed is calling out to an external system binary, and that binary just isn't there in our test environments (Linux CI runners, containers, that kind of thing), so it blows up, and honestly it gives wrong answers on some real macOS setups too. I'd rather have it read from the OS's own installation history file to figure out if the tools are present. That makes the check self-contained and portable instead of depending on a tool that may not exist.

Second thing, there's no way right now to ask the software update service which Command Line Tools package is actually available. I want a new method that runs the update listing command and parses its output to return the package label. Catch is the output format differs between older macOS (pre-10.15) and Catalina-and-later (10.15+), so it's gotta handle both shapes and pull the right label string either way. And when there's no Command Line Tools package in the listing at all, just return nothing. This is the piece we need so we can tell which package to install or upgrade later on, basically laying the groundwork for automated upgrade support.
