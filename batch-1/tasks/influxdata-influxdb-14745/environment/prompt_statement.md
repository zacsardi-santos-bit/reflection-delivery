I'm working on the checks feature in InfluxDB and there's a gap I keep hitting when debugging monitoring checks. When someone configures a check they give it a source query plus a schedule, and those two things together decide how data gets evaluated, but right now there's no way to pull back the actual complete query the system runs when the check fires. The config lives separately from the effective scheduled query and nothing exposes what that final executable script looks like, including how the time window and scheduling params get folded in. That makes it really hard to verify a check will behave the way you expect, or to figure out why one fired unexpectedly or failed to alert.

So I want to add a handler on the check service that, given a check ID, looks up that check and returns the generated query. The generated query should adapt the check's source query so the time range matches the check's run interval (the scheduling interval), and it should append the task scheduling options at the end, since that's what actually happens at runtime. The response back should just be a JSON object containing that generated query as a string, nothing fancier. Basically I want users to be able to retrieve the effective, ready-to-execute query for any check by its ID so they can see exactly what's going to run.
