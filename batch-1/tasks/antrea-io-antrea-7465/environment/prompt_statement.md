I'm cleaning up the IP pool controllers in Antrea and the validation logic is a mess of duplication. Right now the range validation stuff (parsing CIDRs, parsing start/end ranges, checking for overlaps, validating ranges against the configured subnet info) is copy-pasted between the external IP pool controller and the IPAM controller, and the two copies emit different error messages for the exact same kind of failure. So operators get different wording depending on which pool type they're touching, which is confusing when they're trying to figure out what they misconfigured.

I want all that shared validation pulled into one common reusable package that both controllers call into, with consistent user-friendly messages. When a range overlaps with a range in another pool the error should name both conflicting ranges and identify the full resource type and name of the other pool (not just say "pool" or "overlap" without saying which ranges actually conflict). When a range falls outside the configured subnet the message should be identical no matter which controller catches it, and it should identify both the range and the subnet. Prefix length validation errors should follow a consistent lowercase style too.

Oh and there's a real correctness bug mixed in here: the current code rejects deletion of existing IP ranges in a pool but still lets them be updated (changed), which shouldn't be allowed for the same reasons deletion isn't. Right now the error message only talks about deletion so it's misleading. I want the validation logic and that message extended to cover updates as well as deletions. Centralizing this also means we won't drift back into inconsistency as the two controllers keep evolving on their own.
