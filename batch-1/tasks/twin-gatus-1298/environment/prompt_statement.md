I'm trying to get Gatus to monitor stuff that lives behind a firewall, internal APIs and databases that are only reachable over SSH, and right now there's just no way to route a health check through an SSH tunnel so those services are basically invisible to me. What I want is to define one or more named SSH tunnels in the config, each with a host, a port, a username, and auth that's either a password or a private key, and then let any endpoint point at one of those tunnels by name so its health-check traffic gets routed through it. Endpoints inside suites need to be able to reference tunnels too, not just top-level ones.

The part I really care about is validation at startup. If an endpoint references a tunnel name that isn't actually defined in the tunneling config, I want the config loader to fail right away with a clear error that says which endpoint has the bad reference and which tunnel name is missing, and for a suite endpoint the message should also name the parent suite so I can find it fast. Oh and if there's no tunneling config at all, endpoints that don't reference any tunnel should just keep working like they always have, no errors.

Also connections should be reused across requests, spinning up a fresh SSH connection on every single health check would be wasteful. Closing the tunneling config should tear down all the active connections and release resources cleanly, and it's gotta be safe to call close even when nothing ever connected, so no panics or errors on an empty setup.
