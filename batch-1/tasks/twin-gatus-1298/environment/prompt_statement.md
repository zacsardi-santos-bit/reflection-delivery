I'd like to add SSH tunneling support to Gatus so that health checks can be routed through SSH tunnels to reach services that aren't directly accessible from the internet. The idea is that you'd define named SSH tunnels in the config (with host, port, username, and either a password or private key for auth), and then individual endpoints (including those inside suites) could reference one of those tunnels by name to route their traffic through it.

One important part of this is config validation: if an endpoint references a tunnel name that doesn't exist in the tunneling configuration, startup should fail with a clear error message that identifies the offending endpoint and the missing tunnel name. For suite endpoints, the error message should also identify the parent suite. If no tunneling configuration is defined at all, endpoints without tunnel references should continue working as before.

Tunnel connections should be reused across requests — creating a new connection on every health check would be wasteful. Closing the tunneling configuration should close all active connections and release resources cleanly, and closing should be safe to call even if no connections were ever established.
