I want to add a CSV output serializer to Telegraf. Right now there's no built-in way to spit metrics out in comma-separated format, so anyone feeding into log aggregators, tabular storage backends, or data pipelines that expect CSV has to post-process Telegraf's output themselves, which is annoying. A native serializer would let us write proper tabular output directly from the output plugins.

Here's what I'm after: each metric becomes a row of delimited values in the order timestamp, measurement name, then tag values (in tag order), then field values sorted alphabetically by field name so the output stays consistent run to run. I want a few knobs. Timestamp format should default to Unix epoch seconds but also handle milliseconds, microseconds, nanoseconds, or any formatted date/time layout string. The column delimiter defaults to comma but should accept any single character like a semicolon. There should be an optional header row that names each column, written once at the very start and then suppressed for every row after (also in batch mode when I serialize a bunch of metrics at once, the header shows up only once at the beginning). And an optional column type prefix so when the header's on, tag column names get prefixed to mark them as tags and field column names get prefixed to mark them as fields, so it's obvious which is which.

Input validation matters to me too. If someone passes a multi-character delimiter it should be rejected right at config time with a clear error, same deal for an unrecognized timestamp format string, reject early with a descriptive message instead of silently producing garbage. Oh and if the underlying write blows up because of an invalid delimiter character (think a newline), the error should make it clear the write itself failed, not something vague. It's gotta work for both single-metric serialization and batch serialization of multiple metrics.
