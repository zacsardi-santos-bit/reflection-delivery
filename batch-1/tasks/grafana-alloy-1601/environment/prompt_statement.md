I'm building a durable, disk-backed queue for the Prometheus remote write component in Grafana Alloy, over in the network/queue code under `@internal/component/prometheus/remotewrite`. Right now there's nothing that persists in-flight metrics to disk, so if the process crashes or restarts mid write-burst we silently drop buffered data, which is bad for reliable remote write. I want to fix that.

The gist: when something's pushed to the queue it gets written to disk right away so it survives a restart. Each item carries a raw byte payload plus an optional map of string key-value metadata. Items should be delivered to a consumer callback in FIFO order. The important restart bit: when the process comes back up and a new queue is created on the same directory, any previously committed but unread items need to get replayed to the consumer in their original stored order before any new items are processed.

Failure handling matters too. If a file is corrupted or has been deleted by the time the consumer tries to read it, surface that error to the consumer for that specific item only, and keep delivering all the other items normally, don't let one bad file wedge the whole thing. Also any unrelated files sitting in the queue directory that don't belong to the queue should just be ignored completely.

Oh and I need a serializable record type that bundles the data payload together with the metadata map for on-disk storage, it should support binary serialization (marshal/unmarshal) so it can be written to and read from files efficiently. And when the queue is stopped it needs to fully clean up its background resources, no goroutine leaks. Can you implement the queue plus the supporting record type?
