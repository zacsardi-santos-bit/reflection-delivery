I'm hitting a gap in Daft's SQL interface. When I read JSON or CSV files through SQL table functions, I can't specify the schema inline, so I'm stuck with automatic type inference. The Python API already lets me pass a schema dict when reading these formats, but the SQL side doesn't expose that at all, which means I either accept whatever types get inferred or bolt on extra casting after the read. I'd like to fix that so the SQL read functions match what the Python read functions do with an explicit schema.

Concretely I want the SQL function that reads JSON files to take an optional schema argument that lets me define the data type per column, and the SQL function that reads CSV to accept the same optional schema argument. The schema should be expressible right in the SQL query as a mapping of column names to type descriptors, so I can name each column and give it a type inline. The key correctness bar is that a query using this schema argument should produce the same result as calling the equivalent Python read function with an explicit schema dictionary. Same column names, same types, no surprises.

This is really about making the SQL interface consistent with the Python API and giving me full control over column types at read time instead of relying on inference or post-read cleanup.
