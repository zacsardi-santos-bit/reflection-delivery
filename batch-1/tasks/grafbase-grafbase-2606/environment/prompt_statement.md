I'm working on a federated GraphQL gateway that supports schema extensions with typed directive arguments. Right now, when an extension directive is declared with typed arguments — like requiring a specific input object, a scalar value, or an enum — there's no validation of those argument values at schema construction time. Mistakes like providing a string where an integer is expected, omitting a required argument, or using an unknown type in the extension go undetected, which makes debugging really painful.

I'd like the engine to validate directive argument values against their declared types when building the schema. That means catching things like unknown argument names, missing required arguments, incorrect scalar types, malformed input objects (wrong shape, unknown fields, missing required fields), bad enum values, and incompatible list wrapping. Each error should report both the location (whether it's a field-level or schema-level directive and which extension/directive is involved) and the specific path within the argument value where the problem occurs.

Beyond validation, I also need standard coercions to work: single values should be promoted to lists when a list type is expected, and whole-number floats should be accepted where integer scalars are expected. Default values on directive arguments and input object fields should be applied automatically when values are omitted. Custom scalars should accept any value without validation. There should also be a clear distinction between explicitly providing a null value for a nullable argument versus omitting that argument entirely — the former should appear in the output as null, while the latter should be absent.
