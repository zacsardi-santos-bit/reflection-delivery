I'm deep in the Volto CMS block editor and the "add block" button logic is copy-pasted into basically every block component, which is driving me nuts. Each editor independently tracks whether the block chooser panel is open, decides whether to even show the button based on whether the block has any content yet, and wires up its own click-outside handling to close the panel. It's messy, it drifts, and blocks end up behaving inconsistently.

What I want is one reusable component I can drop in that owns all of this. It should take the block's data (its value) and the block's ID, and figure out on its own whether to render the button. If the block already has content, render nothing. Also if the block type isn't recognized (unknown type), be conservative and render nothing too, don't guess. When the block is genuinely empty, show a button that opens the block chooser on click, and handle the open/closed state plus closing on an outside click internally so the individual editors don't have to.

Oh and I want an escape hatch: let me pass in a custom button component in case the default button style doesn't fit a particular block, otherwise fall back to the default look. The whole point is pulling this show/hide logic out of the scattered block editors into a single dedicated component so each editor gets simpler and every block treats the chooser button the same way.
