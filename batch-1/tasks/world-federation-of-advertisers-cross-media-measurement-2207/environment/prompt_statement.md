I'm adding support for wrapping vid sampling intervals in the cross-media measurement system. Right now the sampling code enforces that a sampling interval's start plus its width can't go over 1.0, which is fine for the older sketch-based (LiquidLegions) protocol, but the newer shuffle-based distributed protocol should be allowed to use intervals that wrap around, so something like start=0.8 width=0.5 logically covers [0.0, 0.3] and [0.8, 1.0]. Today the system rejects those outright and it's blocking valid configs for that protocol.

Couple of things I need. The validation logic in the sampling function should permit wrapping as long as the width itself is still at most 1.0 (start plus width over 1.0 is fine, width over 1.0 is not). The metric spec building function should take a new flag controlling whether wrapping is allowed, defaulting to off so existing callers don't change behavior. And the measurements service should allow wrapping intervals when the shuffle-based protocol is selected but reject them with a clear validation error otherwise.

Also there's a utility that computes the combined coverage width of two sampling intervals, it doesn't handle wrapping correctly across the overlap cases so it needs fixing, and please make it public so it can be used and tested on its own. Oh and the measurement consumer simulator currently hardcodes one fixed sampling interval for every measurement type, I want it to accept a configurable interval as a parameter (default start=0.2, width=0.5) so we can drive wrapping scenarios end to end. This matters because the shuffle-based protocol's math works with wrapping intervals and it's a prerequisite for certain multi-party setups.
