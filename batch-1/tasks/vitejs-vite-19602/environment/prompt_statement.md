I'm working on improving how Vite plugin hooks handle filtering. Right now, every plugin's handler for resolving, loading, or transforming modules gets called for every single file Vite processes, and it's up to each plugin author to manually check whether the file is relevant at the start of their handler. This means a lot of repetitive boilerplate in every plugin that only targets specific file types or code patterns.

I'd like to add a built-in filter option to these plugin hooks so that developers can declare which files or code patterns a hook applies to when they define the plugin, and Vite will automatically skip calling the handler for anything that doesn't match. This should work both when running the dev server and when doing a production build.

For filtering by file path, the filter should support glob strings, regular expressions, or arrays of either. It should also support explicit include and exclude lists, where exclude takes priority over include. Glob string patterns should work against paths relative to the project root, should handle absolute paths correctly, and should not match virtual module IDs (the ones prefixed with a null byte). For the transformation hook in particular, there should also be an option to filter by code content — so a handler only runs if the source code contains a certain substring or matches a regex.

There's also a nuance in how these two filters interact for transformation: if the file ID filter gives a definitive yes or no (the file is explicitly included or explicitly excluded), that should be the final answer — there's no need to check the code content filter. Only when the ID filter is undecided (the file wasn't covered by either an include or exclude pattern) should the code content filter be consulted.
