First, there's no way to list API Gateway client certificates as a standalone resource type. I want to write a policy that returns all client certificates so I can report on them or run actions against them, with full access to the certificate fields including the expiration info. Right now I can enumerate stages but client certs just aren't a first-class resource, so please add them as their own queryable resource type in the c7n AWS provider (the API Gateway support lives under `@c7n/resources/apigw.py`).

Today I can list stages but I can't inspect or filter on the client certificate attached to a stage. So I'm after a client certificate filter on the stage resource that looks up the cert and lets me match on its fields, like finding every stage whose certificate has expired. The why here is these client certs are for mutual TLS to backend integrations, and when they expire those integrations can just fail, so we need to proactively catch expiring or expired certs and act before they cause an outage. btw make sure the standalone client certificate resource and the stage-level filter share the same underlying certificate data shape so the fields line up.
