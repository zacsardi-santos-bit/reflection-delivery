I'm hitting a bug in our cluster management tooling, the part that installs provider components into a Kubernetes cluster. When someone picks a target namespace, we're supposed to rewrite all the namespace references in the provider manifests so everything lands in the right place. That works fine for ordinary objects and their metadata namespaces, but it totally skips admission webhook configurations and CRDs that carry embedded namespace references in their webhook client configs. So providers that use webhooks get installed pointing at the old hardcoded namespace and the webhooks just break.

I need the namespace-fixing logic to also handle these webhook-related objects. For admission webhook configuration objects, update the namespace inside the webhook service client config to the target namespace. Same idea for custom resource definitions that do webhook-based conversion, fix the namespace inside their conversion webhook service client config. Oh and there's also cert-manager certificate injection annotations on these objects where the value looks like `namespace/cert-name`, so rewrite just the namespace portion of that to the target namespace.

Also the function doing this work currently swallows problems and returns like nothing happened, I want it to actually propagate an error rather than silently succeeding when something goes wrong. This matters because webhook-using providers are super common now and right now they basically can't be installed into a custom namespace at all.
