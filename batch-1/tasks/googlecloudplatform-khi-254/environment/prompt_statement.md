I'm working on a log-analysis tool that needs to efficiently find known identifiers — like container IDs — embedded in log lines. The identifiers tend to appear right after certain delimiter characters such as quotes or spaces, and there can be thousands of them registered at once. I need a pattern-matching utility that lets me register a set of strings beforehand and then scan arbitrary text to find which registered patterns appear (and where), using longest-prefix matching so that a longer match always wins over a shorter one. After a match is found, scanning should skip past it entirely to avoid reporting overlapping hits. The utility should offer two implementations sharing a common interface: a simpler one for small pattern sets and a more efficient prefix-tree-based one for large sets. Both need to support adding, retrieving, and removing patterns, with clear errors when a pattern doesn't exist or has already been added.

I also need a generic, type-safe concurrent dictionary to use as an internal building block. Right now I'm stuck using untyped maps with manual type assertions, which is error-prone. I'd like a dictionary that preserves the value type through generics, supports the usual set/get/delete operations, provides a "return default if missing" lookup, and an atomic "get existing value or initialize with a function" operation — where the initializer is only called when the key is truly absent. Everything must be safe for concurrent use by multiple goroutines simultaneously.
