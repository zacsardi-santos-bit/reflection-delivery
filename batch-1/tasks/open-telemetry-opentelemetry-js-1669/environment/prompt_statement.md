I'm working with the OpenTelemetry JS AWS resource detector package and it's got detectors for EC2, Elastic Beanstalk, and ECS but nothing for Amazon EKS (Elastic Kubernetes Service), so I want to add one that auto-detects when my app is running inside an EKS cluster and populates the resource attributes with the k8s cluster name and the container ID. EKS is a super common managed Kubernetes service so having this means telemetry gets properly attributed with cluster and container info without me configuring anything by hand.

Here's how detection should work: check whether we're on EKS by looking for the presence of the Kubernetes token file and querying the AWS auth configmap. It should make HTTPS requests to `kubernetes.default.svc` with the right Authorization header, and the auth configmap lives at `/api/v1/namespaces/kube-system/configmaps/aws-auth`. The cluster name comes from the Amazon CloudWatch configmap at `/api/v1/namespaces/amazon-cloudwatch/configmaps/cluster-info`, pulled out of the JSON response's `data["cluster.name"]` field. The container ID gets extracted from the cgroup file at `/proc/self/cgroup` by reading the last 64 characters from any line longer than 64 chars.

It needs to handle partial info gracefully. If I've got the cluster name but can't get the container ID, return a Resource with just the cluster name, and vice versa if I've only got the container ID. If neither is available, return an empty Resource. Same empty Resource when we're not on EKS at all (the auth configmap comes back empty) or when the Kubernetes token file doesn't exist, don't crash. Oh and requests should carry a timeout so nothing hangs, and it should throw proper errors: `EKS metadata api request timed out.` for a request timeout, and `Failed to load page, status code: {code}` for HTTP errors where {code} is the actual status. Export both the detector class and a pre-instantiated singleton.
