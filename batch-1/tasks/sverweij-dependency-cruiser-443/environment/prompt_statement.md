I'm hitting a wall with reachability rules in dependency-cruiser and could use your help. I want to write a single "reachable" rule where the "from" pattern uses a regex capture group to grab a folder name, then I reference that captured value back in the "to" pattern so the rule scopes itself to just that folder's subtree. The idea is one rule that, for each module's index file, checks whether all the modules living in that same folder are reachable from it. But right now capture groups from the "from" pattern don't get expanded into the "to" pattern when reachability gets computed, so the rule either matches way too broadly or matches nothing at all, instead of being evaluated independently per matching "from" module with the right captured value substituted in.

There's a related gap too. Each reachability annotation that lands on a module only records which rule determined it, not which specific "from" module triggered it. So if multiple source modules can match the "from" side of a rule, I can't tell which one actually caused a given module to get marked reachable or unreachable. That "matched from" info isn't just nice for traceability, it's actually needed for the capture group expansion to work right during validation.

So what I'm after: record the source path of the specific origin module that produced each reachability annotation, and use that recorded path to correctly expand capture groups in the rule's "to" pattern, both when computing reachability and later when the validator checks whether a rule is violated (it should use the recorded origin path to expand the "to" groups so path-based conditions evaluate correctly). That way I can write "every module in a folder should be reachable from that folder's index file" as one rule covering all folders, instead of a separate rule per folder or living with false positives and negatives from overly broad matching.
