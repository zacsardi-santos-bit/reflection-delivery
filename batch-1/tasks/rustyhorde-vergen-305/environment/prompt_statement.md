I'm hitting a frustrating gap in the build-metadata pretty-printer. Any custom or non-standard entries I add just vanish when I try to display them. If a key doesn't match the standard naming convention the internal split logic returns nothing instead of passing the entry through, so it's silently dropped. Same deal with key paths that have too few segments, they get discarded rather than landing in some sensible bucket. The upshot is I can't emit custom build metadata alongside the usual version info and actually see it, which makes the library useless for the mixed standard-plus-custom setups I care about.

What I want is for the splitting logic to preserve a key that doesn't fit the standard pattern as a single unsplit entry rather than throwing it away, and when it sees a key path that's shorter than expected it should drop that entry into a "custom" grouping so it still shows up. Display output for anything in that custom group needs to be non-empty whenever the entry actually has a value, so it's not just silently empty again.

Oh and there's a macro that collects build environment variables, I'd like an extended form of it that lets me pass explicit custom variable names so those get pulled in and rendered alongside the standard build info. That way standard and custom entries coexist and I can view all of it through the same pretty-printing interface instead of losing half of it.
