I'm using a pretty-printing library for build metadata and I've noticed that any custom or non-standard metadata entries I add are silently dropped when I try to display them. Entries whose keys don't follow the standard naming pattern just disappear from output — the library returns nothing for them instead of passing them through as individual entries. Similarly, entries with key paths that are shorter than expected are also dropped rather than being placed into some reasonable grouping.

I'd like the library to handle these cases gracefully. Non-standard keys should be preserved as unsplit entries rather than discarded, and short-path entries should be grouped together under a "custom" category so they still appear in output. The library also has a macro for collecting build environment variables, and I'd like that macro to support passing explicit variable names so I can include custom entries in the display output alongside the standard build information.
