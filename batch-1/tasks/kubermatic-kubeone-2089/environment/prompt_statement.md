I'm working on adding Cilium CNI support to KubeOne's node provisioning scripts. When a cluster is configured to use Cilium as the network plugin, the nodes need specific kernel settings applied during setup — particularly, reverse path filtering needs to be disabled on all interfaces, otherwise Cilium's data plane will drop packets it considers mangled, causing networking failures.

Right now, when KubeOne generates setup scripts for nodes (across all supported Linux distributions: Debian-based, CentOS-based, Amazon Linux, and Flatcar), it applies a standard set of kernel sysctl settings but has no awareness of whether the cluster will use Cilium. The Cilium-specific sysctl override should only be added when Cilium is actually the chosen network plugin.

I need the script generation logic to detect when the cluster's CNI is set to Cilium and, in that case, include an additional sysctl configuration file that disables reverse path filtering. This should work for all four supported OS types. The existing kernel settings for standard Kubernetes should still apply in all cases — Cilium just needs an additional override on top of those. I also need the golden test files updated to reflect the expected script output for Cilium-based clusters on each OS type.
