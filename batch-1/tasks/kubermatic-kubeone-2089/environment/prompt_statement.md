I'm adding Cilium CNI support to KubeOne's node provisioning scripts and hitting a networking gap. When a cluster is set to use Cilium as its network plugin, the nodes need extra kernel tuning applied during setup, specifically reverse path filtering has to be disabled on all interfaces. Otherwise Cilium's data plane treats packets as mangled and drops them, which causes hard-to-diagnose networking failures right after provisioning.

Right now when KubeOne generates the setup scripts for nodes it applies a standard set of kernel sysctl settings but has no awareness of whether the cluster will use Cilium. I want the script generation logic to detect when the cluster's CNI is Cilium and, in that case, include an additional sysctl configuration file that disables reverse path filtering on all interfaces (the rp_filter override). This has to work across all four supported OS types: Debian-based, CentOS/RHEL-based, Amazon Linux, and Flatcar.

Important bit, the Cilium sysctl block is additive, it goes on top of the existing standard Kubernetes kernel settings, not instead of them, so those existing settings should still apply in every case. And clusters using other CNI plugins shouldn't be touched at all, the Cilium-specific block should only show up when Cilium is explicitly the chosen plugin. Oh and I need the golden output files updated to reflect the expected script for Cilium-based clusters on each of those four OS types so the generated scripts match what's expected.
