I'm hitting a wall with PyKMIP's authentication handling. The `Authentication` struct over in `@kmip/core/messages/contents.py` only supports a single credential per auth block right now, but the KMIP spec lets you attach multiple credentials to one authentication block (think a username/password credential alongside a device credential), and the current code just can't represent or encode that.

What I want is for the authentication object to hold a list of credentials instead of one. If I construct it with nothing, I should get an empty credentials list by default, and I should be able to pass one or more credentials of mixed types (username/password, device, whatever) into the same object. When it reads an authentication message off a binary stream it needs to populate the list with every credential present in the encoding, including several in sequence, and when it writes back out with multiple credentials it should produce a byte-accurate encoding with all of them in order, matching the standard KMIP test vectors.

Error handling matters too. If credentials are missing when I read or write, raise a descriptive error. And if I try to set credentials to something bogus like a non-list, or a list that's got non-credential items in it, that should blow up with a clear message about what went wrong.

Oh and it should support equality comparison between two authentication instances, plus give me readable str and repr output that includes all the credentials it's holding so I can actually debug this stuff. This is about interop with compliant KMIP servers, without multi-credential support clients can't construct or parse these blocks at all.
