I'm working on this match-template proc macro that takes a single template match arm and expands it into a bunch of arms by substituting a list of type identifiers, saves a ton of repetitive boilerplate when you're branching on types. Problem is the parser only accepts exactly one arm right now, the template arm, and that's blowing up in real code because almost every match needs a wildcard catch-all at the end (think a branch that just panics with "unreachable") to satisfy exhaustiveness or handle unexpected values. Without it I either can't use the macro at all or I have to hand-reconstruct the whole match, which defeats the point.

What I want is for the macro input to accept either one arm (just the template arm, works exactly like it does today) or two arms, the template arm followed by an optional wildcard catch-all arm. When that wildcard arm is there it should be left completely untouched and appended to the very end of the expanded match, so the substituted arms come first and then the wildcard arm follows, exactly like I'd write it by hand. When there's no wildcard, behavior stays identical to before, don't change anything about that path. So basically it's parse one-or-two arms instead of strictly-one, preserve the second arm verbatim, emit it last after all the type-substituted arms.
