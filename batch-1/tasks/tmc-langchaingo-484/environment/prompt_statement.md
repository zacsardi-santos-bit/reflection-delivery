I'm working with a Go LLM library and the core language model interface currently requires every implementation to provide a method for counting tokens in a string. This feels wrong to me — token counting is a generic utility concern, not something specific to each model's ability to generate text. I have to implement this boilerplate in every new language model integration I write, even when I don't actually need token counting for my use case.

I'd like to remove the token-counting method from the language model interface so that implementing the interface only requires the core methods needed for actual language model invocation. The token counting can be provided as a standalone utility instead. All existing chain functionality (sequential chains, map-reduce, document chains, etc.) should continue working normally after this change.
