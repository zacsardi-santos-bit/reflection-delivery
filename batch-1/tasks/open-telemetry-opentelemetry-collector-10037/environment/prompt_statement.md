I'm working on the metadata code generator for the OpenTelemetry Collector and I want to clean up how it emits generated files per component. Right now the generator spits out a single status file that bundles two totally different concerns together: the component type/stability constants (the component package import, the type variable, and the stability-level constants) and also the telemetry provider helper functions for metrics and tracing. Problem is that means every status file drags in metrics and tracing deps even though those really belong in a separate layer, and it muddies what each generated artifact is even responsible for.

So I want to split this into two generated files. One should carry only the type/stability info, no telemetry imports or functions at all. The other should hold the telemetry provider helpers with their metrics and tracing imports plus the helper functions.

Also there's a bug I keep hitting: the telemetry helpers currently pass an empty string as the instrumentation scope name when they grab a meter or tracer from the provider. That's bad because without a component-specific identifier, signals from different components look identical in observability backends. Instead they should use the component's own module path as the scope name so telemetry gets attributed to the right component package.

To pull this off the generator needs two new templates, one for the telemetry implementation and one for the telemetry tests, and both need to be embedded in the generator binary alongside the existing ones. The existing status template should be updated so it only produces the type/stability stuff without any telemetry-related imports or functions. And once that's done every component in the collector (receivers, exporters, processors, connectors, and extensions) needs its generated files regenerated to reflect the new split structure.
