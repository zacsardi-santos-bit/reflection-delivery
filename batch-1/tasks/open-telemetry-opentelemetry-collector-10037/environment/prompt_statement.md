I'm working on the metadata code generator for the OpenTelemetry Collector. Right now, the generator produces a single status file per component that contains both the component type/stability constants and the telemetry provider helper functions (for metrics and tracing). I'd like to split these into two separate generated files: one that only handles component type and stability information, and a separate one that handles the telemetry provider helpers.

Additionally, the telemetry helpers currently pass an empty string as the instrumentation scope name when acquiring a meter or tracer from the provider. Instead, they should use the component's own module path as the scope name so that telemetry data gets properly attributed to the correct component in observability tooling.

To make this work, the generator needs two new templates — one for the telemetry implementation and one for the telemetry tests — both of which should be embedded in the generator binary. The existing status template should be updated to only produce the type/stability information without any telemetry-related imports or functions. All components in the collector (receivers, exporters, processors, connectors, and extensions) should have their generated files updated to reflect this new structure.
