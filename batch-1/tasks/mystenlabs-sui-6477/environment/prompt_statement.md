I'm on the Sui RPC layer and need to close two gaps that are biting tooling. First, there's no way to pull the current on-chain system state through RPC, so wallets, explorers, and monitoring tools have to do individual object lookups to piece together validator info, staking pools, protocol params, and epoch details, which is a pain. I want a new Full Node API endpoint that takes no input params and returns the complete system state in one shot. The response needs the current epoch number and reference gas price, a unique object id for the state object, system parameters like max validator count, min stake, and storage gas price, plus the storage fund and treasury cap balances, and validator report records. It should carry the full validator set structure, meaning active validators, pending validators, pending removals, and next-epoch validator metadata. Each validator should expose its stake amount, pending changes, commission rate, gas price, and its delegation staking pool info, and each staking pool should expose its balance, pending delegation entries, pending withdrawal entries, token supply, and starting epoch.

Second thing, addresses are coming out as bare hex right now, no `0x`. I want every address serialized in API responses and config snapshots to appear as a quoted string with the `0x` prefix instead, matching the convention users and tooling expect. That covers validator addresses everywhere in the system state, including the ones in staking pool records and validator metadata. Getting this right unblocks validator dashboards and staking UIs and fixes the interop headaches the missing prefix causes.
