I'm working on the stack autoinclude feature in our infrastructure tool. Right now, both individual units and composite stacks write their autogenerated dependency configuration to the same filename. This is causing a bug where a stack-level autoinclude file sitting next to a plain unit config gets merged into that unit's configuration — which it absolutely shouldn't be.

I need to split these into two distinct filenames based on the component's kind: one for units and one for stacks. There should be a lookup function that takes a component kind and returns the appropriate filename, and it should panic with a helpful message if an unknown kind is passed. The file generation logic should use a component's kind to decide which filename to write, ensuring that unit autoincludes never appear as the stack filename and vice versa.

On the config-parsing side, when processing a unit's own config file, the stack-level autoinclude filename must be ignored entirely and must not be merged in. Only the unit-level filename should be considered during unit config parsing.
