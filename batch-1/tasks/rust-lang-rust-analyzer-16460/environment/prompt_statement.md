I want rust-analyzer to flag redundant trailing return expressions, the cases where someone writes an explicit `return` at the very end of a function or closure when Rust's implicit tail return would do the exact same thing. Idiomatic Rust prefers implicit returns, so having an in-editor warning with a one-click fix nudges people toward cleaner code and helps folks who don't know Rust's implicit return rules pick up the convention.

This should be a weak hint, not an error, and it needs a fix that strips the `return` keyword (and the trailing semicolon if there is one) leaving just the bare tail expression, and for a bare unit `return` with no value the fix should remove the whole statement instead. It's gotta cover all the realistic spots a trailing return shows up: the last statement of a straight-line function body, both branches of an if/else when that if/else is itself the last thing in the function, every arm of a trailing match expression, closure bodies (both single-expression and block-body ones), and inner function definitions nested inside outer ones. Important, it can't fire when a return appears before other statements, only when it's genuinely the final value of the function or closure.

One tricky bit, some fixtures have if/else where both this new diagnostic and the existing unnecessary-else-branch diagnostic fire at once, which makes fix tests messy. So I also need a new test helper (over in the diagnostics test infra) that takes a list of diagnostic names to suppress for the duration of a fix check, so I can write clean trailing-return fix tests without unrelated diagnostics getting in the way.
