I'm adding two geometry constructors to Apache Sedona and I need them wired up across all the backends, so Spark SQL, the DataFrame API, Flink, Snowflake, and the core Java library depending on the function. Right now we only have plain 2D and 3D (Z) point constructors and a general geometry-from-WKB thing, but there's a couple gaps GIS folks keep hitting.

First one is a point that carries a measure (M) coordinate alongside X and Y. Lots of datasets use M for linear referencing, like measuring distance along a route, so I want a constructor that takes x, y, and m and produces a geometry whose text form follows the standard WKT M-coordinate point format (the POINT M style output). This one should show up as a SQL function, a DataFrame API function, and in the Flink and core Java layers.

Second is a linestring-specific constructor from Well-Known Binary. WKB is everywhere for binary geometry exchange so I want something dedicated. It needs to accept the WKB either as raw binary bytes or as a hex-encoded string, both work. The key difference from the general geometry-from-WKB constructor is it's linestring-only, so if the WKB actually encodes some other geometry type (a point, a polygon, whatever) it should return null instead of handing back a non-linestring geometry. If the input isn't valid WKB at all, then it should raise an error, not silently return null. Oh and it takes an optional SRID, and when I pass one the geometry should carry that SRID and it should be visible in the extended WKT output with the right SRID= prefix. This one goes in Spark SQL, the DataFrame API, Flink, and Snowflake.

For both, null inputs return null results wherever that's the expected behavior, like the DataFrame API.
