I want the Gleam compiler to warn about redundant comparisons anywhere in code, not just inside assert statements. Right now if I write a comparison where both sides are obviously the same, like comparing a variable to itself, or comparing record fields of the same variable instance, or comparing two different constructors of the same custom type that can never be equal, or comparing two literal values (ints, strings, bools, lists) whose result is knowable at compile time, the compiler only flags it when it's inside an assertion. Everywhere else it stays silent, which makes it way too easy to miss copy-paste errors or dead logic that should've been caught. So I want a warning any time such a comparison shows up, standalone expression or not, since it almost always means a bug.

The warning needs to be specific about which way it goes, so it should tell me whether the comparison will always evaluate to true or always evaluate to false, since those are different kinds of problems. Oh and comparisons that involve function calls should be left completely alone, don't warn on those, because the functions might have side effects and the result isn't actually predictable at compile time.

Also while you're in there, the existing warning messages could use cleanup. The assert-on-a-literal-bool case (asserting a plain boolean rather than a comparison) should get its own specific and accurate message instead of the generic text it has now. The redundant-comparison-inside-assert case should switch to the exact same message format as the new general redundant comparison warning so they're consistent. And the warning for a discarded unused literal value should be simplified to something shorter and more actionable. This lives in the type checking and warnings code, roughly around `@compiler-core/src/type_.rs` and the warning emission paths there. Catching these at compile time and not just in asserts helps stop subtle logical errors before they hit production.
