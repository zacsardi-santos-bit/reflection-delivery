I'd like the Gleam compiler to warn about redundant comparisons anywhere in code, not just inside assertion statements. Right now, if I write a comparison where both sides are obviously the same — like comparing a variable to itself, comparing two different constructors of the same type that can never be equal, or comparing two integer or string literals — the compiler only flags it if I'm inside an assertion. I'd expect a warning any time such a comparison appears, since it almost always indicates a bug or unnecessary code.

The warning should also be specific: it should tell me whether the comparison will always be true or always be false, since those represent different kinds of problems. Comparisons involving function calls should be left alone, since those might have side effects that make the result unpredictable at compile time.

Additionally, the existing warning messages for literal assertions and unused discarded values could use some cleanup — the current text is a bit generic and doesn't clearly distinguish between the different cases. The assert-on-literal-bool case should have its own specific message, and the redundant-comparison-inside-assert case should use the same format as the new general redundant comparison warning. The message for discarded unused literals should be simplified to something more concise and actionable.
