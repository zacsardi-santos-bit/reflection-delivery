There's no record of the patience I set, no note of which metric was being monitored, not even the epoch where training bailed out. Makes it really hard to tell why a run ended when it did or which checkpoint's numbers I'm actually looking at.

Here's what I'm after. When an early stopping callback is present during a fit, I want the patience value and the monitored metric logged automatically as run params. Then if training genuinely stops early and best weights get restored, log both the epoch training stopped at and the epoch whose weights were restored as run metrics. Oh and on top of that, append an extra entry to the metric history representing the performance at that restored (best) epoch, so I can eyeball the final model's quality straight from the metric timeline without digging.

If early stopping is configured but training runs all the way through without the patience ever getting exhausted, log the stopped epoch as zero to signal no stop happened, and skip the restored epoch. And if I'm using some totally unrelated callback that has nothing to do with early stopping, none of these fields should show up at all.

This lives in the Keras autologging path in the MLflow codebase. The point is a run should give me the full picture, what triggered the stop, what the best epoch was, and what that restored model actually scored, so comparing runs with different patience settings doesn't mean going back to raw training logs.
