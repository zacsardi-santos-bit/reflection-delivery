I'm looking at a real access control hole in our Admin API and I want the document retrieval endpoint locked down. Right now when a client authenticates with one project's secret key, they can turn around and pull documents belonging to a totally different project just by putting that other project's name in the request body. There's no check anywhere that the authenticated project actually matches the project whose docs are being asked for, so one tenant's key reads another tenant's data, which is a serious confidentiality problem in a multi-tenant setup where each project's credentials should only ever grant access to that same project's own documents.

What I need is for the retrieval handler to compare the project tied to the provided credentials against the project named in the request, and if they don't line up it should bail out with an unauthorized response (HTTP 401) instead of happily serving the data. So a client authenticated as Project A asking for a Project B document gets a 401, and clients can only ever fetch documents from the project they authenticated as. That scoping needs to be enforced at the point where we handle the document lookup, before any data goes out the door.
