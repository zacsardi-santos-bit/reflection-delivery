So I've been chasing a correctness bug in the edge-based contraction hierarchy routing when via-points (waypoints) land in the middle of a road segment. When a query point falls mid-segment we spin up a virtual connection point internally, and the U-turn detection at those virtual points is just wrong. The router's comparing virtual edge ids directly against real edge ids instead of first mapping the virtual edge back to its underlying real road, so sometimes it happily returns paths that actually violate turn restrictions, and other times it fails to route through a virtual point even when nothing's blocking it. I want it fixed so that routing through a virtual node succeeds and gives the right path with correct distances when no restriction is in the way, and when turn restrictions genuinely make every route between two points impossible (including any route that'd pass through a virtual node) the algorithm correctly reports no path exists. The key thing is turning onto a virtual edge that doubles back on the same underlying road has to be treated as a U-turn and blocked, so we need to resolve virtual edges to their real edge before doing the U-turn comparison.

While I'm in here, the test utility that builds random graphs needs updating too. Right now it takes a seed and creates its own random generator internally, but I want it to accept a caller-supplied random generator instead so callers can control and share the random state. Also add a parameter for setting random edge speeds via an encoded value, and a configurable probability that controls whether loop edges get non-zero distances.

This matters because folks routing with waypoints near intersections that have turn restrictions could otherwise get routes that are illegal to actually drive, which is a nasty bug to ship.
