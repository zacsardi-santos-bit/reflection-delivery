I'm working on edge-based contraction hierarchy routing and have found a correctness bug when via-points (waypoints) are used together with turn restrictions. When a query point falls in the middle of a road segment, the system creates a virtual connection point internally. The routing algorithm doesn't correctly detect U-turns at these virtual points — it's comparing virtual edge identifiers directly against real edge identifiers instead of mapping virtual edges back to the underlying real road first. This causes the router to sometimes find paths that violate turn restrictions, and other times to fail routing through virtual points when it should be possible.

I need the algorithm to correctly handle these cases: routing through a virtual node should succeed when no restrictions block it, and the algorithm should correctly determine that no path exists when turn restrictions make all routes impossible — even when those routes would pass through virtual nodes.

At the same time, the utility function for building random test graphs needs to be updated. It currently creates its own random generator from a seed, but it should accept a caller-supplied random generator so the random state can be shared. It also needs a parameter for setting random speeds on edges using an encoded value, and a configurable probability for whether loop edges get non-zero distances.
