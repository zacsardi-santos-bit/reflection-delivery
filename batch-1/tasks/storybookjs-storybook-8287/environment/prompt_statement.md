I'm hitting two bugs in Storybook that show up whenever a decorator calls the story function more than once in a single render cycle, which some decorators do on purpose (double-rendering, inspecting the story, that kind of thing).

First one's in the knobs addon. When a story re-renders and a knob already exists in the store with the same type, any extra config options I pass beyond the value just get dropped on the floor. So if I update a knob's label or its list of choices on a later render, the panel keeps showing whatever I registered the first time around, totally stale. What I want instead: when the knob's type hasn't changed between renders, take those updated options and apply them onto the existing knob entry in the store so the panel stays fresh. The type-matching check is the key bit, only merge the new options when the type still lines up.

Second one's in the hooks system. Side effects I register inside a story are firing once per invocation instead of once per render cycle, so if a decorator invokes the story twice, my effect runs twice, which means duplicate network requests, repeated state updates, and a bunch of behavior that's a pain to track down. Effects should run exactly once per render cycle no matter how many times the decorator ends up calling the story function, so I need them deduplicated across those extra calls.

Both need fixing together since they combine to make these multi-call decorator patterns unreliable. The knob work lives in the knobs addon store logic and the effect dedup lives in the hooks runtime (roughly `@addons/knobs` for the store registration path and `@lib/addons` hooks for the effect handling), so I'd look there. Net result I'm after: knob options stay up to date when the type matches, and side effects only execute once per cycle regardless of how the decorator behaves.
