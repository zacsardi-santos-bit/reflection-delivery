I'm trying to use pandera's Polars schema types as pydantic field types and right now it just doesn't work. When I annotate a pydantic model field with a typed Polars DataFrame carrying a specific schema, pydantic has no idea how to validate it and I get errors instead of validation. What I want is for that field to auto-validate the input against the schema and raise a proper pydantic validation error when the data doesn't conform. I also need the schema model classes themselves to be accepted as field values, with inheritance working so a child schema is accepted where a parent schema is declared, while an unrelated model is not, and passing something bogus like an int or a plain schema object should raise a validation error too.

The typed Polars DataFrame in `@pandera/typing/polars.py` should also read from and write to the usual formats (CSV, JSON, Parquet, Feather, and plain Python dicts), matching what the pandas-backed class already does over in `@pandera/typing/pandas.py`. Unsupported stuff like pickle should raise a descriptive error rather than blowing up cryptically. Oh and when someone passes a dict or a pandas DataFrame where a typed Polars field is expected, it should auto-convert to a Polars DataFrame instead of getting rejected.

This needs to play nice with both older and newer pydantic (v1 and v2 style `__get_validators__` / `__get_pydantic_core_schema__` hooks). And optional columns in schema models have to behave right: missing optional columns are allowed, wrong types for optional columns are rejected, and missing required columns are rejected. The point is folks building APIs or data pipelines on the Polars backend can lean on pandera's type-annotated validation inside pydantic models without hand-wiring it, and the format conversion makes Polars a first-class citizen next to pandas.
