I'm cleaning up the Debian packaging logic for kubeadm and the declared minimum dependency versions are way out of date. Over in the Debian build code that generates the package dependency declarations, the node agent (kubelet) and the CLI (kubectl) currently pin their minimums to some release from years ago, which means apt and friends will happily accept ancient, totally incompatible Kubernetes tooling as satisfying the dependency. I want those minimums bumped to reflect the actual current minimum supported Kubernetes version so package managers enforce a coherent set of components.

Same story with the container runtime tools (cri-tools) dependency, it's pinned to an old version and isn't even being included consistently. Right now it only gets added for releases above some older threshold, but I want it required for all currently supported versions including the minimum supported one, and its minimum version needs to move up to match the current support floor too.

Oh and while we're in there, the logic that picks which kubeadm config file path to use based on the version string should keep working correctly for current version strings and return the right current config path across all supported versions. Basically everything should line up with the real supported version window so users can't accidentally install something broken and think it's fine.
