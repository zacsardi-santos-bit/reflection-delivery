I'm hacking on a JavaScript engine written in Rust and I keep hitting crashes across a huge swath of typed array conformance tests, like construction, property access, iteration, sorting, filtering, slicing, all of it blows up at runtime. I dug in and I think there are two root causes.

First, the trait we use to describe viewable binary types (the ones typed arrays are backed by) doesn't carry any info about which JavaScript prototype each type maps to. So when the engine goes to set up the prototype chain at runtime it has no way to look up the right prototype and just crashes instead. I want every binary type that can back a typed array to declare which prototype it belongs to, so like the unsigned 8-bit integer type links to the Uint8Array prototype, the 64-bit float type links to the Float64Array prototype, and so on for each variant. Once that prototype reference exists the engine can actually wire up typed array prototypes properly during construction and prototype method calls and subclassing.

Second, the clamped unsigned byte variant (Uint8ClampedArray) is just straight up missing from the system. There's no type representing it, no impl of the viewable trait for it, and no wiring to its prototype. Since it's one of the standard typed array kinds, anything that iterates over all the typed array types trips over its absence and crashes too. Can you add a proper clamped byte type that's fully integrated as a viewable binary type, linked to the right prototype, and (this is the important bit) uses clamped conversion semantics when writing values into the buffer, so out of range values saturate instead of wrapping.

After both of these, typed array construction, prototype method calls, and subclassing shouldn't crash on the standard conformance suite anymore. This is foundational stuff since typed arrays are core to the spec and used everywhere in real code, so fixing the prototype wiring plus adding the missing clamped type should unblock a big pile of currently crashing tests.
