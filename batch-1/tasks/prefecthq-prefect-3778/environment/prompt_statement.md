I'm on Prefect's Kubernetes agent and I keep hitting a wall where there's no clean way to set a service account or image pull secrets for the flow run jobs it spins up. Right now I'm stuck hand-editing job template files or doing env var hacks, which is gross, especially when teams are pulling from private registries or running under strict RBAC.

What I want is for the k8s agent to support a service account name plus a list of image pull secrets, both at the agent level (as defaults applied to every job it starts) and at the individual flow level via the run configuration, so a specific flow can override the agent defaults. When both are set the per-flow values should win. And here's the tricky part, if a flow brings its own job template that already has these fields set, the template values should be respected and not clobbered by the agent defaults, even when the template explicitly sets those fields to an absent or empty value (so an intentional None or empty list in the template stays put and doesn't get backfilled).

Also I need these exposed as CLI flags when starting the agent so operators can set the agent-level defaults from the command line. Oh and the new per-flow fields on the run config need to survive serialization and deserialization intact, round-tripping cleanly so nothing gets dropped or mangled when a flow's config is written out and read back in. The precedence order matters end to end: template values first, then per-flow run config, then agent defaults as the fallback.
