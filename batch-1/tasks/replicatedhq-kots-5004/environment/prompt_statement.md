I'm adding network connectivity info to the embedded cluster node join flow. Right now when a node joins we generate a join token and command for it, but the response doesn't tell the joining node which endpoints it has to be able to reach on the existing cluster nodes, so we end up with confusing mid-join failures when a port is blocked by a firewall or bad routing. I want to add a field to the join command response listing the TCP endpoints (host:port pairs) the joining node must connect to, so connectivity can be pre-checked before the join even starts.

The list depends on the role the joining node will have. Worker nodes only need to reach the Kubernetes API server port and the cluster overlay API port on each existing controller node. Controller nodes need those plus the cluster state replication port and the node-to-node communication port on each existing controller, and also the node communication port on each existing worker. Only nodes currently in a healthy/ready state should show up in the list, skip anything not ready, and if there are no existing nodes at all the list should just come back empty.

Oh and while I'm in here, the handlers always grab the real cluster Kubernetes client directly, which makes unit testing basically impossible. I want a small injectable abstraction, an interface with a real implementation plus a mock, living in its own dedicated sub-package, so tests can supply a fake client by setting it on the handler struct. Then the endpoint-building logic can actually be exercised with fake node lists covering the worker vs controller role differences, the ready-state filtering, and the empty case.
