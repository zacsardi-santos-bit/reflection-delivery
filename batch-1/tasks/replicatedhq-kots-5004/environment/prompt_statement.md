I'm working on an embedded cluster node join feature. Right now, when a node wants to join the cluster, the system generates a join token and command for it to use — but the response doesn't include any information about which network endpoints the joining node needs to be able to reach on existing cluster nodes. I'd like to add a field to the join command response that lists the TCP endpoints the joining node must connect to, so that connectivity can be pre-checked before the join process starts.

The list of required endpoints should depend on the role the joining node will have. Worker nodes only need to reach a couple of API ports on existing controller nodes, but controller nodes need to reach additional ports — for cluster state replication and node-to-node communication — on both existing controllers and workers. Nodes that aren't in a ready state shouldn't contribute to this list. If there are no nodes yet, the list should be empty.

I also need to make the Kubernetes client used inside these handlers injectable — right now it's always fetched directly from the cluster, which makes unit testing impossible. I'd like a small abstraction (an interface with a real implementation and a mock) in a dedicated sub-package, so that tests can supply a fake client by setting it on the handler struct.
