I'm working on the Redis caching layer in Argo CD and I've found two problems that need to be fixed together.

The first issue is with the hook that triggers a Redis reconnect when the connection goes down. Right now it detects failures by scanning the error message for a specific text substring. This is fragile — it won't reliably catch DNS resolution failures, and the detection happens too late in the pipeline. I need the reconnect callback to be triggered by actual DNS resolution errors during real Redis operations, not by string matching on error messages. At the same time, successful operations should not trigger the callback at all.

The second issue is that the metrics-collecting hook that's supposed to track Redis request counts and durations doesn't actually do anything. There's currently no way to attach a working metrics hook to a Redis client. I need a function that takes a Redis client and a metrics registry, attaches a proper hook to that client, and then ensures that for each operation: successful requests increment a success counter, failed requests (genuine errors, not cache misses) increment a failure counter, and every request — success or failure — records its duration in a histogram. These are all per-command, so a Set followed by a Get should produce two separate counter increments and two duration observations.
