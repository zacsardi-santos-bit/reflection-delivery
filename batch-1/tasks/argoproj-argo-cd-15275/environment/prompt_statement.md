I'm digging into the Redis caching layer in Argo CD and there are two things tangled together that I want fixed as one change. First, the hook that triggers a reconnect when Redis goes unreachable is way too fragile. Right now it decides a connection failed by scanning the error message text for a particular substring, which is brittle because it won't reliably catch DNS resolution failures if the wording shifts, and it only fires after a full round trip instead of at the connection level where the failure actually happens. I want the reconnect callback to be driven by real DNS resolution errors that surface during actual Redis operations, so when an op fails because the host can't be resolved via DNS the callback gets invoked reliably, and when an op succeeds the callback doesn't fire at all. No more string matching on error messages.

Second problem, the metrics-collecting hook that's supposed to track Redis request counts and durations is basically dead, it doesn't count anything or record durations, so the Redis perf numbers on the Argo CD metrics endpoint are always empty and operators can't see latency or error rates. I need a function that takes a Redis client plus a metrics registry, attaches a proper working hook to that client, and then for each operation does the right thing: a successful request bumps a success counter, a failed request (an actual error, not a cache miss) bumps a failure counter, and every request whether it succeeds or fails records its duration into a histogram. These are all per-command too, so a Set followed by a Get should give me two separate counter increments and two duration observations, not one lumped together. btw both of these matter because without solid reconnect detection Argo CD can silently stay disconnected after a DNS change or restart, and without real metrics there's zero visibility into Redis health.
