I'm doing some cleanup on the resources management service in our workflow scheduling platform and there's a few things tangled up here. First off, some method names are just confusing and don't say what they do. The one that uploads a resource file from a multipart form upload should get renamed to actually reflect that it's an upload op, and the one that creates a resource file from inline text content should be renamed so it reads as creating a file rather than uploading one. I need those renames applied consistently across the service interface, the implementation class, and the REST controller that exposes them, so no dangling old references anywhere.

Also there's a security hole in the resource content update path. Right now you can pass an arbitrary file path that lands outside the tenant's designated storage directory, which is bad, could be used for unauthorized file access. So when updating resource content I want it to check that the given resource path actually falls within the expected storage directory for that tenant, and if it's outside, reject the operation with an error message saying the path is illegal.

Oh and last thing, there are two service methods plus their matching REST endpoints that deal with listing which UDF functions are authorized or unauthorized for a specific user. We don't need that in the resources service anymore, so rip them out entirely, both the interface declarations and the implementation. Consistent naming keeps the API sane and the path check is a real security win.
