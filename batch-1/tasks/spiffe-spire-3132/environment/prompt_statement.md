I'm poking at the SPIRE server's SQL datastore plugin and hit an annoying inconsistency: the method that configures the plugin doesn't take a context, even though every other DB operation in there already does. Since config is where we open connections and do setup, it's basically an I/O-bound step and should follow the usual Go convention of taking `ctx context.Context` as the first argument. Right now there's no way to propagate a deadline or cancellation into that initialization phase, which also means we can't do context-aware work (like cleaning up stale data) during startup, and it just breaks consistency with the rest of the codebase.

So I want to update the configure method on the SQL datastore plugin to accept a context as its first parameter, and then chase down all the call sites and thread a context through. That includes the production startup path in the catalog loader, plus test helpers and the fake datastore used in tests, all of them need to pass a context now. Basically anything that calls the old signature has to be fixed up to pass ctx.

The important thing is the existing error handling has to keep behaving exactly like before, so invalid database types, malformed or bad connection strings, and missing required parameters should all still surface the same errors they do today. I just want the signature change and the plumbing, not a change in behavior. Once it's done, adding the ctx first-arg should make the whole plugin consistent and unlock context-aware setup work later.
