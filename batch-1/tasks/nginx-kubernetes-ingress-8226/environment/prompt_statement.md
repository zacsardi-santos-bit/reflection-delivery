I'm poking at our NGINX Kubernetes Ingress controller and hit a mismatch with the feature flag that controls whether proxy buffer directive values get auto-adjusted and normalized. The intent is that when auto-adjust is off, whatever proxy buffer config a user sets flows through to NGINX byte-for-byte, but right now the controller still parses those values into internal structured objects and can normalize or correct them before they land in the generated config, so what NGINX actually gets can differ from what someone wrote. I want it so that with auto-adjust disabled I take the user's values as plain strings and pass them straight through with no validation or correction at all. When auto-adjust is enabled, keep validating and normalizing recognized size units (case-normalizing the unit suffix, and replacing an unsupported unit with a valid default), and reject clearly invalid formats with an error event instead of quietly fixing them.

There's also a related bug where a proxy buffer spec containing completely unrecognized unit characters gets silently coerced to a default unit rather than rejected. With auto-adjust on those should raise a clear error so the user knows their config is bad.

Oh and the annotation validation errors are too vague. When someone sets a size-type annotation like proxy buffer size or upstream zone size to something invalid, the message just says "must be a size" which tells them nothing. I want that error to describe the expected format, spell out which unit suffixes are valid, and show an example or the validation regex so people can fix it fast. This all lives around the annotation validation and proxy buffer parsing paths in the controller, so trace where size annotations get checked and where buffer specs get turned into structured values and gate that normalization behind the auto-adjust flag.
