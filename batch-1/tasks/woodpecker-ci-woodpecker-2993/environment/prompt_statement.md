I'm adding protocol support to port definitions in our pipeline service configs and could use a hand wiring it through everything. Right now ports in the YAML are just plain numbers, but I need an optional transport protocol alongside the number so services like WireGuard over UDP (think port 51820/udp) or other non-TCP stuff can actually be exposed correctly. Without this there's no way to route traffic on the right transport, which is a real blocker for VPN-style services.

The format I want is a port number by itself, or a port number followed by a slash and a protocol name, so something like `51820/udp` parses into a structured port object carrying both the number and the protocol. Plain `51820` with no protocol is fine too, it just means no protocol set. Parsing needs to be strict though: putting the protocol before the number (wrong order), using some other delimiter instead of the slash, or handing over a non-numeric port should all fail as an invalid port definition with an error rather than silently doing something weird.

Then this structured type has to propagate through the whole pipeline. The Docker backend currently deals in plain integers, so it needs to work with the new port type instead. On the Kubernetes side, both pod containers and services need to expose these ports with the protocol in uppercase (that's what k8s requires), and ports that don't specify a protocol should just omit the protocol field entirely rather than defaulting it. Oh and when a step has ports defined, the k8s pod containers should actually include those port entries, don't drop them. Basically the port number plus optional protocol should survive intact from YAML all the way down into both backends.
