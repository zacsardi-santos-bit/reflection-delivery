I'm working on the mirrord agent's IPTables setup and hitting a real problem when we run as an ephemeral container inside a pod that's part of a service mesh. The mesh sidecar proxy intercepts all pod traffic, including the agent's own communication port, so our traffic gets routed through the proxy and that breaks the agent talking to its clients. There's no way right now to tell the proxy to leave our port alone, so I want to add an opt-in mechanism to exclude the agent's port from the sidecar's routing rules.

What I need is a new IPTables chain that holds these port exclusion rules. When the mesh exclusion option is enabled, create the dedicated chain, and wire a jump to it from the packet pre-routing hook so it runs before the existing redirect rules get applied. The chain holds rules that accept (basically bypass proxy routing for) specific ports, and when the feature's active the agent's own listening port should get added to that exclusion chain so the sidecar skips it.

Lifecycle matters here. The chain gets created during agent startup when this feature is on, and cleaned up when the agent exits. Also I need to support both creating brand new rules and loading existing ones during that lifecycle handling. Oh and the important bit, the new chain name has to be recognized as a mirrord-managed chain so it's picked up by the dirty-check and cleanup passes alongside the existing managed chains, otherwise we'll leak state. The whole thing stays optional and only kicks in when we're deployed as an ephemeral container in a service mesh (think Istio ambient mode or Linkerd), since that's exactly where this interception problem shows up and causes the connectivity failures I'm trying to fix.
