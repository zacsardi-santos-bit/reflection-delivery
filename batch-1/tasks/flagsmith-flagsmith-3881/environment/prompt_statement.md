I'm dealing with our edge V2 migration in DynamoDB, the one that moves identity overrides into the new format, and right now it just runs wide open with no throttling so it can chew through unlimited read capacity. That's scary in prod because a migration on a big dataset can basically run forever and rack up cost and hurt performance, so I want to add a read capacity budget so operators can throttle it.

The idea is each project can have its own configured read capacity budget, and when a project doesn't set one it should fall back to a global default setting. As the migration runs its paginated DynamoDB queries it needs to track how much read capacity it's consumed across those pages and stop gracefully once it hits the limit. When it stops mid-migration because the budget's exhausted, I don't want it to error out, I want it recorded as incomplete instead, a new distinct status separate from "in progress" or "not started" so the run can be retried or resumed later. Anything processed before we hit the budget should still get applied.

There's a rename too. The migration status tracking enum and its matching field on the project model need renaming to reflect their broader scope (not just narrow migration state), and this new incomplete value gets added as part of that. Oh and a project sitting in the incomplete state shouldn't show edge identity overrides for features, same behavior as not-started and in-progress.

Also the piece that fetches paginated DynamoDB records needs to start returning consumed capacity info alongside the records, and the higher-level migration service needs to catch the budget-exceeded condition and return a structured result object that carries both the migration status and the changeset of identity overrides.
