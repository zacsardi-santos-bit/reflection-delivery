I'm cleaning up the component data model in our core types crate over in Rerun and there's a design smell I want gone. Right now the trait that represents a bundle of multiple named component batches has a blanket impl that makes every single individual component type automatically count as a full bundle. That's dangerous because code expecting a real multi-component bundle can silently swallow a bare single component, which doesn't make semantic sense and masks bugs.

So the ask: kill that blanket implementation entirely so an individual component no longer implicitly satisfies the bundle trait. After this, if someone actually wants to pass one component as a bundle they should have to be explicit about it, meaning first treat the component as a batch reference and then wrap that in a slice of batch references before handing it off as a bundle. Arrays and slices of explicit batch references should just work as multi-batch bundles, each element contributing one batch to the collection.

Also while I'm in there I want to pull the bundle trait definition and its impls out of the main library entry file (it's all inline right now which is annoying to read and extend) and into its own dedicated module and source file, but keep it re-exported from the crate root so the public export path stays identical and callers don't need to change anything.

One thing to be careful about: all the existing collection variants still need to keep working, so fixed-size arrays, slices, and vecs of both raw batch references and bundle-implementing types should continue to be supported. Basically the only thing that stops compiling is passing a lone component where a bundle is expected, everything else stays green.
