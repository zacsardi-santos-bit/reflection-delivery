I'm working with the streaming path helpers in `@src/datasets/download/streaming_download_manager.py` and hit a gap. The module already wraps the usual path stuff, joining, opening, grabbing the stem or suffix, so it works the same whether you hand it a local file path or a remote URL. Problem is there's no glob-style matching anywhere in there, so when a dataset script needs to enumerate files by pattern it's stuck. Think listing all the parquet files under date-partitioned directories, or finding everything matching some name pattern inside a remote location, there's just no streaming-compatible way to do it right now.

I want two new utilities added to that module. One globs a directory for entries whose names match a given pattern, it takes a path plus a pattern string and returns each matching entry as a path representation. The other does the same thing but recursively, walking the whole directory tree under the path and returning every match anywhere below it, again path plus pattern string in, matching paths out. Both need to behave identically for local paths and for remote filesystem URLs, consistent with how the existing wrappers in this module already handle that split.

The point here is that streaming mode should be a complete stand-in for file-based access. Right now scripts that discover files dynamically (say, partitioned data organized into dated folders) either can't run in streaming mode at all or have to keep separate code paths for local versus remote, which is exactly what these wrappers are supposed to avoid. Adding glob and recursive glob closes that gap so the same code works either way.
