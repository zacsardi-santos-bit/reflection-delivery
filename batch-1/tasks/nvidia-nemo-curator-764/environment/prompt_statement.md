I'm working in our data curation pipeline framework where stages are the reusable processing units, and I keep running into a gap when I want to reuse an existing stage with tiny tweaks. Say I want the same stage but with different resource allocations, a different display name, or a different batch size. Right now my only options are subclassing it or mutating the original stage object in place, both of which stink. I'd like a method on processing stages that returns a modified copy with property overrides for name, resources, and batch size, while leaving the original stage completely untouched. If I don't pass an override for a property (or pass nothing explicitly), it should just keep the original value. And it should return the new instance so I can chain these customization calls together fluently.

Then there's composite stages, the ones made up of multiple named sub-stages. I want a way to configure individual sub-stages by name before the pipeline runs. This should accumulate the named-stage configs and return the same composite instance for fluent usage, and when the composite expands into its sub-stages the configs get applied in order. If I do this in separate calls, a later call should see the state from earlier ones, so applying to the list of sub-stages works sequentially and a later config can reference names introduced earlier. If two sub-stage names collide (not unique) or I reference a name that doesn't exist, I want a descriptive error raised, not some silent no-op. Oh and the composite stage should report its declared inputs from its first sub-stage and its outputs from its last sub-stage. Overall this makes pipelines way more composable so I can derive customized stage instances inline instead of writing a new class for every minor variant.
