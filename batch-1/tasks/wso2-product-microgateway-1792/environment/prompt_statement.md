I'm working on an API gateway that supports CORS configuration, and I need to add support for specifying which response headers should be exposed to browser clients in cross-origin scenarios. Right now the gateway lets you configure allowed origins, methods, and request headers, but there's no way to set the expose headers — the headers that browsers allow JavaScript to read from responses.

I need to extend the internal CORS configuration model to include an expose headers field, and update the logic that builds CORS policies to populate the expose headers from that field. When expose headers are provided, they should appear as a comma-separated list in the generated policy (matching the existing pattern used for allowed headers). When no expose headers are configured, the expose headers on the generated policy should be empty.
