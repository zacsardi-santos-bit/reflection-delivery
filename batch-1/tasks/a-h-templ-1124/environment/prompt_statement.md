I'm working on a template language server that has a no-preload mode for big codebases where we skip loading files at startup. Problem is when someone opens a template file in that mode, we never go pull in the other templates it depends on, so the server ends up with a half-empty picture of the dependency graph and completions and diagnostics suffer for exactly the people who opted out of preloading.

I want a lazy loading component that kicks in when a document opens: it should discover the complete package dependency graph for that file and open every template file in it, but loading dependencies before dependents so we go deepest-first in topological order. It needs to keep a per-file reference count so a file shared across multiple open packages doesn't get opened twice. Then on close it walks that same graph in reverse, decrementing counts and only actually closing files whose count hits zero. Oh and circular package imports have to be handled without spinning into an infinite loop, that's important.

Also I need real error propagation, not swallowed failures. If loading the package metadata fails, or reading a file fails, or notifying the language server about an open or close fails, each of those should surface a descriptive error that includes the relevant file path and the package path so I can actually tell what went wrong.
