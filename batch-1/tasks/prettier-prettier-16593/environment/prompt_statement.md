I'm hitting a weird Prettier bug with comments in logical expressions. When I've got a chain of conditions joined by `||` and each one has a trailing comment like `// explains this condition`, running the formatter yanks the comment off the last operand and slaps a set of extra parentheses around the whole thing. It only happens when that logical expression is the argument of a unary op, so think a negation or a `void`-type operation wrapping the chain. Outside a unary it's fine, but inside one the trailing inline comment on the last operand gets attached to the wrong node during printing and hoisted up to the enclosing expression, which also drags in unnecessary parenthesization that wasn't in my source.

What I want is for trailing comments to stay glued to the operand they were written next to, and no extra parens introduced just because a comment is present. This lives in the Prettier JS printing path where logical expression operands and their comments get grouped, so the trailing comment on the final operand shouldn't leak out of the group.

Beyond the basic OR-in-a-negation case, it's gotta handle mixed `&&` and `||` chains where precedence-based grouping actually matters (comments staying put at their respective positions while the groups nest correctly), nested parenthesized sub-expressions, and the case where the trailing thing is a block comment `/* like this */` instead of a line comment. All these patterns should format with the comments in the right place. And it needs to behave the same whether semicolons are on or off, across all the supported parsers. It's a formatting correctness thing, the output should preserve what I wrote so reviewers see comments sitting right next to the code they describe.
