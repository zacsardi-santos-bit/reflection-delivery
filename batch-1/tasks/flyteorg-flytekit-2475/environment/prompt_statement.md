I'm building sidecar support for NVIDIA inference model servers inside Flyte task pods, and right now there's nothing built in so people wire up the k8s specs, secret injection, and init containers by hand, which is error prone and doesn't play nice with Flyte's resource and secrets management. I want two classes exposed from the inference plugin's top-level namespace: an NGC model server config and a separate credentials class.

The credentials class needs the NGC API key name, the image pull secret name, and a secrets prefix, all three mandatory, so trying to construct it without any of them should blow up with a clear error. The model server config takes those credentials plus optional model image, memory, port, and env vars. On init it should build the pod template with the right image pull secret, inject the NGC API key as an env var by combining the secrets prefix with the uppercased key name, and apply the resource and port settings. Give it sensible defaults too: base URL at localhost on port 8000, one CPU, one GPU, 20Gi memory, 16Gi shared memory, and a standard health check endpoint path.

Oh and I also want LoRA adapter support, downloading fine-tuned adapters from Hugging Face before the server starts. When someone passes a list of HF repo IDs, validate that a download-step memory allocation is set (raise a descriptive error if it's missing) and that the required source path env var is present (again, descriptive error if not). When both are there, configure a dedicated init container that pulls down all the specified adapters. Make sure both classes import cleanly from the plugin top level.
