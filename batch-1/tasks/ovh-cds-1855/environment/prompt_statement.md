I'm working on the workflow execution engine and I've got a gap around figuring out when a specific node run can be re-triggered. Right now there's basically no real check, it's either missing or some oversimplified heuristic that doesn't actually look at the state of the upstream nodes in the workflow graph before letting you re-run something. That's a problem because if someone hits re-run on a node whose upstream dependencies haven't finished yet, we can get race conditions or an inconsistent pipeline state, so I want accurate eligibility info so the UI and API can correctly enable or disable the re-run action per node.

The rule I want is: a node run is only re-runnable if all of its ancestor nodes, meaning the ones that feed into it via triggers whether directly or indirectly, have already reached a terminal state like success or failure. If any ancestor is still in progress (building, waiting, that kind of thing) then the node isn't eligible. Same deal if an ancestor has never been run at all, so an empty status means not eligible. And if a node has no ancestors, like it's the root of the workflow, then it's runnable as long as its own current status is terminal.

This should live in the workflow data access layer next to the other workflow run loading code, so wherever we load workflow runs today is where this new eligibility function belongs. Just walk the ancestors via the trigger edges and check their terminal states, root nodes only care about their own state.
