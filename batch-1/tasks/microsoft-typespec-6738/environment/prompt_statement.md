I'm working with the TypeSpec C# client code generator, and I've run into an issue with how it handles certain paging operations. Specifically, when I define a list operation that uses paging metadata but doesn't include a next-link URL or a continuation token — an implicit or single-page paging pattern — the generator crashes instead of producing valid code.

What I'd expect is that when a list operation is marked as pageable but has no explicit pagination mechanism, the generator should still emit the correct set of collection result wrapper classes (synchronous and asynchronous, untyped and typed), with each class yielding a single page result and returning null for the continuation token. The client methods for these operations should also return the right pageable types.

There also seems to be a related issue where the generator only considers an operation "pageable" if it has a next-link or continuation token, meaning operations with paging metadata but no token configuration are incorrectly treated as non-paging. Any operation that has paging metadata set should be treated as pageable, regardless of whether it has a next-link or continuation token configured.
