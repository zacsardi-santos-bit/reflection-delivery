I'm working on the transaction gossip layer of an Ethereum node implementation. Right now, when a peer sends a transaction announcement, we trust it blindly and queue everything for fetching without any sanity checks. I'd like to add a validation step that filters announced transactions before we attempt to fetch them.

The validation should handle two announcement message formats — an older format that just contains a list of transaction hashes, and a newer format that also includes a transaction type byte and encoded size for each entry. For the newer format, entries with unrecognized transaction types should be filtered out and the peer should be reported for misbehavior. Entries with a zero-byte encoded size (strictly too small to be any valid transaction) should be filtered out silently without penalizing the peer, since it could be an honest mistake. Duplicate hashes in either format should be deduplicated, and if duplicates are found the peer should be penalized. Empty announcements (either format) should also result in a peer report.

The output of validation should be a map from transaction hash to optional metadata — for the newer format the value is the type and size, for the older format the value is absent. The filter should also return a signal indicating whether the caller should apply a reputation penalty to the peer.

The filter logic should be pluggable so that different networks can define their own validation rules. A default implementation covering standard Ethereum transaction types should be provided, and it should implement the display trait showing its own type name.
