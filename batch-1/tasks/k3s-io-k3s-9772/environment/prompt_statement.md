I'm working on the k3s project and need to add a centralized utility for mapping cluster service names to their associated certificate and key file paths. Right now, any code that needs to know "which cert files belong to the API server?" or "which files belong to the kubelet?" has to hard-code that mapping itself. I'd like a single place that owns this lookup.

Specifically, I need a new utility package that exposes a function accepting a control configuration and a list of service names, and returns a map from each service name to its ordered list of cert/key file paths. The file paths should be derived from the runtime configuration fields (which are already populated by the existing cert file setup utility). The function should return an error if any unrecognized service name is passed in.

The package should also export pre-defined service groupings: one for all standard services, one for server-only services, and one for agent-only services. Additionally, there should be a named constant for the certificate authority service — it's valid to look up, but intentionally kept out of the standard groupings since CA rotation requires manual intervention.

When using the server-only grouping with a given data directory, the returned map should include entries for admin, API server, auth proxy, cloud controller, controller manager, etcd, and scheduler. The all-services grouping should additionally include the k3s controller, kube-proxy, and kubelet entries. For services that span both the server and agent directories (like the controller, kube-proxy, and kubelet), the returned file list should include both the server-side and agent-side paths.
