I'm doing some cleanup on the k3s cert handling and keep running into the same annoyance: everywhere that needs to know which cert and key files belong to a given service (the API server, the kubelet, whatever) just hard-codes that mapping itself. The cert rotation logic does it, and now I want to add expiry checking and I really don't want to re-specify the whole service-to-file mapping from scratch again. So I want one utility package that owns this lookup.

What I'm after is a function that takes a control config plus a list of service names and hands back a map from each service name to its ordered list of cert/key file paths. Those paths should come off the runtime config fields that the existing cert-file setup already populates, so I'm just reading what's there. If somebody passes a service name that isn't recognized, I want an actual error back, not a silently incomplete map.

The package should also export some pre-defined groupings so callers don't have to spell things out: one for all standard services, one for server-only, and one for agent-only. And there should be a named constant for the certificate authority service too, it's valid to look up on its own but I'm deliberately keeping it out of the standard groups since CA rotation needs manual intervention anyway.

Behavior-wise, when I use the server-only grouping against a given data dir, the returned map should have entries for admin, API server, auth proxy, cloud controller, controller manager, etcd, and scheduler. The all-services grouping should include all of those plus the k3s controller, kube-proxy, and kubelet. Oh and for the services that live in both the server and agent directories (the controller, kube-proxy, and kubelet), the returned file list needs to include both the server-side and agent-side paths, not just one.
