I'm hitting a bug with the GraphQL schema import tool that stitches schemas together across files using import comments. I've got a master schema setup where my root file has zero type definitions, it just contains import directives that pull the query types in from a second file. That second file imports a specific type from a third file, and the third file then imports everything from a fourth file via wildcard. When I resolve the whole thing starting from that root file, types defined deep in the chain go missing from the output. There are seven types spread across the four levels and only a subset actually show up. It really looks like transitive dependencies aren't followed all the way through when the entry point is a pure import file with no definitions of its own, so the intermediate hops get dropped and I silently end up with an incomplete schema. That's nasty because the missing types don't blow up at build time, they only bite at runtime.

Can you fix the transitive import resolution so a master schema file that's only imports (no type defs) still pulls in every type reachable through chains three or more levels deep? A root file that selectively imports from a downstream file should give me a complete schema, all transitively required types present no matter how deep they're defined, and it needs to handle the mixed import styles (specific named types at some levels, wildcard-all at others) correctly across the full chain. Basically all seven types should land in the final resolved schema.
