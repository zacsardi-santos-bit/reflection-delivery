I'm on the Site Kit plugin and we've got a blind spot: the dashboard has zero awareness of whether someone's actually online. If connectivity drops mid-session nothing happens, features just silently fail and the user's staring at a broken screen with no clue it's their network and not us. I want to fix that.

First I need a hook that watches the connection. It should read the browser's own online status but also verify it against our server health-check endpoint, since navigator being "online" doesn't mean the server's reachable. It needs to poll on an interval, tighter when we're offline (every 15 seconds) and relaxed when we're online (every 2 minutes), and it should also react right away to the browser's online and offline events instead of waiting for the next poll. When the health-check confirms we're online it writes that into the shared application data store (core/ui area), and when we're offline it updates the store immediately too.

Then a notification component that reads that online/offline state out of the store and shows a banner saying they're currently offline and some features may not be available. When connectivity comes back the banner should vanish on its own, no manual dismiss needed for that transition.

On the store side I need an action that sets the online/offline status, a matching selector that retrieves it, and the state should default to online (true). Whatever internal state key the action writes under has to be the exact same key the selector reads from, otherwise this silently breaks. Also there's an existing selector in the connection-state store that's misnamed, it's named as if it returns a "hook" but it actually returns a count, so rename it to reflect the count it returns.
