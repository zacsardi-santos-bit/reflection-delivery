I'm using this Rust schema generation library and untagged enums keep bugging me. Whenever I have an enum with the untagged representation, the generated schema auto-inserts each variant's Rust name as a title inside every variant's subschema in the "anyOf" array, and it does this unconditionally. Those variant names are internal Rust identifiers, they don't mean anything useful to schema consumers, and they just clutter things up for validators, doc generators, and API clients that never asked for them.

What I want is for variant titles to be omitted by default so the schema comes out clean with no automatically-injected names in the anyOf entries. But I don't want to remove the capability entirely, since some teams actually want those titles for human-readable docs or display tooling. So can you add an explicit opt-in on the schema generation settings/config that turns them back on? When that setting is enabled, every entry in the "anyOf" array should have a string title equal to the variant's name, same as the old behaviour.

Oh and this needs to work the same everywhere, not just for fully untagged enums. If I've got untagged variants mixed into an otherwise-tagged enum (adjacently, externally, or internally tagged), the clean default should still apply, and flipping the opt-in on should still add the variant-name titles across all those cases consistently. Basically the default is quiet, the opt-in is loud, and it behaves identically regardless of the tagging strategy in play.
