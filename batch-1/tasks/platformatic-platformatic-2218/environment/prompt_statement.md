I'm working on the Platformatic code generators and I keep hitting a real problem, every time someone runs the generator on an existing project directory (say to add a new plugin) it regenerates every file from scratch, so routes, custom plugins, and anything else the developer wrote all get clobbered. I want an update mode that only writes back the project configuration file and skips generating everything else, no routes, no env files, no package manifests, just the config.

The way I want this wired up is an update mode option that lives in the generator's standard configuration object alongside the existing config fields, and it defaults to disabled (false). When it's on, calling the generation step should produce only the project config file and nothing else.

I also need a way to load existing project data from a directory on disk. Given a service name and a runtime directory, it should read the service's existing configuration, figure out the template type, and reconstruct the plugin option data from the current environment variable values.

On the utility side I need three new helpers, one that parses an env var file string into a plain key-value object (skipping comments and empty lines), one that flattens a nested options object into a flat structure using dot-notation paths, and one that extracts the framework template name from a schema URL. Oh and there's an existing utility that formats an object of env vars into a string, right now it uses a hardcoded newline, I want it switched to the OS-native line ending so it behaves correctly across platforms.

The point of all this is that developers building and maintaining Platformatic apps need to iteratively refine their projects, adding or updating plugins through the generator, without losing custom code they've already written. Without update mode the generator is just a one-time bootstrapper instead of something you can keep coming back to.
