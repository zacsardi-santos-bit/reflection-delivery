I'm building out the ioctl CLI for IoTeX and there's a gap around reward visibility. Right now there's no clean way for a node operator or delegate to check the reward pool status or see how much they've got sitting in unclaimed rewards, and I don't want people hand-rolling raw API queries against the rewarding protocol just to see a balance.

So I want a new node reward command that works two ways. When it's run with no args it should show the overall pool by querying the rewarding protocol for both the available balance and the total balance and printing those out. When someone passes an account address or an alias as the argument, it should resolve that to a canonical address first and then query and show the unclaimed rewards for that specific account. Basically pool view by default, per-delegate view when you give it something to look up.

It needs to hook into the existing ioctl client infrastructure and go through the API service client for the on-chain state queries, don't invent a parallel path. Oh and while I'm here, the client interface itself is missing a way to turn an address input into a canonical address, so I want to extend it with a method that takes either a direct address or a configured alias and hands back the resolved canonical address string. That resolver is what the new command leans on so it can accept either form of input, and it's generally useful for other commands too.
