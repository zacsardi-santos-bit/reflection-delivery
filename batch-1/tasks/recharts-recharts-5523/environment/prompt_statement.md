I'm hitting a weird recharts bug where hovering over a chart activates the wrong data point and the tooltip shows the wrong info, but only when the chart isn't at the very top of the page. Like if the page has been scrolled, or the chart lives inside some container that has a vertical offset, everything's off. It works fine when the chart is right at the top, so I'm pretty sure it's a coordinate problem.

Digging in, it looks like the code that turns a raw mouse event position into a chart-relative position is just using the raw position straight from the event without accounting for where the chart element itself actually sits on the page. So the offset never gets subtracted, and the internal coordinate that decides which data point is active ends up pointing at the wrong one.

What I want is for the coordinate calc to properly subtract the chart element's own vertical offset (its distance from the top of the page) from the raw mouse position instead of using the raw value directly. And really both axes should be corrected, so the element's horizontal and vertical offset within the page layout both need to be available where that calculation happens. Then when I hover over a data point in a chart that's offset on the page, the right one becomes active.

This matters a lot btw, charts sitting lower on a page or inside scrolled containers are super common, and right now any of them consistently highlight the wrong point on hover, so tooltips are basically unreliable for a big chunk of real-world usage. Just fix the mapping so hover works regardless of where the chart lands on the page.
