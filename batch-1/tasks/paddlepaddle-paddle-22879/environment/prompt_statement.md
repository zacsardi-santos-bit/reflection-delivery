I'm doing a bunch of eager execution work with dynamic graph tensors and the indexing is really letting me down. Plain integer indexing works fine, but the moment I reach for anything fancier it either blows up or gives me wrong numbers. I want indexing and slicing in dynamic graph mode to match standard numerical array semantics exactly, so I don't have to keep converting tensors back to plain arrays just to slice them, which totally kills the flow when I'm experimenting.

Concretely, indexing with a single integer should reduce that dimension and give back the right shape, and full-range slices on one or more dimensions should preserve the shape. Negative indices need to select from the end properly, and scalar indexing across all dimensions should hand me back a 1-element 1D tensor. Slices with negative stops should clip to the right elements, and negative step values (reversing along a dimension) have to work both on a single dimension and when I combine reversals across multiple dimensions at once. Mixed integer and range indices should correctly reduce or preserve each dimension as appropriate. Oh and out-of-bounds stop values in a range shouldn't error out, they should just clip to the actual dimension size gracefully.

The key thing is every one of these operations, integer dim-reduction, full slices, negative indices, negative stops, reverse steps with step -1 across all dims, and all the mixed multi-dimensional combos, needs to be numerically identical to what you'd get running the same indexing on the equivalent standard array holding the same data. That equality has to hold after a reshape too, so slicing keeps working correctly on reshaped tensors. Basically I want the full range of Pythonic array-compatible indexing patterns to just work in dynamic graph mode.
