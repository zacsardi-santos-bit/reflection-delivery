I'm building out KHI and need a fresh package that gives us one consistent way to represent and walk structured data as a typed node tree. Right now there's no shared model, so a YAML document, a JSON document, and some arbitrary Go value each need their own bespoke handling, and I want to collapse that into a single traversal API that downstream config and payload processing can lean on.

Here's what I'm after. The package converts both YAML/JSON text and arbitrary Go runtime values (scalars, slices, maps) into a tree of typed nodes. Each node carries a type indicator distinguishing scalar, sequence (ordered list), or map (key-value pairs), and lets you read its scalar value or iterate over its children. When you iterate children, each entry should carry a positional index, and for maps also the string key. I want map keys orderable alphabetically so traversal is deterministic, so give me a helper that sorts keys that way alongside the function that turns an arbitrary Go value into the node tree.

Scalar nodes expose their underlying Go value, and I need the type mapping to be right when parsing from YAML: null becomes a nil value, booleans stay booleans, strings stay strings, integers stay integers, floats stay floats, and timestamps become time values. Both YAML and JSON should go through the same parsing function since YAML is a superset of JSON, so one parse entry point handles both formats.

Oh and I also want a small utility for building dotted path strings that escapes any dots appearing inside an individual key segment, so there's no ambiguity between the path separator and a literal dot living in a key name. Basically the whole point is that code touching multiple sources (YAML configs, JSON payloads, in-memory Go values) can use one predictable inspect-and-traverse API instead of format-specific logic.
