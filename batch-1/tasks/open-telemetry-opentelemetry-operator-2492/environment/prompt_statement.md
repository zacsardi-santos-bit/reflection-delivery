I'm hitting a security context bug in the OpenTelemetry Operator around the Target Allocator component. When I set security settings in the Target Allocator spec, those settings end up getting applied to the whole pod instead of just the Target Allocator container, which is wrong. The security context for the Target Allocator should be a container-level thing so it only affects that one container, not every container in the pod.

The other problem with the current pod-level behavior is that it can't support container-specific security properties. Stuff like running as non-root, privileged mode, controlling allowPrivilegeEscalation, and setting user/group IDs (runAsUser, runAsGroup) are container security context properties, so when the config gets shoved onto the pod they either get ignored or don't behave right. I want those respected by the Target Allocator container.

So basically the fix is to apply the Target Allocator's security config as a container security context on the Target Allocator container, and stop forcibly deriving a pod-level security context from that same Target Allocator configuration. The pod shouldn't inherit those settings anymore. Anyone relying on container-level security isolation for the Target Allocator isn't actually getting it today, so I want the operator to put the right kind of security context in the right place.
