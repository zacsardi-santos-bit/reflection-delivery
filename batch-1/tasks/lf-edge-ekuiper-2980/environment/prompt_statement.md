I'm working on adding WebSocket server-side support to the ekuiper stream processing engine. Right now there's no way for external clients to push data into the engine over a WebSocket connection — the engine can't act as a WebSocket server endpoint. I need to implement a WebSocket source that allows the engine to listen for incoming client connections on a configurable endpoint, receive messages from those clients, and route the raw payloads into the processing pipeline.

The implementation should include a global server manager that can be initialized with an IP and port, individual endpoint registration and unregistration at runtime, and proper cleanup when clients disconnect (including removing closed connections from internal tracking). On top of that, a source abstraction is needed that follows the standard lifecycle — configuration with validation (an empty endpoint path should be rejected), connection setup, subscription with a data callback, and clean shutdown. A connection factory function should also be provided so this WebSocket source can be registered with the engine's broader connection management infrastructure.
