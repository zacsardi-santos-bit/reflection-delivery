I'm working with the Matrix event system in ruma and I've run into a limitation with how event content types are declared. Some event types are naturally valid as both global account data and room account data at the same time, but right now I can only pick one category per content struct declaration. This forces me to either duplicate code or find awkward workarounds.

I'd like the event content derive macro to support specifying two compatible categories at once using a combined syntax, so that a single struct declaration automatically generates all the necessary trait implementations and named event wrappers for both categories. The combined declaration should also work with the event enum macro, so that including the same event type in both the global and room account data enum blocks correctly produces properly typed enum variants for each.

I also want the system to be safe: if someone tries to combine incompatible categories (like a message-like event with an account data event), it should fail at compile time with a clear error message rather than silently generating incorrect or incomplete code. The only valid two-kind combination should be global account data paired with room account data.
