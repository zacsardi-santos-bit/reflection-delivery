I'm cleaning up the CLI tool that manages cloud Logic Functions and there are a few things tangled together that I want fixed in one pass. First, the capitalization is all over the place. "Logic Functions" is a proper product name but throughout the user-facing text (command help descriptions, error messages, interactive prompts) it keeps showing up lowercased as "logic function" or "logic functions". I want it treated as a proper noun everywhere the user sees it, so "Logic Function" and "Logic Functions" consistently. That includes the error strings that come out of listing, finding, executing, and deploying, all of those should read with the capitalized form.

Second thing, when we run or deploy a Logic Function the tool right now just prints a static status line to stdout right before the operation kicks off, and it looks like a dead log line. I'd rather show an animated busy spinner that stays spinning while the work is happening so it's obvious something's actually going on. The UI object already has a method for exactly this, it takes a display message plus a promise and resolves the promise while the animation runs, so use that instead of the plain print.

Third, there's an actual bug on deploy. The cloud API changed and now it wraps the function's metadata (its ID and version) inside a nested field in the response body, but our client code still reads ID and version straight off the top level of the response, so after a deploy the function's ID and version come back wrong or missing. Fix it to read from the nested wrapper so we correctly capture the ID and version for follow-up operations. Btw all three of these should land together.
