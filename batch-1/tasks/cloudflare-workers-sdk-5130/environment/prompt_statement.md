I'm working on a monorepo that uses a changeset-based release process. When packages are released, public packages get published to the registry automatically, but we also have private packages (like internal Workers and Pages projects) that need to be deployed separately. Right now these each have their own CI workflow, which is a maintenance burden.

I want to create a new tool that runs as part of the release CI step and handles deploying these private packages automatically. The tool should read the list of recently published packages from an environment variable, validate the input format (and throw clear errors if it's malformed), then figure out which packages are private and have a deploy script by scanning the monorepo, and deploy only those. For packages that were already handled via the public registry, it should log that they were skipped. If any individual deployment fails, it should log an error and continue with the rest rather than crashing. At the end, it should print a summary of how many packages were deployed, or a message indicating there was nothing to deploy.
