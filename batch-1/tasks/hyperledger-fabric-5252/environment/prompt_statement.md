I'm extending the channel participation REST API in the ordering service and there's a gap I keep bumping into. Right now you can join a channel from a config block, list channels, or remove one, but there's literally no way to push a config update to an already-active channel through this API. Operators who need to add or remove orderer nodes or tweak policies have no supported path, so I want to add a channel update operation.

The way I'm picturing it, the update takes a configuration update envelope submitted as multipart form data via a PUT to the channels base URL. Before it goes anywhere near the channel manager, validate that the envelope really is a config update type and carries a valid (non-empty) channel ID, and if that check fails return a 400 with a descriptive message explaining what's wrong. The channel manager interface needs a matching update method too, something that takes a channel ID plus the envelope and hands back channel info on success.

For errors: 405 when the channel doesn't exist, 403 when the orderer's a follower on that channel and not yet active, and 409 when the channel's pending removal. Also the usual 400 cases, bad request body, wrong content type, missing form fields, too many form parts, oversized body, all should come back 400 with descriptive messages. Oh and don't forget to update the allowed-methods list advertised in the method-not-allowed responses for the channels base URL so it includes this new PUT alongside the existing ones.
