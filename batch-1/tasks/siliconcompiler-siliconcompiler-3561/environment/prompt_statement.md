I'm cleaning up how tools get handled in SiliconCompiler. Right now finding an executable, checking its version, building env vars, and assembling a command line are all scattered around and hard for tool implementations to reuse, so I want one class that consolidates all of it and is exported from the main package as part of the public API.

The idea is you bind an instance to a running chip context and it validates that a flow, step, and index are all configured, raising clear errors if any of those aren't set. Once bound it should locate the executable on the system (raising a specific not-found error when it can't), run the tool to check its version and compare the result against configured version specifiers using standard specifier syntax including equality, ranges, compound specifiers, and multiple acceptable sets, then assemble the runtime environment variables pulling from global vars, tool-level license server vars, and task-level overrides, with optional PATH management, and finally build the full command list for execution.

The base class needs default stubs for the bits tool implementors override: parsing the version string out of subprocess output should raise a not-implemented error by default, normalizing a version string should be identity by default, and the hook for extra runtime options should return an empty list by default.

Keep runtime state (the logger, schema references, step/index/task context) cleanly separated from configuration state, and make deep-copying the object reset that runtime state while preserving config.

Oh and separately, a bunch of tool-level config params (executable name, path, version specifier, format, vendor, license servers, etc.) are currently job-scoped but they really belong to the tool itself not any particular run, so promote those to global scope and bump the schema version to reflect the change.
