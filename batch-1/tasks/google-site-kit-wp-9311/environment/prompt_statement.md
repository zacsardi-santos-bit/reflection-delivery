I'm reworking the audience segmentation feature in our analytics module and the settings model is wrong for what we need. Right now we just track a boolean for whether segmentation setup is complete, but that can't tell us who did it, so we can't distinguish "nobody set this up yet" from "some other admin set it up but not me." I want to swap that true/false completion flag for a field that stores the user ID of whoever finished the setup, defaulting to a null/not-set value when no setup has happened yet, so null means untouched and any ID means that person configured it. This needs to change in both the JavaScript datastore and the PHP settings layer, both using the new field name and the new data format (ID or null instead of a bool).

On top of that I need a new intro notification component that shows up on the main dashboard, but only for users who have dashboard access and didn't personally do the setup. It should welcome them and tell them they can now compare site visitor groups, and give them a button that scrolls straight to the audience segmentation section of the dashboard. The moment they interact with it, it dismisses permanently so it stops nagging them, and if they've already dismissed it before, the component just renders nothing at all. The whole point here is feature discovery, when one admin turns this on the others don't realize it's live, so we surface it to them without bugging the person who already set it up.
