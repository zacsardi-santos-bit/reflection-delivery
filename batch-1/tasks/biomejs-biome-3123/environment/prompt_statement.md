I want to add a new nursery lint rule to Biome's JavaScript analyzer that pushes people toward the modern standardized string trimming methods instead of the old deprecated aliases. Quick background: JS has two sets of trim methods, the older non-standard ones that browser vendors shipped years back (trimLeft and trimRight), and the ECMAScript-standardized equivalents (trimStart and trimEnd) which use direction-independent naming and are the recommended approach now. The aliases still work for back-compat but they're deprecated, and there's just no rule in nursery to catch them yet.

So the rule should fire on zero-argument method calls that use the deprecated names, on any receiver, whether it's dot notation or bracket notation (single-quoted, double-quoted, or template literal string keys all count). The diagnostic should say something like the deprecated name is an alias for the standard one, and it should offer a safe automated fix that renames the method to its standardized equivalent while keeping everything else exactly as written, including any inline comments sitting between the property access and the argument list. trimLeft maps to trimStart, trimRight maps to trimEnd, both need covering.

Also it's gotta not flag the wrong stuff. Don't touch it when the deprecated name shows up as a standalone function with no receiver, or as the object part of a chain rather than the method actually being called, or when it's passed as an argument to another function, or inside a constructor (new) expression, or in a computed bracket expression that uses a variable identifier instead of a string literal, or in any call that has extra arguments. And bracket notation that already uses the correct standardized names shouldn't get flagged either. btw this matters because deprecated aliases make code inconsistent and could break as runtimes eventually drop them, and a safe fix means folks can modernize without manual search-and-replace, which is why the comment-preservation edge case is important to get right.
