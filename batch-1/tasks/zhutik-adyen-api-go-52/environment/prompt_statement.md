I'm extending an Adyen payment library we've got in Go, and right now it only knows how to do the classic Payment Authorization flow. I need to bolt on support for the newer Checkout API, specifically the endpoint that retrieves the available payment methods for a merchant so we can present relevant options to shoppers. Today there's no way to do this through the library, so anyone building a modern checkout flow has to hand-roll their own HTTP calls and response parsing, which is exactly the kind of duplicated effort I want to avoid.

What I want is a way to query available payment methods and deserialize the response cleanly. That response can include regular payment methods (credit cards, iDEAL with a selectable bank list, SEPA, Klarna, and so on) each with its type, display name, and whatever input fields it needs, oh and it also carries stored one-click payment methods with their saved card details, meaning expiry month, expiry year, cardholder name, and the card number (last four). The types need to map all these nested structures correctly from the API's JSON, including nested details, the selectable items like the iDEAL bank selection list, and optional fields that might not always be present.

I also need the environment config to learn about the Checkout API endpoint URL. For the test environment it should point at the Adyen checkout test host, and for production it should build the URL using the live endpoint prefix and company name that the other production URLs already use. So basically add the types, a gateway to reach the payment methods endpoint, and the environment URL support so this endpoint is actually accessible through the library.
