Header names are case-insensitive per spec so lowercase is fine normally, but these non-standard servers/middleware expect the usual title case where the first letter of each hyphen-separated word is capitalized, like "X-Custom-Header" instead of "x-custom-header". I want to opt into that at the wire level, per client, without touching the default for anyone else so existing code keeps sending lowercase.

Can you add a builder option on the client builder that turns this on? It should be chainable with the other builder settings the way the rest of them are, and when it's set the title case conversion needs to apply consistently across all header names in the outgoing request, not just somewhere in the encoding layer but on the actual connections we open. So the flag has to thread through from the builder down into wherever we set up and drive the HTTP/1.1 connection so the headers get rewritten as they go out on the wire.

Default stays lowercase (title case off), so nobody who doesn't opt in sees any change. When enabled it should hit every outgoing header, not just the first one or a subset.
