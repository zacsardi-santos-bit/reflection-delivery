I'm poking at transaction rejection classification in the CKB node and found something off. When a script running in the VM blows up because it got handed arguments that are too large, that's a deterministic failure, the tx fails identically no matter the chain state, so it's permanently invalid and can never become valid without changing the tx itself. Problem is our code special-cases this argv-too-long error and refuses to classify it as a malformed transaction. That's wrong. It means we don't penalize peers who relay these permanently invalid txs, and the node might keep trying to re-accept something that can never succeed.

I want to rip out that special exception so every script-level verification failure, including the oversized argument case, gets treated as malformed consistently, since script failures are inherently tied to the transaction's own data anyway. There's also an old test assertion floating around that verified the broken behavior (it asserts this error is NOT a malformed transaction) and it directly conflicts with the corrected logic, so that needs to go too. Oh and while you're in there, clean up any constants or imports that only existed to support the old special-casing, since they'll be dead once the exception is gone.

The why here is simple: correctly flagging malformed txs lets the network punish peers propagating garbage and saves us from re-validating stuff that'll never pass. The previous special-casing of argv-too-long was just inconsistent with how we handle every other deterministic script failure.
