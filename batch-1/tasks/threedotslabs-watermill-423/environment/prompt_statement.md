I'm working with the watermill Go messaging library and I keep hitting duplicate processing because the same logical message shows up more than once thanks to at-least-once delivery and network retries, so I want to add a deduplication middleware into the existing `github.com/ThreeDotsLabs/watermill/message/router/middleware` package alongside retry, poison queue, throttle and the rest. The idea is to silently drop duplicates within a sliding time window so my handler never even sees them.

What I need is a `Deduplicator` type with `KeyFactory` (a `MessageHasher`), a `Repository` (an `ExpiringKeyRepository`), and a `Timeout` field. It should work two ways: a `Middleware(h HandlerFunc) HandlerFunc` method that intercepts before the handler (if the hash was already seen inside the window, drop it silently and don't call the inner handler, otherwise pass it through), and a `PublisherDecorator() message.PublisherDecorator` method giving the same dedup behavior on the publish side.

The dedup key comes from a pluggable hashing function, and I want at least two built-ins off the payload: `NewMessageHasherAdler32(readLimit int64)` for a fast checksum and `NewMessageHasherSHA256(readLimit int64)` for a slower collision-resistant one. Both take a configurable read-limit capping payload bytes read, but they need to enforce a floor, `MessageHasherReadLimitMinimum = 64` bytes, so passing something lower (like zero) silently uses 64 instead of producing junk. Also a third constructor `NewMessageHasherFromMetadataField(field string)` that just pulls a pre-computed hash from a named metadata field rather than hashing, and it should return an error when that field is absent.

Oh and I need a default in-memory store, `NewMapExpiringKeyRepository(window time.Duration)`, that's thread-safe, auto-purges expired keys once the window elapses, and exposes a `Len() int` so I can inspect how many keys are currently tracked (handy for testing and monitoring).
