I'm poking at the wasmtime component macro's code generator, specifically the part that emits async host function bindings, and I want to change how the generated closures look. Right now when the generator spits out the closure passed to each async function registration call, the closure body is just the boxed async future returned directly with no wrapping block around it. That's biting me because in some configurations Rust's borrow checker gets confused, there's no clear block boundary to delimit the async region, so when the future captures references that span an await point the compiler may not delimit things properly and it can fail under stricter lifetime analysis or configs that expose type-inference differences between block-expression and expression-body closures.

So what I want is for the generator to always wrap the closure body in an explicit block expression, with the boxed async future sitting as the last (and only) expression inside that block instead of being the naked return value. This needs to apply consistently across every async function wrapper for all WIT interface types, integers, floats, chars, strings, lists, flags, records, variants, resources, and whatever else, and it has to cover both the zero-argument closures and the ones taking one or more typed args. Oh and since we're adding a block, the code inside needs one extra level of indentation to match the new structure. The expanded snapshot files the macro tests diff against all need updating to reflect this new block-expression style too.
