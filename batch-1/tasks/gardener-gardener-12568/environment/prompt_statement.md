I'm wiring an OpenTelemetry Collector into Gardener's seed cluster logging pipeline and need it to act as an intermediary between node log agents and the log store (Vali). Right now the node-level agents push logs directly to Vali over a secured endpoint, but when the collector feature is enabled I want the traffic routed through the collector instead. So the network ingress rules and RBAC/access control policies that log agents rely on need to switch targets based on the feature toggle: when it's disabled they keep pointing at the log store directly using the existing path and service, and when it's enabled they point at the collector service using the Loki-compatible push path.

Part of this is moving the authentication proxy sidecar off the log store component and onto the collector, since the collector should own and manage its own secure endpoint now. The collector component needs a dedicated method to toggle that auth proxy sidecar on or off. By default it deploys with no auth proxy, and only adds one when explicitly configured. When the sidecar is enabled it should run with a read-only non-root security context, expose port 8080, and mount a projected kubeconfig volume for shoot authentication. Meanwhile the log store component should stop activating its own auth proxy when the logging botanist runs, since that's the collector's job now.

Also the collector constructor currently takes a plain endpoint string, I want it to accept a secrets manager instead so it can do credential retrieval properly. And I need a mock of the new collector interface generated for tests.

Oh and two reusable utility functions in the gardener utilities package (`@pkg/utils/gardener`-ish): one that builds a standard projected kubeconfig volume combining a generic token kubeconfig secret plus an access token secret, and one that builds a read-only volume mount for that volume, so any component authenticating against shoot clusters gets consistent volume definitions.
