So I'm deep in the SIMD side of our vector similarity library and I want to add AVX-512 versions of our two core kernels. Right now we've got dot product and L2 squared distance accelerated with the older, narrower vector extensions (think AVX2-ish, 256-bit lanes), but modern server CPUs almost always ship with the wider 512-bit instruction set that chews through more elements per cycle, and we're just leaving that throughput on the floor. As embedding dims keep growing (384, 768, 1024, 1536 are all common now) the distance math is turning into a real bottleneck in our ANN search, so this matters for query throughput.

What I need is two new functions in the assembly-optimized package, one computing dot product and one computing L2 squared distance, both written against the 512-bit wide instruction set. They've gotta come out numerically correct, within a small float tolerance, across the whole spread of vector sizes we see in practice: from tiny stuff like 1 through 6 elements all the way up to 1024 and 1536, and I especially care about the ugly non-power-of-two lengths that trip up tail handling, so make sure things like 31, 67, 260, 299, 390, 777, and 784 all come back accurate too (basically anything not a multiple of 16 or 32 needs proper remainder handling).

Oh and these should only ever get called when the CPU actually reports support for the wider instruction set, so keep the older hardware path intact and don't invoke the new ones unless the feature detection says it's safe.
