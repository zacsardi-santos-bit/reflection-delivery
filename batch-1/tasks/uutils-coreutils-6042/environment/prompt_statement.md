I'm hacking on the recursive group-change utility in uutils/coreutils (chgrp, the `--recursive` with root protection path) and the root guard is bugging me on two fronts.

First off the error message is always generic. No matter how someone spelled the path, whether it's a symlink pointing at root, a path with a bunch of redundant slashes, or some `../..` traversal thing that lands on root, the diagnostic just claims it's dangerous to operate recursively on `/`. That throws away the path they actually typed. What I want: when the argument really is the literal root, keep saying it's dangerous to operate recursively on root directory `/` like before, but when it's some other path that just happens to resolve to root, the message should echo back the original path the user gave and then note that it's the same as `/`. So the user can see what they typed that set off the guard.

Second, some relative forms that obviously point at root aren't getting caught. If the current working directory is already `/`, then passing `.` or `..` should trip the protection too, and right now those slip right through which kinda defeats the whole safety check. Oh and the flip side matters: sequences of dots that just look like navigation shorthands but aren't real ones (think `...`, a normal filename) shouldn't get falsely flagged as root, they should just produce the ordinary not-found error instead.

The relevant logic lives around the root-check handling in the chgrp source under `@src/uu/chgrp/src/chgrp.rs` (and the shared traversal bits in `@src/uucore` if it comes to that). Basically I need the protection to correctly recognize `.` and `..` as root when cwd is root, distinguish those from lookalike dot-filenames, and produce the path-aware error wording described above.
