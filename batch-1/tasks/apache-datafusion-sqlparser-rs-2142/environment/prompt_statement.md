I'm working with a SQL parser library and I've noticed it doesn't handle the PostgreSQL-style syntax for setting a user's password in an alter-user statement. When I try to parse something like altering a user and specifying a password — whether as a string, as null (to clear it), or with an "encrypted" marker — the parser fails. I'd also expect it to handle an optional leading qualifier keyword before the password clause and normalize it away in the output. These are all standard and valid SQL patterns for user management in PostgreSQL-compatible systems, and without support for them I can't use the library for round-trip parsing of user management SQL.
