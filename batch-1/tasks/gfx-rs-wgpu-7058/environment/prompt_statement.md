I'm hitting a bug in the shader compiler around texture load operations, specifically the mip level argument. Right now it only accepts signed integers for the level when you're loading from a mipmapped texture, but per the shading language spec both signed and unsigned integers are valid there. So when I write a shader that samples a mipmapped texture and passes an unsigned integer value for the mip level, the compiler either rejects the shader outright or spits out incorrect output for the target backends. That's wrong, and it's annoying because forcing signed ints makes some shader patterns awkward or impossible to express even though they're totally legal.

What I want is for the compiler to accept an unsigned integer mip level in a texture load without complaining, and then correctly translate that shader across all the supported output formats, so GLSL, HLSL, MSL, WGSL, and SPIR-V. The catch is each backend has its own conventions for how it expects the level index, so each one needs to apply the appropriate type conversion for the unsigned value rather than just assuming it's signed. btw signed levels should keep working exactly like before, this is just about also handling the unsigned case correctly per-backend. Basically shader authors should be able to use signed and unsigned integer types interchangeably for mip levels since the spec doesn't restrict it to signed only.
