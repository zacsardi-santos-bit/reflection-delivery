I'm working on the Datadog metric provider in Argo Rollouts and the credential resolution is too rigid for multi-tenant clusters. Right now when we run analysis templates the Datadog API creds only ever come from the controller's own namespace, either env vars on the controller process or a single global secret sitting in the namespace where the controller is deployed. That doesn't work when different teams manage their own Datadog credentials and don't have access to the controller namespace, they shouldn't need a cluster admin to touch a shared secret for them.

What I want is for an analysis template to be able to point at a named secret in its own namespace. So there should be a namespaced flag on the secret reference, and when that's enabled the lookup should go find that specific secret in the template's namespace instead of the controller's. If the namespaced option is set but no secret name is actually provided, I want it to fail early with an error rather than silently falling back to something else. And if the referenced secret can't be found at all, same thing, fail with an error instead of falling through to the other sources.

To make this clean I think the credential lookup needs a refactor so it supports multiple strategies that get tried in order, the namespace-specific secret, then environment variables, then the default global secret. Each strategy should just return empty values gracefully when it doesn't have creds so the next one can take over, except the namespaced case which errors as described above. Oh and the Datadog provider constructor plus the analysis controller's provider factory both need to accept the analysis namespace now so it can be threaded through to the resolution logic. The relevant code lives around the Datadog provider in `@metricproviders/datadog` and the provider factory in the analysis controller.
