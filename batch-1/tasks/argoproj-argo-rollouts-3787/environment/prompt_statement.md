I'm working on Argo Rollouts and want to improve how Datadog credentials are resolved when running analysis templates. Right now, the credentials always come from the controller's own namespace — either environment variables or a global secret stored there. This is a problem in multi-tenant setups where each team has their own Datadog API credentials and shouldn't need a cluster admin to update a shared secret.

I'd like to support a way for an analysis template to reference a named secret from its own namespace for Datadog credentials. When this option is enabled, the system should look up credentials from that specific secret in the analysis namespace instead of the controller's namespace. If the secret name is missing but the namespaced option is set, it should fail early with an error. If the secret isn't found at all, it should also fail rather than falling through to other sources.

This also means the credential lookup needs to be refactored to support multiple strategies — namespace-specific secrets, environment variables, and the default global secret — so that each strategy can be tried in order. The Datadog provider constructor and the analysis controller's provider factory both need to accept the analysis namespace so it can be passed through to the credential resolution logic.
