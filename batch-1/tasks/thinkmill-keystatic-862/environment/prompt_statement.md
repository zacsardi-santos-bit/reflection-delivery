I'm building a visual editor for MDX-based content collections, and I need two-way conversion between the editor's internal document representation and the MDX file format. Right now there's no way to take what the author has written in the editor and produce a valid MDX file, and there's no way to read an existing MDX file and display it in the editor.

I need a serializer that converts the editor's internal document structure to an MDX-compatible abstract syntax tree (which can then be turned into a string), and a parser that goes the other direction — reading an MDX syntax tree and producing the editor's internal document nodes.

Both directions need to handle all the common content types: paragraphs, headings with different levels, ordered and unordered lists (including nested lists and empty list items), inline text formatting like bold and code, combined formatting marks applied together (such as bold and code on the same text), links (including links that wrap formatted text like inline code), and fenced code blocks that may carry both a language identifier and additional meta text on the opening line.

For parsing, links should always produce a mark that includes both a URL and a title — the title should default to an empty string when none is present in the source. Code blocks with a language identifier and meta text on the fence line should store the combined string as a single language attribute. Headings and code blocks, when parsed, should carry their schema-defined default attributes so the resulting editor nodes are fully valid according to the schema.
