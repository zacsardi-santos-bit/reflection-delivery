I'm hitting a weird dedup bug in the AWS Load Balancer Controller around how it builds TLS certificate lists for an ALB listener. I've got an internet-facing ingress with several certs in the annotation, and the first one in the list is the default cert. The thing is, that same cert ARN also shows up again later in the list, so I want it registered as an SNI cert too, on top of being the default. Right now the controller silently dedupes the cert list and drops any ARN it's already seen, including the default one, so the second occurrence just vanishes. The listener ends up with fewer certs than I asked for.

What I want is for the default certificate to not block that same ARN from also landing in the SNI cert list when it's explicitly listed there. AWS ALB is fine with a cert serving as both the default and an SNI entry, so the controller should honor that instead of suppressing it. This also matters for IngressGroups where one member sets a cert as default and another member contributes the same cert, both roles should survive into the final listener config.

Oh and while you're in there, any completely empty entries in the comma-separated cert list (the usual trailing comma or double comma typos) should just get filtered out silently, no errors, they just shouldn't show up in the final listener configuration. So to be clear, if the same cert ARN appears as the first default cert and again later in the annotation, I need both preserved, one as default and one as SNI. The cert merging logic lives around the listener building code in the ingress model builder under `@pkg/ingress`, that's where the dedup that's eating the duplicate needs fixing.
