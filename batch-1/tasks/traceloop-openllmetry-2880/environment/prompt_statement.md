I'm working on the AlephAlpha OpenTelemetry instrumentation and I've got a gap I need to close. Right now all the LLM prompt and response data goes exclusively into span attributes, but the OTel ecosystem has been moving toward structured log-based events for capturing model inputs and outputs following the newer semantic conventions, so I want to add that event-based path alongside the existing attribute one.

Here's what I'm after: add a flag on the instrumentor that switches between the legacy attribute-only mode and a new event-based mode. When the event mode is on, each completion should emit two structured log events, one for the user's prompt input and one for the model's response, and each event needs to carry the right semantic attributes identifying the event name and the AI system (the gen_ai system being alephalpha). The legacy attribute-based behavior has to stay the default and produce zero log events so I don't break anyone who's already depending on it, that backward compat is important.

Also the existing content-tracing toggle needs to be respected in the new mode too. When content tracing is enabled the full prompt and response content should show up in the event bodies, and when it's off the events should still fire but with empty bodies (content stripped out), don't skip emitting them. Oh and the instrument-time API needs to accept an event logger provider so these events can actually get routed into the right OTel pipeline, otherwise there's nowhere for them to go. The relevant instrumentation lives under the AlephAlpha OTel package (see `@packages/opentelemetry-instrumentation-alephalpha`), so the flag, the two-event emission, the attribute wiring, and the event logger provider plumbing all belong there. Point is teams adopting modern OTel observability want LLM libs to emit in the standardized event format so they can use event-based log pipelines for their AI workflows, and right now they can't with this instrumentation.
