I'm building out the admin side of our package index and hit a gap in how we handle sketchy projects. Right now when an admin reviews a suspicious package they've only got two moves: mark it "not malware" and leave it live, or fully remove it as malware, which is irreversible. There's no middle ground for stuff that looks off but isn't confirmed yet, so I want to add a quarantine feature that makes a project unavailable to install and blocks the owner from making changes while keeping it in the system, and importantly it needs to be reversible so we can restore the project if an investigation clears it.

Concretely I need a utility function to put a project into quarantine and another to clear it back out. The quarantine one should record who quarantined it and when. Both should take an optional flash parameter that controls whether a success notification gets shown to the admin, and when shown, the message should name the project and remind me to update any related support conversations (same reminder on both quarantine and un-quarantine). Also I want admin views so I can trigger quarantine straight from the malware reports project list view and from the malware report detail view, and reverse the quarantine from the project detail view. Wire these up as new dedicated admin routes. Oh and the quarantine actions coming from the malware reports views shouldn't auto-add any verdict actions to the observation, they should just quarantine the project and redirect back to the malware reports list with the right flash message.
