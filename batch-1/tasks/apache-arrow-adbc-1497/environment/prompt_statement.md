I'm on the Go ADBC project and need to bump the Arrow Go library from its current major version to the next major version across the whole codebase. Every Go source file that imports from the old major version import path has to point at the new one, and the module files (go.mod and friends) need to reflect the bump too so we're actually pulling the newer library everywhere. While I'm at it, the vendor arrow version that the FlightSQL driver reports should show the upgraded version, not the old one.

There's also a cookie bug in the FlightSQL driver I want fixed in the same pass. The driver has a cookie middleware option that tracks session cookies across requests, which works fine on the primary connection. The problem is when a FlightSQL server hands back a flight endpoint with a non-empty location URI, the driver opens a secondary client connection to that location, and right now the cookies from the primary connection don't get copied over to that sub-connection. So cookie-based session tracking just breaks silently whenever the server does location-based routing to send us elsewhere for data retrieval, which is super common for distributed query execution. I want the cookies cloned off the primary connection and applied to any sub-connections the driver spins up. Oh and if we already have an auth token from the primary connection, reuse it for the sub-connections instead of kicking off a fresh authentication exchange.

Staying pinned to an old major of a core dep like Arrow blocks us from bug fixes, perf improvements, and new features, so the upgrade matters, and the cookie fix matters because real servers using this routing pattern hit broken sessions today. The FlightSQL driver code lives under `@go/adbc/driver/flightsql`, so the sub-connection creation and cookie propagation logic is what needs touching there.
