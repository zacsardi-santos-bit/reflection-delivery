I'm working on the rule in ruff that checks whether pytest marker decorators use the correct parentheses style. I noticed that the rule currently uses simple name-pattern matching to identify which decorators count as pytest marks, rather than the linter's semantic import-resolution system. This means the rule could flag — or at least attempt to process — a decorator that looks like a pytest mark even when the testing library hasn't actually been imported at that point in the file.

The fix should switch the rule to use proper import resolution so that it only considers a decorator as a pytest mark when it can confirm the library is imported. As a result, a decorator placed before the import statement should be left alone entirely. I've added a test case to the fixture file to cover this scenario: a marker decorator with arguments placed before the import, which should not produce any violations under either the default configuration or the configuration that requires parentheses.

The expected-output snapshot files for the affected tests also need to be updated to reflect both the new behavior and the shifted line numbers caused by adding the new test case at the top of the fixture.
