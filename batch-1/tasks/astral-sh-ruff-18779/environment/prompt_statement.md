I'm poking at the pytest marks parentheses rule in ruff (the one that checks whether marker decorators use consistent parens style, PT023 territory over in the flake8-pytest-style area) and I hit a real accuracy problem. Right now the rule figures out which decorators count as pytest marks by doing simple name-pattern matching on the decorator, basically looking at the dotted name and going "yep that's a pytest.mark thing," instead of asking the linter's semantic model whether the library is actually imported at that point. So it'll happily process a decorator that just looks like a pytest mark even when pytest hasn't been imported yet in the file, which means false positives, and false positives make people stop trusting the linter and start sprinkling noqa comments everywhere.

What I want is to switch this over to proper import resolution so a decorator only counts as a pytest mark when we can actually confirm through the semantic import-resolution system that it resolves to pytest's mark functionality. Concretely that means if a marker decorator (even one with arguments) shows up before the import statement, we can't verify it refers to pytest's mark stuff, so we leave it completely alone, no violation under the default config and none under the config that requires parentheses either. Once the import is present later in the file, everything keeps working exactly like before, flagging markers with the wrong parens style. This also lines the rule up with how the rest of the linter handles import-qualified names, which is nice.

I've already added a test case up at the top of the fixture covering that scenario (a marker decorator with args placed before the import), so you'll want to update the affected expected-output snapshot files to reflect both the new no-violation behavior and the shifted line numbers, since adding a case at the top pushes everything down. btw the fixture and snapshots live in the flake8-pytest-style test area, so make sure the diagnostics and any autofix ranges all line up after the shift.
