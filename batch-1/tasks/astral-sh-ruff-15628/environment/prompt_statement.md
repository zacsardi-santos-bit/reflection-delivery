I've got two lint rules stepping on each other and it's driving me nuts. One rule flags imports that aren't at the module top level (the "move this to the top" warning), and another one bans specific modules from being imported at the top level because I need them loaded lazily inside functions for perf reasons. Problem is, for exactly those lazily-imported modules both rules fire on the same statement and hand me contradictory advice: one says move it up top, the other says this module isn't allowed up top. There's no way to satisfy both, so I end up suppressing one wholesale which kills the point of having them.

What I want is for the linter to notice this conflict and stay quiet. So when an import lives inside a function body, and every module or name it brings in is already on the banned-from-top-level list, the "should be at the top level" warning should just be suppressed, since moving it would only trip the other rule anyway. That suppression needs to hold no matter where the import sits, regular function, class body, or a method inside a class, all the same.

The one exception: if a single import statement pulls in a mix of banned and non-banned names, keep the warning, because at least some of those names could legitimately move up to the top level without any conflict. So it's really an all-or-nothing check on the imported names before deciding to suppress. Fixing this interaction lets me enforce both the lazy-loading requirement and top-level import hygiene together instead of picking one.
