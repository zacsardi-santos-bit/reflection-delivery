I'm working on the AWS Terraform provider and I want to add two provider-scoped functions so folks can build and take apart AWS ARNs right inside their configs instead of hacking around with string interpolation or external data sources. Right now if you need to assemble an ARN from its pieces (partition, service, region, account ID, resource) or split one back out, you're stuck doing fragile string manipulation, and I'd rather just have proper functions for it with real validation.

So the first function takes the individual components, partition, service, region, account ID, and resource path, and returns the fully assembled colon-delimited ARN string. For example passing in the partition, service, an empty region, an account ID, and a resource path should give me back the correct ARN. The second function does the reverse, it accepts a complete ARN string and hands back an object with each component broken out as its own attribute.

The parsing one also needs to validate what it gets, so when the input string doesn't conform to the expected ARN format it should fail with a clear error saying the input isn't a valid ARN (specifically that the prefix is invalid), rather than silently returning garbage.

Both of these should live in a new package at the right spot in the provider codebase (something like `@internal/function/`), and they need to be registered so they're actually callable from Terraform configurations, not just defined and orphaned.
