I'm hitting a wall with the OpenAPI connector when I try to generate a GraphQL schema from the Amadeus Hotel List API. The parser just completely ignores the response schemas and spits out nothing, no GraphQL types, no query operations, totally empty of anything useful.

Digging into it, I'm pretty sure the problem is the content type matching. Amadeus uses a vendor-specific JSON content type in its response definitions (a vendor-prefixed JSON variant, the kind you see with JSON API spec and similar travel and hospitality APIs) instead of the bare `application/json` string. The converter only matches that plain standard form exactly, so when it sees the namespaced one it silently skips the response body and treats it like there's no schema at all. That's why I get an empty schema out.

What I want is for the parser to recognize any content type that's clearly a JSON variant, basically anything whose name ends in "json" including the vendor-namespaced ones, and process the response schema from it accordingly. This unlocks a whole class of APIs (anything following JSON API conventions) that currently can't go through Grafbase's OpenAPI connector at all.

Concretely, once this works, feeding in the Amadeus hotel search OpenAPI spec should convert into a full working GraphQL schema. That means all the hotel lookup query operations should show up, plus the enum types for amenities, hotel source, and radius unit options, and the hotel data object types too. Right now none of that generates because the response bodies get dropped on the floor. Fix the content type check so JSON variants are picked up and the Amadeus spec parses end to end into something complete.
