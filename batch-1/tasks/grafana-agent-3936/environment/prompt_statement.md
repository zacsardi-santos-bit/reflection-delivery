I'm working on adding a new component to Grafana Agent that watches Kubernetes for alerting and recording rule resources and synchronizes them into a Loki ruler instance. The component needs to detect when rules are added, modified, or removed in Kubernetes and apply only the necessary changes to Loki — nothing more, nothing less.

The core reconciliation logic needs to compute a diff between the desired state from Kubernetes and the current state stored in Loki, producing a list of add, remove, or update operations per namespace. The event loop should process Kubernetes watch events and trigger this reconciliation, updating Loki accordingly. When a rule is added to Kubernetes and the event fires, it should eventually appear in Loki; when it's updated, Loki should reflect the update; when it's deleted from Kubernetes, it should be removed from Loki.

I also need an HTTP client package to communicate with the Loki ruler API. The URL building logic must correctly append paths to a base URL regardless of whether the base has a trailing slash, and it must preserve any percent-encoding already present in the path — for example, if a rule group name contains a slash or a space, those should be encoded as %2F and %20 in the request URL without being double-encoded. The client also needs instrumentation support so request durations can be tracked; the instrumentation layer should use an operation name attached to the request context, falling back to the URL path if no name is provided.

The configuration for the component should support standard authentication options (basic auth, bearer tokens, OAuth2), but must validate that only one method is configured at a time and return an appropriate error otherwise. There should also be a configurable prefix to identify which Loki rule namespaces are managed by this particular agent deployment.
