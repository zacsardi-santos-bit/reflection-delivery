I'm building a new Grafana Agent component that watches Kubernetes for alerting and recording rule resources (custom resources) and syncs them into a Loki ruler instance, because right now there's no automated way to discover rule definitions stored as k8s custom resources and push them into Loki, so people do it by hand or with separate tooling which is error-prone and a pain to maintain. Teams already define rules with k8s-native CRDs for other monitoring, so I want this to be the bridge to the Loki ruler API.

The core reconciliation needs to compute a diff between desired state (from Kubernetes) and current state (fetched from Loki), producing a list of add, remove, or update operations per namespace, and only send ops for rule groups that actually changed, nothing more nothing less. The event loop processes k8s watch events across selectable namespaces with a labeling-based filter and triggers reconciliation, so when a rule gets added it eventually shows up in Loki, when it's updated Loki reflects the update, and when it's deleted from k8s it gets removed from Loki.

I also need an HTTP client package to talk to the Loki ruler API. The URL building has to correctly append paths to a base URL whether or not the base has a trailing slash, and it must preserve any percent-encoding already in the path, so a rule group name with a slash or a space stays encoded as %2F and %20 in the request URL without getting double-encoded. Oh and the client needs instrumentation so request durations get tracked, and that layer should use an operation name attached to the request context, falling back to the URL path if no name's provided.

Config-wise it should support the standard auth options (basic auth, bearer token, OAuth2, etc.) but validate that only one method is configured at a time and return an appropriate error otherwise. Also there's a configurable namespace prefix to identify which Loki rule namespaces this particular agent deployment manages, so it doesn't step on rules owned by other deployments.
