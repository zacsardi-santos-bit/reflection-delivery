I'm poking at the vSphere API simulator in govmomi (`@simulator`) and it's not enforcing session auth at all, which is throwing off my integration tests. If I connect a client but never log in, API calls still come back successful, but a real vSphere server would kick those back with an authentication fault. I want the simulator to actually behave: unauthenticated clients hitting protected methods should get proper authentication error responses, and when an un-logged-in client tries to retrieve object properties the result shouldn't be real values, it should come back as an empty property set with authentication fault entries reflecting the missing authorization. Also a client that hasn't logged in should see no active session when it queries session state.

Once login succeeds I'd expect the session to actually track stuff, like it should record the client's user agent, and the last-active timestamp needs to get bumped as the client keeps making API calls. Oh and per-session objects like property collectors are currently shared globally which is wrong, they should be scoped to the owning session so their identifiers carry session-specific info reflecting who owns them.

Couple more lifecycle bits: trying to log in a second time while I've still got an active session should be rejected, same as the real server does. And after I log out it should be possible to log back in and have a fully working session again, including creating property collector filters and receiving update notifications like normal. The whole point is so I can write realistic tests around how client code reacts when it lacks credentials or its session expires, so the sim really needs to reproduce the actual auth and session lifecycle semantics.
