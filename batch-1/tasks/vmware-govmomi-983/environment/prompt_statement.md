I'm working with the vSphere API simulator in the govmomi library and I've noticed that it doesn't properly enforce session authentication. If I connect a client to the simulator without logging in first, API calls still succeed — but a real vSphere server would reject those calls with an authentication error. I'd like the simulator to behave correctly: unauthenticated clients should get proper authentication error responses for protected operations, and when retrieving object properties without a session the results should indicate missing authorization rather than returning values.

I'd also expect the simulator to properly track session state. After logging in, the session should record information like the client's user agent, and the session's last-active timestamp should be updated as the client makes API calls. Additionally, per-session objects like property collectors should be tied to their owning session — right now they seem to be shared globally rather than scoped per session.

Finally, trying to log in a second time while still holding an active session should fail (just like it would on a real server), and after logging out it should be possible to log in again and have a fully working session including creating filters and receiving update notifications.
