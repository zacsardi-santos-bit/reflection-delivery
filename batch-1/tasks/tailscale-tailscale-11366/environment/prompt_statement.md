I'm cleaning up the TailFS share management code and there's a bunch of related stuff I want fixed together. Right now shares get stored and returned in whatever order, so the list looks different every time it's shown, and I want them always kept in consistent alphabetical order instead. The internal representation should move from a map to a sorted slice, so the interface the file system implementation uses to receive share updates needs to accept a sorted slice rather than a map, and any code building that slice should sort it before handing it off.

I also need a rename operation because right now there's no way to rename a share, you have to delete and re-add it with a new name which is clunky and loses config. Rename should atomically rename an existing share, fail if the old name doesn't exist (a distinct not-found error), fail if the new name is already taken (a distinct already-exists error you can match on), and fail if the new name has invalid characters. Oh and share name normalization (trimming whitespace, forcing lowercase) should apply consistently across all the share management operations, rename included.

Another thing: some important error conditions like "the feature isn't enabled" and "the share name is invalid" are currently private unexported errors, so callers outside the package can't detect them. I want those exported so people can do standard errors matching against them.

Last bit, shares should live in the user's regular preferences rather than a separate state store, so the preference struct needs a shares field the preference system knows about, but it should not expose a CLI flag through the general-purpose connection command since it belongs to the dedicated share management subcommand instead. Users on a tailnet need stable ordering and rename without losing the share's setup, and devs integrating with the sharing API need to tell specific failures apart instead of treating everything as one generic error.
