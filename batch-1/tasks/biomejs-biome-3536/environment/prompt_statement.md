I'm adding a new lint rule to keep accessibility modifier usage consistent on TypeScript class members, and I want it to support three configurable modes. One mode (call it explicit) requires every class member to carry an explicit modifier, another (no-public) disallows the redundant annotation for the default public visibility, and a third (none) forbids all accessibility modifiers entirely. The default mode should be no-public since that redundant public annotation is just noise.

The rule needs to apply across all member kinds, so regular properties and methods, constructors, getters, setters, abstract members, and the constructor parameter shorthand where params are declared inline in the constructor signature and get their visibility right there. Oh and in explicit mode, even native JavaScript private fields (the `#field` syntax) should get flagged as missing an explicit modifier, since TypeScript's private keyword and the hash prefix aren't the same thing.

When a violation shows up, the diagnostic should say clearly what's wrong and how to fix it, either add a modifier or remove one depending on which mode is active. TypeScript already lets you mark members as visible within the class, to subclasses, or to everyone, but there's no enforcement so codebases drift into mixed styles, some annotating everything, some nothing, some using the redundant public marker.

Put this in the nursery lint group, and make it configurable through a JSON option key that accepts one of the three string values corresponding to explicit, no-public, and none.
