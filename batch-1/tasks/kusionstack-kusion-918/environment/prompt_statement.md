I'm building out the OCI client package in the Kusion toolchain and I need a way to turn local files or directories into compressed archives so we can eventually push them as OCI artifacts. Right now there's just no path from local project files to an OCI-ready archive and that's blocking the push/pull work, so this is the foundational piece.

What I want is a function living in the OCI client package (something like `@pkg/oci` area, wire it into whatever archive/tar helper file makes sense there) that takes a destination path and a source path and produces a gzip-compressed tar archive at the destination. The source can be either a single file or a whole directory. If it's a directory, pack up all the contents into the tar.gz at the output path I gave; if it's just one file, archive that single file. Oh and it needs to accept a list of ignore patterns that work like gitignore rules, so matching files and subdirectories get excluded, and negation patterns need to actually override the exclusion (so you can re-include something that a broader pattern would've dropped).

Path handling matters here, it should cope with relative paths, absolute paths, and paths with a leading "./" prefix, all of them. And if the source path doesn't exist at all, just return an error rather than producing a broken archive.

Also I need real fixture files under the package's testdata directory so tests have something to chew on, including a sample deployment-style YAML file plus some extra files and directories specifically there to prove the ignore patterns (and the negations) actually get applied the way I expect.
