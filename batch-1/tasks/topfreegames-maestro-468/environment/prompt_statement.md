I'm working on a background worker that watches for game room instance events from a runtime. The worker spawns many concurrent processors that read from an event channel and handle add, update, and delete events accordingly. The problem is that when the event channel is closed by the runtime — for example, because the runtime connection was dropped or the watcher was intentionally stopped — the worker just hangs forever instead of returning. I need it to detect the channel closure, let all the goroutines finish up, clean up the runtime watcher, and then return without an error. Right now it blocks on waiting for the context to cancel, even after all the goroutines have already exited due to the closed channel. The fix should not affect the existing behavior: failed initial setup should still return an error, and event processing errors should still be handled gracefully without stopping the worker.
