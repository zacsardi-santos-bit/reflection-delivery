I'm adding dynamic data source support to MOSN's flow control stream filter and could use a hand. Right now the filter over in the flow control package only knows how to read rules that are baked into the static config, so any time ops wants to tweak a rate-limiting rule they've gotta edit config and bounce the proxy, which is rough in prod. I want a pluggable data source abstraction so rules can come from an external configuration center instead, connect at startup, pull the current flow rules, and keep listening for updates without a restart. First concrete implementation should be Nacos since that's the common one, so MOSN can talk to a Nacos config store, fetch rules on boot, and subscribe to changes. The filter config also needs to let me declare one or more dynamic data resources, each described by a type plus its connection params (server address, namespace, group, data id, that kind of thing), so the abstraction can dispatch to the right source based on type.

I need that fixed everywhere it's used, both in the actual filter code and in the existing tests, so the package builds again and all the current flow control tests compile and pass.
