I'm adding user-defined resource labels to Tilt. Right now there's no way to attach custom organizational labels to a resource, whether it's Kubernetes, Docker Compose, or local, from the Tiltfile, and as projects grow people really want to group and filter services in the UI by team or tier or whatever dimension makes sense for them.

What I want is an optional labels parameter on the resource config functions (the ones for k8s_resource, dc_resource, local_resource) that accepts either a single label name as a string or a list of strings, or actually a tuple of strings too. The labels should get stored on the resource's manifest so they're available for organizational stuff like grouping in the UI. Also when the same resource gets configured more than once, labels should accumulate across those calls rather than clobber each other, so it's additive/merged.

Label names need validating: they've gotta be non-empty, alphanumeric, and must not contain slashes. If someone passes an invalid name I want a clear descriptive error explaining what's wrong. And importantly, changing a resource's labels should not trigger a rebuild since labels are just metadata and don't affect the build process at all.

Oh and I need a reusable Starlark value type that can parse and validate these label values, it should handle the single string, the list of strings, and the tuple of strings cases, and reject any unsupported input type with an appropriate error message so callers get consistent behavior.
