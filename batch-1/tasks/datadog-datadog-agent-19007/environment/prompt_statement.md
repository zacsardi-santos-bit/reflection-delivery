I'm working on adding Kubernetes Deployment support to the workload metadata store in the Datadog Agent. Right now the store can track containers, pods, and nodes, but there's no support for Deployment resources. I need to add the ability to store and retrieve Deployment entities that carry environment/service/version labels and per-container language annotations.

Specifically, I need a way to look up a stored deployment by name from the store and get a proper not-found error when it doesn't exist. The Kubernetes API collector should be extended with a deployment watcher that parses both unified service monitoring labels and language detection annotations from Deployments. Language annotations list comma-separated language names per container (with whitespace trimming), and init containers need to be tracked separately from regular containers. Deployments with no meaningful metadata — no env label and no language annotations — should be filtered out and not stored.

The set of resource types the collector watches should be configurable: deployment watching should be enabled via the language detection configuration flag, pod watching via the Kubernetes tags flag, and node watching should always be on regardless of configuration.
