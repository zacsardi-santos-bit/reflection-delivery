I'm adding Kubernetes Deployment support to the workload metadata store in the Datadog Agent and could use a hand wiring it up right. Today the store tracks containers, pods, and nodes fine, but there's just no notion of a Deployment resource, and I need one because language detection in the agent runs at the Deployment level, annotations get placed on Deployments to describe what languages their containers run, so without storing and retrieving that metadata the language detection pipeline can't propagate anything downstream. This also feeds unified service monitoring in cluster agent scenarios.

So I want Deployment to become a first-class entity in the store, carrying its environment, service, and version labels plus per-container language annotations. I need a retrieval method on the store to look up a specific deployment by its name, and it should hand back a proper not-found error when the deployment doesn't exist.

On the collection side, the Kubernetes API collector needs a deployment watcher that converts Deployments into store entities, parsing both the unified service monitoring labels (env/service/version) and the language detection annotations. Those language annotations are a comma-separated list of language names per container, and I want whitespace trimmed off each name. Also init containers need to be tracked separately from the regular containers, don't lump them together. Oh and if a deployment carries no meaningful metadata, meaning no env label and no language annotations at all, just filter it out and don't store it.

Last thing, make the watched resource set configurable: deployment watching turns on via the language detection config flag, pod watching stays gated on the existing Kubernetes tags flag, and node watching should always be on no matter what the config says.
