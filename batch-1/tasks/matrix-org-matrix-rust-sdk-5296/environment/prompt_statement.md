I'm cleaning up the paginator situation in the Matrix Rust SDK because right now the types are scattered all over the place and it's a pain. The room-level paginator stuff lives buried inside the event cache module and the logic for paginating threaded conversations is stuck inside the UI timeline module, so nothing is easy to find or reuse. I want all the paginator types consolidated into a single dedicated top-level paginator module in the core SDK crate (`@crates/matrix-sdk-base` style location) so you can just import them from one place.

While I'm at it I want a new trait specifically for thread pagination, one that has methods for fetching thread relations and for loading individual events. The thread events loader should move into that new module and become generic over this new trait instead of being tied to the timeline. On the data provider side, the generic room data provider abstraction currently has thread-relations baked right into it, oh and that conflates two separate concerns, so pull that out and make the data provider require the new thread pagination trait as a supertrait bound instead. That way anything implementing the data provider only has to implement the thread-specific trait separately, which makes testing way cleaner since a test impl only satisfies the interface it actually needs.

Also the error type used for loading pinned events with relations should just use the standard SDK error type rather than the paginator-specific error wrapper, since that wrapper was only wrapping the SDK error anyway. And the timeline test infrastructure needs updating to match, so the mock room data provider used in tests should implement the new thread pagination trait, and the relations method has to come off the general room data provider impl since it's now provided via the supertrait. The whole point is clearer, more composable trait boundaries and paginator infra that's reusable without reaching into internal or UI-specific modules.
