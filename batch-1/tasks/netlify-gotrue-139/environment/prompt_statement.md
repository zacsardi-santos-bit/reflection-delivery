I'm building out the storage layer for our auth service and I keep running into the same annoying pattern where I need to do partial updates on a database record, only persisting a few columns and leaving the rest untouched. Right now there's no clean way to say "update just these fields," so folks either hand-roll the skip logic every time or just update all columns which is wasteful and sometimes wrong.

What I want is a helper living in the storage package that inverts an include list into an exclude list. So I hand it a database-mapped model struct plus one or more column names I want to include in the update, and it hands back all the other column names, the ones I want to skip, so I can pass those as excluded columns to the underlying db operation. The column names come from the struct's `db` tag annotations, so it needs to walk the struct's fields and read those tags to know the full set of columns.

Oh and error handling matters here. If I pass in a column name that doesn't actually exist on the struct (typo, stale field, whatever) I don't want it silently ignored, I want the function to return an error so I catch it early instead of debugging some subtle data integrity bug later. This is internal to the storage package and it's what'll power our upsert and partial update logic.
