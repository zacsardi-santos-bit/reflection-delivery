I want nushell to natively read and write MessagePack, that compact binary serialization format you see everywhere in databases, caching layers, messaging queues, and network protocols as a language-neutral JSON alternative. Right now there's just no built-in way to open a MessagePack file or turn nushell values into MessagePack bytes, so anyone dealing with tools that emit this stuff is stuck. I want a command that converts raw binary MessagePack into native nushell values and one that goes the other way, values back into MessagePack binary, and the whole thing needs to roundtrip cleanly with no loss. Opening a file with the right extension should just auto-decode it too.

It's gotta handle all the common types: nulls, booleans, integers of the various sizes, floats, strings, binary blobs, lists, maps (which become records), and timestamps (as datetimes). Oh and I want a streaming mode where a source with multiple consecutive top-level values gets parsed into a list instead of just grabbing the first one. Also a compressed variant alongside the plain format, its own pair of encode/decode commands, full roundtrip too.

On errors, I don't want silent garbage. When input is too deeply nested, or has strings with invalid character encoding, or is truncated or empty, or has trailing data after the message ends, or uses reserved or unknown byte markers, or packs integers too big to represent, or uses non-string map keys, or carries extension types with wrong sizes or unknown identifiers, I want each of those to fail with a clear descriptive error instead of producing wrong output. Basically anything malformed or unsupported should surface a readable message. This is about letting nushell integrate with MessagePack-based systems so I can inspect, transform, and generate that data straight from the shell without reaching for external tools.
