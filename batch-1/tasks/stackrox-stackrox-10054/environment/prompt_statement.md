We've got a built-in security policy that right now flags containers missing any of the four resource settings, CPU requests, CPU limits, memory requests, and memory limits, and honestly the name doesn't describe what it does anymore and the broad coverage keeps firing alerts on workloads that intentionally leave some of those unset, so it's just alert fatigue. I want to narrow it down to the two settings that actually matter, whether a CPU request is set and whether a memory limit is set, and rename the policy so it clearly reflects that it only cares about those two. So the detection criteria needs to change too, it should only raise a violation when a CPU request or a memory limit is missing, and it should stop alerting entirely on missing CPU limits and missing memory requests.

Since this policy lives in the database for existing deployments, I also need a database migration that automatically transitions the old policy definition over to the new name and the new criteria, no manual steps for anyone running an existing install. Oh and the migration has to be careful, it should compare the existing policy's name, description, and rule sections against what we expect the old built-in values to be before it updates anything, so if someone customized their copy we don't clobber their changes, we only migrate the untouched default. The end goal is a more actionable policy focused on the two most impactful settings so we cut down the false positives.
