I'm working with the bulk indexer in the go-elasticsearch client and I need to support optimistic concurrency control on individual bulk items. Specifically, I want to be able to specify a sequence number and a primary term on a bulk indexer item so that the write is only applied if the document is at the expected version. Right now, the item struct doesn't have these fields, and the metadata serialization doesn't include them in the output. I'd like both values to be optional — when provided together with a document ID, they should appear in the serialized metadata header as the sequence number field and the primary term field with their integer values. If either is missing, they should simply be omitted.
