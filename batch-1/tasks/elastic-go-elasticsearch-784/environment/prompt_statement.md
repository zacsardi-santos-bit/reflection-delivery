I'm working with the bulk indexer in the go-elasticsearch client and I need optimistic concurrency control on individual bulk items. Right now when I'm batching writes there's no way to say "only apply this if the doc is at the version I expect," which is a real gap because the underlying engine supports version-based conflict detection just fine and I'm stuck falling back to single-document APIs for conditional writes, losing all the throughput I get from batching.

What I want is for a bulk indexer item to accept a sequence number and a primary term, both optional as pointer values so I can leave them nil when I don't care. When both are set and the item also has a document ID, they should get serialized into the item's metadata header as part of the JSON action object, showing up as the sequence number field and the primary term field with their correct integer values. If either one is missing, or there's no document ID at all, just omit them from the metadata, don't emit empty or zero fields.

So basically the item struct needs the two new fields added and the metadata serialization needs to include them conditionally. The whole point is enabling conflict-safe bulk indexing so I can do optimistic concurrency control at scale without dropping down to per-document calls.
