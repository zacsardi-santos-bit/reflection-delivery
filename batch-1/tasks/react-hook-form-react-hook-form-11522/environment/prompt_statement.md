I'm using this React form library and I keep running into a wall where the only way to observe form state is from inside a component with the hooks, which always drags a re-render along with it. I want to be able to watch form state from outside React entirely, like set up a form control on its own and register a callback that fires when the state changes, so I can hook into non-React code, fire analytics, or do side effects without touching the render cycle.

So the ask is basically a subscription API on the form control. I create the control standalone (no component needed), and subscribe with a callback that gets invoked whenever the parts of state I care about change. I should be able to say which aspects I'm interested in, dirty state, current values, validity, that kind of thing, and also optionally scope the subscription to a single field by name so the callback only fires when that specific field is what triggered the change. When it does fire, the callback needs the full current form state at that moment, including which field caused the update, so I've got enough context to actually react.

Oh and the important bit, when I later hand this same form control to a React component, the component should only re-render for the state it explicitly opts into. My external subscription shouldn't force any React re-renders on its own, that's kind of the whole point, I want to share one control between React and non-React worlds without the outside listener bleeding renders into the component. Basically decouple the observation from React entirely while keeping the in-component subscriptions as granular as they already are.
