I'm working on a zero-knowledge proof library that implements the FRI protocol. The library currently uses the word "config" in its type names and function names to refer to the mathematical and security parameters of the FRI protocol — things like the blowup factor, number of queries, and proof-of-work bits. But these aren't really configuration settings; they're cryptographic parameters that define the protocol. I'd like to rename the relevant types, traits, and helper functions throughout the library to use "parameters" (or "params" for short) instead of "config" (or "cfg"). This also applies to a related trait that abstracts over how folding is performed — its name currently implies it is a generic configuration type, but it should reflect that it defines a folding strategy. Fields in structs that hold these objects should be renamed too. The public API needs to be updated everywhere these names appear so that callers can use the new names.
