I'm building out a distributed tracing library and I keep hitting a wall with how spans get parented. Right now every span I make just automatically becomes a child of whatever span is currently executing in the thread's context, and there's no escape hatch. So if I'm nested inside some span but I actually want to start a brand new root span for its own trace tree, I can't. And I also can't say "hey this new span's parent is this other specific span I made earlier," regardless of what's running at the moment. Both of those are real things distributed tracing needs since work correlates across async boundaries and sometimes I want to attach to a logical root created way earlier, none of which lines up with the lexical call stack.

What I want is a way to pass an explicit parent when creating a span. Two cases: declare a span has no parent so it's a root even while I'm inside another span, and declare that a specific existing span is the parent, overriding the current one. Spans created without any explicit parent should keep working exactly like today, inheriting from context automatically, don't break that.

Also on the subscriber side, when a new span notification comes through, the subscriber needs enough info to tell which of the three situations it's in: explicit root, explicit parent, or contextual parenting. And in the explicit parent case it's got to be able to identify which span is the designated parent. So whatever new-span data the subscriber receives has to distinguish all three and carry the parent's identity when there is one.
