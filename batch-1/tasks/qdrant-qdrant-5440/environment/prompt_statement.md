I'm in the memory-mapped file library over in the Qdrant memory crate and I hit a wall. We've already got a typed wrapper for writable memory maps, the thing that lets you treat an mmap as a slice of some element type, but there's no read-only counterpart and that's biting me. Some higher-level components need to hold both a writable handle and a read-only view over the same underlying file, and without a read-only typed slice type the whole crate just fails to compile when that pattern shows up.

What I want is a new module in the memory library exposing a read-only typed slice type, same spirit as the existing writable typed slice (look at how that one's structured for the shape to mirror). When you hand it a read-only memory-mapped file, it should let you treat the contents as a slice of any fixed-size element type, with the length derived automatically as the file size divided by the size of that element type. Oh and the conversion needs to be fallible, it should succeed when the file size is a proper multiple of the element size and return an error otherwise rather than doing anything with undefined behavior on a bad size.

This unblocks compilation and lets us do efficient sequential-read patterns backed by mmap. Please add the type and wire it up so read-only mmaps can be treated as typed slices.
