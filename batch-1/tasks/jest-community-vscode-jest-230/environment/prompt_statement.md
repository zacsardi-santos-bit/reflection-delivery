I'm chasing a Windows-only bug in our VS Code test runner extension where coverage overlays just don't show up. Dug into it and I'm pretty sure the issue is path normalization. We already lowercase Windows drive letters on test result paths to match how VS Code represents document paths internally, but that normalization never touches the coverage map data, so when coverage comes back with an uppercase drive letter variant those keys don't line up with the editor's file references and the overlay silently never renders.

What I want is dedicated utility functions that normalize both the test results and the coverage map, applied together before the rest of the extension consumes the data. On non-Windows systems everything should pass through untouched, and paths that already have lowercase drive letters shouldn't get changed either. On Windows though, normalize the test result file names plus the coverage map keys and their internal path fields, all down to lowercase drive letters. So both sources of paths from the test runner end up consistent.

While I'm in here I also want to tidy the module layout, the test result types and utilities are scattered across several separate modules right now and it's annoying importing from a bunch of places, so consolidate them into one unified entry point everything imports from. Oh and the cache reset logic buried inside the test result provider should get pulled out into its own public method so I can call it independently when I need to. Net effect is Windows folks actually get coverage highlighting again and the codebase is a bit cleaner to maintain.
