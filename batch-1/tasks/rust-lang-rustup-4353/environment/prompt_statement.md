I'm working on improving the test infrastructure in the rustup project. Right now, the interactive installer tests are quite verbose — every test has to store the command output in a variable and then make multiple separate assertions against its fields. Some tests even have debug print statements left in them. There's also a deprecated macro being used to substitute the current host triple into expected output strings, which generates compiler warnings.

I'd like to introduce a fluent, chainable assertion wrapper so that tests can check whether a command succeeded or failed, and verify its output content, all in a single chain of method calls. The output matching should support pattern-based wildcards so partial matches work without needing exact strings. It should also handle host-triple substitution automatically. Running a command with custom environment variables should work the same way. The new type should be publicly accessible from the test utilities module so all test files can use it.
