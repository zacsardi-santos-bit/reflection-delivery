I'm cleaning up the interactive installer tests in the rustup project and the current style drives me nuts. Every test runs a command, stashes the output in a variable, then does a bunch of separate assertions against individual fields, and some of them still have leftover debug print statements floating around. On top of that there's a deprecated macro we're using to splice the current host triple into expected output strings and it throws compiler warnings every build.

What I want is a fluent, chainable assertion wrapper so a test can run a command and then check success or failure plus verify stdout/stderr content all in one chain of method calls instead of the two-step dance. The output matching should support pattern-based wildcards so I can match any content before or after some key phrase without pinning down the exact string, which also keeps tests from breaking on tiny formatting changes. It needs to handle host-triple substitution automatically via a standard mechanism rather than that deprecated macro. I also want to be able to assert that a given string does NOT appear in the output as a chainable op. Oh and running a command with custom environment variables should give me back the same chainable result type so everything composes the same way.

This new type should live in and be publicly exported from the test utilities module (see the CLI test support code under `@src/cli` / the tests utils area) so all the test files can pull it in. The whole point is dropping the boilerplate so tests read cleanly at a glance, using the wildcard matcher instead of substring or exact-string checks so they're more resilient, and killing the deprecated macro to knock out those warnings and move us toward modern idioms.
