I'm hitting parse failures in SQLFluff whenever a Snowflake SQL file touches external volumes, you know the statements that manage external cloud storage volumes (create, alter, drop, describe, restore). Right now any file with these either throws a parse error or gets flagged invalid even though it's totally valid Snowflake syntax, and it breaks my whole linting pipeline. I need the Snowflake dialect to actually understand these.

So for creating an external volume I want it to handle one or more storage locations specifying a cloud provider (S3, GCS, and Azure), with a base URL, plus optional encryption settings, role ARNs, tenant identifiers, write-access flags, and comments. The create form should support both the "replace if exists" and "create if not exists" variants. Altering needs to cover adding a storage location, removing one by name, or setting properties like write access and comments, and it should also allow an "if exists" guard. Dropping an external volume with or without an existence guard should parse as its own distinct statement type, separate from the general drop statement, not folded into it. Describing an external volume should just work under the existing describe statement support, and restoring (undropping) one should work under the existing undrop statement support.

Oh and in every one of these cases the volume name needs to parse as a dedicated external volume reference node in the parse tree, not some generic object reference. This is all in the Snowflake dialect, so `@src/sqlfluff/dialects/dialect_snowflake.py` is where the grammar lives. The goal is basically parity with the Snowflake docs for external volume management commands so folks running these as part of their data pipelines can lint without spurious errors.
