I'm working on the Azure Terraform provider and I need to add automanage configuration profile support to the Azure Stack HCI cluster resource. Right now there's no way to associate an automanage config assignment with an HCI cluster through Terraform, so I want an optional automanage configuration ID attribute on that resource that users can set when creating or updating a cluster, and I need removing that assignment in a later apply to work cleanly without errors.

The tricky part is the resource ID format for automanage config assignments scoped to an HCI cluster is different from the one used for regular VM automanage assignments, so I can't reuse the existing parsing utilities. I need new parsing logic specifically for this ID type that pulls out the subscription, resource group, cluster name, and the configuration profile assignment name from the ID string. It's gotta reject malformed input too, so empty strings, IDs missing segments, and IDs where the path keywords are in the wrong case should all fail parsing rather than silently succeeding.

Alongside that I want a validation utility that enforces the same constraints so users get clear feedback the moment they supply a bad ID, same rejection rules (empty, incomplete, wrong-cased). This matters because lots of Azure customers use automanage to automate machine best-practice configs, and without this they're stuck doing it manually or out-of-band instead of keeping their HCI cluster lifecycle fully declarative in Terraform. The parsing and validation live under the automanage bits of `@internal/services/automanage/` and the cluster attribute wiring goes into the Stack HCI cluster resource itself.
