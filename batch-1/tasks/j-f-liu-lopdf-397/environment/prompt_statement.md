I'm hitting a nasty bug in the PDF encryption path and I'm pretty sure it's an off-by-one in the permission flag bit positions. The PDF spec lays out where each permission bit lives inside the 32-bit permission integer, and the way it looks to me every one of these flags in the library is shifted one bit off from where the spec says it should be. So when I encrypt a document and then open it in any spec-compliant viewer, the permissions come back wrong, viewers misread which operations are allowed or blocked, and the whole point of setting permissions falls apart.

What I want is for the flags to line up with the actual spec values. The printable flag should sit at bit position 2, so numeric value 4. The modifiable flag should be bit position 3, numeric value 8. The flag for whether content can be copied should be bit position 4, so 16. And the fill-forms flag should be bit position 8, numeric value 256. Right now they're all one bit too high (or too low, depending how you look at it) which is what's breaking things.

Can you go into the encryption code where these permission constants are defined and correct the bit positions so printing, modifying, copying, and form-filling all match the spec? Once they're fixed the encrypted docs should restrict or allow the right operations and a compliant viewer will read them correctly.
