I'm dealing with a Kafka source connector that reads CDC events in debezium format, and the annoying thing is a single topic carries events from a bunch of different database tables all mixed together. Right now there's no way to tell the connector to only care about one table, so every record on the topic gets deserialized and pushed downstream even when it came from a table I don't want. I want to add a config option for a table filter that takes a database name, schema name, and table name, so only matching change events get deserialized and forwarded and everything else just gets silently dropped. Without this I'm stuck filtering out junk in downstream transforms, which defeats the point of building a targeted single-table pipeline.

Couple related things I keep hitting at the same time. First, when an incoming debezium event doesn't include a column that my configured schema defines, deserialization currently blows up or does something wrong. I want those missing fields to just come out as null instead of erroring, since the source schema often has more fields than the actual event data. Second, some connectors like Oracle don't put the database name in the source metadata at all, so the filter needs to handle that gracefully. If an exact match on the full path (db, schema, table) fails, it should fall back to matching on just schema and table name.

Oh and there's also a separate bug in the Avro format serializer where rows with small integer fields, or maps whose values are small integers, aren't handled right. Those should serialize and deserialize correctly on a round-trip. The debezium format and Avro serializer live under the source and format code respectively, so poke around there.
