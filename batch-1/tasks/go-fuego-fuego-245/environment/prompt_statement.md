I'm working with a Go web framework and I'd like to be able to pass a pre-created network listener directly to the server instead of always having the server create its own socket. Right now, the server always binds to an address on its own, which makes it impossible to do things like inherit a socket from a parent process or use a listener that was set up before the server starts. I'd like to add a server configuration option that accepts an existing listener and uses it for accepting connections. When such a listener is provided, the server should use it directly instead of creating a new one from the configured address.

On top of that, I've noticed that when the server fails to start — for example, because the address configured for it is invalid — the error isn't always returned back to the caller. The startup methods should propagate these errors properly so callers can detect and handle failures instead of having them go unnoticed.
