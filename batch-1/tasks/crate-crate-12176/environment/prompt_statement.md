I'm running into a problem with how type signatures are serialized and parsed for object types that have field names containing special characters like spaces, parentheses, or quotation marks. When I create an object type with a field name that includes a space or a bracket character, the system can't correctly reconstruct the type from its serialized signature string. The parsing fails because those characters have special meaning in the signature format, but the serializer doesn't escape them.

I'd like the serialization to properly escape such field names using double-quote wrapping, and for any embedded quotation marks within the name to be backslash-escaped. The parser should then be able to handle these quoted names and restore the original type correctly.

On top of that, I'd like to see the type signature parsing logic moved into its own dedicated class rather than being embedded in the type definition itself. This would make it easier to maintain and test the parser in isolation. Named parameters in type signatures should also expose a way to get the decoded field name — without surrounding quotes or escape sequences — rather than the raw escaped form.
