I'm hitting a bug in how we serialize and parse type signatures for object types when field names have special characters in them. If I make an object type with a field name that has a space, or parentheses, or brackets, or an embedded quotation mark, the round trip breaks. The serializer writes the name out raw, and then the parser chokes because those characters have special meaning in the signature format, so we can't reconstruct the original type from its stored signature string. Users who create object columns with field names like that just hit failures in type resolution.

What I want is for the serialization to escape those field names by wrapping them in double quotes, and any quotation marks embedded inside the name should get backslash-escaped. The parser then needs to read those quoted names back and restore the original type correctly. Field names without special characters should keep serializing and parsing exactly like they do now, no change there.

Also while we're in here, I'd like the type signature parsing logic pulled out into its own dedicated parser class instead of living inside the type definition itself, so it's easier to maintain and test the parser on its own. And named parameters in type signatures should expose a way to get the decoded field name back, without the surrounding quotes or escape sequences, rather than just the raw escaped form.
