I'm adding two new probes to the scorecard project to get finer-grained signal on whether changes landing on a repo's default branch are actually being reviewed before merge. Right now the code review check works at a higher level and there's no probe-level way to separate two distinct things, whether every human-authored changeset got a formal approval from someone other than the author, and whether every human-authored changeset was at least reviewed (even without a formal approval) by someone other than the author. Splitting these lets consumers tell apart projects that have any peer review from ones that require formal approvals, and it's easier to compose into higher-level scoring with different thresholds and weights.

Both probes look at the set of recent changesets on the default branch. Changesets authored by bots get excluded, they shouldn't push the outcome toward pass or fail either way. If the author data can't be retrieved (empty login) the probe reports not-available rather than a false positive or negative, and same thing if reviewer data is missing (empty reviewer login). Self-reviews, where the author reviews their own change, don't count toward the requirement, and duplicate reviews from the same reviewer get deduped so only unique reviewers count.

The first probe is the strict one, it needs a formal approval state from a non-author, so a review that isn't an explicit approval doesn't satisfy it. If any human-authored changeset lacks a qualifying approval it's a negative outcome, if all of them have at least one it's positive. If there are no human-authored changesets at all (say everything was bot-authored) it reports not-available instead of passing or failing. The second probe is the looser one, it only needs at least one different person to have reviewed the change regardless of approval state, so if even a single changeset had no non-author reviewer that's negative, and if all had at least one unique non-author reviewer it's positive, with the same bot-skip and missing-data (not-available) rules.

Oh and one more thing for both, if there are no changesets at all to evaluate, return an error rather than a finding.
