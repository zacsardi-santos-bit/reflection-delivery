I'm hacking on the postgres-operator and hit a real gap: when we sync a StatefulSet we only ever look at the desired PostgreSQL version in the cluster spec, we've got no way to see what version is actually running inside the containers. That's risky because it can lead to incorrect StatefulSet generation and silently ignored upgrade requests we can't safely apply, basically config drift where the operator thinks a cluster is on 12 when it's really on 11.

The running version lives in a container's internal config. There's an env var holding a JSON blob that has a binary directory path, and the version number is baked into that path. So I want a helper that, given a binary dir path plus a path format template, pulls out the version string. It needs to handle both decimal versions like "9.6" and whole-number ones like "11" or "12", so don't assume there's always a dot.

On top of that I want a higher-level function that looks up this path from the container configuration and returns the currently running version. Oh and when it syncs, if that running version differs from the desired new version, it should keep the running version and log a warning, since in-place major upgrades aren't supported so the running one takes precedence.

Also, btw, there are a few spots in the existing code that reference a PostgreSQL version field in the wrong place on the spec struct. Those references need fixing so the package compiles cleanly and all the existing functionality keeps working. Weave the new version-detection logic into wherever the StatefulSet sync and container config handling already live so it fits the current structure.
