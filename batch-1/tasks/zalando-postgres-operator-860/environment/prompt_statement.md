I'm working on the postgres-operator and I need to add the ability to detect the PostgreSQL version that is actually running inside a cluster's containers. Right now, when the operator syncs a StatefulSet, it only looks at the desired version in the spec — it has no way to inspect what version is genuinely deployed. This is a problem because it can lead to incorrect StatefulSet generation and unintended version changes.

The running version can be found in a container's internal configuration: there's an environment variable that contains a JSON blob with a binary directory path, and the version number is embedded in that path. I need logic that can extract a version string from such a path given a format template, handling both decimal versions like "9.6" and whole-number versions like "12". I also need a higher-level function that looks up this path from the container configuration and returns the currently running version — and if that version differs from the desired new version, it should preserve the running version and log a warning, since in-place major upgrades aren't supported.

There are also some places in the existing code that reference a PostgreSQL version field in the wrong location on the spec struct — those references need to be updated so the package compiles cleanly and all existing functionality continues to work.
