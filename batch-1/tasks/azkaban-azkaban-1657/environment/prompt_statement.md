I'm working on Azkaban, this workflow management system, and project names are case-sensitive right now which is kind of a mess. Someone can create "myproject" and then turn around and create "MYPROJECT" as a totally separate thing, and now nobody knows which project is which. I want project name uniqueness enforced case-insensitively so that creating a project whose name only differs in casing from an existing active project gets rejected.

The piece I actually need first is a general-purpose concurrent map utility that normalizes string keys (lowercasing them, say) so lookups, insertions, and removals all treat "MyKey" and "MYKEY" as the same entry. It shouldn't be projects-specific, I want it usable across the codebase, but then wire it in to back the in-memory project name cache so the in-memory duplicate check stays consistent with what the database does. Oh and on the DB side, the database used in tests needs to be configured to do case-insensitive string comparisons so duplicate detection works at that layer too.

Then the behavior: when someone tries to create a project whose name matches an existing one in any casing, throw an error saying the project already exists. I want this at both the project management layer and the database persistence layer, and each error message should clearly call out that a duplicate project name was detected. Without this two projects that differ only by case can coexist and it's just confusing, so I want it predictable no matter how people capitalize things.
