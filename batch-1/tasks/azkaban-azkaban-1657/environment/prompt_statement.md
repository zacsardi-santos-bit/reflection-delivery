I'm working on a workflow management system and noticed that project names are currently treated as case-sensitive. This means someone can create a project called "myproject" and then separately create "MYPROJECT" as if they were entirely different things. We want project names to be unique regardless of how they're capitalized, so creating a project whose name differs only in case from an existing one should be rejected with an appropriate error.

I need a case-insensitive concurrent map utility that normalizes string keys (for example, by lowercasing them) so that operations like lookup, insertion, and removal treat "MyKey" and "MYKEY" as the same entry. This map should be used to back the in-memory project name cache so that duplicate detection works consistently. On top of that, the database used in tests should be configured to do case-insensitive string comparisons so that duplicate detection also works at the database level.

When a user tries to create a project whose name already exists (in any casing), the system should throw an error indicating the project already exists — both at the project management layer and at the database persistence layer, with each error message clearly identifying that a duplicate project name was detected.
