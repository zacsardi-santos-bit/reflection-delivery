I'm building out a form component library and hit a styling gap with the label. Right now the label text renders at the same size no matter where it sits relative to the field, and that's not what I want. When the label is positioned above the field (which is the default layout) it should use the smaller standard text size, but when it's placed to the left of the field it should automatically bump up to a slightly larger size so it stays visually balanced with the rest of the design system. Left-positioned labels currently look off because they're stuck at the small size.

There's also a related bug with custom typography. When I pass my own font-size setting directly to the label, the component just ignores it if the form control is already applying its own position-based sizing. That's backwards. The explicit custom value should always win, even when the label is in the left position and would otherwise get the larger auto size. So the priority is: if a developer hands over a font size, use that, full stop, otherwise fall back to the position-derived size (small for above, larger for left).

Can you wire up both behaviors so the label adapts its size by position and respects explicit font overrides when they're provided? Without this, left labels feel inconsistent and folks lose predictable control over label appearance.
