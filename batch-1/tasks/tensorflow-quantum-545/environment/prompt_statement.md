I'm working on the expectation layer in TensorFlow Quantum (the Keras-facing one, around `@tensorflow_quantum/python/layers/circuit_executors/expectation.py`) and right now it only knows how to do noiseless analytic simulation. I need to add trajectory-based noisy simulation so I can compute expectation values on circuits that carry depolarizing noise and other realistic channels, averaging over a bunch of stochastic runs.

Couple of things I want here. First, the backend arg is annoying, it only takes None or a preconfigured simulator object, so I'd like to also accept plain strings like "noisy" or "noiseless" to pick the mode. When I'm in noisy mode I'll pass a repetitions argument into the call to say how many trajectories to average. That repetitions value needs to be flexible: a single int applied to every operator, a 1D list with one entry per operator, or a 2D list with one per circuit-operator pair.

The error handling matters too. If I'm in noisy mode and forget repetitions, I want a clear descriptive error. Same if repetitions can't be parsed into valid values. And if I pass repetitions while on a noiseless backend it should complain, since averaging trajectories makes no sense analytically.

Oh and the noisy path has to handle everything the noiseless one already does, batched circuits, batched operators including 2D operator lists, symbol names and symbol values, all of it. Also a model built on the noisy backend with enough repetitions should actually train and converge on a simple problem, though I'm fine if the tolerance is looser than the noiseless case since there's sampling noise. This is mostly so people building hybrid quantum-classical Keras models on noisy simulators don't have to drop down to lower-level APIs or work around the layer.
