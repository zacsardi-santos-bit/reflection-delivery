I'm adding a new lint rule to ruff that flags overly specific return type annotations on iterator methods in classes. The idea is that when a class's iteration method (the sync `__iter__`-style one) only yields values without receiving sent values or returning anything meaningful, it's cleaner to annotate the return as an iterator rather than a full generator. Same story on the async side with async iterators vs async generators. So I want the rule to catch these and suggest the simpler iterator equivalent.

Here's the behavior I'm after. It should only fire on methods inside a class body, so module-level functions with the same names get ignored entirely. For the sync case it should flag bare generator return annotations plus parameterized generator types where the send slot and the return slot are trivially unused, meaning set to placeholder values that indicate no meaningful type or no value (like none or any). For async iteration methods it should flag bare async generator annotations and parameterized ones where the send type is trivially unused. Don't flag it when the generator params carry meaningful non-trivial types in the send or return slots, that's a legit generator and should be left alone.

Some edge cases I explicitly don't want flagged: methods actually defined as `async`, methods that have extra or unusual parameters beyond the standard self, and in regular (non-stub) Python files, methods with non-trivial generator bodies, so if the body returns a meaningful value, uses a yield expression to receive a sent value, or has complex statement logic beyond simple yields, leave it. In stub files those body checks don't apply since there's no real body.

Oh and the generator and async generator types need to be recognized whether they're referenced from `collections.abc` or from `typing`, both spellings. This is basically about cutting noise in type stubs and annotated code since the iterator annotation is semantically equivalent and more idiomatic when you only need to declare iterator protocol compliance.
