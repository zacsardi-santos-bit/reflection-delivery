I'm working on the snapshot subsystem for a distributed SQLite database. When taking an incremental snapshot, the system flushes the write-ahead log as part of the process. If that flush fails — for instance because another connection has the database open with an active transaction — the snapshot operation correctly returns an error. However, there's nothing in the code that handles this failure mode beyond returning the error. The next snapshot attempt will try the same incremental approach, potentially failing for the same reason, and leaving the replication state in a bad place.

What I'd like is for a failed write-ahead log flush during snapshotting to automatically mark that the next snapshot must be a full, complete snapshot of the database rather than an incremental one. After such a failure, any check for whether a full snapshot is required should report that one is needed. This way the system recovers gracefully: even if the incremental path is broken, the next snapshot will capture the entire database state and restore consistency.
