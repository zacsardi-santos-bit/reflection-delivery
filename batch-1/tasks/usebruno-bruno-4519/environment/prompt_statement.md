I'm hitting a couple gaps with Bruno's variable interpolation in request templates and want to fix both in the interpolation layer. First problem, when I set an environment variable or collection variable to a whole object or an array and then reference it inside a placeholder, I'd expect the JSON representation to show up in the output but instead it renders incorrectly or gives me some junk instead of a proper string. Same deal with date and time library values, they should serialize to their standard quoted ISO string form (JSON style, so wrapped in quotes) and they don't. What I want is for interpolation to automatically stringify objects, arrays, and date/time values using standard JSON serialization whenever they land as a placeholder value. That includes complex types nested inside other objects, so if I've got an object that itself contains one of these, the nested piece needs to serialize too. Oh and objects that contain their own nested template placeholders should get those inner placeholders resolved first, before the outer object gets serialized.

Second thing, I keep hitting a naming collision. When an object has a property whose name literally contains a dot, there's no way to reference it in a template because the dot always gets read as a nested path traversal. I want a bracket-notation syntax so I can explicitly look up a literal key by name inside a parent object, distinct from the dot-path traversal. Both notations need to work side by side in the same template and resolve to their right values. This all matters because people store structured data and time values in their collections all the time and want to drop them into request bodies, headers, or scripts naturally, plus reference weird keys without manual workarounds.
