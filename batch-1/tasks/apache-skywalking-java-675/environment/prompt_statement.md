I'm extending our SOFA-RPC plugin so distributed tracing actually follows callback-style async invocations across thread boundaries. Right now sync RPC calls trace fine, but when a remote call goes out in callback mode, the response handler runs on a totally separate thread with no link back to the original trace, so that work is invisible, it shows up as a disconnected untraceable operation instead of a continuation of the original call chain.

What I want is for the trace context on the initiating thread to get captured at the exact point the callback is registered, and then restored when the callback fires on its own thread, so the callback processing shows up as a linked segment connected to the span that made the original RPC call. If the callback hits an error or exception during execution, I want that recorded in the trace as a log entry on the callback's span. And if there's no active trace when the callback is registered, the callback thread should still just complete normally without blowing up.

Also the wrapping bit: when the argument passed to the callback invocation method is a recognized callback type, it should get automatically wrapped to enable this context propagation, but if the arg isn't a callback type, leave it untouched, don't wrap it. This is basically about making the async response handling phase actually observable so we can debug latency and failures that happen during callback execution instead of having a hole in the trace.
