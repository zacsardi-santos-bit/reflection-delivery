I'm digging into the SPIRE server's CA manager and hit a gap around how it stores the CA journal, that thing that tracks the history of certificate authority keys and their rotation status. Right now it only gets persisted to disk, so there's no centralized record in the datastore and old journal data that's no longer relevant just piles up forever with nothing to clean it. I want to add datastore-backed storage alongside the existing disk storage. On startup, when the server finds a journal on disk but not yet in the datastore, it should load from disk and start dual-writing to both places going forward.

The datastore needs to support creating and updating journals, fetching a journal by its active authority identifier, pruning journals whose certificate authorities have all expired past a safety threshold, and listing all journals (that last one's mainly for testing). Oh and the CA rotator should periodically prune old CA journals from the datastore in addition to its existing bundle pruning, using a separate interval and safety threshold, so the two pruning operations (bundle pruning and CA journal pruning) each get their own dedicated constants.

Also all the rotation and activation ops on the CA manager, rotating and activating both X.509 CAs and JWT keys, should accept a context so cancellation and deadlines propagate through those calls. The telemetry wrapper around the datastore should emit metrics for each of the new CA journal operations, and if saving a journal to the datastore fails, I want a clear error surfaced while still letting the on-disk save proceed. Without this, operators can't reliably inspect or manage CA journal state across a deployment, and stale journals accumulate indefinitely, which is just operational burden and confusion during rotation.
