I'm hitting a bug in the graph library's copy utilities, the ones that copy all nodes and edges from a source graph into a destination graph and are supposed to handle conversions between directed and undirected types. Right now the implementation grabs edge objects straight from the source and sets them on the destination instead of building fresh edges that the destination actually owns, and that breaks things when the two graphs are different types since the source's edge objects don't belong to the destination's type system.

The most obvious symptom is copying an undirected graph into a directed one. Each undirected edge implies you can traverse it either way, so the directed destination should end up with edges in both directions, but it doesn't right now. Same idea in reverse: copying a directed graph into an undirected one should produce the right undirected edges, and copying between two graphs of the same type (directed to directed, or undirected to undirected) should give me an identical copy. I want all four combinations working correctly, and the weighted variant needs to do the same thing while preserving edge weights during the copy. Oh and isolated nodes, the ones with no edges attached, should carry over to the destination too, don't drop them.

Basically the fix is to construct new edges through the destination rather than reusing the source's, so this works cleanly for both plain and weighted graphs. Folks convert representations or make copies for mutation without touching the original all the time, so these need to actually be correct instead of silently producing wrong results that bite downstream algorithms later.
