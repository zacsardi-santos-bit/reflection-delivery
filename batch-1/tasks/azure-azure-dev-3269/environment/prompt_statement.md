I'm working on our cloud dev CLI that handles containerized service deployments and right now it can only deploy by building images from local source code, there's no way to point it at a pre-built image (say something from Docker Hub or spat out by a CI pipeline) and just deploy that. I want to fix that. Lots of teams manage images externally or split build and deploy into separate pipeline steps, and forcing a build from source every time doesn't fit those patterns, so I need the tool to accept a pre-existing container image as the service source instead of always building.

A couple of behaviors here: when someone specifies a pre-built image but hasn't configured a container registry, skip the push entirely and use the image directly. When a registry is configured, pull the pre-built image, re-tag it for that registry, then push it. Also a service that has a pre-built image but no source project should still resolve correctly into the container deployment workflow, and if a containerized service has neither a source project nor a pre-built image configured it should fail clearly rather than doing something weird.

Separately the image config is too coarse right now, looks like the image name and tag are jammed into one field, so I can't independently control registry, image name, and tag across environments. I want those exposed as separate config options, all supporting env var substitution, so I can drive image references from the environment without duplicating config per environment.

Oh and I need a way to parse a container image reference string into its parts (registry, repository, and tag) and convert it back both to a local reference without the registry and to a fully-qualified remote reference with the registry.
