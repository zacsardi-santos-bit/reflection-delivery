I'm adding AWS Network Manager support to moto since right now it doesn't mock the service at all, so any unit test that touches Network Manager APIs blows up immediately without real AWS creds and connectivity. I want to test my infra automation code locally and offline, so I need a working backend and responses wired up under something like `@moto/networkmanager/models.py` and `@moto/networkmanager/responses.py` with the usual url routing in `@moto/networkmanager/urls.py`.

Core stuff I need: creating global networks (takes a description and tags) which should come back with a pending/provisioning state and a properly formatted ARN, and creating core networks tied to a global network, passing description, tags, a policy document, and a client token, also with a correct ARN that references the account id. Deleting a core network should give back a response reflecting a deletion-in-progress state, and after that the network shouldn't show up in listings anymore. I also want listing all core networks, fetching a specific core network by its id, and describing global networks either all at once or filtered down by one or more ids.

Tag management matters too, so adding tags to both global networks and core networks by their ARN, and removing specific tags from either by ARN. Oh and when someone tries to tag a resource that doesn't exist, it should return an error saying the resource wasn't found, and include the resource identifier that was passed in. Btw all of this needs to work through the moto server too, specifically the HTTP endpoints for listing global networks, listing core networks, and adding tags to a resource. Without this, anyone using moto to test networking infra code is just stuck.
