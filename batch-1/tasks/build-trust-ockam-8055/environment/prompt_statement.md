When I set up a foreground exporting configuration, the method currently makes me pass a boolean quiet-mode flag to say whether the exporter should suppress output. That's an internal implementation detail and honestly the caller shouldn't have to care about it or decide it, the config should just work that out for itself based on its own logic and environment.

So what I want is to drop that parameter entirely so setting up a foreground tracing/logging export takes zero arguments. The quiet vs verbose behavior needs to get determined internally, encapsulated in one place instead of scattered across every call site. Then go find all the existing call sites that pass a boolean into this method and update them to the new no-arg form so nothing breaks.

The reason this matters: exposing that flag in the public API couples callers to the export config internals for no good reason. Removing it simplifies things and cuts the cognitive overhead for anyone wiring up tracing later, and it keeps the decision living where it belongs. Please make sure the whole thing still compiles after you've swapped over the call sites, that's the main thing I'm watching for.
