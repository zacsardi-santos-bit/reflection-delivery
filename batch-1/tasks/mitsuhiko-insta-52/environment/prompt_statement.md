I'm working with an inline snapshot testing library for Rust and I'd like to change how multi-line inline snapshots are formatted when they're embedded directly in test source files. Right now, every line of the snapshot content is prefixed with a special vertical ellipsis character (⋮). This makes the snapshots harder to read, breaks normal editor indentation handling, and is awkward to type or edit manually.

I'd like the library to switch to a simpler approach: inline snapshots should use regular spaces for indentation, aligned with the surrounding code. When reading the snapshots back for comparison, the library should automatically strip the largest common block of leading whitespace from all lines so the content still matches correctly. Leading empty lines and trailing whitespace should also be handled cleanly during this normalization.

Existing snapshots that use the old character-prefixed format should still be recognized and work correctly, so nothing breaks for users who haven't migrated. When the library writes or updates inline snapshots, it should produce the new space-indented format. This should work consistently across all snapshot types — debug output, YAML, RON, and YAML with redactions.
