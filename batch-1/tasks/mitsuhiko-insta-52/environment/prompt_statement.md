I'm working on our inline snapshot testing setup in Rust and the way multi-line inline snapshots get formatted is driving me nuts. Right now every line of the embedded snapshot content is prefixed with that vertical ellipsis character (⋮), which I think was originally a hack to track indentation, but it makes the snapshots hard to read, it fights with normal editor indentation, and it's just annoying to type or copy-paste or manually tweak. Standard editors, formatters, and diff tools don't handle that Unicode prefix well at all.

What I want is to drop the special character entirely and switch to plain space indentation aligned with the surrounding code, so an inline snapshot just looks like ordinary indented text. The tricky part is reading them back for comparison: when the library parses an inline snapshot it should automatically strip the largest common rectangle of leading whitespace across all the lines, so the content still matches correctly no matter how deeply it's nested in the source file. Also leading empty lines before the content and trailing whitespace at the end should get ignored during that normalization so nothing spurious sneaks into the comparison.

Backwards compat matters here, so existing snapshots that still use the old ⋮-prefixed format need to keep working, I don't want to force everyone to migrate all at once. But when the library writes or updates an inline snapshot itself it should emit the new space-indented format going forward. Oh and this all needs to behave the same across every assertion variant we've got, so debug output, YAML, RON, and YAML with redactions should all round-trip consistently with the new format.
