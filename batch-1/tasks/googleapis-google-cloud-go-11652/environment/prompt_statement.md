I'm trying to make distributed tracing actually useful in the Cloud Spanner Go client and right now it's kinda useless for debugging prod. When I run a read-write transaction with a transaction tag and fire off queries with request tags, none of those tags show up on the trace spans, and the spans are also missing basic context like which database and instance I hit, what region, and which client library version was running. So when a trace is slow or failing I've got no way to connect it back to the specific tag or query that caused it, which is exactly the info I need.

What I want is a set of tracing helper functions in the spanner package that standardize how spans get started and ended, and that pull relevant attributes off the RPC request objects being sent (transaction tags, request/statement tags, and the SQL text) and attach them to the active span. Weave these into the existing tracing plumbing so a read-write transaction span ends up carrying the database name, instance name, detected region, client version, repository, artifact details, and the transaction tag when one was set, while a row iteration span carries the statement tag, the SQL query text, and the enclosing transaction tag whenever those are present in the query options.

Big thing though, when tracing isn't enabled these helpers need to be a no-op with basically zero overhead, so the attribute-setting logic has to short-circuit for non-recording spans and skip the allocations. Oh and I'd like a benchmark that demonstrates that skip actually happens, i.e. non-recording spans don't do the unnecessary work. This all lives in the spanner package alongside the existing transaction and row iterator code.
