I'm working on adding support for user-defined log exporters in the OpenTelemetry collector configurations generated by the postgres-operator. Right now, these generated configs only use a built-in debug exporter — there's no way to route component logs (from PostgreSQL, pgBouncer, pgAdmin, pgBackRest, Patroni) to an external observability system like Google Cloud Logging.

I need to update the configuration generation so that when an instrumentation spec is provided with custom exporter definitions and log routing settings, those exporters get included in the generated configuration and all the relevant log pipelines route through them. When no instrumentation spec is provided, the behavior should remain unchanged (debug-only output).

The functions that create collector configurations — including the one that creates a base config, the one for pgAdmin logging, and the one for the pgBackRest repo host pod — need to be updated to accept an instrumentation spec parameter so they can incorporate user-defined exporters. Other logging functions already receive cluster information and can read the spec from there.

A few other improvements are also needed: the Patroni log pipeline should consistently include resource attribute enrichment and attribute grouping processors regardless of whether custom exporters are configured. The pgAdmin log transformation should also be improved to preserve the original log body, set the message as the log body, and record the logger name as the instrumentation scope name.

When custom exporters are configured, the generated configurations should also include appropriate file storage extensions for durable log checkpointing.
