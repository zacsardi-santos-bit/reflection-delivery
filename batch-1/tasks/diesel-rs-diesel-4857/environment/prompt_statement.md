I'm working with Diesel's derive stuff for building update changesets, and I've hit a wall with embedded structs. Right now if I mark a field with the embed attribute in an `AsChangeset` derive, it pulls that inner struct's columns into the update, which is great for grouping related columns together logically. The problem is it only works when the embedded struct is always there. I want to wrap that embedded struct in an `Option`, so the whole group of columns becomes optional.

The behavior I'm after: when the optional embedded value is `Some`, all its fields get folded into the update right alongside the parent struct's own fields. But when it's `None`, those columns shouldn't be touched at all, their existing database values just stay put, skipped entirely from the generated SQL. Basically the same present/absent semantics you already get for a plain optional column, but applied to a whole embedded group.

Today this doesn't work, an optional embedded struct either fails to compile or doesn't handle the Some/None cases right, so there's no way to express "optionally include this group of columns" through embedding. Could you add support for optional embedded structs to the `AsChangeset` changeset derive so partial updates where some column groups may or may not change actually work? The derive macro lives in the codegen crate under `@diesel_derives/src/`, and it'd be good to have runnable examples covering both the present and absent paths.
