I'm working in our monorepo build tool and hit a wall with watch mode. Right now the Angular library executor and the Node application executor both just return a single build result, so when a file changes there's no way to emit a fresh result over time. I want to convert these executor functions so they produce a stream of successive build results instead, something callers can iterate over. In non-watch mode, consuming the results once should give exactly one build result telling me whether the build succeeded or failed, and then the sequence should signal completion with nothing more to follow. In watch mode it should just keep emitting new results as changes happen, and I don't want callers doing weird workarounds to loop over them.

Also the project graph creation utility bugs me. It does file I/O but it's implemented synchronously, which doesn't fit an async-first design and it blocks the event loop. There's already a sync version, but I need a proper asynchronous counterpart that returns something callers can await non-blockingly, so other utilities can pull the graph that way.

One of those utilities is the dependency checker that validates whether a project has any dependents before it gets removed. It needs to become async too since it depends on the project graph, so it should retrieve the graph via the new async function instead of the synchronous one. When the project has dependents and removal isn't forced, it should reject with an error message naming all the projects that still depend on the one being removed. When removal is forced, or when there are no dependents at all, it should resolve cleanly. This keeps everything consistent and lets watch mode actually stream incremental updates.
