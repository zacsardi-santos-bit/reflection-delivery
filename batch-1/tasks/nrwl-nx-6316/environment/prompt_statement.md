I'm working on a monorepo build tool and need to update several executor and utility functions so they can produce and stream multiple results over time instead of returning just a single result. Right now, the Angular library and Node application executor functions just return a single build result, which means watch mode can't stream multiple build results over time — every time a file changes, the executor should be able to emit a new result, but currently there's no way to do that.

I also need the project graph creation utility to be exposed as a proper asynchronous function, since it involves file I/O and should fit into modern asynchronous design patterns. There's already a synchronous version, but I need an asynchronous counterpart that other functions like the dependency checker can use. The dependency-checking function (which validates whether a project has any dependents before it gets removed) needs to become asynchronous as well, since it depends on the project graph and should reject with an appropriate error message listing the dependent projects when a forced removal isn't requested.

Specifically: when an executor is used in non-watch mode, consuming the results once should produce a single build result and signal completion with no more results to follow. In watch mode, it should keep emitting results. And the dependency checker, when dependents exist and removal isn't forced, should reject with an error describing which projects still depend on the one being removed.
