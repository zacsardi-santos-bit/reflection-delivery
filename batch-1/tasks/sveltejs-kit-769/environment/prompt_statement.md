I've found a security issue in SvelteKit's server-side rendering. When a page fetches data during the load phase and that data contains strings with closing script tags (like those found in user-supplied content or untrusted API responses), the framework embeds the raw data directly into the inline scripts in the rendered HTML. This means that if the data contains something that looks like the end of a script block followed by the start of a new one, the browser parses it as real HTML — and any code in the injected script actually runs.

For example, if an API returns a name field containing a script-tag sequence, navigating to the page should show that string as literal visible text. Instead, the injected content executes as JavaScript. In a no-JavaScript (pure SSR) scenario this is especially clear: a variable that should never be set ends up being set because the inline serialized data breaks out of its containing script block.

I'd like the framework to properly escape fetched data before embedding it into server-rendered HTML so that special characters like angle brackets and slashes in the embedded data cannot be interpreted as HTML tag boundaries. The fix should apply to all data fetched during the server-side rendering phase, regardless of content type.
