I'm hitting a wall with rkyv when I want to archive types from external crates I don't own and can't touch. Right now if I want to archive one of these remote types I've gotta hand-write all the Archive, Serialize, and Deserialize impls myself, which is a ton of boilerplate and really easy to screw up. What I want is to define a local mirror type that mirrors the shape of the remote type and slap a single annotation on it so the derive macros generate all the archiving, serializing, and deserializing machinery pointing at that remote type instead.

This should cover named structs, tuple structs, unit structs, and enums as mirror types. I also want partial mirrors where I only list the fields I actually care about and fill in the rest through a conversion I provide. For named structs I should be able to omit any fields I want, for tuple structs only the trailing fields can be dropped, and for enums every variant has to be present but I can leave out fields inside a given variant.

Oh and the other annoying thing, some of these remote types have private fields I can't read directly. For those I need a way to point the derive machinery at a getter function that reads the private field for me, and it's gotta work whether that getter hands back the value directly or returns a reference to it. Also the existing per-field wrapper attributes should keep working right alongside this new remote annotation, don't break those. And the whole round trip, archive it and then deserialize back into the original remote type, needs to preserve the data correctly. This is all in the rkyv derive side of things under `@rkyv_derive` with the trait plumbing living in `@rkyv`, so wire it up there. The goal is basically bringing the same nice derive-based workflow we already have for types you own over to remote types so rkyv actually works for way more real-world cases.
