I upgraded our CI to run strict linting where all warnings are hard errors, on top of the usual type checking, and now the whole build face-plants on the very first step and never even reaches the test runner. The culprit is the HTTP library when it's built with no optional features on: there's a macro in the HTTP context module (over in `@crates/http/src/context.rs` roughly) that only gets referenced from code compiled under the client or server features. In the base case where neither is enabled, which is exactly what the no-features lint check exercises, the macro is defined but never invoked, so the linter yells "unused macro" and since warnings are errors that kills the step.

And because that lint step is a prerequisite for the test step, all 15 tests in the core networking crate show up as failures even though they're totally fine, they just never got a chance to run. Those tests cover a smart pointer utility type (checking it implements clone, deref, borrow, and display properly, plus construction from reference-counted and borrowed forms), a buffered reader (compaction and Unpin behavior), static service discovery, consistent hash load balancing (correctness, stability, change handling, distribution), weighted random load balancing, and the load balance service layer.

What I want is for the HTTP library to compile cleanly under strict lint when built with no features. This unused-macro thing is a known, intentional pattern, that macro's only alive under certain feature combos, so it's fine to just suppress the unused warning for it rather than delete or restructure anything. Don't touch the test logic, it's exercising pre-existing functionality that already works. Once linting passes, all 15 of those tests should run and pass. Basically fix this one macro so the pipeline gets unblocked.
