I'm building a cognitive client package and I need a reusable middleware pipeline utility. The idea is that I should be able to register multiple handlers in sequence, and when I run the pipeline, each handler gets the current error state and value, and can either pass control to the next handler (optionally modifying the error or value), or short-circuit and skip all remaining handlers. Handlers that receive an error should still be called — they can choose to propagate the error or clear it and recover. If a cancellation signal is provided and has already been aborted when the pipeline runs, the whole thing should reject immediately with the abort reason. At the end of the chain, if an error is still set, the pipeline rejects with it; otherwise it resolves with the final accumulated value. I need this to work as a generic, reusable class that I can instantiate for any value type.
