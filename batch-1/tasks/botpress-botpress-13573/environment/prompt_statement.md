I'm building out a cognitive client package and I keep needing the same thing over and over, a little middleware pipeline utility I can reuse for both request and response processing. Think attaching model selection logic or fallback handling before a request goes out, and post-processing responses before they come back. Right now there's no standard way to compose handlers that pass values forward, introduce or clear errors, short-circuit the rest of the chain, or respect cancellation, so I want a proper reusable abstraction I can test in isolation.

Here's how I want it to behave. I register multiple handlers in sequence and they run in the exact order I added them. Each handler gets the current error state and the current value, and it decides whether to keep going down the chain or stop early. A handler can pass a modified value or a modified error to the next step. It can also bypass all remaining steps and just settle the result right there. Handlers that receive an error still get called, they can propagate it or clear it and resume normal resolution.

Cancellation matters too, so if a signal is provided and it's already aborted when the pipeline runs (or gets aborted during), the whole thing rejects immediately with the abort reason instead of continuing. At the end of the chain, if an error's still set, the pipeline rejects with it, otherwise it resolves with the final accumulated value. Oh and it needs to be a generic reusable class I can instantiate for any value type.
