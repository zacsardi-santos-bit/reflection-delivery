I'm cleaning up the uprobe program controller in the bpfman operator and there's a few related things I want to sort out. First off the uprobe program spec currently takes a list of targets but honestly we only ever need one target per program, so I'd like to simplify that to a single string target field instead of a list. It just reduces API confusion and nobody's actually using multiple targets.

Second thing, I noticed the controller always shoves a container process ID of zero into every uprobe gRPC attachment request, even when there's no container being targeted. That placeholder is wrong, oh and it can cause unintended behavior in the daemon downstream, so when I'm building an attachment request without a container selector I want that container PID field omitted entirely, not set to zero.

Last one, I need a pod discovery helper for later work on attaching uprobes inside specific containers on a node. Given a label selector, an optional namespace, and a node name, it should return all the pods running on that node that match the selector. If no namespace is passed in it should search across all namespaces, and also the selector should handle an empty label set, in which case just return all pods on that node regardless of their labels. This is the foundational building block so we can attach uprobes in containers without manual PID management later.
