I'm adding H.265 (HEVC) support to pion/webrtc since right now the library handles H.264 fine but there's no equivalent for HEVC, which is a real gap for anyone building WebRTC apps with H.265 video who otherwise has to roll their own parsing and writing outside the ecosystem. I need two new packages.

First, an H.265 Annex B bitstream reader that takes a raw stream and parses it into individual network access layer (NAL) units one at a time. Each unit needs its header fields pulled out, so the forbidden zero bit, the NAL unit type, the layer ID, and the temporal identifier. It's gotta handle errors properly, so if the input doesn't look like valid H.265 it returns a descriptive error, and when the stream's fully consumed it returns end-of-file. The reader's internal state should track the current buffer of NAL bytes and the count of consecutive zero bytes seen, since that's how Annex B boundaries get detected. Reading a valid stream should hand back successive NAL units with the type and header fields parsed correctly.

Second, an H.265 RTP writer that accepts H.265 RTP packets and writes them to an underlying output destination in Annex B format, meaning each NAL unit gets the standard 4-byte start code prepended. It also needs to identify key frames, including when the packet is a fragmentation unit (where the key frame type is encoded inside the fragmentation header) or an aggregation packet where multiple NAL units are packed together and any one of them might be a key frame, so key frame detection has to cover direct NAL units plus both those packet types. Empty RTP payloads should just be silently ignored without error. Oh and the writer needs a close method that cleans up gracefully even if the underlying destination doesn't support explicit closing.
