So our blockchain storage tests are drowning in boilerplate. Every test that needs a real database backend has to spin up a temp dir by hand, thread that path into the db constructor, then delete the dir when it's done, and honestly the cleanup swallows errors silently so if the removal fails we never hear about it and stale test data just piles up. I want a self-contained temporary database type living in our shared test helpers, something you can construct with a no-argument constructor and get a ready-to-use db back without ever touching a path. It should manage its own storage lifecycle internally (create the temp dir on construction, clean it up on drop) and be usable anywhere we currently use the real on-disk database type in tests, basically interchangeable with it in test contexts.

Also the helper we use to build test blockchains backed by a real database needs to take this new type directly, so drop the path parameter from its signature entirely, callers shouldn't be doing any filesystem path management anymore. And for the few remaining spots where tests still explicitly remove a temp directory by hand, don't just ignore a failed removal, make it fail loudly with an error so a botched cleanup shows up as an actual test failure instead of quietly leaving junk behind. Point is: less boilerplate per test, easier to read, and cleanup problems actually surface.
