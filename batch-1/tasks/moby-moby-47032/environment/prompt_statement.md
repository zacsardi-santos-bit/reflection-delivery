I'm on moby/moby and I keep hitting a version drift problem with our vendored OpenTelemetry stuff. Most of the otel packages already got bumped to the newer release, but the HTTP tracing one (the `otelhttp` instrumentation library under `@vendor/go.opentelemetry.io/contrib/instrumentation/net/http/otelhttp`) is still sitting on an older pinned version, and that mismatch is the kind of thing that causes subtle runtime incompatibilities plus we're missing fixes and improvements that landed upstream. I want it lined up with the same version the other OpenTelemetry libraries in the project are using.

So the ask is basically: update the vendored copy of that library, and make sure everything that tracks it agrees. That means the actual source in the vendor directory, the module manifest in `@vendor/modules.txt`, and the checksums in `@go.sum` should all reflect the new version, no leftover references to the old one anywhere.

Oh and while I'm at it, I want a guard so this doesn't silently regress later. In the client package (`@client`) add a check that verifies the library actually reports the expected version number at runtime, so if someone accidentally downgrades or pulls in the wrong version during a future dependency shuffle, we catch it immediately instead of finding out the hard way. Keeping the otel components in sync makes it way easier to reason about what capabilities and fixes are available, and the explicit version assertion acts as a safeguard against dependency management mistakes.
