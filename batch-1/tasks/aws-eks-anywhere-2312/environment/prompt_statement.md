I'm working on improving our end-to-end test infrastructure for a Kubernetes cluster management tool. Right now, our git integration tests rely on a pre-existing SSH private key that's stored externally and downloaded at test time. I'd like to change this so each test run creates its own fresh GitHub repository and generates its own SSH key pair — uploading the public key as a deploy key on the new repo and writing the private key to the test instance automatically.

To do this, I need the GitHub provider client to support adding deploy keys to repositories. The provider client interface and its GitHub-backed implementation both need a new method that accepts the repository owner, repository name, key content, a title, and a read-only flag. The underlying GitHub API client interface (and its mock used in unit tests) also needs to expose the corresponding low-level operation.

There's also a bug in the local git client's branch creation: when a new branch is set up for tracking, the branch configuration is not storing the rebase setting, even though it should be set to enabled. This causes unit tests that check the resulting branch configuration to fail.

Finally, several constants in the test framework related to git and GitHub environment variables are currently package-private, but other packages need to reference them. These should be exported. The function that returns the list of required environment variables for git-based tests also needs to be updated: rather than requiring the repository SSH URL to already be known upfront, a new variant of this function should return only the variables needed when the repository will be created dynamically (omitting the SSH URL from the required set).
