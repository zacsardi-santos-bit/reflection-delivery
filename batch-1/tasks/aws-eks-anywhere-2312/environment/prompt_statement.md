I'm reworking our e2e test setup for the Kubernetes cluster manager and the git integration tests are annoying me. Right now they lean on a pre-provisioned SSH private key stashed in some external storage bucket that we download at test time, and I want each run to be fully self-contained instead. The idea is that a test spins up its own fresh GitHub repo, generates its own SSH key pair, uploads the public key as a deploy key on that new repo, and writes the private key onto the test instance, no shared external state at all.

For that to work the git provider client needs to grow the ability to add deploy keys. Both the provider client interface and its GitHub-backed implementation need a new method taking the repo owner, repo name, the key content, a title, and a read-only bool, and the GitHub impl should just forward that down to the underlying GitHub API client with those params. That low-level API client interface (plus the mock we use in unit tests) needs the matching operation exposed too.

Also there's a bug in the local git client's branch creation, when it sets up a new branch for tracking it's not storing the rebase setting in the branch config even though it should be enabled, so the unit tests checking the resulting branch config fail. Please fix that so the stored config has rebase turned on.

Oh and a bunch of the git/GitHub env var constants in the test framework are package-private right now but other packages need them, so export those. And the function that returns the required env vars for git tests currently assumes the repo SSH URL is already known upfront, I want a new variant that returns only the vars needed when the repo gets created dynamically (so it omits the SSH URL from the required set), distinct from the older one.
