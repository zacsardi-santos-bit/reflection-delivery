I'm dealing with a quantum simulator that stores states in matrix product state form, and there's a gap I keep hitting. Over in the MPS statespace class I can create MPS objects, set their raw tensor data, and convert them to full wavefunctions, but there's no direct way to compute the inner product (the overlap ⟨ψ₁|ψ₂⟩) between two MPS states. Right now if I want to compare two states I have to expand both into full wavefunction vectors first, which is exponentially expensive in the qubit count and honestly defeats the whole point of using MPS in the first place.

So I want to add an inner product method to the MPS statespace class that takes two MPS states of equal size (same number of qubits, same bond dimension) and returns the complex-valued overlap as a complex scalar. It should contract the tensor network directly, working through the qubit sites from left to right, instead of building the full wavefunctions. The result is a complex number so it needs to capture both magnitude and relative phase, meaning both the real and imaginary parts have to come out accurately.

The key thing is it has to work for genuinely entangled multi-qubit states with non-trivial bond dimensions, not just product states, and the numbers should match to reasonable floating-point tolerance. This is what lets fidelity computations, expectation values, and state comparisons stay efficient for larger systems, so accuracy on the entangled cases really matters.
