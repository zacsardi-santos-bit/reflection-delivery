I'm working on Terraform recipe support in Radius and hit a wall with module inspection when the template path points at a subdirectory inside an archive. We follow the usual convention where a double slash in the template path means "look inside this subfolder of the downloaded archive" rather than the archive root, so if I zip up my Terraform config nested in a named subfolder and point the recipe at `something//subdir`, the inspection step should crawl into that subdir. Right now it doesn't, it just strips off everything after the double slash and always reads the root of the downloaded module, so when my config lives in a subdirectory the inspection either fails or returns garbage because it's staring at the wrong directory.

What I want is for the inspection logic to take the full recipe definition, both the recipe name and the template path, instead of just the module name, and when the template path carries that double-slash subdirectory specifier it should navigate into that subdirectory before loading the Terraform module config for analysis. If there's no subdirectory specifier, keep the old behavior exactly as it is, no regressions there.

Also I need a test data directory set up that mimics a downloaded module laid out with a subdirectory, so this whole thing can be verified end to end. This matters because subdirectory-based archive layouts are a really common packaging pattern and without it people just can't organize their Terraform recipe config in subfolders, which limits how they package recipes.
