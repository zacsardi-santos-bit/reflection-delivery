I'm working on the EKS Anywhere cluster management tooling and need a way to wait for a Kubernetes service to become available by checking whether it has been assigned an IP address. Right now there's no utility for this — I can wait for other resource conditions, but not specifically for a service to get an IP (either a cluster-internal address or one from a load balancer).

I need a method on the kubectl wrapper that accepts the kubeconfig path, a timeout as a duration string, the service name, and its namespace. It should poll the cluster repeatedly until the service has an assigned IP, returning success at that point. If the timeout string I provide isn't a valid duration, it should fail immediately with an error. If the service isn't assigned an IP before the timeout elapses, it should return an appropriate error indicating the wait timed out. This would let automated cluster workflows and integration tests reliably know when a service is ready to accept traffic before they proceed.
