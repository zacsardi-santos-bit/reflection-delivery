I'm deep in the EKS Anywhere cluster management tooling and hit a gap around waiting for services. Right now our kubectl wrapper (over in `@pkg/executables/kubectl.go`) can wait on all sorts of resource conditions but there's nothing that specifically waits for a Kubernetes service to actually get an IP, either a cluster-internal ClusterIP or one handed out by a load balancer. When we deploy packages to a cluster and then want automation or e2e tests to proceed, we don't have a clean way to know the service is ready to take traffic, so people end up guessing at timing or doing ad-hoc polling which is flaky.

What I want is a new method on the kubectl wrapper that takes the kubeconfig path, a timeout expressed as a duration string, the service name, and the namespace. It should poll the cluster repeatedly until the service has an assigned IP and then return success. Couple of edge cases matter here: if the duration string I pass isn't a valid Go duration it should fail right away with an error instead of blocking, and if the service never gets an IP before the timeout elapses it should come back with a timeout error. Success just means the service has any IP assignment, direct or via LB. Oh and please mirror the style of the existing wait helpers in that file so it fits naturally. This is mostly so cluster workflows and integration tests can reliably gate on service readiness before moving on.
