I'm cleaning up the replay listing output in our batch backend and the source column is basically useless right now. When we list replays it just dumps a raw collection name with no label telling you what kind of source it even is, and worse, if a replay is sourced from a dead-letter stage instead of a collection then that info doesn't show up at all, it's just missing. So a stage-based replay looks identical to one with a missing or empty collection, which is confusing.

What I want: the source column should show a labeled string based on the source type. For collection-based replays render it like "Collection - <name>", and for stage-based ones show "Dead Letter Stage - <name>" so you can actually tell them apart. Also the replay type field comes straight from the API in lowercase and I want it normalized to be human-readable, title-cased, instead of the raw value.

Oh and one more thing while I'm in there, the schema listing output currently carries a field for the protobuf root type that's never actually useful to anyone looking at the results, so I want that field dropped from the schema output struct entirely. Cleaning that up cuts down the noise since it serves no practical purpose in what gets displayed.
