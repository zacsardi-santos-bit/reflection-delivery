I'm working on adding preemptive proxy authentication support to OkHttp. Right now, when making HTTPS requests through an HTTP proxy, the client only sends proxy credentials after receiving a challenge from the proxy — it never tries to authenticate upfront. This means every new connection to an authenticated proxy requires an extra round trip even when the application already knows the right credentials.

I'd like the proxy authenticator to be called proactively before the initial tunnel-establishment request is sent. It should receive a special synthetic challenge so it can recognize this as a preemptive opportunity and optionally return a credentialed request. If it does, those credentials go on the tunnel-establishment request. If it returns nothing, the connection proceeds without credentials and falls back to the existing reactive challenge-response behavior if the proxy demands authentication.

When both preemptive and reactive authentication happen on the same connection (for example, the authenticator declines the preemptive opportunity but the proxy sends a real challenge), the authenticator gets called in sequence — first with the preemptive synthetic challenge, then with the real one. The credentials must only appear on tunnel-establishment requests, not on the origin-server requests that follow.

The test helper authenticator class also needs to be updated to support filtering by authentication scheme, so that an authenticator configured for one scheme (like basic authentication) will not accidentally respond to the preemptive synthetic challenge when it shouldn't.
