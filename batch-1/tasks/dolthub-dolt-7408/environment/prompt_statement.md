I'm browsing commit history with `dolt log` and I keep hitting the same wall: the output only gives me the commit metadata (hash, author, date, message) and nothing about what actually changed. On a busy database that's painful, I have to pop into each commit's diff one at a time just to figure out the scope. I'd like a stat-style flag on the log command (think git log --stat) that prints a compact diffstat under each commit summarizing which tables were touched and the row-level counts.

Here's what I want it to show. When a table gets created in a commit, the line should say that table was added, and when a table's dropped it should say deleted. For row changes (inserts, updates, deletes) I want the table name shown next to a count plus a character indicating the change type, and then a summary line at the bottom tallying counts for each change type (added, modified, deleted rows). Oh and it needs to play nice with the existing compact single-line format flag, so I can combine the two and still get the diffstat.

One thing to be careful about: merge commits shouldn't get a diffstat at all since their changes come from merging branches and the summary would just be ambiguous, so skip those.

This basically mirrors the normal VCS workflow where you scan the log to see which files changed per commit, except for us it's tables and row counts. Without it I'm stuck inspecting every commit's diff individually which is slow and cumbersome.
