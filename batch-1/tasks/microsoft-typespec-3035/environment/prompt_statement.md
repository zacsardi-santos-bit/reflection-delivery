I'm working on adding XML support to TypeSpec and I need to create a new XML library package from scratch. The package should provide decorators that let API authors describe how their TypeSpec models map to XML — things like marking a property as an XML attribute instead of an element, marking a property as unwrapped, assigning XML names, and specifying XML namespaces with their prefixes.

For namespaces specifically, I want two ways to apply them: directly with a namespace URL string and a prefix string, or through a specially-marked enum where each member's name becomes the prefix and its string value becomes the namespace URL. The namespace decorator should validate its inputs and emit appropriate diagnostics when something is wrong — for example, if someone tries to use an enum that hasn't been declared as a namespace enum, if an enum member is missing a string URL value, if a prefix is redundantly provided alongside an enum member, or if the namespace string is not a valid URI. Namespace annotations should also not carry over from a parent model to its child properties.

Additionally, the package should provide a utility for determining the correct XML encoding to use for a given property's type. Common scalar types like date, time, datetime, duration, and binary data should each have well-defined default XML encodings, but it should also be possible to override the encoding on a per-property basis.

The package needs to export its decorator implementations, the namespace utility functions, the encoding utility, and a test library definition so that it can be properly exercised in tests.
