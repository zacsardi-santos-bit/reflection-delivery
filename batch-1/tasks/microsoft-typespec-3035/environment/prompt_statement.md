I'm building out XML support for TypeSpec and I need a brand new XML library package from scratch, because right now there's no way for spec authors to describe how their models map to XML when they're building APIs that produce or consume XML. I want decorators that let API authors say which properties become XML attributes instead of child elements, which ones are unwrapped (not enclosed in a wrapper element), assign XML-specific names to a model or property independent of its TypeSpec name, and attach XML namespace info.

For namespaces I want two paths: apply directly by passing a namespace URL string plus a prefix string, or go through a specially-marked enum where each member's name becomes the prefix and its string value becomes the namespace URL. The namespace decorator needs to validate and emit diagnostics when things go sideways, so if someone hands it an enum that wasn't declared as a namespace enum, or an enum member missing its string URL value, or a redundant prefix passed alongside an enum member, or a namespace string that isn't a valid URI, it should complain appropriately. Also namespace annotations shouldn't carry over from a parent model down to its child properties, that inheritance thing keeps biting people.

Oh and I also want a utility for figuring out the right XML encoding for a given property's type. The common scalars (date, time, datetime, duration, and binary data) should each have well-defined default XML encodings, but it's gotta be possible to override the encoding per-property too.

The package needs to export its decorator implementations, the namespace utility functions, the encoding utility, and a test library definition so all of this can actually be exercised in tests. Net goal is making TypeSpec a complete description language for XML APIs so tooling authors have what they need to generate correct XML serialization code and schemas.
