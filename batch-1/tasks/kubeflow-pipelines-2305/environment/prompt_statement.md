I'm on the Kubeflow Pipelines frontend and I want to add artifact links to the run details side panel. Right now when you click a node in a pipeline run graph, the panel shows input and output parameters but there's no way to see artifacts, the files or data a node consumed or produced that live in object storage like Minio or S3. Users can't discover or navigate to them at all, which makes debugging and data exploration harder than it should be.

So a few things. First I need a new artifact link component that takes an artifact's storage config and renders it as a clickable link to retrieve it. It's gotta handle both S3 and Minio backends and build the right URL based on the endpoint (distinguish S3 vs Minio from that endpoint). If the config is bad, null, undefined, or missing required fields like bucket or key, it should render nothing at all.

Also I need a new method on the workflow parser to pull a node's input and output artifacts, following the same pattern as the existing parameters method. And while I'm in there, the parameters method should stop returning a positional array/tuple and instead return a named object with distinct input and output fields, so it lines up with the new artifacts method (which should also return a named object, not a positional tuple).

Oh and the data table component we use throughout the UI only supports string values right now, so it can't render artifact entries as links. I want it to accept an optional custom value renderer so non-string values like artifact configs can be shown using a custom component (the new artifact link component here) instead of just being converted to text.
