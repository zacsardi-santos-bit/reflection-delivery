Hey, got two things I need fixed on this webhook proxy that sits between our source control and the build platform. First problem is when the proxy spins up a new pipeline config in the build system, it never puts the Git repo URI in there, so the build system has no clue where to fetch the source and builds just fail. I want that URI derived from the incoming event data by stitching together a base URL, the project name, and the repo name, then dropped into the generated pipeline config. Right now the config generation is just crude string substitution and I'd rather move to a real template-based approach where named placeholders get filled in, specifically the pipeline name, the trigger secret, the Git URI, and the branch. Oh and the template file itself should be an actual template with named placeholders for all those dynamic fields, not the ad-hoc thing it is now.

Second thing, when the proxy forwards a webhook event over to the build system and kicks off a build, it just tosses whatever response comes back. I need that forwarding op to actually capture and return the response body so we can hand it back to the original caller and they can inspect what happened when the build got triggered.

To make both of these work you'll need to touch the interfaces and data structures a bit. The event data struct needs a field to carry the Git URI so it flows through the system and lands in config generation. The pipeline-creation function should take a pre-parsed template instead of doing raw substitution. And the forwarding function needs to return the response bytes alongside any error, instead of dropping the response on the floor. Without this, triggered builds give zero feedback to callers and the pipeline configs come out incomplete, so let's get both sorted.
