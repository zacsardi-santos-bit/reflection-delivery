I'm hitting a spot where our directory accessibility check just lies to us. If a directory exists but has had all its permissions stripped off (fully locked down so nothing can read or write it), the check happily returns no error, like the dir is totally fine to use. Then we proceed with it and blow up later with some confusing downstream failure instead of a clear "hey you can't touch this" message up front.

What I want is for the accessibility check to actually catch this case. When a directory exists but its permissions are fully restricted, the check should return an error saying the directory is inaccessible and telling the user to check their access rights. Right now it silently sails past that, which is the whole bug, so the fix is making sure even an extremely locked-down directory gets flagged immediately rather than causing mysterious errors somewhere else.

So basically, poke at whatever we use to test writability or readability, because just checking existence or metadata isn't enough when perms are zeroed out. Make it try enough to know for real that the dir can't be used, and return that clear access-rights error when it can't. That way users get an immediate, obvious signal about the permission problem instead of confusing failures down the line.
