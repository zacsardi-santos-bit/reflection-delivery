I'm digging into the ACL permission resolution and hit a real problem with how the resolved global scope is stored. Right now every plugin's global scope permissions get merged into one flat structure with no attribution, so there's no way to tell which plugin a given scope entry came from. The practical fallout is that each plugin ends up getting the combined scope from every plugin instead of just its own, which breaks isolation.

What I want is to restructure the resolved global scope so it's a map keyed by plugin name, where each plugin's entries live grouped under its own name. So when I resolve the ACL and no plugins have any global scope permissions at all, the global scope should come back as an empty map rather than an empty flat scope structure. And when one or more plugins do have global scope entries, those need to show up grouped under that plugin's name, with allow and deny entries kept properly separated but stored together under the plugin's key. A plugin that has both allow and deny globals should have both correctly split out and preserved under its own entry.

This all needs to flow through the ACL resolution logic so the output actually reflects the per-plugin shape. The reason it matters, btw, is plugin isolation: each plugin should only operate on its own globally-defined permissions, not a union of everyone's, and without per-plugin attribution in the resolved global scope the runtime can't deliver the right scope to the right plugin. It's foundational for correct per-plugin global scope delivery at runtime, so getting the data structure right here is the whole point.
