I'm working on the CloudFoundry CLI and I want to start attaching distributed tracing headers to the outgoing HTTP requests we make. Right now when the CLI talks to the Cloud Controller, the Router API, or UAA, none of those requests carry any tracing context at all, which makes it basically impossible to correlate a single CLI operation end-to-end with the log entries on the backend services. That hurts a lot when I'm debugging or trying to observe prod behavior, so I'd like to inject B3 trace context (a trace ID plus a span ID) on every outbound call so operators can follow a request through the distributed system with standard tooling.

The way I want to do it is as connection middleware wrappers, one per API client, so it drops in cleanly to each of the three clients. Each wrapper injects the B3 headers on the way out. The trace ID gets supplied at construction time (think derived from a user session or command invocation), and the span ID is randomly generated per request. Oh and important bit: if a request already has those B3 headers set on it, leave them alone, don't overwrite, just pass through as-is.

I also need a couple small utility helpers for generating the random identifiers. One should always spit out a 32-character identifier (UUID-style), and another that takes a desired length and hands back a random string of exactly that length. The fixed one can just build on top of the variable-length one internally. Keep these next to the tracing/middleware code so each client can pull them in when constructing its wrapper.
