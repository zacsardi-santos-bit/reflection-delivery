I'm working on the Grafana Agent Helm chart and I keep hitting a wall where there's just no way to add sidecar containers to the pod through values. Right now the chart only ever renders the main agent container plus the config-reloader, so if I want to co-locate a helper workload I either have to fork the chart or mess with post-render hooks, both of which are annoying to maintain. What I want is a values key where I can declare one or more extra containers (with their images, env vars, volume mounts, the usual) and have them show up in the rendered DaemonSet alongside the agent and config-reloader.

The concrete thing I'm after is a GeoIP database updater running as a sidecar that continuously downloads and refreshes a database, writes it to a shared volume, and then the agent reads from that same volume to enrich telemetry. So I also need to be able to declare extra pod-level volumes alongside the sidecar (added to the pod's volumes list so the sidecar can mount them), and add extra volume mounts on the main agent container itself so it can get at the data the sidecar produced.

Oh and I want a CI test values file that exercises this exact GeoIP updater pattern end to end, so we can confirm the whole thing renders and works as part of the chart's normal CI. It should live with the other chart CI values so the standard test flow picks it up. Basically I want extra containers, extra volumes, and extra agent volume mounts all configurable declaratively in values.yaml, and the GeoIP scenario proving it out.
