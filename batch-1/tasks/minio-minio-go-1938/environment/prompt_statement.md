I noticed that the minio-go client is retrying requests when it receives a Cloudflare-specific HTTP error response (status code 520). This code is used by Cloudflare as a catch-all when the origin server sends something unexpected — it's not a standard server error like a gateway timeout or service unavailability, so retrying it doesn't make sense and just wastes time and resources. The retry logic should be updated to exclude this Cloudflare-specific code so the client stops treating it as a retryable condition.
