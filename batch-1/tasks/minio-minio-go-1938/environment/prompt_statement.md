I'm looking at the minio-go retry logic and noticed it's retrying on HTTP 520, which is that Cloudflare catch-all status they return when the origin server sends back something unexpected. It's not a real transient server error like bad gateway (502), service unavailable (503), or gateway timeout (504), it's Cloudflare intercepting at their layer, so retrying it doesn't help at all and just burns time and adds load for nothing.

I want the set of retryable HTTP status codes in the client to stop including 520. Right now that code lives in the list the retry code consults when deciding whether a response is worth another attempt, and it shouldn't be there since retrying a 520 is basically guaranteed not to fix the underlying problem. So drop 520 from the retryable status codes so the client treats it as terminal instead of cycling on it. The standard gateway-style codes (502, 503, 504) should stay retryable as before, this change is only about removing that one Cloudflare-specific code.

Btw the goal is just that a request coming back with 520 no longer triggers the retry path, everything else about the retry behavior stays the same.
