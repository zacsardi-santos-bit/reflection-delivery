I'm hacking on Gitea and hit two things that need fixing around collation and Unicode, would love your help.

First problem: on MySQL (and MSSQL too) the database defaults to a case-insensitive collation, so if someone makes two branches or entities that only differ in casing, like "Branch" vs "branch", the db treats them as the same value and you get silent conflicts, especially bad in multi-user setups where branch names and usernames need to be uniquely identifiable. I want new tables to use a case-sensitive collation by default so two values differing only in case can coexist under a UNIQUE constraint. I also need a way to inspect the current collation state, basically checking whether the configured collation is case-sensitive, what collation is expected, what collation is currently in use, which collations are available, and whether any table columns have inconsistent collations compared to what's expected. Part of that inspection should include helpers to figure out whether a given collation name indicates case sensitivity, and to compare two collation names for equality in a database-aware way (with the right normalization per engine, so the MySQL logic and the MSSQL logic both behave correctly). On top of that I want a tool that can convert existing tables to a specified collation, or fall back to a sensible case-sensitive default when none is given, and the existing database conversion maintenance command should get wired up to use this new functionality.

Second problem, kind of unrelated but same theme: the branch creation API rejects names with emoji or other extended Unicode characters. Git itself handles these just fine, so a branch named with an emoji in it should be accepted by the API and come back with a success response instead of failing. Modern naming conventions use this stuff and it's valid in git, so there's no reason to block it.

Can you implement both? The collation checking really needs to be correct for both MySQL and MSSQL.
