I'm wiring up GitLab CI for our linting workflow and hitting a wall on output formats. GitLab has this built-in code quality feature that reads a specific JSON shape from CI artifacts and renders the findings inline on merge request diffs, but our tool doesn't emit anything in that shape, so right now I'm hand-transforming the regular JSON output which is fragile and annoying to keep working.

What I want is a new reporter option that produces GitLab Code Quality compatible output, basically a JSON array where each entry carries a description, a rule identifier (check name), a fingerprint, a severity, and a location with a file path plus the starting line number. It needs to work across the main analysis commands (the code checking one, the lint command, and CI mode), and it should also be accepted by the formatting command, which can just spit out an empty JSON array since formatting isn't really a "code quality" finding in that sense. Oh and the new option has to show up in the help text for all those commands too, don't want it hidden.

That makes it render weird in the existing XML-based reporter output and in the language server protocol diagnostics we send. Can you just join it into a single line with a space between the two clauses so all the downstream consumers get consistent text? Both of these together mean teams on GitLab get annotations directly in MR diffs without extra glue, and messages stay clean everywhere they're consumed.
