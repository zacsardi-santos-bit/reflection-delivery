I'm working on adding GitLab CI integration to our linting workflow. GitLab has a built-in code quality feature that reads a specific JSON format from CI artifacts and displays the findings directly in merge request diffs. Right now, there's no way to get output in that format from the tool — I have to manually transform the JSON output, which is fragile and annoying to maintain.

I'd like a new reporter option that produces output compatible with the GitLab Code Quality report format: a JSON array where each entry has a description, a rule identifier, a fingerprint, a severity, and a location with a file path and starting line number. This should work with the main analysis commands (checking, linting, CI mode) and ideally also with the formatting command (which could just output an empty array since formatting isn't a "code quality" finding in that sense). The new option should also show up in the help text for all the relevant commands.

There's also a secondary issue I noticed: one of the lint rule messages is split across two lines with a newline character in the middle. This causes it to render oddly in the existing XML-based reporter output and in language server protocol diagnostics. The message should be joined into a single line with a space between the two parts.
