I'm updating our Go client for Iggy and the message format is out of sync with the server's current wire protocol, so producers send malformed data and consumers can't parse responses, basically the client's unusable against a current server. The old message type was just a UUID plus a payload byte slice plus a map of typed header entries, and that's not what the server wants anymore.

What I need is a new message representation built around a fixed-size binary header carrying a checksum, the message ID (UUID), an offset, timestamps, and length metadata for both the payload and the user headers. Instead of a structured map, user-defined headers should live as pre-serialized bytes on the message. I also want helper constructors so I can build a message with no headers or with a map of key-value headers that gets serialized to those bytes automatically, both taking an explicit UUID and payload.

The send-messages request serialization needs to change too. It should start with a metadata-length field, then the stream and topic identifiers and the partitioning info, then a message count, then a block of per-message index entries (one entry per message, 16 bytes each encoding cumulative size info), and finally the message data where each message is binary header bytes, then payload bytes, then user header bytes.

Oh and the fetch-messages request is encoding the consumer identifier wrong, it's writing a bare integer when it should use the full identifier format (kind/type, length, then value bytes) matching how stream and topic IDs get encoded. Fix that. And the response deserialization for fetched messages needs to parse the new fixed-size binary header layout coming back from the server.

Everything lives under the Go client code (`@foreign/sdk/go`), touching the message model, the send and poll/fetch message request serialization, and the fetched-message response parsing.
