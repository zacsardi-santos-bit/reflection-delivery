I'm cleaning up our compaction job status store interface and the way it gets tested. That way a new store only has to implement the streaming primitive.

Alongside that I need a real in-memory implementation of the status store that's usable in tests, one that actually tracks the job lifecycle events (created, started, finished) and answers all the querying operations correctly through the real query methods rather than being pre-programmed. Oh and it needs to support fixing the clock during testing so time-sensitive status updates come out deterministic. Then I want the admin client's compaction status report tests switched over to use this in-memory store instead of the mocks they lean on today, so they exercise the real job lifecycle instead of pre-fabricated return values. The whole point is less duplication in the interface plus tests that record actual events and verify resulting statuses through real queries, which is way less brittle than programming mock returns per scenario.
