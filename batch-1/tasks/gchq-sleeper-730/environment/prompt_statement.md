I'm working on refactoring the compaction job status store interface and improving how it's tested. Right now, every implementation of the interface has to independently provide separate methods for querying all jobs, unfinished jobs, jobs by task, and jobs within a time period. This creates a lot of duplication. I'd like to refactor the interface so there's a single foundational streaming method, and all the specific query patterns are provided as default implementations built on top of it.

A proper in-memory store would let tests record real lifecycle events — job created, started, finished — and then verify the resulting statuses through the real query methods. The in-memory store also needs to support fixing a clock so that time-sensitive updates produce predictable results in tests.
