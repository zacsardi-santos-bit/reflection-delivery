I'm building out the events system on the Prefect server and I've hit a wall: there's no database-backed storage layer for events at all right now. It's basically write-only, which blocks event history, dashboards, analytics, and automation triggers that key off past events. I need a proper module (think something under the server events storage area, the database module) that can write events in bulk to a relational DB and read them back with real filtering and pagination.

On the query side I want filters by event name (exact names, name prefixes, and exclusion lists), by the primary resource (resource IDs, ID prefixes, and labels with wildcard matching), by "any" resource meaning primary or related, by related resources (ID, role, label, wildcards), and by event ID. Results order by occurrence time, defaulting to descending but ascending works too. Pagination should hand back a page of events plus a total count plus an opaque token for the next page, and the tokens need to be stable across pages. One gotcha: an empty related-resource filter should be a no-op, don't let it accidentally drop events that have no related resources.

For counting, I want to group by time interval (seconds, minutes, hours, days, weeks), by event type/name, or by primary resource. Time buckets have to be anchored to a fixed reference point so overlapping queries over the same window line up on the same boundaries, and empty intervals get backfilled with a zero count. Also validate the interval isn't too tiny (minimum 0.01 units) and that the total bucket count stays within a sane limit, erroring otherwise.

Oh and I need a cross-db helper to pull a JSON field out of a column that works on both PostgreSQL and SQLite, including a mode that handles dotted key names by wrapping them in quotes in the SQLite JSON path syntax. Last thing, there's an import that checks which major version of the data validation library is installed, it should use the correct boolean constant from that library's internal compatibility module.
