I'm working on a GraphQL schema engine and I want to add support for composable resolver expressions on fields. Right now, each field can only have a single resolver type — HTTP, gRPC, GraphQL, or a constant — but I'd like to be able to combine these into conditional expressions directly in the schema.

Specifically, I want a new field-level directive that takes a resolver expression supporting all the existing resolver types plus a conditional branching variant. The conditional should have three required parts: a condition expression, a branch to evaluate when the condition is truthy, and a branch to evaluate when it is falsy. At runtime, it should evaluate the condition and return the result from the appropriate branch.

When the directive is misconfigured — for example, if the required expression argument is missing, if an unknown expression type is specified, or if any of the three required parts of the conditional are absent — the validator should produce precise, structured error messages indicating what went wrong and where. Fields using this directive should be recognized as properly resolved (not flagged as missing resolvers). The server-side schema should also be able to serialize and deserialize the directive in a round-trip-safe way, and the client-facing schema should strip the directive so those fields appear as plain fields to consumers.
