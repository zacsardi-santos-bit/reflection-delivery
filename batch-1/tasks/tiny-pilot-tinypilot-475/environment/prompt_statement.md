I'm building out the update-job persistence bits for TinyPilot and I need a new `update_result` module (put it at `@app/update_result.py`) that can round-trip the outcome of an update operation to and from a JSON file on disk. Right now there's nothing structured for this, so I can't tell after the fact whether an update succeeded or failed, what the error was, or when it ran.

What I want is a `Result` dataclass holding three fields: `success` as a bool, `error` as a str, and `timestamp` as a datetime. Then two functions, `read()` and `write()`, that handle the serialization. The on-disk JSON should have exactly those keys, `success` (boolean), `error` (string), and `timestamp` as an ISO-8601 string. The timestamp format I'm after looks like "2021-02-10T085735Z", so it's the date, a T, then hours minutes seconds mashed together with no colons, and a trailing Z for UTC.

`write()` takes a Result and a file object (or path) and dumps the JSON out. `read()` goes the other way, parses the JSON and hands back a Result. Oh and the important bit: reading needs to be forgiving about incomplete data, so if I feed it an empty JSON object `{}` it shouldn't blow up, it should just fall back to sensible defaults, `success=False`, `error=''`, and `timestamp` set to the Unix epoch (1970-01-01 at midnight UTC). Same idea if any individual key is missing, just use those defaults for whatever's absent.
