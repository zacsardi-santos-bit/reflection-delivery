I'm cleaning up the Button component API in our gestalt design system and the width prop is driving me nuts. Right now there's a prop that describes the "inline" state, but the default with no prop set actually gives you a full-width button, which is exactly backwards from what the name implies. People keep setting it explicitly just to get the non-default behavior and it's created a ton of boilerplate and misuse. I want to flip this to an explicit `fullWidth` boolean that defaults to false, so no prop means inline (sized to content) and you add `fullWidth` only when you want the button to expand to fill its container.

So the Button component itself needs to accept `fullWidth` instead of the old inline prop, and the internal link wrapper needs the same swap with the layout logic inverted correspondingly (what used to be driven by inline now keyed off fullWidth in the opposite sense). The old prop goes away entirely.

Since this inverts the default, existing code has to migrate carefully or we get regressions. I need a codemod (automated transform) living in a versioned codemods directory that handles the Button imported from gestalt and covers three cases: a button with no width-related prop should gain `fullWidth` (to preserve its current full-width rendering), a button using the old inline-as-true shorthand should just have that prop removed since inline is the default now, and a button with the old prop explicitly set to false should get `fullWidth` added instead. Point is the migration tool keeps behavior identical while the new API stays self-documenting.
