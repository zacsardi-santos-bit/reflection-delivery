I'm adding a new Prowler security check for AWS CodeBuild that flags projects storing sensitive credentials, like cloud access keys, as plaintext environment variables. The whole point is that secrets sitting in plaintext project config are visible to anyone with read access, so we want automated detection to catch these at scale. Variables stored securely via a parameter store type should always be treated as safe and never flagged.

The check needs to iterate over every CodeBuild project and return exactly one finding per project. Projects with no environment variables, or where all the plaintext ones are non-sensitive or excluded, get a PASS. A project fails if at least one plaintext variable contains a detectable secret (run each plaintext value through the secret detection). The fail message should call out the detected secret type and the variable name for each problematic variable, and when there's more than one, list them comma-separated.

Also I want a configurable exclusion list so folks can name specific env var names to skip during scanning, which lets us suppress known false positives without turning off the whole check. That means updating the config file to add the new exclusion setting, defaulting to an empty list.

On the data model side, the CodeBuild project model needs to carry the list of environment variables, each one having a name, a value, and a type, so the check can actually see the plaintext values and their storage type. Wire the new check into the codebuild service the same way the existing checks there are structured (metadata, execute, findings), and make sure the securely-stored types just don't get scanned at all.
