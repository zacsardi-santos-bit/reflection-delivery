I'm working on a Go codebase and ran into a situation where upgrading the UUID library broke compilation across multiple packages. The older UUID generation functions that produced time-based identifiers with MAC address embedded, or purely random IDs, were removed in the newer library version. Now entire packages won't compile — causing hundreds of tests to fail even though those tests have nothing to do with unique ID generation at all.

I need to do two things: first, upgrade the UUID library version in go.mod (and update go.sum accordingly) to one that includes the modern time-ordered UUID generation function. Second, migrate all the places throughout the production code and test support files that use the old UUID generation approaches to use the new time-ordered UUID format instead. This affects a large number of files across many packages — service configuration files, session setup, pipeline construction, compilation utilities, transaction ID generation, object ID generation, and more.

Beyond fixing the compilation issue, there's also a correctness concern: the old time-based format embedded the machine's MAC address into the identifier. In containerized environments, those embedded bytes can accidentally match Docker-specific network interface prefixes, which causes certain assertions to fail. The new time-ordered format avoids this entirely since it uses random bits for the node portion rather than the MAC address.

Can you update the library dependency and replace all the deprecated UUID generation calls across the codebase with the modern time-ordered format so the packages compile again and the MAC address embedding issue is resolved?
