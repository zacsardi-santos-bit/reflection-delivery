I'm hitting a wall on our Go codebase after bumping the UUID library. The newer version dropped the old generation helpers we relied on, the ones that made time-based IDs with the MAC address baked in and the purely random ones too, so now a bunch of packages just won't compile and hundreds of tests are red even though most of them (privilege checks, session handling, protocol stuff, SQL compilation) have nothing to do with generating IDs. They just live in packages that can't build.

So two parts here. First I need the UUID dependency in go.mod moved up to a version that actually has the modern time-ordered generator (the v7 format), and go.sum updated to match. Second, migrate every spot that still calls the removed or deprecated generation functions over to the time-ordered format instead. This is spread wide across production code and test support files, think service config for compute nodes and transaction nodes and log services, session setup, pipeline UUID construction, computation wrappers, compilation utilities, segment and object ID generation, transaction ID generation, and the test cluster configs too.

Oh and there's a real correctness reason beyond just getting it to compile. That old time-based format embedded the machine's MAC address into the ID bytes, and in Docker and containerized environments those embedded node bytes can accidentally match Docker-specific network interface prefixes, which trips assertions that explicitly guard against exactly that. The v7 time-ordered format sidesteps it since the node section is random bits, not the MAC. So after the migration none of the generated identifiers should carry MAC address bytes and none of them should match those Docker network prefix patterns. Once it's all swapped over I want every previously failing package to compile again and their full test suites to pass.
