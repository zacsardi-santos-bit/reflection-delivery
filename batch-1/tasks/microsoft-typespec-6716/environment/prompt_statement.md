I'm working with the TypeSpec C# client generator and I've noticed an issue with how it handles list operations that don't have actual pagination. I have an API operation that returns a list of items wrapped in a response object, and I've annotated where the items live in that response — but I haven't added any next-page link or continuation token because this endpoint just returns everything at once.

The problem is that the generator is treating this as a fully paginated operation and generating paginated streaming collection types for it, even though there's no way to page through results. What I'd expect is for the generator to recognize that without a next-page link or continuation token, this isn't actually a paginated operation — it's just a list endpoint that returns all items in one shot. The generated methods should use regular result types wrapping the full response, not paginated collection types. Additionally, no paginated collection result definition should be generated for such an operation, and the method collection should have the standard set of four methods (sync/async protocol and convenient).

Can you fix the generator so that it only treats an operation as pageable when it actually has a pagination mechanism (a next-page link or a continuation token)? Having only item location hints should not be enough to trigger the paginated code path.
