I'm building out testcontainers-go and want a proper socat module so I can relay traffic between my test host and containers that only live on an internal Docker network. Right now there's nothing built in for this so I keep wiring up socat by hand every single test setup and it's tedious and error prone. socat's that popular little network relay tool, and what I want is to spin up a relay container as part of my test setup and point it at one or more forwarding targets.

The new module should live under the modules directory (something like `@modules/socat`) and let me start the relay container and configure targets. Each target names the host to forward traffic to plus a port mapping, and I need both the exposed port and the internal port to be configurable. Sometimes the external listener and the forwarding destination use the same port, so give me a simpler constructor for that case, and sometimes they differ (say the relay listens on 9080 but forwards to 8080 on the target) so I also want a constructor that takes both ports. If I leave the internal port unspecified (zero), just default it to the exposed port. But if the exposed port itself is zero, adding that target as an option should fail with an error rather than quietly building a broken relay.

Once the relay's running I need a way to get back the reachable URL for a given forwarded port so I can make HTTP requests through the relay in my tests, oh and I want to be able to stack multiple forwarding targets on a single relay container too. The whole point is that integration tests often hit services only reachable on Docker-internal networks, not from the host, and this relay lets host-side test code reach them by forwarding through a container sitting on the same network.
