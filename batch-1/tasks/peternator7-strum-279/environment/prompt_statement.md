I'm working with a Rust enum library and I want to add a derive macro that spits out a companion table type for my enums. The idea is dead simple: for any enum with unit variants, generate a struct that holds one value of some arbitrary type per variant, basically a type-safe enum-indexed map. Right now there's no such macro, so I'm stuck hand-writing match arms or juggling hash maps and parallel arrays, and it's all error-prone and not type-safe. This is a super common pattern (a score per variant, a config option per variant, per-variant state) so I'd love to kill the boilerplate.

The generated table should be generic over the stored value type and have exactly one slot per non-disabled variant. I want default construction where every slot gets the type's default, explicit construction with one value per slot, a fill-all constructor that clones a single value into every slot, and a constructor that takes a closure called with each variant to produce its value. Also indexed read and write access using the enum itself as the key, cloning the whole table, and a map-style transform that takes a closure over each variant and its current value to build a new table of a different value type.

Oh and two convenience collectors: one that walks all option-typed slots and folds them into a single optional table (gives back nothing if any slot is missing), and one that walks all result-typed slots into a single result, returning the first error it hits if any slot failed.

Variants marked disabled should be dropped entirely, they shouldn't show up as constructor params or slots at all, and indexing with a disabled variant should panic. Also make sure variants whose names are reserved keywords still compile fine. And it's gotta be importable straight from the main library crate, not just the macros crate.
