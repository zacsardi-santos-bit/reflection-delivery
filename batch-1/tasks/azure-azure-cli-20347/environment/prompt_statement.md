I'm working on the Azure CLI's AKS module and need to add support for updating the managed identity configuration of an existing cluster during an update operation. Right now, the update decorator handles things like AAD profile and auto-upgrade settings, but there's no equivalent logic for updating the cluster's identity type.

I need a method on the update decorator class that handles the identity update step. When a user enables managed identity and provides a specific identity resource, the cluster identity should be switched to user-assigned with that resource. If managed identity is enabled without specifying a resource, it should switch to system-assigned. If the identity type would change, the user should be asked to confirm before proceeding — and if they decline, the operation should exit without applying changes. Attempting to provide an identity resource without also enabling managed identity should be rejected with a clear error. Passing an invalid cluster object should also be caught and rejected immediately.
