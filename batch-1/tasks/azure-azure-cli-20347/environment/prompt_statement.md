I'm in the Azure CLI AKS module working on the cluster update path and there's a gap I need to close, the update decorator already knows how to update things like the AAD profile and auto-upgrade settings but there's nothing that handles updating the managed identity configuration of an existing cluster. Operators want to evolve their identity strategy over time, like migrating from a service principal over to a managed identity as security requirements shift, and right now there's no supported path so they end up recreating clusters or doing hacky workarounds which is disruptive and error prone.

So I want a method on the update decorator class that handles the identity update step during an update operation. The logic goes like this: when a user enables managed identity and also passes a specific identity resource, the cluster identity should switch to user-assigned using that resource. If managed identity is enabled but no resource is given, it should switch to system-assigned instead. If the identity type would actually change as a result, prompt the user to confirm first, and if they decline the operation should exit gracefully without applying any changes (confirming or bypassing the prompt with a flag lets it proceed). Also if someone passes an identity resource without enabling managed identity that's invalid and should be rejected with a clear error, oh and passing an invalid cluster object should get caught and rejected immediately too.
