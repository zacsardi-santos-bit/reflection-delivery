I've been working on the blank line style rules in this Python linter, and I've run into a crash that I can't figure out. When the linter processes a Python file that has a "blank" line containing only whitespace characters — like a line with just a couple of spaces or a single tab — it panics with an internal assertion failure instead of producing normal diagnostic output. This kills all six blank-line rules at once, so no violations are reported at all for files that hit this pattern.

What I'd expect is that the linter treats these whitespace-only lines as blank lines (the same way it treats truly empty lines) and continues analyzing normally. Concretely, if a function body has one genuinely empty blank line immediately followed by a line with only a space in it, the linter should flag that as two consecutive blank lines and emit the appropriate "too many blank lines" violation. Similarly, if two methods inside a class are separated by two lines that each contain only a tab character, those should count as two blank lines and also trigger the "too many blank lines" rule. On the other hand, if there's only one such whitespace-only blank line followed by a comment that's oddly indented, the linter should not emit any violation — just one blank line, which is fine.

I also need all the stored expected-output snapshots for the six blank-line rules to be updated so the tests reflect the corrected behavior and the new line numbers introduced by the added test cases.
