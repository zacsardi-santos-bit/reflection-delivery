I'm working on the Cairo docs tooling and I need a way to grab an item's formatted signature along with the exact positions of every type reference inside that signature. Right now I can get a signature string for a documentable item, but there's no way to know where each referenced type name starts and ends within that string, which makes turning them into clickable links in the rendered docs basically impossible. So I want a new query that takes any documentable item and hands back both the formatted signature (or nothing, for items that just don't have signatures) plus a list of start/end character positions marking every referenced type in that string. The idea is documentation renderers can cross-reference types without manually parsing the text. Oh and if a type can't be resolved at all (say it was never declared), the signature should drop in a placeholder token there instead of crashing or leaving things blank, and no link position should be emitted for that spot.

Impl block declarations and extern type declarations are missing their trailing semicolons, so those need to be added. And function parameter lists sometimes wrap across multiple lines when they should just stay on one line, so params always need to render on a single line. Please fold those formatting fixes in too so the existing signature output comes out correct alongside the new positions query.
