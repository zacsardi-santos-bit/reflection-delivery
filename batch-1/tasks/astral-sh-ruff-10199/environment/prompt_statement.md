I'm working on the quote-style rules in our Rust Python linter and hit a nasty auto-fix bug I need you to fix. When Python source has implicit string concatenation, meaning adjacent string literals sitting next to each other without any explicit `+` or concat operator, our linter will happily offer to convert a token to the preferred quote style even when doing so corrupts the file. The problem is that converting one of those adjacent strings can put three identical quote chars right at the boundary between two strings, and Python reads that as the start of a triple-quoted string, which totally changes the meaning and throws a syntax error.

There are two patterns where this bites. First, an empty string using the wrong quote style immediately followed by a string in the preferred style, so converting the empty one lands two preferred quotes next to the opening quote of the neighbor and you get the triple sequence. Second, a string that's immediately preceded by two consecutive preferred-style quote chars (coming from an adjacent token), so converting it also produces the triple-quote run.

For those specific tokens I still want us to report that the quote style is wrong, that part's correct, but we must not hand back an autofix for them since it'd break the code. Other tokens in the same implicit concatenation that convert cleanly should still get their normal auto-fixable diagnostics. This needs to cover both regular inline strings and strings sitting in docstring positions, so whatever handles those two cases (the inline quote check and the docstring-position quote check) has to detect the dangerous boundary and drop the fix just for the offending token. Practically that means the violation kinds for both inline and docstring strings need to express that a fix is only sometimes available rather than always, since within one concatenation some tokens are fixable and some aren't. The whole reason this matters is people running fix-all workflows would silently end up with invalid Python, so let's be careful to keep the diagnostic but skip the unsafe fix exactly in these boundary cases.
