I'm working on the Tact compiler and noticed that the built-in debugging output function doesn't validate what type of value you pass to it. Right now, you can call it with a custom primitive type that it has no way to handle — like an internal string builder — and the compiler won't complain. It just silently accepts it. This means the error only surfaces later, in a much less obvious way.

I'd like the compiler to do a type check on the argument at compile time and produce a clear error message if the type isn't one of the standard supported types. All the normal types should still work fine: integers, booleans, strings, addresses, cells, builders, slices, null, void returns, optional types, and maps. But anything outside that set — like a custom or non-standard primitive — should produce a helpful compile-time error that names the problematic type and points the developer to the documentation.
