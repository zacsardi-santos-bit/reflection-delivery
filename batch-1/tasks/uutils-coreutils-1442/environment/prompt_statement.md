I'm hacking on a Rust reimplementation of the coreutils and I've got two annoying failures to sort out. First one is a WSL thing. When the suite runs under Windows Subsystem for Linux a bunch of disk usage checks blow up because `du` reports fewer blocks for subdirectories and for symbolic and hard links than a real Linux kernel does, so the expected block counts need to be WSL-aware and branch to WSL-appropriate values when we're in that environment. On top of that the group-change (`chgrp`) reference-option test misbehaves on WSL thanks to a known bug where non-root users get wrongly handed elevated privileges for ownership ops, so the command succeeds when it shouldn't, and I want that test skipped on WSL the same way it's already skipped when running as root. To make both of those possible I need a shared helper added to the test utilities that tells me whether we're currently running under WSL, on Linux it should detect this by reading the well-known kernel info file (like `/proc/sys/kernel/osrelease`) and checking for the WSL marker, and on any non-Linux platform it should just return false.

Second issue is in the `stat` utility, it's computing birth/creation time wrong. When I use the format specifiers for human-readable creation time and creation time in seconds, the output disagrees with the system's own stat. Looks like it's measuring elapsed time from creation until now instead of the actual creation timestamp relative to the Unix epoch, so I want it fixed to agree with system stat. Oh and when birth time isn't supported by the kernel or filesystem it should print the same "unknown" sentinels the real stat uses, "-" for the human-readable form and "0" for the seconds form.
