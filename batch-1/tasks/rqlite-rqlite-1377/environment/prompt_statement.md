I'm working on upgrading rqlite to a newer version, but I've run into a problem with nodes that have existing snapshot data from an older release. When I start a node with the old data directory, the node can't properly load the snapshots because the snapshot storage format changed between versions. I need a way to automatically migrate snapshots from the old format into the new generation-based layout when the node starts up.

The migration should handle a few cases gracefully: if the old snapshot directory doesn't exist at all, or if it's empty, the migration should just do nothing and return successfully. If the old directory contains valid old-format snapshots, it should pick the most recent one, convert it into the new format, and write it into the new directory. After a successful migration, the old directory should be cleaned up so it doesn't get processed again on the next startup.

Once migration is complete, the snapshot storage in the new directory should behave correctly — the current generation directory should be present, listing snapshots should return the migrated snapshot with its original ID, and opening that snapshot should return matching metadata. Most importantly, a node started with old snapshot data should be able to come up as leader and correctly answer queries against the database, returning results that reflect the data captured in those snapshots.
