I'm upgrading rqlite and hit a wall with nodes that already have snapshot data from an older release. When I point a node at its old data directory it can't load the snapshots because the on-disk format changed. The old layout doesn't match the new generation-based storage we use now, so the node basically loses access to everything it had snapshotted, which kind of defeats the whole point of taking snapshots. I need the node to automatically migrate old-format snapshots into the new generation-based layout on startup, no manual steps.

A few cases the migration has to handle cleanly. If the old snapshot directory doesn't exist at all, or it exists but is empty, migration should just do nothing and return successfully, no error. If the old dir has valid old-format snapshots, it should pick the most recent one, convert it into the new format, and write it into the new directory. And after a successful migration the old directory should be removed so we don't try to re-migrate it on the next startup (double-migration would be bad).

Once migration's done the new storage should behave right: the current generation directory should exist, listing snapshots should return the migrated one with its original ID intact, and opening that snapshot should give back matching metadata. Most important bit, a node started against old snapshot data should come up as leader and correctly answer queries against the db, returning results that reflect whatever data was captured in those snapshots. This matters because folks doing in-place upgrades between major releases need to trust their data survives, otherwise any long-running deployment loses its history and upgrades become impractical for production.
