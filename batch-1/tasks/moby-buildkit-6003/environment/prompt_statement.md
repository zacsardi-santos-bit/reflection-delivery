I'm adding a "raw" socket forwarding mode to BuildKit and could use a hand wiring it through. Right now when a Unix socket gets forwarded into a build container the socket forwarding mechanism always wraps it in SSH agent protocol handling, which is annoying because I can't forward arbitrary Unix domain sockets like a plain HTTP server listening on a socket, or a database listener, or some custom IPC thing, without adding protocol translation nobody wants. So the goal is a raw mode where any Unix socket on the build host gets forwarded straight into the container with no SSH agent wrapping at all.

Concretely I need the socket config struct in the SSH provider package to grow a boolean field for turning on raw mode, and then the provider logic has to branch so that when raw is set it just connects to the backend socket and proxies bytes directly instead of going through the SSH agent protocol. Also the command-line argument parser for the build tool needs to understand a "raw" key-value option in the comma-separated socket config string, and it should be able to appear in any order relative to the socket path (before or after, doesn't matter).

For validation, raw mode only makes sense with exactly one Unix domain socket path, so passing zero paths or more than one path should be an error, and passing a regular file path that isn't actually a socket should error too. When it's all valid I want the provider to transparently proxy bidirectional byte streams between the forwarded connection and the container, and that needs to handle multiple sequential messages and large payloads correctly without dropping or corrupting anything. btw the ordering of the raw flag in the config string parsing is the part I keep second-guessing so make sure that's solid.
