I'm working with the Terraform Azure provider and running into an issue when managing Data Factory pipelines that include web activities with expression-typed HTTP headers. Azure Data Factory allows a header value to be either a plain string or a structured object (like an expression with a value and a type), but the provider's underlying SDK client only handles one format. As a result, any pipeline that uses expression-typed headers in a web activity fails when Terraform tries to read it back — the provider can't properly deserialize the pipeline from the API response.

To fix this, I need to introduce a compatibility layer within the datafactory service package that wraps the existing SDK pipelines client and uses custom types for the pipeline resource and its activities. This wrapper needs to expose the same interface as the existing client so it can be used as a drop-in replacement for reading and writing pipelines, but it should use a custom pipeline activity model that treats web activity headers as a flexible type capable of holding either strings or structured objects.

The wrapper must be implemented as a new sub-package within the datafactory service directory and must be importable by both the pipeline resource implementation and its test code. The existing test infrastructure for the pipeline resource already expects to use this wrapper when verifying that a pipeline exists in Azure.
