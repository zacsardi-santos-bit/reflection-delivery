I'm building a feature where I need to inspect what route a given URL maps to — including its full route name, any dynamic URL segments, query parameters, and even the data the route would load — without actually navigating to that URL or changing what's currently rendered on screen.

Right now the router service only supports navigating to routes. I need two new capabilities on it: one that synchronously returns basic route information for a URL (or nothing if the URL isn't recognized), and one that asynchronously fetches and loads the model for the matched route, resolving with the full route details including loaded data.

Both methods should leave the current application state completely untouched — no transitions, no re-renders, no URL changes. If I pass a URL that doesn't match any known route, the synchronous version should return nothing (indicating no match) and the async version should reject with a message identifying the unrecognized URL. If the application uses a custom URL prefix (root URL), both methods should require that the provided URL starts with that prefix, and raise an informative error if it doesn't. If loading the model for a route fails with an error, the async version should reject with that error.
