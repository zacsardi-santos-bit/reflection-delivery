I'm building out our JSX accessibility linting and there's a real gap I keep hitting: nothing stops someone from slapping an `aria-checked` on a link or `aria-expanded` on a plain `ul`, and those attributes just silently do nothing because the element's implicit ARIA role doesn't include them. So we ship markup that looks accessible but actually confuses screen readers, marking a link as checked or invalid, marking a list as expanded, that kind of thing, and visual testing never catches it. I want a new lint rule that closes this.

The idea is for each JSX element, figure out the implicit ARIA role from the tag name plus the relevant attributes (so input type matters, and whether an anchor actually has an href matters), then check the ARIA attributes present against what that role supports. When an attribute isn't supported by the element's role, flag that element and say clearly which aria attribute is the unsupported one, and include guidance telling the dev to make their ARIA attributes valid for the element's role.

A few things it should skip since we can't figure out the effective role statically: custom components, anything with spread props, and elements that carry an explicit presentation role, don't flag those. And obviously don't flag when the attribute genuinely is supported by the role, that's the whole point. This lives with the other JSX a11y rules so wire it up the same way the existing ones are registered and tested.
