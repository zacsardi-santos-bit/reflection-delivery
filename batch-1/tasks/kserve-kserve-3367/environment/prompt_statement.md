I'm working on the inference graph feature and the router container doesn't have a readiness probe, which is biting us. Right now Kubernetes has no way to know when the router is actually up and ready to serve, so pods get traffic before they're initialized, and when a router is shutting down traffic keeps hitting it instead of draining first. I want to add a readiness probe to the router container so k8s can manage its lifecycle properly, meaning graceful startup (no requests until it's really ready) and graceful shutdown (the router can signal non-ready so in-flight requests drain before the process dies).

The important bit: the same probe needs to be applied consistently whether we deploy with raw Kubernetes resources or via Knative services. Both code paths that build the router container spec should end up with the identical readiness probe. So rather than defining it twice, I'd like the probe config living in one central shared location where the router container spec gets built, and then reused from both the raw k8s deployment path and the Knative path. That keeps them from drifting.

Basically: define the readiness probe once, wire it into both deployment modes, and make sure a shutting-down router reports itself not-ready so traffic gets drained before termination.
