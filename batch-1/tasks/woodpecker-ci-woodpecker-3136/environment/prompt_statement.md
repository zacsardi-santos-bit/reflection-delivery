I'm cleaning up how we report pipeline step failures and the current wording bugs me because it leans on the step's display name. Problem is step names aren't unique, you can have the same name across different pipelines or in parallel runs, so when something blows up it's a pain to figure out which exact step instance actually failed. I want to switch the error types over to use the step's unique identifier instead of the name.

Two cases to cover here. When a step exits with a non-zero code, the error message should call out the step's unique identifier followed by the exit code value, so I can immediately see which instance and what code it died with. And when a step gets killed because it ran out of memory, the message should show the unique identifier along with an out-of-memory kill indication instead of the name.

The whole point is observability, if the same step name shows up in multiple pipelines or concurrent runs the name is ambiguous, but the unique id lets me trace an error straight back to the specific step instance in logs, dashboards, and debugging sessions. So please update the error type definitions and their formatting to carry and print the unique identifier rather than the human-readable name for both the exit-code failure and the OOM-kill failure.
