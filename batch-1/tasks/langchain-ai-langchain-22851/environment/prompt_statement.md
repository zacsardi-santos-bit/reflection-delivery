I'm hitting a gap with chat prompt templates and their input schemas. When I've got a template that mixes regular string variables with message history placeholders, some of those placeholders are required and some are optional, and when I introspect the JSON schema that describes the expected inputs, there's no required field listed at all. So everything looks equally optional from the schema's point of view even when a variable is clearly mandatory and would blow up validation if omitted.

That's a real problem because I'm leaning on the schema to tell downstream consumers (doc generators, validation layers, anything auto-filling defaults) which inputs they actually have to provide. Right now someone reads the schema, sees nothing marked required, skips a mandatory input, and only finds out at runtime. I want the input schema for a chat prompt template to include a proper required field that lists every non-optional input variable by name. A message placeholder marked required should show up in that required list, one marked optional shouldn't appear there at all. And the regular string template variables, the named placeholders declared inside message templates, should always land in the required list since they're always mandatory with no optional flag.

Also the schema should actually behave when validating: if someone tries to validate inputs against it and they've left out one of those required fields, that should raise a validation error rather than silently passing. Basically I want the schema to line up with the template's real runtime validation behavior so it stops lying about what's optional.
