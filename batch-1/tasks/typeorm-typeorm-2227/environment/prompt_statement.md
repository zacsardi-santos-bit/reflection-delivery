I'm working with TypeORM and I keep hitting a wall where I can't set the isolation level on a transaction. Right now the transaction method only takes a callback and everything just runs at the database's default level, so I've got no control over dirty reads, non-repeatable reads, or phantom reads per transaction. I want to be able to pass an isolation level as the first argument so the transaction actually starts at that level, then the callback runs inside it. Think read-uncommitted, read-committed, repeatable-read, and serializable as the four standard modes I should be able to ask for.

This needs to work both ways, through the direct entity manager transaction call and through the method decorator too. For the decorator, instead of just accepting a connection name string I want to pass an options object that carries both the connection name and an isolation level.

Different drivers support different subsets so each one should handle this per its own capabilities. SQLite for instance only supports two of the four levels, so it should apply the right internal PRAGMA config before beginning the transaction when a supported level is requested, and reject the ones it can't do. The full-range databases should just pass the requested level through when starting the transaction.

And obviously after the transaction commits, anything I saved inside it should be findable via normal queries, exactly like it would be if I hadn't specified any level at all. Basically don't break the committing behavior, just add the level knob on top. This lets teams doing long-running reports, batch updates, or sensitive financial stuff configure isolation through TypeORM instead of dropping down to raw SQL.
