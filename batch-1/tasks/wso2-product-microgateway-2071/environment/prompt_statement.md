I'm working on an API gateway that forwards traffic to backend services, and I keep hitting this problem where when a backend is slow or unresponsive the gateway just never times out. It holds the connection open indefinitely, there's no maximum request duration or idle connection limit enforced anywhere at the routing level. This can lead to resource exhaustion and generally unpredictable behavior for API consumers because there's no gateway-level guarantee that a slow or hanging backend will ever produce a client-visible error. I want the gateway to lean into being a protective layer against slow dependencies instead of just passing the hang through.

So what I'm after is having the gateway automatically apply default timeout values to all upstream routes it creates, applied whenever it generates routing configuration for an API. Two things really: a maximum request duration so requests to slow backends eventually get terminated and callers get a proper timeout error, and an idle connection timeout so connections sitting there with no active traffic eventually get closed and we reclaim resources. The default max request duration should be 60 seconds and the default idle timeout should be 300 seconds. Oh and these should be configurable through the gateway's config file so operators can tune them rather than being hardcoded. Basically every route the gateway builds should come out with both timeouts set.
