I'm cleaning up the geometry attribute API in my graphics rendering lib and it's more verbose than it needs to be. Right now every attribute I define has to be wrapped in a full descriptor object even when all I've got is a raw number array or a typed array or a buffer, which is annoying boilerplate. I want to be able to pass that data directly as the attribute value and have it auto-wrapped into the descriptor for me, so a plain array/typed array/buffer just works.

Also there's a naming thing that bugs me. The descriptor property that says which shader binding slot an attribute maps to uses a name that doesn't line up with modern GPU API conventions, so it confuses folks coming from those APIs. I want it renamed to match the standard slot/location naming.

On top of that I need two utilities. One parses a GPU shader program's source and pulls out attribute layout info for each vertex input, so it should return format, stride, offset, location, and the related fields per attribute. The other takes a geometry plus that shader-extracted attribute data and fills in any missing fields on the geometry's attributes, and it's gotta correctly compute stride and start offset for attributes that share the same buffer (the interleaved layout case). Basically it should infer everything the shader already tells us instead of making me specify format/stride/offset by hand for every attribute.

The point of all this is less boilerplate when defining geometry, an API that's consistent with modern GPU APIs, and letting the pipeline auto-resolve attribute layout rather than doing it all manually. So: direct data as attribute value, renamed binding-slot property, a shader-source layout extractor returning those per-input fields, and a resolver that merges shader data into a geometry including interleaved stride/offset math.
