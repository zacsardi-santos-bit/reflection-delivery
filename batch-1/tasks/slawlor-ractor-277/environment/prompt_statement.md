I'm building a supervision tree with ractor and keep hitting gaps in the child management API. When a supervisor is shutting down I want to cleanly stop or drain all its linked children right there in the `post_stop` lifecycle hook, and wait for them to fully finish, including making sure each child's own cleanup hook actually runs. Right now there's nothing built in for this so I'm stuck manually tracking and iterating over children myself, which makes correct shutdown logic in `post_stop` way harder than it should be.

So what I want on `ActorCell` (and reachable from typed actor references too) is a way for a supervisor to stop all of its linked children at once, and separately to drain all of them at once, each with the option to either wait for them to fully exit or not. Whichever variant runs, the children's cleanup lifecycle hooks need to fire properly before things wrap up.

I also want to be able to do this from *outside* the supervisor, so an external caller tells the supervisor to stop or drain all its children. When that happens the children exiting should naturally propagate stop notifications up the supervision tree and trigger the parent supervisor's own shutdown, since all child exits bubble up. And it should be safe to call these same operations from within the supervisor's own shutdown hook.

Last thing, kind of separate. Once I convert a typed actor reference into a type-erased cell I lose the generic message type info, and I'd like to check at runtime whether that actor actually handles a given message type. For local actors this should give a definitive yes or no, and for remote actors it should just indicate the check can't be performed. Handy for generic containers and routing logic that need to verify compatibility without the static types around. This all lives around `ActorCell`, btw.
