I'm extending our cloud security scanner to cover DocumentDB at the cluster level, not just individual instances. Right now we only look at instances for one thing (storage encryption), but clusters are the real management unit in AWS and most of the security-relevant settings live there, plus the instance-level encryption check doesn't line up with how AWS Security Hub reports DocumentDB compliance. Security teams need this cluster visibility to satisfy common compliance frameworks, otherwise stuff like missing backups, no deletion protection, disabled audit logs, or unencrypted storage just slips through undetected.

So I need four new cluster-level checks. First one checks that automated backups are on with a retention period meeting a configurable minimum that defaults to 7 days. A cluster with no backup at all should fail, one that has some backup but sits below the minimum should also fail but with guidance to bump up the period, and anything at or above the minimum passes. Second check verifies both audit and profiler logs are being exported to the centralized monitoring service, so no logs fails, only one of the two enabled still fails as incomplete, and both exporting passes. Third check just confirms deletion protection is enabled, fail if it's off, pass if on. Fourth check verifies cluster storage is encrypted at rest, unencrypted fails, encrypted passes, and this one replaces the old instance-level encryption check which should be removed entirely.

To make all this work the service layer needs to actually fetch and expose cluster data from the provider API, not just instance data, so the data model has to carry the backup retention period, the log export config, deletion protection status, encryption status, and the other standard cluster attributes the checks read from.
