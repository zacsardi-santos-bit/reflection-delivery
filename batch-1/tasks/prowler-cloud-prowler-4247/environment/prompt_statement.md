I'm working on adding cluster-level security checks for DocumentDB to our cloud security scanning tool. Right now the tool only checks individual database instances, but DocumentDB clusters are the real unit of management and several important security settings live at the cluster level.

I need four new security checks that operate on clusters rather than instances. One check should verify that automated backups are enabled with a retention period that meets a configurable minimum threshold — clusters with no backup at all should be flagged differently from those that have some backup but below the recommended minimum. Another check should verify that both audit and performance logs are being exported to the centralized monitoring service; if only one of the two log types is configured, it should still be flagged as incomplete. A third check should verify that deletion protection is turned on for each cluster. A fourth check should verify that cluster storage is encrypted at rest — this one replaces the existing instance-level encryption check, which should be removed.

To support all of this, the underlying service layer needs to fetch and expose cluster data from the cloud provider API, not just instance data. The data model needs to include fields for backup retention period, log export configuration, deletion protection status, encryption status, and the other standard cluster attributes.
