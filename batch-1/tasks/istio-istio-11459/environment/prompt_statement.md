I'm in the RBAC authorization plugin under Istio's networking layer and need to make a few changes that hang together. First off, the function that builds a metadata list matcher hard-codes a single filter namespace right now, and I want it to take the filter name as an explicit parameter instead so I can target different filter namespaces, like the authentication filter for JWT claim checks, or other filters for protocol-specific attributes. So thread that filter name through as an argument rather than baking it in.

Also the functions that build the TCP and HTTP RBAC filters take a separate boolean for proxy version detection that picks which config encoding to use, and I want that gone. Drop the version param entirely and always emit the struct-based encoding format, no more conditional logic. The TCP vs HTTP distinction should just come from the existing options struct internally, so those builders end up taking only the service and options args, and every call site gets simpler.

Oh and I need support for authorization policy constraints that match metadata produced by arbitrary Envoy network filters (think a MySQL proxy exposing which tables a client hits). The key naming uses an experimental prefix followed by the filter name and a bracketed metadata key, so it's a "prefix[key]" binary format: some text before the opening bracket, non-empty content inside, ending with the closing bracket. I want a helper that detects whether a key is in that format, and then the policy conversion logic should call it to generate the right metadata matcher, a list matcher when the constraint value is itself in bracket notation, or a string matcher otherwise. Without this it's impossible to write policies that enforce access control on protocol-specific connection metadata, and killing the per-call version detection cleans up the fragile bits too.
