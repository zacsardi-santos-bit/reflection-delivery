I'm working on the control plane polling component in the router and I want to add jitter so a bunch of router instances don't all hammer the config server at the exact same moment. Right now the poller just takes a fixed poll interval and every instance fires on the same cadence, which is a classic thundering herd against the configuration backend. What I want is to pass in a maximum jitter duration alongside the interval so each instance can offset its poll cycle by a small random delay and spread the requests out over time.

So the polling component should accept both the poll interval and a max jitter duration at creation. If either value is bad it should panic right there at creation time so a misconfig blows up loudly at startup instead of doing something weird at runtime. Specifically a zero or negative poll interval should panic, and a negative jitter max should panic too. A jitter max of zero is totally fine, that just means no jitter gets added.

Oh and the underlying random delay generator utility needs to follow the same rules: panic on negative input, return zero when the max is zero, and return some random value within the allowed range when the max is positive. Even a small per-instance offset smooths out the request distribution a lot and keeps the backend stable under load.
