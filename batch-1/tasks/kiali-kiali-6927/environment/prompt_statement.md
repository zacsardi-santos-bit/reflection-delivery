I'm working on Kiali's multi-cluster support and I keep hitting a gap. Right now Kiali only shows clusters it has direct API access to, so if it doesn't have credentials for some remote cluster (network isolation, missing creds, or just intentional separation), that cluster is completely invisible in the clusters listing. In real deployments you often have two separate Kiali instances on isolated clusters and you'd want each one to at least know the other exists and ideally link to it. So I want to configure these "inaccessible" clusters in the Kiali config so they still show up in the clusters listing even without an active connection.

A few things need to happen. Each cluster in the API response should carry an explicit flag saying whether it's accessible, so the frontend can treat accessible and inaccessible clusters differently, and accessible ones get marked as such too. Configured Kiali instance URLs for the inaccessible clusters should be included in the response so users can navigate to the remote Kiali. Oh and if a Kiali URL is configured for a cluster that already exists in the accessible list, it should enrich that existing cluster rather than create a duplicate entry.

Also the method that retrieves clusters needs to stop depending on the incoming HTTP request, it was using the request to guess Kiali's own URL which isn't clean, so drop that dependency. And cluster discovery needs to work in namespaced (non-cluster-wide) mode, not just when Kiali has cluster-wide access. On the interface side there's some cleanup too: rename the cache layer's service lookup methods so they're more clearly named, and change the router and server constructors so they accept their dependencies explicitly instead of reading from global state. This all lives in the Kiali backend around the business/cluster code and the cache and server/router setup.
