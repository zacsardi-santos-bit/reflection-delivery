I'm working on Kiali's multi-cluster support and need to add the ability to show clusters that Kiali knows about but can't directly connect to. Right now, if Kiali doesn't have credentials for a remote cluster, that cluster simply doesn't show up anywhere in the UI. But in many real deployments, you have two completely separate Kiali instances on isolated clusters, and you'd want each one to at least know the other exists — and maybe link to it.

I need to add support for configuring these "inaccessible" clusters in the Kiali config so they appear in the clusters listing even without an active connection. Each cluster in the response should carry a flag indicating whether it's accessible, so the frontend can treat accessible and inaccessible clusters differently. Configured Kiali instance URLs for inaccessible clusters should also be included so users can navigate to the remote Kiali.

A few things need to happen: the method that retrieves clusters needs to stop depending on the incoming HTTP request (it was using the request to guess Kiali's own URL, which isn't a clean approach). The cluster discovery also needs to work in namespaced mode, not just when Kiali has cluster-wide access. And when a Kiali URL is configured for a cluster that already exists in the accessible list, it should enrich that cluster rather than create a duplicate entry.

On the interface side, there are also some method renames needed to make the cache layer's service lookup methods more clearly named, and the router and server constructors should accept their dependencies explicitly rather than reading from global state.
