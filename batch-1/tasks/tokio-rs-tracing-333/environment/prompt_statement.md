I'm having trouble with the filter directive system in the tracing subscriber. When I configure two filters that have similar structural properties — like two targets with the same number of characters, or two directives that both apply to a span with the same name but different fields — one of the filters silently stops working. For example, if I set up a filter to enable tracing for two different targets that happen to be the same length, only one of them actually gets enabled. The same problem happens when I have two span filters that share a span name but each matches a different field, or when I configure two event field filters that each require a single (but different) field to be present.

It seems like the code that decides the priority order of directives doesn't handle the case where two directives are "equally specific" under the current comparison logic. Instead of both being applied, one effectively shadows the other. I'd like the filter to correctly apply all matching directives independently, so that events and spans pass through as long as any one of the configured directives matches them.
