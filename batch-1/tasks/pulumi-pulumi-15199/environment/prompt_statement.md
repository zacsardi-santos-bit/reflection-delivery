I'm working on extending the import plugin system so that plugins can communicate richer information about each resource they surface during state conversion. Right now, when an import plugin returns resources, it can only describe basic properties like the resource type, name, ID, version, and provider download URL. But I need plugins to also be able to specify whether a given resource is a component, whether it is a remote component, and what its logical name should be. These properties need to flow correctly through both sides of the plugin boundary — from the plugin server back to the plugin client — so the engine receives the full picture. Could you add support for these three additional properties to the resource import data structure and make sure they are properly passed through when converting state?
