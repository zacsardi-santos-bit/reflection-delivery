I'm hitting a wall with the macOS Homebrew module when a package name is ambiguous, like the same name being both a command-line formula and a desktop cask. A bunch of the functions in there just don't let me pass extra flags down to brew, so I can't tell it which variant I actually mean, and the operation either hits the wrong thing or fails outright. The ones that need this are the latest-version lookup, uninstall, the fetch for installed package info, and the list of available upgrades.

What I want is for each of those to take an optional list of additional flags that get forwarded to the package manager, and placement matters here: when I pass those flags they should land after the base subcommand flags but before any package name arguments in the generated command. That's the key spot.

Also two more things while you're in there. The version lookup right now only handles one package type, but it needs to work for both formula-type and cask-type packages, and each stores its version in a different field so pull from whichever format the package uses. And oh, when a formula has published aliases, the installed package listing should include those aliases as separate entries too so the package is findable by any of its known names.

This all comes up because folks with packages from custom taps, or packages that exist in both formula and cask forms, currently can't do common operations unambiguously. The options passthrough fixes that and makes it usable across more real Homebrew setups.
