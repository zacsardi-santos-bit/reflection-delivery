I'm on a quantum simulator that can do non-commuting measurements all in one execution, but it won't natively measure expectation values of multi-term Hamiltonians or sums of observables. I need a new circuit transform that expands those multi-term expval measurements into individual single-term measurements, all kept on the same tape (not split across multiple circuit executions like the existing non-commuting splitting transform does, that one distributes terms across separate runs which is wasteful when the sim can already handle everything in a single pass). After the split I want a postprocessing step that recombines the single-term results back into the correct multi-term values.

Also it should dedupe: if the same observable shows up in multiple different expval measurements, measure it once and reuse that shared result across all the originals. Identity terms should just become plain numeric offsets, no point burning a device measurement on those. And when the incoming circuit already has only single-term or wire-based measurements, leave it basically untouched with minimal overhead.

The transform needs to be differentiable across the major autodiff frameworks, and work with batches of circuits, shot vectors, and batched parameters. Please wire it into the standard transforms API so it's accessible like the others.

Oh and one more thing, both this new transform and the existing non-commuting splitting one should raise a clear descriptive error when someone tries to put a multi-term observable into a measurement type that fundamentally can't decompose observables (think counting bitstring outcomes), rather than failing confusingly or silently returning wrong results.
