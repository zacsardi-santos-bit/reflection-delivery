I'm reworking the endpoint network policy query in Antrea and the current output drives me nuts. When you ask which policies affect a given pod, everything gets lumped into one flat blob, applied policies plus all the ingress and egress rules mashed together, so you can't tell at a glance whether the pod shows up as an ingress source, an egress destination, or both. I want the internal types and the query method to return a clearer structure that separately tracks policies applied directly to the pod, rules where the pod is an ingress traffic source, and rules where the pod is an egress traffic destination.

Also the wire format is architecturally weird right now, the response types for the endpoint query are defined inside the network policy controller package and the HTTP handler borrows those internal controller types. I'd rather the response types for the endpoint handler live in the handler (API) package itself where they logically belong, so the handler isn't reaching into controller internals for its wire format. Oh and when no pod matches the query the endpoint should return a not-found response instead of handing back an empty result set.

On the CLI side, the function that formats endpoint query output is currently embedded as a method on some internal type, and I want it pulled out into a standalone package-level function in the output package so it's reusable. While you're at it, give it more descriptive section headers so operators can read it fast, something like "Applied Policies on Endpoint", then "Egress Rules Referencing Endpoint as Destination", and "Ingress Rules Referencing Endpoint as Source". When a section has no entries it should clearly print "None" for that section rather than just being blank.

The whole point is operational troubleshooting, people need to quickly see not just which policies select a pod but precisely which rules treat it as an ingress source versus an egress destination, and the current mashed-together format makes that ambiguous and hard to read.
