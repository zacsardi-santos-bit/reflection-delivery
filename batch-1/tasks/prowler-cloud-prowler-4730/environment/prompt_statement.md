I'm cleaning up the RDS security checks in Prowler because right now the instance-level checks are secretly evaluating clusters too and it's making findings really confusing. Specifically `rds_instance_default_admin` and `rds_instance_iam_authentication_enabled` both iterate over `db_instances` and `db_clusters` together, so you can't tell if a finding is about a standalone instance or an Aurora cluster. I want these split apart properly.

So two things. First, the existing instance checks should only look at non-clustered RDS instances now (drop the cluster iteration entirely), and their status messages need to say "which is not clustered" so it's obvious the finding is about a standalone instance and not part of a cluster. That applies to both the default admin check and the IAM auth check.

Second, I need two brand new dedicated cluster checks living alongside the AWS RDS checks, `rds_cluster_default_admin` and `rds_cluster_iam_authentication_enabled`. The default admin one flags clusters using a default master username like "admin" or "postgres", and the IAM auth one flags clusters that don't have IAM database authentication enabled. Both should handle Aurora PostgreSQL, Aurora MySQL, and the other relevant engines. Follow the usual Prowler check layout with the check class, metadata, and its own module path under the rds service, so each new check mirrors how the existing instance checks are structured.

Basically I want clean separation: instances report on instances (noting they're not clustered), clusters get their own checks, and nobody's mixing the two anymore.
