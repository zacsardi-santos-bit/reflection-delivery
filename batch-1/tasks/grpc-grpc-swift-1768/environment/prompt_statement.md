I'm building out the HTTP/2 transport layer for a gRPC library and I'm missing two foundational pieces in the core module, both of which need to live under the HTTP/2 core of the codebase (something like `@Sources/GRPC/HTTP2/Core/`). Without these I can't assemble the outbound message-encoding pipeline that formats data for an HTTP/2 connection, so this is the lowest-level stuff I keep hitting.

First thing I want is a small FIFO queue utility optimized for the common case where only one element is held at a time, so it avoids a heap allocation in that situation and only falls back to a heap-backed container when there's more than one element present simultaneously. It should conform to the standard Collection protocol so callers can iterate over it and subscript by index, and it needs append-to-the-back and pop-from-the-front operations that respect FIFO ordering, plus the usual isEmpty and count checks. The tricky part is it has to keep working correctly after the backing switches from single-element to multi-element mode and then drains back to empty again, so don't leave it in a broken state after that transition.

Second, I need a message framer that accepts raw byte arrays (each with a flag saying whether it should be compressed), queues them internally, and on demand produces a single output buffer containing all the queued messages formatted per the gRPC wire protocol. Each message in the output has to be prefixed with a one-byte compression flag followed by a four-byte message length before the actual bytes, and when multiple messages are queued they all get packed into one buffer per flush. Oh and after the buffer's been returned, the next request should signal there's nothing left to deliver.
