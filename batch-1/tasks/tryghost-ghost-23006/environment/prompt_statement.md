I'm adding a middleware to the Ghost admin panel that serves static files for an auth frame, basically an isolated login interface that runs separately from the main admin app but still through the admin server. Right now there's no way for the server to serve the auth frame's own assets so I need to build a middleware factory in the admin middleware layer that handles this.

Here's the behavior I want. The factory should serve files out of a designated auth directory, locating them via the configured public file path. When a request comes in for the root path (the root URL) it should serve the main HTML entry point (the index HTML) from that auth directory. For any other path it should serve the corresponding file, but here's the important bit, it should use only the filename and not the full URL path when resolving, so we don't open ourselves up to directory traversal attacks. Also the served files may contain a placeholder for the site's origin URL, and at request time the middleware needs to substitute that placeholder with the real site URL so the auth frame knows which origin it's talking back to without us hardcoding hosts into the distributed files. Oh and if a requested file can't be found in the auth directory, don't error out, just pass control to the next handler.

While I'm in here, a frontend analytics script is moving out of the public assets directory to a new home inside the frontend source tree, so any references to the old path need updating to point at the new location.
