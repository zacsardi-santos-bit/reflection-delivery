I'm working on the NooBaa NC NSFS health check system and I've run into a gap in how it handles account validation. Some accounts in our system are identified by an OS username rather than explicit numeric user and group IDs, but the filesystem access validation doesn't currently support that kind of identity. As a result, when the health check runs, it can't tell whether a username-based account actually exists on the system or whether that user has read-write access to their configured storage path.

I need two things addressed: first, the directory accessibility check should work correctly for both username-based and numeric-ID-based identities — resolving the OS username to get the actual user and group IDs when needed, and then correctly evaluating standard unix permission bits (owner, group, other) to determine if the directory is both readable and writable. Second, the health check should surface two distinct error conditions for username-based accounts: one when the OS user exists but cannot access the configured path (an access denial), and another when the OS username doesn't correspond to any user on the system at all (an invalid identity error).

Additionally, we need cross-platform utility helpers to create and delete OS users in tests, so that these scenarios can be properly exercised on both Linux and macOS environments.
