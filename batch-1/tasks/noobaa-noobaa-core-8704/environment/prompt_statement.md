I'm cleaning up the online upgrade mechanism for NooBaa's non-containerized storage and hit a few things that need fixing plus test coverage. First off, the error we throw when someone tries to downgrade is misleading, it talks about "container versions" which makes no sense here, the real problem is the version being installed is older than what's already running on the server, so please reword it to clearly say you're attempting to install an older version while the server's already at a newer one.

Next I want integration tests around the upgrade blocking behavior. During a rolling upgrade a host's config directory can be at an older version, and when that happens write ops through the management CLI (creating, updating, deleting buckets and accounts) should be blocked with a "config directory update blocked" style error to avoid corrupting the shared config dir, while read-only ops like listing and status checks keep working fine no matter the config dir version. Same idea through the S3 API, so bucket create/delete/update should fail with an internal error when the config dir is outdated, but object read/write/delete plus head bucket and read-only bucket queries stay unaffected. To drive these tests I also need helper utilities that create and update a system config file with a mocked config directory version, so tests can fake an outdated host state without running a real upgrade.

Also the lifecycle rule status validation is wrong, when the status value isn't exactly one of the two valid capitalized options (Enabled/Disabled) we currently return an invalid argument error, but it should be a malformed XML error instead. Oh and bucket policy evaluation needs fixing too, an explicit DENY for a specific principal should win over an ALLOW for all principals, right now if one statement denies a specific account and another allows all, the deny isn't always respected. This all matters because without blocking writes during the upgrade window, hosts on old code can corrupt the shared config directory, so getting it right keeps multi-host rolling upgrades safe.
