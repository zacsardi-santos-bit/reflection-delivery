I'm digging into the kubelet controller in prometheus-operator and I need to add EndpointSlice support next to the Endpoints resource we already manage. Right now the controller only creates and updates the legacy Endpoints objects for kubelet node discovery, and that doesn't scale for big clusters since Endpoints blobs get huge. EndpointSlices are the modern replacement, splitting endpoint data into smaller pieces, and I want to support both.

Here's the gist of what I want. The controller should be configurable via functional options to manage Endpoints, EndpointSlices, or both at once. When EndpointSlice management is on, IPv4 and IPv6 node addresses have to land in separate slices since each EndpointSlice only supports a single address family, so group by address family. There's also a configurable max endpoints per slice, and once a slice hits that limit new endpoints spill into a new slice of the same address type. When nodes get removed and a slice ends up empty, delete it. And across multiple sync cycles I want existing slices updated in place instead of recreated from scratch, so preserve their identities.

Also the function that creates or updates a Service needs to return the resulting Service object (not just an error) because the EndpointSlice logic needs the service's identity to set owner references on the slices it creates.

Oh and the controller constructor signature changes too. Instead of taking a combined "namespace/name" string for the kubelet service, it should accept the name and namespace as separate params. The node address priority, Endpoints management, EndpointSlice management, and max-endpoints-per-slice settings should all move to functional options rather than positional args. And if neither Endpoints nor EndpointSlice management is enabled, that should be an error at construction time. The Endpoints path stays intact for backward compatibility.
