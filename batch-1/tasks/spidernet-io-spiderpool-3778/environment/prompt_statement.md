I'm chasing a nasty bug in Spiderpool's GC where IP addresses get wrongly reclaimed during rapid StatefulSet scaling, and the same IP ends up assigned to two pods at once which wrecks network comms and is a pain to recover from by hand. Digging in, the root cause is that our endpoint cleanup logic is scattered across a bunch of code paths. When GC wants to clean up a workload endpoint record it has to manually reason about which state the thing is in, like whether it's already being deleted, whether it still has a finalizer blocking deletion, or whether it's already gone. That fragmentation gives us race conditions and bad GC decisions during quick scale-up/scale-down.

What I want is one unified endpoint release operation hanging off the workload endpoint manager that handles every lifecycle case safely. If the endpoint doesn't exist anymore it should just be a no-op and return success without doing anything. If it exists and hasn't been marked for deletion yet, delete it. If it's already being deleted (it's got a deletion timestamp set), remove its finalizer so the deletion can actually complete. And if either the delete or the finalizer removal errors out, propagate that error back to the caller, don't swallow it. This needs to live on the workload endpoint manager's interface so the GC scan-all path and other components can call it safely instead of each rolling their own cleanup. Basically consolidate all these cases into one entry point so nobody's hand-handling endpoint states anymore.
