I'm working on Spiderpool's garbage collection system and running into an issue where IP addresses get incorrectly reclaimed during rapid StatefulSet scaling, causing IP conflicts between pods. The problem is that the endpoint cleanup logic is spread out and doesn't handle all the states an endpoint can be in — particularly when the endpoint is already in the process of being deleted versus when it still needs to be deleted outright.

I need a unified endpoint release operation on the workload endpoint manager that consolidates all these cases: if the endpoint doesn't exist anymore, it should be a no-op and complete successfully without taking any action; if it exists and hasn't been marked for deletion yet, it should be deleted; if it's already being deleted (it has a deletion timestamp), its finalizer should be removed so the deletion can complete. Errors from either deletion or finalizer removal should be returned to the caller. This operation needs to be part of the workload endpoint manager's interface so the GC scan-all path and other components can call it safely.
