I'm cleaning up how we deal with filesystem paths in this C++ codebase and I could use your help. Right now we've got a bunch of standalone utility functions scattered as free functions in a general-purpose utility file, stuff like checking whether a group of paths all live under a given parent directory, computing how deep a path is, checking parent-child relationships between two paths, and computing a path relative to some base. It's annoying because they're hard to discover and everyone passes raw strings around to disconnected functions. Path manipulation shows up all over the place when we're indexing and traversing the drone data file system, so I want one clean abstraction that groups this stuff together, keeps the normalization logic in one spot, and makes it easy to add new path ops later.

What I want is a proper path type, a class that wraps a filesystem path and exposes these as methods, living in an I/O-focused namespace and declared in a new header. Then one that checks whether this path is strictly a parent (ancestor) of another path, and it should normalize first so two paths that resolve to the same spot through `..` references don't get counted as parent-child. Also a method to return the path relative to a given base, and when there's no relative form (like the base is the root) it just returns the normalized absolute path as-is. And a method that gives back a generic cross-platform string representation.
