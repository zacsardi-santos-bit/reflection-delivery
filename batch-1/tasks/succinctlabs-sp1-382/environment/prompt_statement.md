I'm building a recursion compiler for a proof system and I've hit a wall with the VM builder over in the recursion crate. Right now the `Builder` only takes a single base field type parameter, so there's literally no way to represent or execute anything over an extension field, which is a problem because recursive proof systems lean on extension field arithmetic for security and I can't express half the programs I need to.

What I want is to make the builder generic over two type params instead of one, a base field type and a separate extension field type, so extension field elements (values living in an algebraic extension of the base, not just base field elements) become a first-class thing I can store, load, and operate on inside compiled programs. Once that's threaded through I need the runtime and the instruction representation to actually handle extension field arithmetic, so addition, subtraction, multiplication, and division over extension field elements all execute correctly, and I also need to be able to pass extension field immediate values as operands (not just base field immediates).

Oh and equality assertion between two extension field values should work too, with the runtime trapping at execution time if the two aren't actually equal. Important bit: everything I already have that only touches base field ops, the conditional programs and the for-loop programs, needs to keep working unchanged once the builder goes from one param to two. So don't break those while you're adding the extension field path.
