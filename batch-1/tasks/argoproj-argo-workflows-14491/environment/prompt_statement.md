I've got a Go workflow orchestration project and there's no structured way for contributors to document new features as they land, so figuring out what's new at release time means digging through commits and PRs by hand, which is tedious and error-prone. I want to add a small feature-generation tool to fix this.

The idea is contributors drop a short structured text file next to their change, with a recognized component category, a one-line description, the author's name in markdown link format, and the related issue numbers. The tool should validate these pending files and flag ones that are incomplete or malformed as invalid, specifically anything with a missing or empty issues list (needs at least one linked issue), or an unrecognized component name, plus the required one-line description and author fields. Valid files get compiled into a single formatted release notes document that starts with a header carrying the version and today's date, groups entries by component, and formats each entry with its description, author, and issue numbers linked back to the project's issue tracker.

I also want a dry-run mode so I can preview that output without writing anything to disk, and on a final release run it should move the pending files into a versioned archive directory so we keep a record of which features landed in which release.

Oh and there should be a command to scaffold a new blank feature stub from a template given a name, and it needs to reject invalid names (ones containing path separators or other special characters), falling back to a sensible default name when none is given. Please wire this up so the validation, compilation, dry-run, archiving, and stub-creation all behave like that.
