I'm working on a Go-based workflow orchestration project and I'd like to introduce a small tooling utility that helps contributors and maintainers manage feature announcements across releases. Right now there's no structured process: contributors just merge their changes and it's up to maintainers to figure out what's new when it comes time to write release notes.

The idea is to have contributors write a short structured text file alongside their contribution — something with a recognized component category, a brief description, the author's name in markdown link format, and the related issue numbers. The tool should validate that these files are complete and well-formed, reject ones with missing required fields or unrecognized component categories, and compile the valid ones into a nicely formatted release notes document that groups entries by component and links each issue number back to the project's issue tracker. It should also support a dry-run mode so you can preview the output without committing anything to disk. When a release is cut, the tool should be able to archive the pending entries into a versioned folder so we have a record of exactly which features landed in which release.

I'd also like a command to scaffold a new blank feature file from a template, with a given name — and the tool should reject names with invalid characters. If no name is given it should fall back to a sensible default.
