I'm building out the WhatsApp side of our chatbot framework and there's a gap in the component model, right now bot devs literally can't compose the commerce message types WhatsApp supports, so I need new components for single product messages, product lists, product carousels, and media carousels. Without these people have to hand-roll low-level message structures instead of using the idiomatic components we use everywhere else, which is a pain.

For the single-product one it just needs to take basic product identity and display info and render the right message element. The product list component should accept a header, footer, body text, and a list of sections where each section has a title and its own list of products. The product carousel takes a template name, template language, body params, and a list of product cards where each card names a product. The media carousel is similar (template name, language, body params) but each card is image-based with media info, buttons, and its own body params. For both carousels, each card can carry an explicit position index, but if it's missing (or zero) I want it auto-assigned from its order in the list, and same deal for button positions on the media carousel cards.

Oh and the tricky bit: for the carousel and list components the serialized data needs snake_case keys, not the camelCase property names we use in the component interface, since that's what the WhatsApp API expects. So I need a general deep camelCase-to-snake_case key conversion utility that handles nested objects, arrays inside objects, numeric suffixes in key names, and just returns undefined when you hand it undefined. All four of these new components also need to be exported from the main components module so they're importable alongside everything else.
