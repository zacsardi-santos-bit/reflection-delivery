I'm working on a text-to-speech FastAPI service and I keep hitting two related issues that I want fixed together.

First off, the phoneme conversion endpoint blows up when I send it an empty text string. Instead of a clean response it throws an unhandled exception and the server basically crashes. I want it to validate that the text is non-empty and, when it's empty, return a structured HTTP 500 response whose body carries an actual error object with at least one error indicator field (something like an "error" key) so callers can handle it gracefully instead of getting a cryptic 500 with no shape to it.

The second one is bigger and it's in the model layer. Right now there's no standard way to grab the currently loaded model or ask which hardware device it's running on, so the main service class that wraps the model ends up duplicating init logic or bypassing the model lifecycle entirely. That makes it fragile and honestly impossible to test in isolation, there's no stable hook to swap in a lightweight stand-in for the real model. So I need the model class to expose an instance accessor method that returns the active model object and raises a clear error if it hasn't been initialized yet, plus a device query method that returns the current device string. Also the model setup flow needs to actually store the initialized model object on the class so the accessor can return it later, right now that's the missing piece. And the service class should call that instance accessor during its own initialization so the model dependency is explicit and mockable.

Together these let me write real unit tests against the service layer (every attempt errors out today because the model singleton can't be injected) and give API callers meaningful errors instead of server crashes.
