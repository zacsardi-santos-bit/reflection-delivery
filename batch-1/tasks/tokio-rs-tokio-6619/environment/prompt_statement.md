I'm working with the async runtime and noticed that some very basic observability metrics—specifically the number of worker threads and the number of currently alive tasks—are only accessible when building with a special unstable compilation flag. These seem like fundamental, stable metrics that shouldn't require opting into experimental features just to use them in production.

I'd like to promote these two metrics to stable status so they're available in regular builds without any special flags. At the same time, the metrics that genuinely depend on experimental internals should stay behind the unstable flag. It would also help to reorganize the tests so there's a clear, dedicated place for unstable metrics tests (separate from stable ones), making the distinction obvious to contributors and users alike.
