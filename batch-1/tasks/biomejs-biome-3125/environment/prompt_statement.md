I'm adding a new nursery lint rule to our linter that flags the two legacy JS string substring methods nobody should reach for anymore, `substr` and `substring`, in favor of `slice`. The thing with `substr` is it takes a start plus a length as its second arg instead of an end index, which is easy to misuse and hard to read, and `substring` has that surprising edge behavior where it clamps negative args to zero and silently swaps start and end when end is less than start, neither of which `slice` does. `slice` is just more predictable, more commonly used, and better supported, so I want to nudge people toward it.

Behavior I want: report a warning whenever either of these gets accessed or called on any object, including through optional chaining. The diagnostic should tell the dev to use `slice` instead, note that it's more commonly used and less surprising, and link out to the relevant MDN page for more details.

For calls with no arguments, offer an automatic unsafe fix that just renames the method to `slice`. For calls that do have arguments, don't offer any fix since the argument semantics differ and the dev needs to migrate manually. A bare property access of one of these names without calling it should still get flagged, just no fix there either. And obviously don't flag calls that already use `slice`. Register it in the nursery group.
