I'm working on a distributed task queue in Go and I keep running into the same annoyance: there's no standard way to shove structured data through the queue. Every caller ends up rolling their own serialization logic, which means duplication and subtle bugs whenever we pass a struct through or try to pull a typed result back out. I want to fix this once with two little utility functions that live in the existing tasks package alongside the rest of the queue setup code.

First one takes any Go value and marshals it into the task argument format the underlying queue library expects. The output should be a single-element collection holding the encoded form of the input, so I can hand it straight to the queue. Think standard encoding here, nothing fancy, just something that round-trips cleanly.

Second one goes the other direction: it takes the raw task result values (they come back as reflected Go values) and deserializes the first element into a typed destination I give it. Important bit, it should return an error if the result has more than one element, since I'm only ever expecting a single encoded string in there.

The whole point is round-trip fidelity, so a value that goes through marshal then unmarshal should come back equal to what I started with, no lossiness. That's really the contract I care about, marshal then unmarshal is the identity. Also make sure the error path on the multi-element case actually fires, don't just silently grab the first one. Once this is centralized it'll be way easier to add new task types without everyone reinventing the wheel each time.
