I'm working on the Apache Airflow GCP integration and I keep running into a limitation with the Google Cloud base hook in `@airflow/contrib/hooks/gcp_api_base_hook.py`. Right now credential setup is only exposed as a function decorator, which means creds can only be scoped to a whole decorated function. There's no clean way to apply the same setup to an arbitrary block of code, or to scope credential availability to just part of a function (say a specific call out to an external tool).

What I want is a context manager variant on the base hook that does the same thing the decorator does. On entry it sets the appropriate credential environment variable, either pointing it at a key file path or writing the JSON content to a temporary file and pointing at that. Then on exit it restores the environment variable back to whatever it was before. That cleanup needs to happen even if an exception gets raised inside the block, so wrap it properly. Oh and if the credential variable wasn't in the environment at all before entering the context, it should be gone again (not left dangling) after exiting.

Also, the Kubernetes Engine pod operator over in `@airflow/contrib/operators/gcp_container_operator.py` currently rolls its own private helper methods for credential setup, basically duplicating logic that lives in the base hook. Now that the base hook has this context manager, I want the operator updated to use it instead, so rip out those private helpers and just delegate credential management to the base hook. This makes it way easier to scope creds precisely (like for the duration of a subprocess call), lets multiple connections be used in the same function, and cuts the duplication.
