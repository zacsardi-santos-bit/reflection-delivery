I'm working on the Apache Airflow GCP integration and I need to add a context manager variant to the Google Cloud base hook for setting up credentials. Right now, the hook only supports credential setup via a function decorator, which limits how we can scope credential availability. I'd like a context manager that does the same thing — sets the appropriate credential environment variable while inside the block (pointing to a key file or a temporary file written from JSON content), and then restores the environment variable to its original state when the block exits. This cleanup should happen even if an exception is raised inside the block. If the credential variable wasn't in the environment before entering the context, it should be gone again after exiting.

Additionally, the Kubernetes Engine pod operator currently has its own private helper methods for credential setup that duplicate logic from the base hook. Now that the base hook will have a context manager for this purpose, the operator should be updated to use it instead — removing the private helpers and delegating credential management to the base hook.
