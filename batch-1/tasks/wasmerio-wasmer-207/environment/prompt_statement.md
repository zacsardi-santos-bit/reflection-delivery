I'm working on a host app that embeds WebAssembly through the Wasmer C API, and I've got compiling and instantiating modules working fine, plus I can already walk what a module exports. The gap is imports. There's no way for me to inspect what a compiled module actually requires from its environment before I instantiate it, which means I can't dynamically build the right import object without already knowing the module's interface out of band. That's fragile, especially for plugin systems, tooling, and sandboxed runtimes where I really want to introspect dependencies at runtime instead of hardcoding them.

So I want import inspection that mirrors the export inspection that already exists. After I compile a module I should be able to grab the full list of its required imports as a descriptors collection, ask how many there are (a queryable length), and pull each one out by index. For each import descriptor I need to discover its kind, meaning whether it's a function, memory, table, or global, plus the import's name and the module/namespace it belongs to. The collection is owned by me, the caller, so I also need a dedicated function to free it when I'm done. Basically parity with exports, same shape of API, in the C bindings alongside the existing module inspection code. Nothing exotic, just fill in the missing half.
