I'm working on the telemetry collector for the NGINX Kubernetes Ingress Controller and right now our telemetry doesn't say anything about which config settings admins have actually turned on in their ConfigMaps. We've got two of them, one for the main ingress controller config and one for the management/licensing config, and I want to start tracking which recognized keys show up in each. Knowing what people commonly configure would help us prioritize docs, support, and feature work, and since we only report the key names and not their values it stays privacy-safe.

So when the collector runs I want it to look up both ConfigMaps, read the keys present, and filter each one against a known list of recognized/valid settings for that map. Anything unknown or unrelated just gets silently dropped, we only report keys we know about. Then those filtered key lists go into the telemetry data payload so they show up in the collected output. One thing to be careful about: if a ConfigMap has no recognized keys, the reported list should be absent entirely, not an empty collection.

Oh and the collector config itself needs new fields to point at where each ConfigMap lives, using a "namespace/name" format, so the collector knows which Kubernetes objects to go fetch when it's gathering this data. That covers both the main config map reference and the management config map reference.
