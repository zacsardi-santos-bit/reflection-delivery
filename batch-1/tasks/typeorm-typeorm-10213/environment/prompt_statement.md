I'm hitting a WHERE clause precedence problem in the query builder and it's biting me. When I chain multiple conditions together with AND and OR, the generated SQL doesn't wrap each individual condition in its own parentheses, so the boolean logic can get evaluated in the wrong order. Classic case: I've got a strict equality filter (say an exact ID match) alongside an OR-based search (like a name search across a couple columns), and without brackets isolating the OR piece the database ends up applying default operator precedence, so the OR gets evaluated last instead of being treated as one grouped unit. That quietly produces wrong results and it's a pain to track down.

What I want is a data source-level config option that, when I turn it on, automatically wraps each WHERE condition in parentheses. So enabling it globally means a query that combines a simple equality check with an OR condition should emit SQL where that OR condition is enclosed in its own brackets, guaranteeing the OR gets evaluated before the AND rather than falling victim to precedence. The point is I don't want to hand-add parens to every complex OR condition across the codebase, it's error-prone and easy to forget. Flip the switch once at the data source config and it applies everywhere. When the flag's off, behavior should stay as it is today so nothing existing breaks. Basically I need this isolation to kick in automatically for each condition when the option's enabled, and the equality-plus-OR example above is the concrete thing I'd check to confirm the OR really does come out bracketed.
