I'm building out a home automation dashboard that shows sensor readings, and right now everything displays in whatever unit the sensor reports regardless of what the person actually wants to see. So someone who prefers US units still gets kilometers, meters, and metric EV efficiency numbers, and someone on metric ends up staring at miles and feet. It's a mess and I keep writing one-off conversions all over the place, so I want a proper shared helper in the server-side units file at `@server/utils/units.js` instead.

What I need is a conversion function that takes a measurement value, its current unit, and the user's measurement system preference, and hands back the converted value paired with the right target unit for that preference. It's gotta go both ways, metric to US/imperial when the pref is US, and US/imperial to metric when the pref is metric. Cover distances (millimeters, centimeters, meters, kilometers, inches, feet, miles), speeds (km/h, m/s, mph, ft/s), and the EV range/consumption metrics in both systems (km/kWh, mi/kWh, kWh/100km, kWh/100mi, Wh/km, Wh/mi). Couple edge cases matter too: if there's no reading yet, still return the correct target unit but keep the value absent (null/undefined stays absent), and if the preference is unknown or there's just no conversion for that unit, return the original value and unit unchanged rather than blowing up.

Oh and I also want a companion smart-rounding helper exported from the same file, it should pick precision based on magnitude, full precision for very small values, two decimals for small numbers, one decimal for medium ones, and zero decimals (integers) for large values. Apply that rounding automatically to the converted values so callers don't have to think about it. Centralizing this means consistent, tested conversion everywhere instead of scattered ad hoc math or nothing at all.
