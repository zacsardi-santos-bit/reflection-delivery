I'm building out a spin lattice module for PennyLane so folks doing condensed-matter quantum simulation don't have to hand-roll lattice graphs and Hamiltonian terms every time. Right now there's no built-in way to define a geometry or spin up a spin model from it, and I want to fix that.

Core piece is a Lattice class that takes the primitive vectors, basis site positions, number of unit cells per dimension, and boundary conditions, then computes all the lattice sites and their neighbor connections (edges) for me. It should expose the site coordinates and the edge list. A scalar boundary condition applies to every dimension, but I also want to pass a per-dimension list of open/periodic. Validation matters here: wrong-dimensional input arrays should error, and non-integer or negative cell counts too, all with descriptive messages. I also want to manually add edges, so guard against duplicate edges and edge tuples of the wrong length (each should raise something clear).

Then a helper that builds standard named geometries (chain, square, rectangle, honeycomb, triangle, kagome) from a name string, case-insensitive and tolerant of surrounding whitespace, raising a clear error if the name isn't supported.

On top of that, a transverse-field Ising Hamiltonian builder that works off any lattice. Coupling strengths can come in as a uniform number, a single-element array, or a full site-by-site coupling matrix, and the transverse field's configurable too. The Hamiltonian should be pairwise interaction terms for each edge plus single-site transverse field terms for each site. Oh, and a coupling array of the wrong shape should raise a descriptive exception. Put this under the appropriate spin submodule in `@pennylane`.
