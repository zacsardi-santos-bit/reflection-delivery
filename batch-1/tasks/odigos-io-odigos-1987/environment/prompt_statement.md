I'm working on adding support for musl-based containers (like Alpine Linux) in our instrumentation system. Right now, the functions that generate instrumentation plugin names and device names don't have any way to distinguish between containers that use glibc versus musl as their C library. I need to add a C library type concept to the common package and update those naming functions so they can optionally incorporate the C library variant into the generated names.

Specifically, when no C library type is provided (or when glibc is specified), the output should remain exactly the same as today. But when the musl variant is specified, the generated names should include a distinguishing prefix. I also need to make sure that the reverse function — the one that parses a device name back into its language and SDK components — can handle these musl-prefixed names and correctly return the original language and SDK without the prefix interfering.
