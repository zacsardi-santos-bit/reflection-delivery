I'm cleaning up how our schema validation errors land in Sentry and there's two annoying gaps I keep hitting. First one is array paths. When validation blows up inside an array element, say a field called "names" has a bad entry at index 1, the message we send to Sentry just shows "names" and drops the fact that it was an array element at all, which makes it a pain to figure out where the failure actually happened. I want any numeric array index in the path to get swapped out for a standardized placeholder so the message reads clearly that an array element was involved instead of losing that context.

Second gap is that when a bunch of validation issues fire at once, only a limited number fit into the Sentry event extras and the rest just silently vanish, so whoever's looking at the event in prod only sees a partial picture. I want to attach the full list of issues as a separate JSON file whenever there are more issues than the limit allows, and the limit should still apply to the inline extras (keep the events lightweight) so nothing gets lost but events stay small. There should be a new boolean option controlling whether that attachment behavior kicks in.

Oh and while I'm in there, I want to pull the helper utilities out as public exports so we can test and reuse them on their own: one for flattening a path array down to a string (that's where the numeric-index-to-placeholder logic lives), one for flattening a full issue object, and one for generating the formatted message straight from a validation error. Basically validation errors in prod get gnarly with lots of fields and deep nesting, so both the clearer array path format and the attachment fallback should make debugging way less miserable.
