I'd like webpack-dev-server to support a configurable socket server implementation. Right now it seems like the socket server is hardcoded internally and there's no way to swap it out or provide a custom one. It would be really useful to be able to specify the socket server implementation via a configuration option — either by a built-in name, by providing a path to a custom module, or by passing in a class directly. There should also be a base class that developers can extend when writing their own implementation. If someone provides an invalid or unresolvable implementation, the server should throw a clear, descriptive error explaining what went wrong. When no custom implementation is specified, the server should continue working exactly as before with no behavior change.
