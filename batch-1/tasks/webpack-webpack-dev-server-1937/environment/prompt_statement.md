I'm working on webpack-dev-server and I keep hitting a wall where the socket server is baked in internally with no way to swap it out. I want to add a config option that lets me pick the socket server implementation, and it should be flexible about how I hand it over: a short built-in name string like `"sockjs"`, or a full path to a custom module on disk, or the implementation class passed in directly. Under the hood in the server setup code (something like `@lib/Server.js`) it needs to resolve whichever of those three forms I gave it into an actual class it can instantiate.

Also I want a base class exposed that people can extend when they roll their own socket server, so there's a clear interface to follow for the connection handling. Give it the shape developers need to override.

The important bit for error handling: if I pass something that can't be resolved, an unknown name or a path that doesn't exist or just isn't a valid implementation, the server should throw a clear descriptive error telling me what went wrong instead of silently falling back to a default or blowing up in some confusing way later.

Oh and when I don't set this option at all, behavior stays exactly as it is today, defaulting to the existing built-in socket server with no functional change. That's the whole point, it's additive. Teams with weird WebSocket constraints can plug in their own thing without forking the project, that's why I care about this.
