So I'm working on Kargo and we've got this promotion step for updating YAML files, but there's nothing for JSON, which is annoying because tons of teams keep their app settings, feature flags, and deploy params in JSON and right now they have to hack around it with external scripts instead of just declaring the change in the promotion workflow. I want a new step directive that takes a path to a JSON file plus a list of key/value updates, where keys use dot-notation to reach nested fields like "app.version" or "features.enabled", and it should handle string, number, and boolean value types.

Config needs validating, so both the file path and the updates list are required, the path can't be empty, and each update has to have a non-empty key and a value, with friendly error messages saying exactly which field is missing or invalid. If the file doesn't exist it should fail with a sensible error. If no updates are passed it should just succeed doing nothing and produce no commit message output. Oh and empty JSON files should be treated as an empty object and populated from there.

When updates do land, produce a commit message output describing the changes, one line per updated key, string values shown in quotes and non-string values shown without quotes, same style as the existing YAML update step so look at how that one's wired up and mirror it.
