I'm building out the metrics SDK and there's a big gap I keep hitting: there's no way for users to customize how instruments get matched and transformed before their data hits the exporter. I want to add a whole new "view" package from scratch that handles selecting a specific instrument by name, renaming it, overriding its description, or restricting which attributes it reports. Right now none of that exists and it makes user-driven metric customization impossible.

Here's what I need. The view should match instruments by name using wildcard patterns, where one wildcard char matches exactly one character and another matches zero or more characters. Also anything that's special in regular expressions should be treated as a plain literal inside these name patterns, so users don't get surprised. On top of name matching it should filter by instrumentation library scope (name, version, schema URL) where only the non-empty fields actually have to match.

Once an instrument matches, the view needs to optionally rename it and/or override its description, and also filter the attribute set down to a given list of keys, oh and if no attribute filter is set it should just pass everything through unchanged.

Couple of error cases too. Creating a view with no match criteria at all should fail with an error. And renaming while the name pattern is a wildcard should also error out, since a rename targets one specific instrument, not every instrument matching some broad pattern.

I want the package to expose a constructor that takes functional options, plus option functions for instrument name matching (with the wildcard support), instrumentation scope matching, renaming, description overriding, and attribute filtering. This is the foundational building block for configurable metric views so I'd like it clean.
