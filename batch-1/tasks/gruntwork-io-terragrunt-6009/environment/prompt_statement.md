I've got a Terragrunt setup where I put exclusion rules in a shared parent config, the whole point being that any unit including that parent inherits them and skips certain operations like plan or apply. Problem is the exclude block from the parent is just getting dropped in the child. When I parse a child config that includes the parent and the child doesn't define its own exclude block, the merged result has no exclusion config at all, like the parent's block never existed.

What's weird is other top-level blocks in the parent inherit fine, retry error settings (retryable_errors and the auto-retry stuff), the engine config, feature flags, all of that flows down correctly. It's only the exclude block that silently vanishes. And it happens no matter which merge strategy I use, default, shallow (deep_merge with the shallow default), or deep merge.

What I want: when a parent defines an exclude block and the child includes that parent without defining its own, the child's parsed config should carry the parent's exclude settings. And if the child does define its own exclude block on top of including the parent, the child's version wins. Same behavior across default, shallow, and deep merge, and the other inherited blocks should keep working like they do now.

Can you dig into the include/merge logic (that's the code handling how child configs pull in and combine parent config blocks) and fix it so exclude blocks get merged and inherited properly? This is tracked upstream as gruntwork-io/terragrunt issue 5089 if you want context. Shared root configs are a core pattern here so exclusion rules defined once at the parent level really need to flow down, otherwise every child has to duplicate them which defeats the whole thing.
