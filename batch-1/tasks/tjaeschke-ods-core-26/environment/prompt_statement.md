I'm cleaning up the webhook proxy service and I want to kill off the redundant project identifier that callers keep having to stuff into every build trigger request payload. It's pointless because the server already knows its own namespace, and the project is always just the namespace with a standard suffix stripped off, so making callers pass it in only creates a chance for the request's project to disagree with the server's actual context. I'd rather derive it once at startup and be done with it.

So what I want is for the server to hold a dedicated project field that gets set when it initializes, computed by taking the configured namespace string and removing that standard suffix, and then everything downstream (deriving component names, pipeline names, all the subsequent processing) should read from that server-level project instead of pulling it out of each incoming request.

Also the build trigger request payload should stop accepting a project field entirely, don't require it, don't read it. And the internal event objects that get created when handling requests shouldn't carry a project field anymore since the server owns that context now. Events get identified by their namespace, repository, component, branch, and pipeline. Oh and the event validity check needs updating too so it no longer expects or requires a project field on the event to consider it valid.
