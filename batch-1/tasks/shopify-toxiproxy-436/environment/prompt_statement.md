I'm hitting a nasty deadlock in toxiproxy when I remove a toxic from a connection that's actively pushing data. Basically I add bandwidth-limiting toxics to a proxy and then yank them while data's still flowing, and the whole proxy just hangs forever sometimes. Digging in, it looks like the toxic removal path tries to flush whatever's buffered by writing straight to an output channel, but if nothing happens to be reading from that channel right at that moment, the write blocks indefinitely and freezes everything.

What I want is for the proxy to deal with this gracefully instead of hanging. When it can't forward the buffered data during toxic removal, it should try the write with a timeout and return an error if the write doesn't complete in time. The error message needs to make it clear the write timed out and say how many seconds the timeout was. And when the write does go through within the timeout window, it should just complete normally with no error, no drama.

This matters because toxiproxy is all about simulating network conditions in tests, and toxics like bandwidth limiters get added and removed on live connections all the time. Removing a toxic from an active connection should always finish in a bounded amount of time even when the output channel is temporarily blocked, so the fix is a timeout-based write that fails cleanly with a descriptive error rather than deadlocking. Right now this makes dynamic toxic cleanup unreliable and it's messing up test setups that depend on adding and removing toxics on the fly.
