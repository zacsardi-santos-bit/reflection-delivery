I want e2e tests covering the version flag output format, single-file compilation with each mode flag, config-based compilation including decompilation support, the priority of CLI flags over config-file settings, mutual exclusivity of certain mode flags (which should be rejected with an appropriate non-zero exit code), unknown or unrecognized flags being rejected with a non-zero exit code, expression evaluation, and the disassembler tool behavior. Once that's in place, update the internal tools that call it, the map-test generator and the compilation-failure test helper, to use the new API. Oh and add a utility that compiles all contracts matching certain file patterns (globs) inside a folder, so we can drop the old giant config file that listed every single contract by hand.

For the test utilities backing these CLI tests, the command runner and the contract code generator, please make them line up with the Tact compiler's actual output file naming conventions so the assertions match what the compiler really emits. The point of all this is faster local feedback, real reporting, and an API that other tooling and tests can build on without needing filesystem access.
