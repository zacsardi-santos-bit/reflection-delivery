I'm working on the mesh service in our blockchain node and the layer data we hand back to API clients is just wrong. When a client queries layer info they get every block that was part of the layer instead of the single block that actually got verified and applied. I want the layer data to reflect only that one effective (applied) block per layer, not the whole set.

Also our account mesh data API is leaking ATX activation events into the transaction data, even when a client is only asking for account transactions. Those activation events shouldn't show up in account mesh data queries or streams at all, transactions only please.

To make the applied-block thing work, the mesh layer component over in `@mesh` needs a way to look up the specific block that was applied for a given layer ID. If nothing's been applied for that layer yet it should just return nothing, not an error, so callers can treat "not applied yet" as a normal empty case.

The service that uses this lookup should surface a clear error if the layer data itself can't be read, and also error out if transaction data comes back incomplete. But the state root is different, if only the state root is unavailable I want that treated as non-fatal so we still return a valid layer response in that case. btw the reason this matters is clients leaning on the API to understand confirmed network state are getting misled right now, multiple blocks where only one was accepted plus activation noise in account history, and I just want them to see which block finalized per layer and clean transaction-only account data.
