I'm dealing with a Java startup script that launches apps inside containers, and it's totally ignoring proxy settings from the environment. Like if I set the usual proxy env vars in my container, the JVM the script kicks off doesn't translate any of them into the Java system properties for proxy host, port, or the bypass list, so traffic just doesn't route through the proxy and I get connection failures in locked-down networks. Operators expect to configure this stuff with standard env vars the same way every other tool works, so the script needs to bridge that gap.

What I want is for the startup script to read the HTTP proxy, HTTPS proxy, and no-proxy environment variables and hand the JVM the right system properties whenever those vars are set. If only the HTTP proxy is configured, I only want the Java HTTP proxy host and port properties showing up, nothing else. Same deal if only the HTTPS proxy is set, just those HTTPS host and port properties. And if there's a no-proxy bypass list, it comes in comma-separated but Java wants it pipe-separated for the non-proxy-hosts property, so it needs reformatting from the commas into pipes before it gets passed along. These should all work on their own or together, each one added only when its matching env var is actually present. Oh and when none of them are set, the script shouldn't tack on any proxy-related properties to the JVM invocation at all, keep it clean.
