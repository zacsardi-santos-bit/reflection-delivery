I'm working with a Java startup script that launches applications in containers, and I need it to automatically pick up proxy configuration from standard environment variables. Right now, if I set proxy environment variables in my container environment, the Java process launched by the script completely ignores them — it doesn't translate those environment variables into the corresponding Java system properties for proxy host, port, or bypass lists.

I'd like the startup script to read the HTTP proxy, HTTPS proxy, and no-proxy environment variables and automatically pass the appropriate Java system properties to the JVM when those variables are set. If only an HTTP proxy is configured, only the HTTP proxy properties should appear. If only an HTTPS proxy is set, only those properties should appear. If a bypass list is set as a comma-separated list of hostnames, it should be reformatted into the pipe-separated format that Java expects. When none of these environment variables are set, no proxy-related properties should be added to the JVM invocation at all.
