I keep hitting a permadiff on my instance group manager stuff whenever I use stateful IP configs across multiple network interfaces. This is on both `google_compute_instance_group_manager` and `google_compute_region_instance_group_manager`. After I apply a config with a bunch of stateful external or internal IP blocks, running `terraform plan` again shows the blocks need reordering even though nothing actually changed and the state is already what I want. As far as I can tell it's because the Google Cloud API hands back stateful IPs sorted alphabetically by interface name, which doesn't match the order I wrote them in my config, so Terraform thinks there's always a change pending.

What I want is for the provider to preserve the original ordering of the stateful internal and external IP blocks exactly as I defined them in the config when it reads them back from the API. So when it flattens the API response, it should walk my configured order first and match each block up. Oh and any IPs the API returns that aren't in my config should get appended at the end in a stable alphabetical order (by interface name), and any IPs that are in my config but the API doesn't return should just be dropped from the result.

End result: after applying stateful external or internal IP blocks in whatever order I chose, a follow-up plan shows no diff. Users who define these in a non-alphabetical order shouldn't be stuck seeing spurious changes forever, it makes it impossible to trust that the infra's already converged. Fix belongs in the read/flatten path for these stateful IP fields on both the zonal and regional resources.
