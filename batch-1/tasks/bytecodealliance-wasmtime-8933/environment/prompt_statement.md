I'm adding host-side support for WebAssembly GC struct types in Wasmtime. Right now the runtime handles the GC proposal at the bytecode level, but there's no public Rust API for embedders to define struct types, allocate instances, or read and write fields, so host code working with GC structs is basically blocked.

I want a full set of types and methods so host code can define a struct type with zero or more typed, optionally-mutable fields, allocate a new struct instance with initial field values, read a field by index, write a mutable field by index, get back the struct's type, and iterate over all fields (with a count too). Reading a field out of bounds, or on an unrooted/expired reference, should fail with an error rather than do something weird. Writing should fail on out-of-bounds indices, immutable fields, unrooted references, wrong value types, and values that belong to a different store.

This all needs to play nice with the existing GC rooting discipline. Operations on unrooted references return errors, and passing a reference from a different store should panic with a message that clearly says there's a store mismatch. But passing an unrooted reference as a field value during construction should be a recoverable error, not a panic, since that's an easy mistake to make.

Beyond the basic manipulation, struct refs need to work end-to-end with actual WebAssembly. They should survive round-trips through both typed and untyped function calls preserving identity, be storable in and retrievable from globals (set from host and from guest code), and same for tables from both sides. Also I want to check whether a general-purpose heap reference is a struct and downcast/unwrap it into a struct ref if so. And it should be possible to instantiate modules with host-provided globals whose value type is a nullable reference to a concrete struct heap type, covering both null and non-null initial values.

The work lives in the wasmtime crate's GC-facing code under `@crates/wasmtime/src`, so wire it into the existing rooted-reference and Val plumbing there.
