I'm hacking on the Grafbase gateway and hit a rough spot in the local dev loop. When I boot the gateway pointing at a local federated schema file (the `--schema` path style setup) and then edit that file, the running process just keeps serving the old schema. The only way to get new content loaded right now is to kill the process and start it again, which is super annoying when I'm iterating on types and fields.

What I want is automatic hot-reloading for the local schema file case. So when the gateway starts with a local schema file, it should watch that file in the background for modifications, and when it sees the file change on disk (saved with new content), it should reload its schema configuration on its own without me restarting anything. The reload needs to be quick, like within a few seconds of me saving, not some long delay.

The key thing I care about verifying is that introspection reflects the change after reload. So if I remove a field from a type in the schema file, then hit the gateway with a GraphQL introspection query a moment later, that field shouldn't show up anymore. Same idea for added or changed types and fields, introspection should immediately show the updated shape once the reload lands.

This only needs to cover the local file path (not remote/managed schema sources), and it's really about bringing the local dev experience in line with modern tooling so I don't have to bounce the process every time I tweak the graph. Can you wire up the file watching and reload plumbing so it all just works?
