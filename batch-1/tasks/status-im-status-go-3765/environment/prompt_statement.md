I'm building out a community messaging protocol with token-gated communities and channels that use encryption, and I need a way to figure out what encryption key actions to take when a community's state changes. Basically I want to compare the community state before and after some modification (permissions added or removed, members joining or leaving) and get back a structured decision about what to do with the keys.

The rules I care about: if a community or channel goes from open to token-gated, I need to add a new encryption key. If it goes the other way, token-gated back to open (drops its token requirements entirely), the key should be removed. If a member gets removed from a token-gated community or channel, I have to regenerate and rotate the key out to the remaining members so the removed person can't decrypt future messages, that's the whole security point. If new members join a token-gated community or channel and nobody was removed, I just want to send the existing key to those new members only. And if nothing changed, or only some non-access-controlling permission changed, then no key action at all.

This has to work at both the community level and per-channel, since channels can have their own access restrictions too. So the evaluation should return something that carries the action type for the community as a whole plus a map of per-channel actions. Each action needs to carry a set of the relevant members, oh and to be clear that means when I'm sending the key to new members the action says which members receive it, and when rekeying it lists the remaining members who need the new key. Can you implement this evaluation logic with all the types it needs plus the eval function itself?
