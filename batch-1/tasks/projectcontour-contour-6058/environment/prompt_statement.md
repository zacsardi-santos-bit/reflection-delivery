I'm trying to add a per-listener max active connections cap to Contour and right now there's just no way to bound this, so under heavy load or an adversarial connection-flood each listener happily accepts an unbounded number of connections which can exhaust resources. I want an optional limit that applies to each listener independently, so the HTTP and HTTPS listeners each get their own separate cap rather than sharing one global number.

It's gotta be configurable two ways: in the Contour config file under the listener settings, and via the matching field on the listener spec of the Kubernetes custom resource. When the limit is set I want it dynamically reflected in the runtime config as listeners come and go, so if a listener shows up the cap applies, and if all the listeners disappear the connection limit entries should get cleaned up and removed too, not left dangling.

Behavior when nothing's configured should stay exactly like today, unlimited connections, no regression. Oh and one validation thing: a value of zero should be treated as invalid and rejected during config validation, only positive values (1 or greater) are accepted. So zero errors out, unset means unlimited, and anything >= 1 becomes the actual per-listener cap that gets enforced.
