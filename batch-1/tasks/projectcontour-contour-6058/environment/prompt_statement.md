I'd like to add support for limiting the number of active connections per listener in Contour. Right now there's no way to cap connections at the listener level, so under heavy load each listener can accept an unlimited number of connections. I want to be able to set an optional maximum connection limit that applies per listener independently — so the HTTP and HTTPS listeners each have their own cap.

This should be configurable in both the Contour config file (under the listener settings) and via the corresponding Kubernetes custom resource field. When the limit is set, it should be dynamically reflected in the runtime configuration as listeners come and go — meaning if all listeners disappear, the connection limit entries should also be removed. If no limit is configured, the behavior should remain unlimited as it is today. A value of zero should be treated as invalid and rejected during configuration validation; only positive values should be accepted.
