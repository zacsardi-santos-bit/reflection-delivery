I'm working with a GraphQL library that auto-generates a schema from type definitions. I've defined an interface type that includes a relationship field pointing to another node type. When I look at the generated schema, the relationship field on the interface is missing all the querying arguments — things like filtering by related node properties, controlling traversal direction, and pagination options for the connection variant. These arguments are correctly generated when the same relationship appears on a concrete type, but they're completely absent on the interface.

Additionally, in the extended schema mode, the interface's filter input type is missing the relationship-based filter options — I can't filter interface instances by whether their related nodes match certain conditions (all match, none match, some match, etc.), and there's no aggregate filter either. The aggregation input types that should exist for the relationship on the interface are also not being generated.

This inconsistency means I can't write the same kind of expressive queries against interface types as I can against concrete types. Can you fix the schema generation so that interface types with relationship fields get the same full treatment as concrete types — proper field arguments, aggregation inputs, and relationship filter fields in the where input — regardless of whether the interface has custom directives applied to it?
