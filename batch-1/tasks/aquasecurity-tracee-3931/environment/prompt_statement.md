I'm building out event handling and I keep running into a mess where events depend on other events and there's no clean way to track those relationships. I want a dependency tree component that lives in its own dedicated package under the events directory, something like `@events/deptree/`, and the tree manager gets created via a constructor function that takes a resolver, basically a callback that resolves an event's dependencies by its ID. It doesn't need to be thread-safe, I'll handle that elsewhere.

Here's the behavior I need. When I add an event, all of its transitive dependencies should get pulled in and tracked automatically. Each dependency node needs to know which events depend on it (reference counting basically) so that shared deps get handled right and I don't accidentally nuke a dependency another active event still needs. When I forcibly remove an event (hard removal), everything that depended on it should cascade up and get removed too, and any dependency events that are now unreferenced should cascade down and get cleaned up. There's also a soft removal path where an event just gets deselected: in that case it should only actually be removed if nothing else still depends on it, and its unreferenced deps get cleaned but shared ones stay put, untouched.

Oh and I need observer support. Callers register callbacks that fire whenever a node is added to or removed from the tree so the rest of the system can react. Both add and remove notifications should hand back the affected event node. Important bit: when a hard removal cascades (up through dependents, down through orphaned deps), the removal observers need to fire for each of those nodes too, not just the one I asked to remove.

The whole reason for this is that treating event dependencies as a plain map falls apart the moment multiple events share overlapping dependencies, you end up disabling something another event still relies on. A real dependency tree with proper reference counting and cascading add/remove is what lets the broader system stay consistent when the active event set changes.
