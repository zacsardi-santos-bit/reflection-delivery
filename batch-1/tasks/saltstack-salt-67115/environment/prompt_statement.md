I'm hitting a false success bug in the module state execution path. When a module function returns a dict that carries result info, either a top-level result flag, a numeric return code, or a nested state changes sub-dict, the helper that decides whether the call actually succeeded gets it wrong and reports success even when sub-states failed. That's masking real failures in module runs, which is bad because Salt ends up saying everything's green when it isn't.

The problem is the helper in the module state file over in `@salt/states/module.py` currently takes two separate args, the raw return value and a separate changes dict, and that split just doesn't work when a function crams all the relevant info (result code, numeric return code, nested state data) into one dict. I want it refactored to take a single argument, the full return value, and derive success from that.

Logic I'm after: if the return value is a plain bool, pass it straight through. If it's a dict, look at the top level for a result flag and a numeric return code, where a non-zero return code should override a positive result flag (non-zero means failure). Also it should inspect any nested state changes dict inside the return value using those same rules, so a failed sub-state gets caught. Oh and update every existing call site of this helper within that same module state file to use the new single-arg form, don't leave any two-arg calls hanging around.
