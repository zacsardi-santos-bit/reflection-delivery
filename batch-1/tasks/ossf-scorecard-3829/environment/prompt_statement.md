I'm cleaning up the dependency pinning check in scorecard so it follows the same probe-based shape the other checks already use. Right now the pinned-dependencies logic mashes everything together: it takes the raw dependency data (whether each dep is pinned, its type, its location, any message) and does the raw-to-findings conversion plus the scoring all in one spot, which makes it a pain to test independently and just doesn't match how the rest of the system is laid out.

What I want is a new probe living in its own dedicated package that turns raw dependency check results into structured findings. Each dependency becomes a finding: pinned deps get a positive outcome, unpinned ones get negative, if there are no dependencies at all that's a not-available outcome, and when the pinned status is unknown or ambiguous (missing info) it's not-applicable. Processing failures in the raw data should surface as error-outcome findings. Oh and one edge case, if a dependency has neither a location nor a message the probe should bail with an internal error instead of quietly emitting a bad finding. Every finding needs to carry the dependency type as metadata, and the probe should expose its name as an exported identifier so callers can reference it.

Then the evaluation function needs to change so it accepts a slice of pre-computed findings plus a logger, instead of the raw data and the full check request it takes today. It computes the score and logs messages based on the outcomes in those findings. The top-level check entry point should just take the check request and wire the whole flow together (run the probe, hand findings to the eval, return the result).

Also the text-generation helpers that describe why a dependency is unpinned should move into the probe package too, since that's where the findings actually get created. Point being, this decouples the data-to-finding conversion from scoring so each layer is testable on its own and consistent with everything else.
