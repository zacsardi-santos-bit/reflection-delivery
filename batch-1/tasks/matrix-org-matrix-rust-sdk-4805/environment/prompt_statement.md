I'm cleaning up the auth layer in our Rust SDK and the naming is bugging me. We do an OAuth 2.0 flow but the whole public surface is branded around OpenID Connect, so everything says "Oidc" or "OIDC" even though what we actually implement is the broader OAuth 2.0 thing. Devs who know OAuth keep tripping over it because the type names, method names, module paths, and error variants all reference the narrower identity protocol. I want to rename it all to consistent OAuth naming so anyone reading the API instantly gets that it's an OAuth 2.0 integration without having to know the history.

So the auth module path itself should move to an oauth path instead of oidc, and every import from it should come through that oauth path. The main authentication struct returned by the client needs renaming, and so does the authorization data type. The client method that hands back the authentication handler should use OAuth naming too. On the error side, rename the top-level wrapper variant plus the specific sub-types for registration errors, authorization code errors, and token refresh errors, including how those show up in the top-level error enum and in the token refresh error type, and their variants. The variant of the cross-signing reset auth type that's used for this flow should switch to OAuth naming as well. Internally there's a metadata cache field and its lookup key that should move to OAuth or server-oriented naming, oh and the method that fetches server metadata should drop the narrower standard's name in favor of something more general (server-metadata style, not tied to the sub-standard). Goal is consistent OAuth terminology end to end so error handling and pattern matching all use the future-proof names.
