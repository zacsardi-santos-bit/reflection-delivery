I'm working on the governance module and want to add a new parameter called "yes quorum" — a minimum fraction of total voting power that must vote yes for a proposal to pass. Right now, governance only checks that enough tokens participated (the regular quorum) and that enough of the participating tokens voted yes (the threshold). But there's no way to require that a minimum absolute portion of the total stake must specifically vote yes.

I'd like this new parameter to be supported both in the global governance parameters and in per-message governance parameters. When the per-message params are validated and the yes quorum is negative, it should be rejected with an error. When tallying votes, if the yes quorum is set and the actual yes votes as a fraction of total voting power fall short, the proposal should fail but the deposit should not be burned (same behavior as failing due to lack of quorum participation).

I also need the chain upgrade migration to handle the case where chains upgrading from older versions will have this field empty — it should be populated with the default value during migration. Finally, simulation-based genesis generation should randomly generate a yes quorum value as part of the governance parameters.
