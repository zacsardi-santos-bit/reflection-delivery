I'm working on the governance module and want to add a new "yes quorum" parameter, basically a minimum fraction of total voting power that has to vote yes for a proposal to pass. Right now governance only checks that enough tokens participated (the regular participation quorum) and that enough of the participating tokens voted yes (the threshold), but there's nothing that requires a minimum absolute portion of the total stake to specifically vote yes. That's a gap, because a proposal can currently pass with yes votes that are a big fraction of participants but a tiny fraction of total stake, and I want a safeguard for a minimum level of explicit support from the overall staked supply.

So I need this new field supported both in the global governance params and in the per-message governance params. When the per-message params get validated and the yes quorum is negative, reject it with an appropriate error. When tallying votes, if the yes quorum is set and the actual yes votes as a fraction of total voting power fall short of it, the proposal should fail but the deposit should not be burned, same behavior as failing due to lack of quorum participation (don't burn it).

Also the chain upgrade migration needs to handle chains upgrading from older versions where this field will be empty, so populate it with the default value during migration rather than leaving it blank. And the simulation-based genesis generation should randomly generate a yes quorum value as part of the governance params too.
