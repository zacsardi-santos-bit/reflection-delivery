I'm hitting a couple of translation bugs in Oppia around exploration reverts. When we call `revert_exploration` to roll an exploration from its current version back to some earlier version, the translation counts just don't get touched at all, so the opportunity summary keeps showing whatever counts it had before. What I want instead is for a revert to update everything to match the target version, meaning new `EntityTranslationsModel` records get created for the new post-revert version and those records should only carry the translations that actually existed for the version we're reverting to. The reverted-to translations need to be preserved, but the stale counts have to go.

Tied to that, `ExplorationOpportunitySummary.translation_counts` should end up accurately reflecting how many translated content items exist per language after the revert, not the old numbers.

There's a related issue too. When someone updates an exploration in a way that removes content IDs, like switching the interaction type from a Continue button over to MultipleChoiceInput which drops certain customization-args content IDs, the translations for those now-gone content IDs are still hanging around in the new translation models. Those orphaned translations should be deleted when their content IDs no longer exist in the new version, so the models don't accumulate junk for content that isn't there anymore.

So basically two fixes: get the translation count handling right during reverts (create the version-specific translation records and refresh the summary counts), and make sure removed content IDs take their translations with them on any exploration update.
