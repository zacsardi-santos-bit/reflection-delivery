I'm building a data pipeline that pulls change-data-capture events off several Kafka topics at once, and the annoying part is each topic uses a different serialization format. When I deserialize rows from these mixed sources, every row loses track of which table it originally came from, so I can't tell them apart or route them correctly once they all land in the same sink. Right now the deserialization schemas only take a bare schema type object (just field names and types), which is where the whole thing falls down for multi-source configs.

What I want is for the deserialization schemas, the JSON ones including the CDC-specific formats, the Avro schema, and the related schemas, to accept a richer table metadata object instead of the plain schema type. That metadata should encode both the schema structure and the table's identity, meaning catalog, database, and table name together. Then after deserialization each row needs to carry the table identifier derived from that metadata, so downstream components can figure out where a row came from.

I also need a utility method that builds one of these table metadata objects from an existing schema type given catalog, database, and table name strings, so I'm not hand-constructing them everywhere. Oh and once rows are tagged with their origin, I want to actually run a multi-source Kafka pipeline that reads from different topics using different CDC formats (say two different CDC formats on separate topics) and correctly merges everything into a single destination table with proper upsert behavior keyed on row identity. That last bit is really the end goal here, the metadata plumbing is just what unblocks it.
