I'm working on the state sync path in our blockchain node and hit a real limitation. Right now when a fresh node wants to download the full chain state it asks a peer for a snapshot at some block height, but every peer picks a different block, so a syncing node can't pull pieces from multiple peers in parallel because the snapshots are incompatible. I want all peers to independently agree on one consistent archive point so parallel downloads actually work and onboarding gets faster and more reliable.

The plan is to compute the archive height deterministically: take the current head height, subtract the state sync threshold, then round down to the nearest multiple of a configurable archive interval. Since every peer runs the same math they all land on the same height and serve the same snapshot. I need a method on the chain that returns the block header at that computed archive height (the snapshot peers are currently offering for state sync).

The archive interval should differ by mode, small in automated testing (10 blocks) to keep tests fast, and in production roughly 12 hours worth of blocks. Also while I'm in the config, the existing cut-through horizon value in testing is shared between automated testing and user testing modes and that's messy, so please split it into separate cut-through horizon values for each mode rather than one shared one.
