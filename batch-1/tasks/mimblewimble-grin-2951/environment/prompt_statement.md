I'm working on improving the state sync process in our blockchain node. Right now, when a new node wants to download the full chain state, it can request a snapshot from a peer at some block height. The problem is that different peers might each offer a different snapshot, so a syncing node can't download from multiple peers in parallel — the pieces would be incompatible.

I'd like to add a way for all peers to agree on the same consistent archive point that they serve to syncing nodes. The idea is to compute this archive height deterministically: take the current head height, subtract the state sync threshold, then round down to the nearest multiple of a configurable archive interval. That way, every peer independently computes the same height and serves the same snapshot.

There should be a method on the chain that returns the block header at this computed archive height. The archive interval should be different for automated testing mode versus production — small in tests to keep them fast, and larger in production to represent roughly half a day's worth of blocks. The testing configuration should also be cleaned up so that automated testing and user testing modes use separate cut-through horizon values rather than sharing a single one.
