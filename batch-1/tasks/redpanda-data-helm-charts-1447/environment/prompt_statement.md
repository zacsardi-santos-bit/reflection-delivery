I'm doing some cleanup on the connectors Helm chart and hit a gap in the Go-based templating layer. Right now the connectors package doesn't have any type that represents service configuration, so any chart code that manages Kubernetes Service resources has no type-safe way to reference service settings. Everything else already has this covered, deployment and pod configs both have their own dedicated config types in the package, but service is the odd one out and it's blocking me from moving the service template off raw YAML and onto Go-backed templating.

What I want is a proper exported type in the connectors chart package that holds service configuration, something chart authors can reference consistently alongside the other configuration types that already live there. It needs to be exported so chart code constructing Service resources can actually use it, and it should slot in cleanly next to the deployment and pod configuration types so the whole configuration model stays uniform. Basically I'm just bringing service settings in line with the rest of the chart's config model so I can do the template refactor later without fighting the type system. Just need the service config type to exist, be exported, and be usable in a type-safe way for building out Service resources.
