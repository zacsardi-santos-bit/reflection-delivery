I'm working on the TextInput component that has an autocomplete suggestions feature, and right now the rendered markup is basically invisible to screen readers. When I give it a list of suggestions there's nothing semantic in the DOM for assistive tech to work with, so people using a screen reader have no idea the field is even an autocomplete, can't tell suggestions showed up, and can't navigate through them or figure out which one is highlighted. I want to fix the accessibility here so it follows the standard combobox pattern.

Here's what I'm after. When the component has an id and suggestions are actually provided, the input element itself should announce that it's an autocomplete combobox (so the combobox role plus the autocomplete indication) and it should expose whether the suggestion list is currently open or closed via the expanded state. The dropdown container that holds the suggestions should identify itself as a listbox and carry a stable unique identifier derived from the input's id so the input can reference it. Then each individual suggestion item should be marked as a selectable option, get its own unique id based on its position (index) in the list, and expose whether it's the currently selected value.

All of this only kicks in when there's an id set and suggestions exist, so don't add these roles/states/ids when there are no suggestions to show. Basically I want the input, the listbox container, and every option to each carry the right role, state, and identifier so the whole widget reads correctly to assistive technologies.
