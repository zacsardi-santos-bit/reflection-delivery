I'm hitting a TLS problem with the MongoDB Go driver around how it loads CA certificate files from the connection URI. When I point it at a CA file that has multiple certs in it, say a root CA followed by a couple intermediates like you'd see in an enterprise chain, only the first cert actually makes it into the trusted pool. Everything after that just gets dropped, so TLS validation blows up in any environment where the whole chain needs to be trusted, and it fails kind of silently which makes it a pain to track down. I want the loading logic (this lives in the config/CA handling code where the driver reads the PEM file and appends to the cert pool) to walk through and load every PEM certificate block in the file, not just stop after the first one.

The other half of this is error messages. Right now when the CA file is bad the driver spits out different internal errors depending on how it's bad, and none of them are helpful. If the file's empty, or it has no certificate blocks at all (like it's just a private key sitting there with no CERTIFICATE section), or it's got malformed non-PEM garbage in it, I get inconsistent messages that don't tell me what's actually wrong. I'd rather all three of those cases collapse into one consistent, clear error that just says the file doesn't contain any valid certificates. That way anybody misconfiguring their CA file can figure it out fast instead of digging through cryptic internals. So basically: load all the certs, and return one descriptive no-valid-certs error for the empty, no-cert-block, and malformed cases alike.
