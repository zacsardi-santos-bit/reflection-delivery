I'm running the entity generator to reverse-engineer my MySQL schema into TypeScript entity files, and I've got the option turned on that also emits scalar properties next to the relation properties for foreign key columns. Those extra scalars are the non-persisted (virtual, read-only) ones that let me read the raw FK column value directly without loading the related entity, which is super handy. Problem is they're coming out stripped of column metadata from the actual DB definition, so the generated code is an inaccurate picture of the schema and I keep having to hand-patch it after every run, which kind of defeats the whole point of automating it.

Concretely, when a FK column is an unsigned integer, the generated scalar drops the unsigned flag (so a positive-only column looks like it allows negatives). When a FK column is a fixed-length character type like a 2-char country code, the generated property loses that length. If the column has auto-increment set, that attribute gets dropped too. And if the column uses a non-standard database-specific type, like MySQL's YEAR type, the native column type doesn't carry through either.

What I want is for the generator to propagate all the relevant column attributes, so unsigned, length, auto-increment, and the native column type all get copied onto these scalar FK properties when it builds them. That way the generated entities actually match the underlying database schema (a column that only allows positive numbers stays unsigned, a fixed-length char column keeps its length, etc.) and I get ready-to-use files without manual corrections.
