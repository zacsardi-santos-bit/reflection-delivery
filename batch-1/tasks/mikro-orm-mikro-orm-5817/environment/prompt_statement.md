I'm using the entity generator to reverse-engineer my MySQL database schema into TypeScript entity files. I have the option enabled that generates additional scalar properties alongside the relation properties for foreign key columns — these are the non-persisted properties that let you directly read the raw FK column value. The problem is that these generated scalar properties are missing column metadata from the actual database definition.

For example, when a foreign key column is an unsigned integer, the generated property doesn't include the unsigned flag. When a FK column is a fixed-length character type (like a 2-character country code), the generated property omits the length. If a column has auto-increment set, that attribute is also dropped. And if a column uses a non-standard database type (like MySQL's YEAR type), the native column type isn't carried through either.

I'd like the entity generator to propagate all relevant column attributes — unsigned, length, auto-increment, and native column type — to these scalar FK properties, so that the generated code accurately matches the actual database schema and doesn't need manual corrections after every generation run.
