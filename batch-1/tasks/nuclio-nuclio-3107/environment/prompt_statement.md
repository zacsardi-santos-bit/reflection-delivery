I'm chasing down a bug in our defaults-populating helper, you know the one that takes an object plus a map of default values and is supposed to backfill only the empty fields. The whole point is that if a field already holds something meaningful the function leaves it alone, and only unset (zero-value) fields pick up the default. Right now it's doing the wrong thing though, it's clobbering fields that already have a value.

What I'm seeing is the function only checks whether the incoming value from the map is non-zero before assigning it, but it never checks whether the existing field is already set. So if I've got an object where a string field is already a non-empty value and I call this to fill defaults, that existing string gets overwritten when it should've been preserved. Same deal for integers, a field already holding a non-zero number shouldn't get replaced, and for booleans a field that's already true should stay true even when the incoming map also says true.

Can you fix it so it only writes into a field when that field is currently at its zero value, leaving already-populated ones untouched, and make that logic consistent across string, integer, and boolean field types? This matters because callers rely on this to safely apply defaults without stomping on values they explicitly set, and it's the kind of thing that silently corrupts config or object state without anyone noticing.
