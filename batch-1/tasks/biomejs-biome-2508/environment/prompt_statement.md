I'd like to add a new lint rule to biome's nursery category that enforces adjacent placement of overloaded function and method signatures in TypeScript. When the same method or function name is declared multiple times with different parameter types (overloads), all those declarations should appear consecutively — but right now biome has no rule to catch when they're scattered with other unrelated members in between.

The rule should flag code in classes, interfaces, type aliases, namespace declarations, top-level exported functions, and function return type annotations whenever overloads for the same name are not adjacent. For valid code where all overloads are already grouped together, no diagnostic should appear. This mirrors a well-known rule from a popular TypeScript-focused linter, so migrating teams would benefit from it as well.
