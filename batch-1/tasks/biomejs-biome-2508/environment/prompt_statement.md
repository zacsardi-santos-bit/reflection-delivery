I'm trying to add a new nursery lint rule to biome that enforces adjacent placement of overloaded function and method signatures in TypeScript. You know how TS lets you declare the same name multiple times with different parameter types? Those overloads should all sit next to each other, but right now biome has nothing that catches when they're scattered around with unrelated members wedged in between, which makes stuff way harder to read and maintain and also makes it easy to accidentally forget to update one when you add a new overload far from the others.

So what I want is a rule that reports a warning whenever any two signatures for the same name are separated by one or more members that have a different name. It's gotta work across all the relevant TS declaration contexts, so classes, interfaces, type aliases, namespace declarations, top-level exported functions, and function return type annotations too. And when all the overloads for a given name are already grouped together consecutively, no diagnostic should fire, that's the valid case.

This basically mirrors a well-known rule from a popular TypeScript-focused linting plugin, so teams migrating from that toolchain would get an easy win adopting biome. Put it in the nursery category since it's new.
