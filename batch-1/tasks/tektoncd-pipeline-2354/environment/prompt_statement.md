I'm hitting two related bugs with Tekton pipelines when a downstream task's condition tries to consume the result of an upstream task. Basically I've got a pipeline task with a condition whose parameter value is a variable expression referencing another task's result, and the ordering is wrong. The dependency graph doesn't count that result reference as an actual dependency, so the conditional task can get scheduled before the task producing the result has even finished. I'd want the pipeline to look at the params on the conditions attached to a task, spot any result references in there, and treat the task that owns that result as an execution dependency so ordering comes out right and the conditional task only runs after its upstream completes.

Second thing, even when the upstream does finish first, the condition params still hold the raw placeholder expressions instead of the resolved values. It looks like the step that applies task results and substitutes them into params only walks the pipeline task's own parameters and skips the parameters passed to the conditions on that task. So when results get applied to a pipeline run I want that substitution to also reach into the params of every condition associated with each pipeline task, swapping any result reference placeholders for the actual resolved values. Fix both gaps together, the ordering enforcement and the substitution, so conditions can actually receive and use results from upstream tasks.
