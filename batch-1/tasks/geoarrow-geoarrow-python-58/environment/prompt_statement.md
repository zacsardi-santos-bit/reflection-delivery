I'm working with a geospatial type library that uses Arrow metadata to describe geometry types, including coordinate reference systems. Right now, the only way to attach a CRS to a geometry type is to provide a full structured JSON object for the CRS. But I often just want to use a plain authority string — something like a short well-known identifier — without needing to look up or construct the entire PROJJSON dictionary.

I'd like the library to support a new kind of CRS value that simply wraps a plain string. This should work anywhere CRS values are accepted: when constructing type specs, when calling methods or functions that set the CRS on a geometry type, and when passing raw strings the library should automatically convert them to this new string-based CRS type rather than erroring out.

There's also a related serialization issue. When type metadata is serialized to a string, there's currently no way to tell whether the CRS field was originally a structured JSON object or a plain string. I'd like the library to add a discriminator field to the metadata when the CRS is a structured object, so that round-tripping works correctly — parsing metadata back should restore the same CRS type that was originally used.

The new string-based CRS wrapper should also be smart about its contents: if the string happens to be a valid JSON object, it should be usable directly; if it's an authority code string, it should be able to delegate to an external CRS library for richer operations like converting to WKT or full JSON. A plain quoted JSON string input should be transparently unwrapped.
