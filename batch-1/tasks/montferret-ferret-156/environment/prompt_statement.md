I'm poking at the ferret datetime standard library and hit a gap that's kind of annoying. I can already pull the year, month, and day out of a date-time value, but there's no equivalent for the time-of-day side of things, so if I want the hour or minute or second I'm stuck doing string manipulation or some other indirect hack. That's a real problem for any script that needs to filter or compare on specific time portions, and honestly it just feels incomplete next to what people expect from a date/time toolkit.

So I want three new functions added to the datetime package, one each for hour, minute, and second, that take a single date-time argument and return the component as an integer. Hour comes back in the 0 to 23 range, minute is 0 to 59, and second is 0 to 59 too. Each one accepts exactly one date-time arg and nothing else, so if a script calls it with zero args or more than one, that should be an error rather than silently doing something weird.

Also, and this is easy to forget, these need to actually be registered in the datetime library by name so scripts can call them the same way they call the existing year/month/day extractors, otherwise they're just dead code nobody can reach.
