I'm working on cleaning up how the data node bootstrap system is wired together. There are two interface changes I need to make. First, the component that manages connections to peer nodes currently requires callers to pass in a logger at construction time. Since we have a shared application-level logger available globally, that explicit logger argument should be removed and the implementation should use the global one internally. Second, the bootstrap manager currently takes a full top-level options object as a parameter even though it only needs the bootstrap-specific subset of those options. I'd like to change its constructor to accept just the bootstrap-specific options type instead of the full bundle.

Beyond the signature changes, I also need to make sure the bootstrap manager correctly handles concurrent bootstrap requests. If ten goroutines all call the bootstrap method at the same time while a bootstrap is already running, the manager should not kick off ten additional bootstrap cycles — it should track that there's a pending request and run exactly one more bootstrap after the current one completes. That means ten simultaneous calls should result in at most two actual underlying bootstrap executions. I also want the manager to properly expose whether bootstrapping has completed and when the last successful bootstrap finished, so callers can check that state reliably.
