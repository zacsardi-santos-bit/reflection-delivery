I'm reworking the adaptive operation tracker in our distributed storage system and I need help extending its granularity. Right now when we send a read request to a replica, the tracker compares how long that request has been inflight against a historical latency distribution, and if it's past the threshold we fire off a speculative request to another replica. The problem is we only track latency at two levels: the whole datacenter, or per partition. So all replicas in a datacenter (or all replicas of a partition) share one distribution. That works fine when everything's homogeneous, but in practice some individual nodes or disks run consistently slow, and a slow disk mixed with fast ones just dilutes the histogram and delays detection, while a healthy node can get wrongly flagged because it shares a histogram with a slow peer. I want finer-grained tracking, one distribution per individual data node, and one per individual disk.

So a couple things need to happen. The metrics layer should stop being partition-specific and use a more general "resource" abstraction as the map key, so partitions, data nodes, and disks can all be used interchangeably, basically generalize the existing partition-level histogram maps to work with any resource type and expose those resource-level maps from the metrics infrastructure. Also the tracker scope config needs two new options, one for data node granularity and one for disk granularity, on top of the existing datacenter default. When node-level scope is configured, populate the histogram maps with one entry per data node in the cluster, split by whether the node is local or remote. When disk-level scope is configured, one entry per unique disk, again split by locality. And when we're at datacenter-level scope (the default), leave these finer-grained maps unallocated, don't allocate them. Then the tracker itself has to pick the right histogram when checking if a request is past due, for node-level look up by the replica's data node, for disk-level look up by the replica's disk. Point is degraded nodes and slow disks get speculative requests dispatched sooner and more precisely without hurting unrelated replicas.
