I'm adding a reusable CAPTCHA verification service to Ghost so we stop leaving form submissions and similar endpoints open to bot traffic. Right now there's no standard way to validate anti-bot tokens on incoming requests, so I want one service that wraps an external bot-detection provider and hands back a middleware function I can drop into any HTTP route.

The service needs to be configurable. At minimum I want a flag for whether it's enabled, the secret key the provider uses to verify tokens, and a numeric score threshold that decides when traffic looks suspicious. When it's enabled it should produce request middleware that pulls the anti-bot token out of the request body.

Behavior I'm after: if there's no token in the request, pass an error downstream saying the token is missing (don't just let it through). If the external verification call throws or rejects for any reason, catch it and pass a graceful, descriptive error downstream instead of crashing the server. If verification succeeds but the returned score is at or above the configured threshold, that's likely a bot, so block it by passing a generic server error downstream, and don't leak the actual score or any provider details in that message. If the score is safely below the threshold, let the request through with no error at all.

Oh and it has to support being turned off entirely. When the service is disabled the middleware should just be a no-op that calls straight through to the next handler without doing any verification. The whole point is I can add CAPTCHA protection to a route without copy-pasting this logic everywhere.
