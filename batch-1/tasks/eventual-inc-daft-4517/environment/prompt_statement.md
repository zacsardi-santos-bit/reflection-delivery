I'm poking at Daft's distributed execution engine and the pipeline node naming is bugging me. Right now the distributed nodes carry generic internal names that don't make it obvious they're part of the distributed layer, so when I'm debugging a distributed query plan I can't tell at a glance what I'm looking at or how it differs from the local physical plan nodes. I want each node type to get a descriptive name with a "Distributed" prefix that reflects its specific job, so the in-memory scan node, the file-based scan node, the limit node, and the intermediate processing node each end up with a self-describing prefixed name that reads cleanly when I'm inspecting things.

Beyond the renaming I also want these distributed pipeline nodes to support visualization in both ASCII text and Mermaid diagram form, kind of like what already exists for local physical plans. So each node type should be able to describe itself for display, and there should be top-level functions to render the whole distributed pipeline as either an ASCII tree or a Mermaid diagram. This matters because visualizing a distributed plan just isn't possible today, and being able to see the structure the same way I can for local plans makes the whole thing way more observable.

Couple of related internal cleanups while I'm in here. The methods that create work tasks should take collections of inputs instead of a single item at a time. And the execution config, oh, right now it gets threaded through each layer separately at execution time, I'd rather it be carried as part of the plan structure itself so it's not passed around everywhere. Clear consistent naming plus the visualization should make debugging distributed execution a lot less painful.
