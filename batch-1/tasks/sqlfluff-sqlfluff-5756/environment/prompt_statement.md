I'm hitting a wall with SQLFluff on our Snowflake queries. Anytime a query uses Snowflake's ASOF JOIN (the time-series thing that matches each row to the most recent row in another table by timestamp), SQLFluff just blows up with a parse error and can't process the file at all. Makes it useless for linting or fixing any Snowflake SQL that leans on this feature, and a lot of our time-series analysis does.

The syntax is basically the ASOF JOIN keyword followed by a MATCH_CONDITION clause that takes a comparison expression in parentheses, like matching on a timestamp with an operator inside. Optionally there's an equality ON condition after that too. I need the dialect in `@src/sqlfluff/dialects/dialect_snowflake.py` to actually understand this, parse it cleanly with no errors, and let SQLFluff lint and fix files containing it.

A few things I want it to handle: the MATCH_CONDITION should show up as its own distinct named node in the parse tree (not just folded into something generic), the optional ON equality condition needs to parse correctly too, and I should be able to chain multiple of these ASOF joins in one query and have all of them parse. It's also gotta play nice when combined with regular join types in the same query. Oh and the match condition should support the usual comparison operators, greater than or equal to, greater than, less than, whatever, all of those inside the parens.

Basically parsing it right is the whole ask, both the clean parse and the ability to run lint/fix over it without choking.
