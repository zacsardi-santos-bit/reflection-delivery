I want to add plugin persistence plus garbage collection to nushell's plugin infrastructure, since right now every command invocation spins up a fresh plugin process and throws it away the moment it's done, which wastes a ton of time on repeated startup and makes it impossible to keep any plugin state around between calls. I want plugins to stay running after a command finishes so the next call can reuse them without re-spawning, and I want users to be able to list their installed plugins and see whether each one is currently running along with its process ID, plus manually stop a specific plugin process when they want to.

On config, the gc settings should live under their own dedicated section with a global default and per-plugin overrides for how long an idle plugin keeps running before the host shuts it down automatically. That idle timeout only accepts non-negative durations, so a negative value needs to get rejected with a proper error message. Also a plugin should be able to opt itself out of gc by sending a message to the host, and the host should never stop a plugin while it's still producing active streaming output. And when nushell itself exits, the plugin processes should exit too.

Protocol-wise I need a new kind of plugin output message that configures host-side behavior (like disabling gc), and it's gotta survive round-tripping through both the JSON and msgpack encoders. Oh and the type we use to track which plugin a custom value came from needs reworking, it should be shared by reference across all the values it's attached to, and identity should be about whether two values share the same origin object rather than comparing contents. Custom values should stay usable even after their originating plugin got stopped, so the host should automatically re-spawn that plugin when it needs to process the value. This all lives in the plugin crates under `@crates/`.
