I'm hacking on the Winch JIT compiler and hit a wall with atomic bitwise ops on shared memory. Right now the x86-64 backend can compile atomic add, sub, and exchange RMW operations, but the three bitwise variants (AND, OR, XOR) just aren't there yet. So any Wasm module that atomically flips individual bits in shared memory can't be compiled by Winch at all, which kills a whole class of multi-threaded programs. That pattern shows up constantly in synchronization primitives and concurrent data structures, and the threads spec defines these as part of the standard atomic instruction set, plus the other backends already handle them, so Winch's kind of the odd one out here.

What I want is the full set of atomic bitwise read-modify-write ops wired up in the x86-64 backend. That means AND, OR, and XOR each covering all the standard integer widths, so 8-bit, 16-bit, 32-bit, and 64-bit, for both the i32 and i64 result types (the sub-word 8/16-bit ones being unsigned variants like the existing code does). Each op needs to emit correct machine code that atomically reads the memory value, applies the bitwise operation, writes the result back, and returns the original value, matching exactly how the current atomic add/sub/exchange work. Oh and alignment checking for the sub-word and multi-byte cases should be handled the same way it already is, so aligned operations trap on a misaligned address just like the existing ones do. Basically I want this to bring the backend to parity with the spec and the other compilers, no surprises in behavior.
