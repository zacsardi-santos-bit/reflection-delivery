I'm building out the Codex CLI and I keep hitting the same annoying gap: when the remote coding agent finishes a task it hands back a diff, but there's no way to actually get that diff into my local git repo without me copy-pasting patch text and running things by hand. I want a new library crate in the workspace that takes the agent's task response data, digs out the embedded diff, and applies it to my current working tree using a 3-way merge.

The response data comes in as a JSON structure with an optional current turn field, and that turn holds a list of output items. The code-change (PR type) items are the ones carrying the actual diff text; any other item type in the list I just want silently skipped. So the deserialization needs to handle that shape gracefully. Both the apply function and the response types should be public from the crate.

Behavior I care about: when the diff applies cleanly with no conflicts against local state, it succeeds and the new or modified files show up in the working tree with the right content. When the incoming diff conflicts with locally committed content, don't try to be clever, just fail and leave the standard merge conflict markers in the affected files so I can resolve them myself. And if the response has no current turn, or there's no PR-type output item with a diff in it, that's an error, not a silent no-op. Diverged local state should surface right away instead of getting quietly lost.
