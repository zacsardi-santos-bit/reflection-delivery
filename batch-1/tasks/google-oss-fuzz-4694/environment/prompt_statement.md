I'm poking at the compiler wrapper script we use for sanitizer library builds and there's a function in there that's supposed to strip out the linker flags that enforce strict symbol resolution, you know the ones that make the linker blow up when symbols are left undefined on purpose. That matters because sanitizer builds link against libs that intentionally leave some symbols unresolved, so passing strict "all symbols must be defined" flags just fails the whole thing, and stripping them at the wrapper level means we don't have to touch every individual build system.

First off the function name is camelCase and I want it renamed to lowercase-with-underscores like proper Python. Beyond the rename though the logic has gaps. The standalone form of the "no undefined symbols" linker option isn't getting stripped right now, only the version that's baked into a compound flag group gets handled, and I want both forms removed. Also when the flag is split across two separate linker tokens and there's some unrelated argument sitting between them, the function totally misses the pair, so it needs to catch that split case even with intervening args in the middle.

Otherwise keep everything else intact. It should still preserve all the other linker flags, including the ones controlling memory layout like relro and related options that have nothing to do with symbol-definition enforcement. And for the compound args that mix relevant and irrelevant sub-options, only pull out the relevant sub-options and leave the rest alone. Oh and multiple preceding arguments before the flag we're removing shouldn't trip up detection or removal either.
