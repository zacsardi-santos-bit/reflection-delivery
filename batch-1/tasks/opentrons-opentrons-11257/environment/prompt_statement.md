I'm working on the Opentrons desktop app and I need to improve how users can change the Python interpreter path in the app settings. Right now, when someone clicks "Add override path", the UI relies on a hidden file input element embedded in the page to show a directory picker — it's a workaround for browser limitations and it's fragile. I'd like to replace this with a proper shell-level native directory picker so the app-shell handles the dialog directly.

Beyond the UI fix, I also need to move the actions related to Python interpreter management out of the general configuration module. There are two actions involved: one that triggers opening the current Python interpreter directory in the OS file explorer, and one that triggers the directory picker for changing the override path. Both of these logically belong in a new, dedicated protocol-analysis module rather than in the generic config module. The new module should be set up so it can be used both from the UI layer (to dispatch these actions) and from the app-shell layer (to handle them).

The app-shell handler should be registered at startup alongside other shell handlers, accept the main browser window as an argument, and return an action handler that responds to these two new actions. For the "change path" action, it should open a native directory picker and — only if the user actually selects a directory — dispatch a config update with the chosen path. For the "open directory" action, it should open the currently configured path in the OS file explorer. The shell's dialogs module should also expose a utility for opening a directory path in the file explorer.
