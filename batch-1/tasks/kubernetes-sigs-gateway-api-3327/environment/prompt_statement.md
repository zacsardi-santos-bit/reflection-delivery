We're preparing a release candidate for the Gateway API project and need to advance the bundle version identifier embedded throughout the codebase. Right now, the version label is still set to the development snapshot designation from before the release candidate milestone was reached. This needs to be updated to the release candidate label so that conformance tooling, which reads the bundle version annotation from installed CRDs and validates it against the expected current version, correctly recognizes the release candidate. Until this is updated, conformance tests that check for the release candidate version are failing because the code still reports the old development label.
