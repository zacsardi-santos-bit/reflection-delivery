I'm working on refactoring the git credential management code in the GitHub CLI's auth package. Right now, everything is crammed into one place — detecting which credential helper is active, writing our own helper into git config, and updating stored credentials all live together and are hard to test independently.

I'd like to extract this logic into a dedicated sub-package with three focused types: one that represents a configured credential helper and knows whether it belongs to our tool or another, one that reads and writes git credential helper configuration in global git config (covering both the main hostname and its associated gist hostname), and one that stores and replaces credentials using the git credential system.

As part of this, the existing credential flow type in the shared auth package needs its fields reorganized to use these new types, and a method that was previously internal needs to be promoted to a proper public method with a cleaner name. The setup-git command's options struct also needs a field rename to reflect the updated interface, which should now only expose the single method needed to register our tool as the credential helper for a hostname.

The new types should be independently testable — the helper configuration type should correctly handle cases where no credential helpers exist, where a global third-party helper is already set, and where a host-specific third-party helper is already set. The credential update type should erase old credentials before storing new ones so that a subsequent credential lookup returns the updated values. The helper representation type should be able to distinguish our tool's helper command from other helpers, including edge cases like commands that look similar but aren't ours, and should handle Windows-style paths correctly.
