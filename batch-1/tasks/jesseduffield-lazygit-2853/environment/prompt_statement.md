I want to extend our scripted integration test framework so we can reuse it to produce animated demo recordings for the docs and README, not just automated correctness checks. Right now every integration test runs in CI, but demo scenarios have artificial pauses and timing quirks that make them slow or flaky, plus they need on-screen captions, so I need a clean way to mark a test as a demo and have the automated runner skip it entirely since demos get recorded manually.

So first, add a demo flag to the integration test setup so a test can be written exactly like a normal one but tagged as a demo, and make the runner that iterates the global test list ignore anything flagged that way. Then on the test driver I need methods to set a visible caption during recording, both a prefix label (think current task name) and a body caption (think current key being pressed), and the same caption-setting methods should exist on the view driver too so demo scripts can annotate what's happening mid-scenario.

Also the shell helper we use to set up repos needs a new method for creating several commits with realistic-sounding randomized messages and file names, so demos look natural instead of using sequential fixture names like file01, file02.

Once that infra's in place, add a small demo package with four initial scenarios, each registered in the global test list and marked so CI skips it: one staging a file, making a commit, and pushing to a remote; one cherry-picking commits from another branch; one doing an interactive rebase; and one using git bisect to find a bad commit. The idea is these can be run manually in slow mode to record with external tools, and when the UI changes we just regenerate them.
