I'm hitting a wall with TLS between orderer nodes in a Raft cluster on Hyperledger Fabric. The issue is that when I dial a gRPC client connection over TLS, the trusted root certificate authorities get baked into the static TLS credentials at dial time and can never change after that. So if we bring up a new orderer node that uses a different TLS root CA than what the existing members were configured with, the existing members can't verify the new node's cert, the connection fails, and it stays failed. There's no way to recover short of tearing everything down and restarting every cluster member, which is brutal in a live cluster.

What I want is to be able to pass a dynamic callback when I create a connection (the code lives around `@internal/pkg/comm/connection.go`, the gRPC client connection setup there) that gets invoked on each TLS handshake attempt. The callback would receive the current TLS config before the handshake and could mutate it, for example by swapping in a new trusted root cert pool based on whatever the current system state is. That way a connection that starts out failing because the root CAs don't match shouldn't permanently die, it should just sit in a temporary failure state, and then once the callback starts returning the correct root CAs and a reconnect gets triggered, the connection recovers automatically to a working state without ever being closed and reopened.

The real payoff here is that adding a new consensus node with a different CA to a running cluster no longer needs a full restart, we can just update the root CAs in the channel config after the node joins and let connections heal themselves.

Oh and this has to stay backward compatible. Any existing connection code that doesn't pass a callback needs to keep working exactly like it does today, no changes required on that path.
