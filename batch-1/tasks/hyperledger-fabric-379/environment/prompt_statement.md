I'm working on Hyperledger Fabric and running into a problem with TLS connections between orderer nodes in a Raft consensus cluster. Right now, when I create a gRPC client connection with TLS, the trusted root certificate authorities are set once at connection creation and can never change. This means that if we bring up a new orderer node that uses a different TLS root CA than what the existing cluster members were configured with, the connections fail and stay failed — there's no way to recover without tearing everything down and restarting.

What I'd like is the ability to pass a dynamic callback when establishing a connection that gets invoked on each TLS handshake attempt. The callback would receive the TLS configuration and could update the trusted root CAs (or other parameters) based on whatever the current state of the system is. That way, a connection that initially fails because the root CAs don't match could automatically recover once the correct root CAs are made available through the callback — without closing and reopening the connection.

The change should be backward compatible: code that creates connections without any callback should keep working exactly as before.
