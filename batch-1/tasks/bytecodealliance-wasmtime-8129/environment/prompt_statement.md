I'm working on Wasmtime and I want a new integration test suite that exercises the actual WebAssembly to native code compilation pipeline through Wasmtime's own code generator instead of dropping down to the lower-level Cranelift filetest stuff. Right now if I want to check how a wasm module lowers to machine code I have to hand-write all the VM globals, heap bounds, memory configs and other low-level IR details inline in every filetest, which is super tedious and, worse, those tests never actually go through Wasmtime's real codegen path so they miss bugs specific to Wasmtime's own memory model and calling conventions.

What I'm after is a new test directory where I can just drop `.wat` WebAssembly text-format files as test cases. Each file should declare a target architecture up top via simple directive comments, and optionally pick a test mode so I can look at raw compiler output, optimized output, or final machine code. I also want to be able to pass Wasmtime CLI flags as directives to configure the compilation environment (memory layout, optimizations, whatever). The expected output goes right in the same file as comments, and the harness runs Wasmtime's actual compilation and compares against those embedded expectations, so tests reflect what Wasmtime really produces at runtime.

Oh and the directive parsing plus the compare-against-expected-comments logic shouldn't be copy-pasted, I want that shared so both the existing Cranelift filetest infrastructure and this new Wasmtime-level harness use the same code. Basically refactor the common bits out so there's one place that parses the header directives and does the output comparison. Net effect is these tests are way easier to write, more accurate, and directly comparable to real runtime behavior without me replicating low-level details by hand in each file.
