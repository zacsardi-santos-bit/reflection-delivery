I'd like to add a new integration test suite for Wasmtime's WebAssembly compilation pipeline. Right now, when I want to test how a WebAssembly module compiles to native code through Wasmtime, I have to use the lower-level Cranelift filetest infrastructure, which requires me to manually write out virtual machine globals, heap bounds, memory configurations, and other low-level details in every test file. This is tedious and the tests don't actually go through Wasmtime's real code generator, so they can miss issues specific to Wasmtime's own memory model and calling conventions.

What I want is a new test directory where I can drop WebAssembly text-format files, put simple directives at the top of each file to declare a target architecture, choose between testing raw compiler output, optimized output, or final machine code, and optionally pass Wasmtime CLI flags for configuration. The expected output should just be embedded in the same file as comments, and the test harness should run Wasmtime's actual compilation and compare the result against those embedded expectations.

The shared logic for parsing test directives and comparing output against expected comments should also be refactored so it can be used by both the existing Cranelift filetest infrastructure and this new Wasmtime-level test harness. This avoids duplicating the comparison logic in two places.
