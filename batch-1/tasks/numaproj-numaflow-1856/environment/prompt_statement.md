I'm working in numaflow and the readiness check we've got on pipelines and inter-step buffer services isn't cutting it. It only looks at conditions, so anything that isn't strictly running looks broken even when it's fine, and that gives tooling and controllers misleading signals during normal lifecycle stuff like pausing or draining. I want a real health concept alongside readiness.

For pipelines I want a health check where the pausing, paused, and deleting phases all report healthy since those are intentional states, the running phase only counts as healthy if the pipeline is also ready, and the failed phase plus any unrecognized/unknown state report unhealthy. So it's not just "am I ready," it's "am I in a sane operational state." For inter-step buffer services health is stricter: it needs both the running phase and full readiness, so a pending or otherwise non-running service shouldn't be healthy even if its conditions happen to be set.

Separately the pipeline status only tracks one combined UDF count right now and I can't tell map-type from reduce-type at a glance. I want those broken out into separate map and reduce user-defined function counts on the status, and the OpenAPI schema for pipeline status should pick up those new fields too so the generated spec matches.

Oh and anywhere in the codebase that currently waits for an inter-step buffer service to be "ready" should switch over to checking the new health status instead, so behavior stays consistent everywhere. The types live under the numaflow api packages (the pipeline and ISB service types and their status structs), so wire the health methods there and update the status summary accordingly.
