I'm adding workspace renaming to Kusion and right now there's just no way to change a workspace name without nuking it and recreating from scratch, which is a pain when config already exists and you risk losing it. I want a proper rename that keeps the config intact.

Renaming needs to work across every storage backend we support, so local filesystem, Google Cloud Storage, S3, and Alibaba Cloud OSS all need it. The operation should update the workspace's metadata so the new name shows up in listings and the old one drops off, and it also has to move or copy/rename the underlying workspace configuration file so it matches the new name. If either the old or new name comes in empty, the whole thing should just fail with an error, don't try to be clever about it.

On the CLI side the workspace update command should get a new rename flag so folks can rename without having to pass a config file at all. Also validation needs to reject the reserved "default" workspace name as a rename target, that one's off limits.

API side, clean up the request model used for updating a workspace by dropping the field that associates a backend with the workspace on update, since the backend association is fixed at creation time and shouldn't be mutable through updates. And while you're in there the workspace manager's delete and update operations need reworking so they interact properly with both the workspace repository and the backend repository.
