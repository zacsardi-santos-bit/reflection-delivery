I'm working with our graph framework that supports nested subgraphs plus human-in-the-loop interrupts, and I keep hitting a cluster of related gaps. When my outer graph pauses because a subgraph node is sitting at an interrupt, I can see the pending tasks in the state snapshot, but those tasks don't carry any direct pointer to where the subgraph's state actually lives, so right now I'm hand-building checkpoint namespace references to peek inside, which is error-prone and doesn't compose with the rest of the state API. What I want is for each pending task to carry a direct reference to its subgraph's checkpoint, and that reference should work as a plain config I can pass straight into the state inspection and update methods, no manual namespace path construction. Subgraph states today get stashed under a separate dictionary field on the snapshot, which is awkward to navigate.

Also when I inspect state with subgraph expansion turned on, I'd expect each pending task's state to come back fully expanded as a complete nested state snapshot, not just a checkpoint pointer, so I see the whole picture in one call. And updating a subgraph's state should just work by passing that task's state reference as the config.

Oh and the streaming is off across interrupt boundaries. If I resume from an interrupt in value mode, the current state isn't emitted as the first item, I only see states from nodes that run after the resume. In update mode, the output from the node that completed just before the interrupt isn't re-emitted at the start either. And in the async case, resuming after an interrupt returns nothing instead of the final computed state, which is just wrong.

Last thing, I want to be able to fork execution from a historical checkpoint by doing a state update with no new values, then streaming from the resulting config to replay from that point, including any subgraph operations.

Can you fix all of this so subgraph state is reachable via task references, updates flow through those references, streaming always shows the complete picture across interrupts, and forking from a historical checkpoint works? Subgraphs are a great compositional tool but human-in-the-loop patterns are really hard to get right without clean inspect and modify access during an interrupt.
