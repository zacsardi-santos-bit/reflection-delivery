So I'm hitting a wall with the Polars SQL interface around joins and I want to fix it. Right now if I try to join two tables on more than one column at once, like combining a couple of equality conditions with AND in the ON clause (think composite keys, an id plus a date, that kind of thing), the query just fails. It comes back with an error saying only basic single-condition equi-joins are supported, which is super limiting because real datasets use composite keys all the time and I can't express the natural SQL for them.

What I want is for the SQL engine to handle join conditions that chain multiple equality comparisons together with AND, and this needs to work for both inner joins and left joins. For inner joins I should only get back rows where all the specified column pairs match, and for left joins I want all the left-side rows with NULLs filled in where the right-side conditions aren't met. Also the columns don't always share the same name across the two sides, so cross-column matching (different names on each side) has to work too.

A few more things I need: more than two equality conditions chained with AND should work, not just exactly two. Multiple sequential joins in one query, each carrying its own compound condition, should all work together. And these compound conditions need to work inside subqueries as well.

Oh and I don't want to loosen the validation. Malformed conditions should still be rejected with an error, so column references that aren't fully table-qualified, or expressions in the ON clause that aren't equality comparisons, those keep failing like they do now.
