I'm working on the Go SDK harness for Apache Beam and I need to add proper error handling and lifecycle management to the state channel component. Right now, when the state communication channel with the runner encounters an error — either while reading responses or while writing requests — the callers that are waiting for a response just block indefinitely. The context is never cancelled, and there's no way for the channel manager to know it should tear down the connection and try again.

I need the state channel to propagate errors back to any waiting callers immediately when something goes wrong, cancel the associated execution context so that dependent work can clean up, and invoke a configurable callback so the channel manager can delete the old channel and recreate a fresh connection. After the channel has encountered an unrecoverable error, any new requests submitted to it should also fail immediately with the same error rather than blocking.

The channel needs to support concurrent request/response routing by ID — multiple callers can be in flight at once, and each must receive the response that matches its own request ID. The implementation should also handle the case where the underlying stream returns an end-of-stream signal on a write, which per the gRPC stream documentation requires draining the receive side to get the real error.
