I'm working on the CosmosDB JavaScript SDK and I need to add a buffered, non-streaming order-by query execution mode. The problem is some queries, particularly ones that rank by vector similarity distance, can't figure out the final ordering until every document from the backend has been seen, so the SDK has to collect all results, sort them internally, and only then hand them back. Right now those globally-sorted queries either fail or come back in the wrong order.

A few building blocks first. I want a comparator-driven map that keeps one value per key and only swaps in a new value when it "wins" per the comparator, which is handy for dedup while accumulating. Then a fixed-size priority queue that auto-evicts once it hits capacity so it keeps just the top elements by the comparator, and it should let me peek at the current top, drain everything destructively in sorted order, and report its size and whether it's empty.

Also I need a utility that assembles the list of query features the client advertises to the server. By default it includes the non-streaming order-by capability, but it takes a flag to suppress that, useful when talking to older gateways that might reject unknown features. And the query feed options type needs a new boolean so callers can opt out of non-streaming order-by for compatibility with older environments.

Finally, two pipeline components: one that buffers and sorts results through the priority queue, returning empty placeholder results while it's still accumulating and real sorted results afterward, and a second variant that does the same but also deduplicates via the map before returning things in sorted order. Wire these under the query execution context pieces in `@sdk/cosmosdb/cosmos/src` alongside the existing pipeline components and options types. This gives us the global-sort functionality plus a clean migration path for anyone on older gateway versions.
