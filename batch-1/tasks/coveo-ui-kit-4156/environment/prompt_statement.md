I'm working on commerce facets and I need the facet search functionality to pass along the page context — specifically whether the user is on a search results page or a product listing page — when making facet search API calls. Right now all facet search requests look the same regardless of which page type triggered them, and the backend needs this context to process them correctly.

I also noticed that field suggestion requests are missing a query field that the standard facet search API contract expects to always be present. This makes field suggestion requests inconsistently structured compared to other facet search requests.

What I need is for the facet search system to carry a context type (either search or listing) through from the facet controller configuration all the way to the API request. The controller options should require this context type, and it should automatically be appended to the API request URL. Sub-controllers for search and listing pages should each have their own context type wired in automatically, so consumers don't need to specify it per-controller. The action creators involved in executing facet search and field suggest operations should also be updated to accept and forward this context type along with the facet identifier.
