I'm extending our linter to catch pointless escape sequences in string literals, kind of like what we already do for regexes. Right now the tool only flags useless escapes inside regular expressions, but nothing catches them in ordinary strings, and I keep seeing people write a backslash before a plain letter that has no special meaning, or escape a quote that isn't even the delimiter of that string. Those extra backslashes don't break anything at runtime but they clutter things up and mislead readers into thinking some special character was intended, so I want a new lint warning here.

Basically whenever there's a backslash before a character that doesn't need escaping in the given string literal (single-quoted, double-quoted, or untagged template literal) I want a warning emitted, and the message should explain that only the enclosing quote character and recognized special sequences actually need escaping. Oh and there should be a safe auto-fix that just removes the unnecessary backslash while leaving the character itself untouched.

Couple of important exemptions: strings inside JSX attribute values and tagged template literals should be completely skipped since those contexts have different semantics, and recognized escape sequences like null characters, control characters, and unicode escapes shouldn't get flagged either.

Also, while I'm in here, the existing useless-escape-in-regex check should report as a warning rather than an error so both checks look visually uniform in the output.
