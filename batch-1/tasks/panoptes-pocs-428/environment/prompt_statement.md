I'm building out a sensor monitoring setup that reads from a bunch of hardware boards, and I need a clean way to persist and relay those readings asynchronously. Right now the data production and recording are all tangled together and it's getting error-prone. In a multi-board setup the readings come from multiple threads, so I want to decouple the producing from the saving/sending and stay resilient when an individual handler blows up.

What I want is a background worker class in the sensors package (something under `@sensors/`) that runs in its own thread and continuously pulls readings off a shared queue, calling a configurable save function and a configurable send function for each one. Both callbacks should get called with the sensor name and the full reading dict. I want the queue exposed so producers can submit readings onto it directly.

It's gotta be resilient, so if a save or send call throws, it should log the error and keep going instead of crashing the thread. Same deal with garbage on the queue, things like None or malformed entries should just produce a warning log and get skipped, not kill the thread. Oh and when the save and send callbacks aren't provided (left as None), valid readings should just be silently discarded, no errors.

Also I need proper lifecycle handling, so start, stop, and join should all behave like you'd expect for a background thread. It should default to running as a daemon thread but also support non-daemon mode when I want that.
