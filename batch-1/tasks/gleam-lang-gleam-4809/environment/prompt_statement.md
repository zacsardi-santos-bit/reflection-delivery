I keep writing Gleam where an outer case matches a value to pull out a variable, and then the very next thing is another case matching on that extracted variable. It's functionally fine but it nests for no reason and reads worse than one flat case with combined patterns. I'd love a language server code action that collapses these two nested case expressions into one when my cursor is on the relevant variable, merging the outer and inner patterns for each clause.

Here's the tricky part, it needs to handle all the usual shapes. When the inner case is wrapped in a block, unwrap it. When the outer pattern binds several variables, only replace the one being collapsed and keep the rest intact. When constructor patterns use labeled fields, keep the labels. When inner clauses use alternative patterns separated by pipes, distribute them across the outer pattern so each combination becomes its own clause. When the matched variable is still referenced in a clause body, add an alias so that name stays accessible. And guards, oh, if either or both levels have a guard condition, combine them with a logical and, and wrap any guard that uses logical-or in parentheses so precedence stays correct.

This is code action territory in the language server, so it'll live around the engine bits under `@compiler-core/src/language_server`, detecting the case-clause-body-is-a-case-on-an-outer-bound-variable pattern and offering the collapse. The trigger is cursor placement on that variable. Basically I want to detect the nested pattern, offer the action, and produce a single correct flat case that preserves everything from the outer pattern that isn't being collapsed. Reducing this nesting by hand is tedious, especially once guards or labeled fields get involved, so having it automated would help a lot.
