I'm cleaning up the SQL logic test setup for GlareDB and the path handling is driving me nuts. Right now the test runner has to be launched from some nested subdirectory, so every single test script that touches a local data file has to climb up two directory levels before it can even get to the testdata folder. It's messy and honestly confusing for anyone new trying to run the suite.

What I want is to flip this so the runner executes from the project root instead. Once it does, all those relative data file references in the SQL scripts can just be root-relative, starting directly with the testdata folder rather than doing the `../../` dance up two levels. So I need two things really, the runner binary changed so it's invoked from the project root, and then every SQL logic test script updated to use the new root-relative style.

The scripts cover a bunch of stuff so all of it needs the path fixups, the various scan functions (parquet, CSV, JSON, delta, and lance), direct file-path queries, glob patterns, file type inference, plus CTAS, CREATE VIEW, and CREATE EXTERNAL TABLE operations. After the change, queries scanning parquet, CSV, JSON, delta, and lance via relative paths should still return correct results, glob patterns with root-relative paths still work, and direct file-path queries, file type inference, CTAS, views, and external tables all work with the new relative paths. Oh and the tests for unknown file extensions and missing extensions should still produce their appropriate errors, don't want to lose that coverage.

The whole point is making the suite simpler to invoke in CI and locally, contributors shouldn't need to know which subdirectory to cd into first, and the path references become self-evident when they just start from testdata.
