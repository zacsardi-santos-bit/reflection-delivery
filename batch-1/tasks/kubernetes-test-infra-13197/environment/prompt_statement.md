I'm working on prow deck's job rerun feature and right now the rerun handler in deck has zero access control, so if the job creation feature is enabled anyone who can hit the endpoint can trigger a brand new CI job, with the only "protection" being an obscure job identifier. That's not great for instances where only certain team members should be allowed to kick off reruns, it wastes resources and can be abused.

I want to add authorization so only users on an approved allowlist (or everyone, if the config says allow anyone) can actually create a job. First I need the endpoint to cleanly split read vs write. A read request (GET) should just return the job spec without creating anything, while a write request (POST) goes through the auth check and actually triggers the job. If someone sends a write request but the creation feature is turned off, reject it with a method-not-allowed response instead of doing something weird or silently ignoring it. And if an authenticated user isn't on the allowlist and the allow-anyone flag isn't set, don't create the job.

Auth should be configurable, either allow any authenticated GitHub user, or restrict to an explicit allowlist of GitHub logins that the handler compares against. For that comparison to work I also need a helper the handler can call to look up the currently authenticated user's GitHub identity from the OAuth session. The session stores the access token, and from that token we can hit the GitHub API to retrieve the user's login/username, so wire that up so the authorization logic inside the request handlers has the user's identity to check against the allowlist.
