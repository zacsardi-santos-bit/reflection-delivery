I'm hitting a weird SQL generation bug with partial models in SeaORM (the derive macro that builds `SelectStatement` output for `#[derive(DerivePartialModel)]`). When I've got a partial model that includes active enum fields and I slap a table alias on the struct via the `alias` attribute, the generated query drops the type cast that enum-typed columns need. So without an alias I correctly get a cast expression (on PostgreSQL that's the enum type cast to text, `CAST(... AS text)` style), but the moment there's a struct-level alias the cast just vanishes and I get a plain column reference instead, which produces broken queries on Postgres and can throw runtime errors or silently hand back wrong data.

Same deal shows up in a couple related shapes, so I need it fixed consistently. When a partial model field maps an entity column to a different output name through an explicit column mapping (the `from_col` style remapping), the SQL should qualify the column with the table alias and still wrap it in the enum-to-text cast. And when I've got a struct-level alias combined with a nested partial model that carries its own alias, each part of the query should use its own correct alias while both still apply the enum cast, right now the top-level enum fields lose their cast while the nested ones come out fine.

Basically I want the enum cast applied every time regardless of whether an alias is present, top-level, nested, or via column remapping. The relevant codegen lives around the partial model derive in `@sea-orm-macros/src/derives/partial_model.rs` and you can check behavior against how the select expressions get built. Please make it apply the cast uniformly.
