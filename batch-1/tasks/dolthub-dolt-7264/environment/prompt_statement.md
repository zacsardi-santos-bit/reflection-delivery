I'm adding version-awareness to the SQL server YAML config in Dolt and could use a hand. The situation is mixed-version clusters where a newer node shares config that contains options an older node was never built to understand, and that blows up on the older side, so I want each field in the config struct to be able to carry the minimum Dolt server version that introduced it. Then I need a utility that takes a target version number plus a config object and hands back a version-safe copy with any field introduced after that version stripped out. Fields that are still in development and haven't gotten a final version yet (think a "to be determined" / not-yet-versioned marker) should also get omitted during serialization.

There's a constraint I really want enforced: any field carrying a version annotation has to be a nullable/pointer type so it can actually be absent, and it has to be marked omitempty in its YAML tag. If someone accidentally slaps a version annotation on a non-nullable field, I want that caught immediately (fail loud, don't silently pass).

Also I want a validation file that records the version metadata for every field in the config struct. Tests should fail if anyone adds a new field without a proper version annotation, or if that validation file drifts from the current state of the struct. Fields still pending a final version are allowed to exist but they're excluded from the validation file comparison since they're not locked in yet.

Oh and while I'm in there, the existing config struct is missing some serialization tags on a few fields, so those need adding too so everything can actually be unmarshalled and validated properly. The point of all this is letting the server safely share config with older cluster members or replication targets that wouldn't grok newer options, preventing startup failures and weird behavior in mixed-version deployments. Relevant code lives around the server config in `@go/libraries/doltcore/servercfg/`.
