I'm cleaning up path handling in our disk usage tool and it's got a few real bugs I keep hitting. The whole thing assumes Unix, it hardcodes forward slash all over the place for splitting display names, counting directory depth, and other path analysis, which just breaks on Windows where backslash is the separator. So anywhere we're splitting or measuring paths by a literal `/` I want swapped over to platform-aware separator detection using the OS's standard path library instead of assuming one character.

The bigger correctness issue is the parent-of check. Right now it decides whether one directory is an ancestor of another with a plain string prefix match, which is wrong. A directory whose name just happens to start with another directory's name gets treated as a child when they're actually siblings that only share a name prefix. I want that rewritten to do proper hierarchical path comparison, so a path only counts as parent when it's a strict ancestor in the tree. And a path is not a parent of itself, even when it's written with a trailing slash or a trailing current-directory (`.`) component, those should be recognized as the same path.

Related to that, our dedup is weak. The existing helper that just strips trailing slashes only handles a narrow set of cases, so when someone passes paths with redundant separators or `.` components in the middle we don't recognize them as equivalent to the normalized form. I want a proper normalization function (again using the OS path library) that collapses repeated separators, drops interior current-directory segments, and cleans up trailing separator and dot combinations, producing a proper native path string, and it should replace that old slash-stripping helper. Once that's in, paths differing only in redundant separators or `.` components should compare equal and stop showing up as false duplicates.

Oh and there are some existing tests that shell out to Unix-only commands, those need to be marked to skip on Windows so they don't throw false failures over there.
