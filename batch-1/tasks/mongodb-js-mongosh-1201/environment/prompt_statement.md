I'm cleaning up the analytics and telemetry plumbing in our shell tool and the current design bugs me. Right now every bus event carries a boolean telemetry-enabled flag so each handler has to read it and branch, and the analytics provider gets passed around as a factory function that creates the analytics object, which means we also have to catch and special-case the factory throwing. It's awkward and I want the analytics object itself to own the "should I actually send this now?" decision.

So here's what I want. Introduce a wrapper type that starts out paused, meaning it buffers events without forwarding them. It should support enabling, which flushes whatever's buffered and starts forwarding immediately from then on, pausing again, which goes back to buffering new events without sending, and disabling, which permanently discards any buffered events so they never get sent even if the wrapper is later re-enabled. That last part matters, disabling is a hard opt-out, not a temporary pause.

Once that wrapper exists, the logging setup function should just take a plain analytics object directly instead of a factory (and dropping the factory indirection also drops the special error handling around creation). The bus events for user identity and user updates should no longer carry the telemetry-enabled flag since the wrapper handles on/off externally now. Oh and I also want to handle a new bus event that fires when a global config file gets loaded, so we log an entry recording the file's path for troubleshooting.

The whole point is we can hold events until the user's telemetry preference is confirmed, then flush if they opted in or discard if they opted out before anything was sent, plus the simpler signature is just easier to use right.
