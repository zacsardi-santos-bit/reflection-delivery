I'm poking at the Cairo compiler's lowering optimization pipeline and the pass ordering is just backwards. Right now the pass that reorganizes and merges trivial passthrough blocks runs before the pass that eliminates redundant variable remappings, and that's causing real bloat. The block reorganizer refuses to merge blocks that still have remappings on their incoming edges, so I'm left with tons of empty jump-only blocks sitting in the IR, long chains that do nothing except jump to the next block. It clutters everything up right before the match optimizer runs, and the match optimizer really wants compact IR to reason over, fewer redundant intermediate blocks the better, so this ordering is basically a prerequisite for clean match optimization output.

What I want is to swap the order of these two passes so the remapping cleanup happens first. Once the remappings are gone, the block reorganizer no longer needs its guard against merging blocks with non-empty incoming remappings, so rip that guard out entirely, it should unconditionally merge any block reachable through a single unconditional jump without checking for remappings on that edge. It's now the caller's job to have run remapping optimization beforehand.

Oh and after this, the lowered IR for functions doing pattern matching on optional values should come out way more compact since those passthrough chains collapse into the blocks they forwarded to, so the stored snapshot outputs for the match optimizer's test cases will need updating to match.
