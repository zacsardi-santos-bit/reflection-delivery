I'm working on the Cairo compiler's lowering optimization pipeline and noticed that the pass ordering is wrong. The pass that reorganizes and merges trivial passthrough blocks runs before the pass that eliminates redundant variable remappings. Because the block reorganizer refuses to merge blocks that still have remappings on their incoming edges, many empty "jump-only" blocks are being left in the intermediate representation unnecessarily. These chains of blocks that do nothing except jump to the next block clutter the IR before the match optimizer runs.

The fix should swap the order of these two passes so remapping cleanup happens first. Once remappings have been eliminated, the block reorganizer no longer needs to guard against merging blocks with non-empty incoming remappings — that guard should be removed entirely, since it's now the caller's responsibility to have run remapping optimization beforehand. After this change, the stored snapshot outputs for the match optimizer's test cases will need to be updated to reflect the more compact IR that results from successfully merging those passthrough chains.
