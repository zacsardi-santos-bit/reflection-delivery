I'd like Biome to gain the ability to detect hardcoded secrets in JavaScript and TypeScript source files. Right now, there's no lint rule that warns when a developer accidentally writes a cloud service API key, an authentication token, a private key, a webhook URL, or a database password directly into their code. I want a new nursery-category lint rule that catches these cases.

The rule should recognize specific well-known token formats — things like AWS access keys, various OAuth tokens, RSA private key headers, service-specific webhook URLs, and database connection strings with embedded passwords — and also fall back to entropy analysis for high-randomness strings that don't match any known pattern. When a potential secret is found, the diagnostic should name the type of secret detected and include clear, step-by-step guidance on how to safely resolve the issue (removing it from history, switching to environment variables, or suppressing the warning if it's a false positive).

The rule should be smart enough to leave innocent values alone: plain numbers, short readable strings, long human-readable sentences, and connection strings that already use runtime variable references in place of hardcoded credentials should all pass without a warning.
