I'm doing quantum chemistry work in PennyLane alongside OpenFermion and I keep hitting a wall on conversions. Right now I can import fermionic operators from the external library into PennyLane just fine, but there's no way to go the other direction, so if I want to round-trip an operator or hand results off to code that depends on OpenFermion I'm stuck doing it by hand. I'd like a new export function in `@pennylane/qchem/convert.py` that takes PennyLane's fermionic word (`FermiWord`), fermionic sentence (`FermiSentence`), and qubit operator types and converts them into the external library's format. It should accept an optional wire remapping argument (a dict of old wire labels to new ones) so I can remap orbital or qubit indices before converting, and a tolerance parameter that controls whether small imaginary parts of coefficients get dropped or kept.

Also, importing qubit operators from the external library isn't supported at all, only fermionic ones, so I want an import path for their qubit operators too, with a format option to choose between a linear combination (`LinearCombination`) or a sum type (`Sum`) for the PennyLane output, plus a tolerance for handling complex coefficients that are nearly real. Oh and a little utility to render a fermionic operator word as a string in either PennyLane's own notation or OpenFermion's shorthand would help a lot for debugging and logging.

For all of these, I want clear errors when someone passes an unsupported operator type, an invalid format option, a wire mapping that doesn't cover all the operator's wires, or when the external library isn't installed. Basically I just want fully round-trippable workflows between the two libraries without the manual translation.
