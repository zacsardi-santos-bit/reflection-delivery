I'm working on Trivy's CycloneDX SBOM output and noticed that the tool metadata in generated BOMs is using an outdated format. The current code records Trivy itself as a simple entry in a flat tool list within the metadata section, but the CycloneDX specification has since deprecated that structure in favor of representing tools as full software components with a type, group, name, and version. I'd like to update the code so that Trivy's metadata entry uses the modern component-based structure instead of the legacy tool array. This should apply to all types of scans (container images, filesystems, aggregate results, and so on). I also want to make sure that CycloneDX documents previously generated by Trivy using the old format are still recognized as Trivy-produced SBOMs for backward compatibility.
