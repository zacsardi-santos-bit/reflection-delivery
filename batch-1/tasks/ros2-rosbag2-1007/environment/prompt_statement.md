I'm working with the rosbag2 player and I keep hitting a wall where there's no clean way to stop a bag replay that's running in a background thread. Right now if I want to terminate playback my only option is a full ROS shutdown, which is way too destructive since it kills everything else in my application too. I want to keep the rest of the system alive after the bag is done or when I no longer need it, so I need a real stop capability on the player.

Here's what I need it to handle. Calling stop while the player is paused should make the play loop exit immediately without hanging and without any ROS shutdown. Calling stop during active publishing should respect whatever message is currently in-flight (that one can finish dispatching) but then exit the loop, and no new messages should get published after stop is requested. Calling stop before playback has even started should just be a safe no-op, no hang and no error. And destroying the player while playback is running should implicitly stop it too, so the play thread returns cleanly within a short timeout when the player goes out of scope.

Oh and I also need a ROS service endpoint on the player node so external nodes can request a stop over the network, similar to how the existing pause and resume services already work. It should be created and ready for client connections as part of the player's normal setup. The whole point here is making the player composable and reusable inside larger systems instead of forcing an all-or-nothing teardown.
