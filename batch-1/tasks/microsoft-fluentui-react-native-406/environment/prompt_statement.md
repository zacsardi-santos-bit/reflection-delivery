I'm poking at the ContextualMenu component and hit a gap around focus behavior when the menu opens. Right now there's no way to tell it whether it should grab focus on mount, or whether the inner container should be independently focusable via keyboard or accessibility tools, and that's causing headaches for apps that need fine-grained focus management (accessibility and keyboard nav can get weird without it).

What I want is two new optional boolean props. The first controls whether the menu sets focus when it mounts, and it should default to enabled so the callout grabs initial focus by default. The second controls whether the inner container element accepts keyboard focus and accessibility interactions, and that one should default to disabled. When neither prop is passed, the component should just behave per those defaults automatically, so with all defaults the rendered output shows the callout receiving initial focus while the container doesn't independently take keyboard or accessibility focus.

Oh and as part of this, the menu's children should get wrapped in an inner container view element that sits between the callout root and the menu items in the tree. The accessibility and keyboard focus settings go on that container, and the focus-on-mount setting gets forwarded to the callout itself. Sensible defaults for the common case, but advanced focus control when folks need it.
