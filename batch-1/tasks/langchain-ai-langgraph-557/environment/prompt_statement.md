I'm building an agent loop where the model can hand back several tool calls in one response, and I need each of those calls dispatched individually, in parallel, to the same handler node within a single graph step. Right now the only thing I can return from a conditional edge is a string destination (or a signal to end the graph), so there's no way to fan out to the same node multiple times with different args. I want to introduce a notion of "packets" I can return as a list from a conditional edge function, where each packet carries a target node name plus the specific argument to pass to that node, so the graph invokes that node once per packet all in the same step. So if the model returns three tool calls, I return three packets and the handler runs three times with three different inputs.

A couple things I care about on the output side. When I stream, results from packet-invoked nodes should show up grouped as a list under the node name, while normally-scheduled nodes still emit their output as a single dict like today. Also the state snapshot should reflect multiple pending next-steps for a node when multiple packets are queued up for it.

Separate but related, there's a silent-failure bug I keep hitting: if a node accidentally returns a state key that isn't in the declared state schema (a typo, say), the data just gets dropped quietly instead of erroring. I'd rather it immediately raise a clear validation error so I catch the mistake fast, right now debugging that is painful because nothing tells you anything went wrong.

Oh and one more, when I call the graph's state-update functionality with a message whose ID matches an existing message, I want the existing message replaced in place rather than a fresh copy appended to the list.
