I'm working with a JHipster project generator and noticed that the generated applications don't include any protection against log injection attacks. When user-controlled input containing newline or carriage return characters ends up in log messages, it can corrupt log files or allow forged log entries — this is a known security vulnerability that static analysis tools flag in our generated code.

I'd like the generator to automatically include a log sanitization component as part of the standard set of generated server-side configuration files. This way, every new application generated by JHipster gets this protection out of the box without developers having to add it manually. The component should be generated for all standard server generation scenarios, including applications with different frontend setups and applications generated through custom blueprint plugins.
