I'm poking at our JHipster generator and realized the Spring Boot apps it spits out have zero protection against log injection. You know the drill, someone shoves user input with `\r` or `\n` into a log message and now they can forge log records, wreck audit trails, or bury whatever they were actually doing. Our static analysis tooling keeps flagging this in the generated code and honestly it should, it's a real vuln.

What I want is for the generator to drop a log sanitization component into the standard server-side config package automatically, so every fresh app gets this out of the box and devs don't have to bolt it on manually after the fact. Basically it needs to be part of the normal set of generated configuration files that get written to disk, living in the app's config package alongside the other server config classes.

The important bit is it has to show up in every server generation scenario, not just the happy path. So apps with different frontend frameworks, apps with no frontend at all, and apps built through custom blueprint plugins should all end up with this component written out. JHipster's whole pitch is a production-ready app out of the box, and baking in log injection protection by default means teams won't fail a security audit or scan the moment they generate. Just make sure it's consistently emitted across all those cases.
