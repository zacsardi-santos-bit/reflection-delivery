I'm working on our verifiable credential issuer service and the OpenID well-known configuration endpoint is coming back incomplete when wallets query it for supported credential types. Right now the credential configurations supported section is missing a bunch of metadata that wallets actually need, so I want to fill those gaps in.

Specifically I need to add a structured claims object (the list of attributes a credential can contain, which certain mobile document and selective-disclosure formats require), a document type identifier (needed for mdoc-format credentials), a verifiable credential type designator (needed for SD-JWT / selective-disclosure formats), an ordered list of claim names used as display ordering hints, and the scope value for the credential. Oh and the credential definition nested object needs context URLs for linked data proof credentials too. Right now scope is always empty/absent even though it should be coming from the issuer profile, and none of the other fields exist yet at all.

These all need to land in two places: the internal profile data structures that store issuer configuration, and the generated API response types the wallets receive. Then the well-known service layer that transforms profile config into the API response has to map every one of these new fields through, including populating scope from the profile instead of leaving it blank. Also the test data/fixtures used across the tests need representative values for all the new fields so the whole flow can be verified end to end.

The point is compliance with the OpenID for Verifiable Credential Issuance metadata sections. Without these, wallets can't handle certain formats, can't show claims in the intended order, and can't correctly identify credential types. So I want claims metadata, document type, vc type, and claim ordering all in the credential configurations supported section, context URLs on the credential definition, and scope actually populated, all sourced from the issuer profile config and reflected in the response.
