I'm working on a verifiable credential issuer service and need to add several missing fields to the OpenID credential issuer configuration endpoint. Right now, when wallets query our well-known configuration endpoint for supported credential types, the response is missing important metadata fields.

Specifically, the credential configurations supported section needs to include: a structured claims object (for certain mobile document and selective-disclosure credential formats), a document type identifier, a verifiable credential type designator, an ordered list of claim names for display purposes, and the scope value for the credential. Additionally, the credential definition nested object needs to include context URLs for linked data proof credentials. Currently, the scope field is always absent even though it should be populated from the issuer profile, and none of the other new fields exist yet.

These fields all need to be added to both the internal profile data structures that store issuer configuration and the generated API response types that wallets receive. The well-known service layer that transforms profile configuration into the API response also needs to be updated to map these new fields through. The test data used in tests also needs to be updated to include representative values for all the new fields so the complete flow can be verified end-to-end.
