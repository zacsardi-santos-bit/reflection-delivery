I'm extending the Pulsepoint bidder adapter in our prebid server (over in `@adapters/pulsepoint/pulsepoint.go` and the related params file) and right now it's stuck on banner only, which is killing us. Any impression that isn't a banner gets rejected with an error, and every bid comes back typed as banner no matter what was actually in the impression. I want it to accept banner, video, audio, and native impressions, and when I build the bid responses the bid type should reflect the actual media type of the matching impression (so banner, video, audio, or native based on what's set on that imp in the request). The way to figure that out is to look up the impression by its ID and inspect which media type it carries.

Couple edge cases: if a bid's impression ID doesn't match any impression in the request, or it matches one that has no recognized media type, just drop it silently, don't error.

Also I want to kill the ad size field on the bidder extension, we don't need it anymore. It's currently required but the extension should only require the publisher ID and tag ID going forward. And relax the validation while you're at it, missing or zero publisher IDs shouldn't blow up the request. Instead, if no valid publisher ID turns up across the impressions, just use an empty string for the outgoing request. Oh and when picking which publisher ID to send, use the first valid impression's rather than the last one. Same idea for tag ID, missing or zero values should be handled gracefully instead of failing the request.

The whole point is Pulsepoint can't compete in video, audio, or native auctions today, and the ad size requirement is just friction that doesn't match what the exchange actually supports.
