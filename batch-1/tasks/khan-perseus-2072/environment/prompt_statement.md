I'm cleaning up the Perseus test suite and hitting a recurring annoyance where a bunch of tests that check renderer behavior (focus management, input path tracking, widget serialization, grading APIs, interaction event callbacks, that kind of thing) lean on a real production input widget as a stand-in fixture. Problem is that couples them together, so whenever the production widget's internals or rendering changes, tons of unrelated tests start failing even though they aren't actually testing that widget at all. I want a dedicated mock widget that exists purely for testing, minimal and self-contained with no implementation-specific behavior that could shift on us, but still wired into all the standard renderer APIs tests exercise so existing tests can migrate over to it. So it needs to handle focus/blur, input paths, user input, serialization, and grading cleanly.

Oh and it also needs to support generating AI prompt JSON output, since we want to test that prompt-generation pipeline independently against a predictable widget. So please add a helper utility that produces the prompt JSON given the mock widget's render props and its current user input, and add the type definitions for the mock widget's user input too. Then create test data items that use the mock widget, and go update the existing test fixtures and test data across the suite to use the mock widget instead of the production input widget. Also move the related test utilities into a more appropriate spot alongside the mock widget code while you're in there. The whole point is decoupling the test infra from any particular production widget so things are more stable and the prompt path can be tested in isolation.
