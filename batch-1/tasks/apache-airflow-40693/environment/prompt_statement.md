I'm finishing up dataset alias support in Airflow's scheduler and hit a wall where the alias-to-dataset relationship just isn't tracked in the DB. When a task emits output through an alias that resolves to one or more concrete datasets, nothing records which datasets that alias actually maps to. It breaks stuff downstream: DAGs scheduled to trigger when an alias updates never get queued because the scheduler can't look up what the alias resolves to, and the timetable summary can't tell an unresolved alias apart from one with linked datasets, so folks have no idea if their alias-based schedule is even live.

What I want is for that alias-to-dataset link to get persisted when task outlets fire, kept current when multiple aliases point at the same dataset, and queryable both ways (alias to its datasets, and a dataset back to its aliases). The scheduling logic then needs to lean on this so alias-triggered DAGs correctly show up as needing a run when the underlying dataset's queue gets updated, following the usual dataset-triggered rules like max active runs and all that.

Also the alias has to serialize into the DAG's schedule expression, including the alias name, so the expression can be stored and evaluated later. And I need a new alias condition type that's evaluable, it should return true only when the alias is actually resolved and every linked dataset has been updated, otherwise false. Oh and the timetable description matters here too, an unresolved alias should clearly say it hasn't been resolved yet, while a resolved one shows the same summary as a normal dataset schedule. Right now unresolved and resolved look identical which is confusing. Without all this the alias mechanism is basically half-built, events emit but triggers don't fire, so it's not reliable for production.
