I'm working on completing support for dataset aliases in Airflow's scheduling system. Right now, when a task produces output through an alias that maps to one or more concrete datasets, the database doesn't track the relationship between the alias and those datasets. This breaks several things: DAGs scheduled to trigger when an alias is updated never actually get queued for a run, because the scheduler can't look up which datasets the alias resolves to. Also, the timetable summary doesn't differentiate between an alias that hasn't been resolved yet and one that has linked datasets, so there's no way for users to know if their alias-based schedule is active.

I need the alias-to-dataset relationship to be persisted in the database when task outlets fire, kept up to date when multiple aliases link to the same dataset, and queryable in both directions (alias → datasets, and dataset → aliases). The scheduling logic needs to use this relationship to correctly determine when alias-triggered DAGs need runs. The alias also needs to serialize into the DAG's schedule expression so it can be stored and evaluated. Finally, a new condition type for aliases should be evaluable: it should return true only if the alias is resolved and all its linked datasets have been updated.
