I'm building out the new filter-based transformation pipeline in kustomize and I need a dedicated replica count filter that plugs into it. Right now there's nothing in this architecture that handles bumping replica counts for a named resource, so I want to add one.

The idea is the filter takes a target resource name, a desired replica count, and a list of field paths where replicas live in a resource (each path being where the count is configured). When it runs over the resources flowing through the pipeline, it should look at each resource's metadata name and, for any that match the target name, set every one of the specified field paths to the new count. Resources whose name doesn't match should just pass straight through untouched.

Each field path also carries a "create if not present" flag, so the behavior depends on that: if the path already exists in a matching resource, update it in place; if it doesn't exist and the flag says create it, add the field with the new count; and if it's missing but that flag isn't set, leave the resource alone. Oh and it should handle multiple field paths in one pass, updating all of them together.

Main thing is it's gotta work as a real filter in the standard resource processing pipeline, compatible with the same pipeline runner the rest of the kustomize filter architecture uses, so it composes cleanly alongside the other transformers. This kind of replica management is bread-and-butter kustomize stuff, so having it as a proper testable filter here matters.
