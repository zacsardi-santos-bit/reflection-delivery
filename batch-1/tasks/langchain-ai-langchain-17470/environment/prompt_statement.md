I'm working in the LangChain MongoDB partner library and there's just no LLM caching at all right now, so every model call goes out to the API even when I've already sent the exact same prompt before. I want to add a cache module with two implementations that both plug in as the global LangChain LLM cache and integrate transparently with the standard LLM and chat model call paths, so once I set the cache, repeated or similar prompts get served from MongoDB without me touching any calling code.

First one is a plain exact-match cache that connects to Mongo and stores and retrieves responses keyed by the prompt plus the model identifier (llm_string), so an identical prompt comes straight back without hitting the model. It should take a MongoDB connection string, a collection name, and a database name.

Second is a semantic cache that stores prompt embeddings alongside the responses and queries by vector similarity using MongoDB Atlas vector search, filtered on the model identifier so it only matches within the same model. It should inherit from the existing MongoDB Atlas vector store class and accept an embedding model plus the connection string, collection name, and database name. When a sufficiently similar prompt shows up, return its cached response.

Both need to implement the standard LangChain cache interface (update/lookup style), both need a clear method that optionally takes filter criteria, and both have to work across all the usual prompt formats: plain string prompts, lists of chat messages, and multiple generations per prompt. Oh and serialization matters a lot here, responses have to survive a round-trip so all generation types, including chat generations, come back correctly on retrieval and not get flattened into plain generations.

The motivation is that teams already using MongoDB Atlas as their main data store want one infrastructure dependency for both their data and their caching layer instead of bolting on a separate cache or eating redundant API calls and the latency and cost that come with them.
