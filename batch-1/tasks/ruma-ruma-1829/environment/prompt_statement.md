I'm hacking on the MatrixRTC event types in ruma-events and hit a compile wall. The call membership state event content is currently just a plain struct that only knows the old array-based shape where one state event under a top-level "memberships" array holds every session for a user. Problem is the protocol grew two more formats and my code that uses them won't build, which cascades and fails every test in the crate.

What I want is to rework that content into a union/enum covering all three cases: the legacy array-of-sessions format for backward compat, the newer per-device session format (one event per device instead of one for all devices, using flat top-level fields for the application, device, and focus info), and an empty departure state that's literally just `{}` signaling the user left the session entirely. Each variant needs to serialize and deserialize cleanly to and from its own JSON shape, and a full state event of the call membership type should parse fine including correctly recognizing that empty-object case as the departed state. Oh and expiry differs by variant: session-format memberships should never count as expired, while legacy ones expire based on their duration plus creation timestamp.

Separately, the call notification event (the thing that lets folks get notified of incoming MatrixRTC calls) has its tests stuck behind an experimental feature flag over in the integration test file. That feature's mature enough now, so I want those tests moved inline into the module's own test block so they just run whenever the feature's on, no separate guard. Also the call notification feature flag needs to properly declare the core MatrixRTC membership feature as a required dependency so it pulls it in.

This matters because right now any client mixing legacy and new membership formats can't even use the library, and the empty departure state is what makes it reliable to signal someone dropped out of a call when their client goes unreachable.
