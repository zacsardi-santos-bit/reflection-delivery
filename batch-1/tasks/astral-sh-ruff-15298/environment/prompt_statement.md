I've got a lint rule that flags functions with a declared return type when they're missing an explicit return, and it's supposed to be clever about branches that end by calling something annotated as never returning. If a branch terminates by calling a function whose return annotation basically says "this never comes back normally," then there's no need for an explicit return in that branch and the rule should stay quiet.

The problem is the rule only knows about the standard-library form of that "never returns" annotation. When someone uses the semantically equivalent annotation from the popular type extensions library instead, the rule fires a false positive on code that's totally valid. I want both forms treated identically so users of either annotation style don't get spurious warnings. So a function shouldn't be flagged for a missing explicit return whenever a branch ends by calling any top-level function whose return type annotation indicates it never returns, no matter which library that annotation comes from.

Oh and one caveat, the nested-function case (a never-returning function defined inside the same function body) isn't handled yet and the rule may still fire there. That's a known limitation and acceptable for now, so it should be documented as such rather than treated as passing.
