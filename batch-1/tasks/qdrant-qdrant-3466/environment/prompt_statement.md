I'd like to add a new type of filter condition to Qdrant's filtering system. Right now I can use conditions where all must match, where at least one must match, or where none must match — but I can't express "at least N out of M conditions must match." This is a really common pattern in practice. For instance, I might want results that match at least 2 out of 3 characteristics (city, color, and count) without having to enumerate every valid combination of two.

I'd like this new threshold-based filter to work alongside the existing filter types, so I can combine it with "must" conditions in the same filter object, or even negate it using "must not" to exclude points that meet the threshold. It should also be usable in nested filter contexts. If someone sends a request with the condition list but forgets to specify the minimum count threshold, the API should respond with a validation error rather than silently accepting it.

On the internal side, query planning should correctly estimate cardinality for this new filter type — including the property that when the minimum count equals the total number of listed conditions, the estimate should be identical to treating them all as required conditions.
