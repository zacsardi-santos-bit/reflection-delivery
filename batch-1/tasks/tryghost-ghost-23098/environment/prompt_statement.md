I'm building out the top content analytics for the Ghost admin dashboard and I need a service plus a helper module to make it work. The idea is we pull raw visit data from our external analytics provider, and that data has URL pathnames and visit counts but no human-readable titles, so the dashboard's basically useless until I enrich each entry with a real title.

So the service should fetch that top content visit data and then for each entry figure out the title by looking up posts in the database and, for the other stuff like tag pages, author pages, and custom pages, going through the URL routing layer. When a page can't be matched to any known resource I want it to fall back to a label derived from the pathname itself, and the root URL should just get labeled "Home". Big thing here: it has to always return a safe iterable structure. Even when the analytics provider is down, returns null, or throws, I want an empty array back instead of a crash.

I also want a reusable utility for talking to the analytics provider. It needs to build the API request URLs correctly with all the standard query params (date range, timezone, membership status filter), and support an optional versioned pipe name suffix when a version is passed. Oh and it should parse whatever response format comes back, could be a JSON string, an already-parsed object, or something body-wrapped/nested, into one consistent data array. When something fails on the network or the response can't be parsed it should return null gracefully instead of throwing. Also when local development mode is configured it should hit the local endpoint with the local token and skip the versioned pipe names entirely.
