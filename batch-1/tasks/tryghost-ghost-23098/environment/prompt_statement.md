I'm working on the Ghost admin dashboard and I need to add a feature that shows which content gets the most traffic. We receive raw visit data from an external analytics provider that includes URL pathnames and visit counts, but no content titles. I need a service that fetches that raw data and enriches it with human-readable titles by looking up posts from the database and other page types (like tag and author pages) through the URL routing layer.

For pages that can't be matched to any known resource, the service should fall back to a label derived from the pathname itself. The root URL should be labeled "Home". The service should always return a safe data structure — even when the analytics provider is unavailable, returns null, or throws an error, we should get back an empty array rather than a crash.

I also need a reusable utility module for talking to the analytics provider. It should handle building the correct API request URLs with all the standard query parameters (date range, timezone, membership status), support an optional pipe version suffix, parse responses in whatever format they come in (JSON string, parsed object, body-wrapped), and return null gracefully instead of throwing when something goes wrong on the network or the response can't be parsed. When a local development mode is configured, it should use the local endpoint and token and skip versioned pipe names.
