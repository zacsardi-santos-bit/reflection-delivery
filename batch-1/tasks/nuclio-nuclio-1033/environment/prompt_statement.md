I'm on the nuclio platform and I want to add a "never build" deployment mode so I can redeploy an existing function without rebuilding its image from source every single time. Right now every deploy always rebuilds from source even when nothing in the code changed and I just want to update config or re-run something that's already deployed, which is slow and pointless when the image is already sitting there.

So the behavior I need is basically two cases. When I redeploy an existing function with this skip-build mode on, the platform should skip the build step entirely and reuse the previously built image, and importantly the timestamp that records when the function was last actually built has to stay unchanged since no new build happened. Then after any deploy finishes, whether it actually built or skipped, the build mode setting should get cleared off the stored function config so it doesn't stick around and silently affect later deploys.

The other case is the guard rail: if someone tries to deploy a brand-new function (one that's never been built, so there's no existing image to reuse) using this never-build mode, the platform needs to reject it with an error and must not create or store any function record at all. That prevents the silent misconfig where you accidentally skip building something that doesn't exist yet.

Oh and I also need to extend the test suite helpers to cover two new deployment scenarios. One helper should run a deployment that's expected to fail with an error, and the other should do two sequential deployments of the same function with separate post-deployment checks for each so I can verify the last-built timestamp stays put across the second deploy. The whole point here is letting operators rapidly redeploy without the rebuild cost while still tracking when the image was genuinely last built.
