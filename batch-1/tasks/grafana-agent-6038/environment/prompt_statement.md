I'm hitting a wall with the Prometheus-to-Flow config converter, it just doesn't know what to do with HTTP-based service discovery. My Prometheus setup uses HTTP endpoints to dynamically pull in scrape targets (the `http_sd_configs` style discovery), and when I run it through the converter it either bails with an error or quietly drops those discovery entries instead of giving me the right Flow equivalent. Lots of people lean on HTTP SD as a flexible way to load target lists from a web endpoint, so right now anyone in that boat is blocked from the migration tooling and has to hand-rewrite their configs, which is exactly what I'm trying to avoid.

What I want is for the converter to treat HTTP service discovery the same way it already handles the other discovery types. So it should validate an HTTP SD config and return no errors when the input is well-formed, and then emit the matching Flow discovery block. That block needs to carry over the URL, the refresh interval, the authorization settings, and any relabeling rules from the original. Oh and it can't just produce the discovery block in isolation, the output has to actually wire the discovery results into the associated scrape and remote write blocks so everything's connected properly, same as the existing discovery conversions do. Basically I just want HTTP SD to be a first-class citizen in the converter alongside whatever else it supports today.
