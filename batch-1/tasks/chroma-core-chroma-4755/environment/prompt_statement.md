I've been chasing down a flaky-test bug that turns out to be a lifetime problem in our shared test infrastructure. We've got a helper that spins up a temporary local storage instance for unit tests, but it's deleting the temp directory right out from under us. The root cause is that the helper consumes the tempdir guard object inside the function, converts it to a plain path, and then the guard gets dropped before the function even returns, so the OS cleans up the directory immediately. That means every test leaning on this helper is running against a storage backend whose underlying directory is already gone from disk, which is exactly the kind of silent breakage that leads to weird failures and flakiness.

What I want is for callers to control how long the temp directory sticks around. So the helper's return type needs to change: instead of handing back just the storage instance, it should return the directory guard alongside the storage as a pair. After it returns the temp directory should still exist on disk and be accessible, and cleanup should happen naturally when the caller drops the guard at the end of the test scope. Since this helper is shared across several packages, the fix has to land at the source in the helper itself, and then every call site needs updating to unpack the returned pair and keep the guard alive for as long as the test needs it.
