Been poking at the home page search on our site and the coupling's bugging me. Right now the search component takes a callback prop from its parent that fires when someone submits, and the parent owns all the navigation logic (routing to results, deciding what happens when a suggestion gets picked from the autocomplete). I want to pull that responsibility into the search component itself so it's self-contained and reusable, no callback prop needed at all.

So the goal: when a user selects an autocomplete suggestion or submits the search form, the component should redirect them to the search results page on its own, with the query URL-encoded properly in the address bar. While I'm in there, I want the search area to use real semantic form markup so browser form behavior just works, meaning pressing Enter submits and the submit button actually acts as a form submission trigger (not some onClick handler faking it).

Couple of visual things too. The autocomplete suggestion dropdowns, both on the home page and in the site header, have layering (z-index) and spacing values that are off, so fix those to correct depth and spacing. And the home page title heading has a subtitle that currently sits after a line break element as a block, it should just be a space so the text flows inline instead. That last one's tiny but it's been annoying me.

Decoupling the navigation makes the search way easier to reuse elsewhere, and the proper form semantics helps accessibility and keeps behavior consistent across browsers and keyboard input.
