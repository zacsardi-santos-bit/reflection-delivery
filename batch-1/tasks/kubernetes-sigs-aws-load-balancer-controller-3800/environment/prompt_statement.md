I'm hitting a couple of gaps in the AWS Load Balancer Controller around how we manage security add-ons on load balancers, specifically WAF Classic, WAFv2, and Shield Advanced protection driven by ingress annotations. Right now there's no clean way to explicitly turn these off. If I want to drop a WAF ACL association or kill Shield protection, my only option is deleting the annotation, but that just leaves whatever's already on the LB untouched, so it never actually gets disassociated. I want a sentinel value I can set to signal "turn this off" explicitly, so setting the WAFv2 annotation to "none" disassociates the WAFv2 ACL, setting the WAF Classic annotation to "none" disassociates the Classic ACL, and setting the Shield annotation to "false" disables Shield Advanced. For Shield I actually want the controller to track an explicit enabled/disabled state rather than treating mere presence of the annotation as enabled, and also when it removes a Shield protection it should only remove ones the controller itself created and leave externally-managed protections alone.

Second thing, the error messages when reconciliation of these add-ons fails are too vague. They don't tell me which service blew up, so I'm stuck grepping logs to figure out if it was WAFv2, WAF Classic, or Shield. When we fail to get, create, or delete an add-on association, the error should name the affected service clearly.

Oh and since ingresses come in groups, all ingresses in a group need to agree on the same add-on settings, and conflicting values across the group should produce a descriptive error rather than silently picking one. Basically I need full lifecycle management of these security features through annotations, enable and disable both, with debuggable failures.
