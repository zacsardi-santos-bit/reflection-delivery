We run Pomerium behind an Envoy proxy a lot, and I keep hitting this problem where the real client IP isn't actually in the connection's remote address when traffic comes through Envoy. Envoy stashes the original client IP in a special forwarded-address header instead, so anything reading `RemoteAddr` directly gets the proxy's address or something useless. I want a shared helper for this so different handlers don't reinvent it and get it wrong.

Can you add a utility function to our internal HTTP utilities package (the httputil package under `@internal/httputil`) that takes an incoming `*http.Request` and returns the client's real IP as a string. Logic I'm after: check that Envoy forwarded-address header first, and if it's set just return that value. If it's not present, fall back to parsing the IP out of the request's remote address, stripping the port suffix if there is one (so `1.2.3.4:5678` becomes `1.2.3.4`). And if neither of those gives us anything, default to the loopback address `127.0.0.1` as a safe fallback so callers always get something usable.

The point is to centralize this so every part of the codebase identifies the originating client consistently, whether the request arrived directly or through an Envoy sidecar. Right now there's no single place for it and that's asking for inconsistent behavior. Keep it in httputil so it's easy to share.
