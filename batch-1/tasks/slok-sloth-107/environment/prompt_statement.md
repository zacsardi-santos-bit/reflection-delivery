I'm dealing with a YAML loader mess in our SLO tooling. We support a few different spec formats for describing service-level objectives, and right now when a YAML document comes in the tool just tries every parser one after another until something sticks. It's slow, it's fragile, and when nothing matches you get a garbage error that doesn't tell you anything useful.

Here's the thing though, each format has distinctive header fields at the top of the YAML that uniquely pin down which parser to use, stuff like a version identifier and a resource kind indicator. I want each spec loader to expose a quick check method that says "yes this is my format" or "no it isn't" by looking at those header fields, before we commit to a full parse. So each loader gets a way to inspect a given YAML document and decide whether it matches its expected version and kind.

The tricky part is the check has to be forgiving about how the values are written. It needs to handle field values wrapped in double quotes, single quotes, or no quotes at all, and it should tolerate extra whitespace around the values too. And it's gotta return false in the obvious failure cases, so an empty document, malformed/broken YAML that won't parse, or a document whose version or kind values just don't match should all come back as not-this-format.

Once that's in place I want the generate and validate commands to use it to route each document straight to the right loader instead of the trial-and-error loop, which also means we can give a clean error when we hit an unknown spec format. Basically detection first, then parse.
