I'm building out the beacon node's state archiving and I need a utility for computing hierarchical archive layers. The idea is historical states get stored across multiple tiers: the widest interval keeps full snapshots and the narrower intervals keep incremental diffs, so we can reconstruct any historical state cheaply when running in differential backup mode. Right now there's nothing that decides the minimal set of archived states needed to rebuild state at a given slot, and this is a prerequisite for the whole multi-layer archiving thing.

I want to express the config as a comma-separated list of positive integer epoch intervals in ascending order, where the last (largest) number is how often a full snapshot is taken and the earlier numbers are progressively finer diff tiers. Parsing a valid string (say four ascending positive ints) should give me back an object that reports the total layer count and can reproduce the original string.

Then given any slot, the utility returns the nearest preceding snapshot slot (the start of the most recent snapshot epoch at or before that slot, or genesis if no snapshot has happened yet) plus an ordered, deduplicated list of diff slots, one from each diff tier, being the most recent applicable diff slot from each tier since the last snapshot. Slots before any snapshot occurs return genesis with no diffs.

It's gotta validate the input too and reject it with specific, programmatically inspectable error codes so callers can branch on them. Reject when the string is empty, when fewer than two layers are given, when any interval is zero, negative, or non-integer, and when the intervals aren't in strictly ascending order. Each of those cases raises a structured error carrying its own distinct code, not just a generic message.
