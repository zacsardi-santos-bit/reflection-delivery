I'm extending Winch (the fast baseline JIT in Wasmtime) and hit a wall with two SIMD reduction ops that just aren't wired up yet. I need all-true and bitmask working for packed integer vectors across every lane width, so 8-bit, 16-bit, 32-bit, and 64-bit elements all need to be covered. Right now modules that use these either fail to compile or come out wrong under Winch, which is a problem since these are core Wasm SIMD instructions that image processing, crypto, and data validation code lean on all the time.

The all-true op is the "are all lanes non-zero" check, and it's gotta return 0 the moment any lane holds a zero, and 1 only when every lane is non-zero. I want that to hold whether the vector came from a load out of memory or from splatting a scalar across all the lanes, both paths need to give the same right answer. The bitmask op pulls a mask out of the sign bit of each element, again for all four lane widths.

Oh and beyond just being correct, I want these to actually use the good instructions when the CPU has them. When the compiler's told an advanced vector extension is available for the target, it should emit the hardware-accelerated instruction for each lane width instead of falling back to the generic sequence. So basically two things: correctness everywhere, and the optimized codegen path lighting up when the relevant hardware feature is detected.
