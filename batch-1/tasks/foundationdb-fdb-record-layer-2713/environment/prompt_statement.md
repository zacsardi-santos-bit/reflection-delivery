I'm working on adding support for CJK (Chinese, Japanese, Korean) text and email addresses in our Lucene-based auto-complete search. Right now we only have a generic text analyzer, but it doesn't know how to split CJK text into individual character tokens, which is necessary for auto-complete to work in those languages. Similarly, email address strings with "@" symbols and domain parts aren't handled correctly.

I need a new specialized analyzer that can handle all of these cases: CJK character-level tokenization, email address recognition, mixed CJK and Latin script, and case-insensitive matching for Latin text. The analyzer should also have configurable minimum token length filtering so that very short words get dropped from the token stream — for instance, with a minimum length of 3 characters, a word like "of" should not appear as a completed token when parsing phrase queries.

The analyzer needs to be wired up as a named factory so that a Lucene index can be configured to use it by specifying its identifier in the index options. Once configured, the index should return correct auto-complete suggestions for phrases in CJK languages, for strings that contain email-like patterns, and for mixed-script queries. When two CJK characters are typed as a query, the system should recognize the first as a completed token and the second as the prefix being completed.

Also, the phrase auto-complete logic needs to correctly exclude short words from the completed-token list. For example, querying "United States of Ameri" should treat "united" and "states" as completed tokens and "ameri" as the prefix — not include "of" as a completed token, since it falls below the minimum length threshold.
