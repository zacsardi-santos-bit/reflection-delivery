I'm working with the async message-passing channels and I keep hitting a wall on the receiver side: there's just no way to peek at the channel state without actually pulling messages off it. I want to ask stuff like is this thing closed, is there anything waiting, how many messages are buffered right now, all without disturbing the queue. Comes up constantly when I'm writing monitoring logic or thinking about back-pressure or just debugging weird channel behavior, and right now I'm stuck doing gross workarounds like consuming and re-queuing just to inspect, or maintaining my own external counter.

So I'd like the receiver types for both the bounded and unbounded channels to grow three inspection methods. One reports whether the channel is closed, which should be true either when the receiver explicitly closed it or when all the sending ends have been dropped. It needs to be right regardless of whether messages are still sitting in the buffer (a channel with messages but no senders still counts as closed), and an outstanding reserved permit should keep it counted as open, oh and dropping all the strong senders while only weak ones remain should still mark it closed.

Second one checks whether there are any messages currently buffered, returning true when empty and false when at least one's waiting, and it's gotta stay accurate after partial or full consumption. Third returns the exact count of buffered messages, incrementing on each send and decrementing on each receive, staying correct whether or not the receiver's been closed or the senders dropped. Important bit: that count should only count real messages, not the internal sentinel bookkeeping entry the channel writes when it closes, so an empty closed channel reports zero, not one.

Basically I want cheap introspection into channel health and message load without touching the messages themselves.
