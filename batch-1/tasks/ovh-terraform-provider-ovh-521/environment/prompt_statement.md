I'm extending our Terraform provider for the cloud platform and I need to add IAM permissions groups support. Right now we can manage IAM policies fine, but there's just no way to handle permissions groups, which are reusable named collections of cloud API actions that can be allowed, excepted, or denied. Without them teams keep duplicating action lists across every single policy and it gets unmaintainable fast, plus you can't share a set across policies which is the whole point.

So I want three things wired in. First a managed resource so people can create and update a permissions group with a name, a description, and up to three action sets (the actions explicitly allowed, the ones excluded from that allow set, and the ones always denied). It should expose its unique identifier, the URN, so other config can reference it, and it needs to support import by that URN so existing groups can come under Terraform management.

Then a data source to look up a single group by its URN and return all its attributes, and a separate data source to list the URNs of all available groups so you can do dynamic references.

All three need to be registered properly with the provider. Oh and btw the provider's internal validation tests are currently failing to compile because the new test files reference a type that doesn't exist yet, so part of this is just getting the package to build again. This is a key building block for composable IAM config, define a permission set once and reuse it everywhere instead of dealing with drift.
