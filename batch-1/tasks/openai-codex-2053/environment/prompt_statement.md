I'm hitting this annoying bug where one API error during streaming totally wedges my session. When the model service throws an error mid-conversation, my agent surfaces the error fine, but it never signals that the task is actually done. So the task just hangs open, the session stays locked, and any follow-up message I send gets queued forever with no way out short of restarting the whole thing. That's brutal for transient errors, users should be able to just retry or keep talking.

What I want is proper cleanup after a streaming failure. When a streaming or API error happens during a turn, emit the error notification like it does now, but also emit a task completion signal right after even though the turn failed. The point is to conclude the failed turn cleanly so the running task gets cleared and the session is fully released. Once that happens I should be able to immediately send another message.

And that follow-up message needs to actually work, oh and it should get accepted, processed normally, and produce its own task completion signal like any healthy turn would. Right now the current behavior emits the error event but never the completion, the task is never cleared, so nothing after it goes through. Basically: error, then completion, then session freed, then the next message flows through normally.
