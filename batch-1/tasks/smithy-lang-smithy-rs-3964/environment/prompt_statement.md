I'm working on the smithy-rs SDK runtime and hit a bug with the retry token bucket system. The token bucket is supposed to globally limit how many retries a client can make for a given service — when the bucket runs out, retries stop even before the configured max-attempt limit. But right now, the bucket isn't actually being wired into the retry strategy for standard retry mode. The bucket isn't placed into the operation's configuration before the retry loop, so the retry strategy can't find it and just skips enforcement entirely. Clients end up retrying all the way to their max attempt count regardless of bucket state.

There's a related issue too: token buckets should be shared across all operations targeting the same service. If one operation exhausts the bucket, another operation for the same service should see that the bucket is depleted and stop retrying early. But right now, there's no partitioned global bucket — each operation effectively gets independent bucket state, so exhaustion from one operation doesn't affect another.

I need the standard retry setup to: (1) ensure a token bucket is always placed in the operation's configuration bag before the retry loop begins, (2) share that bucket globally across all operations using the same service partition, so that after one operation exhausts the quota a second operation for the same service gets stopped after just one attempt, and (3) keep buckets for different services fully independent from each other.
