I'm digging into the Chia blockchain codebase and hit two things I want cleaned up.

First one's a layering annoyance. The class that stores fee estimation data currently lives in the full-node module, but it's really a shared protocol-level thing. Right now anybody who wants fee store functionality has to reach into the full-node module to import it, even when they've got nothing to do with full-node internals, which is awkward coupling. I want it moved over into the protocols module so it lives where it logically belongs and can be imported from that path instead. Just a relocation so the import site is the right one.

Second is an actual bug in mempool handling of non-canonical CLVM encodings in coin solutions. When a spend bundle comes in and one of its coin spends is eligible for deduplication, but that spend's solution program uses a non-canonical encoding, the mempool manager should flat out reject it and hand back an "invalid coin solution" error. Right now it doesn't return the correct error code, it just quietly changes the spend's dedup eligibility status instead, so callers can't actually tell why the spend got refused, it's indistinguishable from other failure modes. I want submitting a spend bundle where a dedup-eligible coin spend has a non-canonically encoded solution to fail with that explicit invalid-coin-solution error code reported back to the caller. Both changes are about better module organization and more precise error signaling for consumers of the mempool API.
