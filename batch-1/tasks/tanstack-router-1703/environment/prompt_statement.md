I'm hitting a nasty relative path resolution bug in the router. My app has deeply nested routes, and I've got components down at a child route that render navigation links pointing at a specific ancestor as the starting point for navigation. Problem is, when I give a relative destination path (say I want to hop to a sibling of that starting route), the relative resolution ignores the starting route I specified and instead resolves from whatever the currently active deep route is. So instead of landing on the sibling I actually want, I end up at some nonsensical deeply nested path.

Concrete example: active route is the "details" sub-route of a parameterized post route, and I set the navigation starting point to the parent parameterized post route, then navigate relative to a sibling called "info". I expect to land on "info" resolved from that ancestor, but instead it resolves from the active "details" route and sends me somewhere deeply nested and wrong. Same deal with parent-relative traversal using `..` style stuff, the going-up happens from the wrong base route.

This bites both the anchor-element links (the ones that render an actual href) and programmatic navigation triggered by user actions, so oh and both paths need to respect the specified starting route when computing the final destination, not just one of them.

The other half of this: when the starting route path I hand it doesn't match anything in the current active route hierarchy at all, nothing happens. No error thrown, no error shown, the app just silently misbehaves and it's miserable to debug. I want a clear error produced immediately in that case with a descriptive message that says which starting route couldn't be matched.

Can you fix the relative path resolution so the specified starting route is actually used as the base for all relative path calculations (both href generation and programmatic nav), and add that error when the starting route can't be found in the active hierarchy? This matters because I'm trying to write reusable navigation components inside child routes that navigate relative to a known ancestor, and right now it's basically impossible plus a source of silent bad navigation.
