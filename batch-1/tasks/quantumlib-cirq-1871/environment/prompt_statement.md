I'm cleaning up the Google quantum engine client in our codebase and the auth model is wrong for Google Cloud. Right now the client takes an API key as its main param and stuffs it into request URLs, but that's not how Google Cloud wants it. What I actually need is for the project ID to live on the client itself and get sent as a request header for billing and quota attribution, with OAuth credentials doing the real auth instead of API keys in URLs.

So concretely I want the client constructed with a project ID (not an API key), stored on the client, and reused everywhere: when it builds the underlying API service, when it lists processors, when it retrieves calibrations, and when it infers job config paths. Job configurations shouldn't carry a project ID anymore since the client already knows it, so drop that field and just use the client's own value automatically. When it connects to the API service the project ID goes in as a request header, not an API key query param.

Oh and I want an optional custom discovery URL so I can point at alternate endpoints, but it's mutually exclusive with specifying a version, passing both should be an error. Also the convenience helper that builds the engine from environment variables needs to look for a project ID env var and raise a clear, informative error if it's missing rather than failing silently later. The whole point is to match standard Google Cloud patterns (project-scoped auth, headers for billing, env-based config) and stop making users repeat the project ID in every single job configuration.
