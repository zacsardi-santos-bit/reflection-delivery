I'm building a Telegram bot on this framework and session handling is broken for basically everything except plain private messages. When users hit the bot in groups, edit their messages, fire inline queries, interact through channel posts, or go through the payment flow with shipping and pre-checkout queries, the session comes back empty and there's nothing to work with.

Digging in, the code that figures out the session key and populates session context only handles two update types, plain messages and callback queries, and it silently does nothing for the rest. So edited messages, channel posts, edited channel posts, inline queries, chosen inline results, shipping queries, and pre-checkout queries all fall through, the session key ends up empty and no user, group, or channel info gets set. That means group bots, channel bots, inline bots, and payment bots are effectively dead for a big chunk of valid Telegram interactions.

What I want is for the session to always carry three fields, one for the current user, one for the group (only when the update comes from a group), and one for the channel (only for channel posts). For query-based updates like inline queries or the payment queries, populate the user field from the sender. For channel posts, set only the channel field. For group messages or group callback queries, populate both user and group. Oh and every session context object should carry a timestamp of when it was last refreshed.

Same idea for the unique session key that identifies a conversation, it should come from the most meaningful identifier per update type, the chat id for message-based updates, or the sender's id for query-based updates. Basically any supported update type should produce a real key and real context instead of nothing.
