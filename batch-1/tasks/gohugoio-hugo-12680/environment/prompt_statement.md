I'm building out SVG stuff in Hugo templates, generating arc paths and laying out elements around a circle, and I keep hitting a wall because the math template namespace just doesn't have any trig. There's no sine, cosine, or tangent, no way to get pi, nothing for converting between degrees and radians. I end up doing awkward workarounds or preprocessing outside the template, which is annoying for what should be simple geometric math.

Can you add these to the math namespace over in `@tpl/math`? I want sine, cosine, and tangent that take radian inputs, plus the inverse ones, arcsine, arccosine, and arctangent, and also a two-argument arctangent (atan2 style) that keeps the quadrant info right. Oh and access to the constant pi, and helpers to go degrees to radians and radians to degrees both directions.

All of these should work with whatever numeric input type gets passed in, so accept anything numeric and convert it. If somebody passes a non-numeric value though, return an error. But here's the subtle bit: for values that are numerically fine but outside the function's mathematical domain, like taking the arcsine of something bigger than 1, don't error, just return a NaN result. That distinction matters. This'd make Hugo way more usable for circular layouts, map projections, and other data-driven visual template work without needing custom shortcodes.
