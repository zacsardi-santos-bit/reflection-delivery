I want to add Webnames.ru as a DNS provider in the lego ACME client so I can automate cert issuance and renewal with DNS-01 challenges instead of hand-editing DNS records every time. Webnames.ru is a registrar a lot of Russian-speaking folks use, and right now there's no way to use lego with domains parked there, which kind of defeats the whole point of automated renewal.

Here's what I'm after. The provider should read a Webnames API key from an environment variable to configure itself. If that env var isn't set, initialization needs to bail out with a clear error that says which credential is missing. Same deal when someone configures the provider programmatically without supplying the key, it should fail with an error indicating credentials are missing rather than silently going forward.

Once it's wired up, the provider should automatically create the DNS TXT record needed to prove domain ownership when a cert is requested, and then clean up (remove) that TXT record once the challenge completes. Under the hood the HTTP client talking to the Webnames API should send form-encoded POST requests carrying the right fields to add or remove a TXT record. When the API comes back with a success indicator the operation just completes with no error, and when it returns a failure indicator that error should get surfaced back up to the caller so it doesn't fail quietly.

Basically I want Webnames users to get the same hands-off automation everybody else already has.
