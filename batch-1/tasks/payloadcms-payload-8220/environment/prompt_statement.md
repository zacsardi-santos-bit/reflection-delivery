I'm hitting a nasty bug with document duplication in Payload CMS whenever localized content is involved. If I duplicate a doc that has localized blocks containing nested arrays, or a localized group living inside a tab field that itself contains a nested array field, the copy doesn't keep the right locale-specific data. Top-level stuff copies fine, but the deeper nested array items either lose their locale data or come out corrupted.

Concretely I've got a collection with a blocks field where each block holds an array of items, plus a tab that has a localized group field which itself contains an array. When I duplicate a doc that has both English and Spanish content in those structures, the duplicate drops the nested array data per locale.

Best I can tell, the root cause is on the relational database side: when a doc gets duplicated there we need fresh record IDs for every block and array row, and that ID regeneration isn't happening recursively for the nested structures, just at the top level. And when arrays are nested inside a localized group inside a tab, the locale data for those arrays gets dropped or mangled during the copy.

What I want is for duplicate to produce an exact copy of the original, with all locale-specific content intact at every level of nesting (both the localized-blocks-with-nested-arrays case and the localized-group-inside-tabs-with-nested-arrays case, English and Spanish preserved as-is), and with brand new unique database IDs generated for all block and array rows at every depth so there aren't any ID conflicts. This matters because editors working with multi-locale content lean on duplicate to spin up similar records fast, and if it silently drops or corrupts nested locale data they can end up publishing incomplete or wrong content, which is especially bad for these complex nested field shapes.
