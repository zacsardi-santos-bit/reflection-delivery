The tricky part is it uses C bindings, so the build has to have CGO enabled and the toolchain needs to support that, and right now there's nothing in the binary that actually pulls the library in so I've got no way to know whether it compiles and links properly across the whole pipeline.

What I want is a new hidden subcommand called "zstd" living under the existing "dolt admin" command group. It doesn't need to do anything clever, honestly it can be temporary or pretty much minimal, the whole point is just to exercise the compression library so I can confirm the dependency is actually wired up and the binary builds with CGO on. So the command should call into the zstd library somehow (compress or decompress something trivial) just to force the linker to include it.

A few things that matter: running `dolt admin zstd` should work from any directory, no dolt repository required, and it should complete successfully with a success exit code. Oh and I also need the Go module files updated so the compression library package shows up in the dependencies (go.mod / go.sum under the dolt Go source).

Basically this is a lightweight integration smoke test that proves the CGO-based dependency compiles and links, and it establishes the dependency so we can actually use zstd elsewhere in the codebase later.
