I'm migrating the p2p networking library in our blockchain node and it's a bit of a slog. The peer identity utilities that used to ship as a separate standalone package got folded into the main library under a new package path, so every import that points at the old standalone location needs to move to the new consolidated one. On top of that they renamed the method that turns a peer ID into a human-readable string to match the standard Go naming convention, so anywhere we convert a peer ID to a string for logging, comparison, or storage has to call the new method instead of the deprecated one.

Right now the old path and old method name are still scattered across a bunch of files, the node info manager, the p2p agent, the block syncer, the chain service, the dispatcher, the message batcher, plus the generated mock files, all of those need updating. The build won't even compile against the current library version until this is done, and actually the deprecated string method was removed outright in the new lib so any leftover call to it just breaks.

There's a correctness angle too. The node info broadcasting feature stores the local node's peer ID as a string, and after the migration that stored value has to match exactly what the new string conversion produces (it was using a deprecated method for this before, swap it consistently for the standard one). Same deal in the p2p agent when it captures and compares source peer IDs during message routing, both the broadcast and unicast handling paths should use the updated method.

Oh and don't forget the module dependency manifest, it needs to declare the new library package and version instead of the old standalone one, with the checksum entries updated to match.
