I'm working on the Gen 1 to Gen 2 Amplify migration code generator and hitting a few gaps I want to close out.

Right now the generated backend code hardcodes the Gen 1 environment name as a static value, which breaks when the same generated code needs to run across dev, prod, sandbox, etc. I want it reading the environment name dynamically at runtime instead. When the generated code runs inside a CI environment and the env name isn't set, it should throw a descriptive error right away so misconfigured pipelines fail fast and loudly instead of silently producing broken deployments. When running locally outside CI, it should fall back to a default of "sandbox". Oh and the generated storage bucket name should use this dynamic env name too rather than a hardcoded string, the bucket identifier passed into the renderer includes the environment name as its last dash-separated segment, so I want that segment swapped out for the dynamic value at runtime.

Second thing, the data source code generator currently writes a TODO placeholder comment instead of the actual schema, which forces devs to hand-copy their schema in later (error prone, annoying). I want it accepting the real GraphQL schema as input and including it in the generated output as a template literal variable, and the old placeholder export plus the TODO error should just go away.

Third, the migration tooling needs a way to actually fetch the GraphQL schema from the Gen 1 project files. It should find the AppSync API resource in the project metadata, then check for a schema folder with multiple schema files (merging them all together), or fall back to a single schema file, and if neither exists it throws a clear error saying no schema could be located in the project.

Last, the generated project's package config needs the CI detection library added as a dev dependency so those runtime CI checks actually work.
