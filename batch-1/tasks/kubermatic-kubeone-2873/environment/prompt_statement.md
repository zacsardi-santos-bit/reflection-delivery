I'm working on keeping our CI pipeline configuration consistent and up-to-date. We have a generator tool that creates a CI configuration file from a scenario definition file, and there's an automated consistency check that fails whenever the generated output doesn't match the checked-in configuration.

First, the test job definitions for our OpenStack provider include an explicit timeout environment variable that shouldn't be there anymore — the framework handles timeouts another way, and this redundant setting needs to be removed from the job definitions so it no longer appears in the generated CI configuration. Second, our upgrade scenarios that test against a reference stable version of the tool are pointing to the main development branch instead of the proper stable release branch. These scenarios had an explicit branch override that was set to the development branch, but it should actually use our stable release branch. Removing the explicit override lets the generator use the correct default.

After both fixes, the CI consistency check should pass: the tool generates a configuration file from the scenario definitions, and that output should exactly match what's checked in as the expected configuration. Right now it fails because the generated output includes the extra timeout variable and uses the wrong branch reference.
