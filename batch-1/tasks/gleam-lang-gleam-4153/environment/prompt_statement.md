I'd like the Gleam language server to offer two new code actions for pattern matching on structured values.

The first action should appear when I place my cursor on a function argument — whether it's in a named top-level function or in an anonymous function expression (including nested ones). When I trigger it, it should insert the appropriate destructuring code at the start of the function body. For tuple arguments, it should generate a pattern binding with auto-named variables. For custom types with a single constructor, it should generate a let pattern using label shorthand for labelled fields and numbered names for unlabelled ones (except when there's only a single unlabelled field, in which case just "value" without a number). For types with multiple constructors it should generate a case expression with a branch for each constructor. The action should be smart about constructor name qualification — using whatever alias or qualified/unqualified name matches the current file's imports. It should not be offered for empty tuples or for types that are internal to another module.

The second action should appear when I place my cursor on the variable name in a let binding. Triggering it should insert the same kind of destructuring code immediately after that let statement.

Both actions need to handle the case where the function body is empty (just an opening and closing brace with nothing in between), reformatting it correctly instead of producing malformed code. They should also preserve indentation of any code that already exists in the function body.
