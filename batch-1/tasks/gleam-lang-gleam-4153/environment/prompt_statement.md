I'm working on the Gleam language server and I want to add two new code actions that generate pattern matching boilerplate for me, because right now whenever I get a tuple or custom type as an argument I have to hand-write the whole destructuring pattern or case expression every single time and it's tedious.

First one, call it "Pattern match on argument", should show up when my cursor is on a function argument, and this needs to work for named top-level functions and also anonymous function expressions including nested ones. Triggering it inserts the right destructuring at the very start of the function body. For a tuple arg it generates a pattern binding with auto-named variables. For a custom type with a single constructor it generates a let pattern using label shorthand for labelled fields and numbered names for the unlabelled ones, oh and the special case: if there's only one unlabelled field just call it "value" with no number, otherwise number them starting from 0. For a type with multiple constructors it should build a case expression with one branch per constructor, each arm holding a placeholder expression. It's gotta be smart about constructor name qualification too, using whatever alias or qualified/unqualified form matches how the current file imports things. Don't offer it for empty tuples, and don't offer it for types marked internal that live in another module.

Second one, "Pattern match on variable", shows up when the cursor's on the variable name in a let binding, and it inserts that same kind of destructuring code right after the let statement.

Both actions have to handle an empty function body (just `{}` with nothing inside) without producing malformed code, reformatting it properly instead, and they need to preserve the indentation of any code that's already in the body.
