I'm adding support for a control plane outbound load balancer in private clusters and could use a hand wiring it up. Right now in a private cluster, where the API server is only reachable internally, the control plane nodes have no managed outbound internet path. The node outbound LB already covers worker nodes, but control plane nodes are left stranded. I want an optional config field in the cluster's network spec so operators can opt into a dedicated outbound load balancer for the control plane.

Here's the behavior I'm after. If the cluster is public (the API server load balancer is internet-facing), then setting a control plane outbound load balancer should be rejected at validation time, since outbound traffic is already handled there and it doesn't make sense. If the cluster is private, it's optional, and when it's left unset (nil) we just don't create an outbound LB for the control plane at all. When a private cluster does set it, I want the system to fill in sensible defaults automatically: derive the load balancer name from the cluster name, set the right SKU and type, and generate frontend IP address configs based on the requested count.

Also this thing needs to be immutable once the cluster's created, so any update that tries to change the control plane outbound load balancer config after creation should get rejected. And the frontend IP count needs a cap, max 16, and going over that should produce a validation error. Oh and I also need to update the private cluster CI template to include a control plane outbound load balancer with one frontend IP so we've got coverage there.
