I'm working on adding support for a control plane outbound load balancer in private clusters. In a private cluster (where the API server is only internally accessible), control plane nodes don't have a managed outbound internet path today. I'd like to add an optional configuration field in the cluster's network spec that users can set to enable a dedicated outbound load balancer for the control plane nodes.

The behavior should be: if the cluster is public (API server load balancer is internet-facing), the control plane outbound load balancer must not be allowed — it should be rejected at validation time since outbound traffic is already handled. If the cluster is private, the control plane outbound load balancer is optional; if left unset, no outbound load balancer is created for the control plane. If the user does set it, the system should automatically populate defaults like the load balancer name (derived from cluster name), SKU, type, and frontend IP address entries.

Additionally, once a cluster is created with a control plane outbound load balancer configuration, that setting should be immutable — any attempt to update it after creation should be rejected. The number of frontend IPs should be capped at a maximum of 16, and exceeding that should produce a validation error. I also need to update the private cluster CI template to include a control plane outbound load balancer with one frontend IP.
