I'm reworking the batching layer in our ColossalAI inference serving stack and the way sequences manage their own memory individually is making it painful to group them for prefill and decode. What I want is a new batch container class that holds a batch of sequences and tracks their KV cache block table assignments, which should start out unallocated as negative block indices. It needs to support adding sequences, appending new decode tokens to the whole batch at once, removing an individual sequence, merging two batches together, and clearing the batch entirely (clearing should release all associated memory and reset the tracking state). The batch should always know how many sequences it holds, their current lengths, and whether the internal layout is compact with no gaps.

On the memory side I need the KV cache manager to expose separate allocation methods, one for the prefill phase where we process the full initial context and one for decode where we add a single token at a time. It also needs to free memory for a single sequence (1D) or for a batch of sequences (2D) in one call, and after freeing, each internal cache block should report its full available space restored. Oh and the manager should expose its per-head size and the max blocks per sequence since I need those to construct the batch container.

The running list that tracks active sequences needs two new ops too, one that marks everything currently in prefill as actively running, and another that moves a given set of sequences by their IDs from prefill into decode, so the inference loop can drive the stage transitions explicitly. Also please drop the block table parameter from the sequence constructor since block tables live in the batch container now, not on the sequence itself. This all lets us build a cleaner batched loop where prefill and decode are clearly separated and memory allocation is reversible and verifiable.
