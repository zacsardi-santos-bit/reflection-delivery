I'm digging into SSL buffer management and hit a real problem with how we decide when connection buffers can be freed, over in the code that backs `SSL_free_buffers`. The freeing logic doesn't handle pipelined connections right. When a pipeline-capable cipher is in use and two records show up together, if the app fully reads the first one but the second pipelined record is only partially sitting in the read buffer, we wrongly say it's fine to free the buffers even though there's still pending data those buffers are holding. That's the kind of thing that turns into data corruption or use-after-free in apps leaning on pipelining for throughput, so I want it tightened up.

What I need is for the buffer-freeing path to refuse whenever any unread data remains, no matter if it came in whole or partial. That covers the case where only a record header landed, where a full header arrived but no body yet, where a partial record body is buffered, and where the app's only done a partial read of what's available. And most important, the pipelining case: second pipelined record partially received means we still won't free, even after the first complete record was read successfully.

Also I keep duplicating the setup for the pipeline-capable engine across test files, so I want a shared helper in the SSL test helpers that loads and initializes that dummy pipeline engine once, and I can reuse it everywhere instead of copy-pasting the load logic. Wire it into the relevant test support so both the buffer tests and anything else can call it.
