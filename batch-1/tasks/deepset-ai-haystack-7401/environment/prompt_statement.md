I'm adding an LLM-based evaluator to Haystack so developers can judge pipeline output quality with a language model as the judge, since right now anyone wanting to check things like toxicity, factual accuracy, or relevance has to hand-build and wire up their own eval pipeline, and there's no reusable declarative piece for it. What I want is a proper Haystack component where a developer writes their evaluation criteria in plain language (the "instructions"), declares which inputs the evaluator receives and what score outputs it should produce, and passes a few few-shot examples showing sample inputs and the matching judgments, plus optionally configures the underlying LLM API and auth.

It's gotta validate its config hard at init time, rejecting malformed inputs, outputs, or examples with clear helpful error messages, and it should have separate methods for validating the input parameters and validating the output structure so those checks can be run independently. At runtime it also needs to check that all the provided input lists are the same length and complain if they're not. Oh and it should expose a method that generates the prompt template it uses.

The thing needs to be fully serializable and deserializable so it survives being saved and restored as part of a pipeline, and it should be importable directly from the main evaluators package. When it runs it calls the underlying LLM, parses the structured response, and returns a results list with one dictionary per evaluated item, each holding the evaluation scores plus an identifying label so downstream components can consume it reliably.
