I'm working on a collaborative document editor built on CRDTs and hit two things I want cleaned up. First, initializing a tree data type is annoyingly inconsistent with the rest of the API. Right now it wants a pointer to the initial node, but everything else works with value types, so I keep tripping over it. I want tree init to accept a value instead of a reference, and this needs to apply across both the object and array APIs where trees get created.

Second, and this is the bigger one, there's no built-in way to snapshot a document's full live state and get it back out again. I can't export the current CRDT state, serialize it to compact JSON, and rebuild an identical doc from that string. The doc holds a bunch of CRDT types: objects, arrays, counters, plain text and rich text, trees, plus primitives, and any snapshot has to preserve the type info for each one so reconstruction is faithful.

So I want a new package that defines typed representations for each of these value types (object, array, counter, text, rich text, tree, primitive) and a conversion function that walks the live CRDT root state and produces those typed reps. Each type needs marshal and unmarshal operations, and the on-the-wire format should be compact JSON that round-trips reliably, so a doc reconstructed from a snapshot serializes back to the exact same form as the original. Oh and deserialization has to be careful about bad input: invalid data formats, wrong or unrecognized type codes, malformed nested structures, all of those should come back as descriptive errors rather than panicking or silently corrupting. This is the kind of thing that unlocks state transfer, offline sync, document storage, and debugging, so type fidelity through the round-trip really matters.
