I'm wiring up Azure Blob Storage support in SkyPilot's storage layer and hit an annoying gap. Right now if you hand the system a bad bucket name for AWS S3 or Google Cloud Storage it catches it right away and raises a storage name error with a clear message before it ever touches a cloud API. That's great, but Azure containers get no such treatment, so you just try to create a container with a name Azure doesn't like and get back some cryptic cloud-side error instead of anything actionable. Super inconsistent with the other backends.

I want the same kind of upfront validation for Azure container names, matching how the S3 and GCS paths behave today. Azure's rules are specific: names have to be between 3 and 63 characters long, can only use lowercase letters, digits, and hyphens, must start and end with a letter or digit, and can't have two consecutive hyphens anywhere in them. So anything shorter than 3 chars or longer than 63, anything with uppercase letters, anything that doesn't start with a lowercase letter or digit, or anything with two hyphens in a row, all of those should get rejected. When a name breaks any of those rules I want a storage name error raised with a descriptive message explaining what's wrong, and crucially it needs to happen before any network calls go out, same as the existing S3 and GCS validation. Point is to make the storage system behave uniformly across all the cloud providers we support so users get real feedback instead of confusing failures.
