I'm adding a new lint check to kube-linter and could use a hand wiring it up. The gap is there's no built-in way to enforce annotation policies on StatefulSet storage, so teams end up deploying StatefulSets whose volume claim templates are missing required metadata like backup policy labels, billing tags, or compliance markers, and nobody notices until something breaks (missed backups, untracked cloud costs, that kind of thing).

What I want is a new linting template that takes a configurable annotation key as its parameter and checks that every volume claim template in a StatefulSet actually carries that annotation. If any volume claim template is missing it, whether the template has some other annotations or none at all, the linter should emit a diagnostic that names the StatefulSet resource type and calls out exactly which annotation was expected. If all the volume claim templates have the annotation, then no diagnostic at all. Oh and the template config needs to validate that the annotation parameter is actually provided, so reject any configuration that leaves it out.

There's also some plumbing on the infra side. I need a utility that extracts the spec from a StatefulSet object, and it should handle both directly typed StatefulSet objects and ones that embed the spec via reflection, falling back gracefully (returning nothing usable) when the object isn't a StatefulSet at all. And also a small function that returns the API version string for PersistentVolumeClaim resources, since the check needs to reason about those. Thanks!
