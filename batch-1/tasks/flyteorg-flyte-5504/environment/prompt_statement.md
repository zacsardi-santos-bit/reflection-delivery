I'm adding OTLP trace export to the OpenTelemetry utilities in the Flyte standard library, over in the otelutils package. Right now the telemetry config only knows how to ship traces to Jaeger or dump them to a local file, and that's it, no OTLP at all, which is a pain because OTLP is what every modern observability backend and collector speaks (Grafana Tempo, Datadog, the OpenTelemetry Collector, etc). So I want two new exporter options in the telemetry config, one that sends traces to an OTLP gRPC endpoint and one for an OTLP HTTP endpoint, each with its own configurable endpoint URL field so operators can point them wherever their collector lives.

Also sampling is totally hardcoded at the moment, there's no operator control over trace volume. I want a new sampler config section where you can pick a strategy, like always sample everything, or a trace ID ratio-based sampler. Oh and the function that registers tracer providers currently ignores context entirely, it needs to take a context parameter instead so the OTLP exporters (which need a context to actually establish their connections) can init properly with the right lifecycle handling.

Last thing, all these new knobs (the OTLP gRPC endpoint, the OTLP HTTP endpoint, and the sampler type) should be wired up as command-line flags too so they can be set without editing config files. Without this we're stuck on Jaeger or file exports and can't plug into the standard observability ecosystem, so it matters for platform teams who need control over where traces go and how much gets sampled.
