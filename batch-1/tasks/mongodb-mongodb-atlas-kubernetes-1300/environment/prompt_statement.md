I'm bumping the Kubernetes controller-runtime style framework we depend on in our operator, and the newer version broke a bunch of stuff that I need cleaned up so it compiles and the tests pass again. First thing, all the event handler callbacks (create, update, delete, and the generic event one) now have to take a context object as their first argument, our current handler types don't have that param so they won't build against the updated library, so every type implementing the event handler interface needs the signature updated.

Also we've been building namespace-scoped and label-filtered cache builders inline in a couple places, both in the main binary and in the e2e test helper, and it's duplicated. I want two shared utility functions pulled into the controller package instead, one that builds a cache scoped to a given list of namespaces and one that builds a cache filtered by a label selector for a particular resource type, and then swap the inline constructions over to call those new functions.

Last bit is some unit tests that use the fake Kubernetes client. In the new version you have to explicitly declare which resource types carry status subresources, otherwise status updates just get silently dropped and the tests fail in confusing ways, so those need registering. And a few tests set a deletion timestamp before creating the object in the fake client, which resets the timestamp, so move that to set it after creation instead. Without all this the operator won't compile and everything fails against the updated framework, plus the cache extraction just kills the duplication between prod and test.
