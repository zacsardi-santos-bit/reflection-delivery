I'm working on improving the proxy access authorization in our token authentication system. Right now, when someone specifies which principals are allowed for proxy access in an authorization detail, they can only name a single principal using a plain string. I'd like to change that so the allowed principals are expressed as a list, making it possible to name multiple allowed proxies in one entry. The token issuance endpoint should accept requests using this list format.

Beyond the format change, I also need certificate-bound token validation to actually verify the proxy access claim against the certificate being presented. Currently, when someone presents a certificate alongside an access token that includes proxy access authorization details, the system doesn't check whether that certificate's identity is among the listed allowed principals. I want it to look up the certificate's SPIFFE identity URI and compare it against the list. If it matches any entry, the token should validate successfully. If the authorization details are missing, can't be parsed, use the wrong format for the principals list, or the certificate's identity isn't in the list, the validation should fail with a confirmation error.

I'll also need a utility function that extracts the single SPIFFE identity URI from an X.509 certificate — it should return nothing if there are no SPIFFE URIs, and also return nothing if there are multiple SPIFFE URIs (since the identity would be ambiguous in that case).
