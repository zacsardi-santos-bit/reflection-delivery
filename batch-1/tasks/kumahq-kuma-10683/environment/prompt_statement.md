I'm working on adding hostname generation support for multi-zone services in Kuma. Right now, the hostname generator can target single-zone services and external services via label selectors, but it has no awareness of multi-zone services. I need the hostname generator to support multi-zone services as a first-class selector type, so that operators can configure it to automatically assign DNS hostnames to multi-zone services that match given labels.

Concretely, I need a new selector type added to the hostname generator spec so that a generator can be configured to target multi-zone services. I also need a new generator implementation that watches multi-zone service resources, matches them against configured hostname generators, and writes the generated hostnames into those services' status when a match is found. The generator must respect selector isolation — a generator configured for single-zone services should not produce hostnames for multi-zone services, and vice versa. Multi-zone services with no matching generator should have no automatically assigned hostnames.
