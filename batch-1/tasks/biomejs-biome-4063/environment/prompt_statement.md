I'd like to add a new CSS lint rule to the nursery group that enforces a consistent, semantic ordering of properties within CSS rule blocks. Right now there's nothing preventing developers from listing properties in random order, which makes stylesheets harder to review and maintain.

The rule should detect when properties aren't in the expected semantic order and offer a safe auto-fix to reorder them. The ordering should place custom properties first, then layout-related properties, then spacing, then typography, then interactive behavior, then decorative styles, and finally transitions and animations. Nested selectors and media queries should always appear after all property declarations in a block.

The rule also needs to handle some tricky cases: vendor-prefixed versions of a property should come before the unprefixed version; property name comparisons should be case-insensitive; when a shorthand property appears after its own longhand variant it should be treated as valid (no diagnostic); and the sort should be stable so duplicate property declarations don't get reordered relative to each other. The rule should also check the contents of nested rule blocks recursively.
