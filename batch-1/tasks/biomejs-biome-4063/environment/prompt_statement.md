I'm adding a new CSS lint rule to the nursery group in Biome and I want it to enforce a consistent, semantic ordering of properties inside CSS rule blocks. Right now nothing stops folks from listing properties in whatever random order they feel like, which makes stylesheets a pain to review and to debug specificity issues, so I want the linter to flag any rule block where the properties aren't in the expected order and hand back a safe auto-fix that reorders them for me.

The order I'm after groups related concepts together: custom properties (CSS variables) come first, then layout properties, then spacing like margin and padding, then typography (color, font), then interactive behavior stuff (pointer events, visibility), then decorative styles (borders, backgrounds), and transitions and animations dead last. Oh and any nested selectors and media queries should always land at the very end of their containing block, after all the plain property declarations.

There are a few edge cases I really care about. Vendor-prefixed variants of a property need to sort before their unprefixed counterpart. Property name comparisons should be case-insensitive. When a shorthand property legitimately follows its own longhand variant don't emit a diagnostic, that's a common override pattern and it's fine. The sort has to be stable so duplicate property declarations keep their relative order instead of getting shuffled. And it needs to recurse, so the contents of nested rule blocks get independently checked and fixed too.

The upshot is I want to rely on the tool to keep ordering consistent automatically instead of doing it by hand every time.
