I'm working on Cairo's documentation extraction and hit a real gap: it only reads outer doc comments (the ones placed before an item) and totally ignores inner doc comments (the ones written inside an item's body). Both are valid, idiomatic ways to document things in Cairo, you can put a comment above a function or inside it, but right now only the outer style gets picked up, so any docs written inline never show up in hover tooltips or anywhere else. On top of that, file-level comments at the top of a crate root or a submodule file aren't captured at all, so crate-level and module-level documentation is just invisible.

I want to extend the doc system so a few things happen. For functions, trait methods, and impl methods, the extracted documentation should combine both the outer comments and any inner comments found inside the body into a single string, outer comments first. Same idea for inline modules, combine the outer prefix comment with any inner comments in the module body. For non-inline submodules (the ones defined as separate files), the docs should pull the file-level comments from the module's own source file along with any outer declaration comment. Crates should just return the file-level comments from their root source file.

Also the language server's hover tooltip needs to surface this full combined documentation (both outer and inner) for any item that has it. And importantly, items that only support outer comments, so structs, enums, traits, impls, and their members and variants, should keep returning their outer documentation exactly as before, don't change that behavior.
