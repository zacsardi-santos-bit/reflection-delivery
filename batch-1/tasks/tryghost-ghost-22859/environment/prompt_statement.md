I'm updating the analytics tracking integration in Ghost and need a few things changed. Right now the tracker script we inject into page heads sends visitor events straight to the third-party analytics provider's infra using an older data source identifier, and I want it routed through our own Ghost-operated proxy endpoint instead, with the data source name renamed to a simpler value. This is part of moving analytics onto a Ghost-controlled layer so we get more control over data handling down the road.

Also there's no sane way to test analytics locally without hitting production, so I want a new optional local development mode in the tracker config. When it's enabled, all analytics traffic should redirect to a local proxy endpoint using a separate local auth token, and when it's off (the default) everything behaves as before against the production endpoint and credentials. Oh and the front-end tracker script should read its host and authentication token from its own data attributes now, instead of storage mode being set as a separate attribute on the script element, so all the init values (host, token, everything) flow through the data attributes map consistently.

Last thing, I need test fixtures for the analytics reporting APIs that pin down expected query results. They should cover the KPI metrics per date (visits, pageviews, bounce rate, average session duration), top browsers, devices, locations, operating systems, pages, and traffic sources by visit count, plus filtering by browser, device type, location, operating system, page path, referral source, and member subscription status. The fixtures also need to verify that single-day date ranges come back with hourly granularity (one row per hour across the full 24-hour day) while multi-day ranges return daily granularity, and that timezone params correctly shift the date boundaries when filtering.
