Working on Beyla and I want to change a default. Context propagation, the feature that injects distributed trace headers into outgoing HTTP requests using the Linux kernel's traffic control (TC) subsystem, is currently off unless someone explicitly turns it on. That's a problem because if you deploy Beyla without any special config, distributed tracing between services just silently doesn't work until you happen to discover the option and flip it. I'd like it enabled by default so distributed tracing works out of the box, while still letting people disable it if they really need to.

So basically flip the default value for the context propagation setting to on, so that when Beyla starts with no explicit config for this it's already active. The disable path still needs to work though, users who don't want it should be able to turn it off through configuration, it just shouldn't be required for the common case anymore.

The why here is that distributed tracing is a core observability thing and requiring folks to hunt down and manually enable it creates friction and means a lot of deployments miss out entirely. Making it the default gives better out-of-the-box observability for everyone. Just make sure enabling stays optional (it's the default) and disabling still honors the config.
