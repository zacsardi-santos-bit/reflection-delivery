I'm working on the storage backend for a container image library and I want to clean up two related things in how layers get committed to local storage. Right now the logic that computes a layer's unique chain ID lives inline inside the larger commit function, which makes it impossible to unit-test on its own. I'd like it pulled out into a standalone function so I can feed it known inputs and check the outputs directly. The rules stay the same: for a layer identified by its uncompressed digest (the traditional full-stream pull), the ID either equals that uncompressed hex directly when it's a root layer with no parent, or it's a hash combining the parent's ID with the layer's uncompressed digest, following the usual Docker/OCI chain-ID derivation. For a layer identified by a table-of-contents digest (the partial-pull path), the ID must always be produced by hashing, never returned raw, and the TOC digest has to be folded in using a distinct prefix so it can never collide with or be confused for an uncompressed-digest-based ID. Also the blob digest attached to a layer shouldn't influence the chain ID at all, keep it out of the computation.

Second thing, actually this is the one that bugs me more, right now we happily write an image even when the uncompressed-digest (DiffID) values declared in the image config don't match the actual uncompressed content of the layers being committed. That's an ambiguity waiting to bite us because a single compressed blob can be seen two ways, decoded traditionally via the full tar stream or via the partial-pull TOC path, and nothing enforces the two views agree. So when a config does declare those DiffID values, I want to enforce they match what's really being stored, and any mismatch should fail the store operation with a clear error rather than silently persisting a misrepresented image. When the config doesn't declare them, don't invent a check. Both changes together make the ID derivation explicit and testable and close the gap where a stored image could lie about its layer contents.
