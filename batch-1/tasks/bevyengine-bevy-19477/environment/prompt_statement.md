I'm poking at Bevy's ECS and hitting a papercut with system initialization. Right now when I call the init method on a system it just returns nothing, so if I want to know what components a system reads or writes, or check whether two systems conflict on their access, I have to go reach for separate indirect mechanisms after the fact. It's annoying because the info is right there at init time, the system already computes its component access, we just throw it away.

What I want is for the system initialization method to return the system's component access set directly instead of returning nothing. That way right after I initialize a system I can immediately call the conflict-detection methods on whatever it hands back and see if it clashes with another access set, no extra round trip. Makes building tooling and diagnostics around access patterns way less painful.

Can you update the init method on the system trait so it returns the component access set, and make sure every existing system type still implements the updated signature. That includes systems that get built from plain functions through the standard function-to-system conversion path, those need to return their access set too. Basically anything that's a system today should compile against the new return type and actually hand back the real access set, not some placeholder.
