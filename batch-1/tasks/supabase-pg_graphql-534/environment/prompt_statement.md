I have SQL functions that use other SQL functions as default argument values — for example, a function whose parameter defaults to calling a helper that returns the current user's ID. When I expose these through the GraphQL API, something goes wrong: instead of the parameter appearing as optional in the schema, it seems like the GraphQL layer can't handle the expression-based default and either treats the parameter as required or breaks the schema entirely.

The same issue happens when a parameter's default is an arithmetic expression rather than a plain literal. I'd expect these arguments to show up in GraphQL introspection as optional with a null default value (since the expression isn't a static literal), and I'd expect the function to be callable both with and without the argument — using the database's own default evaluation when no value is supplied. Right now neither of those things works correctly for complex default expressions.
