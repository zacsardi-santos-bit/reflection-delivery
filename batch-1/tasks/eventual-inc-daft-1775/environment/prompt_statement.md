I'm working with Daft and I keep hitting a wall with nested columns. I've got list columns and struct columns and there's just no expression-level way to reach into them and grab individual elements or fields, which means right now I'm exploding rows or dropping into Python to do it, and that's slow and clunky when I'm trying to build a real nested-data pipeline.

What I want is two things. First, list element access by index. I want to pull the element at a given position from each row of a list column, and the index should be able to come from either a constant integer or another column so it can vary per row. Both positive and negative indices should work, negative counting back from the end. It also needs to accept a fallback value that gets returned when the index is out of bounds or when the whole list row is null, and if I don't pass a fallback it should just return null in those cases. One subtlety: if the list is valid and the index is in bounds but the element sitting there happens to be null, I want that actual null back, not the fallback. This should behave the same for variable-length list columns and fixed-size list columns. And if I try this on a column that isn't a list type at all, it should raise a clear error rather than doing something weird.

Second, struct field access. I want to extract a named field out of a struct column as its own standalone expression, and the result should carry the field's original name and type. Null struct rows should produce null in the extracted result. If I ask for a field name that doesn't exist in the struct schema, or if I try struct field access on something that isn't a struct column, it should raise a clear error too.

Both of these live in the Daft expressions layer alongside the existing list and struct handling, so they should plug into the same expression machinery.
