I'm adding update notifications for installed extensions in the GitHub CLI. Right now we notify users when a new version of the CLI itself is out, but there's nothing equivalent for extensions, so people miss fixes and new capabilities unless they manually run upgrade commands. I want a dedicated function that checks whether an installed extension has a newer release available, and it should rate-limit itself to at most once every 24 hours per extension so we're not hammering the network. Local extensions (the ones installed from a local path rather than a remote repo) should never get checked since they don't have published releases, just skip them entirely.

Also the cached update state matters here. When an extension gets removed, clean up any cached update state for it, and when an extension is reinstalled or freshly installed, clear any stale update state left over from a previous install, otherwise stale notifications pop up after a reinstall which is confusing.

Users need to be able to opt out of extension update notifications on their own, using a separate environment variable from the one that disables the main CLI's own update notifications, so the two are independent. And like the existing CLI update check, extension update checks should be automatically suppressed in CI environments and in codespace / hosted dev environments where notifications would be noise.

Oh and the function that constructs the extension command needs to accept a pluggable update-check function so the checking behavior can be injected instead of hardcoded, makes it way easier to swap or customize. Last thing, in the upgrade output the extension names shouldn't be padded to a fixed width anymore, it reads cleaner unpadded.
