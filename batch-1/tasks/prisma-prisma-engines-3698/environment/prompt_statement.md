I'm working in the SQL schema describer library of a Rust database tooling project and the table struct's got this problem where it tracks partition-ness with a single boolean, and that just doesn't scale once you want more table characteristics. Specifically I need to also know whether a table has child tables inheriting from it (PostgreSQL table inheritance), and adding a separate bool per property is gross.

So I want to swap that lone boolean partition field for a proper bitflags-typed field on the table data structure. Introduce a bitflags enum defining the available table property flags with at least two variants, one for partition tables and one for tables that have subclass tables (child tables inheriting from the parent via PostgreSQL-style inheritance). The serialized JSON needs to change too: where the old format emitted a boolean for the partition property, it should now emit a numeric integer encoding the combined flags, and that's zero when no flags are set.

Everywhere that currently creates partition tables through the old dedicated method needs to move to a new, more general method that takes a set of property flags. Update the walker methods too, so the existing is-partition check reads from the new flags field, and add a new method to check whether a table has subclasses. All the database-specific describers (MySQL, PostgreSQL, MSSQL, SQLite) should use the new table-creation API, and the PostgreSQL describer additionally has to query the database metadata and populate the subclass flag from it. Point is a compact bit-flag model that avoids boolean proliferation and unblocks better inheritance support.
