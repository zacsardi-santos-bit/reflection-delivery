I'm poking at the ArgoCD project server and found a real authorization hole in how project updates get checked. Right now if you've got project-update permission you can also strip cluster destinations off a project or yank source repo access, even when you have zero permissions on those clusters or repos yourself. That basically lets a restricted user route around the whole cluster and repository permission model just by hitting the project update endpoint, silently revoking access for every app under the project. I want the update path to actually enforce the right checks first.

Concretely, when a project update removes clusters from the allowed destinations, the caller needs cluster-update permission for each removed cluster, and anyone lacking it gets rejected. Same idea for source repos, removing one requires repository-update permission on that specific repo. And if the project's cluster-scoped resource allowlist or namespace-scoped resource blocklist changes, that should require cluster-update permission for every destination cluster in the project, since those settings govern what's deployable everywhere. Someone with only project-update access shouldn't be able to do any of this without the extra perms.

To make the diffing clean I also want a utility that, given a combined list of items, returns only the elements appearing exactly once, so it gives me the elements unique to one side of a comparison. Oh and I need a method on the project spec type that returns the list of cluster server URLs pulled from the project's destination entries, so destination clusters can be extracted and checked easily.
