I'm working on a Gateway API project and noticed that one of the policy resources — the one for controlling client traffic — uses its own custom type for reporting status conditions, while all the other policy resources use the standard shared status type from the upstream API specification. This inconsistency makes the API less predictable for users who work across multiple policy types.

I'd like to remove the custom status type and switch this resource over to the standard shared type instead. As a nice side effect, this should also fix the auto-generated API reference documentation, which currently has extra blank lines in the area around where this custom status type was defined. The project has a check that the checked-in documentation file must exactly match what the documentation generator produces from the source types — so once the custom type is removed, that check should also pass cleanly again.
