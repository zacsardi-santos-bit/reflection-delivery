I'm writing authorization policies in Cerbos and I keep hitting a wall when I try to reference the scope and policy version of the principal and the resource inside a condition expression. Like I want a rule that only allows an action when the principal and resource share the same scope, or the same policy version, but when I reference those fields in a condition the evaluation just fails because they don't seem to be available in the expression context.

The thing is, both scope and policy version are already part of every access check request, for both the principal and the resource. Other stuff like resource attributes and principal roles works fine in conditions, so I'd expect scope and policy version to be reachable the same way. Can you expose these so I can write scope-aware and version-aware rules?

Concretely I need the requesting principal's scope and its policy version both accessible in condition expressions, and the same for the target resource, its scope and its policy version. And rules that condition access on equality or comparison of these values, whether comparing principal against resource or checking against a known constant, should evaluate correctly. These values are part of the request contract already so they should show up alongside the other request properties I can already read.
