I want to add a topological sort utility to u-root, living under `@cmds/exp/tsort`. This is the standard Unix tsort, it reads whitespace-separated pairs of names from stdin or from a file passed as an argument, where each pair means the first item has to come before the second, and it prints a valid ordering of all the items one per line so each name shows up before anything that depends on it. Topological sorting is that classic dependency-ordering operation a lot of build tools and package pipelines lean on, so having it makes the toolkit feel more complete for folks working in embedded or minimal Linux setups.

A few behaviors I care about. Input parsing needs to be flexible, any mix of whitespace (spaces, tabs, newlines, carriage returns, whatever) should work as token delimiters. If I feed it an odd number of tokens, meaning there's an incomplete pair dangling at the end, it should report an error about that. If the graph has cycles it should still emit output for all the nodes but also report each detected cycle to stderr prefixed with "tsort:", and return a non-fatal error status in that case. If I pass a file that doesn't exist, the error should name the missing file. Oh and self-referencing pairs, where both elements are the same name, should just declare that single node with no dependency edge rather than being treated as a cycle.

Also the graph and any supporting data structures backing the algorithm should each have clearly defined, safe behaviors, including proper error propagation when something tries to operate on a missing or invalid element.
