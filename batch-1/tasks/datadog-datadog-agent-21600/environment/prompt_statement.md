I'm cleaning up the secrets resolution system in the Datadog Agent and hit two things that need fixing. First, the path tracking for secrets inside YAML arrays is busted. Right now if I've got two secrets in the same array they both get the same path (like both showing as "instances/password" in debug output), so I can't tell them apart. I need the tracked path to include the numeric index of the array position so each secret has its own accurate location, e.g. the first element at index 0 and the second at index 1 each get their own path entry.

Second, there's no way to refresh secrets after they've been resolved at startup, which means secret rotation needs a full agent restart today. I want a subscription mechanism where callers register a callback to get notified whenever a secret is resolved or its value changes, and the callback should receive the handle name, origin, the full path, plus both the old and new values. Alongside that I need a refresh operation that re-fetches all known handles from the backend and only notifies subscribers when a value actually changed. For safety there's gotta be a per-handle allowlist restricting which secrets are allowed to change during a refresh, so only explicitly permitted ones (API keys, say) can update at runtime.

Couple more things tied to this. The config method that sets up the secrets backend needs a new parameter for the refresh interval. And I need a utility function that can assign a value to a config setting by walking a path of string keys, including down into nested maps and slices using numeric string indices, since the refresh workflow leans on that. Oh and the existing callback-based resolve method should just be replaced entirely by the new subscription model. The whole point is letting the agent support live secret rotation for allowlisted handles without restarting or disrupting service, and keeping the debug/change tracking unambiguous when multiple secrets share an array.
