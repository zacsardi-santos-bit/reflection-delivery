So I'm building a retry wrapper for Mongoose transactions and I keep hitting this thing where saving a doc inside a transaction that later aborts wipes the document's dirty state, same as a successful save would. That means when I loop back and try saving the same doc instance again there's nothing marked modified, so the writes just vanish silently. Reloading from the DB after every failed attempt is annoying and can be wrong when the instance carries in-memory state beyond the modified fields, so I want to solve this on the document itself.

What I want is a way to snapshot a document's current modification state right before I attempt the transaction save, and then restore that snapshot if the transaction aborts, so the doc goes back to its pending-changes state and saves correctly on retry. The snapshot and restore need to cover everything, top-level fields, nested object paths, single nested subdocuments, and document array elements, not just the root doc's modified paths.

Oh and separately I'd like a way to fully and explicitly clear all of a document's pending modifications on demand, so a save right after writes nothing even if the doc had unsaved changes, and that clear should apply to every subdocument too, not just the root.
