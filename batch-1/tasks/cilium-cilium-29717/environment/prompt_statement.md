I'm building out a new package in the Cilium tree at `@pkg/container/bitlpm` in Go, and I need bit-based longest-prefix match tries because right now there's no clean, efficient way to do prefix-based hierarchical lookups over either IP networks or generic unsigned integer ranges. This blocks networking policy work where I keep wanting to ask things like "which stored prefixes cover this IP?" or "which port ranges overlap this range?" without scanning everything.

I want two tries. First a generic one keyed by any unsigned integer type where entries live under a (key, prefix-length) pair, kind of like CIDR notation but for arbitrary unsigned ints. It's gotta support insert plus update, looking up the most specific prefix matching a given key, delete, iterating all entries, and traversing both ancestors (shorter, broader prefixes that cover a given key) and descendants (longer, narrower prefixes contained by a given key). Both the ancestor and descendant traversals should visit entries in order from the broadest (least specific) prefix down to the most specific, so ordering matters for both.

Second, a CIDR-specific trie that wraps the first one and works with the standard library's network prefix type (netip.Prefix). It should insert/update by network prefix, look up the most specific prefix matching a given IP address, and expose the same ancestor and descendant traversals with that same broadest-to-most-specific ordering. It's got to handle IPv4 and IPv6 correctly. The internal key type backing the CIDR trie needs bit-level operations too, oh and specifically a way to return the bit value at a given index (0 or 1, counting from the most significant bit) and a way to compute the number of leading bits two prefixes have in common.

I care a lot about correctness across a wide spread of cases, so think sparse and dense prefix sets, single-entry tries, full-range coverage, and deletion done both in insertion order and reverse order. This is meant to be a foundational building block for scalable network policy evaluation, so it needs to be solid across all of that.
