We've got a nasty reconciliation loop in our operator on OpenShift and I need help closing it. The platform auto-injects image pull secrets into every service account, but when our operator reconciles those accounts it strips out the image pull secrets that the platform put there because our desired state doesn't include them. Then the platform re-adds them, which kicks off another reconcile, which wipes them again, and round and round it goes forever, wasting resources and generally messing with whatever the platform's trying to manage on those service accounts.

Here's the thing, we already handle this for regular secrets during service account updates. When the existing object has secrets that our desired state doesn't include, we carry the existing ones forward instead of clobbering them. I want the exact same protection for image pull secrets. So when we're updating a service account and the current live object has image pull secrets while our desired state has none, we should pull the existing image pull secrets forward into the update rather than removing them. Basically mirror the regular-secret preservation logic but for the image pull secrets field.

That should break the loop and keep us from stepping on the platform (or any other controller) managing service account data.
