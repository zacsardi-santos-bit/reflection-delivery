I'm working on adding Deno builder support to GoReleaser, similar to how Bun, Rust, and Zig builders are already implemented. GoReleaser can compile and release software for multiple runtimes, and I'd like to add the same capability for Deno — allowing it to compile TypeScript projects into native standalone binaries for the standard desktop platforms.

The new builder needs to live in its own package alongside the existing non-Go builders, self-register under the name "deno", and report the Deno runtime binary as a required system dependency. It should parse Deno-style target triple strings into a structured representation (with separate fields for architecture, vendor, OS, and ABI), translate Deno's architecture names into the conventional Go-style names used throughout the rest of the codebase, and supply sensible defaults (tool name, compile command, working directory, entry point file, and a default set of five standard targets).

The artifact filtering system also needs to be updated so that artifacts built with this new builder behave consistently with the other non-Go builders when filtering by architecture variants. Additionally, an example configuration file should be included so users can easily initialize a new Deno project configuration. The health-check subsystem should recognize "deno" as a required binary when a project is configured to use this builder.
