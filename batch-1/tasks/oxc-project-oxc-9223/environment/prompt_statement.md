I'm working on the linter and want to add reporting for unused inline directive comments, the kind you write to suppress a lint warning on a specific line. Right now if someone drops a suppression comment for a rule that wouldn't have fired on that line anyway, we have no way to flag it as pointless, and a re-enable comment with no matching disable earlier in the file just gets silently ignored. Over time codebases accumulate stale or redundant suppression annotations that add noise and mislead reviewers into thinking a rule is genuinely problematic when it isn't, plus enable-without-disable is basically dead code, so I want a CLI-level way to audit all this.

What I'm after is a new group of command-line options grouped under an "inline configuration comments" section. There should be a simple flag that turns on reporting with a default severity, and a separate flag that takes an explicit severity value (either warn or error) instead of the default. Only one of those two forms should be usable at a time, they're mutually exclusive. When enabled, the linter should warn about disable directives where no violation would've actually been reported on the targeted line, and also warn about enable directives that have no matching disable directive.

On the plumbing side, the lint command's parsed options struct (the thing you get back from parsing CLI args) needs a dedicated field that aggregates these settings. And the underlying directive-tracking logic needs updating too, it has to record which disable directives actually matched a violation so we can identify the unused ones, and separately track enable directives that never had a matching disable. Both pieces of state need to be there for the reporting to work.
