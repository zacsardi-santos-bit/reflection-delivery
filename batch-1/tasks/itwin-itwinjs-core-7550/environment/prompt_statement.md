I'm cleaning up the public API surface of our core common library and there are a few related things I keep tripping over. First, the internal rendering classes for packed feature tables and the related model lookup tables are getting exported straight out of the main public feature table module, but these are implementation details of the rendering pipeline and shouldn't be reachable by external consumers. I want them moved into a new internal module living under a dedicated internal subdirectory so they're no longer importable from the main public feature table module and can only be pulled in from that internal module path. It makes it way easier to evolve the guts without breaking changes downstream.

Second, the plan projection view settings class has a constructor that was always meant to be internal-only but it's still technically callable from outside. It already has a static factory method that's the intended way to make instances, so I want the constructor made truly private so the factory is the only supported path. Oh and the factory should return nothing when it's handed an empty config object (no meaningful properties), so callers can tell "no settings" apart from "settings with all defaults."

Third, the feature overrides class exposes some internal backing fields to subclasses even though the base already has proper public getter properties for the same data. Make the backing fields for the always-drawn and never-drawn element ID sets, plus the per-model appearance overrides, private so subclasses can't reach around the public API anymore. The always-drawn and never-drawn sets stay available as public read-only properties right on the base class. The backing fields for per-element overrides, subcategory overrides, visible subcategories, and per-model subcategory overrides should stay accessible to subclasses like before.
