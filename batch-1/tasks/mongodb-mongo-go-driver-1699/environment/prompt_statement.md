I'm working on the MongoDB Go driver and hit a real perf problem with logging. Right now whenever we convert a BSON document, array, or value to a string, we always build the full Extended JSON representation, and for huge documents (hundreds of thousands of keys, multi-megabyte string values, giant arrays) that's brutal on CPU and memory even though we only ever log the first few hundred bytes. So I want bounded stringification.

Basically I need a method on the document, array, and value types in the core BSON package that takes a byte-length limit and returns the Extended JSON representation truncated to at most that many bytes. When the limit is zero or negative it should just give back an empty string, and when the full representation fits under the limit it should return the complete string unchanged. The whole point is generation should stop once we hit the limit instead of building the entire thing first.

Also I need a shared string-truncation helper in an internal package that handles multi-byte Unicode correctly, so it stops at the last complete character that fits within the byte width and never splits a character mid-way, and it must not append any ellipsis or suffix. Its width parameter should be a plain signed int (not uint or anything).

Oh and the logging package needs a function that formats a raw BSON document into a bounded string for command logging, replacing the current approach that stringifies the whole document and then truncates. That truncate-after-the-fact thing is exactly what causes the latency spikes on bulk inserts and big query results, so the new one should produce the log-friendly preview without generating the full representation first.
