I want to pull the gossipsub protocol implementation out of the networking library where it currently lives as an internal module and make it a standalone package of its own. Right now if anything needs gossipsub it has to compile the whole networking crate and reach types through a long nested module path, which is annoying, and it means I can't build or test gossipsub in isolation. I'd like it to be independently buildable and testable with all the existing tests still passing after the move.

So the gossipsub code should live in its own dedicated package separate from the networking library, and everything it does today (all functionality and tests) needs to keep working. Since it's now its own crate, the internal imports within the gossipsub code shouldn't reference the enclosing library's module hierarchy anymore, they should use the crate root as their base instead. Other components that depend on gossipsub, like the network service, should declare a direct dependency on the gossipsub package rather than getting at it through the networking library.

Oh and while I'm in there, there's an unnecessary dependency on an async runtime library that's only pulled in for a network address type. That type is already available in the standard library, so swap it over to the standard library equivalent and drop the async runtime dependency. The whole point here is better modularity, easier navigation, gossipsub tests runnable on their own, and a smaller dependency footprint.
