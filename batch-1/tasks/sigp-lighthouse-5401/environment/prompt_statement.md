I'd like to extract the gossipsub implementation from its current location as an internal module inside the networking library and turn it into its own standalone package. Right now, anything that needs gossipsub has to pull in the whole networking crate and reference types through a long nested module path, which is cumbersome. I'd like gossipsub to be independently buildable and testable as its own package, with all existing tests continuing to pass.

As part of this, internal imports within the gossipsub code should use the crate root as their base (since gossipsub is now its own crate), and other components like the network service should be able to declare a direct dependency on the gossipsub package rather than accessing it through the networking library. There's also an opportunity to remove an unnecessary async runtime dependency by switching to the equivalent type from the standard library for network addresses.
