I'm building out a snippet generation library that spits out HTTP client code for a bunch of languages, and Dart is the one glaring hole right now. Anyone doing Flutter or general Dart work can't get a ready-to-run example out of us, so I want to add a Dart HTTP client generator as a plugin alongside the existing ones. The idea is it takes a standard request description (URL, HTTP method, headers, query string params, cookies, request body, and optional basic auth creds) and returns a complete runnable Dart source file as a string.

It's gotta cover the usual HTTP patterns properly. GET and POST plus other methods, request headers where I filter out empty values and when there are duplicate header names I take the last one, query string params with proper URL encoding of special chars, cookies also URL-encoded, JSON bodies emitted as raw string literals, URL-encoded form bodies, multipart form data, and binary/raw content too. Basic auth should only show up when both a username and a password are actually provided, don't inject a half-filled auth block. Oh and empty collections matter: if there are no headers or no cookies I don't want empty dangling sections in the output, just skip them.

Edge cases need to degrade gracefully, so special characters in URLs, query params, cookies, and auth credentials should all be handled without breaking, and extremely long URLs shouldn't choke it either. Basically wire this up as a new language plugin the same way the other generators register, so it's discoverable in the library and produces valid Dart that someone could paste and run.
