I'm cleaning up the PowerShell extension's debugger attach flow and could use a hand. Right now when someone attaches the debugger to a PowerShell host process, the debug configuration resolver figures out which process and which runspace to use by dispatching to external VS Code commands that two separate standalone picker classes register. That bouncing through the command bus between sibling components makes the whole thing hard to follow and really annoying to test in isolation, so I want to pull it together.

What I want is to fold the process-picker and runspace-picker logic straight into the main debug session feature class as private methods, and have the debug config resolver just call those methods on itself instead of routing through external commands. Once that logic is absorbed, the two standalone picker classes should go away entirely.

The behaviors I need preserved: if no process id is specified, the feature prompts the user to pick a host process, and if they cancel, the attach gets aborted (debug session cancelled). Same deal for the runspace, if no runspace id is given it prompts using the resolved process ID, and a cancel aborts the attach. Oh and the constructor needs to register the relevant VS Code commands so that command substitutions in debug configs keep working, which means any tests that instantiate the feature more than once have to account for those commands getting re-registered. Basically I want the feature self-contained for the attach-to-process workflow so tests can stub the picker methods directly on the instance rather than intercepting the global command bus.
