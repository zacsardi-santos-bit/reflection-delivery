I'm working on our IAM MCP server and there's a big gap: it handles users and roles fine but has zero support for groups. That's a real problem because in AWS groups are how you manage permissions at scale, you attach policies to a group and drop users into it instead of wiring up permissions person by person. I want to add the full group lifecycle so operators can do this programmatically.

Specifically I need to list all groups in the account with optional filtering by a path prefix, and retrieve detailed info for a single group including its current members and its attached policies. Then create and delete groups, add and remove users from a group, and attach and detach managed policies to/from a group.

Couple things that have to stay consistent with the rest of the server. All the write operations (create, delete, add user, remove user, attach policy, detach policy) need to respect the existing read-only mode, so when someone tries to mutate anything while read-only is on it raises a clear error the same way the user operations already do. Error categorization also matters: a not-found error when a group or user doesn't exist, a conflict error when a group can't be deleted because it still has members or policies hanging off it, and a validation error when a policy isn't attachable.

Oh and for delete specifically I want a force option, so it automatically removes all members, detaches all managed policies, and deletes all inline policies before deleting the group itself, that way operators don't have to manually clean everything up first. This should bring groups up to the same level we already give users and roles.
