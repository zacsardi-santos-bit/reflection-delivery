I'm adding a new code action to the Gleam language server for the `use` shorthand expressions, you know the ones that let you write callback or continuation style code in a nice sequential way. Problem is newcomers (and honestly plenty of experienced folks too) often don't know what `use` actually expands to under the hood, and there's no editor tooling to help them see it. So I want an action that fires whenever the cursor is sitting inside a `use` expression and offers to rewrite it into the equivalent expanded form, which is just a plain function call where the remaining block after the `use` gets wrapped in an anonymous fn and passed as the last argument.

It needs to cover the common shapes: a `use` that calls a function with no arguments, one that already has arguments (those should be preserved as-is), a `use` with no bound variables, with a single bound variable, and with multiple bound variables where each one becomes a parameter of the generated anonymous function. Oh and bound variables with type annotations, keep the annotations on the params. Also nested `use` expressions matter, the action should apply to whichever one the cursor is currently inside, not automatically the outermost.

One thing to be careful about: don't offer the action at all when the `use` binds via complex destructuring like tuples or literal patterns, since those can't be expressed as simple anonymous function parameters. The code action logic lives with the rest of the language server actions, around `@compiler-core/src/language_server/engine.rs` and the code action module alongside it. This mostly helps people learn the semantics of the form and makes it easier to refactor or migrate that style when a plain call reads clearer.
