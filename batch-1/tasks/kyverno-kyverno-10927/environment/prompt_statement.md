I'm on the Kyverno policy engine and hit something annoying with global context references in cluster policies. If you create a policy whose rule has a global context entry with no `name` set (empty or just missing), the API happily accepts the resource and only spits out a warning. That's wrong, the name should be treated as required and a policy without it needs to get rejected outright at admission time with a clear validation error, not silently saved.

The root cause looks like a serialization thing. When the name is absent it doesn't show up in the serialized form at all, so the schema-level validation never gets a chance to catch it. I want the name to always be present in the serialized representation even when it's empty, so the schema can actually enforce it. Once that's in place, submitting a policy with an empty or missing global context reference name should fail with an explicit error that identifies exactly which field is missing and says it's a required value.

So basically: no partially-configured policy should be quietly accepted anymore. Admins shouldn't have to wait for runtime failures to find out the config is broken, they should get immediate actionable feedback at the point they apply the policy.
