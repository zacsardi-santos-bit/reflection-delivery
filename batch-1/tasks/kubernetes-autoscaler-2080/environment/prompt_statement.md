I'm working on the Vertical Pod Autoscaler and noticed a gap in how recommendations are applied: the admission controller respects container-level resource constraints from limit ranges, but it completely ignores pod-level limit ranges. In clusters where administrators have set pod-level resource minimums or maximums, this means VPA can produce a set of per-container recommendations that are each individually fine but whose sum violates the pod's overall resource policy.

I'd like to fix this so that after computing per-container recommendations, the system also checks whether the aggregate resources across all containers in the pod comply with any pod-level limit range in the namespace. If the total would exceed the pod-level maximum, the per-container recommendations should be scaled down proportionally to fit. If the total would fall below the pod-level minimum, they should be scaled up proportionally. The adjustment should cover both CPU and memory.

To support this cleanly, the interface used to look up limit range information should expose a separate method for querying pod-level constraints, distinct from the existing method for container-level constraints. All existing implementations of that interface (including the no-op variant) should be updated accordingly.
