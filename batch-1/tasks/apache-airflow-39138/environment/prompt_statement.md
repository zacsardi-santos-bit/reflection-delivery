I'm adding a priority DAG file parsing feature to Airflow because right now when I tweak a DAG file I have to wait for the processor to cycle through everything (alphabetical, random, or mod-time order) before it picks up my change, and there's no way to say "parse this one first." I want a REST API endpoint that lets authorized users submit a request to re-parse a specific DAG file with priority. It should take an encoded file path, validate that the file is actually a registered DAG file and that the requesting user has edit permissions on the DAGs contained in it, and then record the request in the database so the processor can act on it.

Error handling matters here: if the file isn't recognized as a known DAG file, return a not-found response, and if the user lacks the needed permissions, return a forbidden response. Also duplicate submissions of the same file path shouldn't blow up, just handle them gracefully and still return success.

On the processor side, at each processing loop iteration it should check for any pending priority parsing requests and move those files to the front of the parse queue so they get processed ahead of the others, then clean up those request records after each loop so the table doesn't accumulate stale rows. Oh and since the processor manages its own cleanup lifecycle for that table, it needs to be excluded from the general db cleanup / maintenance utility too. The whole point is giving operators fast feedback on individual DAG changes without waiting through a full cycle.
