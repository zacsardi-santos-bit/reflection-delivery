I'm adding container query support to our pattern system and it's kind of a mess right now because there's no built-in way to declare an element as a container, so devs have to hand-write the CSS props every time. Container queries let elements respond to their containing element's size instead of the viewport, which makes components actually portable no matter where you drop them, and I want first-class DX for that just like we have for viewport breakpoints.

So I want a new built-in preset pattern that creates a container query context. It should take an optional container name and an optional container type, and the type should default to inline-size since that's what everyone reaches for. It needs to work both as a plain function call and as a JSX component. The generated CSS should set container-type and container-name with proper utility class names.

The important bit: when you give the container a name, our responsive shorthand (the at-sign/name/size syntax) should generate a correctly scoped container query rule in the output, not a plain viewport media query. Also the utility property types need a container name property typed to accept values from the container names token category, plus raw CSS values when strict mode is off.

Oh and one more thing that's actually annoying me, the at-rule sorting logic handles media queries fine but doesn't sort container query at-rules properly, so their ordering in the generated CSS is inconsistent right now. Container queries should sort the same way media queries do: non-container styles first, then min-width container queries ascending, then max-width ones after. Fix that so the cascade is predictable.
