I'm hitting a nasty bug in BAML's streaming partial deserializer when my output schema has array fields typed as a union of a few different object shapes. Like say I've got an output class with two array fields, and each array can hold items that are one of three distinct class types (each with its own set of fields), the deserializer just falls over or spits out wrong results even though the JSON I'm feeding it is totally valid and complete.

Digging in, it looks like when the deserializer needs to figure out which fields are required and which should be null-filled for each array element, it's consulting the field's declared union spec instead of the item's actual concrete type. A union isn't a concrete class so you can't look up field definitions on it, which is why it blows up. What I want is for it to look at each item's real type and resolve field requirements against that concrete class.

So the fix: for every element in these array fields, deserialize it according to its own concrete type's field schema. Fields present in the input stay preserved, fields missing get filled with null based on the resolved class (not the union). Oh and mixed-type value arrays nested inside those objects (stuff like arrays that hold strings, ints, or floats) need to survive too. End result, all items across all arrays show up in order with the right structure. Right now this makes streaming unreliable for any schema using unions in collections, so I really need it correct.
