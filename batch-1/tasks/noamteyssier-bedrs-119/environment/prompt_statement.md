I'm working in this genomic interval crate and it's got solid trait infra and low-level primitives, but there's nothing that maps directly onto the standard BED format column variants that bioinformatics folks actually reach for. I keep having to roll my own or bend the lower-level types to get BED3, BED4, BED6, and BED12 shapes, which is just friction. I'd like proper named structs for each of those.

The 3-column one should hold chromosome, start, and end. The 4-column one adds a name on top of that. The 6-column adds score and strand. And the 12-column should cover the full BED spec, so thick start/end coordinates, an item color, and the block info (block count, sizes, starts). Each of these should be constructible by just passing the relevant fields straight in, and then expose those fields back through accessor methods so you can read them out cleanly.

Also they all need to implement the library's existing coordinates trait so they slot into the rest of the functionality naturally, nothing special-cased. And importantly I want all four importable directly from the crate root (`@src/lib.rs`), so users don't have to go digging through module paths to find them. Basically it should feel immediately usable for standard workflows without having to understand the internal generics up front.
