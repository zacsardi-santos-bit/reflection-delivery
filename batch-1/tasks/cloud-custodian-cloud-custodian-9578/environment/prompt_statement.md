I'm trying to write Cloud Custodian policies for our AWS MemoryDB clusters, but I'm running into a wall — the MemoryDB resource type doesn't support the network and encryption filters I need. Specifically, I want to be able to filter clusters by the security groups they're attached to, by the subnets they live in (resolved through the subnet group association), and by the KMS key used for encryption (matching on key alias names). I also need the network-location filter so I can compare tags between MemoryDB clusters and their subnets to detect mismatches.

Right now, none of these filter types are available on the MemoryDB resource, even though they work fine for other database resource types like ElastiCache or RDS. Could you add support for these four filter types to the MemoryDB resource? The subnet filter is a bit tricky because MemoryDB clusters don't store subnet IDs directly — they reference a subnet group, which in turn lists the subnet identifiers. So the subnet filter needs to resolve the subnet group to find the actual subnets. It would also make sense to expose the MemoryDB subnet group as its own queryable resource type so the subnet filter and network-location filter can work correctly.
