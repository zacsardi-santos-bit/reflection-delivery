I'm reworking how change events get delivered in our collaborative document library, and the current shape is fighting me. Right now when something in a doc changes, the event object dumps a single container's diff, path, and identity straight onto the top level, so if one commit touches multiple containers I can't see all those changes together in a single callback. I want the event to instead carry an ordered list of all the container-level changes that came out of that commit, so I can just iterate over each one and handle them as a batch. Each entry in that list should expose the target container's identity, the path to that container, and the diff for that container.

There's also a cleanup I keep bumping into. Today the document-level contextual metadata, stuff like whether the event came from a time-travel checkout or was generated locally as a local change, gets mixed into a property that also holds container data, which is genuinely confusing. I'd rather that metadata live under its own dedicated property on the event, cleanly separated from the per-container entries.

On the TypeScript side, the exported event type needs to be updated to reflect this new batched shape and renamed to match, so the type system actually says "each event can carry multiple container diffs" instead of pretending it's one. The type should describe the list of container-level diff entries plus the separate metadata property.

The point of all this is that subscribers shouldn't have to work around the API to deal with multi-container commits. With the batched shape I can process everything from one commit atomically in a single callback, and the document-level context stays clearly distinct from the individual container diffs.
