I'm working with this collaborative document library and I want to restructure how events are delivered to subscribers. Right now, when something changes in a document, the event object only exposes a single container's diff and path directly on the top level — which means if a single commit changes multiple containers, I can't easily see all those changes in one callback. I'd like the event object to instead carry a list of all the container-level changes from that commit, so I can iterate over each one and handle them together.

There's also a cleanup I'd like: the document-level contextual metadata — things like whether this event came from a checkout or was generated locally — should live under a dedicated metadata property on the event rather than being mixed into a property that also contains container data.

On the TypeScript side, the event type should be updated to reflect this batched shape and renamed accordingly, so that the type system accurately represents that each event can carry multiple container diffs. The per-container entries in the events list should expose the target container identity, the path to that container, and the diff for that container.
