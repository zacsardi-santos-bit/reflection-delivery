I keep running into this annoying pattern where I've got some traversal or pipeline logic that hits external stuff (reading files, fetching over the network, querying a db) and I end up writing it twice, once sync and once async. It's error-prone and a pain to keep the two in sync. What I want is a way to write the core logic once as a generator that yields at each point where an external operation is needed, and then have a driver take care of resolving those yielded values and pushing the results back in until the generator's done.

So I need two named exports living in a new module at `packages/trampoline/src/trampoline.js`. One's a synchronous driver that takes a generator function plus a sync callback plus any extra args (forward those extra args along to the generator), drives it by feeding each callback result back into the generator, and returns the final value directly. The other's an async driver, same deal but the callback can be sync or async, it awaits each callback result, and it returns a promise resolving to the final value.

Error handling matters here too: if the callback throws or rejects, I want that error thrown back into the generator so the generator's own try/catch can deal with it, don't just blow up the driver. Oh and recursive generator delegation (yield*) has gotta work, since the whole point is I'm using this for walking dependency graphs where traversal is naturally recursive.

The nice thing is the generator itself doesn't change at all between the sync and async cases, you just pick which driver to call and hand it the right kind of callback (sync file reads in tests, async in prod, that kind of thing).
