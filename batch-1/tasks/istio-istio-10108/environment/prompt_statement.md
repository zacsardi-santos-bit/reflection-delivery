I'm hitting a bug in how Istio's Pilot handles route discovery for Envoy proxies and it's biting us on gateways. When a global config push fires, the control plane sends every available route to every connected proxy instead of just the routes each connection actually subscribed to. So if a gateway subscribes to a single route, a global push should hand back only that one route, but right now it dumps everything, which wastes bandwidth and violates the RDS protocol contract. I need subscriptions tracked per-connection and respected on every push, and when a proxy switches its subscription from one set of routes to another, the response should carry only the new set, not the union or the old stuff.

There's also a nonce problem in the ack protocol. When Envoy sends back an acknowledgment token (nonce) that doesn't match the last one the server sent, that request is stale and should be silently ignored, not processed. And there's the protocol-error case where a proxy sends a response carrying the last sent nonce but with no route names at all. Right now that can wedge the connection so later fresh route requests never get served. Instead I want the server to log the error and keep going, so subsequent fresh subscription requests from that same connection still get answered normally. So basically: filter pushes by per-connection subscription, detect and ignore stale nonces, log protocol errors without breaking future responses, and return only the updated set when a subscription changes. This all lives in the RDS push path of the discovery server, oh and the nonce tracking is what ties the ack handling and the push filtering together, so make sure both use the same last-sent-token state per connection.
