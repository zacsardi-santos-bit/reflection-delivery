I'm running into issues with how Istio's control plane handles route discovery subscriptions for Envoy proxies. When a global configuration push is triggered, it seems like the control plane sends all available routes to every connected proxy instead of only the routes each proxy subscribed to. For example, if a gateway proxy subscribes to just one route, a global push should only return that one route — but currently the server doesn't seem to respect per-connection subscriptions during push.

There's also a problem with how the server handles the nonce-based acknowledgment protocol. When an Envoy proxy sends back an acknowledgment token that doesn't match the last one the server sent, that request should be treated as stale and ignored. And when a proxy sends a protocol error signal — a response carrying the last sent token but with no route names — the server should handle it gracefully, log the issue, and continue serving. Right now, connections can get into a state where subsequent fresh route requests are not served after a protocol error.

The fix needs to ensure that: route subscriptions are tracked per-connection and respected on every push; stale acknowledgment tokens are detected and ignored; protocol errors are logged and do not prevent future route responses; and when a proxy changes its subscription from one set of routes to another, only the new set is returned.
