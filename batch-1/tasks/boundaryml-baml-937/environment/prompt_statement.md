I'm working with BAML's TypeScript code generator and I've noticed that the generated TypeScript client files have their linting suppression comments in the wrong order. The comment that suppresses ESLint errors is currently placed at the end of the suppression block in the file header, after the TypeScript skip-checking directive. Since linting tools process files from top to bottom, this means the ESLint suppression isn't active when the TypeScript directive is encountered, which causes spurious linting errors in otherwise auto-generated code that should be fully suppressed.

The fix should reorder the comments so that the ESLint suppression comes first in the header block, before all the other lint and type-check suppression directives. This needs to be consistent across all generated TypeScript client files.
