I'm working on the staking precompile in Sei chain and there's a gap I keep hitting. Right now it only lets you delegate, redelegate, and undelegate tokens through the EVM, but there's no way to register a new validator or edit an existing one's settings from the EVM side. Operators who want to manage their validator infrastructure entirely through EVM tooling are stuck dropping down to separate native transactions, which is annoying and makes the precompile feel incomplete.

So I want to add two new operations. The first lets a caller create a validator by passing a consensus public key in hex format, a display name (moniker), commission settings (the rate, max rate, and max daily change rate), a minimum self-delegation amount, and an attached funding value for the initial self-delegation. On success the validator should show up in the staking module queryable with the moniker I gave it. The second operation lets an existing validator's operator update the display name, commission rate, and minimum self-delegation. Passing an empty string for the commission rate leaves it unchanged, and passing zero for the min self-delegation leaves that unchanged too. An edit must never touch the operator address or the consensus public key, and it should only change fields I explicitly provided while leaving everything else intact.

Both operations need solid input validation with specific, descriptive errors. So invalid hex for the public key, a missing funding value/amount, commission values that won't parse, zero self-delegation, and trying to edit a validator that doesn't exist should each produce their own clear message. Also both require the calling address to be linked to a native chain address, and if it's not linked the caller needs a clear error about that. The precompile logic lives under `@precompiles/staking`, so the new create and edit paths plus their validation and error strings go there alongside the existing delegate/redelegate/undelegate handling.
