I'm working in the IoTeX core codebase and I want to add a second embedded storage engine as an alternative backend under the key-value store layer. We only support one engine right now, but I'd like an LSM-tree-based option I can swap in without touching any of the application code that reads and writes data. The whole point is that different workloads favor different engines, so operators should be able to pick the one with the best performance profile for their deployment without changing any read/write logic upstream.

I need a new constructor that builds a db instance backed by the alternative engine, and it should take the same config struct the existing backend uses (the one with a path to the database directory). It's gotta implement the full set of ops: open and close the database, read a value by namespace and key, put a value, delete a key, write a batch atomically, do a range-filtered scan over a namespace, and iterate over all entries in a namespace.

Some behaviors I care about specifically. Reading a nonexistent key (or nonexistent namespace) should come back with a recognizable typed "not found" error. Writes need to work including overwriting existing values and creating new namespaces on demand. Deleting a key should be idempotent, so deleting one that isn't there just succeeds silently, no-op. Batch writes must apply all operations together atomically and dedupe entries for the same key with last-write-wins when the same key shows up more than once in one batch. The range-filtered scan returns only the key-value pairs whose key falls within an inclusive range and also satisfies a caller-supplied predicate, and if nothing matches (including when the namespace is empty or doesn't exist) it needs to signal that same "not found" condition. Full namespace iteration though should succeed with no entries and no error when the namespace is empty or nonexistent, don't error there. Oh and keys from one namespace can't leak into another even if the raw key bytes are identical, so namespace isolation matters.
