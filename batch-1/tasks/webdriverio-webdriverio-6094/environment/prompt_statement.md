I'm cleaning up how browser launch options get configured in the devtools package over in the WebdriverIO monorepo and it's kind of a mess right now. The problem is that devtools-specific stuff like headless mode, ignoring the default browser args, and viewport size all have to go in different spots depending on which browser you're driving, sometimes inside the vendor's own capability namespace (like the chrome or firefox options blob) and sometimes at the top level of the capabilities object. It's inconsistent and it makes it hard to tell what's a real standard WebDriver capability versus a devtools-only launch option.

So what I want is a dedicated capability namespace just for these WebdriverIO devtools options, so folks can group them all in one place no matter the browser. At minimum it needs to support turning on headless mode, overriding or ignoring the default browser arguments (either as a boolean flag that ignores all the defaults, or as a list of specific args to skip), and setting a default viewport size. And anything set in this new namespace should win over the same setting living in a vendor-specific namespace, so the dedicated one takes priority.

Big thing though, don't break existing behavior. People who currently drop these settings into vendor namespaces or at the top level of capabilities should see zero change, it all still works exactly like before for backward compat. This is really about making the config API consistent and predictable across every supported browser and separating our internal launch config from actual WebDriver caps.

Oh and while you're in there, there's a small naming nit to fix. In the command descriptor type there's a field that holds a single spec reference URL but it's currently named in the plural form, so rename it to the singular so it actually reflects that it's just one URL.
