I'm trying to write offline unit tests for code that spins up and manages SageMaker HyperPod Clusters, but our moto-style AWS mock doesn't back any of the cluster APIs yet, so every cluster call just blows up with no implementation behind it. I need the mock SageMaker service to cover the whole cluster lifecycle so I can test this stuff in CI without real AWS creds.

Concretely I want CreateCluster to accept a cluster name, one or more instance groups (each carrying an instance count, instance type, lifecycle config, execution role, and threads-per-core), a VPC config, and optional tags, and return the cluster ARN. DescribeCluster by name or ARN should give back status (should read as InService right after creation), the instance group details, and the VPC config. DeleteCluster should remove it and a later describe should raise a proper not-found error (ResourceNotFound style). ListClusters should return everything with filtering by a name substring plus sorting by name ascending or descending.

For nodes, DescribeClusterNode by node id should return that node's status, instance type, lifecycle config, and threads-per-core, and ListClusterNodes should list nodes across all instance groups with optional filtering by instance group name substring. Each node id should be predictable, derived from the group name and a zero-based index.

Tagging needs to work end to end, oh and both tags passed at creation and tags added later via the tagging calls should show up when I list tags on the cluster ARN. Also enforce the real validation rules: creating a second cluster with an existing name gives a resource-already-exists error, and a lifecycle config whose source storage path doesn't start with the expected prefix gives a validation error. Lastly, clusters created with tags should surface through the Resource Groups Tagging API when filtered to the sagemaker service, with the cluster ARN and its tags appearing in the results.
