I'm adding namespace-scoping to the IP pool logic in OpenELB and could use your help. Right now every EIP is available to services in any namespace, which means I can't hand teams their own dedicated IP ranges, and there's no priority mechanism when more than one pool could satisfy a request. What I want is for an IP pool to be configurable so it only serves specific namespaces, either by listing namespace names directly or by giving label selectors that match namespace labels. When multiple pools match the same namespace, pick the one with the lowest priority value. I also want to mark a pool as a cluster-wide default so it acts as a fallback for services that don't match any namespace-restricted pool.

Separately there's a couple of bugs to clean up while I'm in here. The IP allocation record currently carries a protocol field, but the protocol's already tracked on the pool itself, so storing it on the allocation record just creates artificial mismatches that block otherwise valid IP assignments. I want that field removed from the allocation record and no longer used to filter or reject allocation requests. Also there's a case where a service that already has an active IP allocation is being deleted but the release doesn't fire, the system returns nothing (a no-op) instead of a release record for the existing allocation, so that needs fixing to actually return the release record. Oh and when checking whether an IP falls within a pool's address range, if you pass an empty or invalid IP address it should just return false rather than doing something weird.

The why here is network isolation, admins can't enforce per-team boundaries today, so this lets them carve out dedicated ranges per namespace while still keeping a sensible default for unconstrained services.
