I'm hitting a wall with our internal JSON path evaluation library. Right now it can walk to specific named fields and count elements, but that's basically it, there's no wildcard, no numeric array indexing, no aggregation, and it's making a bunch of queries impossible to write.

Concrete example: I've got nested objects, like a map of items where each entry has a "stored" count, and I want to grab that count from every sub-object without knowing the key names up front. Can't do it in one path expression today. Same deal with arrays, I need to pull an element by position (say the first one), and I also want to sum numeric values that are spread across multiple keys in an object.

So here's what I want added. A wildcard operator that fans out across all values in an object or array in one step, no need to know keys ahead of time. It should chain with further path segments too, so wildcard-then-field pulls that field from each matching entry and hands back the collected values as an ordered list. Multiple wildcards in a row should work and give me a flat list of everything matched. Oh and when wildcards produce nested collections they should get flattened automatically into a single list rather than staying nested.

I also need zero-based numeric indexing into arrays via a numeric path segment, and a sum function that aggregates all the numeric values in the current object or array into one total.

One important thing for determinism: when the wildcard fans out over map entries, the results have to come back in a consistent order, alphabetical by key, so I get the same output regardless of however the map happens to be ordered internally. Without this stuff callers are stuck manually iterating and aggregating themselves, which kind of defeats the whole point of a path library, especially when keys are dynamic or I'm summing distributed counts.
