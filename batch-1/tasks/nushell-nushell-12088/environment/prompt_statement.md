I'm working on the nushell plugin system and need to improve how plugin custom values are represented internally. Right now, the custom value type stores its type name, binary payload, and plugin source as directly accessible public fields, and all the code that creates these values uses struct literal syntax. This makes it hard to add new fields without touching every construction site across the codebase.

I'd like to refactor this so that construction goes through a proper constructor function rather than struct literals, and the internal fields are accessed through getter methods. I also need to add a new boolean flag to track whether the plugin wants to be notified when the value is dropped, with a corresponding getter method. When this drop notification flag is set, the system should ensure the plugin receives a notification (like printing a message to stderr) when the value goes out of scope — and this notification should fire exactly once even if the value was copied or shared multiple times.

Additionally, I'd like the plugin custom value type to participate in standard nushell data operations: users should be able to navigate into them using cell paths (both by numeric index and by string key), sort collections of them, and concatenate them with the append operator.
