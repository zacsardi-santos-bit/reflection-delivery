I'm working on Prebid Server and there's a gap in the setuid endpoint (the thing that handles cookie syncing for user identification across ad exchanges) where it does zero account-level validation right now. So if a host operator disables a publisher account, setuid still happily processes cookie sync requests for that account as if nothing happened, which means deactivated publishers can keep triggering user syncing on their behalf. Not great, since host operators need to be able to turn off a publisher and have that stick everywhere, including this flow, otherwise a disabled account can still influence user tracking and undermine the host's control over publisher relationships.

What I want is for the setuid handler to look up the account named in the request and check whether it's active before doing anything. If the request comes in with an account identifier for a valid, active account, it should process normally and return a successful response like it does today. But if the account's been disabled, I want it to bail out with a 400 Bad Request and an error message telling the publisher the account is disabled and to contact the host.

One structural thing to make this work: the setuid endpoint currently only gets handed the host cookie portion of the config, but it needs the full server configuration so it can do account lookups using the same account service the other endpoints already use. That's really the point here, aligning setuid with the account validation the rest of the system already enforces so account status gets applied uniformly across all endpoints.
