I'm reworking the value-source system for flags in our Go CLI library and the current design is too limited. Right now a flag holds multiple sources (env vars, files) it checks when resolving its value, but the lookup only hands back the value plus a plain string label, so there's no way to get a reference to the actual source object that resolved things. I want to trace exactly where a value came from when several sources are configured.

So here's what I'm after. I want a public interface that source types satisfy, with a human-readable String method and a Go-syntax GoString method for debug output, plus a lookup method that returns the value and a found boolean. Then a chain type holding an ordered list of these sources that supports a basic lookup (value and found) and an extended lookup that also returns which source in the chain actually provided the value.

The helpers that build chains from a list of env var names or from file paths should return this chain type directly so they can be assigned straight to a flag's sources field without wrapping, and the file-path helper needs renaming to line up with the env-var helper naming.

Oh and the internal source structs for env vars and files should be unexported with clearly named fields instead of the current public string-based types. When a flag can't parse a value that came from an env var, the error message should call out the value, the expected type, the env var name, and the flag name. Also update the flag type's sources field to use the new chain type instead of the old slice, and fix up all the existing test usages to match. This should clean up the API consistency and give us proper debug formatting too.
