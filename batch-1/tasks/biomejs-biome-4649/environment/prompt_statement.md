I'm cleaning up how our linter deals with suppression comments and there are two behaviors that are just wrong right now. First problem: when a file already carries a file-wide suppression that turns off a specific rule for the whole file, and there's also a range suppression (a start/end pair) aimed at that same rule, the linter happily treats the range suppression like it's doing something. It isn't, it's totally redundant, and nobody gets told. I want those redundant range suppressions flagged as unused warnings, with a message that says it has no effect and a note pointing back to the file-wide suppression that's already handling that rule so the dev knows where the real coverage is coming from.

Second problem: if a file-wide suppression comment shows up somewhere other than the very top of the file, we currently warn about the misplacement but then still silently apply it, so the targeted rules stay suppressed as if the comment were fine. That's misleading, people think their code is being checked when it's actually not. A misplaced file-wide suppression should truly do nothing, so the lint violations it was trying to hide need to be reported as real errors, each misplaced comment should still produce its own misplacement warning, and the command has to exit with a non-zero error status instead of quietly succeeding. Both of these matter because otherwise folks leave dead suppression comments lying around or believe checks are running when they aren't. Fixes go in the linter's suppression handling logic.
