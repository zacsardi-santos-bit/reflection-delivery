I'm hitting two bugs with the crate that turns my Rust structs into TypeScript type defs, and both make the output wrong.

First one is tuple structs. On a normal named struct I can slap the optional and optional-nullable annotations on individual fields and they show up correctly in the generated TS, but the moment I try the same on a tuple struct's positional elements nothing happens, they just get ignored. Same deal with the struct-level settings that are supposed to apply optionality to every eligible field, works for named structs, does nothing for tuple ones. What I want is for tuple struct elements marked optional to come out as optional elements in the TS tuple type, and the optional-nullable ones to be both optional and nullable, and I want the struct-level settings to flow into tuple structs the same way they do for named structs while still respecting any per-element overrides I put on top.

Second thing is about the serialization compat feature (serde-style skip attributes). It already honors some of those annotations, but it doesn't catch the case where a field is set to skip during serialization, whether that's always or conditionally, and also has a default value. When both of those are true the field can just be absent from the serialized output, so the generated TS type ought to mark it optional, and if the field's type is an optional wrapper it should be nullable too. Right now it stays required which is wrong and blows up on the TS side when the value's actually missing. Oh and I need escape hatches: a per-field override to force a field non-optional even when the skip+default inference would say otherwise, and one to force it optional-but-not-nullable even when the framework would infer nullable. Explicit per-field overrides should win over both the struct-level settings and the serialization-inferred behavior. Also I want a struct-level switch to turn the automatic inference off for the whole struct, and when that's off individual fields should still be able to re-enable it for themselves.

Everything lives in the type-generation crate that reads these attributes off the struct definitions, so the fixes go there.
