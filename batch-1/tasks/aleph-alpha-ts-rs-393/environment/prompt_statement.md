I'm using a library that generates TypeScript type definitions from my Rust structs, and I've run into two problems that result in incorrect TypeScript output.

The first issue is with tuple structs. I can annotate individual fields in a regular named struct to make them optional or nullable in the generated TypeScript, but when I try to do the same thing on a tuple struct's positional fields, nothing happens — the annotations seem to be ignored. The same goes for struct-level settings that should apply optionality behavior to all eligible fields: they work fine for named structs but have no effect on tuple structs. I'd expect the generated TypeScript to properly encode optional tuple elements as optional and optional-nullable elements as both optional and nullable.

The second issue involves how the library handles serialization-skipping annotations from the serialization framework. When I mark a field to be skipped during serialization and also give it a default value, that field may be absent from the serialized output — so the TypeScript type should reflect that the field is optional. Right now the library doesn't infer this, so the generated TypeScript type says the field is required even though it might never appear in the actual data. I'd also want the ability to override this automatic inference: I should be able to explicitly force a field to be non-optional even if the serialization annotations would suggest otherwise, or force it to be optional-but-not-nullable even if the framework would infer nullable. There should also be a way to disable the automatic inference for an entire struct while still allowing individual fields to re-enable it.
