I'm hitting a really annoying determinism bug with the job scheduler in my Go app. When I grab the full list of scheduled jobs via the method that returns all of them, the order isn't stable across calls. Like if I call it twice back to back without touching the scheduler at all (no adds, no removes, no modifications in between) I sometimes get the jobs back in a different sequence each time. I'm pretty sure it's because internally the jobs are held in something with non-deterministic iteration order (a map, probably), so every retrieval just spits them out in whatever order the runtime feels like.

The thing is this makes it basically impossible to build any reliable logic on top of it. I want to retrieve all jobs, stash the result somewhere, retrieve them again later, and be able to compare the two slices for equality and actually trust the answer. Right now that comparison is flaky even though nothing changed, which breaks anything downstream that assumes repeated calls give predictable results.

So what I want is for the retrieval method to return jobs in a stable, deterministic order every time. Two consecutive calls with no changes in between should always come back in the exact same order so the returned slices can be treated as equal. Can you sort them by something consistent before returning so the ordering holds no matter how they're stored under the hood?
