I'm hacking on the C# frontend for Joern and the type names in the generated code property graph are all over the place. Primitive types like int and string get stored as their short C# aliases instead of the fully qualified .NET names (System.Int32, System.String, that kind of thing), but the parameter types on those same nodes are already fully qualified, so there's this annoying mismatch. I want everything to be consistent, method return types, call node types, method signatures, identifier types, all of it should use the fully qualified names everywhere in the graph. Right now writing queries is painful because I have to account for both representations of the same type.

While I'm in here a couple related things bug me too. Nullable types declared with a `?` annotation are keeping the nullable marker in the recorded type name, so I can't easily match the base type regardless of nullability, drop the marker. Also generic collection types are embedding their type parameters in the name, I just want the base name without the generic args stuffed in there.

Oh and there's a real bug with inherited method calls, when a subclass calls a method defined on its parent with no explicit receiver, the class hierarchy is being walked wrong and the computed full method name comes out wrong, so call graph edges end up pointing at the wrong fully qualified method. Need that resolution fixed so it points at the right one.

Last thing, the API that processes AST generator results currently makes callers build and pass a separate type-mapping object as an explicit arg. I want to kill that dependency so callers just hand over the list of parsed files plus the config, and type resolution happens internally instead of being coupled to callers.
