So I'm deep in the guts of our distributed object storage stats pipeline and we recently moved to a MySQL-backed stats store that uses structured typed objects instead of the old generic snapshot blobs. Problem is we don't have an aggregation component that speaks these new types yet, the existing logic is still coupled to the older snapshot format and just can't work with them directly.

What I want is a new cluster aggregator class that takes a map of per-instance storage stats wrappers (keyed per cluster instance/host) and spits out two aggregated results. First is a raw combined view that just sums all the raw data from every node in the cluster. Second is a valid selected view that picks the best replica's data per partition. The selection logic should prefer the replica with larger physical storage usage when both replicas reported within a close time window, but if one report is significantly more recent than the other (past a configurable time-difference threshold) then use the more recent one regardless of size. And stale/outdated nodes get excluded from the valid aggregation entirely, they shouldn't pollute the valid view.

This has gotta work for both account-level storage stats (organized by partition, then account, then container) and partition class storage stats (organized by partition class name, then partition, then account, then container).

Oh and there's a related bug I need fixed too. The partition class storage stats object currently forces you to pass a data map to its constructor, so any code that just wants an empty instance has to hand it an empty placeholder, and that's causing null-related errors whenever we try to make an empty one. I need a no-arg constructor that inits to an empty state, plus a copy constructor that deep-copies an existing instance. Without these the MySQL aggregation path can't produce the structured results downstream consumers expect, and the empty-instance code path just blows up.
