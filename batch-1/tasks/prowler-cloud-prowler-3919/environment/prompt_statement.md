I'm adding AWS Lightsail support to Prowler because right now it doesn't scan any Lightsail stuff at all, no service integration and no checks, so teams running Lightsail (simplified VMs, managed relational databases, and static IPs) have a total blind spot in their audits and misconfigs slip through.

I need a full Lightsail service module that discovers three resource types (instances, managed databases, static IP addresses) from the relevant AWS APIs and models them with proper data structures. For instances I want to track networking ports including whether each port is public or private, whether automated backup snapshots are on (derived from the instance's add-ons config), and the instance's IP addresses. For databases I need to know if public access is enabled. For static IPs I need to know whether they're currently attached to an instance and which one.

On top of that, four checks. First, flag any database configured to allow public internet access, pass when it's restricted. Second, flag any instance without automated snapshots enabled since missing backups risks data loss. Third, flag any instance that has a public IP and at least one network port open to the public, and report the list of exposed port numbers, while instances with no public IP or no public-facing ports pass. Fourth, flag any static IP that's allocated but not attached to anything, and when it is attached include the instance name in the passing result.

Each check needs clear human-readable status messages for both pass and fail, following the conventions other Prowler checks use, reporting resource ARN, resource ID, tags, and region. Oh and static IPs don't carry tags so those checks should report an empty tags list. Point is to keep security posture consistent across all AWS workloads including Lightsail.
