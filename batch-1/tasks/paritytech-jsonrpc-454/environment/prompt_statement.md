I'm using a JSON-RPC library that has a derive macro for defining RPC traits. Right now I can only define methods that return a result, but JSON-RPC 2.0 also has notifications — fire-and-forget calls where the server doesn't send any response. I'd like to be able to declare notification handlers directly in the RPC trait by just writing a method with no return value, and have the macro automatically treat it as a notification handler.

The expected behavior is: if someone sends a request without an `id` field to a notification handler, the server processes it silently and returns nothing. But if someone sends a request with an `id` field to a notification endpoint (treating it like a regular method call), the server should reject it with a "Method not found" error. Notification handlers should also be compatible with traits that include pub/sub subscriptions.
