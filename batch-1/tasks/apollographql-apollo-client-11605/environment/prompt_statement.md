I'm trying to write integration-style component tests that exercise the full Apollo Client data-fetching stack without standing up a real server, and right now I'm stuck because the existing test helpers only mock at low network levels and skip too much of the actual client behavior. What I want is three testing utilities that work together, all exported from the testing package so consumers can actually import them.

First one takes a GraphQL schema and auto-fills placeholder values for every scalar field so I don't hand-write every resolver, and custom scalars (dates, say) can supply their own placeholder. The mocked values should stay consistent across repeated queries on the same schema instance.

Second wraps that mocked schema and lets me layer custom resolvers on top of the defaults, where any field the custom resolver doesn't cover falls back to the scalar defaults. This one needs forking, so I can create an isolated copy for a single test without touching the original. It's gotta be additive too, meaning there's a method to add resolvers incrementally over time, and when I fork, the fork inherits all those accumulated resolvers while the original stays unaffected by whatever the fork does.

Third intercepts the global network fetch during a test and routes GraphQL requests through my local schema instead of a real server, then restores the original fetch automatically when the test block exits. It should play nice with modern resource management so it cleans up via the standard language-level disposal mechanism. Also handle the edges: if a resolver throws a GraphQL error, propagate that back to Apollo Client as a proper GraphQL error, and if I accidentally pass an invalid object as the schema, surface a meaningful validation error as a GraphQL error in the response rather than crashing silently.

Point of all this is realistic component tests against the full link chain (queries, mutations, error handling, schema validation) with no backend infrastructure, so tests get faster and easier to isolate.
