I'm working on the Crossplane CLI and there's this gap that keeps biting our operators. Right now there's no built-in way to see CPU and memory usage for Crossplane-managed pods, so folks fall back on generic Kubernetes tooling and then have to manually figure out which pods actually belong to Crossplane (the core controller, providers, functions, extensions, whatever). It's tedious and error prone once you've got a busy cluster, so I want a focused subcommand under the beta group that shows the resource footprint of just the Crossplane bits.

What I'm after: a new package in the CLI that displays resource usage for all Crossplane-related pods in a given namespace as a clean table with columns for pod type, namespace, name, CPU in millicores, and memory in mebibytes. I also want an optional summary mode that aggregates things, so total pod count, per-type counts, plus total CPU and total memory across all the Crossplane pods.

Classification is by labels. Pods carrying labels in the Crossplane package namespace (keyed by component type) get identified by that type, and the core Crossplane controller pod (the one labeled as part of Crossplane) shows up as its own type. In the summary the type names should be printed with just the first letter capitalized and listed alphabetically.

Oh and I need a small helper that capitalizes only the first character of a string, returning the string unchanged if it's empty or if the first character isn't a letter (so no forcing digits or symbols through it). Wire up the classification, the table-printing, and the summary-printing logic together so the whole thing works end to end.
