I'm working on the Noir language server and I want to add code actions that help folks fix unrecognized identifiers. Right now when someone references a type or module that exists somewhere in the project but isn't in scope, the editor just shows an error and offers no way to fix it, which is annoying because Noir projects tend to spread types and modules across lots of nested submodules and there's no editor help, you have to manually look up the full path and either write the import or type out the qualified name yourself.

So here's what I want. When the cursor is sitting on an unrecognized type or module name, I want the language server to return two code actions. One imports the symbol, meaning it inserts the right import statement at the top of the file so the bare identifier becomes valid without any other changes. The other qualifies the reference in-place, replacing the bare identifier with its fully qualified path, which is all the containing module names joined together in order followed by the name itself. Both of these need to work for struct types and also for modules that live inside nested submodule hierarchies, not just top-level stuff.

The code action request handler should go in the standard location for LSP request handlers in the project (alongside the other request handlers under the lsp requests directory), and it's gotta wire into the existing language server state. Basically I want this to feel like what modern language servers do for other languages, so the dev experience is smoother.
