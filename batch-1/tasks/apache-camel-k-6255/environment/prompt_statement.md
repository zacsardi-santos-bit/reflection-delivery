I'm working on our Kubernetes integration framework and hit a wall with port config. Right now both the container config trait and the service exposure trait only handle a single primary HTTP port automatically, and there's no way to declare extra named ports. I want to add support for a list of additional ports on both traits so integrations can expose stuff on custom port numbers or non-TCP protocols, think an app listening on 8085 instead of 8080, or a UDP-based service.

The format I want is a simple semicolon-separated string. On the container side each entry gives a port name and port number, with an optional protocol that defaults to TCP when it's left off. On the service side each entry gives a port name, the external service port, the internal container port, and an optional protocol (also defaulting to TCP). These custom ports should be additive, so they show up alongside whatever ports the framework already wires by default, not replace them.

When the format's wrong I need it to fail loudly with a descriptive error, like if an entry is missing required fields, or the port number isn't a valid integer, the message should explain what went wrong and spell out the expected format so people can fix it.

Oh and one more thing, the activation logic for the service exposure trait needs updating too. Right now it only enables the service when the default HTTP exposure flag is set, but if someone's declared custom ports that should be enough on its own to turn the service on, even without that flag.
