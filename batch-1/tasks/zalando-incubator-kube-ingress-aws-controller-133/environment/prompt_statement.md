I'm working on a Kubernetes ingress controller that provisions Application Load Balancers on AWS, and right now the controller always pools ingresses together onto as few shared ALBs as possible to minimize the number of load balancers. Problem is there's no way to tell it that a specific ingress should get its own dedicated load balancer instead of sharing one, and some workloads really need that isolation for security, traffic management, or cost allocation reasons, so I want to add an ingress-level annotation that lets users opt out of the sharing behavior.

Here's what I'm after. The internal ingress representation needs to carry a boolean flag tracking whether sharing is enabled or disabled for that ingress. It should default to true (sharing allowed) when the annotation isn't present, so the normal grouping behavior stays the default. When the annotation is explicitly set to disable sharing, the flag flips to false and that ingress gets its own dedicated ALB exclusively.

The tricky part is the conversion between the Kubernetes ingress resource format and the internal representation, it's gotta read and write this annotation correctly in both directions so the value survives a roundtrip conversion without drifting. Basically read the annotation into the flag on the way in, and write the flag back out to the annotation on the way out, and make sure a roundtrip preserves whatever was set.
