I'm working on the KHI Kubernetes inspection framework, which processes audit logs and builds a visual history of resource changes. Right now, every time I write a new inspection plugin I have to re-implement the same patterns: filtering logs down to a subset, grouping them by resource, reading structured field data from each log in parallel, and then translating the grouped logs into history timeline entries.

I'd like to have a set of reusable task factory functions in the inspection taskbase package that cover each of these steps. They should all respect the framework's run-mode vs dry-run-mode distinction — in dry-run mode none of them should modify any state or return real data. The field-reading task in particular should be able to handle large batches of logs concurrently. The history-modification task should carry per-group state from one log to the next within a group, and if a single log's processing fails it should skip writing that log's changes to history but keep going with the rest.

I also need the history builder and timeline builder types to have test-utility methods so I can inspect the raw accumulated history and retrieve copies of timeline events in tests — otherwise there's no way to verify the constructed history programmatically.
