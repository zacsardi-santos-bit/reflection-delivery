I'm adding repeatable directive support to our GraphQL schema library and right now the whole thing assumes every directive can only show up once per location, so applying the same directive twice on the same element always trips a validation error even when the directive was literally designed to stack. Classic example is directive-based APIs that want to accumulate multiple annotations on one element, currently impossible to express or validate.

So a few pieces. The SDL parser needs to recognize an optional `repeatable` keyword in a directive definition, and parsing that should produce a directive definition AST node carrying a boolean flag that reflects whether it's repeatable, with the flag being false when the keyword isn't present. On the type system side the directive representation should expose a boolean repeatability property that defaults to false, so code building directives programmatically can opt in by setting it true, and when it's explicitly true the directive counts as repeatable. The SDL printer should emit the `repeatable` keyword when that flag is set so schemas roundtrip cleanly through print and reparse.

Most important bit is the uniqueness validation rule that flags duplicate directives at a location. It needs to skip the check for directives whose definition is marked repeatable, letting them appear multiple times at the same location without any error. Oh and also, while I'm in there, directives that aren't actually defined in the schema should just be silently ignored by this rule instead of triggering errors, since we can't reason about their repeatability anyway.
