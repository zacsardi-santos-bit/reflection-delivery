I'm working on the Z-Wave JS integration for Home Assistant and there's a gap I keep hitting: there's no way at all to view or change the driver's logging config through the WebSocket API, which makes debugging network issues painful when you'd otherwise have to restart or poke at the filesystem directly to adjust log level or output destination at runtime. I want to add two new WebSocket commands, one to fetch the current log configuration and one to update it. The get command should return everything relevant, whether logging is enabled, the verbosity level, the file logging settings, the log file path, and whether console output is forced, and all the field names in that response need to be snake case. Oh and the log level in the response should come back as a numeric value matching the driver's log level enum representation, not a string.

The update command should let callers change any combination of those settings, but it needs real input validation. It should reject a request that doesn't provide at least one setting to change, reject unrecognized verbosity level names, and reject any attempt to enable file logging without also giving a log file path, each with a clear informative error message. The verbosity level input comes in as a human-readable string and I need it converted appropriately before it gets sent down to the driver. This all lives in the Z-Wave JS websocket API code (`@homeassistant/components/zwave_js/api.py`), btw, so the new commands should slot in alongside the existing ones there.
