I'm hacking on the naga shader compiler and want to clean up how we gate the shader output backends. Right now the backends for SPIR-V, Metal (MSL), DirectX (HLSL), OpenGL/WebGL (GLSL), WGSL, and DOT output all get compiled purely based on explicit feature flags, so Metal shaders build even on non-Apple platforms and DirectX builds even on non-Windows boxes, which is just wasted compilation for targets that'll never use them.

Two things I want here. First, add platform-conditional compilation so Metal output only compiles when we're targeting Apple platforms and DirectX (HLSL) output only when targeting Windows. I still want the existing unconditional features around too, so this means adding new target-platform conditional features to the Cargo manifest (`@Cargo.toml`) alongside what's already there, one for Metal gated to Apple and one for HLSL gated to Windows.

Second, the conditional compilation logic is verbose and repeated all over the place, so I want short cfg aliases defined in a build script (`@build.rs`) for each backend, one each for the spv, msl, hlsl, glsl, wgsl, and dot output. Each alias should resolve to the right feature flag or flags, plus the platform condition where it matters (so the msl alias folds in the Apple check and the hlsl alias folds in the Windows check). Then go through the source and test files and replace all those long feature-flag `cfg` expressions with the concise named aliases instead.

Point is to cut unnecessary compile overhead and let people flip on Metal/DirectX only when they actually target those platforms, while getting rid of the boilerplate cfg conditions scattered everywhere.
