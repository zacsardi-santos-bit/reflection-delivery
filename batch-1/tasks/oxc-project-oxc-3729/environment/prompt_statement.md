I'm seeing our JS minifier tack on an extra semicolon at the very end of every output, even when there's zero reason for it. Like if I minify a plain arithmetic expression I get the simplified value followed by a trailing `;` instead of just the value itself. It's pointless, a trailing semicolon at the end of a file or snippet doesn't do anything, it just wastes a byte, and honestly it makes us inconsistent with the other popular minifiers out there which don't emit it. So I want to stop appending that trailing semicolon at the end of minified output.

To be clear, semicolons that are actually needed inside the code should still be there. If I've got two consecutive statements, the separator between them stays put, it's only the one after the very last statement or expression that should go away. So two statements minify to keep the middle semicolon but end clean with no trailing one.

Oh and this needs to hold across everything the minifier handles, not just simple expressions. Comparisons, logical operators, variable declarations, function and class expressions, arrow functions, assignments, exports, all of it should come out without that trailing semicolon. Basically every JavaScript construct we support should end clean.
