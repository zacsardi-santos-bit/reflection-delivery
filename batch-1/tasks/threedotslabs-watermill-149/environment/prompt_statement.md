I've got a message router with middleware support but right now every middleware I add is global, it hits all handlers registered with the router. What I want is per-handler middleware so I can scope cross-cutting stuff like special error handling, authorization, or tracing to just one handler without having to spin up a whole separate router or add conditional logic inside a shared middleware to filter by which handler it is.

The way I'm picturing it, when I register a handler with the router that registration call should hand back something I can chain another middleware call onto, and that extra middleware only runs for that one handler and doesn't touch any of the others. Global middleware added directly to the router should keep working exactly like before, applying to all handlers, that existing behavior needs to stay intact.

Ordering is the part I really care about getting right. All middleware, global or handler-specific, should follow the same rule the existing global middleware already uses: reverse registration order, so the last one registered wraps the outermost layer and runs first. This unified ordering has to hold up even when I interleave global and handler-specific calls during setup, and when I've got multiple handlers each carrying their own middleware. Basically one consistent ordering model across both scopes.
