I'm extending PyPI's trusted publishing so it supports Google Cloud alongside the existing GitHub Actions provider. Right now teams releasing Python packages from Google Cloud infra have no equivalent to GitHub OIDC, so they're stuck babysitting long-lived API tokens and passwords instead of short-lived workload-specific creds, and I want to close that gap.

What I need is for project maintainers to be able to add, view, and remove Google Cloud trusted publishers for their projects the same way they already can for GitHub Actions, and account holders should be able to register pending Google-based publishers for projects that don't exist yet too. The Google trusted publisher model needs to store the relevant Google-specific identity fields, and the publisher URL for a Google publisher should be handled gracefully when it doesn't exist (don't blow up, just return nothing/none in that case).

On the publishing management side, both the account-level and the project-level publishing pages need a form for registering Google-based publishers, and they should show whether each provider (GitHub and Google) is currently enabled or disabled by admins via a per-provider disabled status flag. Admins need to be able to disable Google trusted publishing independently of GitHub, so that's a dedicated admin flag separate from the GitHub one. Oh and when a provider is administratively disabled, trying to add a publisher of that type should surface a clear error message that names the disabled provider so it's obvious what's turned off.

Also make sure the event logs and metrics correctly identify Google publisher operations as being for the Google provider, not lumped in with GitHub. Basically Google should be a first-class provider everywhere GitHub already is, add/remove flows, pending publishers, admin toggles, status display, logging, all of it.
