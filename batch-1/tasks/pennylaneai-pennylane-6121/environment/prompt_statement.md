I'm building out the arithmetic template library in PennyLane and there's a gap I keep hitting: we've got in-place modular addition and multiplication already, but no out-of-place modular addition and no modular exponentiation. These are the bread-and-butter subroutines for Shor's factoring and other number-theoretic quantum routines, and right now users have to hand-roll them or work around the absence, which slows everything down.

So I need two new templates, both reachable straight from the top-level `pennylane` namespace and both passing the standard operation validity checks, implemented in the same style as the existing arithmetic templates. The first is an out-of-place modular adder that takes two input registers plus a separate output register, adds the integers encoded in both inputs modulo some value, and accumulates into the output without disturbing either input. When no modulus is passed it should default to the largest value representable by the output register. It needs wire overlap validation that raises a descriptive error for each distinct kind of conflict between the register groups, and it has to be JIT-compatible.

The second is a modular exponentiation template taking an exponent register and a separate output register, computing a fixed classical integer base raised to the power encoded in the exponent register, multiplied by whatever's currently in the output register, all modulo some value. Same default modulus behavior (max value representable by the output wires when none given), same kind of wire overlap validation with clear per-conflict error messages, and it also needs to check that enough output wires exist to represent the modulus. Oh and it needs auxiliary/work wire validation too, where the required number of work wires depends on whether the modulus is a power of two. JIT compatible as well.

Both should follow the existing patterns you'll find in the arithmetic templates directory so it all stays consistent.
