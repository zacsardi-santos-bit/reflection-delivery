So I'm cleaning up the admin metrics page and the big problem is it's showing raw internal metric identifiers, those dotted technical keys, as the metric names in the table. That's fine for devs but admins looking at it just want to gauge system health at a glance and these keys mean nothing to them. I want each metric to show a clear human-readable display name instead of its raw technical key so the whole page reads naturally without needing any deep knowledge of the internals.

Couple things that have to keep working after this: the filtering and the dropdown-based selection in the metrics table need to behave correctly against the new display names, not the old keys. And metrics coming from certain internal subsystems, specifically authentication, multiprocessing (background processes), and garbage collection, should still get excluded from the view exactly like they are today, don't regress that.

Also, while I'm in here, I want to pull out a new general-purpose paginated table component that we can reuse across the app. It should render tabular data with configurable columns, support row selection via checkboxes with a callback that receives the selected rows, allow clickable rows with a customizable per-row click handler, and have optional pagination controls that automatically hide themselves when there aren't any pages to show. Basically a reusable table so we're not rebuilding this stuff everywhere. The metrics page should end up using friendly labels throughout so nobody misreads what a metric actually is.
