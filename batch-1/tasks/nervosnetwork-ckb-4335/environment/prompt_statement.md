I'm cleaning up test utilities in the CKB blockchain codebase and I keep hitting the same annoyance: a pile of genuinely useful test helper code lives inside the chain crate's local test module (over in `@chain/src/tests/util.rs` or wherever the chain crate stashes its test helpers), which means no other crate can reuse any of it without copy-pasting. Stuff like mock chain builders, transaction factory functions, cellbase creators, reward calculators, and the DAO field calculators are all trapped there. It's a duplication risk since any other crate wanting similar tests has to re-implement the whole thing from scratch.

There's already a shared test utilities crate meant exactly for this, so I want all those common blockchain test helpers moved into it (the shared crate under `@util/test-utils/src` or similar) and exported from there. The mock chain builders, the tx factories, cellbase creators, reward calculators, and DAO field calculators should all live in the shared crate now. Then slim down the chain crate's local test helpers module so it only keeps what's truly chain-local, basically just the chain controller startup helpers.

All the existing chain tests need to keep passing, just now pulling the helpers from the shared crate instead of the local module, so update those imports. Oh and the dependency that was only pulled into the chain crate because of those helpers should get moved too: add whatever the shared utilities crate needs to support the moved code (in its `Cargo.toml`), and drop that now-unused dependency from the chain crate's `Cargo.toml`. Point is to centralize these in one place so other crates can write consistent tests without maintaining their own copies.
