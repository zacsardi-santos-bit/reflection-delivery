I'm cleaning up timestamp handling in the badger storage backend for Jaeger and could use a hand. Right now every span write recomputes the current time and the expiration time separately for each index entry we create, so service index, operation index, duration index, tag indexes, all of them independently call into the clock and convert to the format they need. That's a bunch of redundant conversions on the hot write path, and in theory it can even drift slightly if the clock ticks between calls. I want the start time and the expiration time computed once per write call and then threaded through to all the helper functions that build the index keys, the trace keys, and update the cache.

There's also a type mismatch that bugs me. The in-memory service and operation caches store expiration timestamps as signed integers, but the storage engine works with unsigned integers natively for its own expiration mechanism, so we keep casting back and forth which is error-prone and can cause subtle comparison issues. I want those cache timestamp maps switched over to the unsigned integer type so things line up throughout and we drop the conversions.

Concretely, the functions that construct storage keys (index keys and trace keys) should accept the pre-computed unsigned timestamp directly instead of receiving a time value and converting it themselves, and the cache update call should get handed the pre-computed expiration time rather than recomputing it internally. Everything hangs off that single per-write computation.

Oh and after these changes I'd also expect trace query results to come back in a consistent newest-to-oldest order, so double check the query path sorts that way.
