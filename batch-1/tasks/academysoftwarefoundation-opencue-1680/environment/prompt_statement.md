I'm cleaning up the Nimby subsystem in the render queue daemon, the bit that watches for user activity so it can lock or unlock a rendering host. Right now it's a mess of separate implementation classes, one that does Linux device file monitoring and another that does cross-platform library-based monitoring, plus a factory that picks between them at runtime. It's more complex than it needs to be and annoying to maintain, so I want to collapse all of it into a single unified Nimby class that always uses the cross-platform input monitoring library approach, and rip out the old classes and the factory entirely.

While I'm in here, there's an attribute that tracks whether Nimby is operational and its name implies the thing is actively doing work when really it just means it's initialized and ready to run. I want to rename it so it clearly reads as "ready" instead of "active", and every place in the codebase that touched the old class names or that old attribute needs to point at the new unified thing.

Behavior-wise, the new class should handle the case where the input monitoring library can't be imported gracefully, so if the import fails it just marks itself not ready and does nothing when asked to run, no crashing. When the library is there it should set up mouse and keyboard listeners, and on any user interaction it locks the host from rendering right away. Then once the user's been idle past a configurable threshold it unlocks the host for rendering again, but only if the machine actually has enough resources to run jobs, don't unlock otherwise. Oh and there should be a static helper that sets a sensible default display environment variable if one isn't already configured in the environment.
