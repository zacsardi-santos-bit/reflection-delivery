I'm working on the render queue daemon's Nimby subsystem, which monitors user activity to lock or unlock a rendering host. Right now the code has multiple separate implementation classes — one for Linux device file monitoring and one for cross-platform library-based monitoring — plus a factory that selects between them. I want to simplify this by replacing all of them with a single unified class that always uses the cross-platform library-based approach.

As part of this, I also want to rename the attribute that tracks whether Nimby is operational. It currently implies the system is actively doing work, but what it really communicates is whether the system is initialized and ready to run. Every part of the codebase that refers to the old class names or the old attribute name needs to be updated as well.

The new unified class should handle import failures of the required input monitoring library gracefully by marking itself as not ready and doing nothing when asked to run. When the library is available, it should set up mouse and keyboard listeners, lock the host when any user interaction is detected, and unlock the host once the user has been idle beyond a configurable threshold — but only if the machine has sufficient resources to run jobs. There should also be a static utility method that sets a default display environment variable if one isn't already configured.
