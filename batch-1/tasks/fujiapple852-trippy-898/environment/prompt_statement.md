I'm cleaning up the public API of our tracing library and the names bug me. The main tracer algorithm config type is exposed with this long prefixed name that just repeats the module context, so callers have to spell out the whole thing even though they're already inside the tracing module. I want to rename it to a short unadorned name within that module, and there's a couple other related types carrying the same redundant prefix that should get the same treatment. All the existing functionality needs to keep working after the rename, so update the call sites too.

While I'm in there, the only way to build these config objects right now is big multi-arg constructors where you pass everything positionally, which is painful. I want builder types for both the tracer config and the network channel config. Give them chainable setter methods so you set only the fields you care about, and a final build method that produces the configured object. The builders should start from the defaults so if you only tweak one setting the rest just fall back to sensible values.

Oh and both config types should derive equality comparison and have reasonable defaults (implement Default) so the builder-from-defaults thing works cleanly and folks can compare configs in tests. This is mostly about ergonomics: shorter names cut boilerplate and the builder pattern lets people incrementally construct complex config using only the overrides they need, which really helps when you just want to customize a few knobs.
