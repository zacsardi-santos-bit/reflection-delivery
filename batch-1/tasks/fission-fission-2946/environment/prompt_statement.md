I'm working on the message queue trigger manager in Fission and I want to lock down the core subscription lifecycle with some actual unit tests, because right now there's nothing verifying the basics and regressions could slip in silently. The manager tracks which triggers have active subscriptions, hands back subscription data when you query it, and removes subscriptions when triggers get deleted, but none of that is covered so anyone changing the trigger management logic is flying blind.

Here's the behavior I want pinned down. A freshly created manager should report no active subscription for any trigger you ask about. Once I register a subscription for a trigger, the manager should confirm that trigger is present and give me back the correct subscription details, including the original trigger name (its identity should round-trip cleanly). Then after I remove that subscription, the manager should report the trigger is no longer active. All four operations, adding, checking, retrieving, and deleting, should complete without errors under normal conditions.

One important thing: the manager runs all subscription requests through an internal background loop, so the tests have to go through its exposed methods rather than poking at internal state directly. No shortcuts around the public API.
