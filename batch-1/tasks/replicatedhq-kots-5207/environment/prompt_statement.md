I'm porting the embedded cluster install scenarios into our current end-to-end regression framework. Right now we've got solid coverage for existing cluster installs (both airgapped and online, across the various RBAC levels), but the embedded cluster variants never got moved over, so there's a real gap. I want to add new end-to-end test suites for embedded cluster airgapped install and embedded cluster online install, following the same structure and validation steps the existing cluster tests already use so they're equivalent in coverage.

While digging into this I hit a snag with the shared helper that validates the dashboard metric graphs. It always tries to configure a metrics endpoint before checking the graphs show up. That's correct for existing clusters where you have to manually punch in the endpoint URL, but embedded clusters ship with their metrics infrastructure already configured, so doing that setup step there just causes failures on something that's already done. I want the helper to take a flag telling it whether it's running against an existing cluster or an embedded one. When it's an existing cluster it should configure the metrics endpoint first and then check the graphs appear, and when it's an embedded cluster it should skip that endpoint configuration entirely and go straight to verifying the graphs render. Oh and the existing cluster specs need updating too so they pass this new cluster-type flag through when they call the dashboard graph validation helper, otherwise they'll break. Basically all the current existing-cluster suites have to keep working with the updated helper. The end goal is accurate, complete regression coverage across every supported install type without the false failures embedded clusters were hitting.
