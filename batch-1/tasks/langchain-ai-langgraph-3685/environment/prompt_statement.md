I'm building a state graph where I want to separate the full internal state from the public interface. My internal state has many fields — including some with custom merge/reduce behavior — but I only want callers to provide a couple of required fields as input, and I only want the graph to return a focused subset as output. So I've defined three separate structured data models from a validation library: one for the full internal state, one for input, and one for output.

The problem is that when all three models are defined this way, the graph doesn't work. Passing an instance of my input model directly to run the graph or stream its outputs fails or produces incorrect results. The schemas the graph reports for input and output don't match my narrower input and output models — they seem to be derived from the wrong type. And when I compile the graph with a checkpointer and try to use interrupts or resume from a saved state, it also breaks.

I'd expect the graph to accept an instance of my input model directly, derive its input and output JSON schemas from those narrower models (not the full state), and work correctly with checkpointers including saving state, interrupting, resuming, and updating state mid-run.
