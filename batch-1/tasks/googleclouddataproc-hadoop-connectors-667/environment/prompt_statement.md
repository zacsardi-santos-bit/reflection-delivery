I'm poking at the Hadoop connector config system and I've got a security worry I want fixed. Right now when you pull a password out of a config property you just get back a plain `String`, and there's nothing in the type system telling you it's sensitive, so the second it hits a logger or gets interpolated into some log message the real secret shows up in plaintext. That's exactly the kind of accidental credential leak I want to make impossible by default.

What I want is a dedicated wrapper type for sensitive string values, something that signals sensitivity right at the API level. When a password gets retrieved from configuration it should come back wrapped in this type instead of as a raw string, and the wrapper needs to let me explicitly grab the underlying value through an accessor when I genuinely need the real thing. The big win though is that any logging that happens during the retrieval should automatically emit a redacted placeholder (think a redacted marker) rather than the actual credential, so secrets never land in the logs even when nobody's thinking about it.

Non-sensitive stuff like string collections shouldn't change at all, those should keep logging their actual values normally, it's only the password/credential path that gets the redaction treatment. Oh and this is a breaking-ish change for callers, so any existing code that calls the password retrieval method and just uses the result directly as a string will need updating to go through the wrapper's accessor to pull out the real value. Basically I want sensitivity encoded in the type and redaction enforced at the point of retrieval, so developers get leak protection for free.
