I'm adding distributed tracing to the CF CLI because right now our outgoing requests to the Cloud Controller, UAA, and Routing APIs don't carry any tracing headers at all, which makes it basically impossible to correlate a single CLI invocation's activity across those backend services when we're chasing failures or perf issues. What I want is B3-style tracing headers on every outgoing request, one for the trace ID and one for the span ID, so operators and devs can line up CLI-initiated requests with server-side traces.

Concretely I need connection wrapper types for each of the three API clients (Cloud Controller, UAA, Routing) that inject these headers automatically into every request. The trace ID should be pre-configured, meaning it's passed in when the wrapper is created and initialized once per CLI invocation (either generated fresh or provided externally), and then attached to all requests in that session. The span ID on the other hand should be freshly and randomly generated per request. Oh and important, if either header is already present on a request (say the caller set it explicitly), the wrappers need to leave it alone and not overwrite it.

I also want a shared utility for managing and setting those headers so the three wrappers aren't duplicating logic, plus the generator functions behind the IDs: one that produces a 32-character hex string suitable for use as a B3 trace ID, and another more general one that generates a random hex string of a configurable length, which is what I'll use for the span IDs. Keep the existing behavior intact otherwise, just weave the header injection in.
