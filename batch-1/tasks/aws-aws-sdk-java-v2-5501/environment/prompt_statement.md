I'm hitting a gap in the DynamoDB Enhanced client around transactional writes. Right now when I call the transactional write method it just returns void, so even if I set the request up to report consumed capacity or item collection metrics, there's literally nowhere for that data to land. I want to actually see how much throughput a transaction burned and track item collection sizes, mostly for cost management and capacity planning, and falling back to the low-level client to get that means I lose all the type-safety and convenience of the enhanced client, which is annoying.

So I need a new variant of the transactional write operation that returns a response object instead of nothing, and it needs to exist on both the synchronous and the asynchronous enhanced client. The response should carry a list of per-table consumed capacity entries plus an item collection metrics map keyed by table name where each value is a list of metrics. When I enable capacity reporting or collection metrics on the request and the write succeeds, those fields should actually be populated from what DynamoDB hands back.

Also the request builder needs to let me say I want consumed capacity returned and whether I want item collection metrics returned, that's the part that's missing today. And the new response object should have proper builder support and correct equality semantics (equals and hashCode behaving sensibly, so two responses with the same capacity and metrics compare equal), since I'll be comparing and logging these. Keep it consistent with the rest of the enhanced client so it feels like a first-class operation and not a bolt-on.
