I'm working on adding resizable array buffer support to the Boa JavaScript engine. The ECMAScript specification allows array buffers to be created with an optional maximum byte length so they can grow dynamically up to that limit. Right now, the internal function that creates the underlying byte data block only accepts a fixed size — there's no way to pass in a maximum capacity alongside the initial size. I need to update this function to accept an optional maximum byte length as an additional parameter, placed between the existing size argument and the context argument. When no maximum is provided (i.e., the option is absent), the function should behave exactly as it does today: allocating memory for a valid size succeeds, and trying to allocate an unreasonably large block (like the maximum possible integer value) fails with an error.
