I'm working on the Gleam language server and want to add an "Inline variable" code action. The idea is simple: when I've got a local variable that holds some straightforward value and then use it exactly once right after, the editor should offer to inline it, so it deletes the `let` binding line and drops the expression directly where the variable was being referenced. Basically automating the tedious manual step of deleting the binding and pasting the value at the usage site, which gets especially annoying in deeply nested code.

A couple of things matter here. It should trigger whether my cursor is sitting on the variable at its definition or at the spot where it's used, either works. And it can't just work in top-level function bodies, it needs to apply inside nested blocks and inside case clause branches too. When I fire it off, the let line disappears and the value shows up inline at the usage.

Also, and this is important, the action shouldn't show up when inlining would be wrong. So if the variable's referenced more than once, don't offer it (we'd be duplicating the expression). Same if the variable came from a destructuring pattern rather than a plain simple binding, or if it was bound by a case clause pattern instead of an actual `let` statement. In all those cases the action just shouldn't appear.

This should live with the other code action logic in the language server crate, roughly around `@compiler-core/src/language_server/code_action.rs`, with coverage in the language server tests.
