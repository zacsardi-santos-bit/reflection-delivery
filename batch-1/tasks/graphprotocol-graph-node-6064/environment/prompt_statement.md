I'm poking at the chain store in graph-node and want to clean up how we get block timestamps when doing a lookup by block hash. Right now there's a method that takes a block hash and hands back the block's number, its timestamp, and the parent hash, but the timestamp comes wrapped in this internal time abstraction (a `BlockTime`-style type) so every caller has to turn around and convert it into raw Unix seconds before it's usable. That's an annoying extra hop and it forces callers to know about the internal time type and call some specific method on it just to read a plain integer.

What I want is for the timestamp to come back as a plain unsigned integer, seconds since the Unix epoch, directly usable with no conversion. And for blocks that don't have a timestamp at all, I'd rather the field just be absent (think `Option` returning nothing) instead of handing back some sentinel value stuffed inside a custom wrapper type. The block number should still come back correctly alongside the timestamp and parent hash like before, that part shouldn't change behavior.

Oh and the method name bugs me too, it currently implies it returns a "pointer" which isn't really accurate. I want it renamed to something that clearly says it returns the block's number and associated metadata rather than a block pointer. Basically this removes an unnecessary abstraction layer and makes the API simpler and more consistent, plus the rename makes the code read better since the name will actually describe what it returns.
