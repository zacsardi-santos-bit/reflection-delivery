I'm hitting a crash in the managed ledger module around size-bounded reads on read-only cursors. When a consumer does an async read that limits both the entry count and the total byte size, and the cursor is read-only, it blows up with an unexpected runtime exception. The root cause is that the size-estimation code unconditionally reaches for the currently active write ledger, which just doesn't exist in a read-only context, so any size-bounded async read on a read-only cursor fails instead of returning entries. I want that read to complete successfully and hand back the correct number of requested entries.

The other half of this is testability. The estimation logic (how many ledger entries fit inside a given byte budget) is buried inside the cursor implementation and can only really be exercised through a full integration test with a real managed ledger. I'd like it pulled out into a standalone utility class that I can test directly with just a ledger metadata map, no full managed ledger needed.

The utility has to get the edge cases right. For an "earliest"/beginning-of-time position (before any stored ledger) it should start estimating from the first available ledger, and for a "latest" position (past all stored ledgers) it estimates from only the last active ledger. When the active ledger ID is missing (the read-only case) it should fall back to using the last entry in the ledger metadata map as the active ledger. Empty ledgers get skipped, and when only an empty ledger is present it should use a default estimated entry size, so please expose that default entry size constant so it's accessible for the fallback when no entry size info is available. A tiny byte budget that can still fit at least one entry must return at least 1, there's an explicit upper bound (max entries cap) it must respect, and when the max byte size is the largest possible value it should return that max entry count immediately. A zero or negative byte budget returns 0.

Without this, operators running read-only cursors can't use the size-bounded read API at all, and extracting the logic also lets me verify the behavior in isolation to avoid future regressions.
