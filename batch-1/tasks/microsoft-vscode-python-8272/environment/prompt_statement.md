I'm adding debug session logging to the Python extension for VS Code. Right now when someone runs the experimental debug adapter mode there's no way to see what's happening between the IDE client and the adapter, all that protocol traffic is just invisible and it makes diagnosing weird debugger behavior really painful since there's no record of what messages went back and forth or when lifecycle stuff happened.

So I want an optional logging feature. If a debug session has file logging turned on in its configuration, we should create a log file in the extension root directory named after the session ID and write all the session events to it. That means logging when the session starts, when messages are sent from the adapter out to the client, when messages come in from the client, when the session stops, any errors that happen, and when the adapter exits including the exit code and signal. Direction of each message should be clear in the output.

Also important, if a session doesn't have file logging enabled or the option is just missing entirely, then nothing should get written and no file should be created at all, don't touch the disk.

Oh and the component that registers the debug adapter factories needs updating too, it should register this new logging factory right alongside the existing descriptor factory so both get set up together when the experimental mode is active. When we're not in experimental mode, neither factory should be registered. This is the piece that activates the debug adapter, so both capabilities come online at the same time.
