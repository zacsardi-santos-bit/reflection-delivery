I'm working on the Python extension for VS Code and we need to add debug session logging support. When someone is using the experimental debug adapter mode, there's currently no way to capture what's happening between the IDE and the debug adapter — all that communication is invisible. I'd like to add an optional logging feature where, if a debug session has file logging turned on in its configuration, we create a log file in the extension root directory (named after the session ID) and write all the session events to it: when the session starts, when messages are sent from the adapter to the client, when messages are received from the client, when the session stops, any errors, and when the adapter exits along with the exit code and signal.

If a session doesn't have file logging enabled (or the option is missing), nothing should be written and no file should be created. The component responsible for registering the debug adapter factories should also be updated to register this new logging factory alongside the existing descriptor factory, so both are set up at the same time when the experimental mode is active. When not in experimental mode, neither factory should be registered.
