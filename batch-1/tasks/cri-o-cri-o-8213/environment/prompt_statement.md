I'm hitting a bug in the container runtime config reload path for pinned images. When I reload with an empty list of pinned images, the runtime doesn't clear the previously pinned ones, they just stay pinned like the reload never happened. So if an operator updates the config to set no pinned images and triggers a reload, the old pinned images stick around and the only workaround is fully restarting the runtime service, which is a real operational pain when you just want to unpin everything dynamically.

What I want is for an empty pinned images list in the new config to actually replace the existing list with an empty one. So when the pinned images list is set to empty and a reload happens, all previously pinned images get unpinned, and the runtime ends up tracking zero pinned images. Right now it silently preserves the old list, which makes it impossible to unpin all images through a config reload.

Can you fix the reload logic so it handles the empty-list case correctly? The core thing is that providing an empty list should remove all existing pinned images rather than being treated as a no-op, and after the reload the runtime should report no images pinned at all.
