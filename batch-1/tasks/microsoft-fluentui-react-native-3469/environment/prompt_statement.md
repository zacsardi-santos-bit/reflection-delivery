I'm building out a React Native UI library and there's a gap I need to fill under the experimental overflow package. The scenario is a row of items sitting in a container that might be too narrow to show them all, and when that happens I want the ones that don't fit hidden and surfaced in a dropdown menu instead. There's nothing that does this automatically right now so I need to add three pieces that work together.

First, a container component that wraps all the items and takes the full list of item IDs upfront so it can track which ones fit and which overflow. It needs to measure how much space is available and decide what shows. Important detail: it should start hidden at opacity 0 while it runs its initial layout pass (avoids that flash-of-content thing), then reveal itself once it knows which items to keep visible.

Second, an item wrapper that each individual item plugs into, identified by a unique string ID. Each one should pass style and layout callbacks straight through to its child without adding any extra wrapping element to the tree, so it stays transparent structurally.

Third, a hook a custom overflow menu component can call to build itself. It should expose whether the menu should currently be shown (and it needs to default to yes before the first layout pass resolves), which item IDs are hidden right now and should appear as menu options, plus a ref and a layout callback to attach to the menu trigger element so the container can account for the trigger's own size when it does its math.

The point is any component, buttons, tabs, whatever, can drop into this container and the visible-vs-hidden logic just gets handled, with hidden ones showing up in an accessible menu. Container, items, and hook all need to coordinate so the space calc, the fit decision, and the menu stay in sync.
