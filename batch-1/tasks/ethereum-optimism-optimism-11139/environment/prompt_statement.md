I'm working on the supervisor component of a multi-chain system and I need to add proper chain-awareness to the storage and processing layers. Right now, all operations are chain-agnostic — there's no central routing layer that takes a chain identifier alongside a storage operation and dispatches it to the right per-chain database. I need to introduce a multi-chain database coordinator that accepts a chain ID with each log-recording or rewind request, routes it to the correct per-chain storage, and returns a clear error when the chain is unknown.

I also need to add a persistent head tracker that stores all the "head" block pointers for each chain (there are several categories: unsafe, cross-validated unsafe, locally safe, cross-safe, locally finalized, and cross-finalized). This tracker needs to persist its state to disk so it survives restarts, and it must apply updates atomically — if the update operation itself returns an error, or if writing to disk fails, the in-memory state must remain unchanged from before the attempt.

Additionally, the per-chain log database should be reorganized into its own sub-package (separate from the multi-chain coordination layer), the processing pipeline components need to carry chain identity through each operation they produce, and the database recovery function should be simplified to return only success or failure rather than a block number.

The head tracker's state must be loadable from a file path; if the file doesn't exist yet, it should start with empty state. When an update is applied via an operation function, the changes are only committed if both the operation succeeds and the data can be written to disk. Any error in either step must result in the state being fully rolled back to what it was before the attempt.
