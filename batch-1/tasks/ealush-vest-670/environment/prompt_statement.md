I'm building custom validation rules on top of this enforcement library and I keep hitting a wall: my rules only ever see the single value they're directly validating. There's no way for a rule to know where it's sitting in the bigger schema, like which key it's checking inside an object, or what array index it's on, or what the parent object even looks like. So cross-field validation is basically impossible right now. What I really want is to write something like "no item in this friends array equals a specific field on the parent object" and there's just no hook to reach up and grab that.

Can we give custom rules access to a context object that describes the current validation scope? It should expose the value currently under validation, plus whatever positional metadata is relevant (the field key name when we're inside an object schema, or the index when we're inside an array), and a reference to the parent scope so I can walk upward. The parent traversal needs to be chainable, so if I'm three levels deep I can keep calling up the parent chain until I reach the top. And at the outermost level, walking up should hand back some sentinel value signaling there's no further parent to go to.

The whole point is that without this my rules are stateless with respect to the hierarchy, they can't take sibling or ancestor values into account at all. With it I can do real cross-field stuff, like checking that no entry in a list duplicates a value stored elsewhere in the same structure. Basically walking up the context tree to enable grandparent-aware validation.
