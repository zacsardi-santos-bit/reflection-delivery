I'm building out subtask support in my task management app and right now everything's flat, tasks have no hierarchy at all, and I want to nest tasks under a parent so users can break big work into steps. A few things I need wired up. When creating a task I want to pass a list of sub-items in the same request, and when updating an existing task I want to add, edit, or remove sub-items too, oh and empty sub-item names should just be silently ignored. I also need a dedicated endpoint to fetch the sub-items of a given task, and it should return an empty list when there are none or when the task doesn't even exist, and unauthenticated requests to that endpoint get rejected, but requests for another user's task's sub-items should quietly return an empty list rather than erroring out.

The completion sync is the tricky part. When a parent gets marked done, all its sub-items should flip to done too with their completion timestamp set, and marking the parent undone reverts every sub-item to incomplete with timestamps cleared. Going the other way, when a sub-item is marked done and it was the last incomplete one, the parent auto-becomes done, and when any sub-item is marked undone the parent immediately reverts to incomplete. Toggling a standalone task with no sub-items still needs to behave normally.

Also the main task list endpoint should only return top-level tasks, sub-items don't show at the top level, and the "completed today" metrics data should exclude sub-items the same way. Creating a sub-item under a task that belongs to another user should return an error btw.

Last thing, unrelated-ish, recurring tasks: deleting a recurring task template is currently blocked by a database constraint, and I want that changed so the delete succeeds and the child recurring instances just have their reference to the deleted template cleared instead of the whole thing getting rejected.
