I want to add a Zulip alerting provider to Gatus. My team lives in Zulip and we want monitoring alerts there when endpoints fail or recover, and right now there's no built-in support so we're stuck with hacky workarounds. Gatus already has a bunch of alerting integrations (Slack, Discord, PagerDuty, Telegram, etc) so this should slot in alongside those.

The provider needs to be configurable with a bot email, a bot API key, an organization domain, and a channel ID. All four are required, so if any of them is missing the provider should be considered invalid. I also want per-group overrides so I can route alerts for different endpoint groups to different Zulip channels, and each override has to specify a group name plus a complete set of those same credentials (email, key, domain, channel).

When it sends an alert it should post a message to the Zulip API authenticating with the bot credentials. The message content needs to clearly say whether the alert was triggered (from repeated/consecutive failures) or resolved (after repeated/consecutive successes), include the alert description if one's set, and then list out each condition result with a visual indicator showing whether it passed or failed. Oh and if the API call fails or comes back with a non-success status code, the provider should return an error.

You'll want to wire this up like the other providers under `@alerting/provider/zulip/zulip.go` and register it in the alerting config alongside the existing ones. Match the conventions the other providers already use for validation, per-group overrides, and building the request body.
