I'm digging into the Ansible operator watches system and I want to add support for referencing roles by their fully-qualified collection name, you know, the three dot-separated parts: collection namespace, collection name, then the role name inside that collection. Right now the watches config only understands traditional filesystem paths for roles, but collections are basically the standard way people ship roles these days, so if you want to use a role that came from a collection you're stuck hardcoding the full path, which kills portability and isn't the Ansible way.

The core thing I need is for the role path resolution logic to stop returning a single path and instead hand back all the candidate paths where a role might live, so it can check multiple spots. For a collection-style name that means the standard Ansible collection install directories, both the system-wide location and the one under the current user's home dir. Oh and if a configurable collection path env var is set, only those paths get searched instead of the system defaults. I still need existing behavior preserved for the roles path env var, and each entry in that variable should contribute two candidates per path.

Also when loading the watches config, it should fail with an error if a collection role is referenced but can't be found in any of the expected locations, rather than silently accepting something invalid. And it should handle the good case too, where a collection role is correctly found because the collection path env var points at it.
