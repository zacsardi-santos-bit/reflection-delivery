I'm knee-deep in the copy-paste feature in Sanity Studio and hit a pile of issues I want sorted out. The big one: when someone copies a reference value and pastes it into a field, we don't check that the referenced document actually exists, so the paste just goes through and we end up with broken data. I need that paste to validate the referenced doc exists before applying anything, and if it's missing, show a clear error and don't apply the change at all.

Array fields are also busted. I can't paste an object or a reference into an array right now, and there's no way to append a single item to an existing array instead of blowing away the whole thing. Default behavior when pasting into an array should replace it, but I also want an append mode that inserts the incoming item at the end.

Oh and reference strength: when I copy a reference between two fields where one wants a weak reference and the other a strong one, the strength property should auto-adjust to whatever the target field's schema expects.

There's a wrong-error-category bug too, when array value types don't match it shows a generic schema mismatch error instead of one specific to array value incompatibility. Fix the categorization so type-incompatible array pastes report the right thing.

Last thing, unrelated-ish, the recent searches storage is tangled directly into the UI hook and it makes the tests super flaky. I want the storage logic pulled out into its own standalone module that can be tested in isolation and mocked independently of the hook. The stored format should be versioned as version 2, and each entry records the query, the document type names, the filters, and a creation timestamp. Also important, removing a search at an index that doesn't exist (too large or negative) should be a no-op, the storage stays completely unmodified in those cases.
