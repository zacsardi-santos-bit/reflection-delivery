I'm working on this Kubernetes state reflection setup where reflectors watch resources and keep a local data store in sync, and right now they handle the incremental add/update/delete events fine but there's no real initial reconciliation when they boot up. What I want is: on startup, when the synced flag is still unset, the reflector does an initial sync pass that compares what's already in the data store against the live state from Kubernetes, then adds the entries that are missing, updates the ones that changed, and deletes the stale ones that aren't in Kubernetes anymore. Without this, stale data just piles up across restarts and new objects get missed, which means the networking control plane drifts out of sync with Kubernetes and we end up with bad routing decisions or stale network config. Each of those operations should bump per-operation statistics (adds, updates, deletes), and after the pass finishes the synced-status check method needs to return true (that flag starts false and flips true once the initial sync completes).

Structurally I need the reflector types for Endpoints, Namespaces, and Services to all embed a shared base reflector struct that provides the sync logic, the synced-status check method, and a stats-reporting method, plus that synced field. Also the event handlers (add, delete, update) currently kind of silently ignore it when they get an argument of the wrong type, I want that to instead increment the argument error counter in the reflector stats and not proceed with the operation.

Oh and the mock lister we use in testing doesn't take any init parameter right now so it can't reflect the current data store state, needs to share the same underlying data as the mock writer. Also there are two new plugin packages, a service configurator and a processor, that just need to exist as valid compilable Go packages even without full implementations yet.
