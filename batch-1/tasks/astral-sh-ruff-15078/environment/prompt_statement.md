I'm hacking on the Ruff type checker and want to add a native suppression comment format so people can silence type-checking errors with a comment style that's ours, instead of always borrowing the syntax that came from other type checkers. Right now we only understand the borrowed format, and having our own gives users a way to tell apart errors muted for Ruff-specific reasons vs ones muted for interop, plus it sets us up for later stuff like flagging unused suppressions.

Here's how I want the new inline comment to behave: bare, it suppresses all type-checking errors on that line, but you can also name specific diagnostic codes to suppress only those, and you can list multiple codes in one comment. The parser needs to be forgiving, so extra whitespace around the separator and inside the code list is fine, whitespace between the comment marker and the keyword is optional, and a trailing comma after the last code is allowed. An empty code list suppresses nothing, invalid characters in a code name mean the whole suppression is ignored (error stays visible), and a missing separator between codes makes it invalid too. Syntax errors and the diagnostics we use for type introspection stay unsuppressible no matter what.

Oh and while I'm in here, I hit a bug where a suppression comment isn't recognized when it shows up after another inline comment directive on a continuation line, like when a formatting directive sits before the suppression on the same token. Fix that at the same time.

For the parser to know which diagnostic codes are real, it needs access to the lint registry, so add a new method on the database interface that exposes the registry to the suppression logic.
