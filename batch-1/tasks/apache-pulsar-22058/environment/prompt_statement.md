I'm wiring up OpenTelemetry metrics on the Pulsar broker and I keep hitting this precision problem with durations. Observability systems like OTel want latency and other duration metrics expressed in seconds, but the standard library's time unit conversion truncates to integers, so a 1-millisecond duration just becomes 0 seconds, which is useless when most of the latency stuff I'm recording is sub-second. I need a shared helper so I'm not rewriting this conversion in every broker component that emits duration metrics.

Can you add a small utility class in the common stats package (somewhere under the common stats utilities, `@pulsar-common/src/main/java/org/apache/pulsar/common/stats/`) that exposes a static method taking a numeric duration amount plus a `TimeUnit` and returns the exact equivalent in seconds as a double, keeping the fractional part intact. So 1 hour should come back as 3600.0, 1 minute as 60.0, 1 second as 1.0, 1 millisecond as 0.001, 1 microsecond as 0.000001, and 1 nanosecond as 0.000000001. The whole point is preserving full precision across all the standard time units so short-lived operations actually show up in the histograms instead of collapsing to zero. Keep it simple and reusable so the conversion logic doesn't get duplicated everywhere.
