I'm poking at the jinja2 template expander service, that persistent gRPC server we use for template expansion in the compositions framework, and I've got a port mismatch that's breaking everything. Right now the server defaults to listening on 50051, which is the usual gRPC dev/test port, but that's not right for how we actually deploy this thing as a long-running service next to other components. Our test suite spins the server up locally and connects on 8443 by default, so with the server still bound to 50051 every test that touches the validate and evaluate operations just fails to connect and blows up.

What I want is for the default port to be 8443 instead, so when the service starts with no explicit port args it binds to the right address out of the box. Still keep the ability to pass an explicit port to override the default, don't rip that out. And obviously the template validation and evaluation functionality needs to keep working correctly once it's on the new port, nothing else should change behavior-wise.

Reason it matters: 8443 is the standard port for secure service endpoints in our Kubernetes deployments, so lining the expander up with that keeps it consistent with the surrounding infra config, and it's what the tests already expect.
