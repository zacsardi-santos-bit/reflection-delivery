I'm digging into the deployment config controller in OpenShift and the status update logic is bugging me because it always bumps the observed generation field unconditionally. That's wrong. When the controller hits an error mid-reconciliation, or when a config is paused and work gets deferred, it still happily reports that it's observed the latest metadata generation even though it hasn't actually finished processing the change. That breaks trust for tooling and operators, like if I pause a deployment and want to confirm the controller acknowledged it, there's no reliable signal, and automations that wait for observed generation to advance before proceeding end up misbehaving because the controller claims it caught up when it didn't.

What I want is to make the observed generation update conditional. The function that computes a new deployment config status should take an explicit boolean flag saying whether to advance observed generation. When true, the returned status reflects the current metadata generation; when false, it preserves whatever the previously observed generation was. The internal status-update helper that calls that calculation also needs to accept and forward this flag through. Then the different code paths in the controller's main reconcile loop should pass true or false depending on whether they've fully processed the config change (true on full reconcile, false on errors or deferred/paused work).

Oh and while I'm in there, please update the import aliases across the affected controller files to the apps-prefixed naming convention the rest of the codebase is moving toward, replacing the older deploy-prefixed aliases.
