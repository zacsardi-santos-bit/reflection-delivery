I'm working on the resource management piece of our AI agent framework and the way we build file paths right now is driving me nuts. Everything keys off a raw numeric ID, so when the system creates an output path for an agent or reads an input file, you end up with these anonymous numeric folders that are impossible to trace back to a specific agent or execution run. I want to fix the on-disk layout so it's human-readable, basically combine the agent's name and its numeric ID (name and id joined with an underscore) so I can glance at a directory and know exactly which agent or run produced what.

So a few things I need. First, path formatting utilities that take a path string with a placeholder and substitute in that combined name-and-ID label, one for agents and one for executions. Second, the models themselves need a way to load a record from the database by its ID, so both the agent model and the agent execution model should get a lookup-by-id method backed by a db session. Third, the resource helper should stop taking bare numeric IDs and instead accept actual agent and agent execution objects when it builds paths or resource records, and it needs distinct methods for resolving where to read agent files versus where to write them (separate read-path and write-path resolution).

Oh and any tools that touch agent files, the file readers and the email attachment stuff over in the tools code, they should use these updated resource path methods and look up the agent/execution objects from the db via a session rather than passing the raw id around. Point is to make debugging way easier by having each agent's output directory reflect both name and id.
