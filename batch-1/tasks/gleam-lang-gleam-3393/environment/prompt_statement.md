I've been hitting a papercut with the Gleam compiler's inexhaustive case expression errors. When it lists the missing patterns I need to handle, it uses the raw internal constructor names instead of whatever names are actually in scope where I'm writing the case, so I can't just copy the suggestions into my code and move on.

Concretely, if I import a module under an alias and use that alias in my case, the suggested missing patterns still show the original module name, which isn't even valid syntax in my module. Same deal when I import a constructor with a rename: the error suggests the original constructor name instead of the alias I gave it. And when a local type shadows an imported constructor, the error sometimes suggests an unqualified name that would actually resolve to the wrong type, or shows an ambiguous name where a module qualifier is really needed to disambiguate.

What I want is for the missing patterns to always use the exact name and qualifier I'd actually write at that point in code, so they're copy-pasteable straight into the case expression to fix the error. That means respecting module aliases (show the aliased module name), constructor aliases (show the renamed constructor), unqualified imports (show the bare unqualified name), and any shadowing (show the module qualifier when it's needed to avoid resolving to a locally shadowed name).

This needs to work for all the ways a type constructor can come into scope: qualified with the original module name, qualified with a module alias, unqualified via an explicit import, renamed via an import alias, and it should cover both user-defined types and built-in prelude types, including when prelude names get shadowed by local definitions. Basically the compiler should suggest patterns using the syntax that's actually valid in that module, every time.
