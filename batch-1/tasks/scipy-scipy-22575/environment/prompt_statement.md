I do a ton of image and array filtering and keep running into a wall with the generic filter in the ndimage-style image processing library. It works fine but it calls my reduction function once per output element, which is painfully slow on big arrays when the callable I'm passing already handles batched input natively (think numpy mean or sum over an axis). All that per-window iteration happens in Python instead of dropping into optimized native code, so I'm eating overhead I don't need to.

What I want is a vectorized cousin of the generic filter that hands all the sliding windows to my callable at once, or in memory-controlled batches, so vectorized ops over windows run way faster. It should take the same window-spec options as the existing generic filter, so size, footprint, axes, origin, and the boundary modes, and behave identically for the standard padding modes (reflect, nearest, mirror, wrap, constant). On top of those I want a "valid" mode that returns only the output elements where the window sits entirely inside the input, no padding at all, so the output comes out smaller than the input in that case.

Also I need a memory-budget knob to cap how large each batch of windows gets at one time, since I'm running this on huge arrays and don't want to blow up RAM. If that budget is set too low to even process the smallest possible chunk, raise a clear error rather than silently doing something weird. And it should support the usual extras: custom footprints, axis selection, and passing an output array, where when I give an output array the result gets written into it and cast to that array's dtype. Oh and don't mutate my input array, I'm reusing it downstream.
