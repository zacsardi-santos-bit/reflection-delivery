I'm cleaning up drag-and-drop in our list component and hit a behavior that feels wrong. Right now items marked "disabled" get excluded from drag operations entirely, they don't get the draggable indicator, their data gets left out of the drag payload, and they're not counted in the accessibility label that tells users how many items are being dragged. So if someone selects a few rows where some are disabled and drags, the disabled ones silently vanish from the drag data, which is confusing and basically data loss. Accessibility folks relying on the announced count get the wrong number too.

What I want is that any item in a draggable list can be dragged regardless of its disabled status. Disabled rows should show the drag handle on hover, press, and keyboard focus just like any other row. When multiple rows are selected and a drag starts, all of them (disabled included) go into the drag data and get reported across the drag lifecycle events, drag start, drag move, and drag end, all reporting every selected row identifier. The drop event should receive all dragged items with no silent exclusions. And the accessibility label on the drag handle needs to count all selected items, disabled ones too.

Oh and there used to be a per-item callback you could pass to selectively mark specific items as non-draggable, I want that mechanism removed entirely. It created this inconsistency where some selected items would quietly disappear from the payload with no indication to the user. The rule going forward is simple, if a list supports drag-and-drop then all items in it are draggable, full stop.
