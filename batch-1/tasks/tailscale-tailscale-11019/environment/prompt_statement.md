I'm working on the Tailscale Kubernetes operator and need to add a new controller that automatically manages DNS records for Tailscale proxy services within the cluster. Right now, when we deploy egress proxy services (configured with a tailnet FQDN via an annotation) or ingress proxies, the cluster nameserver has no way to know what IP addresses the proxy pods are running at, so it can't route DNS queries correctly.

What I need is a reconciler that watches these proxy services and keeps a shared configuration resource updated with the current hostname-to-IP mappings. Specifically, it should handle two cases: egress proxies where the DNS name comes from an annotation on the parent service, and ingress proxies where the DNS name comes from the ingress's load balancer hostname. In both cases, the mapping should update automatically when the pod IP changes, when the FQDN annotation changes, or when the ingress hostname changes. The reconciler should also be gated on the presence of exactly one ready nameserver configuration resource in the cluster — if no such resource is ready, no records should be written.

Additionally, as part of this work, I need to rename a field in the DNS configuration status (the field reporting the nameserver's IP address) and rename the configuration resource and its data key to use clearer naming conventions that reflect their purpose.
