I'm building out the Tailscale Kubernetes operator and I need a new controller that keeps DNS records in sync for our in-cluster Tailscale proxy services. Right now when we deploy egress proxies (the ones forwarding traffic to a tailnet address, configured through a dedicated FQDN annotation on the parent service) or ingress proxies, the cluster's internal nameserver has no idea what IPs the proxy pods actually live at, so it can't resolve the Tailscale domain names to the right addresses. Kind of a big gap.

What I want is a reconciler that watches these proxy services and maintains a shared config resource holding hostname-to-IP mappings the nameserver can consume. Two cases to cover: egress proxies where the DNS name comes off the tailnet FQDN annotation, and ingress proxies where the name comes from the ingress's MagicDNS / load balancer hostname. In both cases the mapping needs to auto-update when the proxy pod IP changes, when the FQDN annotation value changes, or when the ingress hostname changes. So it's got to re-reconcile on any of those.

Also important: this should only write records when there's exactly one properly configured, ready nameserver resource in the cluster. If none is ready, don't write anything, just no-op. Exactly one ready, otherwise skip.

Oh and while I'm in here, do a bit of naming cleanup. I want to rename the field in the DNS config status that reports the nameserver's IP address, and rename the config resource used to store the DNS records along with its data key, all to clearer names that actually reflect what they're for. It's mostly the operator DNS controller and config plumbing so look around `@cmd/k8s-operator` and the related types where the nameserver status and the records config resource are defined.

This matters because without it the Tailscale nameserver literally can't learn the current proxy pod IPs it needs to route through, which is the whole point of DNS-based routing in a Tailscale-enabled cluster.
