I'm working on adding support for BGP route aggregation in Cisco NX-OS configurations to Batfish. Right now, when Batfish parses an NX-OS config that contains BGP aggregate address statements, those statements are simply ignored — nothing gets stored in the vendor model and nothing ends up in the normalized data model that Batfish uses for analysis.

I need the NX-OS parser to recognize aggregate address configuration entries in the BGP IPv4 unicast address family section and store them with all their optional modifiers: whether AS-path inheritance is enabled, which route map (if any) controls which routes contribute to the aggregate, which route map transforms the aggregate's attributes, whether all more-specific routes should be suppressed, and which route map selectively suppresses routes. If a referenced route map doesn't exist in the configuration, the reference should be treated as absent during conversion.

During conversion from the vendor model to the normalized Batfish model, each aggregate should produce a corresponding normalized aggregate entry. When an aggregate is configured to suppress all more-specific routes, the appropriate system suppression policy should be referenced. Attribute transformation maps should be carried through to the normalized model. Some features like AS-path-based generation policies and suppress-map-only suppression don't need to be fully implemented yet — those can be left as null for now.

Additionally, certain unsupported track configuration types (ones that reference routing reachability checks) were previously producing placeholder objects and parse warnings. These should instead be silently ignored — no placeholder objects, no warnings.
