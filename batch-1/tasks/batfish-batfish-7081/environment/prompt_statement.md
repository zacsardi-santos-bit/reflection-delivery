I'm adding BGP route aggregation support for Cisco NX-OS configs in Batfish and right now the parser just drops aggregate address statements on the floor, nothing lands in the vendor model and nothing shows up in the normalized data model we use for analysis. Aggregates combine multiple more-specific routes into one summary advertisement, so silently ignoring them means we can produce incomplete or wrong analysis for networks that lean on route summarization.

What I want is for the NX-OS grammar to recognize aggregate address entries inside the BGP IPv4 unicast address family section and store them in the vendor-specific model with all their optional modifiers preserved: whether AS-path inheritance is on, the route map that filters which routes contribute to the aggregate, the route map that transforms the aggregate's attributes (attribute-map), whether all more-specific routes get suppressed (summary-only style), and the route map that selectively suppresses routes (suppress-map). If a referenced route map doesn't actually exist in the config, treat that reference as absent during conversion, same as if the option wasn't there.

Then on conversion from the vendor model to the normalized Batfish model, each aggregate should produce a matching normalized aggregate entry. When it's set to suppress all more-specifics, wire up the appropriate system suppression policy reference. Carry the attribute-transformation map through to the normalized model. Some stuff doesn't need real implementation yet, so AS-path-based generation policies and suppress-map-only suppression can just be left null for now.

Oh and separately, there are some unsupported track configuration types (the ones referencing routing reachability checks) that used to spit out placeholder objects plus parse warnings. I want those silently ignored instead, no placeholder objects and no warnings at all.
