I'm hitting a bug in the unnecessary dict spread rule in ruff (the lint that flags spreading one dict literal into another dict where you could just inline the keys). It works fine when a dict literal gets spread directly, but the moment the dict is wrapped in parentheses before the `**` spread, the auto-fix it generates is broken. It correctly flags the case as an unnecessary spread, that part's fine, but the fix only strips the inner dict braces and leaves the closing parens dangling, so you get orphaned `)` characters and the resulting code won't parse at all. Anyone who applies it lands a syntax error, which makes the autofix actively harmful here, it should be correct or not offered.

What I want is for the fix to remove the spread operator along with all the enclosing parentheses and the outer dict braces too, not just the inner braces, so the output is valid equivalent Python. It's gotta handle one or more layers of wrapping parens, trailing commas, and comments sitting between the `**` and the actual dict content. Oh and the comments need to be preserved in the output, don't drop them. Result must always be syntactically valid.

Also the snapshot that captures the expected diagnostics and fix diffs for this rule's test cases needs updating to include the correct expected output for all the new parenthesized test cases (diagnostics plus fix diffs). Reference is astral-sh/ruff issue 15366 if you want the context.
