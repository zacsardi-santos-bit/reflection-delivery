I'm adding a new CSS lint rule to biome's nursery group that catches invalid direction values inside gradient functions, since it's really easy to write a direction that looks fine but is actually non-standard and then the browser either renders the gradient in the wrong direction or silently ignores it. That's a nasty silent bug so I want to catch it at dev time.

Here's the deal with the syntax. The standard gradient function wants directions to use a direction-indicator prefix keyword before the directional word, so a bare cardinal keyword sitting there as the first argument without that prefix is non-standard and should get flagged. Angle values also need a real unit suffix, so a bare number with no unit isn't valid but a number with a recognized unit suffix is fine. Also flag invalid or malformed direction strings, including ones that duplicate a keyword.

The vendor-prefixed gradient variants are the tricky inverse case, oh and those older-engine functions actually use the old syntax where the bare directional keyword is correct, so there using the prefix keyword is the mistake and needs flagging instead.

Be lenient about stuff that clearly isn't a direction. If the first argument is a color value rather than a directional keyword or angle, don't raise anything, and directions that include color interpolation syntax should be treated as valid too. Function name matching needs to be case-insensitive. When there's a violation the diagnostic should say they've got an unexpected nonstandard direction and point them at the relevant spec for reference. Also make sure it works inside multi-value background declarations that mix a gradient function with other values like image URLs.

New rule lives under the nursery group in the CSS analyzer, roughly `@crates/biome_css_analyze/src/analyzers/nursery/`.
