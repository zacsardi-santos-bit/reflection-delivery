I'm working with Firestore queries and running into a couple of limitations with how query cursors work. Right now, cursors only accept a dictionary of field name-value pairs or a document snapshot — there's no way to pass a plain ordered list or tuple of values directly, which would be more convenient when I already know the values in the right order.

On top of that, I noticed that I can currently specify a cursor before defining the query's sort order, and the system doesn't complain until much later (if at all). This can lead to silent bugs. I'd expect the system to validate that the cursor and ordering are compatible, and to raise a clear error if there's a mismatch — for example, if the cursor contains more values than there are order fields, or if the cursor references a field that isn't part of the ordering.

I'd like cursors to accept lists and tuples as input in addition to dicts and snapshots. Tuples should be converted to lists internally. The cursor validation against the ordering should happen explicitly, and the ordering must be established before a cursor is applied. When a dict cursor is normalized against the order fields, values should be extracted in field-order to produce an ordered list. The internal helper that converts a cursor to a protobuf format should also be simplified — it should receive an already-normalized list of values rather than needing to do its own field lookup.
