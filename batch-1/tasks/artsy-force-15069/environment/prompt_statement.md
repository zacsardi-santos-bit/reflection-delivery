I'm working on the artist works-for-sale page and the browser tab title bugs me because it stays totally static when someone filters the artworks by medium. Like if a user picks paintings or sculptures or photographs, the tab still shows the same generic title, so you can't tell a filtered view apart from an unfiltered one in the tab, and shared URLs to filtered views end up with useless titles. I want to add a component that dynamically updates the page title based on whichever medium filters are active right now.

Behavior I'm after: when no mediums are selected it shows the default artist title, something like "Artist Name - Works for Sale | Artsy". When one medium is picked the title reflects it, e.g. "Artist Name - Paintings | Artsy". When multiple are picked, list them alphabetically with natural language joining, so two mediums get joined with "and", and three or more become a comma-separated list with "and" before the last item. When the filters get cleared, it falls back to the default again.

Oh and it also needs to handle the case where medium filters come in via URL query params at initial page load, so the title's already accurate on first render, not just after someone toggles a filter. That last part matters most for the shared-link scenario. So the component should read the current active mediums (from filter state and from the URL on mount), sort them, format them, and drive the document title off that.
