I'm hitting a bug in the MongoDB adapter for Payload CMS, specifically the utility over in `@packages/db-mongodb/src/utilities/sanitizeRelationshipIDs.ts` that converts string relationship IDs in stored docs into native MongoDB ID objects. The problem is with sparse data, when a document has some relationship fields that are absent or unset, the traversal fills them in with empty default values instead of skipping them, and that corrupts the document structure with phantom fields that break downstream stuff. What I want is for it to only touch fields that actually have data present, so it never adds new fields or injects empty defaults for relationships that weren't in the original doc, and everything absent just passes through untouched.

The conversion itself also needs to handle the full range of relationship configs, plain single-value relationships, hasMany relationships that are arrays of IDs, and polymorphic relationships where each entry stores both the target collection name and the ID value alongside it. Oh and all of these can show up in their localized forms keyed by locale code too. Also they can be nested inside arrays, blocks, groups, rows, and tabs, including the localized variants of each of those containers, so the utility has to traverse into all of them correctly.

Net result after the fix: every string hex ID present in the data becomes a native ID object with the same underlying value, across every nesting context, and no phantom fields get added for relationships that weren't there to begin with. This matters because folks running data migration scripts or any step that converts stored relationship IDs depend on this producing correct, unmodified document structure except for the actual ID conversions.
