I need to add an account lockout feature to protect user accounts from brute-force login attacks. Right now, anyone can make unlimited failed login attempts without being blocked. I want the system to track failed login attempts by source IP and user account, and after a certain number of consecutive failures, temporarily prevent that IP from logging in to that account.

When a lockout is in effect, the authentication endpoint should respond with a "Too Many Requests" status rather than the usual unauthorized error, so the client can distinguish between wrong credentials and a lockout condition. When the correct password is provided, the failed attempt counter for that IP/account pair should be reset. On the login page, I'd also like users to see a clear alert when they've hit the lockout limit, instead of just getting a generic error.

The authentication service function needs to accept the caller's IP address as an additional input, check whether that IP is currently locked out before even trying to validate the password, record failures when wrong passwords are given, reset the counter on success, and return the lockout expiry time alongside the usual response so the HTTP layer can decide which status code to send.
