I'm adding account lockout to ShellHub's auth flow because right now there's zero brute-force protection, anyone can hammer a login with unlimited wrong passwords and never get blocked, which is obviously bad. I want to track failed login attempts keyed by the source IP and the targeted user account, and after some configurable number of consecutive failures from the same IP against that account, temporarily block that IP from any more auth attempts against that account.

The main change lives in the auth service function that validates credentials. It needs to take the caller's IP address as an extra input, and before it even bothers checking the password it should look at whether that IP is currently locked out for that account. If a wrong password comes in it records the failure (IP plus account), and once we cross the threshold the lockout kicks in. On a correct password the failed attempt counter for that IP/account pair gets reset. Oh and the function should return the lockout expiry time alongside the normal response so the HTTP layer knows what to do.

At the HTTP layer, when a lockout is active the authentication endpoint should respond with Too Many Requests (429) instead of the usual unauthorized error, so the client can tell the difference between just-wrong-credentials and an actual lockout. And on the frontend login page I want users to see a clear alert when they've hit the lockout limit, something that actually explains they're temporarily locked out, not just a generic error message. Without this accounts are wide open to automated password guessing, so it's a basic but important layer, plus it gives people real feedback about why they can't get in.
