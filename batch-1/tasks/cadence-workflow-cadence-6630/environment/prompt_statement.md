I'm working on the Cadence workflow engine codebase and need to refactor the timer gate components used by the history queue processor. Right now, these timer gate types live inside the queue processing package and have a few problems: they have inconsistent method names compared to what I'd expect from a general-purpose abstraction, and the real-time variant leaks a background goroutine because it starts one in its constructor with no way to stop it. This causes goroutine leak tests to fail unless we explicitly ignore the leaked goroutine, which is not a real fix.

I want to move both the real-time and event-driven timer gate types into the shared clock package so they're more broadly reusable. The real-time variant should work with any time source and must expose a channel for timer notifications, a method to update the target time (returning whether the update was accepted), a method to check if the timer will fire after a given time, and a clean stop method that doesn't leave dangling goroutines. After stopping, the gate should be resumable by calling update again.

The event-driven variant is for remote/standby scenarios where time advances through external signals rather than wall-clock time. It should also expose a notification channel and an update method, but instead of stopping it needs a method to advance the internal "current time" — this method should return whether the time actually moved forward, and should trigger the channel if the timer target has now been reached. After a timer fires, it should fire at most once until updated again.

The history queue processor should then be updated to use the new shared timer gate type, including renaming the channel-access method and the teardown method to match the new interface. The goroutine leak exception in the tests should be removed since the new constructor won't start background goroutines.
