I'm cleaning up the Sierra code generator in the Cairo compiler and the current pattern is driving me nuts. Right now every code generation function builds a list of statements and hands it back up, so each caller has to collect, extend, and merge these lists by hand, and worse, every call site has to remember to set or propagate source location info onto the statements it just got back. It's noisy and it's easy to forget the location bit somewhere.

What I want is for the generator context itself to act as a statement accumulator. Instead of returning statement lists, the generation functions should push their output straight into the shared context, and then the context owns the accumulated list and exposes a method so callers can pull all the statements back out once generation is done. The big win here is that source location can get applied centrally at the moment a statement is pushed into the context, rather than being scattered across every call site.

This needs to cover the whole surface: block code generation, statement code generation across all the statement kinds, match handling, return code generation, and all the internal helpers too like the duplicate-variable insertion and drop insertion paths. Oh and while I'm in there, the little helper functions that construct individual statement values should return plain statement objects now instead of location-wrapped ones, since the context is taking over the location wrapping. Net effect is a lot less boilerplate, consistent location tracking, and no more risk of a caller silently dropping location data.
