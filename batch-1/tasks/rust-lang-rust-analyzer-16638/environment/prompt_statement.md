I'm working on rust-analyzer and want to add a new assist that turns a plain struct variable binding into a destructuring pattern. Right now if I do something like `let foo = Foo { ... };` and then access `foo.field_a`, `foo.field_b` all over the place, there's no quick action to convert that into destructuring, I have to rewrite the binding by hand and hunt down every field access to fix it up, which is annoying and error-prone.

What I want is for the assist to trigger when my cursor is on the variable name of a struct binding. When I apply it, it should replace the plain binding with a pattern that names all of the struct's visible fields, using the struct's type path in the pattern. Then it needs to go find all the existing field accesses on that variable within the same scope and rewrite them to use the destructured names directly (so `foo.field_a` just becomes `field_a`).

One thing to be careful about, when a field was accessed through a reference expression like `&foo.field_a`, the reference should stick around after substitution, only the field access part changes to the bare field name so it ends up as `&field_a`. Also for record structs where there aren't any naming conflicts in scope, use the shorthand form where only the field name shows up in the pattern rather than the redundant `field: field` binding.

This lives with the other assists in the ide-assists crate, roughly `@crates/ide-assists/src/handlers/`. The whole point is to automate a common but tedious refactoring so I can get cleaner, more idiomatic code that patterns-matches at the binding site instead of repeating field accesses everywhere.
