I'm working on getting the CosmWasm VM test suite to run on Windows and I keep hitting a wall in the cache layer where filesystem errors bake in OS-specific text. Like when I try to open a WASM file that doesn't exist, the error comes back with whatever the operating system says, on Linux it's something like "no such file or directory" and on Windows it's totally different wording, so any test asserting on the exact error string passes on one platform and blows up on the other. It's also potentially a problem for consensus-critical error paths since the message content shouldn't drift by platform.

What I want is for all the filesystem-related errors in the cache to use fixed, platform-independent messages that don't embed any raw OS error detail. When a WASM file can't be opened for reading (most commonly because it just isn't there), I want the error to say something simple and deterministic instead of the underlying os string. Same deal for file read failures and for directory creation failures, none of those should leak OS text either.

Oh and anywhere in the code that currently matches against the old OS-specific error format needs updating to expect the new standardized message, otherwise those checks break. The whole point is that the error output reads identically no matter which OS runs it, so the Windows build gets closer to parity with Linux.
