I'm working on Ghost's membership and billing side and hit a gap. Our member subscription records only store a legacy plan identifier right now, but Stripe's current billing model uses a separate product-and-price hierarchy, so there's no direct link between a subscription and the actual Stripe price entry it's on. I want subscriptions to also carry a dedicated Stripe price identifier that points at a real price row in the database, that way we can reliably tie a member's subscription to the structured products → Stripe products → Stripe prices hierarchy. Without it we can't track which specific price someone subscribed to, which blocks any later work to display, filter, or update pricing info.

So the subscriptions table needs a new column for that Stripe price identifier, alongside the existing plan id field. Also, and this matters, the foreign key relationships between products, Stripe products, and Stripe prices should NOT cascade deletions, deleting a parent shouldn't nuke the children. Once the schema changes I need to update the schema integrity hash check so it reflects the new shape.

Oh and the test fixtures need sample data for products, Stripe products, and Stripe prices, inserted in that order before subscriptions load, since subscriptions reference them. And when I create subscriptions in tests I want to be able to pass both the old plan identifier and the new Stripe price identifier.
