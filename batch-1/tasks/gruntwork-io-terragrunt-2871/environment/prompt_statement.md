I'm building out a Terragrunt feature and I keep hitting the same gap: Terragrunt can tell me what a given module depends on, but it can't answer the reverse question, which modules depend on me? When you've got a big Terraform/Terragrunt codebase where module A depends on B, B depends on C, and so on, I need to know the blast radius of a change, like which modules need re-applying or safe destruction when something upstream shifts. Right now I'm tracing the graph by hand and it's painful, and honestly this reverse mapping is the prerequisite for the bigger "graph apply" and "graph destroy" stuff where you run a command across the whole set of modules that transitively depend on a target, in the right order.

So what I want is a function that takes a module stack and produces a reverse-dependency map. It should have an entry for every module that has at least one dependent, and the value is an ordered list of those dependents with direct dependents before indirect (transitive) ones. Concrete example, if A depends on B and B depends on C, then C's entry lists B first, then A. Ordering matters here as much as correctness since it's driving downstream apply/destroy sequencing.

Oh and it's gotta handle cycles gracefully, if modules form a circular dependency chain it shouldn't hang or panic, just deal with it and return sensible results. Please keep this within the existing Terragrunt module/stack code so it slots in naturally with how dependencies are already tracked.
