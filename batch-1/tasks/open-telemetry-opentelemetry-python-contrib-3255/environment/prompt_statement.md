I'm using the OpenTelemetry instrumentation for the VertexAI generative AI SDK and tool/function calling is basically invisible in the telemetry right now, which is killing me for debugging agent-style workloads. When the model responds asking for one or more function calls, the emitted response event has nothing about those requests, and when my app sends function results back to the model in a multi-turn conversation, no events get emitted at all for those tool responses. I want both halves of the tool use cycle captured.

So when the model requests a function call, that request should show up as structured data on the response event, with the function name, a generated identifier for the call, and the arguments (only when content capture is enabled). And when the conversation history carries function results going back to the model, I want a dedicated tool message event emitted per function result, capturing the role, a generated identifier, and the response payload (again, content only when capture's on). One more thing that's tripping me up: a turn that's purely function results (no user text) shouldn't also emit a separate user message event, since the tool message events already cover it. Right now it does that double-emit and it's wrong.

This all lives in the VertexAI instrumentation code that builds the log/telemetry events off the request and response contents, so the changes are about how those content parts get translated into events. Understanding which tools were invoked, what inputs the model passed, and what came back is the whole point of having telemetry here, so please make sure function calls and function responses both land as proper events.
