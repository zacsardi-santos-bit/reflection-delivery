I'm working on the pipeline expression evaluation code in the kubeflow/pipelines backend and running into a frustrating issue with numeric comparisons in conditional expressions. Pipeline parameters that hold numeric values are stored internally as floating-point numbers. When I write a condition like checking if a parameter equals the integer 1, the evaluator throws a type compatibility error instead of simply comparing the values. The CEL language specification actually says this comparison should be supported, and the issue seems to stem from the expression evaluation library being at an old version that doesn't implement numeric type promotion yet. The desired behavior is that conditions using integer literals should work correctly against floating-point parameter values without requiring users to explicitly write floating-point literals.
