I'm running into an issue in the Linode manager where a price of $0 is being treated as a missing or invalid price in several places throughout the application. This is causing real problems for users in regions where certain services — like backups or node pools — are available at no cost.

For example, when I try to enable backups for a Linode in a region where backups are free, the dialog shows an error message saying the price can't be loaded, and the confirm button is disabled. But there's no actual error — the price is just legitimately $0. The same problem shows up in the "Enable All Backups" drawer, where Linodes in $0 regions are excluded from the total and the count is wrong. In the Kubernetes node pool resize and add pool drawers, users in $0-priced regions see erroneous "price unavailable" error notices and the action buttons are disabled. And in the Linode migration flow, the pricing panel doesn't render at all when the region has $0 pricing.

The core issue is that a price of $0 is being treated the same as a missing price — but these two cases are fundamentally different. I'd like all of these places to correctly distinguish between "the price is $0" (which is valid and should display as $0.00 without any error) and "the price could not be determined" (which should show the error state). The Kubernetes node pool components also need to properly handle $0 pricing so that valid zero-cost regions no longer trigger error notices or disabled buttons.
