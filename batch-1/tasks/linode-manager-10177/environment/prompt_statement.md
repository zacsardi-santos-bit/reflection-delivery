I'm hitting a bug in the Linode manager where a price of $0 gets treated like it's missing or invalid, and it's blocking real users in regions where stuff like backups or node pools are actually free. The core thing is we're conflating "price is $0" (totally valid, should just show $0.00) with "price couldn't be determined" (the real error case), and those are fundamentally different so I want them separated everywhere this shows up.

Concretely, when I try to enable backups for a Linode in a region where backups cost nothing, the backup dialog throws up a message saying the price can't be loaded and disables the Enable Backups button, but there's no actual error, the price is legitimately zero. So in that flow the button should stay enabled when the price is $0, no error notice should render, and it should display $0.00. Same deal in the Enable All Backups drawer, right now Linodes in $0 regions get excluded from the total and the count comes out wrong, so I need the total to include those free-tier Linodes contributing $0 to the sum, and the count of Linodes without backups needs to include the $0-region ones too.

Then over in the Kubernetes node pool resize and add pool drawers, users in $0-priced regions see bogus "price unavailable" error notices and the action buttons get disabled, so those node pool components need to handle $0 pricing properly so valid zero-cost regions don't trip error states or disabled buttons, and the pricing panels should render and show the zero values. Oh and the Linode migration flow has a related issue where the pricing panel just doesn't render at all when the destination region has $0 pricing, so that panel needs to render and display the zeros correctly too.

Basically everywhere: if the price is genuinely $0, show $0.00 with no error and keep things enabled; only surface the error/unavailable state when the price truly can't be loaded.
