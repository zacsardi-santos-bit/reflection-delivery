I'm cleaning up a leftover that's been bugging me. At some point somebody added an executor assignment field to task instances and to task/operator definitions, the idea being you could target a specific executor per task, but that feature never actually got built or supported. The field's just sitting there across a few layers now and it's misleading, people see it and assume they can set it and it does nothing.

I want it gone everywhere it shows up. First, the task instance data the model layer hands back shouldn't carry any executor field anymore since per-task executor selection isn't a thing we support. Second, when we serialize DAGs and the task/operator definitions inside them, that executor key shouldn't be written out at all. And third, the web view responses that list task instances shouldn't expose an executor field on any task instance record either.

Basically wherever a task instance or a task/operator definition gets represented, whether that's the in-memory model layer results, the serialized DAG format, or the API responses backing the UI task views, drop the executor attribute completely. Keeping a placeholder that does nothing is worse than just removing it, so I'd rather delete it outright and have the data model actually match what the system can do. Please make sure none of those three surfaces still leak it.
