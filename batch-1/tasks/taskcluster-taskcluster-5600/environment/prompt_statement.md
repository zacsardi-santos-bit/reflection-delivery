I'm working on the Taskcluster UI and there's this gap on the task creation page where we don't validate a task payload against the worker type schema before it gets submitted. Right now people can write a totally invalid payload and only find out something's wrong after they submit the task, which is a rough developer experience, so I want to catch it inline instead.

Can you add a utility module (living all together in one file under the UI source tree, so somewhere under `@ui/src`) that validates a given task payload against its corresponding schema. The idea is it fetches the relevant schemas at runtime and checks the payload structure against them, then returns a list of human-readable error messages, or an empty list when everything's valid. So when a payload validates cleanly against its schema, I should get back an empty list, no errors.

Also I need a companion helper in the same module that takes a raw validation error object and formats it into a readable string. The logic there: if the error is about a wrong type at a specific path in the payload, append that path to the message so people know where the problem is; if it's about an unexpected extra property, append the offending property name instead; and otherwise just return the message as-is with no extra structural detail. Both of these should sit side by side in the one utility. The whole point is letting folks catch and fix mistakes earlier so we cut down on frustration and failed submissions.
