I'm poking at Airflow's REST API and the user management side is half-baked. I can read users fine (listing them, grabbing individual records) but there's literally no way to create, update, or delete a user through the API, only read endpoints exist. That blocks any automated provisioning/deprovisioning flow, so I want to bring users up to parity with the other resources that already have full CRUD.

What I need: a POST to create a user where I hand over username, password, email, first name, and last name, plus an optional list of roles. If I don't pass any roles it should just assign the default public role automatically. I also want to update an existing user, both profile fields and role assignments, and it's gotta support an update mask so I can selectively apply changes to only the fields I name. And a delete to remove a user outright.

Auth needs to behave properly across all these writes. An unauthenticated caller gets a 401, and someone who's authenticated but lacks the right create/edit/delete permission gets a 403. If I try to create a user whose username is already taken, that's a 409 conflict. Updating or deleting a user that doesn't exist should come back 404. And for bad request bodies, missing required fields, unknown/unrecognized field names, or role names that don't actually exist in the system, I want a 400 with a descriptive message that spells out exactly what was wrong so I'm not guessing. The relevant handlers live around the user endpoints in the REST API namespace (`@airflow/api_connexion/endpoints/user_endpoint.py`) with the schema validation alongside it, so that's where the create/update/delete logic plus role lookups and error responses should land.
