I'm adding an alternative entity recognition backend to our NLP library. Right now entity recognition always goes through the built-in local mechanism, but I want the option to delegate named entity extraction to an external HTTP service instead, since a lot of entity types are painful to handle with purely local rule-based recognition and a dedicated service gives us broader coverage with better accuracy while still degrading gracefully when it's down.

So I need a new module that wraps calls to this external service and translates its responses into the entity format the rest of the library expects. It's gotta handle a wide range of entity types, emails, phone numbers, URLs, integer and float numbers, distances, quantities, temperatures, volumes, currencies, durations, and date/time expressions, each mapped to the correct entity type name with a properly structured resolution object holding the recognized value. Each extracted entity should carry the position in the text, the matched text, an accuracy score, and that type-appropriate resolution.

On setup, when given a URL it should detect the right default port from the scheme (443 for HTTPS, 80 for HTTP, or whatever explicit port is in the URL), and fall back to a sensible default address if no URL is configured. It also needs to convert a 2-character language code into the locale format the external service expects.

Important bit: if the external service call fails for any reason, catch the error and return an empty list of entities instead of propagating the failure or crashing. And the NLP manager should be updated so that when a settings flag enables this external service, it routes entity recognition through this new module. Oh and the module's request method needs to be accessible/replaceable so it can be swapped out for testing.
