I'm building out a new contrib plugin for the Sloth SLO framework and I keep hitting a false-paging problem with services that have seasonal traffic. Think business-hours-heavy stuff that goes quiet overnight. Under the standard recording rules every time window gets equal weight no matter the actual request volume, so during those low-traffic periods a handful of errors makes the burn rate look catastrophic and pages everyone for nothing. What I want is a plugin that corrects the SLI error ratio by scaling the failure impact against traffic volume relative to the full SLO window, so high-traffic windows contribute proportionally more to the burn signal and quiet windows contribute less.

A few behaviors I care about. It should only work with events-based SLIs, meaning the ones defined with separate error and total queries, and if someone hands it a raw SLI definition it needs to fail clearly with an error rather than limping along. Same deal if the query templates have invalid syntax or reference template variable names that aren't supported, return an error instead of silently emitting wrong rules.

For valid SLOs it should generate two sets of recording rules: corrected SLI error ratio rules that replace the standard ones, plus new metadata rules capturing the correction factor itself for each alerting time window and for the total SLO window. The correction factor for a given window is just the ratio of that current-window traffic to the total-window traffic, so during low-traffic stretches the factor scales the error's contribution down proportionally.

Please wire this up as a proper contrib plugin in the existing plugin system, following the same conventions the other contrib plugins use. It should accept an empty JSON config object with no required fields.
