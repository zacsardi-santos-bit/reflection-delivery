I'm hacking on the Podman machine extension (the bit that spins up Podman VMs on macOS and Windows) and I noticed that when someone creates a fresh machine, none of their host registry config comes along for the ride. So any custom registries, mirrors, or auth they set up on the host are just silently missing inside the new VM, and then image pulls from non-default registries blow up in confusing ways. I want to fix that so the host's registry configuration gets linked into the right spot in the VM automatically, right at first boot.

The way I'm thinking about it: introduce a dedicated registry-configuration component that knows two things, where the registry config file lives on the host, and how to express that same location as a path that's valid inside the VM. On macOS those are identical, but on Windows I need to translate the Windows-style path into the Linux-compatible form used in the VM, so a drive-letter path (like `C:\...`) turns into something under the right mount-point prefix. Please give me both the interface definition for this component and a working implementation.

On top of that, the component should generate an automation script (think a playbook) that creates a symlink from the computed in-VM path into the standard container runtime config directory inside the VM. That script needs to get written out to a temporary directory under the correct filename, and then its path gets passed as an argument into the machine init command so the VM bootstraps with the host's registry settings already wired up. Oh and the wiring matters too, the machine creation function should actually use this thing, but only when the installed Podman version supports it. Basically I want host and VM to feel consistent from the moment the machine first initializes, no manual replication per VM.
