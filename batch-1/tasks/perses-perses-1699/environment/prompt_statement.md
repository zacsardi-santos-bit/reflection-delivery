I'm building out a Go CLI for dashboard-as-code workflows and I've got a gap plus some cleanup to do. The big thing is a new build subcommand. Right now if someone wants to compile a dashboard definition into JSON or YAML they have to reach for an external eval tool and hand-wrangle the output, which is annoying. I want build to do it inline: give it either a single definition file or a whole directory of them, and it evaluates each one and writes the result into a dedicated output folder, preserving the relative directory structure and tacking an output suffix onto the filename. Format defaults to YAML but I want a flag to switch it to JSON. Oh and there should be a mode flag so instead of writing files it just prints to stdout, which is handy for piping straight into deploy.

While I'm in there, the lint command only takes a file flag and doesn't have a directory option, even though apply already does. I want both apply and lint to treat file and directory as mutually exclusive but required, so exactly one has to be passed. Today when you give neither, both commands spit out confusing errors, so I want a consistent clear message saying exactly one of the two is required, and when both are passed they should say the flags can't be used together.

Build needs the same treatment: require exactly one of file or directory, reject bad file or directory paths with descriptive errors, and handle the both-passed case too. Consistent flag validation everywhere so nobody gets confused.
