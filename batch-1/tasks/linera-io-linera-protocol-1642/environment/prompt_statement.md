I'm working with our WIT derive macros, the ones that auto-generate WebAssembly Interface Types serialization for Rust structs and enums. They compute the wire format layout, load values out of WebAssembly memory, and store values back into it. Trouble is some of my types carry fields that are purely internal, marker types or phantom data or cached stuff that has no business crossing the WebAssembly interface boundary, and right now the derives shove every single field into the serialization so I just can't use them on those types at all without ripping the fields out or hand-writing the whole impl.

What I want is a field-level attribute that lets me tag a field to be skipped during WIT serialization. When a field's marked as skipped it should drop out of the type layout computation (so size and memory representation only account for the non-skipped fields), it shouldn't get read from memory on load (instead just fall back to its default value), and it shouldn't get written on store either, silently ignored. This has to work across the board, named structs, tuple structs, and every enum variant kind, meaning empty, tuple, and named struct variants.

Oh and important, the skip attribute needs to actually be registered with each of the three derive macros (the layout one, the load-from-memory one, and the store-to-memory one) so the compiler doesn't start whining about an unknown attribute. Without this, anything with local implementation details is stuck, and I'd rather make the derives usable for a much wider range of real types.
