I'm adding AWS Step Functions support to Prowler because right now there's just no way to audit whether state machines have logging turned on, and that's a real gap for compliance folks. There's zero integration for this service today, can't list state machines, can't pull their config, nothing.

So I need a new service class under `@prowler/providers/aws/services/stepfunctions/stepfunctions_service.py` that enumerates all state machines across every region we're scanning. For each one it should grab the full details, so logging configuration, tracing configuration, encryption configuration, and tags. It's gotta call the right APIs to list machines and then describe each to get the logging status and the rest. Oh and it needs to handle the usual AWS failure modes gracefully, like when permissions get denied or a resource isn't found, without the whole thing crashing out. Just log and keep going.

Then on top of that I want a check, something like `stepfunctions_statemachine_logging_enabled`, that evaluates each state machine. If logging is off it flags a failing finding with a message that clearly says logging isn't enabled on that machine, and if logging's properly on it passes. Each result needs to carry the state machine's identifier (its name), its full resource ARN, and the region it lives in so the findings actually point somewhere useful.

Why bother? Without logging on these workflows you lose the operational trail, makes troubleshooting painful and blows a hole in audit requirements, so surfacing which machines are missing logging lets teams go fix it.
