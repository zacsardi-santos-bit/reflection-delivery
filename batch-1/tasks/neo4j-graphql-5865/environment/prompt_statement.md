I'm hitting a bunch of issues with the `@default` directive in my Neo4j GraphQL schema and I think they're all related to how default values get validated and applied across scalar types. First off, temporal fields are broken. If I declare a default on a `Time` field (with timezone) or a `LocalTime` (without tz), or a `LocalDateTime`, or a plain `Date`, it either fails schema validation outright or the default just never gets applied at runtime, so when I create a node without passing that field it comes back empty instead of populated with what I declared. I need all four of those temporal scalars to accept defaults and actually apply them when a node's created without the field.

Same deal with `BigInt`, defaults aren't supported there at all. I want big ints to accept a default given as either a numeric literal or a string, and values should come back out as strings.

Then there's the float strictness problem. Integer literals like `1` are getting rejected as defaults on `Float` fields and float list fields, which is silly since ints are perfectly valid floats. The `@coalesce` directive has the exact same over-strict rejection on float and float-list fields. Both should accept integer literals fine.

Oh and the error message when you put `@default` on something genuinely unsupported (spatial/geographic types like `Point`) is stale, it lists an old set of supported types that doesn't match reality, so it's useless for figuring out what's actually allowed. That message should accurately list all the types that really are supported now.

The underlying validation and runtime default logic lives in the schema-model and directive handling code (roughly `@packages/graphql/src`), so the fixes need to cover both the validate-at-schema-time path and the apply-at-create-time path. Right now developers get silent failures on temporal and big int defaults, plus confusing rejections on float defaults, and the whole feature behaves unpredictably. I want it complete and consistent across every scalar type it claims to support.
