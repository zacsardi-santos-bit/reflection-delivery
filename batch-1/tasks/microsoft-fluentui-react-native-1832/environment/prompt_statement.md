I'm poking at the experimental Text component in our React Native design system, over in `@src` where the shared text primitive lives, and I hit an accessibility gap that's bugging me. When a screen reader user (VoiceOver on iOS, say) double-taps a text element that has a press handler wired up, nothing fires. The accessibility tap gesture and the regular press action just aren't connected, so the action gets silently swallowed and an entire category of users can't interact with text-based actions at all.

What I want is for the Text component to bridge these automatically. If a text element has a press handler (onPress), then the accessibility tap gesture (the double-tap activation, onAccessibilityTap) should invoke that same handler without me having to do anything extra. Oh and I still want an escape hatch, so if a developer explicitly passes a custom accessibility tap callback, that one wins and we don't override it with the press handler. Only fall back to press when no custom accessibility tap was provided.

The nice part is this text primitive is shared all over the place, tabs, menus, badges, notifications, etc., so fixing it once here should propagate everywhere without touching each of those components individually. That's the whole point of doing it at the shared level, consistent accessible behavior across the design system.
