I'm working with the TPM2 library and hit two gaps plus some cleanup I need done. First, I need to load an externally-generated RSA key pair into the TPM, meaning I pass in both the public key parameters and the private key material and get back a TPM handle I can use for later operations, since right now there's just no way to bring an outside key in. Second, I want to certify a key that's already held in the TPM: given a subject key handle and a signing key handle, the TPM should hand me back an attestation blob plus a signature over that blob, and that signature needs to verify with standard RSA signature verification against the signer's public key. This is the whole point of TPM attestation workflows (remote attestation, key certification, etc.) so without it I can't really do those.

Also, the existing functions for creating primary keys, creating child keys, loading keys, activating credentials, and evicting persistent keys currently smush the parent-or-hierarchy authorization and the key's own authorization into a single password, which is sloppy and honestly a place where you can accidentally apply the wrong password in the wrong context. I want those split into separate parameters so I can pass distinct passwords, one for the parent/hierarchy auth and one for the key auth. Oh and the default RSA key size in the library's key parameter defaults should bump to 2048 bits to line up with modern security expectations.
