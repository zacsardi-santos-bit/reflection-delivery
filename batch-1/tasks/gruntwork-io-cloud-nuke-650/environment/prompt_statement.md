I'm working on cloud-nuke and I've got a gap I keep hitting: the tool cleans up S3 buckets fine but it's completely unaware of the three S3 access point flavors AWS supports, so when I nuke a test environment the standard access points, the object lambda access points, and the multi-region access points all get left behind, which leaves cost and clutter around and honestly causes name conflicts and failed re-deploys when I spin up fresh environments later.

I want cloud-nuke to discover and delete each of these three types following the same pattern the other supported resources use. For standard S3 access points and for S3 object lambda access points I need name-based filtering to work, meaning regex-based name exclusion. For S3 multi-region access points I need both name-based and time-based filtering, specifically the ability to exclude ones created after (or before) a given point in time so I can skip access points created before a certain date.

Also the config system needs to recognize each of these as its own distinct resource type so I can apply independent filtering rules per type, consistent with how everything else is configured. So that's three new resource types wired into listing, deletion, and the configuration schema, with standard and object lambda supporting name exclusion and multi-region supporting name plus time exclusion.
