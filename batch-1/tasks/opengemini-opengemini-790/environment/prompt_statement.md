I'm building out a gRPC record write service for openGemini and need it wired up end to end. The idea is that binary-protocol clients push batches of binary-encoded time-series records over gRPC and we ingest them efficiently, which right now we just can't do since there's no dedicated high-performance write path for this.

So I want a service that starts and stops cleanly, no leftover goroutines or hanging listeners. It should take pluggable dependencies, specifically a writer implementation and an authorizer implementation, so I can swap those in for real or for testing. The core is batch writes: a request carries multiple records, each binary-encoded, and I need every record validated individually. Then three outcomes, all records valid means write them all and return a success response, all records invalid means return a failure response, and the mixed case where some are good and some are bad should still write the valid ones and return a partial success response. That partial success bit actually matters a lot because clients need to know part of their data landed even when part of the batch was malformed, instead of getting an opaque all-or-nothing error back.

Also it needs to answer health-check ping requests by reporting the server is up. And auth should be optional, when it's enabled a write request has to carry valid user credentials that have write privileges, and if the credentials are missing or the user doesn't have write access I want the request rejected. When auth is off, writes just go through. Thanks!
