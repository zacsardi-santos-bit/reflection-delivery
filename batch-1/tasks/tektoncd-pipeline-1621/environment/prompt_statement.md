I'm cleaning up the pod-building code in the Tekton pipeline project and the split between packages is driving me nuts. Right now the main function that assembles a pod from a task run lives over in the reconciler's resources package, while all the related helper stuff lives in the dedicated pod package, and because the two packages reference each other I've had to export a ton of internal helpers that nobody outside the pod-building code ever touches. I'm talking about the functions for ordering containers, converting scripts, initializing credentials, resolving entrypoints, and setting up working directories, plus all their associated volume mounts, volumes, annotation keys, and container name prefixes. None of that should be public API.

What I want is to move the pod assembly function into the pod package so all those helpers can go back to being unexported and stay as internal implementation details. Along with that, the label keys used to identify pods managed by the task run reconciler should also live in the pod package so they're accessible from there. Oh and the three helper container images (the one for entrypoint injection, the credentials initializer, and the shell commands image) are currently getting passed around as individual strings in a few different places, which is messy. I'd rather group them into a single structured value that gets passed together everywhere.

Also the test files for pod assembly need to move into the pod package too, so they can reach the now-unexported symbols directly without me having to export anything purely for testing. The whole point here is that unnecessarily exported symbols force external packages to depend on internals that might change, making future refactoring harder, so consolidating into one package with a minimal public surface keeps things cleaner and cuts the unintended coupling between the reconciler layer and the low-level pod-building concerns.
