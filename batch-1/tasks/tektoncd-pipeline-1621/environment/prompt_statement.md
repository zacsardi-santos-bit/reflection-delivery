I'm working on consolidating pod-building code in the Tekton pipeline project. Right now, the main function that assembles a pod from a task run lives in the reconciler's resources package, while related helper code lives in the dedicated pod package. Because the two packages reference each other, many internal helpers — functions for ordering containers, converting scripts, initializing credentials, resolving entrypoints, initializing working directories — and their associated volume mounts, volumes, annotation keys, and container name prefixes all have to be exported even though nothing outside the pod-building code ever uses them.

I'd like to move the pod assembly function into the pod package so that all these helpers can become unexported and stay as internal implementation details. Along with that move, the label keys used to identify reconciler-managed pods should also live in the pod package. The three helper container images (for entrypoint injection, credentials initialization, and shell commands) are currently passed around as individual strings in different places — they should instead be grouped into a single structured value that gets passed together.

The test files for pod assembly should also move into the pod package so they can access the now-unexported symbols directly without anything being exported purely for testing purposes.
