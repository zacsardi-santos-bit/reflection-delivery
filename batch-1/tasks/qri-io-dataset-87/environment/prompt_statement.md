I'm poking at our dataset library and hit a gap. We've got these six core types, one for commits, one for datasets, one for metadata, one for the data structure itself, one for transforms, and one for the viz config, and each of them carries an internal path field that tracks where the data lives in storage. Problem is there's no public way to set that path from a plain string once the object already exists. So if I load something or resolve a reference and then want to programmatically assign the path afterward, I'm stuck reaching into the struct internals or doing some other workaround, which is gross and easy to get wrong.

What I want is a dedicated method on each of these six types that takes a single string argument and sets the internal path from it. The rule is: if I pass an empty string, reset the path back to its zero value, and if I pass a non-empty string, construct the appropriate key from that string and store it. Same behavior consistently across all six, so it's a predictable pattern. Also it'd be good to document that this is a set-path-with-care kind of operation since it's mutating where data points to. Just make the intent explicit instead of leaving callers to fiddle with the raw fields.
