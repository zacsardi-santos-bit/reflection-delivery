I'm hitting a validation gap in git-secret and I want the add-user and remove-user commands (the `git secret tell` and `git secret killperson` style flows) to stop accepting partial identifiers. Right now if I type just the short username part of someone's email without the domain, the command doesn't reject it the way it should, it behaves inconsistently, sometimes looking like it succeeded and sometimes silently failing to find the right person. Same deal if I pass a string that's only a substring of a real email in the keyring, like a prefix that partially matches one or more actual addresses, it can do weird stuff instead of just refusing.

What I want is simple: both commands should require a full, exact email address that actually exists in the GPG keyring before touching anything. If the input isn't an exact match to an email in the keyring (short name, partial string, prefix, whatever), the command needs to bail out immediately with a non-zero exit code and leave the keyring state completely unchanged, no partial writes. And after that kind of failure, when I query who currently has access to the secrets it should still show the unchanged state, so nothing got added or removed on a rejected call.

Fully qualified exact emails that exist in the keyring should keep working exactly like before, don't break the happy path. This is really a correctness and safety thing, it's way too easy to accidentally add or remove the wrong person or get no clear feedback that it failed, so requiring the exact match makes it predictable and auditable. Context is over at the git-secret issue #176 if you need it.
