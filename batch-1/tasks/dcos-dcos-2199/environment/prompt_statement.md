We're on DC/OS and I want to clean up how Admin Router does TLS. Right now there's one shared TLS config file feeding both the Master and Agent Admin Routers, and that's the core problem since the two roles have genuinely different needs. The Master Router is externally facing so it has to stay flexible for browsers and API clients across a range of TLS versions, while the Agent Router only ever handles cluster-internal traffic, so it should always be locked to TLS 1.2 only with a tighter, internal-optimized cipher list no matter what the master is set to.

So first, split the single config into two separate files, one for the Master Admin Router and one for the Agent Admin Router. The agent one always enforces TLS 1.2 only with its own strict cipher suite, full stop.

Second, I need finer control over protocol versions on the master. Today we can only toggle TLS 1.0 on or off while 1.1 and 1.2 are stuck enabled together, so there's no way to express something like "TLS 1.2 only" or "1.0 and 1.2 but not 1.1". I want each of the three versions (1.0, 1.1, 1.2) independently enable/disable-able for the Master Router. Oh and add a guard so nobody can accidentally turn off all three at once, because that'd make the whole cluster unreachable. When someone sets all three to disabled the config generator should bail out and return a clear error explaining that constraint.

Last thing, the Master Admin Router should support a configurable custom cipher suite so operators can override the default cipher list when they need to. That override should never touch the Agent Router's cipher suite though, it stays on its own strict list regardless.
