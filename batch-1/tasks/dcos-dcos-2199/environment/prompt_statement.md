We're running DC/OS and need to improve how TLS is configured for Admin Router. Right now there's a single TLS configuration file used by both the Master and Agent Admin Routers, but these two roles really need separate configurations. The Agent Router only handles cluster-internal traffic, so it should always use TLS 1.2 only with a tighter cipher list, regardless of what's configured for the external-facing Master Router. The Master Router configuration should remain flexible.

Beyond the file split, we also need finer control over which TLS protocol versions are enabled for the Master Router. Currently we can only toggle TLS 1.0 on or off, while TLS 1.1 and 1.2 are always enabled together. We need to be able to enable or disable each of the three versions (1.0, 1.1, 1.2) independently. We should also add a guard that prevents operators from accidentally disabling all TLS versions simultaneously, since that would make the cluster unreachable. When someone tries to set all three to disabled, the configuration generator should return a clear error explaining the constraint.

Finally, the Master Admin Router should support a configurable custom cipher suite so that operators can override the default cipher list when needed. The Agent Router's cipher suite should never be affected by this override.
