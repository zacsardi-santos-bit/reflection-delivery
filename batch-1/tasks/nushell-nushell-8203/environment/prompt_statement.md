I'm hitting a wall with nushell's `bytes starts-with` command when the binary comes from an external process. If the data's already fully in memory as a binary value it checks the prefix fine, but the moment I pipe in output from an external command it blows up with an error instead of giving me a clean true/false. Looks like it just doesn't know how to deal with streaming binary, which is a real pain when I'm checking leading bytes of big file outputs or network data or whatever another command spits out, because collecting the whole stream into memory kind of defeats the point of streaming in the first place.

What I want is for it to process the raw binary stream incrementally over in `@crates/nu-command/src/bytes/starts_with.rs`, comparing chunks against the pattern as they arrive without buffering everything up front. It should return true when the start of the stream matches the pattern, false if it doesn't match or if the stream runs out before the pattern's fully covered. Short streams and really long ones (think tens of thousands of repeated byte sequences) both need to work, and the stream might come through as a mix of binary chunks and string-typed chunks, so handle that too. Oh and plain string values that weren't converted to binary should still get rejected with an error saying that input type isn't supported.

Also I need a new test helper that can emit arbitrary raw binary including null bytes, since the existing byte-repeater util doesn't handle arbitrary binary values right. It should take alternating hex-encoded byte sequences and repeat counts, writing each decoded byte sequence to stdout the given number of times.
