I'm poking at the watch stuff in our distributed KV store and hitting a few things I want cleaned up. Right now watching a single key only works if the key already has a value written to it. If I call the watch function on a key that's never been written, it silently fails or skips values instead of just waiting around. That forces me to pre-populate keys with dummy placeholder values before starting any watch, which is a fragile hack I shouldn't need. What I want is for watching a key that doesn't have a value yet to work correctly: the watcher should block and wait for the first write, then report that first value naturally, no pre-population required. This matters because in real usage key creation and observation happen concurrently and consumers shouldn't have to know whether a key exists first, they just subscribe and get updates as they happen.

Then there's the prefix-watch feature which has two bugs. When it reports a key update to the callback it strips the prefix off the key name before delivering it, so I only get the suffix. I want the full key name (including the prefix) delivered instead. Also it sometimes fires duplicate notifications for keys that didn't actually change, so each changed key should get reported exactly once, no dupes for unchanged keys.

Oh and one more thing, there's a string codec implementation that's currently copy-pasted across multiple files (test and client files). I'd rather have a single reusable string codec living in the shared codec package that everyone can import, instead of it being duplicated all over.
