I'm working on the Cloud Foundry API layer and hit a compliance gap with tasks. When a task gets created via the API, the response body comes back with no timestamp fields at all, so there's nothing telling clients when the task was created or last updated. Every other resource type surfaces a creation timestamp and a last-updated timestamp, but tasks just don't expose them, and the CF API spec expects these on all resource types. Without them any client that relies on this for ordering, display, or auditing breaks, so folks can't figure out task age, sort by creation time, or show a meaningful "created at" in the UI. Basically it makes our task responses non-compliant with standard CF API clients.

The annoying part is the underlying resource already knows its creation time, it's just not being carried through. So I want the internal task data record to actually capture the task's real creation time from that underlying resource, and then I want the API response to include both a creation timestamp and a last-updated timestamp. Both should be formatted as standard ISO 8601 UTC date-time strings, no fractional seconds, just the clean UTC notation. And since tasks are immutable once created (they can't be updated after the fact), the created and updated timestamps should just be the same value reflecting that one creation moment.
