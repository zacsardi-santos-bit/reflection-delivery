I'm trying to wire up distributed tracing on my nginx ingress controller and right now there's just no path for it, operators who want OpenTracing-compatible tracing for traffic passing through can't turn anything on. What I want is for an operator to globally enable tracing and pick a backend by dropping a collector host into the controller's global config, so if they set a collector host (or endpoint) for Jaeger, Zipkin, or Datadog the controller should automatically load the matching tracing plugin shared library and emit the right tracing directives into the generated nginx config.

It also needs to work per-route, so individual Ingress resources should be able to enable or disable tracing via Kubernetes annotations independent of the global setting. And when tracing's actually active the controller should inject the correct context-propagation directive into each location block, picking the standard HTTP propagation directive versus the gRPC-specific one depending on whether that route's backend is HTTP or gRPC.

Oh and I want control over whether incoming trace context headers from external clients are trusted, both globally and per route. Also a way to set a custom operation name template for spans at both the global level and the per-location level.

Big one: when tracing's fully disabled, meaning off globally and not overridden on in any location, no tracing directives at all should show up in the generated configuration. This all lives in the template and config plumbing under `@internal/ingress/controller/config` and the nginx template logic. Without this operators can't tie their ingress-managed services into distributed tracing infra, which makes observing request flows across microservices painful, so it matters for real production observability.
