I'm working on the Kubernetes process monitor for FoundationDB (the argument handling lives around `@fdbkubernetesmonitor/args`) and I need to get dual-stack networking working. Right now the process monitor arguments only support simple single-value environment variable lookups, so there's no way to pick the right IP when a pod has both IPv4 and IPv6 addresses. I want a new argument type that reads a comma-separated list of IP addresses out of an environment variable and returns just the one matching a desired IP family, 4 for IPv4 and 6 for IPv6. The list can have both families mixed in any order, and any entry that isn't a valid IP should just get skipped silently rather than blowing up. If there's no address of the requested family in the list, I want it to fail with a descriptive error saying so, and if someone asks for an IP family that isn't 4 or 6 that should error out too.

While I'm in here, I also need a method on the argument type that resolves an argument's value given a set of environment variables directly, without running the whole argument generation pipeline (handy for just inspecting a config value). It should handle both the plain environment-variable case and this new IP list type, reusing the same logic and the same error messages so they stay consistent.

Oh and one more thing, the error messages for missing environment variables are capitalized inconsistently right now. They should start with a lowercase letter and still include the actual variable name in the text.
