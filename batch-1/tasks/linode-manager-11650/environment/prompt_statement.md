We're cleaning up how auth state works in our app and I want your help. Right now the session token, its expiration, and its scopes all live in a centralized application store, and components everywhere connect to that store just to see if someone's logged in or if an admin is impersonating a customer. It's overcomplicated and it makes tests miserable, every component test that touches auth needs a custom store setup, so I want to rip all that out.

Replace it with a plain utility module that reads and writes the token data straight to local storage. I need a function to get the current token that returns an object with the token string, the expiration, and the scopes, plus one to set a new token, and one to clear it, where clear means every field resets to an empty string (not null). Also I need a function that tells me whether the currently logged-in session is an admin impersonating a customer, and that has to be derived from the token value itself, not from any store-derived state.

Then update the logout component and the OAuth callback component to use this utility instead of dispatching store actions or taking store-connected props. The logout component should take no props at all and just clear the session and kick off logout on mount. The OAuth callback component also takes no props, it reads the current URL location when it mounts, and on a successful code exchange it stores the token (formatted with a bearer prefix), the expiration, and the scopes through the new utility. On any failure it should clear the session and send the user off to the login server's logout endpoint.

Oh and the API error handling, when we get an unauthorized (or expired) response back, the error handler needs to clear the session token and redirect to the login page. Also in the parent/child account switching flow, after the token expires users should land on the login page rather than the logout page. The whole point here is to make the token reachable everywhere without a store connection, so testing gets simple and the session behavior is easy to trace.
