I'm building out the workspace settings flow for custom report fields and I need the action layer that actually creates a new report field for a workspace. Right now there's no way to programmatically create these, so the whole "add report field" settings UI is dead in the water. Admins want to add fields that show up on expense reports so they can prompt submitters for extra structured info.

There are three field types: free text, a date picker, and a list/dropdown of options. When someone creates a text field, it should land in the workspace right away with the given name, type, and default value, and no pre-populated dropdown options. Date fields are similar, they get added with the name, type, and a date as the default value. For list/dropdown fields the available values and their enabled/disabled states need to come straight from whatever was configured in the form at submission time, so read that current state and carry it into the field.

Everything here should be optimistic, so the field shows up in the workspace immediately without waiting on the server, and then the pending indicator on the field gets cleared once the server confirms the change. Oh and I also need a small utility that deterministically generates a unique field ID from the field's name, that ID is what gets used to compute the key the field is stored under in the workspace's field list, so same name in should always give the same key out.
