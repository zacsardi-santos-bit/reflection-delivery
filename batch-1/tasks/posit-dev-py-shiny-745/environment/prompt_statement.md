I'm working on select input widgets that can optionally show a button to remove or clear the current selection. The right button type depends on whether the input allows multiple selections or just one — a per-item remove button for multi-select, and a full-clear button for single-select. I need a helper that takes an existing options dictionary (which a developer may have already partially filled with their own plugin and configuration entries) and injects the correct button plugin automatically, without duplicating it if it's already there and without disturbing any other keys or plugins the developer has set.

I also need a way to embed JavaScript expressions inside these nested options dictionaries and then later identify exactly which keys hold those expressions. The configuration can be deeply nested, so the identification utility should return dot-notation paths for all JavaScript-expression values found anywhere in the hierarchy — for example a value two levels deep would be reported as something like "parentKey.childKey". Plain string values and intermediate sub-dictionaries should not appear in that list, only the keys whose values are actual JavaScript expressions.
