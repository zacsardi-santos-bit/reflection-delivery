So I want to add a new built-in function to meson, call it `summary`, that lets project authors print a clean structured config overview at the end of setup. Right now there's no good way to do this, you end up scattering `message()` calls all over the build script and the output is a mess, so I want a first-class mechanism for maintainers to communicate the important config choices to whoever's running `meson setup`.

The function should take key-value pairs either as two positional args (a single key and value) or as a dictionary, and optionally let me group them under a named section (a positional string, I think). It's gotta be callable multiple times so I can register config progressively as the build file runs, accumulating entries across sections. Oh and I want a keyword option, something like `bool_yn`, that renders boolean values as colored YES/NO instead of the raw `true`/`false`.

The formatted summary needs to print at the very end of the configuration output. If the project has subprojects, their summaries come first, sorted alphabetically, each with a header showing the subproject's name and version, then the main project's summary after. Within each group the keys should be right-aligned based on the longest key in that group. List values should put the first item on the same line as the key with the rest aligned underneath on following lines. Also if a subproject errors out before it ever registers any summary data, it should contribute nothing to the output, don't want half-broken headers showing up.

Last thing, make sure the AST interpreter over in the interpreter code recognizes `summary` too so static analysis tooling doesn't choke on it or reject build files that use it.
