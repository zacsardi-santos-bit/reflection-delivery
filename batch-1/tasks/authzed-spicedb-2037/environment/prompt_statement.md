I'm working on the SpiceDB codebase and need to make two related improvements to internal data structures.

First, there's a set type for tracking object-namespace-relation identifiers that currently lives in a shared utility package, but it's only ever used by the development membership subsystem. I'd like to move it into the membership package itself as a value type (rather than a pointer-based type). The new version should have a constructor that accepts optional initial elements, and should support the standard set operations — adding elements, checking membership, bulk-adding from a slice, intersection, subtraction, and union (where union is non-mutating and returns a new set). The membership tracking type in that same package should be updated to use the local version instead of importing from the shared package, and the old implementation and its tests in the shared package should be removed.

Second, the permission check dispatch logic needs a new purpose-built data structure that can accumulate relationship tuples and then produce batches of sub-problems to dispatch. These batches should be grouped by subject type, split by a configurable chunk size, and — importantly — subjects with conditional access (caveats) and subjects without should be placed into separate chunks. Each chunk should carry a flag indicating whether any of its subjects have caveats. The structure should also support reverse lookups: given a subject, return the list of resources that have a relationship with it, along with any caveat that applies to each individual resource-subject pair.

Both pieces need to live in their respective packages with the exact names and signatures that the rest of the codebase will use.
