I'm hitting a couple of bugs with the Rust-to-TypeScript type generation and I'd love a fix. First one is the tag attribute handling. When I annotate a Rust type with a tag attribute to add a discriminant field, the tag key comes out as a bare unquoted identifier in the generated TypeScript instead of a quoted string literal. That's wrong, TypeScript and JSON both want string literal keys in these spots, so the emitted tag key should always be quoted.

Second issue is trickier. I've got a pretty common pattern where one internally-tagged enum gets used as a flattened field inside a variant of another internally-tagged enum. Right now the output is either malformed or missing the intersection type entirely. What I'd expect is an intersection type that combines the outer variant's own fields with the inner enum's union of variants wrapped in parentheses, so the two get anded together correctly.

Also while you're in there, when a struct directly flattens an enum type, the generated declaration for that struct should come out identical to the declaration for the flattened enum itself, and I'm not confident that's holding up. Oh and one more, internally-tagged enum variants where all the named fields end up skipped shouldn't leave extra whitespace hanging around in the output.

The why here is simple, folks bridging Rust and TypeScript rely on this output actually compiling and behaving, and busted quoting plus broken nested-enum flattening means manual fixups every time codegen runs. Can you get the tag keys quoted as string literals and the nested tagged-enum flattening producing correct intersection types?
