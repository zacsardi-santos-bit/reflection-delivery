I'm building out reserved IPv6 address management for the doctl CLI and want it to hit feature parity with what we already have for reserved IPv4. Right now folks can create, list, get, delete, and assign/unassign reserved IPv4 addresses to servers, but there's nothing for IPv6, so anyone wanting stable movable IPv6 addresses for HA setups or server migrations has to fall back to the web interface or raw API calls, which kills any chance of scripting these workflows.

What I want is a set of compute subcommands for reserved IPv6 addresses. There should be a create command that reserves an address in a given region, and it needs to return an error if no region is passed. Then a list command that shows all reserved IPv6 addresses on the account, a get command for details on a specific address, and a delete command that permanently removes one (with a force flag so you can skip the confirmation prompt). On top of those, I need action subcommands to assign a reserved IPv6 address to a specific server by giving both the address and the server's numeric ID, plus an unassign to detach it.

Every command that returns address data should render it as a table with columns for the address, the region, and the associated server ID and name, and those last two should come back blank when no server is assigned. Please wire all these new commands under the compute command group, matching how the existing reserved IPv4 commands are laid out and registered so it all stays consistent.
