I'm working on gcsfuse and I want to pull our GCS object stat caching out of the third-party library it currently lives in and into our own internal package, because right now both the stat cache and the caching bucket wrapper are external which makes it painful to add features or fix bugs ourselves. The new package should live under an internal subdirectory dedicated to cloud storage caching, and anything that imported this from the external lib needs to point at the new internal package instead.

I need two pieces. First, a stat cache that maps object names to GCS object records, each with a time-based expiration. It should handle positive entries (object exists) and negative entries (object was not found, returned later as a not-found response). Insertions follow a "best wins" rule so an existing entry doesn't get replaced by one carrying an older object version, older generations don't clobber newer ones. Entries expire after a configurable TTL, and once the TTL elapses the entry counts as expired so we go back to GCS. When the cache hits its configured capacity it evicts the least recently used entry.

Second, a bucket wrapper that uses this cache. It should invalidate the relevant cache entry before any mutating op (create, copy, compose, update, delete), then insert the result on success. For stat requests it serves from cache on a hit and falls back to GCS on a miss, and it supports an option to bypass the cache entirely and fetch straight from GCS no matter what's cached. Oh and when GCS says an object isn't found, drop a negative entry in so subsequent stats for that same name also get answered from cache without another GCS round-trip.
