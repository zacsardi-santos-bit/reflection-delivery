I'm cleaning up how the cluster autoscaler reports what happens when it deletes nodes during scale-down, and right now it's frustrating because node deletion just hands back a plain error value. You can tell something broke but not which stage failed or which pods were the problem, so debugging means digging through logs instead of reading structured data that monitoring tools could actually query and react to.

What I want is for node deletion to return a structured result that classifies the failure by stage, so whether we failed to mark the node for deletion, failed to evict the pods, or the cloud provider rejected the delete. And when pod eviction happens I want a per-pod breakdown, tracking for each pod whether its eviction timed out, what error occurred if any, and whether it ultimately succeeded.

The drain function needs updating too so it exposes this per-pod eviction detail as a return value, plus an extra headroom duration parameter controlling how long to wait for pods to disappear after eviction. The results map should cover all pods, so ones that succeeded get marked as such (not timed out, no error), while ones that failed or timed out waiting to disappear reflect that with the right error and timeout info. Oh and when we check for pod disappearance after eviction, the different outcomes (API errors, pod still present, pod not found) each need recording accurately in that per-pod result. Finally, plumb this structured node deletion result type and the per-pod eviction results through the scale-down status reporting so downstream processors can get at it.
