I'm working on improving how the cluster autoscaler reports node deletion outcomes during scale-down. Right now, when a node is deleted, the system only returns a plain error value — you can tell if something went wrong, but you don't know what stage failed or which pods were involved. I'd like to enrich this so that node deletion returns a structured result that includes a classification of why it failed (e.g., failed to mark the node, failed to evict pods, or failed to remove from the cloud provider), and when pod eviction is involved, a per-pod breakdown of whether each pod's eviction timed out, what error occurred, and whether the eviction was ultimately successful.

The function responsible for draining a node should also be updated to expose this per-pod eviction detail as a return value, with an additional headroom duration parameter that controls how long to wait for pods to disappear after eviction. The results map should cover all pods — pods that succeeded should be marked accordingly (not timed out, no error), while pods that failed or timed out waiting for disappearance should reflect that with appropriate error and timeout information.

This structured eviction result should also be reflected in the scale-down status reporting so downstream processors can access it.
