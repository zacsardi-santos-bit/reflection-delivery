I'm running into a bug in the build scheduler where certain graph configurations cause builds to fail or hang. The scheduler tries to merge edges between different build graph vertices that share the same cache key as an optimization, but under specific ordering conditions, these merges can create cycles in the graph even though the original graph is acyclic. I need the scheduler to detect when an edge merge would create a cycle and avoid it — choosing the safe merge direction instead of blindly proceeding. This needs to work both for the simple case of two vertices whose edges would form a cycle when merged, and for the more complex case where a vertex has already been merged multiple times through different owners and a further merge through one of those owners would introduce a cycle. In both cases, the build should complete successfully and return the correct result.
