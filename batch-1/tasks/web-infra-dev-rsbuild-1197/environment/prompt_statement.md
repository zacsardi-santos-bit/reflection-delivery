I'm hitting a few related snags with SVG minification and image compression in the Rsbuild e2e tests and could use a hand cleaning them up. Right now the SVG processing tests all live in one shared test file that configures its plugins inline, which is fragile and doesn't reflect how a real project actually consumes the build tool. I want to split these out so each SVG test case reads its plugin config from its own build config file sitting in the test case directory, so tests don't have to pass plugins manually anymore.

Two SVG minification bugs are biting me. First, when an SVG that declares a viewBox gets optimized during the build, the viewBox attribute is being stripped out. It needs to survive into the compiled output so the rendered component keeps the correct width and height (layout) info, otherwise I get visual regressions that are a pain to track down. Second, when an SVG contains elements with IDs (think a gradient definition), those IDs should get a prefix derived from the source filename in the compiled output. That way multiple SVGs don't collide on duplicate element IDs, another one of those hard-to-debug things. So the expected behavior is an element ID automatically prefixed based on the source file name.

Also the image compression test needs reworking. Instead of checking internal build statistics (which behave differently across bundler providers), I want it to directly compare the output file sizes against the original source files and confirm they're smaller after compression. So the JPEG, PNG, and SVG output files should all come out smaller than their originals. And oh, the compression itself should be configured in a dedicated build configuration file per case rather than passed inline in the test, same idea as the SVG split.

So basically, set up the build config files for each of these test case directories and make the SVG minification preserve viewBox and add the filename-based ID prefixes. Restructuring like this mirrors real usage and keeps things maintainable.
