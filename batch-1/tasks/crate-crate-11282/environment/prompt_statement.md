I'm adding privilege enforcement to our database catalog views, the low-level system views that expose metadata about tables, columns, functions, schemas, and constraints. Right now they totally ignore the privilege system, so any user, even one with zero granted privileges, can query these views and see metadata for every object in the whole database including schemas, tables, functions, and columns they've never been granted access to. That's a real isolation problem because a restricted user can discover the existence of objects they shouldn't even know about, and it leaks sensitive info about the database structure. While an unprivileged user can't directly read data from a restricted table, they can still find out it exists, which breaks schema-level isolation.

What I want is for these catalog views to filter their results based on the querying user's privileges. If a user hasn't been granted read access to a table, they shouldn't see any entry for that table in the views for tables, columns, or constraints. Same idea for schemas: no schema grant means they don't see the schema or its functions in the relevant views. Once a read privilege gets granted, whether on a table or a schema, the entries should become visible and show the exact same data a superuser would see. Also creating tables or functions in a user-created schema shouldn't expose those objects to unprivileged users through the catalog either.

One exception: the built-in catalog schema (the one the database itself uses for system metadata), along with the other well-known internal system schemas, should always be freely accessible to everyone without any explicit grant, similar to how the existing built-in system schemas already get treated. So accessing the catalog schema or any of its internal tables should never get rejected for missing privileges.

Oh and there's a naming cleanup too. There's an internal constant defining which schemas are read-only system schemas, and it needs renaming to better reflect its purpose, specifically to distinguish system schemas from other read-only schemas, and all references to it should get updated accordingly.
