I'm working on adding proper privilege enforcement to the database catalog system. Right now, even users with no granted privileges can query the catalog views and see metadata about every table, column, function, schema, and constraint in the entire database — including objects in schemas they have no access to. This means a restricted user can effectively discover the existence of tables and schemas that should be hidden from them.

What I need is for the catalog views to filter their results based on the querying user's privileges. If a user hasn't been granted access to a table, they should not see any entry for that table in the catalog views for tables, columns, or constraints. If a user hasn't been granted access to a schema, they should not see that schema or its functions in the relevant catalog views. Once a privilege is granted, the entries should become visible and show the exact same data a superuser would see.

There's also a related change needed: the built-in catalog schema (used by the database itself for system metadata) should be freely accessible to all users without requiring any explicit privilege grant, similar to how other built-in system schemas are already treated. This means accessing the catalog schema or any of its internal tables should never be rejected due to missing privileges.

Finally, there's an internal constant that defines which schemas are read-only system schemas — this constant needs to be renamed to better reflect its purpose (specifically distinguishing system schemas from other read-only schemas), and all references to it should be updated accordingly.
