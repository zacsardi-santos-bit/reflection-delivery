I'm working on the alerts listing page in our cloud monitoring UI over in the frontend, and right now it just dumps every alert into one flat table with no way to narrow anything down. Once you've got hundreds of alerts spread across different services it's basically impossible to find the one you care about, so I want to add search and filtering plus clean up the table itself.

For filtering I need a text search input up above the table with the placeholder "Search for Alerts" that filters the visible rows by alert name as you type. Next to that I want a service type filter dropdown where you can pick one or more services and only see alerts tied to those, and also a status filter dropdown with "Enabled" and "Disabled" options so you can narrow by current status.

On the table side, the columns should be Alert Name, Service, Status, Last Modified, and Created By. The alert name in each row needs to be a clickable link straight to that alert's detail page instead of making people dig through the action menu. The Status column should show a colored icon (green for enabled ones) so you can eyeball the state fast. Oh and the Service column should render the service display name, not the raw service type code, and the date should be in a human-readable format.

Also I want the table pulled out into its own reusable component that takes props for the alerts, a loading state, an optional error, and the services list, so the listing page component can just handle the filtering logic. If there's an error loading alerts, the error message should show up in the table area so it's actually visible.
