I'm working on the scalar conversion layer that translates query engine scalar values into PostgreSQL-compatible types. The conversion already handles timestamps in microsecond and nanosecond precision, but it completely misses second-level precision timestamps. When a second-precision timestamp comes in, it falls through to a generic catch-all case instead of being properly converted to a timestamp, so the output shows a raw epoch number rather than an actual date and time. I need to add support for second-precision timestamps without a timezone so that they are correctly converted to the appropriate date/time representation, consistent with how the other timestamp precisions are handled.
