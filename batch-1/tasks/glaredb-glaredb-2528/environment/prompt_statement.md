So when I query tables that use second-precision datetime columns (think data sources that store datetimes at second-level precision, which is common and totally valid), the output shows raw epoch numbers instead of readable date/time values. It makes the data basically unusable without manual post-processing which is annoying.

What I want is for second-precision timestamps to be converted to proper date/time representations during scalar conversion, exactly the way the micro and nano precision cases already are. So I need a dedicated handler for the second-precision-no-timezone variant added alongside the existing timestamp arms, converting the epoch seconds into the appropriate timestamp value rather than letting it hit the fallback. Once that's in, queries over second-precision datetime columns should come back as formatted timestamps, not numbers. Just keep it consistent with how the other precisions are handled so the behavior lines up across the board.
