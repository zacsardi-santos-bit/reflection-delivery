I'm building out the docs publishing step of our Airflow release tooling and I need a utility class that handles pushing documentation packages up to cloud object storage. Right now there's no automated path for this and I keep doing it by hand, so I want something that discovers all the doc packages sitting in a local archive directory and lists them out. If that archive directory doesn't actually exist, I want it to exit with an error cleanly rather than blowing up with some unhandled exception.

I also need to be able to skip certain packages, so let me pass a comma-separated list of names or partial names to exclude. The matching should be a substring match, and here's the annoying bit, dots in my exclusion patterns need to be treated the same as hyphens in the package names (the naming is inconsistent between the two). Oh and if after all that filtering there's nothing left that's eligible to publish, it should also exit with an error instead of silently doing nothing.

Two publishing modes here. First is a versioned stable mode where each eligible package goes to both a version-specific path and a "stable" alias path at the destination, and the version comes from reading a file in the package's own source directory. Second is a bulk mode where I just mirror each package's whole directory to its corresponding destination path. In both cases I want the utility to track which source-to-destination path pairs it actually processed so I can inspect afterward what got done.

Last thing, there's an overwrite flag. If a package already exists at the destination and overwrite is off, just silently skip it, don't re-publish. If overwrite is on, always publish it regardless of whether it's already there. This whole thing is about letting the release team automate docs deploys reliably with control over what ships, stable aliasing, and some safety against clobbering stuff by accident.
