I'm hitting a wall with the variable-aware if-then-else pipeline step whenever a condition uses a relative date and the date value is a template variable placeholder instead of a real date. The setup is a date-bound filter where the range is expressed as a relative date structure (a duration plus an offset, like "1 year until <some start date variable>"), and the moment the date field holds a placeholder string rather than an actual date, model validation blows up at parse time and complains the placeholder is an invalid value. So I can't define conditions like "filter rows where the date falls in the previous year relative to a user-supplied start date," because those user dates only get resolved at runtime.

What I want is for the variable-aware version of this step to accept relative date conditions where the date portion is a template variable placeholder, no validation error, same as it already handles simple non-relative date conditions today. Also this needs to work when multiple such relative date conditions get combined with AND logic, those compound cases shouldn't fail validation either. The raw placeholder strings should stick around on the parsed model so they can actually be resolved later. And then the step's variable resolution method should correctly substitute the placeholders both when the condition's value is a plain template string and when it's a relative date structure whose date portion contains the placeholder. Basically dynamic date ranges driven by runtime variables should just work in if-then-else steps, right now any step mixing date-bound conditions with variables is unusable.
