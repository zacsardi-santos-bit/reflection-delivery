I'm working on the network flow monitoring agent that dedupes traffic seen across multiple interfaces, and the deduplicator right now has two modes: one drops duplicate flow observations, the other lets them through but tags them with a duplicate flag. I want that "mark as duplicate" mode gone entirely so dedup always just drops duplicates, full stop, no option to mark-and-pass. It adds complexity without real benefit since downstream consumers have to check the flag themselves and it can inflate metrics in weird ways. So after this change, consumers never need to worry about whether a flow is a duplicate.

There's also this related thing: when a flow passes through and gets forwarded, it still carries the interface identifier and direction from whatever interface first observed it. Those fields don't mean anything after dedup (the flow could've been seen on any of several interfaces), so I want them replaced with well-defined sentinel "unset" values so it's clear they're not meaningful. Keeping them set just inflates metric cardinality with random per-interface values and produces confusing or inconsistent label values, oh and it makes exported metrics unpredictable.

Also, while I'm in here, the data-link layer address fields (the device-level identification bits) are no longer needed for flow tracking, so drop them from the flow identity structure entirely.
