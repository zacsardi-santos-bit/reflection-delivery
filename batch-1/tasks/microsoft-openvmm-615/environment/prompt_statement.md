I'm working with a mesh-based channel library that passes messages between components using serialization. The channel types currently require that message types be thread-safe, but this restriction doesn't make sense for channels that serialize messages rather than moving them across threads. I have some types that hold non-thread-safe data (like raw pointers) but are fully serializable, and I can't use them with the channel API right now.

I'd like the channel types — both the sender and receiver sides — to work with any serializable type, without requiring that the type also be thread-safe. Converting a receiver to a port and back should work for non-thread-safe types as well. Sending a message of a non-thread-safe but serializable type and receiving it back should yield the correct value. The thread-safety requirement should be dropped wherever it appears in the channel implementation, since messages are encoded at send time and decoded at receive time anyway.
