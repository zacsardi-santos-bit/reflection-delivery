I'm working on a storefront and want to stop leaning on the upstream library for a few order-history and mini-cart UI pieces so we can actually customize them in-project. Right now there's no local order row component and no local detailed order view, and the order history page pulls the order row straight from the external package. I want a locally-defined order row instead, and I want the history page updated so it imports that local one rather than the upstream version.

The order row should show the order number, date, a formatted total, a thumbnail gallery of the ordered items, a status badge, and a progress bar for order progress. It's gotta be expandable, so clicking a toggle button collapses or expands the detailed view. When it's expanded and not loading, show the full details (shipping address, shipping method, billing address, payment method info, the ordered items list, and a totals summary with a Print Receipt button). While it's loading though, keep that detailed area empty. Oh and when an order's status is "Complete" or it has shipments present, the progress bar should read "Delivered". Each item in the details view needs a product thumbnail (or a placeholder if none's available), the product name, selected options, quantity, price, and a Buy Again button.

Also I need a locally-defined mini-cart item component, and the mini-cart product list should use it. It shows the product thumbnail, name, the selected/configurable options, quantity, price, and stock status, plus a delete button. Out-of-stock products should surface an "Out-of-stock" indicator. It should also support showing a variant-specific thumbnail when it's configured to do that. And the delete button needs to be disabled while a deletion's in progress.

The whole point here is owning these components locally so we can tweak appearance and behavior without depending entirely on upstream, which makes the storefront way easier to maintain.
