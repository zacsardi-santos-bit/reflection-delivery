I'm hardening the stop/restart path in Home Assistant so we don't nuke the database when a schema migration is mid-flight. Right now if someone hits stop or restart while the recorder is migrating, we just barrel ahead and shut down, and that can corrupt the db or lose data. I want both the stop and restart services to check whether a migration is currently running and flat out refuse if one is, raising a clear error that explains why we're bailing.

While I'm in there I also need a helper that any part of the system can call to check migration status. Key thing is it has to be safe to call even when the recorder component isn't loaded, in that case it should just return false, and when the recorder is loaded it should report the real migration state (whether it's actively doing a schema migration). Put that helper somewhere the recorder migration code lives, roughly `@homeassistant/components/recorder/migration.py`, so other components can import it.

For restart specifically, keep the existing config validation, so if the configuration is invalid it should raise a clear error before restarting. The stop service though does not need a valid config, only the migration check applies there, don't make stop depend on config being good.

Oh and both the stop and restart actions should fire with a short async delay rather than executing immediately inline. Also when restart comes in remotely over the WebSocket API it should be called in a blocking fashion to avoid the race conditions we've been seeing. The core service handlers for this live around `@homeassistant/core.py` (or the homeassistant component services), and the WebSocket restart command is over in the websocket API side.
