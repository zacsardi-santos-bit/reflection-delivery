I'm working in the OData service inquirer package and need to add a path for connecting to on-prem SAP ABAP backend systems, not just the direct OData service URL we support today. Lots of folks manage their services through a system catalog and don't know the full service URL up front, so I want to let them pick an on-premises ABAP SAP system as a data source type and then walk them through entering the system URL, an optional SAP client number, and username/password credentials when the system actually requires auth. Once we're connected I want them to see and choose from the OData services registered in the system's catalog, and it'd be great if service selection supported type-ahead autocomplete search when enabled since these lists get big. Also there should be a prompt to optionally save the connection under a name, and I want it to suggest a sensible default derived from the URL while auto-generating a non-conflicting name when that system URL already exists in storage. Oh and show a warning when no services come back, or when the selected service isn't the UI type.

On the validation side, the internal API in the connection validator is using positional boolean params right now which is hard to read and extend, so I want to swap both the URL validation method and the auth method over to structured options objects instead. For the URL validation one the options cover ignoring certificate errors, forcing re-validation, whether the target is a full system rather than a specific service URL, the SAP client, and the OData version. The auth method's options cover system mode, SAP client, and cert error handling. When we're connecting to a full system (not a service URL) the validator should use the lower-level provider approach that separates the base host URL from the service path. And when auth validation fails because the URL comes back not found, I want it to return a descriptive error string instead of just returning false.
