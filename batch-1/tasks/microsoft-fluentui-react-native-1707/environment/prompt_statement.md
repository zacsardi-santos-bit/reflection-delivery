I'm poking at the Avatar and Badge components in our React Native UI lib and their accessibility story is basically nonexistent. When Avatar renders, the outer container doesn't declare that it's an image, it's not flagged as accessible at all, and there's no label going out to screen readers. Worse, the inner views (the background and initials area) aren't hidden from the accessibility tree, so a screen reader will happily walk through each internal child and announce them one by one instead of treating the whole Avatar as one thing. That's the opposite of what I want.

What I'm after is Avatar presenting itself as a single accessible image. So the outer container should be marked accessible, carry an image role, and expose an accessibility label, and when nobody passes a label in it should default to an empty string rather than undefined. Then the inner container needs to be pulled out of the accessibility tree (mark it as not accessible / hidden from assistive tech) so it doesn't get announced separately. Basically one coherent image element, no opaque sub-views leaking through.

Badge has a smaller version of the same gap. Its displayed text isn't explicitly marked as accessible, so please flag the Badge's text element as accessible too.

Why bother? Folks relying on screen readers or other assistive tech currently can't navigate or make sense of these components, and I'd like them to be usable by everyone with the Avatar reading as a meaningful single image instead of a pile of sub-views. Can you wire up the right accessibility props on both components?
