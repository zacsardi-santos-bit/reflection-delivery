I'm adding a lightweight built-in auth manager to Apache Airflow so people don't have to wire up a whole external identity provider just to run a dev or test setup. Right now that's way more painful than it should be, and I want something self-contained that ships with Airflow, works out of the box, and gets selected via config.

Here's the shape of it. Admins declare user accounts, each with a role, and the manager auto-generates passwords and writes them to a local file. There are four roles with a clear hierarchy. The admin role grants full access to everything. The op (operator) role gets read and write on operational resources like configuration, connections, datasets, pools, and variables, plus everything the lower tiers can do. The user role gets full DAG access including writes, plus read on datasets and pools. The viewer role is read-only on DAGs, datasets, and pools, plus access to UI views. Any logged-in user can hit UI views and custom views no matter their role, but unauthenticated requests get denied across every resource type.

I also need a user model that stores a username and a role and exposes them through the standard interface methods (get name, get id, that kind of thing).

For the web side there's a login page showing a "Sign in" heading, a short instruction line reading "Enter your login and password below:", and labeled fields for username and password. Logout should clear the session and redirect back to the login page. Submitting credentials validates against the stored passwords, and on success it redirects to the main Airflow dashboard, on failure it bounces back to the login page with an error flag set. Viewers and above should be able to reach UI views once they're logged in.

This makes Airflow much easier to set up and evaluate for developers and small teams who just want to run the scheduler and poke at their DAGs without standing up an IdP.
