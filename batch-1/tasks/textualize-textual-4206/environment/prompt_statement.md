I'm working on a Textual TUI and keep running into the same annoying pattern where a widget's child layout depends on some reactive value, and every time that value changes I have to hand-write a watcher method that tears down and rebuilds the children manually. That basically duplicates the logic I already have in my compose method, and it's error-prone. The reactive system can already trigger repaints or a layout pass when a value changes, but there's just no option to say "rebuild all my children when this changes."

What I want is a recompose mode on reactives, so when I declare a reactive attribute with that flag turned on, any change to the value makes the owning widget throw away its current children and rebuild them from scratch using the same child-building method it uses for the initial mount. I'd also like the refresh mechanism to take a recompose flag so I can trigger this explicitly and programmatically, not just via reactive changes.

Couple things that matter: the recompose has to be atomic, remove the old children and mount the new ones without any visible flicker in between. And it needs to play nice with the existing data binding, so bound reactive values on the parent still flow through correctly to the freshly recomposed children. Right now if the child structure depends on reactive state I'm stuck writing manual watchers, and I'd rather have one compose method serve both the first mount and every later update.
