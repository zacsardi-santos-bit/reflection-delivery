I'm building a Textual TUI app where some widgets need to completely rebuild their child widgets whenever a reactive attribute changes. Right now the reactive system can trigger repaints or layout passes, but there's no way to automatically rebuild children when a reactive value changes. I have to write watcher methods that manually manage child widgets, which duplicates logic I already have in my child-building method.

I'd love a way to declare that a reactive attribute should trigger a full recomposition — removing all existing children and rebuilding them — whenever the value changes. Ideally this would also work with the existing data binding feature so that bound reactive values correctly flow through to recomposed children. The display refresh mechanism should also accept a flag to trigger recomposition explicitly, for cases where I want to do it programmatically. The recompose should happen atomically so there's no visual flicker between the old and new children.
