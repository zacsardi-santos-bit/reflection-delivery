I'm working with Apache Iceberg views in Spark and I've noticed two issues. First, there's no support for modifying view properties after a view is created — I can't use the standard SQL statements to set or remove key-value metadata on views the way I can with tables. I'd expect to be able to add, update, and remove custom properties on a view after creation, and have those changes persist when I reload the view from the catalog.

Second, certain internal or reserved properties — like the format version and the internally-managed property that tracks query column names — should be protected from user modification. Trying to set or unset these should produce a clear error. Also, trying to remove a property that wasn't set in the first place should produce a meaningful error unless an "if exists" qualifier is used. When unsetting a reserved property even with the "if exists" qualifier, it should still fail with an appropriate error, since it is explicitly reserved (not just absent).

Additionally, there's an internal naming inconsistency: the property key used to store the column names from a view's defining query should be prefixed to indicate it's Spark-specific internal metadata, rather than appearing as a generic user property key.
