I'm migrating the Azure DNS provider in cert-manager off the deprecated Azure auth library and onto the modern Azure SDK, since the old one is being phased out and it's a maintenance and security drag. The whole authentication layer needs to change over to how the current SDK obtains credentials and acquires and refreshes tokens. While I'm in there, Microsoft retired the Azure German Cloud environment so I need to drop it entirely, any attempt to use that environment name should now come back as an error rather than being silently accepted. Also I want the tenant ID validated right at init time so operators get an actionable error at startup if it's malformed (contains spaces or otherwise busted) instead of some confusing runtime failure later when the controller actually tries to talk to Azure DNS.

The auth needs to support workload identity too. When the environment indicates a federated token file is available and no client ID is explicitly set, the provider should use workload identity credentials, and those creds should automatically grab a fresh token when the current one expires by re-exchanging the federated token with the authorization server. Oh and the client ID from the managed identity config section should override any ambient client ID when requesting tokens, and the tenant ID should show up lowercased in the token endpoint URIs.

One more thing on the plumbing side: the credential init function should take the new SDK's client options type instead of the old environment type, and the subscription ID shouldn't be a parameter to that function anymore.
