I'm working on the AWS Load Balancer Controller and hitting a cluster of issues I could use help fixing.

First one is nasty and intermittent: OIDC auth breaks for some customers for no obvious reason. Turns out some secret management tools append a trailing newline (or other trailing whitespace) when they write client credentials into Kubernetes secrets, and we're using that value verbatim including the newline, so auth fails silently even though the secret looks fine when you inspect it. I want us to strip trailing control characters off the client secret value when building the OIDC authentication config so those extra chars don't sneak through.

Second, listener attributes. When multiple ingresses in the same group each set a listener attribute via annotation and two of them give different values for the same attribute key, we currently bail with an error. But we also support setting listener attributes via IngressClass parameters, and when an IngressClass parameter already defines the value for that attribute, the conflicting annotation values should just be ignored instead of failing. The IngressClass config is the authoritative source and should win, no error raised.

Third, the error message we show when multiple ingresses define conflicting values for the same load balancer attribute key is too generic, it doesn't say which kind of resource is involved so it's hard to diagnose. I want that message updated to clearly indicate the conflict is about load balancer attributes.

Last thing is observability. We've got no way to measure how long a pod's readiness gate takes to flip to healthy after it's added to the load balancer. So I want to add a metrics collection interface the resource manager can use, and when a pod's target health condition transitions from unhealthy to healthy we record how long that transition took, emitting the metric on each such transition. Oh and please include a mock implementation of that metrics interface so we can use it in tests.
