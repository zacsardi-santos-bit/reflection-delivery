That's an invalid state since a list item container is only supposed to hold list-compatible content, and I can see the structure is wrong when I look at the rendered HTML. It doesn't blow up loudly, it just silently breaks and makes later editing behave weird.

What I want is for the block-type conversion logic to place the new element outside the list rather than nesting it invalidly inside a list item. The whole list structure and nested hierarchy above the cursor should stay exactly intact, and the new paragraph should keep the indent level of the original list item (so one level of indentation in this case). After that conversion I want to be able to type in the paragraph normally and press Enter to get a plain new paragraph underneath with no extra indentation. This matters because outline-style docs that mix nested lists with regular paragraphs are super common, and right now you can quietly wreck your document without noticing. Can you fix the conversion so it always produces a valid, well-structured tree no matter what list nesting surrounds the cursor?
