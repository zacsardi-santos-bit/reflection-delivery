I'm poking at the zsh-autosuggestions plugin and hit two things I want fixed together. First one is perf: right now we re-bind every widget on every single precmd (so basically every prompt render), which is nice for playing well with other plugins that wrap widgets but the cost is real, especially for folks with big widget lists or a pile of plugins loaded. I want a config option that lets people opt out of that automatic re-binding. When the option is set, changes to the widget list shouldn't take effect on their own, and instead I should be able to manually kick the rebind by calling the internal bind function directly. After I trigger that manual rebind, the updated bindings need to actually work correctly going forward, so the manual path has to be a real substitute for the automatic one, just on my schedule.

Second thing is async mode. When async suggestion fetching is on and I start typing (which fires off a background fetch), hitting Ctrl-C is supposed to cancel the current line and drop me on a fresh empty prompt. But the current async implementation, which leans on a pseudo-terminal, makes Ctrl-C misbehave in that state instead of cleanly starting over. I want async refactored so Ctrl-C properly terminates the prompt and begins a new one, showing the aborted input on its own line followed by the new empty prompt underneath. Basically make interrupt behave like you'd expect in an interactive shell even mid-fetch.
