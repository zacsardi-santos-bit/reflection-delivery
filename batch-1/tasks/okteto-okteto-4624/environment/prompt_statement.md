I'm working on the Okteto CLI and want to add a manifest validation command so folks can sanity-check their config files before actually deploying. Right now there's no way to validate a manifest without triggering a real deployment, which means typos and schema mistakes only blow up way too late in the loop. I want to catch that stuff early.

So I need a validate command that takes a manifest file path and exits cleanly with no error when the file is valid, and returns a meaningful error (with a failure exit status) when it's broken. Broken covers a bunch of cases: an empty file, a file with YAML syntax errors, a file with invalid values inside specific sections, or one that references unknown top-level config keys that don't exist in the schema. Oh and pointing it at a file that doesn't exist should error out too.

I also need integration test helpers to make the end-to-end tests actually runnable. That's a config struct holding fields for the working directory, the manifest path, and the home directory, plus a function that invokes the CLI validate command and surfaces whatever errors come back. And I need sample manifest fixtures, both valid and deliberately broken examples, so those tests can run against real files on disk.
