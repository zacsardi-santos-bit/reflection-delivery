So I'm working on a Telegram bot with teloxide and I keep hitting a wall with the command derive macro, it only lets me register one name per command variant. I want alternate names for the same command, like a short `/s` for `/start`, or a Cyrillic `/помощь` standing in for `/help`, and right now there's no clean way to do that without duplicating all my handler logic or hand-rolling a parser.

What I want is to declare alternative names right on a command variant with an attribute. When it's just one alt name I'd use a single-value attribute form, and when I need several I'd use an array-style form, and both need to allow non-ASCII chars for localization. These aliases should be parsed exactly like the primary command name, so invoking any of them hits the same variant. They should also show up in the generated help message next to the primary name as a comma-separated list before the description, so something like `/help, /h — Show help`.

Oh and I also want a "hide aliases" flag on a variant that keeps the aliases working for parsing but drops them from the help text, handy for shorthand forms I don't want cluttering the listing. It should combine with the existing whole-command hide too, so a hidden command with aliases still parses but stays out of the help output. And if I slap hide-aliases on a variant that has no aliases at all, it should just be a no-op, no error and no change to what gets printed. This all lives in the derive macro side of things, btw, so the attribute parsing, the parser acceptance, and the help formatting all need to line up.
