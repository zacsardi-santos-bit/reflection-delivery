I'm chasing a bug in how our workload controller reacts to admission check rejections, specifically in the reconcile path in `@pkg/controller/core/workload_controller.go`. Right now when any admission check gets rejected we immediately mark the workload as finished, and that's fine for a workload that never got off the ground, but it's wrong for one that's already admitted with quota reserved and actively using cluster resources. Those need to go through the normal eviction lifecycle first so other components can react before we call it done, otherwise we bypass cleanup and can leave cluster state inconsistent.

So what I want: if an admission check is rejected on a workload that's already admitted, don't mark it finished yet. Instead set an eviction condition on it and wait for eviction to actually complete. While that eviction is in progress the admitted status has to stay as-is, it should stay true and not get prematurely cleared. Only once eviction finishes do we mark the workload as done with a reason pointing at the rejected admission check, and at that point the admitted condition gets cleared.

For workloads that were never admitted (no quota reservation, not in an admitted state), keep the existing behavior, just directly mark them finished on check rejection, don't change that path at all.

Oh and one more thing, when a workload's quota reservation gets cleared, I need the admitted condition recalculated so it reflects the new state correctly rather than being left stale.
