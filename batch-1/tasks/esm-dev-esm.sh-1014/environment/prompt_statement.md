I'm reworking how the server package for our JavaScript CDN stores build metadata. Right now it's all JSON, which is verbose and honestly kinda slow to parse once you're doing a metadata lookup on every request, and as we serve more and more module builds that overhead really adds up. I want to switch to a compact custom binary encoding so we can stuff this stuff into a lightweight embedded key-value store instead of the general-purpose file-based thing we've got now.

So what I need is a pair of functions, an encoder and a decoder, that turn a build metadata record into a compact byte representation and back again with full round-trip fidelity. The metadata tracks a handful of properties per build: whether the module uses the CommonJS format, whether it's got associated CSS, whether it's types-only, whether it exports a default, the TypeScript definition file path associated with it (the definitions path), and the list of other modules it imports.

Couple things I care about for correctness. Encoding a fully populated record should give me back a non-empty byte sequence, and decoding that should return the exact same values with nothing lost or corrupted. And the empty case matters too, so if I encode a zero-value record and decode it, all the boolean fields should come back false, the definitions path should be empty, and there should be no imports listed. Round-trip both ways, populated and empty.
