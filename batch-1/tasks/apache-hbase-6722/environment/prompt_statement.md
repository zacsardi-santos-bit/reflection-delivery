I'm working on the HBase region balancer and hit a gap I want to close. Right now when the balancer distributes regions across the cluster it can drop the internal metadata catalog table regions onto the same region servers that host ordinary user and system table regions, and that causes contention and latency problems for metadata ops, especially under heavy load where a busy metadata server can spike latency cluster-wide.

I want to add a configuration flag operators can turn on that tells the balancer to isolate the metadata table onto its own dedicated region servers, so no server hosting metadata regions also hosts regions from any other table. When it's enabled the balancer shouldn't just avoid placing them together, it should actively move regions until that isolation constraint is actually satisfied.

The tricky part is this has to play nice with the existing replica distribution behavior (spreading region replicas across distinct servers), so both constraints need to be satisfiable at the same time, not one clobbering the other.

Also the balancer needs a way to report whether table isolation is currently active so callers can query it, and this should replace the older internal checks that conflated isolation with other balancing concerns, so some existing methods should get renamed to reflect that this isolation concept is now distinct. Oh and a utility method that verifies a given table's regions are properly isolated from all others would help too. The balancer code lives under `@hbase-balancer/src/main/java/org/apache/hadoop/hbase/master/balancer`, so wire it in there.
