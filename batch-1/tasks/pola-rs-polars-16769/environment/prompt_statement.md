I'm wrapping up a breaking change in Polars around how left joins handle their key columns by default and I need help pushing it over the line. Here's the deal: the old default was to coalesce, meaning a left join would automatically merge the join key columns from both sides into a single output column and silently drop the right side's key, plus it'd emit a deprecation warning whenever this happened implicitly. That deprecation window is done now, so I want the new non-coalescing behavior to be the permanent default.

So with the new default, a left join done without explicitly asking for coalescing should keep both the left and right join key columns in the output, same as inner joins and the other join types do. The right-side key column should show up with a disambiguating suffix appended when it'd otherwise collide with the left key's name. Folks who actually want the old single-merged-column output need to opt in explicitly by passing the coalesce option, and when they do it should behave the old way (one merged key column, no right-side key present).

Also, and this is important, the deprecation warning for doing a left join without specifying a coalesce preference needs to go away entirely, no warning at all since this is just standard now. Any existing code relying on the old coalescing default will need to add an explicit coalesce flag to keep working the way it did.

This has to be consistent across both streaming and non-streaming execution, and apply to both the eager and lazy APIs. Expect the output shapes and column counts for left joins without explicit coalescing to go up since the right-side key column is now included in the result. The why here is that people kept getting confused by left joins quietly dropping the right key, which made it hard to tell which values actually matched, so making the default non-coalescing makes the output predictable and consistent with the rest of the join API.
