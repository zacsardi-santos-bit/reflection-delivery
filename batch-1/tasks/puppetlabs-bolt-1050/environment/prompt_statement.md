I'm cleaning up the inventory v2 plugin system in Bolt because right now target-discovery plugins and config plugins use two totally different syntaxes and it's confusing. Target plugins get declared under their own separate group-level key with a plain identifier, while config plugins go inline in their section with an underscore-prefixed marker. I want to unify these so both kinds use the same inline underscore-prefixed syntax within their respective sections, so target plugins should be declared inline in the standard targets list the same way config plugins already are, instead of through a dedicated group-level key.

As part of this I also need to rename the hook names plugins register to advertise their capabilities so they're more consistent and descriptive. The built-in plugins for prompting users for input, for querying PuppetDB, and for reading Terraform state files all need their hook names and the matching method names updated, and when any of those plugins get used the system should call the renamed method on the plugin.

On validation, if someone still uses the old separate-section (group-level key) syntax for target plugins, I want a clear error explaining that syntax is no longer valid and pointing them toward the new inline format so they can migrate. Also when a plugin gets referenced for a capability it doesn't support (like using a config-only plugin for target discovery or the reverse), raise a descriptive error that names the specific plugin and the missing capability. The whole point is users shouldn't have to learn two syntaxes depending on whether they're supplying targets or config values, and better errors make debugging inventory files way easier. Relevant code lives around the inventory and plugin handling paths.
