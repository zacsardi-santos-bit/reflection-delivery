I'm working on updating the inventory plugin system in Bolt to make it more consistent. Right now, target-discovery plugins and configuration plugins use two completely different syntaxes in inventory files — target plugins have their own separate section at the group level with a different identifier style, while config plugins use an underscore-prefixed inline marker. I'd like to unify these so both kinds of plugins use the same inline syntax within their respective sections.

As part of this, the hook names that plugins register to advertise their capabilities also need to be updated to reflect the new, more consistent naming. The built-in plugins for prompting users for input, querying PuppetDB, and reading Terraform state files all need their hook names and corresponding method names updated to match. When any of these plugins are used, the system should call the renamed method on the plugin.

On the validation side, if someone uses the old separate-section syntax for target plugins, the system should raise a clear error message explaining that the syntax is no longer valid and pointing toward the new format. Also, when a plugin is referenced for a capability it doesn't support — for example, using a config-only plugin for target discovery or vice versa — the system should raise a descriptive error naming the plugin and the missing capability.
