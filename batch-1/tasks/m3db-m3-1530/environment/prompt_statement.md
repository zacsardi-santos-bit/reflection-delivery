I'm working on adding caching support for field-existence queries in our index storage layer. We already cache results for regular expression and exact term queries, but we're missing the same support for queries that just check whether a specific field exists — these have no pattern, only a field name. Right now every field-existence check goes straight to the underlying segment even if we've already seen the same query before, which is wasteful.

I need to add a new query pattern type for field queries to the postings list cache, along with get and put methods that work without a pattern component. The read-through segment layer also needs to be updated so that field-existence lookups consult the cache on the way in and populate it on a miss, just like we already do for regexp and term queries. The cache bypass behavior should also be consistent: if caching is disabled via the existing options, field queries should bypass the cache too, and everything should degrade gracefully when no cache is provided at all. Field entries also need to participate in the normal LRU eviction and segment purge logic.
