I'm building an automated codemod to migrate Storybook story files into the new factory-based format, where meta and story declarations use factory method calls instead of plain object exports with type annotations. Right now anyone adopting the new format has to hand-rewrite their story files which is slow and error-prone across big projects, so I want this to handle the whole range of existing writing styles, both JS and TS, and spit out consistent output.

The main job is converting plain object exports into factory calls. For meta, the existing default export (whether it's a const declaration followed by a default export, or an inline default-exported object with no intermediate variable) becomes a factory call, and the variable should always be renamed to "meta" even if it was called something else. Each named export that's an object gets wrapped in a story factory method call on that meta variable. You'll need to add the import from the storybook preview config and merge it into any existing import from that same path, and oh, if the file already has a local variable named "config", alias the imported configuration so it doesn't collide.

It also has to deal with older function-style stories where the export value is a function rather than an object, converting those into the new factory story format with a render property. For TypeScript files, strip all the type annotations off meta and story declarations (both the type assertion variant and the satisfies type annotation variant, covering the common ones) since types are inferred now, and drop the type imports from storybook packages that aren't needed anymore. Importantly the output should be identical no matter which TypeScript annotation syntax was originally used.

Export the migration as a named function that takes a file info object (source content plus path) and returns a promise resolving to the transformed source code.
