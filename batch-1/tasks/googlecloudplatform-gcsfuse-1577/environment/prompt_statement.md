I'm working in the gcsfuse codebase and need to add a configurable max entry count to the directory inode's type cache. Right now that cache grows without bound, there's no way to cap the number of entries or turn it off from config, and the entry type constants live inside the inode package where nothing else can reuse them. I want to fix both of these together.

First the config side. Alongside the existing TTL setting I want a new field for the maximum number of entries the type cache can hold. Setting it to zero disables the cache entirely (regardless of TTL), a negative value means unlimited, and when it's absent from the config file a sensible default kicks in. The parser needs to validate this field and return a clear exported error constant for invalid values, and the JSON serialization of the config struct should include the new field too.

Second, I want to move the filesystem entry type constants (regular file, explicit dir, implicit dir, and add two new ones, symlink and a nonexistent value for negative caching) out of the inode layer into a dedicated shared metadata package. The type cache implementation should live there too and implement a clean interface with get, insert, and erase operations, evicting the oldest entry when full.

The directory inode constructor should take the new max-entries param, and the cache should stay consistent after every lookup, listing, creation, clone, and deletion, reflecting the right entry type for each child name. Oh and when the cache is disabled (zero max-entries or zero TTL), any get into it should just return the unknown type value.
