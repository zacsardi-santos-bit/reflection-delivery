I'm refactoring the outputs system in our multi-cloud security scanner and the way we turn a raw check result into a reportable finding is driving me nuts. Right now there's a standalone helper that manually maps provider-specific fields onto a legacy finding model, so all the logic (how to show the auth method, which field is the resource name vs the resource UID, what counts as region for Kubernetes namespaces, account metadata) is buried in that helper instead of living on the finding itself. I want a new unified finding model that replaces the legacy one and can build itself straight from a provider plus a check output via a class method, handling all four providers we support.

For AWS the auth method should be prefixed "profile:", resource name comes from the resource ID and resource UID from the ARN. For Azure the auth method is the identity type and identity ID joined by a colon ("{identity type}: {identity ID}"), with resource name and id from the check output. For GCP prefix the auth method with "Principal:" and pull account info from the project object. For Kubernetes an in-cluster context shows as "in-cluster" (otherwise "kubeconfig"), region reads "namespace: {name}", and account name reads "context: {name}".

Also I want a proper abstract base class for output formats that on instantiation automatically calls a transform method and optionally creates a file descriptor. The CSV output should be a concrete subclass of that base, transforming findings into uppercase-keyed dicts (joining list fields with " | " and formatting compliance dicts as "key: value" entries), then writing semicolon-delimited CSV. Oh and the standalone CSV row-writing utility needs to accept either a dict or an object as the row. Since the new CSV class manages its own file descriptor now, the general-purpose file descriptor initializer should stop handling CSV mode and just skip it. And that old legacy helper function for converting findings to the output model, go ahead and remove it. Centralizing this stuff on the finding model itself keeps things cleaner so new output formats only implement a small interface instead of duplicating all the provider field mapping.
