I'm cleaning up how the Tact compiler gets at its standard library and the current layout is bugging me. Right now the prepackaged stdlib bundle (the map of relative file paths to their encoded file contents) lives under an imports folder, and separately, any code that needs to actually read stdlib files off disk just computes the path inline with hardcoded relative navigation like walking up directories. There's no single source of truth for where the stdlib lives, so if the location ever moves I'd have to touch a bunch of unrelated spots, which is annoying.

What I want is to pull the stdlib bundle into its own dedicated module directory so there's one authoritative place exporting that in-memory map of stdlib file paths to contents. Then, in that same directory, I want a separate small module that just exports the canonical filesystem path to the stdlib root, so anything needing to read stdlib files from disk can import that path instead of hardcoding it. Basically centralize both the in-memory representation and the on-disk path.

Everything has to keep working after the move. In particular contract compilation and the memory allocation resolution both consume stdlib data, so those should still resolve correctly pulling from the new locations. Just make sure consumers import from the new module directory rather than the old imports path or inline path math.
