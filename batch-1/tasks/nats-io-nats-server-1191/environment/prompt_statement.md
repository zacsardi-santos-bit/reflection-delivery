I'm running a NATS server with JWT-based auth, account imports, and signing keys, and I've hit three related bugs in the account import handling that I need fixed together.

First one is a silent failure. When a client account has an import referencing a signed activation token, and that token's issuer account field points to the wrong account (like pointing back at the importing account instead of the exporting account it should reference), the server just quietly rejects the import with zero log output, which is miserable to debug. When the activation claim's issuer account doesn't match the exporting account I want it to log a clear error and reject the authorization (return false), and the message should name the bad issuer account, the import subject, the import type, and the account being imported into so operators can actually tell what's misconfigured. Two imports with wrong issuers should give me two separate error log entries.

Second, when those imports use signing keys (exporter account signs the activation tokens with a signing key), a connecting client can sometimes deadlock the whole server. Looks like it happens when another goroutine holds the exporter account's write lock at the same time the import validation is verifying the signing key, so the lock acquisition ends up cycling. Connecting with imports from signing-key-based accounts just can't deadlock, the lock ordering during import validation needs to be sane.

Third, in a gateway cluster there's a race where the same account gets registered twice, once from an optimistic message send path and again from a direct client connect (slow account resolver makes it worse). That leaves stale entries in the server's internal temporary account tracking map even after everything's done, and it messes with subscription routing across the gateway. After any combination of concurrent account fetches and registrations finishes, that temp account tracking map has to be empty, no duplicate registrations left behind even under concurrent access.

All three live in the JWT account import path, oh and they should be fixed together since they're intertwined. Net effect I want: activation claim validation logs and rejects wrong-issuer accounts, import validation doesn't deadlock, and temp account state always gets cleaned up after registration completes.
