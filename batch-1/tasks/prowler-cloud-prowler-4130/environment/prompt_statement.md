I'm adding a new Prowler security check for AWS RDS that verifies whether an account has event notifications set up for database security group events, specifically both the configuration change and failure event categories being watched via active subscriptions. Right now the RDS service layer in `@prowler/providers/aws/services/rds/rds_service.py` doesn't pull event subscription info at all, so I need to extend it to fetch and expose that data. Each event subscription object should capture at least the topic ARN (the SNS ARN), whether the subscription is enabled, the source type, the list of subscribed event categories, and the region it lives in.

Then the new check itself evaluates each region's event subscriptions and emits findings per region. If an active subscription covers db-security-group events across all categories it passes, but if a subscription only covers one of the two required categories it fails with a message calling out exactly which one is missing (so if it only has failure, the finding says the configuration change category isn't covered, and if it only has configuration change, it says the failure category isn't covered). And when there are no relevant subscriptions at all, it fails saying both the configuration change and failure categories aren't subscribed.

Oh and it needs to respect the existing Prowler behavior where if the scan is configured to ignore services with no active resources and there are no RDS instances present, the check just produces no findings at all. The whole point here is closing a visibility gap, security teams currently have no automated signal from Prowler telling them whether they'll actually get alerted when someone modifies a database security group or when one hits a failure, which matters for catching unauthorized changes to database access controls.
