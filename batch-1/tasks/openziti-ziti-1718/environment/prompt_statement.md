I'm working on the router side and hitting a gap around startup behavior when it can't reach a controller. Right now there's no way for operators to control how long the router waits during startup before it gives up and exits, the wait is either absent or hardcoded so nobody can tune it. That's a real pain in environments where network conditions vary a lot, like routers that are geographically far from their controllers or setups where the controller takes a while to come up, and honestly in the other direction too since some operators would rather fail fast on startup instead of hanging around.

What I want is a new optional setting in the router's controller configuration section that lets operators specify a startup timeout as a duration. So it should live in the controller config block, be optional (existing configs without it keep working), and the router's internal configuration structure needs to expose this startup timeout as a settable and readable duration field so it can be tuned per deployment. Basically the config struct should carry a duration field for this that can be set and read back.

The point is giving operators explicit control over startup behavior so the whole thing is more predictable and plays nicer with automated deployment and monitoring workflows.
