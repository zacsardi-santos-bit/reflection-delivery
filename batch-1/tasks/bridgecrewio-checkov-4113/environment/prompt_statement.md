I'm filling some gaps in our infra scanner for AWS stuff defined in Terraform. Right now we've got zero coverage for a bunch of security controls and I need graph-based policy checks for each, done as YAML graph checks following the existing conventions in the codebase so the test framework picks them up and runs them automatically.

Here's what I need. First, a check that API Gateway stages require client certificate authentication, and it's gotta cover both the older and newer API Gateway resource types (v1 and v2), so a stage without a client certificate configured should fail. Second, a check that API Gateway methods have request parameter validation on, meaning a method with no request validator should fail. Third, CloudFront distributions shouldn't use outdated insecure SSL for origin comms, specifically flag origins that permit SSLv3. That one should pass for distributions using only secure protocols or with no custom origin SSL config, and fail only when an explicitly insecure protocol like SSLv3 is set. Fourth, EMR clusters need a security configuration attached, so a cluster with no security configuration fails. And fifth, OpenSearch and Elasticsearch domains need fine-grained access control fully enabled, which means both the top-level access control option and the internal user database must be turned on. That check should fail if either one is disabled.

Why it matters: these are real risks, unauthenticated API traffic, unvalidated API inputs, deprecated SSL protocols, unencrypted EMR data, and overly permissive search domain access. Catching them before prod is the whole point.
