I'm working on adding several missing security checks to our infrastructure scanner for AWS resources defined in Terraform. Right now we have no coverage for a handful of important security controls, and I need to add graph-based policy checks for each of them.

The checks I need are: one to ensure API Gateway stages require client certificate authentication (covering both the older and newer API Gateway resource types), one to ensure API Gateway methods have request parameter validation enabled, one to ensure CloudFront distributions don't use outdated insecure SSL protocols for origin communication, one to ensure EMR clusters have a security configuration attached, and one to ensure OpenSearch and Elasticsearch domains have fine-grained access control fully enabled — meaning both the access control option itself and the internal user database must be turned on.

Each of these should be implemented as a YAML-based graph policy check following the existing conventions in the codebase, so the test framework can discover and run them automatically. The check for CloudFront should pass for distributions that use secure protocols or have no custom origin SSL config, and fail only when an explicitly insecure protocol is configured. The OpenSearch check should fail if either the top-level security option or the internal user database option is not enabled.
