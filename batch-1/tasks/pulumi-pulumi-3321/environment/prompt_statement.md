I'm working on the Node.js runtime for Pulumi (the JS/TS SDK) and I want to make top-level programs way nicer to write. Right now if I want any async setup at program startup, like awaiting config, hitting an external API, or doing dynamic setup before I create resources, I'm stuck exporting a plain object at the module's top level, which only really works for synchronous stuff. The workaround people use is an immediately-invoked function expression and honestly it's awkward and not obvious at all.

What I want is for the runtime to let me export a single top-level function as the whole program entry point. So when the module's exported value is actually callable, the runtime should detect it's a function, call it with no args, and await whatever comes back. That needs to work whether I export a regular synchronous function, a function that returns a promise/async value, or a proper async function. And any pending async values nested inside the returned value should get deeply resolved too before anything is registered, then the fully resolved return value becomes the stack's outputs.

Couple things that have to keep working: resources I create inside that exported function need to be tracked and registered exactly as if I'd created them at the module top level, no difference. If the function returns nothing, the stack outputs should just be empty. And if it returns a value while also creating resources, both the resources and the outputs need to register correctly. Basically I want to write async-first programs by just exporting an async function, no boilerplate. The runtime hook for this lives in the Node language host / run logic (around `@sdk/nodejs/cmd/run` and the runtime stack handling in `@sdk/nodejs/runtime/stack.ts`), so that's where the detect-call-await-resolve behavior should land.
