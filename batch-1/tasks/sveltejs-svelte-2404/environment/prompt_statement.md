I'm working on the Svelte documentation site and we need to improve how URL anchors are generated from heading text. Right now the site just strips non-ASCII characters, which completely breaks anchor links for headings written in non-Latin scripts — for example, documentation pages written in Russian end up with empty or meaningless anchors.

I need a slug utility module that supports two modes: one that transliterates non-Latin characters (like Cyrillic) into their Latin equivalents for ASCII-safe URLs, and another that preserves native Unicode letters as-is so non-Latin documentation can have readable anchors. Both modes should handle typical documentation content correctly — spaces and punctuation should become separators, dollar signs should be preserved (they appear in Svelte's API, e.g. method names starting with a dollar sign), Unicode symbols should be converted to their word equivalents, and emoji should be removed. The latinizing mode should also support language-specific symbol translations when a target language code is provided.

I also need a configuration file that exports the separator character and default language code used by these utilities, so both the slug functions and other parts of the codebase can import consistent settings.
