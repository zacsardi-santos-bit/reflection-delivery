I'm working on the Svelte docs site and our URL anchor generation is broken for anything that isn't plain ASCII. Right now it just strips non-ASCII characters, so headings in non-Latin scripts (Cyrillic, for example, our Russian pages) end up with empty or garbage anchors, which makes it impossible to publish properly-linked docs in those languages. I want a dedicated slug utility module with two processing strategies. The first is a latinizing mode that transliterates non-Latin letters (like Cyrillic) into their Latin equivalents so anchors are fully ASCII-safe and RFC 3986 compliant, and this is the default for English docs. The second is a unicode-preserving mode that keeps native Unicode letters as-is so non-Latin docs get readable, human-friendly anchors.

Both modes need to handle the usual documentation edge cases the same way. ASCII text should be lowercased and spaces and punctuation should become the configured separator character. Dollar signs need to be preserved and stay attached to adjacent words since they show up all over Svelte's API (method names starting with `$`, that kind of thing). Unicode symbols should be converted to their English word equivalents by default, and emoji should just be stripped out entirely. The latinizing processor converts non-ASCII letters to Latin, while the unicode-preserving one keeps them, and oh, in unicode mode when a Latin word is directly concatenated to a non-Latin word they should get split with the separator. The latinizing mode also needs to support language-specific symbol translations when I pass a target language code.

I also want a small config module that exports the separator character and a default language code used for symbol translation, so the slug functions and other parts of the codebase can all import consistent settings and the site can be set up to use either mode.
