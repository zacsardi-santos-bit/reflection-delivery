I'm working on the Kargo stage controller and I need to extend the Stage status to track freight history in a richer way. Right now, the stage status has a single "current freight" reference field, which only works when a stage gets freight from one warehouse. I want to support scenarios where a stage aggregates freight from multiple warehouses, so each deployment snapshot needs to be a collection of freight items keyed by warehouse name, not just one flat reference.

Concretely, I need a new history structure on the stage status where each entry holds a map of freight references by warehouse name, and the history is ordered so the most recent deployment is first. The stage controller's verification-related operations (starting, getting status of, and aborting a verification, as well as building the analysis run resource) currently read the freight context directly off the stage status — I need those to accept the freight reference as an explicit parameter instead, so they can work correctly in multi-warehouse scenarios.

The indexer that maps stages to their active analysis runs also needs to be updated to look through all freight items across history entries, not just the old single-reference field. Similarly, the helper functions that trigger reverification or abort verification need to use the new history structure to find the current freight. When a stage is a control-flow-only stage, the new history field (along with current promotion tracking fields) should be cleared from the status just like the other freight fields.

The existing single-reference fields should stay for backward compatibility but should be treated as deprecated. The new structure should coexist with them.
