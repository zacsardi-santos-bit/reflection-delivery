I'm working on the Kargo stage controller and I need to make the Stage status track freight history in a way that handles freight coming from more than one warehouse. Right now the status just has a single flat "current freight" reference which only works when a stage pulls from one warehouse, and there's no way to tell which freight came from which warehouse. That falls apart the moment a stage is supposed to aggregate freight from several independent warehouses at once, and it means our verification and analysis steps can end up operating on the wrong freight context.

What I want is a new history structure on the stage status where each entry holds a map of freight references keyed by warehouse name, ordered so the most recent deployment is first, and that top entry represents what's currently deployed across all contributing warehouses. The old single-reference fields should stick around for backward compat but get marked deprecated, and the new structure coexists with them.

The verification stuff in the controller (starting a verification, getting its status, aborting it, and building the analysis run resource) currently reads the freight straight off the stage status, so I need those to take the freight reference as an explicit parameter instead so they behave right in multi-warehouse cases. The indexer that maps stages to their active analysis runs needs to scan across all freight items in every history entry, not just the old single field. Same idea for the helper functions that trigger reverification or abort verification, they should use the new history structure to find the current freight. Oh and when a stage is control-flow-only (not doing deployments), this new history field along with the current promotion tracking fields should be cleared from the status, just like we already clear the other freight fields.
