So I'm trying to fix a reliability gap in KubeVirt's device plugin manager and I could use your help wiring it up. Here's the deal: when the node agent (kubelet) on a node restarts, it wipes out all the device plugin socket files and expects the plugins to notice and re-register. Right now our device plugins have no way to detect that the socket got deleted, so the device manager just sits there broken and no new VMs can be scheduled or started on that node, even though the hardware is still physically present. Someone has to manually intervene, which is awful during routine stuff like kubelet upgrades.

What I want is for the device health monitoring code to watch for socket file deletion and, when it sees that event, automatically kick off a clean re-registration with the node agent. Tied to that, the plugins need real restart behavior. There's no retry loop today, so if a plugin fails to start it just stops. I want it to retry with exponential backoff delays when it hits errors (don't hammer a system that needs time to recover), but restart immediately with no delay when it exits cleanly as part of a normal re-registration cycle. Also please run multiple device plugins concurrently so one unavailable device doesn't block the others from starting. End result: after a node agent restart and the re-registration cycle, I should be able to start new VMs on that same node again.

Couple of smaller cleanups while you're in there. The device plugin socket path construction should be pulled out into a standalone exported function so other parts of the codebase can call it, and the name constant for the KVM device should be exported too. Oh and there's a utility function that runs commands on pods, it needs to correctly propagate any error from the command even when there's partial output available, right now it can swallow that.
