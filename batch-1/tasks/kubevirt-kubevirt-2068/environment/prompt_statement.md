I'm working on improving the reliability of KubeVirt's device plugin manager. Right now, when the node agent restarts and deletes the device plugin socket files, our device plugins have no way to detect this event and re-register themselves. The result is that after a node agent restart, no new virtual machines can be started on that node until someone manually intervenes — even though the physical hardware is still available. I need the device health monitoring code to watch for socket file deletion and trigger a clean re-registration automatically when that happens.

Related to this, I also need proper restart behavior for the device plugins themselves. Currently there's no retry loop: if a device plugin fails to start, it just stops. I need it to retry with backoff delays when it encounters errors, but to restart immediately (no delay) when it exits cleanly as part of a normal re-registration cycle. Multiple device plugins should be managed concurrently so one unavailable device doesn't block the others.

The device plugin socket path construction logic should also be extracted into a standalone exported function so it can be referenced from other parts of the codebase, and the name constant for the KVM device should also be exported. Additionally, a utility function that runs commands on pods should correctly propagate any errors from the command even when partial output is available.
