I've got a fairness problem in the coordinator duty that submits kill tasks for unused data segments. It runs on a schedule across multiple datasources, but when several of them have unused segments piling up, the same one keeps getting picked run after run while the others just accumulate backlog. I want the scheduler to rotate through datasources round-robin so no single datasource gets chosen twice in a row as long as there are other eligible ones. When only one datasource is eligible it should of course get picked every run, and when the set of eligible datasources changes between runs the scheduler needs to adapt to the new set while still honoring the round-robin order.

The clean way to do this is a reusable circular collection that holds an ordered set of elements and remembers its cursor position between traversals, so each time I iterate it picks up where it left off and wraps back to the start when it hits the end. It also needs a way to check whether the set of elements it was initialized with matches a given set, so the coordinator can detect when the datasource list has changed and reinitialize the collection.

That's wrong. For that run it should just report zero eligible segments, and then it should correctly process that datasource in subsequent runs once unused segments actually appear. Fix that too so nothing gets stranded.
