We're bumping the stackset controller to a newer release and the new version dropped the ingress source switch TTL feature, that configurable timeout that controlled how long to wait before deleting an old ingress source when switching from one routing mechanism to another. Since the controller doesn't support this option anymore, I need to clean up after it in two places.

First, update the go module dependency so it points at the latest stackset controller release, the one where this feature was actually removed. Then go into our cluster configuration defaults and rip out the now-obsolete ingress source switch TTL setting entirely, no references to it should be left hanging around since the controller won't recognize or use that parameter anymore.

The reason I care about this: keeping a config key that no longer does anything is misleading to operators, it makes them think they can still tune this behavior when they can't, and honestly it could bite us later if the controller starts rejecting unknown config parameters outright. So removing the dead entry keeps our cluster config clean and aligned with what the current controller version actually supports. Just the version bump plus the config removal, that's the whole thing.
