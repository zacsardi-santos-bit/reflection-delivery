I'm cleaning up the environment model in our infra platform and it's overdue. Right now creating or updating an environment makes you set both a minimum and a maximum instance count, which is way more complexity than anyone needs, most people just want one target number. So I want to collapse that into a single desired scale value, and while I'm at it introduce an environment "type". There's a "static" type that manages a fixed pool of instances driven by the scale value, and a "dynamic" type that only stands up a cluster and security group and doesn't create or manage any instance pool at all.

So on create, a dynamic environment should skip the instance pool entirely and just do the networking and cluster infra, while a static one uses the single scale value to drive both the min and max instance count under the hood. When reading an environment back, I want the current count of actually-running instances and the desired scale returned separately instead of the old min/max pair, and the type should come back too and get stored as a tag alongside the existing name and OS tags.

On the CLI side, replace the separate min and max scale flags with one combined scale flag, and if someone passes a negative scale treat it as an input error. When a scale value is provided the environment should be treated as static. The environment listing output needs updating so it shows the type per row and drops the scale and instance type columns, oh and the summary listing should gain a type column too.

And for the IaC configs, the resource and data source definitions for environments should expose a single scale setting plus an environment type setting, removing the old separate min and max scale settings. The whole point here is the min/max model is cognitive overhead without real value, and having a dynamic type unlocks more flexible deployments where scaling isn't a fixed range you babysit.
