I'm adding a new built-in to the ferret query language's objects stdlib and I want it to match how ArangoDB does this. Basically I need a function that zips two parallel arrays into an object: the first array is the string field names, the second is the values, and I get back an object pairing each key with the value at the same index. Right now ferret just doesn't have this, so anyone whose data is split across two arrays can't assemble an object in a single query expression, and since ferret's trying to stay compatible with ArangoDB query semantics this gap is annoying.

Behavior I'm after: it takes exactly two arguments and both have to be arrays, otherwise error. Every element in the keys array must be a string, so any non-string key should get rejected with an error. If the two arrays are different lengths, that's also an error. On the happy path it returns an object mapping each key to its corresponding value. The one edge case I care about, and this is how Arango handles it too, is duplicate keys: if the same key shows up more than once in the keys array, only the first occurrence wins and keeps its value, and later duplicates (plus their values) just get silently dropped, no error.

So same-length string-keys array plus any-values array in, fully-formed object out. Wire it into the objects standard library alongside the other object-manipulation functions.
