I'm adding AWS Wavelength Zone support to our Kubernetes cluster networking provider and right now the code only knows about standard availability zones and Local Zones, so Wavelength Zones aren't a distinct zone type and clusters can't get proper networking provisioned there. Wavelength Zones are edge zones that deliver ultra low latency to mobile users through carrier infra, so this actually matters for folks running low-latency mobile workloads.

What I want: recognize Wavelength Zone subnets as their own edge zone type, separate from Local Zones and normal AZs. I need a way to check whether a subnet belongs specifically to a Wavelength Zone, not just the general is-edge check. The subnet collection utilities should include Wavelength Zone subnets when returning edge-inclusive results, but leave them out of the standard non-edge subnet ID lists. Setting zone info on a subnet needs to work for Wavelength Zones too, populating the zone type and the parent zone name. Oh and it should be possible to check whether a collection of subnets contains any public Wavelength Zone subnet.

On the networking side the VPC config needs somewhere to store a carrier gateway identifier. A carrier gateway should get created when managing a VPC that doesn't have one yet, and deleted on cluster teardown. For route tables, public IPv4 subnets in Wavelength Zones should use the carrier gateway as their default route instead of the internet gateway. IPv6 isn't supported in Wavelength Zones so that path should return a clear error. And private subnets in Wavelength Zones should route through the NAT gateway in their parent availability zone, same as Local Zone subnets already do.
