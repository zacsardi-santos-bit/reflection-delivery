I'm extending our Azure security auditing tool with some VM checks and honestly we've got zero coverage right now for disk encryption or managed disk usage, so I want to fill that in. I need four new checks plus a service layer to back the VM ones.

First, a new Azure virtual machine service under the compute area (something like `@prowler/providers/azure/services/vm/vm_service.py`) that uses the Azure compute management client and follows the same conventions as our other Azure service integrations. It should fetch and model both VMs and disks per subscription, and for each disk I need the encryption type and whether it's attached plus which VM it's attached to. Disks and VMs keyed by subscription basically.

Then the checks. One flags disks currently attached to a VM that aren't using customer-managed encryption (platform-managed only should fail, and unattached disks are out of scope here). A separate one does the opposite, it flags unattached disks not using customer-managed keys and skips attached ones. Another verifies each VM uses managed disks for its OS disk and any data disks, and it fails if any disk (OS or data) is unmanaged. And the last one reads Defender security assessment data to report whether endpoint protection is installed on VMs, passing when the recommendation is healthy and failing when unhealthy.

Each check reports pass or fail per resource with a human-readable message naming the specific resource and its subscription. Oh and they should handle empty cases gracefully, so if there are no subscriptions or a subscription has no relevant resources, just return no results, don't blow up. Why bother? Customer-managed keys give us control over data protection and confirming endpoint protection is live shrinks the attack surface, and today there's no automated way to audit any of this across subscriptions.
