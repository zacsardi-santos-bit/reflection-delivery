I'm cleaning up the time series ensemble models and hit a few things that need fixing together. The greedy ensemble model right now forces you to pass a name when you construct it, and that's annoying in automated or default contexts. I want to be able to instantiate it with no arguments at all, so make the name optional and fall back to a sensible default name when none is given.

Second thing, the predict method is too picky about its input. Currently it validates that the set of models in the input predictions exactly matches the set of models the ensemble learned weights for during fitting, and if you hand it extra models it errors out. That's wrong. It should accept any input that contains at least the models the ensemble knows about, and just quietly ignore the extra ones. Btw if any base model the ensemble actually needs is missing entirely from the input, predict should raise a runtime error.

Third, I need to move some hyperparameter tuning utilities into their own dedicated submodule inside the abstract models package. Specifically the helper that handles the empty search space case (skipping tuning when there's no search space defined) needs to live in that new module, either moved there or re-exported from it, and the existing code that calls it during hyperparameter tuning has to point at the new location instead of the main abstract model file.

Once all this is done, the ensemble should fit correctly on multi-window validation data where each base model gives predictions across several different time windows, and across varying numbers of validation windows, base models, and prediction lengths the resulting forecasts should have no NaNs and their time index should line up with the input predictions. This keeps the tuning logic cleanly separated and makes the ensemble more flexible for multi-window validation.
