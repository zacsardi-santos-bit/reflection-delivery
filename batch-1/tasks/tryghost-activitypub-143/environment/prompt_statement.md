I'm building out an ActivityPub service and right now all the federation activities get handled synchronously inside the HTTP request path, which just falls over under load (timeouts, dropped work, the usual). I want to move this onto Google Cloud Pub/Sub so activities can be queued and processed async with retries.

So I need a message queue class that publishes messages to a cloud messaging topic. Each message goes out as JSON plus some metadata attributes identifying it. One quirk: if a message has a delay configured on it, I want to skip publishing it entirely rather than sending it immediately. And if the publish call fails, don't swallow it, let the error propagate up to the caller.

The queue also needs to listen for incoming messages, which come in through an internal event bus (not directly off the wire). When a message arrives and the handler processes it fine, ack it. If the handler throws or fails, nack it so Pub/Sub can redeliver later.

On top of that I need an init helper that constructs and wires up this queue. It should connect to the Pub/Sub client using only the config options that are actually set, so host, emulator mode, and the project id should only be passed through when they're explicitly provided, don't forward them as undefined. Before it hands back the configured queue, it's gotta check that the required topic and subscription both exist. If the topic's missing, throw an error saying which topic doesn't exist; same deal for a missing subscription with a similar message. Basically I want the thing to fail fast at startup with an actionable message instead of quietly misbehaving at runtime when the infra isn't there.
