I'm working on an ActivityPub service and need to add support for processing federation activities through a cloud message queue. Right now, everything is handled synchronously, which doesn't scale well and causes problems under load.

I need a message queue implementation that can publish messages to a cloud messaging topic — each message should be sent as JSON along with some metadata attributes identifying it. If a message has a delay configured, it should be skipped entirely rather than published. If publishing fails, the error should propagate to the caller. I also need the queue to support listening for incoming messages, which will arrive through an internal event bus. When a message comes in and the handler processes it successfully, the message should be acknowledged; if the handler fails, the message should be negatively acknowledged so it can be retried.

I also need an initialization helper that sets up this queue. The helper should connect to the messaging service using only the configuration options that are explicitly provided — host, emulator mode, and project identifier should only be passed to the client when they are actually set, not as undefined values. Before returning the configured queue, the helper should verify that the required messaging topic and subscription both exist. If the topic is missing, it should throw an error saying which topic doesn't exist. If the subscription is missing, it should throw a similar error. This way the service fails fast at startup with a clear message rather than discovering missing infrastructure later at runtime.
