I'm building out an EVM emulator and the gas accounting is only half-done right now, memory expansion and storage slot access just aren't being priced at all, which means the totals don't match what Ethereum actually charges. I want to fill that gap.

On the memory side I need two things. First, a method that reports the current gas cost of whatever's allocated, based on the number of 32-byte words in use, and remember memory cost grows quadratically with word count so the math has to reflect that. Second, a method that takes a starting offset and a size and computes the incremental cost of expanding memory to cover that new region, and if the region already fits and no expansion is actually needed it should just return zero.

For storage it's the cold vs warm distinction from the access-list pricing changes. The first time you touch a slot in a transaction it's expensive, after that it's cheap, so the storage component needs to track which slots have been accessed (through reads or writes both count) within a session so it can report the right access cost. I need a method that returns that access cost for a given slot, cold access is 2100 and warm access is 100. And I need another method that computes the full cost of writing a value to a slot, which combines two factors: whether the value being written is zero or non-zero (different base costs), and whether the slot is cold or warm. Concretely, writing a non-zero value to a cold slot is 22100, writing zero to a cold slot is 5000, non-zero to a warm slot is 20100, and zero to a warm slot is 3000.

This all matters because anything that analyzes or simulates contracts needs accurate gas numbers, and higher-level stuff like function-level gas profiling can't work if the underlying accounting is off.
