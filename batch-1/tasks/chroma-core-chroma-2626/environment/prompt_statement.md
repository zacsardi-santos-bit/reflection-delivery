I'm cleaning up Chroma's internal data model and I want to enforce something that's actually always true but the code pretends otherwise: every segment belongs to a collection. There's no valid case where a segment exists without one, but right now the collection reference gets treated as optional/nullable in a bunch of places, including the proto schema and the function that converts a segment into its network representation. So when a segment with no collection gets serialized, the collection field on the resulting message comes out null or missing instead of holding a real value, and various spots have to special-case the null which is annoying.

What I want is to make collection required everywhere. In the proto definition the collection field on the network Segment message should be a plain non-optional string, not optional or a pointer type. The conversion to wire format should always populate it, and when no specific collection ID is set it should fall back to the all-zeros nil UUID string rather than leaving it null or absent. So serializing a segment with a nil/zero collection ID gives you a message where collection equals that nil UUID string (all zeros).

Also the existing test cases that build segments with a null collection need to be updated to always use a real UUID instead. And the code that references collection IDs while constructing a segment should use proper attribute/property access on the collection object rather than dictionary-style key lookup. Oh and the ability to update a segment's collection to null should just be removed, no code path should let you create or update a segment with a null collection reference anymore. Basically kill the null handling since it shouldn't need to exist.
