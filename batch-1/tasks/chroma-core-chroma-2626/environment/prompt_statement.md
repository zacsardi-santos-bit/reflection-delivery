I'm working on Chroma's internal data model and I want to enforce that every segment must always have a collection — there's no valid case where a segment exists without one. Right now the collection reference on a segment is treated as optional/nullable in several places, including in the proto schema and the function that converts segments to their network representation. When a segment with no collection is serialized, the collection field in the resulting message ends up as null or missing, rather than being populated with a proper value.

I'd like to make the collection field required everywhere: the proto definition should declare it as a plain non-optional string, and the conversion function should always populate it — using the all-zeros nil UUID string as a placeholder when no specific collection ID is set. The existing test cases that create segments with a null collection should be updated to always use a real UUID, and the code that references collection IDs during segment construction should use proper attribute access on collection objects rather than dictionary-style lookup. The ability to update a segment's collection to null should also be removed.
