Right now if I write a binding-with-else statement where the right-hand side is a struct literal followed by an else block, the parser happily accepts it and says nothing, even though this pattern shouldn't be valid.

What I want is for the parser to catch this case and emit a clear error explaining that a right curly brace before else in a binding-with-else statement isn't allowed. The error needs to be reported at the position of that closing brace of the struct literal, not somewhere vague, so the span points right at the offending `}`. Oh and it's important the parser still recovers after emitting the error and produces a useful, valid parse tree rather than bailing out on the whole thing, otherwise downstream analysis gets wrecked.

The why here is that without this diagnostic devs can write syntactically ambiguous struct-literal-in-binding-with-else code and get zero feedback, so adding the proper error both explains why the construct is disallowed and lets downstream tooling like IDE diagnostics surface the problem accurately.
