I'm working on the automatic resource provisioning feature in the Cloudflare Workers deployment tool and hit a handful of things that need cleaning up. First off the output's too noisy when a resource finishes provisioning, right now the success message appends the resource's name and then prints a separator line after it, and I just want a clean success indicator, so drop both the appended name and the separator.

Second thing, when a database or bucket name is already specified in the worker config file, the tool still pops a confirmation dialog asking the user before creating the resource. That's annoying, if the name's already in the config the intent is clear, so kill the confirmation and just go ahead and create it non-interactively.

Third, the D1 database flow doesn't check whether a database with the given name already exists before it provisions, but the R2 bucket flow already does this right (if a bucket with the specified name exists it gets reused). D1 needs the same treatment, look up the database by name and if one's found use it directly by its identifier instead of going through provisioning, and if the lookup comes back with a "not found" error then proceed to create the database.

Last one's an actual bug with R2 bucket inheritance. When we decide whether to inherit an existing R2 bucket binding from a previous worker deployment, we're not considering the geographic jurisdiction at all. If the existing binding's jurisdiction doesn't match what's specified in the current config, don't inherit it, provision a new bucket in the correct jurisdiction instead. Net effect I'm after: simpler success output, no prompts when names are pre-specified, D1 reused by name like R2, and jurisdiction mismatches trigger re-provisioning.
