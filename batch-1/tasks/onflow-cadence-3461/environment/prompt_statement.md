I'm knee-deep in the Cadence 1.0 state migration for capability controllers and I hit a real bug with account links. Back in old Cadence you could make an account link capability where the borrow type was just a plain, non-privileged account reference with no entitlements on it, and my capability consistence migration doesn't handle those right, they either fail or spit out the wrong output when they should migrate cleanly into fully authorized account capability controllers.

What I want is for the migration to correctly process both the plain unauthorized account reference type and the fully authorized account reference type when they show up in old account link capabilities. In either case it should issue an account capability controller with the fully authorized account type, and it needs to work for both public and private path domains. So an account link sitting at a public path or a private path with an unauthorized borrow type should migrate successfully and emit a properly formed event.

Oh and there's a related event bug, when I emit migration events for fully authorized account capabilities the type string comes out malformed with a doubled reference prefix (like `&&Account` sort of thing), which is just wrong and the event needs the correctly formatted fully authorized account type instead.

Also there's the chain case, where an inner link is an account link and the outer link uses an unauthorized account reference pointing at it, each link in that chain should get migrated and each should emit events carrying the correct type info for that particular link.

Why this matters: if unauthorized account reference capabilities don't migrate, any on-chain state from before Cadence 1.0 using that pattern gets stuck, and the doubled-prefix event string is a signal that the type info baked into the new controller is actually wrong too, which'll cause downstream problems. Fix both.
