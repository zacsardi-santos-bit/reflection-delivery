I've been looking at the compiled output of Svelte components in the client functional rendering mode, and the generated JavaScript for templates is incredibly verbose. For each component, the compiler emits a factory function that creates every single DOM element with individual API calls, manually sets each attribute, and then assembles everything into a fragment. For a component with any meaningful structure, this can be hundreds of lines of boilerplate just for the template setup.

I'd like the compiler to switch to a much more compact, declarative format for describing the template structure. Instead of generating an imperative function, it should produce a nested array/object descriptor where elements are described with their tag name, optional static attributes, and optional children — and text content and reactive placeholder markers are embedded inline. The runtime function that processes these templates would need to be updated to interpret and build the DOM from this declarative descriptor rather than executing a factory function.

This should dramatically shrink compiled output size for templates, which matters for bundle size and also makes the generated code much more readable when you need to inspect it.
