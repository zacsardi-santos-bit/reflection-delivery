I've been staring at the compiled JS for Svelte components in the client functional rendering mode and it's honestly painful. For every component the compiler spits out this factory function that creates each DOM element one by one, individually sets every attribute, manually makes each text node and comment node, and then assembles the whole thing into a fragment step by step. A template with any real structure balloons into hundreds of lines of setup boilerplate, which is terrible for bundle size and also just miserable to read when you're trying to inspect what got generated.

I want to switch this to a compact declarative descriptor instead. So rather than emitting an imperative factory function body, the compiler should produce a nested array/object structure that describes the element tree directly: each element as an object with its tag name, optional static attributes, and optional children, text nodes as plain string values embedded inline, and reactive placeholder markers (those comment nodes used as anchors) represented as empty slots in the structure. Then the runtime template function needs updating so it interprets this declarative format and builds the equivalent DOM rather than running a factory function.

The payoff is way smaller compiled output (fewer bytes to download, faster loads) and the generated code actually becomes readable. A template that's currently hundreds of lines of creation and insertion calls should collapse down to one concise nested structure representing the same hierarchy, oh and the DOM it produces needs to stay equivalent to what the old factory approach built.
