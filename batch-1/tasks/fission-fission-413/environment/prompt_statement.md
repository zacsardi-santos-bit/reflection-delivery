I'm hacking on Fission (the serverless framework for Kubernetes) and hit a real gap in how it stands up runtime and builder pods for an environment. Right now when Fission creates those pods it builds the whole container spec from its own internal logic, so there's no way for a user to pass through container-level settings like env vars for their language runtime or builder. That's a pain because people constantly need to set environment variables to configure runtimes, point at services, or flip on debug flags, and today they're stuck doing fragile unsupported workarounds.

What I want is an optional container customization section in the environment spec for both the runtime and the builder components, and at pod creation time those user-supplied settings should get merged into the container spec Fission builds. The system's own values need to win for the fields it controls (name, image, pull policy, that kind of scalar stuff), but fields the system leaves unset, like env vars, should come through from what the user provided.

To make that work I need a general-purpose merge utility that combines multiple container specs into one. The rule is earlier specs take priority for scalar fields, while list-type fields (env vars being the main one) get accumulated from all the specs in order. It's gotta handle the edge cases cleanly too: no args returns an empty result, and a single spec returns a correct copy of it. And order matters, so running the same specs in a different order should give a different result whenever there are conflicting values.
