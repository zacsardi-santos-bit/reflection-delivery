I'm working on the Fission serverless framework for Kubernetes and need to add the ability for users to customize the containers used for their runtime and builder environments. Right now, when Fission creates the pods for an environment, it builds the container spec entirely from its own internal configuration, with no way for the user to pass in extra settings like environment variables. I'd like to support this by allowing users to specify an optional container customization in the environment definition, and have those settings merged into the container spec at pod creation time.

To support this, I need a utility function that can merge multiple container specifications together. The merging should give priority to earlier specs for simple scalar fields (name, image, pull policy, etc.) while accumulating list-type fields like environment variables from all specs in order. The function should handle edge cases cleanly — returning an empty result with no arguments and a correct copy when given a single spec. Order must matter: running the same specs in a different order should yield a different result when there are conflicting values.
