I'm building out a GraphQL schema diffing library and need it to compare two schema strings, a source and a target, and hand back a sorted list of changes where each change carries a kind (what got modified) and a dot-separated path pointing at the affected element. Right now there's no way to programmatically tell what shifted between two versions of a schema, and I need that for tracking schema evolution, catching breaking changes before deploy, and generating changelogs when the API moves.

The kinds I need detected: object types added or removed, fields added or removed on object types plus interfaces and input types, a field's type changing, interface implementations added or removed on types, enum types added or removed along with their values changing, union types added or removed along with their members changing, directive definitions added or removed, schema-level root type assignments (query, mutation, subscription) changing, the schema definition block itself being added or removed, and at the argument level, field arguments added or removed, an argument's type changing, and default values on arguments getting added, removed, or changed.

It's gotta work bidirectionally so callers can diff either direction. For sort order I want schema-level changes first, then type-level, then field-level. When a type changes its fundamental kind, say an object type gets replaced by an enum with the same name, report both the removal of the old kind and the addition of the new kind. And when a whole type is removed, don't also spam individual field removals for it, just the type removal itself should show up.
