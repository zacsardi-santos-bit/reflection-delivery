I'm chasing down resource leaks in the Flink Kafka consumer over in `@flink-connectors/flink-connector-kafka-base/src/main/java/org/apache/flink/streaming/connectors/kafka/FlinkKafkaConsumerBase.java`. The problem is the internal partition discoverer doesn't get closed reliably when the consumer shuts down, so underlying connections and background threads tied to partition discovery just leak whenever the consumer hits a failure or gets cancelled. That's rough for long-running jobs that restart consumers, it slowly destabilizes things.

What I want is basically: no matter how the consumer stops, the partition discoverer always ends up fully closed by the time the close operation completes. A few specific cases I keep hitting. If partition discovery itself throws an exception during startup, the discoverer should still get closed when the consumer shuts down. Same deal if creating the internal Kafka fetcher throws during initialization, the discoverer still needs to be closed on shutdown. And when the fetcher fails during operation (so it was actively running), the discoverer should get woken up first so any blocking partition discovery calls get interrupted, and then closed. Oh and normal cancellation counts too, when someone explicitly stops the consumer while it's running the discoverer should be properly closed.

So it's the wakeup-then-close ordering for the running case, plain close for the others, but the end state is always a fully closed discoverer regardless of error or cancellation path.
