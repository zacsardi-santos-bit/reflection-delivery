I'm working with txiki.js and I keep hitting a wall because the runtime only gives me the high-level TCP/UDP stuff, and I need to drop down to raw POSIX sockets straight from JS. The idea is to expose a low-level socket API on the global runtime object so I can implement custom protocols, poke at socket options at the OS level, all that.

Concretely I want to create sockets by passing address family, type, and protocol directly, both datagram and stream kinds. I need the standard socket constants I'd reach for in C (address families, socket types, option levels, option names) available through a single definitions object so I don't have to hardcode magic numbers. There should be a way to encode an IPv4 address plus port into the binary sockaddr format the OS actually expects.

For datagram sockets I need bind, send, and receive, and the receive side has to hand me back both the data and the sender's address, not just the bytes. For stream sockets I need bind, listen, accept incoming connections, and write to an accepted connection with the byte count returned. Also want to query the underlying file descriptor number, and poll a socket for readability with a way to stop that poll later.

Setting and getting socket options matters too, and the getsockopt side should actually raise an error if I hand it an invalid level, a zero-length buffer, or an unsupported option, don't just silently succeed. Oh and a couple helpers would be great: converting between network interface names and their numeric indices (and it needs to round-trip correctly for every interface the runtime can enumerate), plus a function to compute IP checksums over raw byte buffers.

This is only meaningful on POSIX platforms, so on Windows it's totally fine for the whole thing to be a no-op that quietly does nothing instead of throwing.
