I'm hitting a nasty bug in Argo CD's ignore-differences feature whenever the ignore rules target fields that live inside arrays or lists. Say I've got a resource with routes that carry rate limit policies and I want to ignore the route entries entirely, after normalization those entries come back as empty objects instead of keeping the real data from the live resource. Same deal when I try to ignore a specific env var inside a container's env array, if my target manifest adds new env vars they either go missing or the existing entries get corrupted.

What I'd expect is that when an ignore rule selects elements inside an array, the controller copies the live values for those ignored elements into the target, while still preserving any new entries that only exist in the target. So if the target added new environment variables alongside an ignored one, all of them should show up in the normalized result, the ignored entry with its live value plus the new target entries. Right now normalization is just producing empty objects where there should be real data.

Oh and it should also handle the case where combined ignore rules apply, both field-level JSON pointers and path expressions at once, on a resource that gained extra fields in the target like new labels, new resource requests, or new env vars. When that happens the ignored fields (image, replica count, whatever the rule targets) should take the live value, but all the new target fields need to be included in the normalized output too, nothing dropped. The normalization logic lives around the diff/normalizer code in the application controller, and the fix should make array-element ignores merge live data in cleanly instead of clobbering it. This matters because people rely on these rules for fields the cluster mutates automatically (runtime-injected env vars, auto-assigned replicas), and the current behavior makes resources look perpetually out-of-sync and can overwrite live data with those broken empty objects on sync.
