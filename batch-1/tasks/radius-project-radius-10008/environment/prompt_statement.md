I'm working on Radius's dynamic resource provider, which allows users to register and deploy custom resource types with their own schemas. Right now, when a user registers a resource type with a JSON schema and then deploys a resource of that type, the platform doesn't actually validate the resource's properties against that schema. Resources with missing required fields or wrong-typed values are accepted silently, which defeats the purpose of defining a schema.

I'd like to add schema validation to the deployment pipeline so that when a user submits a resource for creation or update, the system fetches the schema registered for that resource type and API version, then validates the submitted properties against it. If validation fails, the deployment should fail with a clear error message explaining the problem. If no schema is registered, the deployment should proceed normally. Validation should only apply to create and update operations — delete operations should not be affected.

The validation result needs to surface properly through the asynchronous operation result so that users see a meaningful failure status with an error code and message that identifies it as a schema validation failure.
