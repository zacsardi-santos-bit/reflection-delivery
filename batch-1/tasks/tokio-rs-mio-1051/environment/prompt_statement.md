I'm building something where I spin up a bunch of background threads that each register I/O sources (TCP listeners and streams) into a shared registry while my main thread sits there polling for readiness events. The problem is the registry and poll types don't actually implement the standard thread-safety marker traits, so the compiler won't let me drop the registry into a normal shared-ownership container like an Arc and hand clones of it out to threads. It either flat out rejects it or forces me into unsafe workarounds, which I really don't want.

Right now the way you share the registry is by cloning it, and that clone leans on internal reference-counting under the hood, so it looks like a plain value copy but the original and the clone are secretly sharing the same underlying OS resources. That's confusing and I want it gone. Instead I want the poll and registry types to formally satisfy the language's thread-safety requirements so sharing across threads just works, and I want a proper explicit way to make a genuinely independent registry handle, one that's fallible so it's obvious the duplication can fail at the OS level rather than silently succeeding. That explicit try-style clone should replace the old simple clone on the registry.

Once that's all in place I want to be able to put a registry inside a shared pointer, clone that pointer into several threads, have each thread register a different source, and then poll from the main thread and actually get back at least one readiness event. Make this multi-threaded registration pattern idiomatic and safe instead of the non-obvious hacks it needs today.
