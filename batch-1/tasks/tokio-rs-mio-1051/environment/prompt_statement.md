I'm working on a project where I need to register I/O sources (TCP listeners and streams) from multiple background threads while the main thread polls for readiness events. Right now, the registry and poll types don't formally implement the thread-safety traits the language uses to enforce safe concurrent access, so I can't put the registry into a standard shared container and hand it off to threads without the compiler rejecting it.

I'd like the registry and poll types to be officially thread-safe, and I'd like there to be a proper way to create an independent copy of a registry — one that's explicitly fallible, so it's clear the operation can fail at the OS level. The existing approach of a simple clone on the registry should be replaced by this more explicit mechanism. Once these pieces are in place, I should be able to place a registry inside a shared pointer, clone that pointer into multiple threads, have each thread register a different I/O source, and then have the main thread successfully poll and receive at least one readiness event.
