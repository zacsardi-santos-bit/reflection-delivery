I'm building out the entity caching layer in Gravitino and I need a proper cache key class, because right now there's no clean way to tell apart a directly stored entity from an entity that's cached as part of some relationship (think "which roles does this user belong to?" or "which groups does this role have?"). Both kinds of entries share the same entity identity, so a key holding just a name identifier and entity type isn't enough to keep them straight.

What I want is a strongly-typed, immutable key that bundles three things together: a name identifier, an entity type, and an optional relationship type (the relation category). The relationship one is nullable on purpose, since directly stored non-relational entities won't have one, but the name identifier and entity type both need to be there, so reject nulls on those by throwing the appropriate exception while still accepting a null relationship type.

It also needs a compact human-readable string that encodes all its components: the identifier parts joined by dots, then the entity type's short name, and if a relationship type is present its name too, all separated by colons. When there's no relationship type, just omit that trailing component entirely.

Oh and equality and hashing have to be based on all three fields, so two keys with the same identifier, entity type, and relationship type compare equal and hash the same, while any difference in any one of the three makes them unequal. That's what lets it work as a map key with predictable lookups. Having this well-defined format also makes cache debugging way easier when both direct and relation-based entries coexist for the same entity.
