I'm trying to set up a standby cluster that stays synchronized with its primary using WAL archiving rather than a direct streaming connection. The current cluster specification only supports providing streaming replication connection details for a standby cluster, but there's no way to also supply archive recovery settings for the ongoing replication phase after the initial restore. I'd like the standby configuration to be a richer structure that can optionally hold both streaming connection settings and archive recovery settings independently — so that either or both can be specified depending on the setup. It should also be possible to promote such an archive-backed standby cluster to a full primary. I'm also aware that the existing tests for streaming-based standby clusters need to be updated to use the new configuration structure.
