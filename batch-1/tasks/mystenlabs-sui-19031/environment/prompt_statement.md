I'm bumping the max supported protocol version in Sui from 54 to 55 so enum types finally become available to smart contract devs on mainnet. Enum support was gated and unavailable on the main network before, and this version bump makes it generally available (it's already been validated on testnets), so contracts using enums can be deployed and executed. It's a routine version registration, incrementing the ceiling, attaching the right feature flag config, and updating all the downstream snapshots that record the current max version.

Concretely I need the protocol config to recognize 55 as the max supported version so new networks initialize with protocol version 55 by default, and version 55 needs to turn on the newer bytecode format that supports enums. Oh and the public API spec (OpenRPC) has to advertise 55 as the max supported protocol version too.

The annoying part is all the genesis configuration and swarm snapshot files that record the current max protocol version, those need refreshing since they embed derived on-chain object addresses that change deterministically whenever the protocol version changes, so regenerating them will shift those addresses. Make sure every snapshot and test fixture reflects both the updated version number and the new deterministically-derived on-chain state.
