I'm building out the publish path for our CLI that ships plugins and addons together with their docs, and the docs are markdown that usually has images sitting locally next to the source. When we push to a remote registry those local images have to get uploaded and the local paths in the markdown swapped for the hosted URLs, otherwise the docs render with broken images in the registry, which is a bad look for anyone reading them.

What I need first is a scanner that walks a markdown document and finds every local image reference no matter the syntax. That means plain inline images (with or without alt text or titles), HTML `<img>` tags (single or double quotes, possibly spanning multiple lines, possibly with messy attributes), reference-style links, and images that are also wrapped in a hyperlink. For each hit I need the exact byte range recorded so we can substitute later. Group the references by the image's content identity so the same physical image referenced multiple times only uploads once. Skip anything already externally hosted over http or https, and skip images inside code fences or inline code spans since those are just examples, not real refs. Oh and it has to handle file-protocol URLs plus filenames with special characters. If a local path doesn't actually exist on disk, return an error.

Then a companion function that takes the document plus the resolved references (local to remote URL) and produces the updated document with all local paths replaced. Before doing that replacement I want validation that the discovered positions are sane, no overlapping ranges and no range where the end comes before the start, and an error back if anything's inconsistent. This all lives in the CLI publishing utility code, so wire it in there.
