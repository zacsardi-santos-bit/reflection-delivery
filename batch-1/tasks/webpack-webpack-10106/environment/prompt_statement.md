I'm digging into webpack's scope hoisting (the module concatenation optimization in `@lib/optimize/ModuleConcatenationPlugin.js`) and there are two gaps that bug me. First, when I turn on verbose build stats I can see timing logs from the other optimization plugins, but concatenation contributes nothing, it's totally silent. I want it to emit timing info for each of its major phases so it shows up as its own dedicated section in the verbose stats output. The phases I care about are selecting which modules are relevant candidates, sorting those modules, finding/identifying which ones to group together for concatenation, ordering (sorting) the resulting configurations/groups, and finally creating the merged concatenated modules. So five distinct timing measurements basically, each labeled clearly in the log section. This matters because scope hoisting can be one of the slower optimization steps on a big build and right now there's no way to tell if it's the bottleneck.

Second thing, the optimization runs synchronously today and has zero connection to webpack's build cache, so even when nothing changed it re-runs the whole thing from scratch every build, which kills incremental rebuild speed. I want the concatenation process reworked to be fully async so each concatenated module group can be built, cached, and restored on its own. With caching enabled it should pull cached modules before building and store the result after, so subsequent builds restore previously computed concatenated modules instead of recomputing everything. Keep it working the same otherwise, just async plus cache-backed.
