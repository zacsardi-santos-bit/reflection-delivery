I want to add a new nursery lint rule to Biome's JavaScript analyzer that validates the autocomplete attribute on form inputs. The autocomplete attribute only accepts a specific fixed set of standardized values from the HTML autofill spec and related accessibility guidance (WCAG 1.3.5), but right now nothing catches invalid, misspelled, or improperly ordered tokens at lint time, browsers just silently ignore them which breaks autofill and can fail accessibility audits.

So the rule should flag input elements whose autocomplete attribute has unknown tokens, invalid combinations, or values in the wrong order. It reports a diagnostic saying valid values for the autocomplete attribute must be used, with a note that the attribute accepts only a fixed set of specific values, and it should link out to WCAG 1.3.5, the HTML Living Standard autofill section, and the MDN docs for the autocomplete attribute. It shouldn't report on missing, empty, or boolean-form autocomplete attributes, and it needs to skip validation entirely when the attribute value is a dynamic expression instead of a static string, or when the element's input type is determined dynamically.

Oh and I want a config option that takes an array of custom component names so user-defined input wrapper components get the same validation as native inputs. Only components listed there get checked, anything else custom is ignored.

Also please register it properly everywhere so it can be turned on and configured through the normal Biome config file, that means the nursery module declaration, the configuration schema, the diagnostics categories registry, and the options type registry all need the new entry. And if the rule uses any internal sorted lookup tables for fast lookups, add a unit test that verifies they stay in the correct sorted order.
