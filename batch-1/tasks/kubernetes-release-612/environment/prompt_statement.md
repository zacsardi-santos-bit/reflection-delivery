I'm cleaning up the Debian package build tooling for Kubernetes and hit a real problem with kubeadm. Right now the dependency list for the kubeadm package is just hardcoded in the package control template with no awareness of which Kubernetes version we're actually packaging, which is plain wrong. The thing is, starting from Kubernetes 1.11 there's an extra container runtime interface tools package (cri-tools) that became a required runtime dependency for kubeadm, and there's nothing in the code that conditionally pulls it in based on the target version, so packages built for 1.11+ end up missing tooling they need at install time.

What I want is a function that lives in the existing build tool over in the debian package directory (the Go build helper under `@build/debs`), takes a version object as input, and hands back the correct dependency list as a single comma-separated string plus any error it hits while parsing that version. For anything older than 1.11 the string should carry the four baseline entries: kubelet with a minimum-version constraint (>= 1.6.0), kubectl with a minimum-version constraint (>= 1.6.0), the kubernetes-cni package pinned to an exact version (= 0.6.0), and the standard Debian miscellaneous placeholder `${misc:Depends}`. Then for 1.11 and newer it's those same four in the same order plus cri-tools pinned to a minimum of 1.11.0 tacked on at the end. The output needs to drop straight into a Debian control file, so comma-separated, formatted cleanly. Getting this right per release is what makes the packages actually valid and installable.
