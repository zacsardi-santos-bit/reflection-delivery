I'm working on a Go mock generation library and I'd like to refactor the main constructor so it uses a configuration struct instead of positional arguments. Right now the constructor takes two separate string parameters — a source directory and an optional package name — but this makes it hard to add new options without breaking existing callers. I want to introduce a configuration struct with named fields for source directory, package name, and a new option for choosing the code formatter. The source directory should be the only required field, with the package name defaulting to an inferred value and the formatter defaulting to the standard Go formatter when not specified. There should also be support for an import-aware formatter as an alternative choice. All existing functionality should be preserved under the new interface.
