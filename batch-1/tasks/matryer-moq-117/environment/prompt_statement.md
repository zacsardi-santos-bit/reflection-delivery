I'm cleaning up the API on our Go mock generation library and I want to fix the main constructor before we add more options to it. Right now it takes two separate positional string args, a source directory and an optional package name, and it's already painful, every time I want to add a knob I'd have to break every caller. So I'd like to switch it over to a single configuration struct with named fields instead.

The struct should carry a source directory, a package name, and a new field for picking the code formatter. The whole point is that callers only fill in what they care about and everything else falls back to sane defaults. Source directory is the only thing that's actually required. If someone leaves the package name empty it should get inferred automatically like it does today, and if they don't set a formatter it should default to the standard Go formatter (gofmt-style).

The formatter field is the new bit, oh and the reason I want it, is so folks can opt into an import-aware formatter as an alternative that post-processes generated mock code and organizes imports for you, instead of just the plain standard formatter. So two choices there, standard by default and the import-organizing one when asked.

Keep all the existing behavior intact under the new struct-based interface, nothing should regress, this is really just about making the API self-documenting and extensible so future options don't force another round of caller churn. Make sure the constructor and its callers in the mock generation code move over to the new config struct approach.
