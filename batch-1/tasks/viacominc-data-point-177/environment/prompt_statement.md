I'm working on an entity processing library and I want to refactor how entity factories receive the entity identifier. Right now, the identifier has to be embedded as a property inside the entity specification object, which mixes together two concerns that should be separate — the entity's identity and its structural configuration. I'd like the factory to accept the identifier as a distinct argument instead of reading it from within the spec.

At the same time, I need a reusable way to validate that an entity's configuration only uses recognized property names. I'd like a utility that, given an identifier, a specification object, and a list of allowed property names, throws a descriptive error if any unrecognized keys are present. I also need a higher-level variant of this utility that automatically treats a standard set of common modifier properties as always-allowed — so consumers only need to list their entity-specific properties, and the base modifiers are included automatically.
