I'm working on fixing architecture support boundaries for live update features in KubeVirt. Right now, the codebase incorrectly treats arm64 as a supported architecture for memory hotplug, when in reality memory hotplug is only available for x86_64 virtual machines. This means the validation logic and error messages need to be corrected — the error message for unsupported architectures currently says memory hotplug is available for both x86_64 and arm64, but it should only say x86_64.

There's also an issue with CPU hotplug: maximum CPU socket configuration is being incorrectly applied to arm64 VMs, where it's not supported. CPU hotplug should only be applied for x86_64 and s390x architectures, and not at all for arm64.

Beyond the feature correctness issues, the test suite needs to be improved. Currently some tests use runtime architecture skip guards to silently bypass tests on unsupported architectures, rather than explicitly parameterizing test cases per architecture and labeling them with architecture requirements. I'd like to replace those skip guards with proper per-architecture test entries using explicit architecture-requirement decorators. Specifically, I need to add three new architecture requirement decorators (for x86_64, s390x, and arm64) and remove the deprecated skip-on-s390x helper function. The tests for unsupported machine types and panic devices should be parameterized with architecture-specific machine type names and device models, decorated appropriately so they only run on the relevant architecture.
