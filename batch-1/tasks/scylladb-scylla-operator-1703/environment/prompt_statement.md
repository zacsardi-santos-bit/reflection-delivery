I'm working on the scylla-operator codebase and need to add two new helper functions to the resource-apply package. The package already has apply helpers for several Kubernetes resource types that follow a consistent pattern: they compute a hash of the desired state, compare it against the existing resource in the cluster, create or update the resource if needed, verify controller ownership before making changes, and emit informational or warning events. I need the same kind of helper for both legacy endpoint records and modern endpoint slice records, since these are currently missing from the package.

Each helper should create the resource if it doesn't exist yet, update it when the desired state differs from what's in the cluster, and do nothing if the resource is already up to date (determined by comparing stored and computed hashes). They should refuse to act on resources not owned by the controller and must handle the case where the local cache is stale compared to the API server. Both functions should be idempotent — calling them multiple times with the same desired state and no external changes should produce no further updates and no events.

The helpers should also handle labels and annotations carefully: externally added labels and annotations (ones not declared in the desired state) should be preserved during updates, only the managed ones should be changed. When no resource version is specified in the desired state, the existing object's resource version should be used instead.
