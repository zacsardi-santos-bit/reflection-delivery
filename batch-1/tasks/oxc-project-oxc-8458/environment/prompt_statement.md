I'm hitting a bug in our TypeScript namespace transformer where it drops import aliases too aggressively. You know how TS namespaces let you write a local shorthand alias pointing at a value from an outer module? The transformer is nuking those alias declarations completely, even when they're actually referenced as values inside the namespace body. The result is broken JS because the variable binding just doesn't exist anymore in the output, so anything that used it blows up with a runtime reference error at the point it runs.

What I want: if the alias is used as a value somewhere in the namespace body, keep it and rewrite it into an ordinary variable declaration in the output. If it's unused, or it only ever shows up in a type annotation position, then it's fine to drop it. There's also that existing transformer option for preserving non-type imports, and when that's on I want all these namespace-local aliases kept unconditionally regardless of whether they're referenced or only appear in type positions. Oh and in every one of these cases, the type annotations on the other variable declarations inside the namespace still need to get stripped out of the output, even when we're preserving the alias itself. So basically: value-referenced alias becomes a var, unused/type-only alias gets removed unless the preserve-non-type-imports mode says otherwise, and type annotations always go away.
