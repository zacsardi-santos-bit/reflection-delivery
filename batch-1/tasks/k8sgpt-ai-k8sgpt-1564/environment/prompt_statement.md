I'm extending k8sgpt to cover resources managed by the Operator Lifecycle Manager, which OpenShift and a bunch of other Kubernetes distros rely on for installing and upgrading in-cluster operators. Right now there's just no coverage for any OLM resource types, so broken operator installs, misconfigured operator groups, dead catalog sources, stuck subscriptions all slip through completely undetected, and cluster admins running OLM get zero actionable diagnostics for that whole chunk of their resource landscape. I want to fix that by adding five analyzers.

First, catalog sources: flag any that aren't in a healthy/ready connection state, and include the name of the failed connection state in the reported error. Second, cluster service versions: flag any that haven't reached the succeeded phase, with the relevant condition details pulled into the error message. Third, install plans: flag ones that didn't complete successfully and surface the failure reason from the status conditions. Fourth, operator groups: detect any namespace that has more than one operator group since that breaks operator resolution, and here the reported name should be the namespace itself rather than an individual object. Fifth, subscriptions: flag any that aren't at the latest known state, pulling in condition reasons like unreachable catalog sources so it's clear why.

Across all five, I want the status conditions woven into the error output so the diagnostics are useful, and anything in a normal/complete/latest healthy state should be silently ignored and produce no results at all. Oh and all five need to be registered as built-in analyzers so they run alongside the existing ones, same as the standard Kubernetes workload analyzers already do.
