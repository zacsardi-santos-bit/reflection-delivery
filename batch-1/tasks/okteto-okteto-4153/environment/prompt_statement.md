We're leaning on an old, basically abandoned Go library for parsing Git URLs and I want it gone. There's a modern, actively maintained package that does the same thing with a matching API, so this should be a pretty clean drop-in swap. Right now the old thing shows up as a direct dependency in our module config and gets imported across a bunch of source files, so I need all of that pointed at the replacement instead.

Concretely, update `@go.mod` so it references the new Git URL parsing library and no longer lists the old one, fix up every import statement in the source files that pull in the old package so they use the new one, and regenerate `@go.sum` so the checksums line up with the new dependency (otherwise the build won't verify). The whole point is that this stays invisible to anyone using the project, so every bit of existing parsing behavior has to keep working exactly like before.

That means parsing HTTPS Git URLs still works with and without trailing slashes and with or without the `.git` extension, SSH URLs still parse correctly whether or not they carry the `.git` suffix, and the messy cases (empty strings, invalid or incomplete URLs) still get handled gracefully rather than blowing up. The reason I care is that an unmaintained dep is a security and compatibility liability, and moving to something maintained means we actually get future bug fixes and patches. Just keep it a straight behavior-preserving swap.
