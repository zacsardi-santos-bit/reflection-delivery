I'm on the litehtml C++ project and I want to flip the build over to strict compiler warnings, warnings-as-errors across every supported compiler, but the moment I turn that on in the build config the whole thing refuses to compile because we've quietly accumulated a bunch of the usual C++ junk. Once it's clean the full test suite can actually run, which is the whole point since latent bugs love hiding when warnings are off.

Here's the stuff that's blowing up. There are signed/unsigned comparison mismatches, like a signed loop counter compared directly against an unsigned container `.size()` result. There's string emptiness being checked by comparing a string against a `""` literal instead of just calling the empty-check method. There's the result of a string search (find) being compared against a signed literal like 0 or -1 instead of the proper unsigned sentinel `std::string::npos`. There are partially initialized aggregate types where a brace initializer only fills some fields and leaves the trailing ones unset. There are function parameters that are named in the signature but never touched in the body. And there's null being returned as integer `0` rather than `nullptr`.

I need all of these fixed throughout the production code, the Linux container implementation, and the test infrastructure so it compiles cleanly under the strict settings.

Oh and the URL parsing tests are part of this too. Some of those test cases only give three URL components in their expected-result data but the struct they initialize has five fields (scheme, host, path, query string, fragment), so the query and fragment end up uninitialized and that trips a warning too. I need each of those URL test cases to fully specify all five components.
