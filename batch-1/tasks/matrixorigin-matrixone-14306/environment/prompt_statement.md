I keep hitting this annoying thing where creating or dropping a user-defined function with a database-qualified name (like when the target database is baked into the function name) doesn't actually check that the database exists first. So if I typo the db or reference one that isn't there, the operation just barrels ahead and blows up later with some confusing downstream error instead of telling me the real problem up front, which is that the database simply doesn't exist.

I want to add a check on both the create and the drop paths that verifies the specified database exists before doing anything. If it doesn't exist, reject the operation immediately with a clear error saying the database does not exist. When it does exist, both operations should proceed normally like they do today.

There's already a pattern in the codebase for checking whether a tenant or a system resource exists before acting on it, so I'd like to follow that same shape and add a shared helper that checks whether a given database exists, then wire that helper into both the function creation flow and the function deletion flow. Basically the create-function and drop-function code should each call this new database-existence check early and bail out with the informative "database does not exist" error if the lookup comes back empty, otherwise carry on as usual.
