I'm working on the kubebuilder project and I need to add support for plugins to store their own configuration data within the project's config file. Right now the config only supports core project fields, but I need plugins to be able to persist structured data under a unique key in the config file, and later retrieve it as a typed object.

This should only work for projects using the newer config version — for older config versions, encoding or decoding plugin data should return an error. When the config is saved to disk, plugin data for newer-version projects should appear in a dedicated section of the YAML file, and loading the file back should correctly reconstruct the plugin data including nested structures and lists. Trying to save a config that has no file path configured should also fail gracefully. I'd like the encode/decode methods on the config model and the save/load cycle to all behave correctly with these constraints.
