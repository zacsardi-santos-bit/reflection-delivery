I'm working with Arrow-rs and hitting a gap around compact decimals. Right now the library only has 128-bit and 256-bit decimal arrays, which are total overkill for a ton of real-world data where you don't need anywhere near that range, so it's just wasted memory and storage. I want to add two new smaller decimal array types, a 32-bit decimal for values with up to 9 significant digits of precision and a 64-bit decimal for values up to 18 significant digits. I should be able to build Arrow arrays for each of these from integer values and set precision and scale on them, and use each new type as a column data type when I'm putting together record batches and schemas.

The part I really care about is that these work end-to-end with Parquet. When I write arrays of these new decimal types out to a Parquet file and then read back the row-group-level statistics (min value, max value, null count, and row count per row group), the reader needs to hand me back those stats as arrays of the correct new decimal type, not fall back to something generic. And the stats should come back marked as exact, not truncated. One wrinkle on the physical storage side: for the smaller precision range (up to 9 digits) Parquet stores these as 32-bit integers, and for the 64-bit decimal with moderate precision (up to 18 digits) it uses 64-bit integer storage, so the statistics reader has to handle both storage widths correctly and still produce the right decimal-typed arrays. Also I need data-page-level statistics to work for these types too, including the annoying edge case where a page contains only null values. This all matters because these compact types are what make memory-efficient analytics practical, and getting their stats into Parquet is what unlocks predicate pushdown and query planning that currently only work for the bigger decimal types.
