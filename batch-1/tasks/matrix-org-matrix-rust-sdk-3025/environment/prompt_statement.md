I'm working in the Matrix SDK on the room list service plus the timeline module and I've hit two gaps I need closed. First one is timeline access. Right now the room list service method that hands you a room's timeline also initializes it as a side effect, so I've got no hook to configure anything before it spins up. I want to split that apart into an explicit init step and a separate retrieval step. So a room should give me a method returning a sensible default timeline builder, and a separate async method that takes any builder and uses it to initialize the timeline. Then retrieval becomes a plain synchronous call that just gives me the already-initialized timeline, and if it hasn't been initialized yet it should tell me that clearly (return nothing / fail gracefully) instead of auto-initializing behind my back.

Second thing, filtering timeline events today means writing a custom predicate closure, which is way too much boilerplate for the common case of "only show room name events" or "hide all message events". I want a declarative filter type that takes include/exclude lists of event types, so whitelist mode means only the listed types show up and blacklist mode means the listed types get hidden. It needs to plug into the existing event filter setting on the timeline. Oh and while I'm in there, I need to be able to treat room topic state events as their own category within the existing state event content type, so topic changes are distinguishable.

Both should work together, I want to init a timeline with a custom event-type filter and then retrieve it cleanly. The motivation is being able to configure timelines properly before use and build focused views like an audit log showing only certain event categories without all the boilerplate.
