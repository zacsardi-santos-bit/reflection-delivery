I'm knee deep in the Amazon Verified Permissions bits of Airflow's AWS auth manager and there's a security hole plus a few gaps I need closed. Right now DAG authorization isn't actually going through the policy service at all, it just checks whether the user's logged in, which means any authenticated user can hit every DAG no matter what the policies say. I need DAG access evaluated through Verified Permissions the same way connections, variables, pools and the rest already are, in the auth manager over in `@airflow/providers/amazon/aws/auth_manager`. Oh and it has to support passing context about which specific aspect of a DAG someone's touching (like its source code, its run history, or its task instances) so the policies can make fine-grained calls on those sub-entities.

Also the authorization facade currently blows up when there's no user object instead of just saying no, so when user is None it should cleanly return false rather than erroring out. While I'm in the facade, I want it to take optional context that gets passed through to the policy evaluation. There used to be an entity-fetcher mechanism there, it's not needed anymore, so rip it out and replace it with a simpler context dict. When context is actually given, wrap it in the format the policy service expects, and when it's absent just omit it from the request rather than sending null.

Last thing, I need a constant for a region name config key in the auth manager constants module with the value `"region_name"` so the authorization service can be pointed at a specific AWS region set via the auth manager config section. And every one of these authorization methods should return the real boolean decision the policy service hands back, not just fire it off and ignore what comes out.
