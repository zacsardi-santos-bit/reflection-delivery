Working on a TrueType hinting engine and I've got a bunch of instructions that were implemented but never actually wired into the dispatch table in the main execution loop, so they're just sitting there commented out. When a font program hits the write-to-storage instruction I get an "unhandled opcode" error instead of the value getting written, and same story for reading back from storage, plus writing and reading the control value table, measuring rendering params like pixels per em and point size, and the point-modification stuff like flipping on/off curve status or untouching points. I need all of these dispatched and executed correctly so WS can store a value that RS reads back, WCVT/RCVT round-trip against the control value table, and the measurement instructions return accurate values from the current graphics state.

A couple of these aren't even implemented yet, so I also need the actual implementations for measuring pixels per em and point size, and for flipping curve points (individual points or ranges) and untouching points.

Oh and there's a backward compatibility wrinkle: the instructions that modify outline points need to respect a mode where if both horizontal and vertical interpolation passes have already run, those point-modification instructions get skipped entirely. That means the graphics state has to track whether each interpolation pass (horizontal and vertical) has completed, so wire those flags in too.

Why this matters: font rendering depends on executing hint programs faithfully, and any instruction that's silently dropped or errors out gives incorrectly hinted glyph outlines. These opcodes show up in plenty of production fonts, so leaving them unhandled just breaks correct rendering.
