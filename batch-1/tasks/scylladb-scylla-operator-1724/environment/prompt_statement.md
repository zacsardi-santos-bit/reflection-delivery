I'm working on the node tuning controller for the Scylla operator. Right now, when it needs to figure out which CPUs are pinned to Scylla containers (so it can assign the remaining CPUs to IRQ handling), it queries the container runtime directly and falls back to reading cgroup filesystem paths when the runtime doesn't provide that information. The cgroup fallback has separate path patterns for different Kubernetes environments like EKS, GKE, and Minikube, which is messy and hard to maintain.

I'd like to replace this whole approach with the kubelet pod resources API, which exposes CPU assignments for all pods in a unified way that works the same regardless of which container runtime or cloud environment you're running on. The function that computes IRQ CPUs should be updated to take a client for this API instead of the container runtime client, and it should no longer need a cgroup mount path parameter. The CPU lookup should work by matching on pod name and namespace, then finding the Scylla container within that pod to get its CPU IDs.

The IRQ CPU logic itself — using the host's full CPU set minus the CPUs assigned to Guaranteed QoS Scylla pods — should remain the same. Burstable pods should still be skipped. I also need a new client interface and implementation for talking to the kubelet pod resources API.
