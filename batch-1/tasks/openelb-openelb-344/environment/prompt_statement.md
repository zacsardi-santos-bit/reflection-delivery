I'm deep in the IPAM controller for our external load balancer operator on Kubernetes (OpenELB-style) and the IP allocation logic needs real unit test coverage instead of the current setup that leans on a full cluster and misses a bunch of edge cases. I want three methods on the IPAM manager type, all testable against a fake Kubernetes client so I don't need a live cluster.

First one takes a service plus the current EIP pool state and decides the action: allocate a new IP, release an existing one, both (when we're switching pools it should emit a release record for the old EIP and an allocation record for the new one), or do nothing. It's gotta handle the service being nil, the service not being a LoadBalancer type, the service missing the required annotations, the service being deleted, and the service that lost its OpenELB load balancer annotation but still holds an allocated IP (that's a release). Nil or non-LB-with-annotations means no action at all.

Second method takes an allocation record and assigns an IP from the named EIP pool to the service. It returns an error in every unavailability case: the pool is being deleted, it's administratively disabled, its protocol differs from what's requested, the requested static IP is outside the pool's range, or the pool's out of capacity. On success it updates the service with the finalizer, a label pointing at the EIP, and the allocated IP in the load balancer ingress status.

Third takes a release record and frees the IP back to the pool, clearing the service's finalizer, label, and ingress status. Oh and if the EIP no longer exists it should still clean up the service state without erroring out. Fast, safe iteration is the whole point here.
