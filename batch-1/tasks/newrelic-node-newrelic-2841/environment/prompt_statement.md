I'm working on adding health reporting to the New Relic Node.js agent so it can integrate with a centralized agent management system. The idea is that when the agent is running under a management layer in a containerized environment, it should periodically write a structured status file to a configurable directory. External tooling can then read that file to determine whether the agent is healthy or experiencing problems.

The status file needs to include a boolean health flag, a human-readable status message, an error code, and timestamps in nanoseconds for when the agent started and when the status was last written. The status should automatically update to reflect what's happening: for example, if the agent is disabled via configuration, is missing a license key, encounters backend connectivity issues, has a misconfigured proxy, gets a force disconnect, is missing the application name, or shuts down. When shut down cleanly from a healthy state, the file should reflect a graceful shutdown. If the agent shuts down from an error state, it should preserve the last error code rather than overwriting it with the shutdown code.

There also needs to be configuration support for enabling/disabling this feature, specifying the output directory (which should support file URI format), and setting the reporting frequency in seconds. These should be configurable both via the config file and via environment variables. When health reporting is not enabled or the output directory is inaccessible, the agent should log a clear message and skip all reporting activity.
