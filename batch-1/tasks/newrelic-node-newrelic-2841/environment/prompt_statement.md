I'm adding health reporting to the New Relic Node.js agent so it can plug into a centralized agent management layer in containerized setups. The idea is when the agent runs under a management control plane in something like Kubernetes, it periodically writes a structured status file to a configurable directory so external tooling can tell whether the agent is healthy without parsing logs or poking at internal metrics.

I want a new config block controlling whether health reporting is enabled, where the status files get written (a directory path or a file URI, so it needs to handle URI format), and how often updates are written in seconds. All of that should be settable via the config file and via environment variables too. When enabled the agent writes a status file at regular intervals holding a boolean health flag, a human-readable status message, an error code, and timestamps in nanoseconds for when the agent started and when the status was last written.

The status needs to auto-update to reflect what's actually going on. If the agent's disabled via config the file should show an unhealthy state with the right error code, oh and same deal for backend/connectivity trouble where it should reflect the specific problem, invalid license key, missing license key, proxy misconfiguration, forced disconnect, or a general connection failure. Also if the app name isn't configured, or some unexpected internal error hits during startup, update the status accordingly. When it shuts down cleanly and was previously healthy, the file should show a graceful shutdown, but if it shuts down from an error state don't overwrite the last error code with the shutdown one, preserve it.

And when health reporting isn't enabled, or the output directory is inaccessible, I just want it to log a clear message and skip all reporting activity, no crashing.
