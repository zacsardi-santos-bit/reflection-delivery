I'd like to add a new lint rule to Biome's nursery group that enforces consistent use of curly braces in JSX. The rule should flag cases where string values are unnecessarily wrapped in curly braces — both when used as child content and when used as attribute values — because those can be expressed more simply without the braces. It should also flag the opposite case: when a JSX element is used as an attribute value but isn't wrapped in curly braces (which it needs to be for readability and correctness).

The rule should come with automatic unsafe fix suggestions: removing unnecessary curly braces (converting the expression to a plain string attribute or plain text child) and adding missing curly braces where needed. For cases where a string child has inline comments alongside it inside the curly braces, the fix should preserve those comments as standalone expression children rather than dropping them.

Things that should be considered valid and not flagged: plain text children, string attributes written without curly braces, numeric or variable expressions inside curly braces, JSX element attribute values already wrapped in curly braces, JSX element direct children, text mixed with expression children, and standalone comment expression nodes.
