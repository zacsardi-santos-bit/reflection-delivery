I'm adding a new nursery lint rule to Biome that enforces consistent curly brace usage in JSX, because it's really easy to end up with a mess where some string values get needlessly wrapped in expression containers while other things that actually need braces go without them, and right now there's just nothing catching that across both attributes and children.

So the rule should flag a plain string value wrapped in unnecessary curly braces when it's a JSX child (that string could just be written directly as text), and same deal when a string is an attribute value inside braces when it could be a plainer attribute. Oh and the reverse too: when a JSX element is used as an attribute value but isn't wrapped in curly braces, flag that since it needs the braces to be valid and readable.

I want automatic unsafe fixes for all of these, so removing the pointless braces (turning the expression into a plain string attribute or plain text child) and adding the missing braces where a JSX element attribute needs them. One tricky bit: if a string child has inline comments sitting alongside it inside the curly braces, the fix can't just drop those, it should keep them around as standalone expression children instead.

Stuff that's totally fine and shouldn't get flagged: plain text children, string attributes already written without braces, numeric or variable expressions inside braces (those legitimately need them), JSX element attribute values that are already wrapped in braces, JSX elements as direct children, text mixed with expression children, and standalone comment expression nodes. Also handle the edge cases right, like multiline string expressions and string expressions with surrounding inline comments. This lands as a nursery rule with the usual diagnostic plus fix suggestion setup so folks can keep JSX consistent without hand-editing.
