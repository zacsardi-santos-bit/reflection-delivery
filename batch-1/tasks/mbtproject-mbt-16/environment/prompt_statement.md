I'm building out a monorepo build tool and right now it can only work off committed git state, it needs a branch name, a commit SHA, or HEAD to figure out which modules to build. That's annoying during active dev because if I've been hacking on a module and haven't committed yet, I can't build just the stuff I've been touching, I have to commit first which kills the iteration loop.

What I want is a way to build off the current local working directory state instead. So basically I need to create a manifest by scanning the working directory and detecting which modules have uncommitted changes or are brand new and not yet tracked by git. This local manifest should be clearly marked as a local snapshot, not tied to any git commit. When there are no changes at all the module list should come back empty, when I've modified files in a module that module should show up, and when I've added a completely new module git doesn't know about yet it should get picked up too and flagged as a local module. Oh and I also want an option to include all modules regardless of change state, for when I need a full local rebuild.

On top of that I need a matching build function that can run builds from this local manifest, routing stdout and stderr appropriately and firing the standard build-stage lifecycle events, so building locally behaves just like a regular build (running the build scripts, reporting build stages, the whole thing). By default it should only build modules with actual local changes though, unless I flip on the include-all option.

Last piece, the local change detection won't work right for modified-but-unstaged files unless I can see them, so I need a utility that retrieves the diff between the current working directory and the index. That's what makes the detection correct even when I've edited files but haven't staged them.
