I'm working on fixing Flink's idle/active stream status handling, which has several correctness issues.

The biggest problem is that watermarks are still being forwarded through operator chains even when the task has been declared idle. This includes both watermarks arriving from upstream and watermarks generated by intermediate operators within a chained pipeline — all of them should be blocked while the task is idle. Only once the task becomes active again should watermarks resume flowing.

Relatedly, new-style sources are incorrectly wrapping every emitted record in a pair of active-then-idle status signals, even when the task was already in an idle state. These spurious status events shouldn't appear in the output — status signals should only be emitted when there's a genuine state change.

The watermark assigner operator has a similar issue: it emits a "stream is active" status event every time it processes a data element, regardless of whether the status actually changed. It should only emit a status change when transitioning between idle and active states.

Finally, the shared watermark tracker doesn't correctly handle the case where all registered partitions are removed. When the last partition is unregistered, the combined output should transition to idle (preserving the last emitted watermark value). And in the opposite situation — when no partitions have ever been registered — the combined output should remain non-idle rather than unexpectedly flipping to idle.

Could you implement the fixes so that: watermarks are properly blocked anywhere in the chain while idle, status change events are only emitted on genuine transitions, and the watermark tracker correctly manages idle state when partitions are added and removed?
