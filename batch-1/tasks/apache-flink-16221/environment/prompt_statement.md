I'm chasing down a batch of idle/active stream status bugs in Flink's watermark handling and could use a hand implementing the fixes. The core issue is that watermarks keep flowing through operator chains even after a task has gone idle. Both the watermarks coming in from upstream and the ones generated by intermediate operators inside a chained pipeline should get blocked while the task's idle, and they should only start flowing again once the task goes active. Right now they leak through everywhere and it corrupts event-time processing downstream.

There's also this annoying thing where the new-style sources wrap every single emitted record in a pair of status signals, active before the record and idle after, even when the task was already idle to begin with. Those spurious events shouldn't show up in the output at all, status signals should only fire on a genuine state change. The watermark assigner operator has basically the same bug, it emits a "stream is active" status event on every data element it processes regardless of whether anything actually changed, so it needs to only emit on a real transition between idle and active.

Last piece, the shared watermark tracker (the multiplexer that combines per-split/partition watermarks) doesn't handle partition removal right. When the last registered partition gets unregistered the combined output should transition to idle while preserving the last emitted watermark value, and in the opposite case where no partitions were ever registered it should stay non-idle instead of unexpectedly flipping to idle. Btw these matter because idle source detection can silently break event-time semantics, watermarks advancing further than they should or status signals lying to downstream operators about whether a source is alive.

So overall I want watermarks blocked at every link in the chain while idle, status change events only on real transitions, and the tracker managing idle state correctly as partitions come and go.
