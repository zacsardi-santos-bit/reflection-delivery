I'm adding a new transformer to logkit's mutate transform package (over in `@transforms/mutate`) that just stamps a fixed static label onto every log record flowing through the pipeline. The idea is people want to tag all their entries with constant metadata like an environment name, datacenter, or service identifier, and right now there's no built-in way to do that at transform time, so they end up bolting on custom logic outside logkit or hacking around it.

Here's what I want. The transformer takes a field name and a fixed value and adds that field to every record it processes. If the target field isn't in the record yet, just add it with the value, easy. But if the field already exists, by default I don't want to clobber it, so it should leave the record alone and return an error signaling the conflict, and also keep a running count of how many records got skipped that way so I can see the error stats later. Oh and I need an opt-in override mode too, when that's enabled it should replace the existing value instead of skipping.

Also the transformer needs to report which pipeline stage it belongs to, and it should run at the stage after parsing, same as the other mutate-style transforms. And it should expose its error statistics (that skipped count) on request. Can you wire this up in the mutate package?
