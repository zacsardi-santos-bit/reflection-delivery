I've noticed that when I pass strings containing shell-special characters as arguments to external commands in nushell, those characters aren't always handled correctly. For instance, if a string contains a semicolon, an ampersand, or a subcommand substitution pattern, it seems like those characters could be interpreted by the underlying shell rather than being passed to the external program as literal text. This feels like a security problem — any string I pass to an external command should arrive exactly as-is, regardless of what characters it contains. This should also hold when the argument comes from the output of another nushell expression, not just from a literal string in the script.
