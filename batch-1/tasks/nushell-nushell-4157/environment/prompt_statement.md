I'm hitting what looks like a shell injection hole in how nushell hands args off to external commands. When I pass a string that has shell-special characters in it, like a semicolon or an ampersand or one of those subcommand substitution patterns, those characters aren't getting sanitized before they reach the underlying subshell, so instead of arriving as literal text they can get interpreted by the shell and trigger stuff I never asked for. That's both a correctness bug and a security problem, since any string I pass should show up at the external program exactly as-is no matter what's in it.

So concretely, if I run an external command with a string arg that contains a semicolon, the command should receive a literal semicolon and not treat it as a command separator that splits things into two commands. Same deal with an ampersand, it should arrive as a literal ampersand and not kick off background execution. And a string with subcommand substitution patterns in it should land as plain literal text, not get evaluated.

Oh and this needs to hold even when the arg value isn't a literal in my script but comes from evaluating another nushell expression, so the sanitizing has to happen right at the point where the argument gets handed off to the external program.
