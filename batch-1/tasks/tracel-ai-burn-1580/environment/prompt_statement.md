I'm working on the compute layer of a deep learning framework and I'd like to improve how memory resources are managed across read and execute operations. Right now, when I want to read data from the compute server or run a kernel, I have to pass references to handles — the handles need to stay alive for the duration of each call. This makes it hard to reason about ownership and lifetime when resources are passed between different parts of the system.

I'd like to introduce a "binding" concept: a lightweight, owned value that gets created from a handle at the point where you want to use it. Instead of passing handle references, callers would convert their handles into bindings and pass those bindings by value into both read and execute operations. This would make resource consumption explicit — creating a binding signals that the resource is being committed to a specific operation.

The binding should carry the underlying memory resource information so that the server can access the actual memory for the operation. It should also support cloning, since autotune operations need to duplicate their resource references for benchmarking. The memory management layer should also be updated to work with bindings by value rather than raw handle references. Ideally, both the client-facing API and the server trait should consistently use this binding pattern.
