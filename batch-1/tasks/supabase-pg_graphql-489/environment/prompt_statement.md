I'm working with the GraphQL API that sits on top of our Postgres extension, and right now the only way I can page through a collection is by following cursor tokens one page at a time. That's fine for sequential traversal but it's painful when I actually want page-number style navigation, like jumping straight to the third page without walking through one and two first. I'd like to add an optional integer offset argument to collection queries so I can skip ahead by a specific number of records, either from the start or from wherever an existing cursor sits.

Couple of behaviors I care about here. This offset should only make sense for forward pagination (the case where I say how many records to return from the front), so if someone tries to mix it with the backward pagination args I want a descriptive error back rather than silently doing something weird. Also the pagination metadata needs to stay honest: when I skip a non-zero number of records, the result should report that previous pages exist even if I never handed it a cursor, since I've obviously skipped past stuff. And when the offset is zero it should behave exactly as if I hadn't passed it at all.

Oh and I want this discoverable, so the argument needs to show up in schema introspection with a description that makes clear it's forward-pagination only and it's an alternative to pure cursor-based pagination. Offset paging is just such a familiar pattern that having it available alongside the cursor stuff gives a lot more flexibility for displaying database-backed data.
