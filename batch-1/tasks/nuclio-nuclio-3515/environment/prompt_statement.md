I'm building out a release automation tool that figures out the current version, the target version, and the helm chart target version during a release, and right now there's no way to persist those resolved values to disk. That's a pain because downstream steps in our CI/CD pipeline need those versions, and without a file to read from they either re-run parts of the release logic or lean on fragile workarounds to pass values between stages. I want a single source of truth written once so multi-stage pipelines can all read from it.

So here's what I'm after: add an option to specify a file path where the release version info gets saved. When a path is provided, write a structured text file containing all three resolved values, current version, target version, and helm chart target version. Keep it a simple line-oriented format, one version per line, each prefixed with its label, so shell scripts and other tooling can pull out individual values with standard text processing utilities like grep or awk. And when no path is given, just skip writing anything and carry on normally, no errors, no side effects.

The labeled line format is the important bit since later pipeline stages depend on it being easy to parse.
