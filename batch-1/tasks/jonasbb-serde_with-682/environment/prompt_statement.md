I'm hitting a compile error when I put our serialization transformation macro on a struct field that also carries an explicit JSON schema type annotation. The macro just blindly generates its own schema annotation for the field without checking whether I already declared one, so the two collide and the whole crate won't build.

What I'm after: a field that gets serialized one way for transport (say as a string over the wire) but shows up as a different logical type (say an integer) in the generated JSON schema. That's a totally normal API-contract situation, the thing's an int in the public schema but we serialize it as a string internally, and right now there's just no way to customize the schema for a field independently from how it serializes. Combining the transformation attribute with an explicit schema-type attribute needs to compile cleanly and the generated schema should use the type I specified, not whatever the transformation would auto-pick.

Also I need conditional schema annotations to behave right. If I gate a schema-type annotation behind a compile-time condition that's always true, it should act exactly like an unconditional annotation and the macro should defer to my type. If it's gated behind a condition that's always false, the macro should treat it as absent and go ahead and generate its own schema automatically.

So basically make the macro detect an existing schema type annotation on the field (including conditionally-enabled ones) and respect it instead of always injecting its own potentially conflicting one.
