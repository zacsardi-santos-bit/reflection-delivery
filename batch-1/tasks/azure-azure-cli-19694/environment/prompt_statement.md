I'm extending AKS cluster update to handle attaching and detaching Azure Container Registries. Right now that ACR attach/detach only works at cluster creation time, but operators managing long-lived clusters need it during updates too, otherwise they're stuck doing manual role assignments or recreating clusters just to change ACR access, which is rough for day-2 management.

The tricky part is figuring out the right client ID for a cluster, since it comes from different places depending on the auth mechanism. For managed identity clusters the client ID lives in the kubelet identity profile, and for service principal clusters it's in the service principal profile. So I need a small utility that determines whether a given cluster object is using managed service identity (versus a service principal), and it's gotta handle edge cases like a missing or null cluster object gracefully. Then I want a method that resolves the client ID regardless of which auth type is in play, and if no client ID can be found it should raise a clear error.

On the update decorator side I need a method that does the attach/detach ACR work during an update. It should look up the correct client ID for the cluster, pull the subscription ID from the context, and call the underlying ACR permissions helper appropriately, once for attach if that was requested and once for detach if requested, with the detach call passing a flag that indicates removal. If no matching cluster object (mc) is provided it should raise an internal error, and when neither attach nor detach was asked for, nothing happens at all.

Also the context object needs a way to retrieve the "detach ACR" parameter in update mode, analogous to how "attach ACR" is already retrieved, and btw the "attach ACR" retrieval should work correctly in update mode too.
