I'm adding config file support to the Cloudflare Pages local dev command and right now it's kind of annoying because Pages dev doesn't read any configuration file at all, so you have to pass everything (bindings, vars, all of it) through CLI flags every single time you run local dev. That's cumbersome for complex projects and inconsistent with how Workers projects work. I want Pages local development to automatically read the standard project configuration file from the project root when running, and apply all the top-level bindings and settings defined there to the running worker, so environment variables, KV namespaces, D1 databases, R2 buckets, service bindings, Durable Object bindings, and AI bindings all become available to the worker at runtime.

The merge behavior I'm after: command line arguments take precedence over config file values, so CLI flags win when both are given (per-run overrides), while config file entries that aren't overridden on the command line get preserved and merged in. This needs to work for both Pages Functions projects and Pages Advanced Mode projects, including proper handling of custom routing rules.

Also a few error messages need updating to reflect this. When no directory, proxy command, or proxy port is given on the command line, the "missing args" error should now hint that you can configure the build output directory in the configuration file as an alternative (since a config file with the output dir set should let Pages dev run without explicit CLI args). And when someone tries to specify a custom path for the config file (which isn't supported), the error should be clearer that it's specifically the custom (non-default) path that's unsupported, not configuration files in general. Oh and the validation errors when checking a Pages config file need formatting fixes too, the error for unsupported environment names should quote each name individually and use proper indentation, and the error for conflicting configuration keys needs its indentation corrected as well. This closes a real gap so teams can check config into version control and stop retyping flags, aligning Pages closer to the Workers dev experience.
