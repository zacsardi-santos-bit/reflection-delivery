So I'm working on this Go payment API client library and hit a couple gaps I want you to close out. First up, the existing payment modification operations, meaning capture, cancel, cancel-or-refund, and refund, each need their response parsing to actually work right and be verified. When the processor sends back a valid JSON body, each one should parse into a result that exposes a payment reference (basically the pspReference identifier) plus a status string coming from the processor. And the important bit, when the body's invalid or can't be parsed as JSON, the parse method has to return an error instead of just silently succeeding and handing back an empty result, which is the kind of thing that bites you later.

Second thing, there's no support right now for adjusting a previously authorized payment amount, and I want to add that. It's a pretty standard flow, merchants sometimes need to bump or lower a pre-auth before the actual capture, think a hotel stay getting extended or a final bill landing different from the initial estimate, and without it folks have to fall back to spinning up a whole new authorization which is annoying. So add an adjust-authorisation operation that follows the exact same pattern as the existing modification ops, its own response type exposing a payment reference and a status string, and its parse method returning an error on malformed input just like the others. Keep it consistent with how capture and friends are structured so the response parsers all behave the same way.
