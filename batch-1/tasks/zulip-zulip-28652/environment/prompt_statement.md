I want to clean up two functions in our frontend markdown module that both work by mutating a message object you hand them, which is honestly kind of a pain to reason about. Right now one of them parses raw message content and writes the rendered HTML plus the message flags back onto the object you passed, and the other pulls links out of the message topic and again writes them back onto that same object. On top of that, the topic-link one makes every caller pass in the linkifier config at the call site even though the module already keeps that in its own initialized state, so it's redundant.

I'd like both to be pure value-returning functions instead, no input mutation at all. The content renderer should take a raw text string and give me back a new object holding the rendered HTML, the message flags, and a status-message indicator. The topic-link extractor should take a topic string and return an array of link objects, and it should read the linkifier rules from the module's own stored state (the same rules the init function sets up) rather than expecting me to pass them in. Oh and when there's no topic, like for direct messages, it should just return an empty array.

Then update all the existing callers to the new signatures, including the local-echo path for both stream messages and direct messages, spreading the returned values into their own message objects wherever they need them. The point is a clearer contract with no hidden side effects, so callers stop having to build a throwaway object just to read values back off it.
