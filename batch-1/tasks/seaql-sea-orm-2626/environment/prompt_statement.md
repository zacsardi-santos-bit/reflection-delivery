I'm working on a Rust ORM library that supports multiple database backends, and I keep hitting a wall when I write code that matches on the active backend. We handle MySQL, PostgreSQL, and SQLite, but that trio doesn't cover every possible configuration, so when some unexpected backend shows up in a match, my only real options are a wildcard arm that panics or non-exhaustive code that won't compile. Neither is great, I can't gracefully handle a backend I don't know how to deal with.

What I want is a dedicated structured error variant meaning "this operation isn't supported by the current database backend." It should carry two things, the name of the backend that's unsupported (as a string) and the name of the operation or context where the failure happened, so callers get meaningful diagnostics about which backend was encountered and what it was trying to do. Then in a match I can just add a catch-all arm that returns this error instead of blowing up.

Oh and the backend type itself needs a method to get its name as a static string, so I can embed it in these error values without hardcoding the name anywhere. That way migration code, schema setup, and other db utilities can return proper recoverable errors instead of panicking on a backend they don't recognize.
