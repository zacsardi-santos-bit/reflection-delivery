I'm building out some quantum arithmetic subroutines in PennyLane and I keep having to hand-roll modular integer addition on quantum registers every time, which is tedious and easy to get wrong. This stuff shows up everywhere in quantum crypto and number theory algorithms, so I want two proper templates in the library instead.

First one operates on a register that's already in the Fourier (frequency) domain, adds a classical integer constant k to the encoded value modulo m. It should handle negative k just fine, and when no modulus is given it should default m to the max value the given wires can represent, which is the nice edge case where m equals that max and you don't need any ancilla wires at all. When m is non-trivial though it does need ancilla wires, so it should error clearly if they're missing, and also reject any overlap between ancilla and data wires. Oh and it has to reject float values for either k or m with a readable error, ints only. Same goes for not enough wires to represent m, complain loudly.

Second template does the same modular addition but on standard computational-basis registers, so it handles the transform itself, basically apply QFT, call the first adder, then invert the QFT. Same interface, same validation, same error conditions.

Both should be importable from the top-level namespace, work with named wires not just integer indices, pass the standard operation validity checks, be jit-compatible, and support program capture (functional tracing) for transform pipelines. Also the Fourier-basis one should expose its internal phase-rotation helper as a module-level function so the decomposition logic is reusable elsewhere. These'd live in the templates area, something like `@pennylane/templates/subroutines/`.
