I'm working in the OpenTelemetry C++ SDK and hit a gap: I can export traces over gRPC and logs over HTTP, but there's no gRPC-based log exporter anywhere. I want to send log records to an OpenTelemetry Collector over gRPC in OTLP format, the same way traces already go out, so my collector config can use one transport for every signal type instead of mixing protocols.

So I need a new OTLP gRPC log exporter that plugs into the existing log provider and batch processor. When a logger emits a record, the batch processor should collect it and hand it to this exporter, which forwards it to the collector via gRPC. It should return a success result when the gRPC call succeeds and a failure result when the call fails or gets cancelled. Also, once the exporter's been shut down, any further export attempts need to return failure too, not silently drop stuff or do something weird.

Log records should carry full context: trace id and span id, the trace sampling/flags, severity level, the log name, the message body, plus key-value attributes across all the usual types, booleans, integers of different widths, floating-point numbers, strings, and arrays of each of those. And the exporter's config options (endpoint, SSL creds, timeout, metadata headers) should reuse the same options pattern as the existing gRPC trace exporter so it all stays consistent.
