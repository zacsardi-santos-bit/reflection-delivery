I'm building out a Java test data generation library and right now the string generator can only spit out ASCII flavored stuff, alphabetic, alphanumeric, hex, or digits, which makes it useless for testing anything that deals with international text, emoji, or multibyte characters. I want to add real Unicode support because tons of real apps handle non-ASCII, user names in different scripts, comments with emoji, content from international users, and today you'd have to hand write or hardcode those test strings.

So here's what I need. The string generator should support a Unicode mode where, when no specific scripts are asked for, it produces code points spanning many different Unicode blocks from across the full Unicode space. I also want to be able to restrict generation to a specific set of writing systems or Unicode blocks, say only Cyrillic and emoji, and when one or more blocks are given the output should contain only code points from those blocks so devs can hit specific i18n scenarios. When a length is specified for Unicode strings it needs to mean the number of Unicode code points, not Java char units, since some code points take two Java chars, and generating a Unicode string of length zero should just give back an empty string.

On top of the per-field config I want a global setting that makes all generated strings in a test session Unicode by default without touching each field. It's gotta be settable programmatically and also expressible as a properties file property, and this new string type setting should be parseable from the properties file config the same way the other enum based settings already work.

Oh and there needs to be an internal utility for mapping Unicode block names to their corresponding code point ranges, and it's gotta be accurate, like the Cyrillic block mapping to its correct start and end code points, the Emoticons block to its range, etc. That lookup infrastructure has to be available and correct.
