I'm hitting a few gaps in Qdrant's general-purpose query endpoint and want to sort them out together. The big one is cross-collection vector lookup for recommendation queries. Our dedicated recommendation endpoint already lets you point at a separate collection as the source of example vectors (handy when the example points live somewhere other than the collection you're searching), but the query endpoint just doesn't do it. I want that lookup working both at the top level of a query and inside nested prefetch queries, and the results should come back identical to what the dedicated recommendation endpoint produces for the same inputs, since people use the query endpoint for composable stuff (combining recommendation with prefetch, fusion, etc.) and shouldn't have to fall back to the narrower endpoint.

Also there's a security hole I noticed. With JWT-based access control, we don't check permissions on the collection you're looking vectors up from, so a user restricted to one collection can just reference another collection via the lookup mechanism and sneak past. I want it to reject that with a permission error when the token doesn't grant access to the lookup collection, and that check has to apply both at the top-level query and inside prefetch queries.

Oh and one more thing, there's a missing validation. If someone sends a fusion-style query (like reciprocal rank fusion) together with an explicit vector name selector in the same request, that combo is meaningless and right now we silently accept it and ignore one of the inputs. I want it rejected with a clear validation error instead.

Across all of this I want descriptive error messages for the failure cases too, so missing lookup collections, missing point IDs, and missing vector names each surface a clear message rather than empty or wrong results.
