I'm working on a vulnerability scanner that needs to fetch dependency metadata from Maven and npm registries, but it currently only makes unauthenticated requests. Many of the registries my organization uses are private and require credentials, so the scanner fails silently when it can't access them.

I need to add an HTTP authentication layer that can handle multiple authentication schemes — basic credentials (via username/password or a pre-encoded token), bearer tokens, and digest challenge-response. The authentication logic should support two modes: one where credentials are always sent with the first request, and another where the client waits for a 401 response and the server's advertised authentication challenge before selecting the appropriate scheme. When multiple schemes are configured, the first applicable one in the configured preference order should be used. Successful authentication should be remembered so subsequent requests to the same server automatically include the right credentials without re-challenging.

For Maven specifically, credentials should be read from the standard Maven settings configuration files, with environment variable placeholders properly expanded. Global settings and user-specific settings should both be supported, with user settings taking priority when the same server ID appears in both. The resulting per-server authentication configuration should be automatically applied when making requests to the corresponding registries.

For npm, the request-making flow should be updated so that authentication is applied at the time the HTTP request is executed, rather than being a separate step.
