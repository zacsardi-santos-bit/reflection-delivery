I'm cleaning up two things in our runtime code and want your help knocking them out together.

First one's an encapsulation issue. Our universal API struct over in the universal API layer exposes a bunch of internal fields as public (exported) names when they really shouldn't be. Specifically the logger, the resiliency policy handler, and the component store are all implementation details, not part of the external contract, and I don't want consumers reaching in and poking at them directly. Please make those three fields private so they're not accessible from outside the package. It's just tightening the API surface so people can't accidentally depend on internals we might change later.

Second one's actually a security bug and it bugs me more. The logic that decides whether a given environment variable name can be accessed from a secret store only does case-sensitive comparisons right now. So the checks that are supposed to block sensitive or reserved names, like keys starting with a reserved prefix or matching a sensitive token identifier, only fire when the casing matches exactly. That means someone can just pass the lowercase version of a blocked name and it slips right through the filter, which is obviously bad since it lets a misconfigured component or attacker grab internal tokens or config. I want the filtering to be case-insensitive so blocked names get denied no matter how they're capitalized (upper, lower, mixed, whatever). Oh and same deal for the allowlist path, when an allowlist is in use it should match entries case-insensitively too, so a key is still allowed even if its casing differs from the allowlist entry. Basically both the deny checks and the allow checks need to stop caring about case.
