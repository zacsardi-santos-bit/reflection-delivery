I'm building out the SAP jenkins-library and there's a gap I keep hitting: there's no dedicated Go package for talking to the SAP Alert Notification Service (ANS). Pipeline steps that want to publish structured alerts have nowhere standard to go, so everyone ends up reinventing HTTP handling and credential wrangling. I want to add a proper client under `@pkg/ans` in Go so we've got one tested path for this.

Here's what I need it to do. There should be a client type that sends a structured event to the service via an authenticated HTTP request using a bearer token, and when the service returns the expected HTTP 202 it comes back with no error, otherwise it hands back an informative error. I also want a connectivity check that does a lightweight authenticated HTTP GET to confirm the setup is reachable and configured right, returning no error on HTTP 200.

The client should be configurable from a service key that bundles the backend URL together with the OAuth credentials, and those service keys need to be parseable from a JSON string, with malformed input producing a clear error rather than something cryptic.

Events should be composable too, so I can merge a JSON-formatted event definition into an existing event object, combining the tags and the resource metadata from both sources. And events need validation before they go out: invalid category, bad severity, a priority that's out of range, or negative timestamps should each produce their own descriptive error message so it's obvious what's wrong. Oh and one more thing, it should automatically translate standard log severity levels into the service's own severity and category vocabulary so callers don't have to think about the mapping themselves.
