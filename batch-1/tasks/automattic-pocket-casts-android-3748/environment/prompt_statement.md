I'm adding support for Pocket Casts AI-generated transcripts on Android and right now the transcript system treats every transcript the same, so there's no way to gate generated ones behind a subscription. I need a boolean flag on the transcript model marking whether it's AI-generated versus human-authored, and it needs to persist locally so there's a new database migration to store that generated flag.

The player behavior is the key bit: when a free (unsubscribed) user opens a generated transcript that actually has content, the UI should show a paywall instead of the transcript text, but paid subscribers (Plus or Patron) should see it normally like any other transcript. Oh and if the generated transcript has no content yet, don't show the paywall at all regardless of tier. For the view model to make that call it needs the subscription manager injected as a dependency so it can check the user's tier. Also the transcript loading function no longer needs the parameter that tells it whether the transcript view is currently open, that check is gone so update all the callers accordingly.

When picking the best transcript for an episode out of a list of candidates, prefer human-authored ones over generated, but generated-only should still work as a fallback so it's usable.

On the fetching side I want a new Pocket Casts-specific transcript source supported in the show notes response, and transcripts coming from that source get automatically flagged as generated. Entries missing either a URL or a type should be filtered out. Also if an episode has no transcripts from any source at all, the update process should still run with an empty list rather than skipping entirely.

This matters because these generated transcripts are a premium feature, so they need proper attribution, selective gating for free users, and lower priority than human-provided transcripts when both exist.
