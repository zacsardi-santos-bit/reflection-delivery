I'm cleaning up our API docs extraction tooling and hit an annoying inconsistency. The whole project is TypeScript now but this one utility that parses TS source files and pulls out documentation is still plain JavaScript using old-school CommonJS. So everywhere we want to use it we're stuck doing a `require` call instead of a normal import, which means special-case handling in the build config and no type checking on it. Kind of gross.

What I want is to convert that JS extraction utility into an actual TypeScript file and expose its main extraction function as a named export, so I can pull it in with standard TS/ES module import syntax rather than the CommonJS require dance. The file itself should stop being a `.js` and become a `.ts`, and the entry function needs to be a named export (not a default export or module.exports assignment) so imports look consistent with the rest of the codebase.

The important bit is nothing changes behaviorally. It still has to parse TypeScript sources and extract docs for directives, components, services, and interfaces, along with their inputs, outputs, methods, properties, and type parameters, plus JSDoc annotations like deprecation notices and feature-introduction (since-version) info. All of that has to keep working exactly like before, the only difference anyone should notice is that it's imported with a named import now instead of loaded via require.
