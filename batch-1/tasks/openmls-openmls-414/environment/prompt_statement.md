I'm working on our MLS group management library and hit a gap around Welcome messages. Right now when someone gets invited to a group they can't join off the Welcome alone, they have to receive the ratchet tree separately through some out-of-band channel first, which is a pain for deployments and testing. I want to add a config flag on the managed group config that controls whether the ratchet tree gets embedded in the Welcome.

When the flag is on and a new member is added, the Welcome sent to them should carry the ratchet tree so they can join successfully with just the Welcome and nothing else. When it's off (and off should be the default, keeping today's behavior), joining from a Welcome without an externally-provided ratchet tree needs to fail with a clear, specific, identifiable error saying the ratchet tree is missing, not silently misbehave or panic.

Two things I need concretely: the config constructor should accept this new flag as a parameter, and the join-from-welcome operation should correctly succeed or fail depending on whether the ratchet tree is actually available, either embedded in the Welcome or passed in externally. Basically the join should reconstruct group state fine when the tree's there and error out cleanly when it isn't.
