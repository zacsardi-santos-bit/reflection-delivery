I'm working on a project that uses Biome to lint and format CSS, and I'm running into issues with two modern CSS at-rules that Biome doesn't seem to support yet. One of them is for defining anchor-positioning fallback rules — it takes a dashed custom identifier as a name (like a custom property name starting with double hyphens) followed by a block of CSS declarations. The other is for configuring animated view transitions between pages and takes just a declaration block with no name argument.

Right now, Biome's parser doesn't recognize either of these at-rules as valid CSS constructs, and the linter flags them as unknown at-rules even though they are part of current CSS specifications. I need the parser to be able to properly build a syntax tree for both of them, and I need the linter's unknown at-rule check to recognize them as known, valid CSS so it stops reporting false positives. Both at-rules should work correctly whether the block is empty or contains standard property declarations.
