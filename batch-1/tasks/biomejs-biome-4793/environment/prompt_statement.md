I'm hitting a wall with Biome's CSS support and two modern at-rules it just doesn't understand yet. The first is `@position-try`, which sets up anchor-positioning fallback rules. It takes a dashed custom identifier as its name (basically a custom-property-style name that starts with a double hyphen like `--my-fallback`) followed by a block of CSS declarations. The second is `@view-transition`, which configures animated view transitions between pages, and that one takes no name at all, just a declaration block.

Right now the parser in Biome's CSS crate can't build a proper syntax tree for either of these, so they end up as malformed or unknown nodes, and then the linter's unknown at-rule check (the one that lints for at-rules it doesn't recognize) flags them as false positives even though both are part of current CSS specs. I want the parser to properly recognize and build structured syntax nodes for both, and I want that unknown at-rule rule to treat them as known, valid CSS so it stops complaining.

Both need to work whether the block is empty (like `@view-transition {}`) or full of normal property declarations, so `@position-try --foo { top: 0; }` and `@view-transition { navigation: auto; }` should both parse cleanly and lint without errors. This is friction for anyone using these features in production since Biome currently generates bogus lint errors and could reject or mangle otherwise-valid stylesheets. Getting both parsing and the lint recognition right keeps things compatible with where CSS is actually going.
