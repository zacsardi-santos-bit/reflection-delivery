I'm working on adding support for custom profile attributes in the mobile app's edit-profile screen. Right now, even when the server has custom profile attributes configured, those fields don't show up in the edit-profile form at all — users have no way to see or change them from mobile. I need the form to load the custom attribute values from the server when the screen opens, display them as editable fields alongside the standard profile fields, and save any changes back to the server when the user submits.

To support this, I also need a new remote action that fetches both the attribute field definitions and the user's current values and combines them, as well as an action that sends the updated values back to the server. The REST client is also missing the method to update custom attribute values via a PATCH request. Additionally, a reusable hook is needed for managing a dynamic keyed collection of focusable field references, since the form's field list is now built dynamically and the old approach of individual static refs doesn't scale.

The edit-profile form component itself needs to conditionally render the custom attribute inputs based on a feature flag prop — when the flag is off, those inputs should not appear; when it is on and there are custom attributes, each should be rendered with appropriate identifiers so that changes can be routed back to the right attribute in the state.
