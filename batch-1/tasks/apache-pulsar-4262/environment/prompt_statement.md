I'm hitting an orphaned schema problem in Apache Pulsar. When the broker garbage collects a topic (the GC kicks in because there are no active consumers and no subscriptions), the schema that was registered with that topic just sits there in the schema registry forever. The topic's gone but its schema record lingers, so over time the registry fills up with stale entries for topics that don't exist anymore.

What I want is for schema cleanup to be tied to the topic lifecycle so it happens automatically during garbage collection, and this needs to work for both persistent and non-persistent topics. When the broker GCs a topic, the associated schema should get deleted from the schema registry right along with it.

The important part is the schema should only go away when the topic is actually being removed. If a topic still has active consumers, it shouldn't be garbage collected at all and its schema stays intact. Same deal if there are existing subscriptions even when no consumers are currently connected, don't GC it, leave the schema alone. But once all the subscriptions get deleted and there aren't any active consumers left, then the next round of GC should clean up both the topic and its schema together.

So basically the schema deletion path needs to run inside the GC logic for both topic types, gated on the same conditions that already decide whether a topic can be collected. Get the lifecycle lined up so decommissioned topics don't leave garbage behind.
