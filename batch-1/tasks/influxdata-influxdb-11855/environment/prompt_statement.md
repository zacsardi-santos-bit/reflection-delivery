I'm trying to display human-readable names for resources across a bunch of UI features (audit logs, authorization descriptions, that kind of thing) and right now it's a pain because there's no single place to ask "given this resource type and ID, what's its name?" I have to know which specific service to call for buckets vs dashboards vs orgs vs sources vs telegraf configs vs users, and it's turning into a dispatch table that every caller reinvents. I want the key-value service to handle this uniformly with one lookup method that takes a resource type plus an ID and hands back the name.

Behavior I'm after: buckets, dashboards, organizations, sources, telegraf configurations, and users should all resolve to their names through this single call. For resource types that don't really carry meaningful names, like authorizations and tasks, I want an empty string back rather than an error, since that's a legit case. But if the resource type is unrecognized or the ID is invalid, that's an error. And if the ID is valid and the type supports names but nothing exists in the store for it, also an error.

Oh and while you're in there, the test helper functions that spin up store instances need to return the store interface type instead of the concrete implementation types, so I can use them interchangeably across the different test scenarios that exercise this new lookup. Centralizing this on the key-value service is really the point here, it kills the duplication and makes adding name resolution for future resource types easy.
