I'm working with a parser that supports cancellation via a progress callback — the callback returns true to signal that parsing should stop. This works fine during the main parsing phase, but I've noticed that it has no effect once the parser enters the final tree-balancing phase after the main parse is done. For large inputs with many repeated structures, this balancing step can take quite a while, and there's currently no way to interrupt it.

I'd like the parser to respect the cancellation signal during tree balancing as well. Specifically: if the progress callback returns true while balancing is in progress, the parser should stop and return no result, just like it would during the main parse phase. Additionally, the byte offset reported by the callback should remain stable (not advance) during balancing, so callers can detect that balancing is happening by observing that the offset hasn't changed.

It would also be useful if a parse that was cancelled during balancing could be resumed without starting over. Since the main parsing work is already done by that point, resuming should pick up the balancing step from where it left off, rather than re-parsing the entire input. After resumption, the parse should complete successfully and produce a correct result.
