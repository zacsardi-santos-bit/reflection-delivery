I'm hitting a gap in the parser's cancellation story. The progress callback that returns true to stop parsing works great during the main parse, but it does nothing once we're past all the tokens and into the final tree-balancing step. On big inputs, think files with tons of repeated structures, that balancing pass can run for a while and there's no way to interrupt it, so a parse job that enters balancing becomes uninterruptible. That's a real problem for stuff like language servers that enforce timeouts and need to stay responsive, latency spikes there are unacceptable.

What I want is for the balancing phase to respect the same cancellation signal. So if the progress callback returns true while balancing is going on, the parser should stop and return no result, exactly like it does during the main parse (no tree, meaning the parse didn't finish). Also the callback needs to fire periodically during balancing, and the byte offset it reports should stay put and not advance while balancing runs, so callers can tell balancing is happening just by noticing the offset didn't move.

Oh and one more thing, since the main parsing work is all done by the time we're balancing, a parse that got cancelled mid-balance should be resumable without starting over. If I call parse again without resetting the parser, it should pick up the balancing step from where it left off instead of re-parsing the whole input, and after that resumption it should complete successfully and give back a correct tree.
