I'm adding a Solid.js lint rule to Biome, in the nursery group, and I want it to stop folks from destructuring props right in a component's function parameter because that breaks Solid's fine-grained reactivity. The thing is, Solid tracks reactive deps at the moment you access a value, so destructuring at function entry copies values out of their reactive containers and updates stop flowing through. It's a super common mistake for people coming from React where destructuring props is totally idiomatic, and right now there's no way in Biome to catch it.

Here's when I want it to fire: an arrow function assigned to a PascalCase-named variable that has a single parameter which is object-destructured. It should catch every form of that destructuring, so simple properties, aliased properties, computed key properties, default values, rest elements, and TypeScript-typed destructuring, oh and an empty destructuring pattern should get flagged too. For each destructured variable that then gets used as a JSX attribute value, the diagnostic should point at where the variable is used, with a secondary label pointing back to the destructuring site where it was defined.

It should NOT fire when the function takes a plain (non-destructured) props object accessed via property syntax, when there's more than one parameter (not a component then), when the destructuring happens inside the function body instead of the parameter list, when it's a nested inner function inside a component, or when it's just a plain JSX element declaration rather than a function.

The diagnostic messaging needs to make clear this is a Solid-specific thing about property access and reactivity, and it should guide the dev to use property accesses on the props object instead so tracking is preserved. Catching this early saves people from subtle bugs that are a pain to debug.
