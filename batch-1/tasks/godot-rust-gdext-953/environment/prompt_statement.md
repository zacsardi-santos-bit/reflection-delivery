I'm building a Godot extension in Rust and I keep running into a wall where I have to choose between a Godot smart pointer or a Rust trait object but never both. The Godot pointer gives me engine method access, upcasting, and the safe runtime borrow checking, while a trait object gives me polymorphic dispatch, and right now the moment I abstract over a trait I lose the Godot side entirely. What I want is a common case handled well: a bunch of different Godot node types that all implement some shared Rust trait, say a health or damage system, stored together and still able to participate in the normal Godot object lifecycle.

So I need a new smart pointer type that wraps a Godot object and also carries a trait relationship. From it I want to acquire shared or exclusive access guards that let me call the trait methods, and I still want to call Godot engine methods directly through the pointer. The same borrow-checking rules the existing Godot pointer uses should apply here too, so if I'm holding a mutable/exclusive guard, other clones shouldn't be able to grab any guard or free the object, that kind of thing. I also want to upcast to a parent Godot class while keeping the trait connection alive, and convert back to the original concrete pointer type when I need it, preserving object identity. And passing this pointer straight to Godot API functions that take the parent class type should just work.

To wire up the trait relationship I'd like an attribute macro I can slap on a trait `impl` block for a Godot class, and have it auto-generate the connection the pointer needs, so I don't hand-write the plumbing. Oh and all of these new types plus the attribute should come through the standard prelude so nobody needs extra imports to use them.
