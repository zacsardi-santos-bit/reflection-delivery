I'm on a Spartacus project using NgRx and we've got this convention where any action class that represents a failure (basically anything with "Fail" in the class name) is supposed to implement our error-handling interface so the error infra can recognize it consistently. Problem is nothing enforces it, so devs forget and we end up with failure actions that compile fine but silently skip the contract. I want a custom lint rule that flags exactly these cases, a class whose name contains "Fail" that isn't implementing the required interface, and it should auto-fix by adding the interface to the class declaration plus inserting the missing import if it's not already there.

The flagging needs to be precise. A class that already implements the interface should be treated as valid no matter where it sits in the implements list, whether there are other interfaces alongside it, and whether or not there's a superclass. And classes without "Fail" in the name should never get flagged, obviously.

The auto-fix has to handle every class shape correctly: no extends and no implements, only extends, only implements, and both extends and implements. Placement of the added interface matters in each case.

Also I want the underlying logic pulled out into reusable utility modules so other lint rules can use it later. One set of utilities around interfaces: checking whether a class already implements a given interface, and adding a missing one with correct placement given the shapes above. Another set around imports: checking whether a given identifier is already imported from a specific module, and inserting a missing import statement either at the top of the file or right after the last existing import. Keep it clean so it's genuinely shareable, don't bake the failure-action specifics into the generic helpers.
