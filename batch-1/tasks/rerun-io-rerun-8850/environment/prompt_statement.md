I'm working on a video decoding system where individual decoder implementations sometimes need more samples queued ahead of the current playback position than what the player currently provides. The problem is that some decoders just silently produce no output unless they have a certain number of extra samples submitted beyond what was requested — and right now there's no way for a decoder to communicate this requirement to the player.

I'd like to add a method to the decoder abstraction that lets each decoder declare the minimum number of additional samples it needs enqueued ahead of the current request. The default should be zero (so existing decoders that have no special requirements don't need to change), but decoders that need extra look-ahead can override it to return the appropriate count.
