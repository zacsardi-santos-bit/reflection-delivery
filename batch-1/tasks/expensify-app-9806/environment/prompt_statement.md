I'm working on simplifying our staging release management tooling. Right now, our release issue body lists each pull request with two separate checkboxes underneath it — one for QA and one for Accessibility. I want to drop the accessibility tracking entirely and just use a single checkbox per pull request (checked if QA-verified, unchecked if not).

This means the function that generates the release issue body should no longer accept an "accessible PR list" as a parameter, and each PR entry in the body should be a single line with a checkbox rather than a multi-line block. When the body is parsed back into data objects, the PR records should no longer carry an accessibility-verified field. Finally, the tooling that checks the release issue for deployment blockers currently has a special exception that ignores accessibility checkboxes — that exception should be removed so that any unchecked item is treated as a blocker.
