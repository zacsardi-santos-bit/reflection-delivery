I'm trying to get rid of a deprecated, unmaintained third-party HTTP client library that our Node.js APM agent still leans on inside the test suite. It's no longer actively developed so it's a maintenance and security liability plus dependency bloat, and I want it gone completely, not just unused. First thing, pull it out of our declared project dependencies so it never gets installed at all. Then everywhere the tests currently use it to hit test servers needs to switch over to Node's built-in HTTP module directly.

The tricky part is a few tests fire off form-encoded POST requests, which the old library handled automatically but the built-in `http` module doesn't, so I want a small shared helper for that living in the sanitize-field-names test directory rather than copy-pasting the same form-encoding logic into each file. That helper should get reused across all the relevant web framework integration tests (the sanitize-field-names ones span multiple framework integrations). The affected tests are spread across a few areas btw: cloud metadata tests, HTTP instrumentation tests, and those sanitize-field-names tests. Migrate the cloud metadata and HTTP instrumentation ones to use built-in HTTP directly too.

Point is to make the project more self-contained and cut the supply-chain risk from depending on unmaintained open source, while keeping everything working long term.
