I'm running tools in a local sandbox that spins up a virtual environment, and I keep hitting the wall where a tool needs a Python package that isn't bundled anywhere in the codebase. Right now there's just no way to say "hey, install these packages when you build the venv," so if something isn't already present and isn't in a requirements file that ships with the code, the tool blows up at runtime with a module not found error. I want to declare a list of pip package requirements as part of the local sandbox config, where each entry has a mandatory package name plus an optional version so I can pin things when I need to, and then the virtual environment should get provisioned with those deps automatically. This matters because otherwise anything depending on third-party packages can't run locally without me manually poking at the environment first, and I'd rather have it be first-class in the config.

Also, creating a local sandbox config without specifying a sandbox directory should just work, falling back to a sensible default (a configured path if there is one, otherwise a well-known default location) instead of making me set it every time. And I want a REST API endpoint where I can create or update a custom local sandbox config, including those pip requirements, and get back the persisted configuration with all the details I passed in.
