So I'm deep in this code visualization tool (CodeCharta) that lets you diff two versions of a codebase side by side, and I keep hitting a bug in the comparison mode where some nodes only carry difference values, positive or negative, instead of real absolute metric values. That happens when a file got added or removed between the two versions, so it only has a delta. Right now the tree view and the 3D map treat those delta-only nodes like they have zero area, so they get grayed out with the "no area metric" treatment and basically look irrelevant, which is misleading since a negative delta actually means a file shrank or got removed and that's meaningful info I want to see rendered normally.

I need the area validity logic across the app to treat a negative difference value as valid. Concretely, when a node only has a negative delta for the area metric, the tree view item name shouldn't get the no-area-metric styling, and the icon color pipe should return the node's marking color instead of the neutral gray. If the delta is zero or positive, or there's no delta at all, it should still count as no valid area and keep the gray styling. On the map side the building height logic should use zero as the minimum height in comparison (delta) mode when a delta value is present, rather than enforcing the normal positive minimum, but when there's no delta the standard minimum still applies.

Also, two side things while I'm in here. The edge arrow service currently does both populating its internal edge data structure and rendering the arrows in one method call, and I want those split into two distinct method calls so the data-prep step and the rendering step are independent. And oh, the CSS class name that highlights search-matched items in the tree view needs renaming to something more semantically meaningful.
