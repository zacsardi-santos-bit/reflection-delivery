I'm working on a secrets management tool that fetches from a backend and writes output files, and when a secret gets refreshed we update all the files that depend on it, but right now there's no way to control the write order, it just comes out indeterminate or alphabetical. I need an optional numeric priority field on each file in the config so lower numbers get written first, and when a priority isn't given I want a sensible default applied. In real deploys the order actually matters, like a cert chain has to be fully written before a service reloads, so this cuts down on race conditions during rotation. When two files share the same priority I want them sorted alphabetically by path so it stays deterministic and stable.

Also I want to restructure the config so the file list is its own top-level section instead of being nested inside each individual secret definition, it makes things cleaner and lets files reference multiple secrets without awkward duplication.

On the state side, the internal structure that tracks which files depend on each secret needs to carry both the path and the priority, and this priority-aware list has to be sortable. Oh and the sort order has to survive a save-and-reload cycle, so persisting state to disk and reading it back should give an equivalent ordering. One more thing, when I load state from an older file that doesn't store explicit priorities, I want the order the entries appear in the file to be used to reconstruct the priority sequence so the effective ordering is preserved.
