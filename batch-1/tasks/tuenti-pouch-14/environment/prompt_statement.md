I'm working on a secrets management tool that writes output files using data fetched from a secrets backend. Right now, when a secret is refreshed, the tool updates all files that depend on it, but there's no way to control the order in which those files are written. I need to add support for an optional numeric priority field on each file in the configuration, so that files with a lower priority value are written first. When multiple files share the same priority, they should fall back to alphabetical ordering by path to keep things deterministic.

I also need to restructure the configuration format so that the file list is a top-level section rather than being nested inside each individual secret definition. This makes the config cleaner and allows files to reference multiple secrets without awkward duplication.

On the state management side, the internal data structure that tracks which files depend on each secret needs to be updated to carry both the file path and its priority. This priority-aware list needs to be sortable, and the sort order must survive a save-and-reload cycle. When loading state from an older file that doesn't store explicit priorities, the order of entries in the file should be used to reconstruct a sensible priority sequence.
