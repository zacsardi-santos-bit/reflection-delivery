I'm working on the ECS agent's introspection server and need to refactor it into a cleanly structured, testable package. Right now there's no way to construct the introspection server programmatically with configurable options like timeouts or toggling profiling endpoints on and off. I also need a proper typed error system so that different kinds of failures — resource not found, data fetch failure, multiple conflicting results — are translated correctly and consistently to HTTP status codes and corresponding operational metrics.

The server should expose endpoints for agent metadata, task metadata (queryable by full container identifier, short container identifier, or task ARN), and license text. It should validate its required inputs at construction time and return clear errors if they are missing. Profiling endpoints should be off by default and only exposed when explicitly enabled; when enabled, the write timeout should be bumped to accommodate long-running profiling requests. The server's root endpoint should advertise only the currently active endpoints. Panics inside handlers should be caught and translated to 500 responses with a crash metric emitted rather than crashing the server.

I also need a small helper to write plain-text responses with the correct content type, and a mapping utility from content type strings to human-readable labels for logging.
