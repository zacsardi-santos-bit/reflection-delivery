I'm cleaning up the ECS agent's introspection server and want it pulled into its own properly structured, testable package with a real API for building and configuring the thing. Right now I can't construct the server programmatically at all, no way to pass custom read/write timeouts or flip profiling endpoints on and off, and there's no typed error system so backend failures don't map consistently to HTTP status codes or the operational metrics we emit.

So here's what I want. A constructor that validates its required deps at build time, specifically agent state and the metrics factory, and returns a descriptive error if either is nil. It should take optional config for read timeout, write timeout, and whether profiling is enabled. Profiling's off by default, and when it's off those profiling paths shouldn't be exposed and the root endpoint must only advertise the currently active non-profiling endpoints. When profiling's on, include the profiling paths and also bump the write timeout so long-running profile requests don't get cut off.

The server exposes endpoints for agent metadata, task metadata (queryable by full container id, short container id, or task ARN), and license text. Oh and I need typed errors so a resource-not-found maps to 404, a fetch failure maps to 500, and multiple conflicting results maps to 400, each emitting the right metric. Also any panic inside a handler needs to get caught and turned into a 500 with an empty body plus a crash metric, don't let it take down the server. And a little helper for writing plain-text responses that sets the content type to plain text, plus a mapping utility from content type strings to human-readable labels for logging. Without this we can't tell user errors from internal ones or actually monitor the introspection service's health, and a configurable API makes testing way cleaner too.
