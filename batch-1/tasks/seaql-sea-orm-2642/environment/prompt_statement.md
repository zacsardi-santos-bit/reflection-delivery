I'm hitting a wall with sea-orm's partial model system and could use a hand extending it. When I build a custom query result struct that pulls data from a joined table, I can use the nested attribute to grab fields from another partial model, but I can't just point a nested field at an actual entity's `Model` type directly. So if I want every column from a joined entity, I end up defining a redundant partial struct that mirrors the entity model field for field, which is pure boilerplate since the full model already describes exactly those fields.

Same story on the query side, I'd love to call the partial model query method with an entity's own `Model` as the target type and get results back typed as that model, but right now that only works with purpose-built partial structs, not the entity model types themselves, so I'm forced to write a redundant wrapper type just to get there.

What I want is for entity `Model` types to be treated as first-class participants here, both as the top-level target of a partial model query and as a nested field inside a partial model struct. The nested case especially matters with left joins, where the related record may or may not be present, so wrapping the nested model in an optional container should populate the full related record when there's a match and give back an absent value when there isn't. This should cut the duplication and make the API more consistent overall, no more duplicating field definitions just to get behavior the full model already gives me.
