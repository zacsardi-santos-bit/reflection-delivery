I'm using a Rust serialization helper library where I lean on its wrapper types to control how struct fields serialize, and now I want to generate JSON schemas for those structs too. Problem is a bunch of the wrappers I use don't implement the schema generation trait yet, so the moment I derive JSON schema on a struct that touches them the build just falls over. That's blocking me from generating API docs, validating payloads, or using any schema-driven tooling on models that include these wrappers, which is kind of the whole point.

Can you add JSON schema support for these? The byte-array wrapper should produce a schema describing an array of unsigned 8-bit integers. The null-defaulting wrapper should say the field is either the inner type or null. The separator-delimited string wrapper should just describe a plain string. The type-conversion wrappers should reflect the target type being converted into, not the original Rust type. The map-from-sequence wrappers, both the one over a vector of pairs and the one over a fixed-size array of pairs, should describe an object with additional properties matching the value type.

Oh and the two set wrappers matter a lot here because their semantics differ. The one that silently accepts duplicates and keeps the last value should produce an array schema of the inner element type with duplicates explicitly permitted, while the one that rejects duplicates should produce an array of the inner element type with unique items required, meaning JSON input containing duplicate values should actually fail schema validation. Also the borrowed-string wrapper should produce a valid schema consistent with the underlying string type. Basically everywhere the schema trait is missing on these, wire it up.
