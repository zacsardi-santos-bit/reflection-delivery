I'm migrating the commitlint CLI package's test suite over to the same test runner the rest of the monorepo already uses. The test files themselves have already been rewritten to the new framework's syntax, but two things are still off: the project-wide test runner config doesn't know to pick up the CLI package's tests, and the CLI package still carries the old framework around. So I want the project-level runner configuration updated to include the CLI package's test source files so that running the standard project-wide test command actually executes the CLI tests too, no special handling. Right now they get skipped because the runner never looks there.

Then I need the old testing framework gone from the CLI package entirely, its config file, its scripts in package.json, and the dependency itself, all removed. Keep the CLI's build tooling intact though, it's only the test-specific bits that should go. After this the CLI package shouldn't reference the old framework anywhere.

Oh and there's a related change in the shared test utility package (the one that sets up fixture directories). Its bootstrap/fixture setup functions should take an optional directory parameter so callers can say where fixture resolution starts from instead of always leaning on the current working directory, which is flaky depending on where tests run from. Also that shared package needs to properly expose its TypeScript type definitions. Consolidating everything under one runner keeps CI simple and means the CLI's always tested in the standard flow.
