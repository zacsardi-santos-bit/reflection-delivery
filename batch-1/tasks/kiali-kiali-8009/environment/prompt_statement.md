I'm working on Kiali's Ambient mesh support and I've got a visibility gap I need to close. When I look at a waypoint workload's details right now I can see the workloads it covers, but I've got no idea which services are enrolled under it, and going the other direction from a service I can't tell which waypoint proxy is actually handling its traffic. For operators this is painful because diagnosing stuff like a service not covered by any waypoint, or two waypoints both claiming the same service, means manually cross-checking labels across a bunch of resources.

So I want two new things in the service business layer. One takes a waypoint's name and namespace and returns all the services enrolled under that waypoint. The other takes a service and returns the waypoint workloads responsible for that service's traffic. On top of that I need the workload model updated so when a waypoint workload gets fetched the response carries both the enrolled workloads and the enrolled services, but only when that waypoint is configured to handle service traffic or all traffic. For enrolled non-waypoint workloads the response should still reference its waypoint by name, just don't include enrolled services there.

The data structures for enrolled services and enrolled waypoints need to carry name, namespace, cluster, and a field noting where the enrollment label actually came from (like whether it was set directly on the service, on a namespace, or on a workload). Oh and the existing field that stores enrolled workloads on the waypoint should switch over to this lighter reference type instead of hauling around the full workload model. This lives in the service and workload business logic plus the related models, so wire it through there.

Also I need a test helper that spins up fake Kubernetes clients with a waypoint deployment, one enrolled service (labeled with the waypoint enrollment label), and one unenrolled service, so I can exercise all this end to end.
