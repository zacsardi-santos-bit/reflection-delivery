I'm hitting a weird silent failure with the no-restricted-imports lint rule. It supports two config styles for listing restricted modules, either a plain array of module name strings, or an array of objects where each object carries the module name plus a custom message explaining why that import is off limits. The string style works great, imports get flagged like I'd expect. But the moment I switch to the object format directly in the top-level array (not nested under some special sub-key, just sitting right there in the array), the restriction gets completely ignored. Imports from that module sail through with zero warnings, which is super confusing since I never get told anything's wrong.

What I want is for both formats to behave identically. If I give the rule an array entry that's an object with a module name (and optionally a message attached), any import from that module should report a violation, same as if I'd passed a bare string. The only difference between the two should be that the object variant lets me attach a descriptive error message. Oh and I should be able to mix plain strings and objects in the same config array without one form breaking the other. Basically the object-style entries need to be recognized and enforced just like strings, so devs relying on custom messages actually get enforcement instead of nothing.
