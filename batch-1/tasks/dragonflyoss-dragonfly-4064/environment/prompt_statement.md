I'm in the storage package and need two helpers added, since right now every caller reinvents piece sizing and nobody has a clean way to check if a task file's already on disk without knowing our internal directory layout and ID rules.

First one's a piece-length calculator. Give it a file's total content length and it divides that by a max piece count of 500, rounds the result up to the nearest power of two, then clamps between a 4 MB minimum and a 64 MB maximum. If content length is zero it just returns the minimum (4 MB). I want the three boundary values exported as named constants (minimum piece length, maximum piece length, max piece count) so other code in the same package can reference them directly.

Second is a task-stat function that checks whether a given task file exists on disk. It takes a base storage path and a URL as required positional args, plus optional metadata via a functional-options pattern: content length, piece length, tag, application name, and filtered query params, each settable independently. If the base path or URL is empty it returns an error. If neither content length nor piece length is provided, also an error. When only content length is given, derive the piece length automatically through the calculator above. Internally it should generate a task ID from the URL, derived piece length, tag, app, and filtered query params using our existing task-ID generation utilities, then return the filesystem metadata for the file at the path built from the base path, a `content/tasks` subdirectory, the first three chars of the task ID, and then the full task ID.
