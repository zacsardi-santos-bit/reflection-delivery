I'm working on the storage package and need two new utilities added.

The first is a piece-length calculator: given a file's total content length, it should divide that length by a maximum piece count of 500, round the result up to the nearest power of two, and clamp the final value between a minimum of 4 MB and a maximum of 64 MB. If the content length is zero, it should simply return the minimum piece length (4 MB). The three boundary values — minimum piece length, maximum piece length, and maximum piece count — should be exported as named constants so other code in the same package can reference them directly.

The second is a task-stat function that checks whether a particular task file already exists on disk. It should accept a base storage path and a URL as required positional arguments, plus optional metadata through a functional-options pattern: content length, piece length, tag, application name, and filtered query parameters. If the base path or URL is empty, it must return an error. If neither a content length nor a piece length is provided, it must also return an error. When only a content length is given, the piece length should be derived automatically using the piece-length calculator. Internally, the function should generate a task ID from the URL, derived piece length, tag, application, and filtered query parameters (using the existing task-ID generation utilities in the codebase), and then return the filesystem metadata for the file located at the path composed of the base path, a "content/tasks" subdirectory, the first three characters of the task ID, and the full task ID.
