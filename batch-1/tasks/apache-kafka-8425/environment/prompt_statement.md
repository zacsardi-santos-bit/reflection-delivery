I'm working on improving how Kafka Streams handles task rebalancing. Right now, when the system decides to move a stateful task from one client to another to achieve a more balanced assignment, it always schedules that move as a warmup replica — even if the destination client is already fully caught up and could immediately take over the task. This wastes time and delays rebalancing unnecessarily.

I'd like to add the ability to recognize which clients are already fully caught up for each stateful task — either because they were the previous host or because their state lag is within the acceptable recovery threshold — and then skip the warmup phase for those movements entirely. When a task is being moved to an already-caught-up client, the reassignment should happen directly and immediately, without being counted as a warmup replica movement. Tasks being moved to clients that are not caught up should continue to go through the warmup process as before.

This requires adding a utility to compute the mapping from tasks to their caught-up clients, updating the assignment logic to accept and pass along this information, and updating the movement calculation logic to use it when deciding whether a move can happen immediately or needs a warmup phase.
