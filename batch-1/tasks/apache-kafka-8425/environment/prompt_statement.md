I'm working on Kafka Streams task rebalancing and hit an inefficiency I want to fix. When we decide to move a stateful task from one client to another to get a more balanced assignment, we always schedule that move as a warmup replica, even when the destination client is already fully caught up on that task's state and could take over immediately. That wastes time and drags out rebalancing for no reason.

What I want is the ability to figure out, per stateful task, which clients are already fully caught up. A client counts as caught up if it was the previous active host of the task, or if its state lag is within the acceptable recovery threshold (basically zero lag). Then for those movements I want to skip the warmup phase entirely, so when a task moves to an already-caught-up client the reassignment happens directly and immediately, and it doesn't count against the warmup replica limit. Tasks going to clients that aren't caught up should still go through warmup like before, and tasks where no client is caught up keep being treated as warmup movements.

Concretely this needs a utility to compute the mapping from each task to its set of caught-up clients, then the assignment logic has to accept and thread that mapping through, and the movement calculation logic that decides whether a move can happen immediately or needs a warmup phase has to actually use it. Oh and immediate moves must not increment the warmup counter. The payoff is faster rebalancing since we're not redoing warmup work for clients that already hold current state, which cuts end-to-end rebalancing latency and makes the cluster more responsive when the topology changes.
