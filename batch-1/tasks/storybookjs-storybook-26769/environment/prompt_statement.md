I'm adding a feature to Storybook's core dev server so it can generate a new story file for an existing component instead of making people hand-write the boilerplate every time. I want to hand it a component's file path, the exported name, and whether that component uses a default or named export, and get back a ready-to-use story file with the right imports and structure.

The generator should figure out TypeScript vs JavaScript automatically from the component's extension. For a TypeScript component I need proper type annotations, so type-checked meta declarations and type-annotated story exports. For a plain JavaScript component clean imports plus an untyped meta/story structure is fine, no types.

I also need two little utilities. One converts arbitrary strings into valid PascalCase variable names good enough to drop into generated code, and it has to handle nasty inputs like leading digits, hyphens, spaces, or other special characters. The other normalizes file path separators to forward slashes no matter what OS you're on, since backslashes on Windows would break the generated imports.

Oh and the whole thing should be wired up channel-based. The server listens for a "create story" request, generates the file, then emits a result event back. On success I want a unique story identifier derived from the file path and story name (so a tool or IDE integration can navigate straight to it), and on failure a descriptive error message explaining what actually went wrong.
