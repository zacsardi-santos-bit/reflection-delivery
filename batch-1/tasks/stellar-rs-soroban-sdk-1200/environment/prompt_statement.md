I'm working with the Soroban smart contract SDK and I've noticed that when I write a contract function that takes a duration or timepoint value as a parameter, the auto-generated contract specification doesn't reflect the correct type. Instead of showing the proper built-in duration or timepoint type, it falls back to treating them as unknown user-defined types. This causes problems for any tooling that reads the contract specification to understand what types a function accepts. The contract itself can be called at runtime just fine, but the generated spec is wrong. I'd like both duration and timepoint parameter types to be correctly identified in the contract's XDR specification so that clients and tools reading that spec get accurate type information.
