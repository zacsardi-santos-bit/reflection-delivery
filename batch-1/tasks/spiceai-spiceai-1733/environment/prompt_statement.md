I'm hacking on the Arrow to SQL DDL library, specifically the PostgreSQL side that turns Arrow schemas into `CREATE TABLE` statements, and I've hit a wall with nested types. Right now the method that generates the PostgreSQL table-creation SQL hands back a single string, which is fine for flat schemas but totally breaks when a schema has structured (nested composite) fields, because Postgres needs those composite types declared in their own statements before the `CREATE TABLE` can reference them. With one string there's just no room to emit those prerequisite statements in order, so any schema with nested structured fields can't be materialized at all, the composite type defs never get emitted and the table creation fails. That's blocking full structural type support on the Postgres backend so I need to fix it.

What I want is for that table-creation method to return a sequence of SQL statements instead of one string. For schemas where every field is a simple non-structured type, the sequence should have exactly one element, the same `CREATE TABLE IF NOT EXISTS` statement as before, so nothing changes there. For schemas that include structured fields, I want one composite type creation statement per structured field prepended to the sequence, and then the `CREATE TABLE` statement after them. Those composite type statements need to be conditional, only creating the type if it doesn't already exist, using Postgres's procedural language block mechanism (the DO block / plpgsql check-then-create pattern) so re-running is safe.

Oh and there should be a standalone builder component for generating these conditional composite type creation statements from a set of Arrow fields, it takes a type name and a collection of fields and produces the right conditional SQL.
