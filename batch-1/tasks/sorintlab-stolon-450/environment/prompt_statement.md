I'm hitting a bug in our PostgreSQL version parsing. When we shell out to the postgres binary to grab its version, the output usually comes back with a trailing newline at the end, which is totally normal for command-line tools. Problem is our parser chokes on it and returns an error instead of pulling out the major and minor numbers. So something like "9.6.7" with a newline tacked on the end should parse cleanly to major 9, minor 6, no error, but right now it doesn't.

Can you fix the parser so it strips or otherwise tolerates that trailing newline before it does the version extraction? And I want to make sure it still handles the cases that already work, so version strings without any trailing newline should keep parsing fine, and ones that include pre-release suffixes need to keep working too.

This matters because a bunch of other code leans on this parser to figure out which PostgreSQL version we're talking to and then picks features and behaviors based on that. When the parser blows up on the typical binary output, all that version-specific logic downstream gets unreliable, so it's worth getting right.
