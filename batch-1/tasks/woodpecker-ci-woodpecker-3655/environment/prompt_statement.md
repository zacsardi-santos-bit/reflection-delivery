I'm working on the Woodpecker CI Kubernetes backend and I want to add a way for pipeline steps to reference native Kubernetes secrets that already exist in the cluster. Right now steps can only use Woodpecker-managed secrets or image pull secrets, so if you've got credentials or config sitting in a cluster secret you have to duplicate all of it into Woodpecker's own secret store, which is redundant and easy to get wrong. Lots of k8s workloads already keep this stuff as cluster secrets so I want steps to consume them directly, but in a controlled way where an admin can turn the whole thing on or off per installation.

So what I need is for step definitions to accept a list of native secret references, and each reference should support three injection modes. Simple mode references a secret by name only and injects all its key-value pairs as environment variables. Key-to-env mode references a specific key within the secret and maps it to an env var, defaulting the variable name to the uppercased form of the key name unless an explicit target name is given, in which case use that. And file mode references a specific key and mounts it as a read-only file at a given path inside the container.

There also needs to be an admin-level config flag controlling whether steps can reference native cluster secrets at all, and it should default to off so installations that don't want steps touching cluster secrets stay secure by default. When the feature's disabled, any secret references in a step should be silently ignored, no error and no injection, just nothing happens.

The actual wiring is the important part, oh and it needs to land correctly in the Kubernetes pod spec: env references end up as environment entries on the container (via secret key refs or an envFrom-style all-keys injection for simple mode), and file references produce volumes mounted read-only into the container at the requested path. This all lives in the k8s backend code under `@pipeline/backend/kubernetes`, so the pod/container construction there is where the secret refs need to be translated into the right env and volume/volumeMount entries.
