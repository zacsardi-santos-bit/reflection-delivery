I'm deep in the ActivityPub publishing code and hit two gaps I want you to close. First off, our content transformations are scattered all over and impossible to test in isolation, so I want a dedicated reusable content preparation utility living as its own module in the publishing directory (something like `@core/server/services/activitypub/`). It should apply transformations on demand where each one is opt-in and off by default so dropping it in doesn't change any existing behavior. The transforms I need are: stripping out the member-only portion of a post body, escaping HTML characters, converting newlines into line break tags, and wrapping content in a paragraph element. Oh and it should expose a well-known marker constant that identifies where the member-only content begins in a post body, that's the designated separator between the public and members-only sections.

Second thing, the publishing service only knows how to publish full blog posts right now. I need a new method for publishing standalone short-form notes too. A note has a content body plus an author handle, and it should get distributed to that author's followers over ActivityPub. If we can't resolve the actor for the given handle, throw an informative error so it's obvious what went wrong.

Also, both the existing post-publishing method and the new note method should return a structured result so callers can tell whether publishing actually happened or got skipped (like when a members-only post has no publicly visible content left after stripping). That result needs a status indicator plus the activity payload. And the publishing service should take the new content preparation utility as a constructor dependency. This is mostly about making the transformation logic reusable and testable while extending what we can publish to include short-form notes for ActivityPub-connected sites.
