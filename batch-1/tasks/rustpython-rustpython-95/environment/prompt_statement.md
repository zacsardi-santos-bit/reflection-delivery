I'm hacking on RustPython's compiler and hit a short-circuit bug with boolean conditions. Python promises that each operand in a compound `and`/`or` chain gets its truthiness checked at most once, that's the whole point of short-circuit eval being safe for objects with side effects. But the interpreter I'm on double-evaluates the truth value of operands when the compound expression sits as the condition of an `if` statement, a `while` loop, or an `assert`.

Here's how it shows up: I make an object whose `__bool__` records that it's been called and raises the second time around, then drop it into an `or` or `and` condition inside an `if`. Under real CPython that error never fires because the truth value is only looked up once, but here it blows up since the operand gets re-checked.

What I want is the codegen for these conditions to jump straight based on the operand's already-computed truth value instead of testing it again. So in an `or` chain inside an `if`, a truthy operand should jump immediately into the body without re-checking, and in an `and` chain a falsy operand should jump past the body without re-checking. Same single-evaluation guarantee needs to hold for `while` conditions and `assert` statements too. The compiler code that emits jumps for these conditional constructs is what needs fixing (see the compile logic in `@compiler/codegen/src/compile.rs`), so that any object with a side-effecting `__bool__` never gets called more than once per use-site. Net goal is making the bool evaluation semantics match CPython exactly.
