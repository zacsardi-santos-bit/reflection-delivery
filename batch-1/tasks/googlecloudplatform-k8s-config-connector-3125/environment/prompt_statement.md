I'm working on the BigQuery Dataset controller in k8s-config-connector and I need to fix how dataset updates and deletes are handled. Currently, when updating a dataset, the controller sends the full dataset object back to the API — including fields that are read-only and shouldn't be included in write requests. This causes unnecessary noise and potentially incorrect behavior. The update operation should instead use partial-update semantics, sending only the mutable fields that actually need to change.

For deletions, the controller doesn't explicitly specify whether the dataset's contents should be preserved. I'd like the delete operation to explicitly indicate that contents should not be deleted, making the behavior predictable regardless of the API's defaults.

After each reconciliation, the dataset's resource ID should be written back into the spec so users can see the actual cloud identifier being managed. I'd also like the default collation field to be properly included in update requests and reflected in exported manifests.

On the test infrastructure side, the HTTP log normalization code needs to be updated. The per-service normalization hook (which let mock GCP services apply their own field replacements during log normalization) should be removed — the normalization logic should work without it. As part of this, the callback signature used when prettifying JSON in HTTP logs should be simplified to not pass the request URL. The BigQuery dataset set/unset field management test scenario should also be migrated to use the direct reconciler mode instead of the older state-into-spec mode.
