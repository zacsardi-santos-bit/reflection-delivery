I'm working on the table function execution framework in our query engine. Table functions go through a bind phase that resolves inputs and produces a bind state, followed by execution phases where data is produced. The problem is that the execution and scanning methods — the ones that create partition states, poll for output batches, and finalize execution — don't receive the bind state at all. They only get the operator state and partition state, so if an implementation needs to reference its original configuration during execution, it has no way to do so without redundantly copying that data into the operator state.

I'd like to thread the bind state through to all of these downstream methods so it's available when needed. That means updating the trait definitions for both execute-style and scan-style table functions to accept the bind state as an additional parameter in the relevant methods. The bind function itself should also be cleaned up — it's currently an instance method but there's no real reason for it to be; it should just be a plain associated function.

Once the trait signatures are updated, all the existing implementations scattered across the codebase need to be brought in line with the new signatures. The series-generating table function in particular should remain fully working — it should be able to execute a generate-series call with valid start, stop, and step values using the updated interface.
