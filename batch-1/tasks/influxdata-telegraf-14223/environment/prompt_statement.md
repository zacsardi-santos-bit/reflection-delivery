I'd like to add a new general-purpose SNMP tag lookup processor to Telegraf. The existing interface name processor does something similar but it's hardcoded to one specific use case. What I really want is a processor that can look up any tags from an SNMP table and attach them to metrics — not just interface names.

The way it should work is: each incoming metric has a tag that identifies the SNMP agent to query and another tag that holds a table row index. The processor should walk the configured SNMP table for that agent, find the row matching the index, and add those values as tags on the metric. Since querying SNMP on every metric would be far too slow, the results need to be cached per agent with a configurable time-to-live. When the cache expires, the next metric for that agent should trigger a fresh SNMP query.

There are a few edge cases to handle: if an incoming metric doesn't have the agent or index tag, it should pass through unchanged. If the index isn't found in the cached data, the metric should still pass through (without the SNMP tags), but the processor should schedule a re-query in case new rows have been added to the device since the last lookup — though only after a configurable minimum interval to avoid hammering the device. There should also be an option to preserve the original ordering of metrics in the output, even when SNMP lookups for different agents complete at different times.

Additionally, I'd like to clean up a code duplication issue: both the new processor and the existing interface name processor need the same default SNMP client settings, so a shared helper function providing those defaults should be introduced rather than each processor duplicating the configuration.
