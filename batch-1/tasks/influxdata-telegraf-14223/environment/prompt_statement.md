I want to add a general-purpose SNMP tag lookup processor to Telegraf. We've already got a processor that enriches metrics with network interface names by doing SNMP lookups, but it's hardcoded to that one use case, and folks who want to attach other SNMP-derived tags (device descriptions, interface speeds, whatever lives in an SNMP table) have no flexible way to do it. So I want a new processor plugin that generalizes this.

The idea: each incoming metric carries a tag that identifies the SNMP agent address to query and another tag holding a table row index. The processor walks the configured SNMP table for that agent, finds the row matching the index, and attaches those values as tags on the metric. Querying SNMP per metric would be way too slow, so results need to be cached per agent with a configurable time-to-live, and when the cache expires the next metric for that agent triggers a fresh query.

Some edge cases: if a metric doesn't have the agent tag or the index tag, it should just pass through unchanged. If the index isn't found in the cached data, the metric still passes through (without the SNMP tags), but the processor should schedule a re-query in case new rows got added to the device since the last lookup, though only after a configurable minimum refresh interval so we don't hammer the device. It also needs to support concurrent lookups across multiple agents with a configurable degree of parallelism, and there should be an optional ordered mode that preserves the original ordering of metrics in the output even when lookups for different agents finish out of order.

Oh and there's a cleanup piece too. Both this new processor and the existing interface name processor need the same default SNMP client settings, so instead of each one duplicating that config I want a shared helper function that hands back those sensible defaults, and both should use it. This matters because people running SNMP-enabled gear usually need more than interface names, and a general lookup makes it much easier to correlate telemetry with device inventory data.
