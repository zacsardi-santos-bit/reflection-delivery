I'm working on a Terraform provider for a managed Kafka service and I've noticed that two configuration fields related to local retention for tiered-storage topics are essentially broken. The fields exist in the schema and users can write them in their Terraform configs, but the values are never actually sent to the API — they were commented out in the implementation — and when Terraform reads topic state back from the API, those fields are also never populated. So from a user's perspective, setting these fields does absolutely nothing.

I need these fields to be properly enabled: values written in Terraform config should flow through to the Kafka API on create and update, and API responses should be read back into state correctly.

I also need validation to be added so that if someone sets the local retention byte limit without setting the overall retention byte limit, they get a clear error explaining the dependency. And if they set the local retention byte limit higher than the overall retention byte limit, they should also get an error about that invalid combination.

Additionally, the function that converts API topic configuration responses into Terraform state currently has a correctness issue: it always populates all configuration fields in the output regardless of whether the API actually returned values for them. This needs to be corrected so that only configuration fields with actual values from the API response are included in the state, with each value stored in the format the Terraform schema expects. The function also needs to be accessible for direct unit testing.
