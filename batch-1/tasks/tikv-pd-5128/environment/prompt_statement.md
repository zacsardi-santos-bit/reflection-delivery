I'm extending the GC safe point management system to support per-service safe points, since right now it only tracks a single global value and that doesn't cut it anymore. We've got multiple services each with their own minimum data boundary, the oldest point in time they need data preserved up to, think the core GC worker plus a change-data-capture pipeline and a backup job, and without per-service tracking they can't safely coordinate GC boundaries. A backup or CDC run could lose data if GC advances past the point they still need, so the whole idea is that GC only moves past the minimum reported across all active services.

What I want is for each service to register and update its own safe point independently, and for the manager to track all registered services and expose which one currently holds the overall minimum. A few constraints matter here. The core GC worker uses a special reserved service identifier and it always has to be registered with a permanent (non-expiring) duration, so if someone tries to register it with a finite duration reject that with an error. A negative duration means remove the service from tracking, so don't apply the update but don't return an error either. And trying to register a safe point below the current system-wide minimum should be silently dropped (no error, update not applied) because data down there may already be collected. Oh and when no services have registered yet, auto-seed the GC worker with a safe point of zero so there's always a floor. Also the constructor for the safe point manager needs to be exported so it's usable from outside its package.
