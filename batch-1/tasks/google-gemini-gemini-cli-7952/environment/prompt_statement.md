I'm working on the Gemini CLI and I want to pull all the structured JSON model request logic into one shared service instead of having every tool reinvent retry loops, default params, response cleanup, and error handling. Right now that duplication means inconsistent behavior across tools and it's annoying to add cross-cutting stuff like telemetry.

So I need a centralized, reusable LLM client for making JSON-structured requests. It should apply sensible default generation parameters and let callers override them per request, and only attach a system instruction when one is explicitly provided. It should wrap requests in a retry mechanism for transient failures. When a model response comes back wrapped in markdown code fences it should strip those automatically and log telemetry that it had to do so, but plain whitespace around a JSON response should just get trimmed without firing any malformed-response telemetry. For errors I want specific, actionable messages for empty responses, unparseable responses, and generic API failures, and aborted requests should propagate the abort error through without being reported as an error (treat user aborts differently from real failures).

This client gets initialized as part of the auth flow and exposed through the config object, so tools reach it via config. If something tries to access it before authentication finishes, throw a clear error saying it's not initialized yet, and after auth it should be ready to go.

Also I need the utility that fixes failed file edit operations (the edit-correction helper) to switch over to this new shared client. It should read a request-tracking prompt ID from async context when that's available, and when it's not, warn in the logs and fall back to a generated ID. It should cache results so identical requests don't hit the model twice, but make a fresh request whenever any parameter differs. Oh and a way to reset those caches during testing would help too.
