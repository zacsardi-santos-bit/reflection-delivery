I'm building out the Firebase Remote Config Go Admin SDK and hit a real gap: server-side condition evaluation just isn't there. Right now when I call the evaluate method on a server template it hands back the static default value for every parameter and totally ignores the conditions in the template, so if a template targets 10% of users for some experimental flag, everybody still gets the default. Useless for rollouts or personalization, and it makes the Go SDK way weaker than the other platforms.

What I want is for evaluate to take a context map (at minimum a user/device randomization id for percentage rollouts) and return values that reflect whichever conditions are active. Conditions can nest OR (true if any sub-condition is true) and AND (true only if all are true), both short-circuiting. Percentage targeting works by deterministically hashing a seed string combined with the randomization identifier to bucket users, and I need it to handle less-than-or-equal-to, greater-than, and between-a-lower-and-upper-bound operators. When there's no valid randomization id in the context, or the operator's unrecognized or missing, that percentage condition should just evaluate to false.

When a condition is true and the parameter's value is set to use the in-app default rather than an explicit remote value, fall back to the default config the caller supplied at template creation and mark the result source as coming from the local default. If there's neither a remote value nor a local default, return an empty string and mark the source as static. Oh and evaluate needs to error out if no template's been fetched into cache yet.

Couple of related fixes while I'm in here: the way default config values get stringified is wrong, string values should be stored verbatim, not JSON-encoded (that was wrapping them in extra quotes). And the template's JSON serialization is using wrong casing on the version identifier field, it should be the lowercase field name.
