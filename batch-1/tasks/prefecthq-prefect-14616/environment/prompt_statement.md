I'm refactoring the event processing in Prefect and I want to pull the causal ordering logic out of the automation trigger processing module into its own dedicated module. Right now all the stuff for tracking which events have been seen, holding events that arrive before the predecessors they depend on, and recovering events whose predecessors never showed up is tangled directly into the triggers module, which makes it impossible to test that logic in isolation and, worse, means multiple consumers can't keep separate ordering contexts without stepping on each other's state (so an event seen in one context looks "already seen" in another, subtle bug city).

So what I want is a scope-aware ordering component. You construct an instance with a named scope, and two instances built with different scopes have to operate completely independently, no shared state at all. The new module should export the ordering class itself plus the relevant exceptions and constants so other parts of the system, including the triggers module, can import them. The triggers module needs to keep working exactly as before but also expose a way for external callers to grab a reference to the ordering instance it uses internally so they can call methods on it directly.

The extracted module has to preserve all the existing behaviors: hold early-arriving events until their predecessors are seen, process followers in causal and occurred-time order, respect a configurable lookback window so very old events don't get stuck waiting forever on a predecessor that'll never come, and raise the appropriate error when recursive follower evaluation recurses too deep. Point is to make this concern testable on its own and reusable, with scoping keeping consumers from accidentally sharing ordering state.
