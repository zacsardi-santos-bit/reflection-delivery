I'm adding support for two flat sampling qualifiers in my WGSL shader compiler and it's a whole end-to-end thing. The WebGPU spec lets flat interpolation carry an extra sampling qualifier that controls which vertex's value gets passed from vertex to fragment shaders, one that forces the first vertex of a primitive and one that lets the implementation pick any vertex freely. Both are already in the spec and other GPU backends accept them, but right now my implementation doesn't recognize them at all so shaders using them just fail to parse.

So first the frontend parser needs to accept both new qualifiers as valid interpolation attributes. Then the validator has to enforce that these two are only legal paired with flat interpolation and reject them when someone combines them with perspective or linear, and while I'm in there the centroid and sample qualifiers should stay invalid for flat interpolation too. Any bad combo should produce a clear structured error that names the offending interpolation and sampling types, not some vague message.

For code gen, the SPIR-V, Metal, HLSL, and WGSL backends should all emit correct output, treating both new qualifiers as plain flat with no extra centroid or sample decoration. The GLSL backend is the exception, OpenGL just can't represent the "first vertex" qualifier, so trying to generate GLSL for a shader that uses it should return an explicit backend error rather than spitting out invalid output. Without this the spec-conformant WebGPU shaders that rely on these qualifiers can't be compiled or validated at all, so I want it working across all of it.
