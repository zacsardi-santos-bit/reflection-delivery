I'm adding support for both versions of the Kubernetes VolumeSnapshot API in our backup and restore tooling. Right now the snapshot code only knows about the older alpha API, but plenty of clusters have moved on to the beta version, which has a different structure, and on those clusters our snapshot operations either silently fail or behave incorrectly. I want the tooling to detect at runtime which API version is actually installed (alpha or beta) and pick the right implementation automatically.

I also want separate, directly-instantiable implementations for each version so callers who already know the version can construct a specific one explicitly. Both implementations need to cover the same full set of operations: creating, getting, deleting, and cloning snapshots, waiting for readiness, retrieving the snapshot source, and looking up snapshot classes by annotation.

The current factory that builds a snapshotter always hands back an object even when no snapshot API exists on the cluster, which makes it impossible to catch that early. I'd like it to return an error instead when neither the alpha nor beta version is supported.

Oh and I need public helper functions to build the unstructured Kubernetes API objects (the snapshot, the snapshot content, and the snapshot class) for both alpha and beta, since the two versions lay out their fields differently. Also the beta API types (things like a snapshot class carrying a driver field and a deletion policy field, plus a snapshot content with its own deletion policy field) should live in a new dedicated package that mirrors how the existing alpha types package is laid out. This way any cluster on the beta API can actually use snapshotting, we stay compatible across Kubernetes versions, and we surface a real error when there's nothing to snapshot with.
