I'm working on js-libp2p and I need a way to prove that routing data, like a peer's set of listen addresses, actually came from the peer it claims to be from and hasn't been messed with by some intermediary relaying it. Right now there's just no built-in mechanism to cryptographically sign and verify arbitrary records that get passed around the network, so a node can't tell an authentic address announcement from a tampered one. This is the groundwork for self-certified, trustworthy peer routing.

What I want is a general-purpose signed data container (an envelope basically) that can wrap any record along with a signature from the originating peer. I should be able to seal a record into it using the peer's private key, then serialize the whole thing to bytes for sending over the wire, and on the other end deserialize it and verify it. Verification takes the raw bytes plus an expected domain string, and if the domain doesn't match it should fail with a recognizable error code. I'm adding a new code for invalid signatures into the errors module (something like `ERR_INVALID_SIGNATURE`) since that's what gets thrown on a domain mismatch. Oh and two envelope instances should be comparable for equality.

Alongside that I need a concrete peer routing record type that holds a peer's listen addresses plus a monotonically-increasing sequence number. It's gotta serialize to and from bytes, support equality checks across peer identity, sequence number, and the addresses, and work with the envelope so a full seal-then-verify round trip works end to end.
