I'm adding Starlark as a fourth pipeline config format in Agola alongside the JSON, YAML, and Jsonnet we already support. The idea is users drop a script in their repo's `.agola/` config directory with a `.star` extension and we detect that extension, execute the script, and hand it the current build context (branch name, tag, ref type, commit SHA, pull request ID, and the rest) exactly like we do for Jsonnet today, so folks can write dynamic pipeline definitions in a Python-like scripting language they already know. The script returns a data structure that we convert to JSON and then parse as normal pipeline config.

The core piece here is the Starlark-to-JSON conversion. It's gotta handle all the common Starlark value types, so dictionaries, lists, strings, integers, floats, booleans, and null. For dicts only string keys are allowed, and if a non-string key shows up the conversion should bail out and return an error with a clear message saying the key can't be converted. Also string values with special characters like newlines and tabs need to be properly JSON-escaped without HTML encoding (so no turning `<` into `\u003c` and that kind of thing).

Then the existing config parsing logic needs extending to recognize the `.star` extension and route those configs through the new execution and conversion path before parsing them like any other pipeline config.
