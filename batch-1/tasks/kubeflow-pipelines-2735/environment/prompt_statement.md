I'm plugging a hole in the multi-user auth for our pipeline server. Right now we only check permissions when a run gets created, so we verify the user can create a run in a given namespace, but once a run exists there's nothing stopping someone from archiving, unarchiving, deleting, terminating, or retrying runs that live in namespaces they've got no business touching. That breaks namespace isolation for multi-tenant setups, so I need the access check applied consistently before any mutation of an existing run.

The annoying part is that once a run is stored in the DB, its namespace lives in an internal model data structure, not the API-layer objects. We've already got a helper that pulls the namespace out of API-level resource references, but there's nothing equivalent for the model objects we get back from the database. So I want a new utility that extracts namespace info from those stored model-layer resource references, analogous to the existing one. Oh and rename the existing API-layer helper so it's obvious it operates on API objects and not stored model objects.

Then wire it up: look up a run by ID, find its namespace from the stored model records, and verify the requesting user's allowed to access that namespace, rejecting with an appropriate error if they're not. This should gate archive, unarchive, delete, terminate, and retry. In single-user deployments all these checks should be no-ops, same as the create path.
