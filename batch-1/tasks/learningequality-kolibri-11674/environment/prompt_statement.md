I'm reworking our quiz/exam feature to move questions into named sections instead of one flat list, and I need the API and model to play along. The idea is each section carries its own unique identifier, a title and description, a resource pool, and a question count, plus an optional list of questions. A section with no questions is totally fine, but if a section is missing its unique identifier, resource pool, or question count it should get rejected with a 400. Same deal if the section identifier isn't a valid UUID, that's a 400 too. And any question that's missing its content identifier should also fail with a 400.

The write path needs to enforce this new section-based shape, so if someone tries to create an exam using the old flat question list format, reject it with a 400. Reads are the tricky part though, older exams already saved in the flat format have to keep fetching successfully, so I want backward compatibility on reads even while writes require the new structure. No manual migration, the legacy data just stays accessible.

Oh and the exam model needs a method that returns all questions as a flat list no matter which format the exam uses, so for the new format it flattens questions out of their sections, and for the older formats it just hands back the questions directly. Also the internal content-download tracking that figures out which content nodes need downloading has to look inside the sections to pull question identifiers, while still handling the legacy flat format correctly. This whole thing is about richer quiz organization by grouping questions into logical sections, and making sure the download system traverses the nested section-and-question hierarchy without breaking anyone's old data.
