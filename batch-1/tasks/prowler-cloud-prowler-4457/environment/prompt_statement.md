I'm working on refactoring the S3 upload logic in the prowler security scanning tool. Right now the code uses standalone module-level functions that require callers to pass the session, bucket name, output directory, filename, and output mode separately on every call. There's also no way to tell programmatically which files succeeded or failed — if an upload fails you just get an exception with no structured error reporting.

I'd like to replace this with a class-based approach where you initialize the object once with the session, bucket name, and output directory, and then call a single method that accepts all the output objects at once organized by category. The method should return a structured result clearly showing which files were uploaded successfully (with their S3 keys, grouped by file extension) and which ones failed (with both the intended S3 key and the error, also grouped by file extension). When there are no outputs to send, it should just return empty success and failure collections.

There are also two utility methods that should live as static methods on the new class: one that derives the S3 object key prefix from an output directory path (stripping up to and including the "prowler/" segment when present, and leaving the path untouched if "prowler/" isn't in it), and one that maps a file extension to its corresponding S3 subfolder name. The extension-to-subfolder mapping should handle at minimum CSV, HTML, and the two JSON variants used by the tool.
