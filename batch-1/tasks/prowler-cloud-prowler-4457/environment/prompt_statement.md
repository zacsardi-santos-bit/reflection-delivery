I'm cleaning up the S3 upload path in prowler and the current setup is annoying. Right now it's all standalone module-level functions where every call has to pass the session, bucket, output directory, filename, and output mode separately, and worse there's no structured way to know what happened. If one upload blows up you just get an exception and can't tell which files made it and which didn't.

What I want is a class over in the S3 output handling code that you init once with the session, the bucket name, and the output directory, and then a single upload method that takes all the output objects at once as a dict keyed by category (like regular outputs and compliance outputs). It should return a result dict with two keys, one for the successful uploads and one for the failures. On success I want each file extension mapped to a list of the S3 object keys that got uploaded. On failure (say the bucket doesn't exist) each extension should map to a list of tuples of the intended S3 key plus the exception that got raised, so callers can handle partial failures gracefully instead of crashing the whole output pipeline. Oh and if there are no outputs to send at all, just hand back empty success and failure dicts, don't error.

Also promote the two path helpers to static methods on this class so they work without instantiating anything. One derives the S3 object key prefix from an output directory path, stripping everything up to and including the "prowler/" segment when it's there, and leaving the path as-is when "prowler/" isn't in it. The other maps a file extension to its S3 subfolder name, and it needs to cover at least CSV, HTML, and the two JSON variants the tool uses. Keeping it grouped by extension throughout makes this way easier to test too.
