I'm adding configurable access control to the API key feature in our Stratos backend. Right now keys are all-or-nothing, there's no way to restrict who can use them, and operators want to roll this out gradually or lock it down to trusted admins. So I want a config setting with three modes: fully disabled, admins only, and enabled for all users.

Here's the behavior I'm after. When keys are disabled, any request to create, list, or delete an API key should get rejected with a "forbidden" error. When it's admins-only, non-admin users trying to manage keys should be blocked the same way, and the middleware that authenticates requests via API key tokens should silently skip auth for keys belonging to non-admin users instead of granting access. When it's enabled for all users, existing behavior stays exactly as it is now.

The middleware processing incoming requests with API key tokens needs updating too. If the feature is fully disabled, it should bypass all key processing entirely. If it's admin-only, it should look up the user tied to the key and only proceed when they're an admin. Important bit: if any lookup fails or the user isn't allowed, don't fail the request outright, just pass it on without setting any auth context.

Oh and the session verification endpoint should return the current setting as part of its config payload so the frontend can react and adapt its UI accordingly.
