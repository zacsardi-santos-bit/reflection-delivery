I'm working with Beam's SQL extension and I keep hitting a wall because variance aggregate functions just aren't there. If I write a SQL query that uses population variance (VAR_POP, divides by n) or sample variance (VAR_SAMP, divides by n minus 1) over a PCollection, it blows up because those aggregations aren't implemented, so right now I have to compute variance myself in lower-level pipeline code outside SQL which is annoying and kind of defeats the point of having a declarative SQL interface for analytical work.

I want both variants working correctly against numeric columns. For integer columns the result should come back as an integer (truncated), and for double/floating-point columns it should be a precise floating-point number. So the type of the input column drives the type of the output.

Also, and this matters for real pipelines, the aggregation needs to support parallel/distributed computation. That means I should be able to build partial accumulators on separate workers and then merge them together correctly using the standard parallel variance combination formula (the one that accounts for count, sum, and the running sum of squared deviations when combining two partial results). If the merge math is wrong the distributed answer won't match the single-machine answer, so the combine logic has to be exact.

Can you add these two variance aggregate functions to the Beam SQL extension so they slot in like the other aggregates and give correct results for both int and double inputs whether the work runs on one node or many? Statistical aggregates like variance are pretty fundamental for data analysis and it'd bring Beam SQL closer to the standard SQL dialects people expect from data warehouses.
