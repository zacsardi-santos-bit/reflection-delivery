I'm working on the OpenTelemetry Go metric SDK and I want to wire up temporality configuration on the reader types. Right now the readers in `@sdk/metric` don't expose any way to say whether they want cumulative or delta reporting, and there's no knob to set it when you build them. Different observability backends need different temporality styles (some want running cumulative totals, others want per-interval deltas, the change since last collection), so I need each reader configurable at construction time instead of relying on a single hardcoded global default.

Concretely, I want to pass an option when constructing a manual reader or a periodic reader that specifies a temporality selector, basically a function mapping an instrument kind to the desired temporality. If nobody passes that option, the reader should default to cumulative temporality. And if someone passes the same option more than once, the last one wins (later settings overwrite earlier ones). Both reader types should also expose a way to query the configured temporality for a given instrument kind so you can check what's in effect.

Oh and the reader interface itself should reflect that temporality is part of a reader's contract, so any type implementing the reader interface has to declare how it handles temporality for a given instrument kind. That way it lines up with what the backend exporter expects without workarounds.
