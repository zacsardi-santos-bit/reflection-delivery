I'm cleaning up the inbound proxy policy system and there's this annoying duplication where we've got two address types floating around that really mean the same thing in the inbound context. The policy enforcement path uses one type (the "server address" wrapper) for lookups and a different original destination address type for connection metadata and authorization results, so we keep converting back and forth all over the place and it makes the data flow way harder to follow than it needs to be. I want to consolidate on the original destination address type everywhere in the inbound policy path, from the policy lookup interface down through the authorization permit and the connection metadata, and drop the "server address" concept entirely.

While I'm in there, the policy lookup interface returns a future right now even though the policy state is already sitting in memory synchronously, so let me make that lookup synchronous instead of handing back a future for no reason.

I want the test proxy builder to let me mark specific inbound ports to skip protocol detection directly, without wiring up a policy controller, so a test that just wants a port treated as opaque can do that cheaply.
