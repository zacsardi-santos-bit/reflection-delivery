I'm hitting a wall with our MLS group messaging library around Welcome messages that carry the ratchet tree inline. The protocol lets you bundle the ratchet tree directly inside the Welcome so a new joiner doesn't have to fetch the tree over some separate channel, and when a group's configured that way the Welcome should be fully self-contained. Problem is, joining from that kind of Welcome just fails right now. It looks like the embedded ratchet tree isn't getting parsed and fed into the new member's group state properly, so any time the tree's distributed in-band instead of out-of-band the whole join path is broken.

What I want is the full flow working end to end: an existing member adds someone, the resulting Welcome (with the tree embedded) gets encoded and then decoded, and the new member can join off of just that Welcome without supplying the ratchet tree through anything else. So the join logic needs to pull the tree out from inside the Welcome and use it to build the group state. Also I need those tree-embedding Welcome messages to round-trip cleanly through encode/decode, and while we're in here, commit messages mixing add, remove, and update proposals together should encode and decode correctly too.

Oh and as part of setting up the join there's a spot where we need to find a key package bundle by matching it against a specific key package, so a little helper for that lookup would help wire this up.
