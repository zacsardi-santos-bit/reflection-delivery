I'm building a suggest box in a VS Code extension's webview UI and there's no keyboard way to open the suggestion dropdown right now, users have to click. I want Ctrl+Space to open the floating popup when the input is focused and the dropdown is closed, that's the well-known "trigger suggestions" combo. So I need a hook that listens for keydown on the reference element and opens the popup only when it's currently closed, pressing it while already open should do nothing. Also only the exact combo counts, any variant with extra modifiers like Shift, Alt, or Meta/Cmd (or a different key) gets ignored, and when it does fire I want the default browser/OS behavior for that key prevented.

One catch, the returned event handler needs a stable function identity across re-renders, so when surrounding context like the open/closed state changes and the hook re-runs, the handler stays the same object. That means I also need a small utility hook that wraps a callback and always hands back the same stable reference while still calling the latest version of the callback internally, otherwise I'll get unnecessary re-renders and perf regressions.

Oh and the mock object utility used in tests is currently duplicated inside the VS Code integration test helpers, I want it pulled out into a shared top-level file so view-layer tests can import it too (the helper and its associated types), and the existing integration test helper should re-export it from that shared location instead of defining its own local copy.
