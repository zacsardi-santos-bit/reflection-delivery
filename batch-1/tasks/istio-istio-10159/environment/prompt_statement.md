I'm working on adding TCP keepalive support to Istio's cluster generation logic. Right now, even when I configure TCP keepalive settings at the global mesh level, those settings aren't being picked up when Envoy cluster definitions are generated. The same problem exists for keepalive settings specified in destination traffic policies.

I need the cluster builder to properly propagate these settings into the upstream connection options of each generated cluster. Specifically: if a global mesh-wide keepalive is set, it should appear in the clusters. If a destination traffic policy also specifies keepalive for a port, that should take precedence over the global setting. And if a policy sets an empty keepalive configuration with no values, the cluster should still carry a keepalive entry to signal that OS defaults should be used — rather than inheriting the global setting. If no keepalive is configured anywhere, the upstream connection options should be absent from the cluster entirely.
