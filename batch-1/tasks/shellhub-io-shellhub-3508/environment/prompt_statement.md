I'm adding a "connection announcement" feature to ShellHub namespaces so admins can set a custom text message that shows up when someone connects to a device inside that namespace. Right now there's nothing like this anywhere in the system, and admins have no way to communicate policies or info automatically at the start of a session, so I want to wire it through all the layers.

On the backend the namespace settings model needs a new connection announcement field, and it should default to an empty string when a new namespace gets created during initial system setup. Existing namespaces in the DB need migrating too, so I want migration number 64 that initializes the field to an empty string on upgrade and cleanly removes it on rollback (reversible, so we can roll back without leftover cruft).

Frontend-wise I need a new component for editing namespace settings that has a text area for the connection announcement sitting next to the existing name field. It should be clearly labeled "Connection Announcement" and carry a short description reading exactly "A connection announcement is a custom message written during a session when a connection is established on a device within the namespace." The component starts in read-only mode and flips to edit mode when the user clicks an edit button, and on save it sends both the name and the connection announcement to the backend together. Oh and if the API call fails I want an appropriate error notification to pop up.

Also the frontend data store that manages namespace data needs updating so namespace objects carry this connection announcement field in their settings, handling reading, storing, and updating the namespace including the new field.
