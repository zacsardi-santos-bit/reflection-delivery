I'm working on the OpenTelemetry Go SDK and need to update it to use the latest version of the semantic conventions. The current codebase references an older version throughout the exporters, SDK, and example code, and the newer version has renamed several attributes — especially around network communication. The attribute names for identifying a remote peer's address and port have both changed, and the name used for an HTTP response status code has also changed.

The most involved change is in the Zipkin exporter: its logic for figuring out the remote endpoint of a span from attributes needs to be updated to support the new attribute names and an expanded, reordered priority list. The new priority should place the newer network peer address attribute above the older socket-based attributes, and should also add support for server address, server socket domain, and server socket address as intermediate sources. Each IP-based source must use its own corresponding port attribute — they must not be mixed up across attribute families. Invalid IP values must result in no endpoint being returned, and IPv6 addresses must parse correctly even without a port.
