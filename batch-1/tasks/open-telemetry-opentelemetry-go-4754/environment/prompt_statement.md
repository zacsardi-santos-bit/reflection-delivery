I'm updating the OpenTelemetry Go SDK to the latest semantic conventions and the whole codebase (exporters, SDK internals, example code) is still pointing at an older version so I need everything bumped to reference the current conventions version. The newer spec renamed a bunch of attribute keys, especially network stuff, so wherever we identify a remote peer's address and port those need to move to their current names, and the HTTP response status code attribute got renamed too so that has to match the current spec name everywhere it shows up.

The gnarly part is the Zipkin exporter over in `@exporters/zipkin`, its logic for pulling the remote endpoint of a span out of the attributes. That whole thing needs to understand the new attribute names plus an expanded and reordered priority list. Highest to lowest it should go: explicit peer service name, then server address (the name one), then the legacy peer name, then network peer address (an IP), then server socket domain (name), then server socket address (IP), then legacy socket peer name, then legacy socket peer address (IP), then peer hostname, then peer address (IP), then finally database name. So the newer network peer address sits above the older socket-based attributes, and I'm adding server address, server socket domain, and server socket address as intermediate sources.

One thing that keeps biting me: each IP-based source has to grab its own matching port attribute, don't mix ports across attribute families. Also invalid IP values should give back no endpoint at all rather than something bogus, and IPv6 addresses need to parse right even when there's no port attached. The point is when someone exports to Zipkin with the latest standard network attributes on their spans, we actually identify the remote endpoint instead of dropping or misidentifying it.
