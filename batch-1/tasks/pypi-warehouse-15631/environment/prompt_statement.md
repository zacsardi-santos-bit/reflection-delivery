I'm working on the PyPI warehouse application and I want to refactor the package upload logic to separate metadata parsing and validation from the HTTP form handling. Right now everything lives in one big module, which makes it hard to test the metadata validation in isolation and hard to reuse it outside of the form context.

I'd like to introduce a dedicated metadata module that can accept either raw bytes from an uploaded package file or form post data, parse the metadata, validate it, and raise structured exceptions that identify the specific field that failed. The validation should cover things like unsupported metadata versions, version strings with local identifiers, field length limits (summary capped at 512 characters), email address format, classifier validity and deprecation, URL scheme restrictions (only http/https), and disallowing direct URL dependencies in distribution requirement fields. There should also be an opt-in flag to allow deprecated classifiers through (useful for backfill scenarios). When parsing form data specifically, the module should handle keywords as comma-separated lists, project URLs as labeled dictionaries, empty strings as absent values, and detect duplicate values for single-value fields or duplicate project URL labels.

I also want to move the upload form validators and form class into their own separate forms module. The form should validate that at least one file digest is provided and that wheel uploads include a Python version specifier.

Finally, the internal function that constructs database dependency records should be updated to work with the new metadata objects rather than form objects directly, and the specifiers stored for distribution requirements should use the normalized canonical format for requirement specifiers.
