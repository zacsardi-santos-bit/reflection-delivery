I'm refactoring the package upload flow in the PyPI warehouse app because right now the HTTP form handling and the Python package metadata validation are all crammed into one big module, and it makes the validation logic impossible to test in isolation or reuse outside a form context, plus the error messages we spit out at package authors are inconsistent and vague about what actually went wrong.

What I want is a dedicated metadata module that can parse metadata from either raw bytes off an uploaded package archive or from HTTP form post data, validate everything, and raise structured exceptions that pinpoint the exact field that failed rather than some generic blob. The validation should cover version format including rejecting version strings with local identifiers, unsupported metadata versions, field length caps (summary maxes out at 512 characters), email address format, classifier validity plus deprecation handling, URL scheme restrictions where only http and https are allowed, and disallowing direct URL dependencies in the distribution requirement fields. Oh and deprecated classifiers should be rejected by default but there needs to be an opt-in flag to let them through for backfill scenarios.

When it's specifically parsing form data, it needs to turn keywords into comma-separated lists, treat project URLs as labeled dictionaries, treat empty strings as absent values, and detect duplicate values for single-value fields or duplicate project URL labels and report those.

Separately, move the upload form validators and the form class into their own forms module so responsibilities stay clean and away from the core upload handler. That form should validate that at least one file digest is provided and that wheel uploads include a Python version specifier.

Last thing, the internal function that builds database dependency records should work against these new metadata objects instead of form objects directly, and the specifiers we store for distribution requirements should use the normalized canonical format for requirement specifiers.
