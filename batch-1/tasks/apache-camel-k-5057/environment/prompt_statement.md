I'm hacking on the builder trait in Apache Camel-K and hitting a couple things I want fixed together. Right now when the trait runs into a bad config, say a build strategy that isn't compatible with the current platform, or a Maven profile reference that's invalid, it just returns a Go error straight up. That's wrong for a k8s operator. What I actually want is for those validation failures to be recorded as conditions on the integration kit's status, meaning the kit gets moved to an error phase with a descriptive condition explaining what happened, and the reconciliation loop keeps going normally instead of bubbling the error up. Users should be able to just look at the integration kit resource status to see what broke.

Second thing, two missing features around custom build tasks and pipeline management. Custom tasks are defined as semicolon-separated strings and I need them to accept a container user ID as an optional fourth field so we can set the security context for those containers. Also I want the trait to support a task filter, a comma-separated list of task names, that lets people pick which pipeline tasks run and in what order. No filter means all tasks run in their default order like today. With a filter, only the listed tasks get included, in exactly the order given. Oh and if a referenced task name doesn't exist, return an error, and if the resulting pipeline's final task isn't a publishing or user-defined task, that's also an error.

One more, the fake client utility we use in tests needs updating so it properly supports status subresource updates on integration kit objects, otherwise the whole status-update approach won't work right in the test environment.
