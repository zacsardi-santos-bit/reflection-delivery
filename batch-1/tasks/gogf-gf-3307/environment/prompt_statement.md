I want every table's dao index file path always included in the reported output regardless of whether it actually got written this run.

Second problem: the per-table overwrite setting doesn't get respected right when there are multiple entries, say one configured to preserve its existing dao file and another configured to regenerate it. Right now it's not honoring them independently. So can you fix it so a table with overwriting disabled keeps its current file contents fully intact, and a table with overwriting enabled gets a freshly generated file, per entry? Basically two fixes, all managed dao index paths always show up in the output, and per-table overwrite is respected on its own for each table. Projects lean on this because folks customize their dao index files by hand and don't want that wiped during regen, and the accurate path list matters for tracking what the tool actually manages.
