I'm chasing down a couple of spec compliance gaps in the Intl built-ins for this JS engine and could use a hand closing them.

First one is around plural rules. When I build a plural rules formatter and call the method that hands back its resolved options, the object I get is missing the field that describes the notation style. Per the ECMAScript Internationalization spec that field is supposed to always be there, and when I construct the formatter with default options (nothing explicit passed) it should come back as the basic decimal notation style, so the default value for that style. Right now it's just absent, which means anything inspecting the resolved config to figure out how the formatter is set up gets an incomplete picture. So I need the resolved options to carry that formatting style key with the right default.

Second thing is the locale prototype. It's missing the accessor property for locale variant subtag info. The spec wants that accessor present on the prototype itself, but if I feature-detect it by checking for the property on the locale prototype it comes back false, which breaks code walking the prototype chain to see if this is supported. I want that accessor exposed on the prototype so presence checks return true.

Both of these are cases where the API technically exists but returns incomplete data or is missing a required property, so it's really about matching what the ECMAScript Internationalization spec says these should look like. The plural rules changes live wherever the plural rules resolved options get assembled and the locale one wherever the locale prototype's accessor properties get wired up.
