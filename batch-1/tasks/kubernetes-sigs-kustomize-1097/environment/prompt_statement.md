I'm building out a built-in namespace transformer plugin for kustomize and want it to do the namespace application right across all the Kubernetes resource types. The idea is to set a target namespace on a resource set, but there's a bunch of nuance. Namespace-scoped stuff like config maps and service accounts should get the target namespace set or overwritten, creating the metadata namespace field if it's missing. But cluster-scoped kinds should never get a namespace, so namespace objects themselves, cluster role bindings, custom resource definitions, persistent volumes, and cluster roles all need to be left completely unchanged when the transformer runs, no metadata namespace touched at all.

The tricky part is the cross-reference case. When a role binding lists service accounts as subjects, each subject entry carries its own namespace field, and I want that updated, but only for subjects that map to a service account actually being transformed, meaning the subject's name and original namespace match a service account in the resource set. Any other subject references (pointing to service accounts outside the transformed set) have to stay untouched.

Oh and there's an existing bug I need fixed as part of this: processing a role binding that has no subjects field at all currently panics because of an unsafe type assertion. Handle that gracefully so it doesn't crash. The plugin should follow the standard kustomize builtin plugin conventions and just delegate to the existing namespace transformation logic rather than reimplementing it, so it stays consistent with the other transformers and is configurable through the normal plugin API.
