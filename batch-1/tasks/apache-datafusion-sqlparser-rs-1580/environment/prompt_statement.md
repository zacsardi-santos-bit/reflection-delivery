I'm working with a Rust SQL parser and I need to add table sampling support, because right now any statement with a sample clause in the FROM part fails to parse outright, which makes the library useless for real queries coming out of Snowflake, Hive, ClickHouse, and standard SQL that all use sampling to pull a statistical subset of rows for perf testing, data exploration, and stats work.

The tricky part is the forms differ by dialect. I need to handle a plain percentage or row count, a sampling method name (row-based, system-based, block-based), bucket specs where you pick a bucket out of some total number of buckets with an optional column expression for the hash, an optional seed or repeatability value for reproducible samples, and an optional offset. Also the clause can show up either before or after the table alias depending on the dialect, so the dialect trait needs a new method to control whether sampling comes before or after the alias.

On the AST side the table reference type needs a new optional field carrying the sample spec. And since a bunch of existing tests build these struct literals by hand and break every time a field is added, I want a helper that constructs a basic table reference from an object name with all the optional fields defaulted out.

Once it's wired up I want the usual parse-then-serialize round-trip to hold for a spread of sample strings: ClickHouse using the SAMPLE keyword with fractional values and ratios, Hive using bucket sampling and size-based sampling, Snowflake using both SAMPLE and TABLESAMPLE with different methods and seeds, and generic dialect cases too. Everything should reproduce the original SQL exactly.
