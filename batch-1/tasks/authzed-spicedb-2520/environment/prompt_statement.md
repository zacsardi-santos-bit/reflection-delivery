It should only block the removal when relationships actually exist for that exact variant being removed, but right now it conflates the two, so it either blocks a valid change when no relationships of the removed variant exist, or lets a removal through when it shouldn't. Concretely, if a relation accepts both forms and only the type-through-relation relationships exist, I want to remove the plain type without error, and the reverse should work too, and either removal has to stay blocked when that specific variant genuinely has matching data.
