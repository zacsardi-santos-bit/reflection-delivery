I'm adding bandwidth quota management to Kafka's remote log storage subsystem. The Remote Log Manager, which copies log segments to remote storage and fetches them back, has no way right now to limit how many bytes per second it reads from or writes to remote storage, so these background operations can eat unbounded bandwidth and starve produce/consume traffic and other critical broker work. I want configurable byte-rate quotas for both the copy (upload) and fetch (download) paths, each independently tunable.

So I need a new quota config holder for the manager that carries the byte-rate limit, the number of rolling-window samples, and the window duration, plus a new quota manager that tracks recorded byte usage against the configured rate limit and can report at any point whether it's currently exceeded. When bytes recorded within the rolling time window push past the limit it should read as exceeded, and once the window rolls past that recorded activity it should stop reporting as exceeded, so the clearing is automatic. When no limit is configured the default should be effectively unlimited throughput (no real quota).

I also want to update the quota at runtime, and when I do that it should only reconfigure the metrics tied to the byte-rate quota, leaving all the other internal metrics the system tracks untouched. The remote log manager's config object needs to expose these quota settings for copy and fetch separately with those sensible unlimited defaults, and the manager itself needs to take the metrics infrastructure as a constructor argument so it can register and track the quota metrics internally. Oh and I want static helper methods on the manager that build the right quota config objects out of the overall remote log manager config, reading the relevant config properties and falling back to unlimited defaults when those properties aren't set.
