I'm porting a piece of the BrickKit framework over to Kotlin and need the abstract base class for data models rewritten so it stops living in Java. Right now the class exists only in the old Java form and I want it in Kotlin to match the rest of the modern codebase, cuts down on interop overhead and just makes maintenance saner. This base class is used all over to keep UI components in sync with their data sources, so the observer pattern logic here really has to be correct.

Here's what I need. It's an abstract class that anything in the framework can subclass. It supports registering and unregistering listeners for change notifications, so a party interested in a given data model instance can add itself, and when a data change gets signalled on the model, every currently registered listener has its notification method called. The important part is that any listener that was previously removed must not get called anymore, so the register/unregister bookkeeping needs to actually hold. Also the class should expose a method that says whether the model is ready to be processed, and it returns true by default so subclasses can override it if they need to, meaning consumers can just use a fresh instance right away without extra setup.

Oh and the listener interface should be a nested interface defined inside the class itself, not a standalone thing. Keep it clean, plain observer pattern, nothing fancy.
