I'm cleaning up the agent codebase and want to move the out-of-band resource manager to a cleaner home. Right now it's buried under a deeply nested path inside the broader resource manager subsystem and honestly it's a pain to find compared to the other top-level agent components. It really deserves its own dedicated package directly under the agent directory with a shorter, more obvious name that reflects that it's a standalone thing.

The catch is I need everything to move together and keep working. That means all the sub-components come along: the checkpoint management piece, the endpoint lifecycle handling, the executor, and the metadata manager. All the internal cross-references between those sub-packages have to keep resolving at the new location, so any imports pointing at the old nested path need updating too. Also the agent entry point that initializes this component on startup has to point at the new location, don't forget that one.

This is purely structural, no behavior changes at all. So checkpoint state management, endpoint creation and removal, CPU set commitment, container resource updates, resource name mapping, and the container skip logic all need to behave identically after the move. Basically if anything works differently afterward I did it wrong. It's just a reorg to make the architecture easier to navigate for contributors who want to find or extend this thing.
