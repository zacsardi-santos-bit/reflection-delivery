I keep hitting friction with wrangler's bulk secret upload. I manage local dev secrets in dotenv-style files, key-value pair lines like `.dev.vars` or `.env`, but the bulk upload command only takes JSON, so I have to hand-convert my env file to JSON first every time. It's tedious and I make mistakes doing it. I want to just pass my env file straight to the command and have it parse each key-value line and upload each pair as a secret.

This needs to work across all three bulk upload paths I use: regular Workers, Pages projects, and versioned Workers. So the parsing should accept both JSON and env-file formats transparently in each of those contexts.

A few cleanup things that go with it. The CLI help text for the positional file argument should mention that both JSON and env-file formats are accepted, not just JSON. The error messages shown when no input is provided currently call out JSON specifically, and those should stop doing that since we accept more than JSON now. Same with the "finished processing" success message, it says "JSON file" and shouldn't anymore since the input may not be JSON.

Oh and for the versioned Workers command specifically, when someone passes a file whose content can't be parsed as either JSON or env format, don't give a generic error. The error should include the filename and the specific parse failure details so I can actually tell what went wrong.
