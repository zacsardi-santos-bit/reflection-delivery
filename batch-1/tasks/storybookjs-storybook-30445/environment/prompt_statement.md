I'm building a shared state system for Storybook so the manager (the sidebar/UI shell) and the preview frames (where stories render) can sync state over the existing channel infra instead of everyone hand-rolling their own bespoke channel plumbing every time, which is error-prone and repetitive. I want a universal store with a leader/follower model where one environment creates the leader that owns the authoritative state and any other environment creates a follower that auto-syncs with it. Both leaders and followers can update state and send custom events, and changes propagate to everyone through the channel, so a follower in another environment discovers the leader and gets the current state on creation.

The store needs a real lifecycle (not ready, syncing, ready, error) that I can inspect and await before doing anything. A few edge cases I care about: if the store gets created before the channel is available it should queue up until the channel's ready; if two leaders accidentally exist for the same store id, flag both as errored and log a clear diagnostic message; if a follower can't find a leader, reject its readiness promise with a clear error; and operating on a store that isn't ready yet should throw a descriptive error that includes diagnostic context about what state it's in.

Oh and I want a hook for manager-side components so they can subscribe to a store's state and re-render when it changes, with optional selector support so only the relevant slice triggers a re-render. The whole thing should live at a specific path under the shared utilities of the core package, and there should be a manual mock for the internal instance registry that tests can use. Without this every cross-environment feature needs custom wiring, so a universal store cuts the boilerplate and keeps the patterns consistent across manager and preview.
