We're on the Kong Kubernetes Ingress Controller and I keep hitting two annoying gaps around how protocol annotations get validated. First off, when I set a service to use WebSocket protocols, both the secure and non-secure variants (ws and wss), the controller's protocol validation logic flags them as invalid even though Kong supports them natively, so I want those recognized as valid protocol values everywhere the controller checks protocols. Oh and an empty protocol annotation value should count as valid too, meaning just use the default.

The bigger pain is the admission webhook. Right now it doesn't check protocol annotation values at submission time on either Ingress or HTTPRoute resources, so I can push a totally misconfigured resource to the cluster and it gets accepted no problem, and I only find out later when things quietly don't work. I want the webhook to reject those resources immediately at create time with a clear, descriptive error that tells me exactly which annotation value is the unrecognized one, so I get actionable feedback at deploy time instead of debugging runtime behavior after the fact.

Last thing, when overrides get applied during processing of backend services and a service is carrying an invalid protocol annotation, I don't want that silently ignored. There should be a recorded translation failure operators can inspect so it's clear what went wrong.
