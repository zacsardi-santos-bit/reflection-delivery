I'm adding namespace-scoped watching to the Contour gateway provisioner and could use a hand wiring it all up. Right now every provisioned gateway watches routes across all namespaces, which breaks isolation in multi-tenant clusters where I want a gateway to only serve specific teams or environments. I need it so a gateway can be configured with a list of namespaces to watch, and routes created outside that list get ignored entirely, never accepted, never reconciled, while routes inside watched namespaces get accepted normally and traffic flows through like usual.

A few pieces need to come together for this. First I need a little utility that converts our internal namespace type into plain strings, since the watched namespaces have to get passed down as a comma-separated list of strings to the underlying Contour process. Second, the gateway's deployment config should automatically include those watched namespaces as a command-line arg, and it should also append the gateway's own namespace to that list so the gateway can always see itself. Third, the RBAC setup needs work, the roles and role bindings should be creatable in an explicitly given namespace rather than always inheriting the Contour instance's namespace like they do now. And the cluster-level role needs a mode where it only emits cluster-scoped resource rules (the ones for managing gateway classes and namespaces) without also pulling in the namespace-scoped resource rules, for when I want finer-grained RBAC.

Oh and I also want a predicate function I can use in tests or elsewhere to check whether a route got completely ignored by the gateway, meaning it has zero status parents at all, which tells me Contour never touched it. That's the signal for "outside the watch list."

Motivation is really just isolation, multi-tenant clusters need each gateway to only see traffic from its own namespaces instead of everything in the cluster.
