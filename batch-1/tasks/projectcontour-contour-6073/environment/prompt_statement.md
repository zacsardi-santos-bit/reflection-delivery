I'm working on adding support for namespace-scoped watching in a gateway provisioner. Right now, when a gateway is provisioned it watches routes across all namespaces. I need to make it possible to configure the gateway to only watch routes in a specific set of namespaces, so that routes created outside those namespaces are completely ignored and never reconciled by that gateway instance.

To support this, I need a few pieces to come together. First, I need a utility that converts an internal namespace type into plain strings, since namespaces need to be passed as a comma-separated list of strings to the underlying process. Second, the deployment configuration for the gateway should automatically include the watched namespaces as a command-line argument, and it should also append the gateway's own namespace to that list. Third, the RBAC setup needs to be updated: roles and role bindings should be creatable in a specific namespace rather than always using the same namespace as the gateway. Finally, the cluster-level permissions role should support a mode where it only includes cluster-scoped resource rules (for managing gateway classes and namespaces) without also including rules for namespace-scoped resources.

I also need a predicate function that can be used to check whether a route has been completely ignored by the gateway — meaning it has no status parents at all, which indicates Contour never processed it.
