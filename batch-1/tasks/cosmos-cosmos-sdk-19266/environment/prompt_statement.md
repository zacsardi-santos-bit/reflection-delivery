I'm working on the Cosmos Hub LSM fork of the SDK, and we have a query endpoint that looks up all accounts holding a specific token denomination. This endpoint relied on a reverse index that was intentionally not built during our state migration — maintaining it would be too costly for this deployment. As a result, this query always fails at runtime because the index doesn't exist.

The problem is our tests still expect this query to succeed for valid denom inputs: they set up funded accounts, issue the query, and expect to get paginated results back. But in reality, the endpoint returns an error every time. I need the implementation updated so that this query explicitly returns an error (and a nil response) for all requests — not just for nil or malformed inputs, but for every query regardless of whether the denom is valid and regardless of how many accounts hold it. The tests should reflect that this query is simply unavailable in this deployment and users should be directed to an external indexer.
