I'm trying to wire AWS Glue Data Quality into my Airflow DAGs and there's just nothing native for it, so teams that define rulesets and run evaluations against their data tables end up writing custom glue code every time. Data quality matters a lot in these pipelines and without proper components I can't cleanly halt a pipeline when the data doesn't meet standards, so I want to add a hook, a couple operators, a sensor, and a trigger covering the whole workflow.

For the hook I need low-level access to the Glue Data Quality APIs, so something that can check whether a ruleset exists, plus a method that validates evaluation run results by logging how many rules failed and raising an error if any did, oh and a custom waiter for evaluation run completion.

Then operators. One to create or update a ruleset that validates the ruleset string is in the correct format and propagates the underlying API errors properly, like when the ruleset already exists on create or isn't found on update. Another to start a ruleset evaluation run, which should validate all referenced rulesets actually exist, let me pass additional run options, and support waiting synchronously, polling with a waiter, or deferring until completion. That one returns the run ID.

Also a sensor that polls or defers until an evaluation run hits a terminal state, returning success when it completes and raising a failure with a descriptive message (including the run ID, the status, and the error string) when it enters a failure state. It's gotta support soft-fail mode and deferrable execution too. And finally a trigger for the deferrable path that uses a custom waiter and signals completion with both a success status and the run ID. These should land alongside the other AWS provider components under `@airflow/providers/amazon/aws/` in the hooks, operators, sensors, and triggers modules respectively.
