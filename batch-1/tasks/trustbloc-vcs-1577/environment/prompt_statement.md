I'm working on the credential issuance service and the way we publish issuer metadata from the well-known endpoint is a mess. Right now the list of supported credential types lives as a collection of untyped key-value maps, so just to read something basic like the credential format I have to do an unsafe type assertion on a map entry, which is fragile and hard to maintain. I want to swap that for a proper typed structure with named, strongly-typed fields for the credential id, format, credential types, credential subject, and display info.

Tied to that, the well-known config response needs to match the current OpenID for Verifiable Credential Issuance spec. Instead of the older flat array format, the supported credential types should come back as a keyed map where each entry is keyed by the credential type name and describes the cryptographic binding methods, cryptographic suites, proof types, display metadata, and the credential definition details for that type.

Also there's this annoying thing where fields like grant types, scopes, the pre-authorized access flag, plus the authorization and token endpoints are always present even when nobody configured them, so a client can't tell "not configured" apart from an explicit false or empty value. I want those made optional so absent config actually reads as absent instead of a misleading zero value.

Oh and signing. When the issuer config is signed the endpoint currently hands back the raw signed token with a token-specific content type. It should instead return a JSON document that wraps the signed value using a standard JSON content type, so the response format stays consistent whether or not signing is on.

Last thing, when dynamic client registration is enabled for a profile, I need the registration endpoint URL included in the configuration response too.
