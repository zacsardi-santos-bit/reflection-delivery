I'm building out the xDS resource management layer for a network proxy and I've hit a real gap: when I push a config change to proxy nodes over the discovery protocol I've got no way to know when a node has actually applied it. I can send the update fine, but nothing tells me the node confirmed the new version, which makes it painful to coordinate stuff like waiting for a policy update to land on every relevant node before I flip a traffic switch.

What I want is to attach a completion callback to an insert, update, or delete op that fires automatically once all the specified nodes have acked the relevant version. For inserts and updates the ack needs to match both the right version and the right resource name per node. For deletes, since the deleted resource won't show up in the node's ACK by name anymore, just match on version. Oh and if a node sends a newer version than the one I was waiting on, that should satisfy the pending completion too. When I list multiple nodes, the callback only fires once every single one of them has acked, not partway through.

I also need the server config updated so each supported resource type carries both the resource data source and an acknowledgment observer together instead of only the source, so when ACKs come in on the discovery protocol stream they get routed to the right observer.

Also I need a little utility that parses an Istio-style proxy node identifier and pulls out the node's IP, which we use as the canonical node id for ack tracking. Format is four tilde-separated parts where the second part is the IP. It should return an error if the input's malformed, has the wrong number of parts, or the IP doesn't parse.

Last thing, the cache's upsert, delete, and transaction methods each need a new boolean param that controls whether updates get forced even when the resource value hasn't actually changed.
