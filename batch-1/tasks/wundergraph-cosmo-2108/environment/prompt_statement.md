I'm building a gRPC service generation tool that reads a GraphQL schema and spits out protobuf and mapping files, and right now it does zero validation before generating anything. So when someone hands it a schema using patterns we don't support, the generator either silently produces wrong output or blows up somewhere deep in the pipeline where the error message makes no sense. Developers get no actionable feedback on whether their schema is even compatible, and I want to fix that with a real validation layer that runs before any files get written.

Here's the split I care about. Some stuff should just be warnings and let generation keep going and produce all the normal output files, like a nullable item inside a list type, or the use of a directive that's planned but not implemented yet (unsupported directives). Other stuff should be a hard error that stops generation immediately with no output files created at all, like nested key references that can't be properly mapped to the generated code. And if a schema has both warnings and errors at the same time, the errors win, generation still halts completely.

For the shape of it, I want the validation logic wrapped up in a dedicated visitor class that takes the schema string, walks it, and hands back two separate collections, one for errors and one for warnings. Then the generate command calls into this validator and decides whether to continue or abort based on what comes back. Basically warnings alone means proceed, any errors means stop cold. That way the distinction between "tolerable but unsupported" and "genuinely can't generate correct code" is clear and early instead of cryptic and late.
