I'm adding native Windows SSH agent support to posh-git and right now it just ignores the built-in stuff entirely. On Windows 10 and later the OS ships with its own OpenSSH client and an SSH agent service, but posh-git doesn't detect or touch any of it, so folks who have it available end up manually starting the service, pointing git at the right ssh, and loading keys every session. Kind of a degraded experience, I want startup to just handle it.

So first I need a function that checks whether the native Windows OpenSSH agent service is actually present and hands back the service object if it is (nothing otherwise). Then a second function that drives the whole startup dance. If the service is disabled and the current user is an admin, it should enable it and then start it. If it's disabled but the user isn't an admin, don't try to start anything, just write out a clear informative error message explaining what's up and bail gracefully. And if the service is only stopped (not disabled) it should just start it normally.

Beyond the service itself the startup function needs to sort out git config too, it should set git to use the correct native SSH executable path, but only if that setting isn't already configured, don't clobber an existing value. Same careful approach for keys, check whether any are already loaded first and only add keys when the agent's empty, otherwise you get those annoying duplicate prompts the native agent throws when keys are already added. This all lives in posh-git's module code so wire it into the relevant `@src` functions there.
