I'm working on a Kubernetes operator for TiDB clusters and I've noticed that the bootstrap SQL configuration — the SQL statements that run when a cluster is first initialized — is currently placed inside the TiDB component's security settings. This placement is confusing because bootstrap SQL is a cluster-wide initialization concern, not a per-instance security property. I'd like to move this configuration to the cluster specification level so it sits alongside other cluster-wide settings and is clearly scoped to the whole cluster rather than individual TiDB component groups. Any existing logic that reads this configuration from the TiDB component's security section should be updated to read it from the cluster spec instead, and the field should be removed from the TiDB security type entirely.
