I'm hacking on the Gleam language server and hit an annoying gap: when I'm inside a function body and start typing the name of a variable I defined locally, autocomplete gives me nothing. Module-level values, imported names, type constructors, those all show up fine, but anything I bound locally in the current function is just invisible to the completion engine. Kinda kills productivity for functions with lots of params or gnarly pattern destructuring.

What I want is for local variables to show up as completion items, each one displaying its inferred type. It's gotta respect lexical scoping though. Function parameters should appear as candidates within the body. Variables bound by let statements before the cursor should be suggested, but ones bound after the cursor position shouldn't, since they're not in scope yet. Pattern match bindings need to work too, including aliased patterns and destructuring patterns for tuples, lists, bit arrays, and string prefixes, and they should only appear within their respective scopes.

Anonymous functions are the tricky bit: params of an inner anon fn should only complete inside that fn's body, not leak out into the enclosing scope. Oh and discard bindings, names starting with an underscore, those shouldn't be suggested at all. Also when the cursor's sitting inside a function's parameter list declaration itself, don't offer any local variable completions there.

The completion logic lives in the language server crate around `@compiler-core/src/language_server/completer.rs`, so that's where the scope-walking for locals needs to happen.
