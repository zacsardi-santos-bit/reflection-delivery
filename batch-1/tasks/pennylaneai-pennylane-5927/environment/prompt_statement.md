I've got a bunch of legacy quantum devices built on PennyLane's older device interface, and I want to use them where the newer device interface is expected without rewriting any of them. Can you build me an adapter class that wraps a legacy device and makes it look like a new-interface device? It should expose the wrapped device's metadata through the new interface, so things like name, author, version, and wires come through correctly, and it needs to translate shot config into the new interface's shot representation, including partitioned shots. Tracking has to forward too so execution counts and shot totals get captured right.

For preprocessing, the adapter's pipeline should bridge the legacy expansion function and batch-transform into the new transform pipeline, and it should defer mid-circuit measurements unless the underlying device natively supports them. Oh and post-selection mode should get passed along to the underlying device when it does support mid-circuit measurements. When I hand it a batch of circuits with different shot counts, each circuit needs to be executed individually with its shots tracked separately.

Gradients are the tricky part. If the underlying device supports adjoint differentiation, configure execution for it with the right gradient keyword arguments. If the device provides its own Jacobian, recognize that capability. For backprop via pass-through devices, swap in the appropriate pass-through device at execution time, but only when needed, and never for circuits containing sparse Hamiltonian observables. If someone asks for a differentiation method the underlying device doesn't actually support, raise a clear device error. Also snapshot/debugger functionality should stay accessible through the adapter whenever the underlying device supports it. This is basically about smoothing the migration so existing legacy devices keep working with all the new-interface features (gradients, tracking, preprocessing) without touching their code.
