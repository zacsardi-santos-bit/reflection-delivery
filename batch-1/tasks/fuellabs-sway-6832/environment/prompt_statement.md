I'm building zero-knowledge proof stuff in Sway and the stdlib is missing the primitives I need for elliptic curve crypto. Right now there's no standard way to represent a 2D elliptic curve point or a scalar, so it's basically impossible to cleanly use the EC operations the VM already supports, and every team ends up rolling their own representations and poking at the precompile calls by hand. I want to fix that by adding a curve point type and a scalar type to the crypto module in the standard library.

The point type should let me build a point from a pair of 256-bit integers (either sign convention, so signed or unsigned works), from arrays of 256-bit ints, and from raw byte arrays too. I want to pull the x and y coordinates back out as byte sequences, and there should be a zero/minimum-value constructor plus a way to check whether a point is the zero/identity element. Also equality comparison between two points, and conversion back to the original numeric forms (tuples and arrays of 256-bit integers). The scalar type is similar but simpler: construct it from a 256-bit integer or a raw byte array, get the underlying bytes, a zero/min constructor and a zero-check, and convert back to 256-bit integer types.

On top of the types I need three functions that operate on them, one that adds two curve points together and returns the resulting point, one that multiplies a point by a scalar and returns the resulting point, and one that takes a list of point pairs and evaluates whether their bilinear pairing relationship holds, returning a bool (true if the pairing check passes, false otherwise). All three should revert rather than quietly returning garbage when they're handed inputs that aren't valid curve points. This all lives in the crypto module of the standard library alongside the other crypto primitives.
