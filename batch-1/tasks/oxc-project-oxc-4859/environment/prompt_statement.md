I'm poking at the semantic analyzer for JS/TS and something's off with how call expressions get traversed. Right now the references for the callee (the function actually being called) end up with higher reference IDs and node positions than the references for the arguments, which is backwards. In JS/TS evaluation semantics the callee gets resolved before its arguments, so I'd expect it to be visited first and therefore land lower reference and node identifiers, not higher.

Digging in, it looks like the underlying node struct for a call expression stores the arguments field before the callee field, so when the visitor walks the node it hits the arguments first and assigns them IDs before it ever gets to the callee. I want the field order flipped so the callee comes first and gets visited and analyzed before the arguments, giving it numerically lower reference identifiers and AST node positions.

This isn't just a one-line struct tweak though, oh and it ripples out everywhere. Anything that constructs or manipulates a call expression node needs updating to the corrected field ordering, so builder helpers, any layout or field-offset assertions, and all the call sites across the codebase that create these nodes. Also the snapshot output for semantic analysis will shift since arg references used to have the lower IDs and now the callee should, so those expected snapshots need regenerating to reflect callee-first order. The motivation here is that downstream tools and consumers relying on reference ordering or node positions assume evaluation-order traversal, and the current arg-first layout just confuses anything making that assumption. Please get the callee visited before the arguments and update everything that depends on it.
