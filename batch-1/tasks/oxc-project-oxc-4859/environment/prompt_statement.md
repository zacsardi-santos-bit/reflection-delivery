I noticed that in the semantic analysis of JavaScript and TypeScript code, the references for the function being called in a call expression are assigned higher identifiers than the references for the arguments. This feels wrong to me — the callee should be evaluated (and therefore visited) before its arguments, so I'd expect it to receive lower reference and node identifiers. It looks like the underlying data structure stores arguments before the callee, causing the traversal to process arguments first. I'd like this corrected so that the callee is visited before the arguments in a call expression, and all the snapshot output, layout assertions, builder helpers, and call sites throughout the codebase are updated accordingly.
