I'm working on the Scaleway Terraform provider and the serverless job definition resource has a gap I keep bumping into. Right now you can set the name, image, CPU and memory limits on a job definition but there's literally no way to say when the job should run on a schedule. I want to add a cron block to the job definition resource so folks can wire up recurring runs, like nightly cleanup tasks or periodic reports or a regular data sync, straight from their infra-as-code instead of clicking around outside Terraform.

The cron block should take a schedule expression and an IANA timezone. When I apply the resource with that block present it should create the schedule against the API and persist both the expression and timezone so they're readable back from Terraform state. When I change the expression or the timezone on an existing job definition it should update in-place, no destroy-and-recreate. And when I remove the cron block from my config entirely it should delete the schedule from the underlying API and leave no cron entries in state.

The main thing is after every operation (create, update, delete) the Terraform state has to accurately reflect whether a cron schedule is configured and what its values are. The resource wiring lives around the serverless job definition code in `@scaleway`, so the create/read/update/delete paths there need to handle the cron block lifecycle. Btw the timezone is IANA-style so keep that in mind for validation and round-tripping.
