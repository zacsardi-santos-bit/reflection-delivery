I'm adding Hetzner service discovery to VictoriaMetrics because right now there's no native support for it, and folks running on Hetzner have to hand-maintain static scrape targets which just doesn't scale as servers come and go. Hetzner has two totally different platforms, a modern cloud one and a legacy dedicated server (robot) one, and I want VM to discover servers from both so those users get the same dynamic scrape config everyone else gets.

I want this split into two files inside the Hetzner discovery package, one for cloud and one for robot. For the cloud side I need to parse the server list and network list responses from the Hetzner Cloud API and turn each discovered server into Prometheus-style metadata labels covering server identity, public IPv4 and IPv6, datacenter name plus its location and network zone, the server hardware type (CPU cores, CPU type, memory size in GB, disk size in GB), OS image info (name, description, OS flavor and version), and private IP addresses keyed by network name.

For robot, the server list response comes back as a JSON array, and I need labels for server identity, public IPv4, the public IPv6 network taken from the subnet info, datacenter name lowercased, the hardware product name, and cancellation status. Both roles should share a common base label set (server ID, name, status, public IPs, datacenter) with the role-specific stuff layered on top.

One gotcha, both parsers have to handle the JSON field naming each API actually uses, including cases where the JSON field names don't match what you'd guess from the Go struct field names, so watch the struct tags. Parsing valid response bodies from either platform has to succeed without error, and the resulting label sets need to be complete and accurate so they're usable for target relabeling in scrape configs.
