I use a little markdown query tool that selects and extracts chunks out of markdown docs, and right now it can spit results out as formatted markdown or as structured JSON, but neither is great when I want to pipe stuff into other text tools (word counters, diff, grep, whatever) that don't speak markdown. I want a third output mode that gives me plain text with all the formatting stripped off.

So in plain mode I need inline styling like emphasis and bold markers gone so only the underlying text survives, and links should collapse to just their visible display text with no URL or bracket/reference notation hanging around. Code blocks should emit only the code content itself, no fencing and no language label, and an empty code block should produce nothing at all. Tables should flatten into rows of space-separated cell values, one row per line, without the alignment/separator row or any padding. Oh and when there are multiple consecutive blank lines between blocks, collapse them down to at most a single blank line so the output stays tidy.

While I'm in there, the existing structured (JSON) output isn't fully covering code blocks, so make sure that when a code block gets serialized it includes the code text, the language, and the block type all represented properly.

Also, actually, the test utilities should get a helper that converts a document element into its reference form and checks that the conversion produced the expected variant, since that's handy when I'm writing unit tests for this new plain output mode. Wire the new format in as a selectable option alongside the markdown and JSON ones.
