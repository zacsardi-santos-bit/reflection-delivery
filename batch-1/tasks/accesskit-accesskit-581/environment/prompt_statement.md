I'm working on an accessibility consumer library that has filtering logic to decide which nodes in an accessibility tree should be exposed to assistive technologies. The library currently has no automated coverage for this filtering logic, leaving the core behavior unverified.

The filtering logic covers several scenarios: a normal node should be included; a hidden node should exclude its entire subtree; a hidden node that is currently focused should still be included despite being hidden; a generic structural container node should be excluded at the node level only (its children remain traversable) by the standard filter, but a root-exception variant of the filter should include it; when a parent is hidden, its children should also be excluded — unless a child is the focused node, in which case the focused child should still be included; and certain internal text representation nodes should be excluded at the node level only.
