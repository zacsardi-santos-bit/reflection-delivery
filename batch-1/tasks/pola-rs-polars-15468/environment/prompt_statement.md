I'm working with a dataframe in Polars and I keep hitting a wall with the top-k and bottom-k expression operations. Right now they only rank on a single column and there's no way to say which column should drive the ranking, so I can't grab the k highest (or lowest) rows by one column while also pulling back the corresponding values from other columns at the same time. That's such a common analysis pattern and doing it today means verbose workarounds like joining, sorting the whole frame, then slicing.

What I want is to pass a ranking key (a column or list of columns) to these ops so that when a key is given, all the selected columns come back together for those k rows. I also want to control sort direction, ascending or descending, as a single boolean flag for the simple case, and as a per-column list when I'm ranking by multiple columns. Oh and this needs to work inside grouped aggregations too, so I can get top/bottom k rows per group ranked by a chosen column.

The error handling matters here. If I hand it a list of directions but no ranking key, I want a clear error telling me a single boolean direction is required when no ranking key is given, not a silent wrong result. And if the number of sort directions doesn't match the number of ranking key columns, it should raise a descriptive error about the length mismatch. Basically make these consistent with how similar sorting operations already behave elsewhere in the API.
