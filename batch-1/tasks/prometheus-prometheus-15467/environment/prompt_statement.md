I'm adding write-ahead log support for native histograms that use custom bucket boundaries in Prometheus, since right now those boundary definitions get dropped on the floor when these histograms hit the WAL. The encoding only stores bucket counts, not the boundaries, so after a restart replay, during checkpointing, or when the WAL gets tailed for remote write, the boundaries are gone and we can't reconstruct the histograms correctly. Custom-bucket histograms let users define their own boundaries instead of the standard exponential schema, and those boundaries are essential metadata, so losing them makes the counts basically useless for query and aggregation, and it also breaks reliable remote write forwarding of this variant.

What I want is dedicated WAL record types for custom-bucket histograms, both integer and float variants, kept separate from the existing standard histogram record types, and the new encoding needs to include the bucket boundary values. The decoder should handle both old and new record types through the same decoding methods so there's no special-casing scattered around. Then every place that reads from the WAL needs to recognize the new types and process them right, that's head replay, agent WAL loading, checkpoint creation, out-of-order buffer replay, and the WAL watcher. When these records come back the boundary values should be fully restored, not silently dropped.

Oh and I also need test utility functions that generate sequences of custom-bucket histograms (both int and float) for use in tests, similar to the existing helpers that produce sequences of standard histograms.
