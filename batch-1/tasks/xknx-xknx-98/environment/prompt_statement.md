I'm adding KNX scene support to the XKNX Python library and it's kind of a gap right now, the lib already handles lights, switches, covers, climate and so on but there's just no way to represent or fire a KNX scene, you know the thing where you activate a predefined environment like a "Romantic" lighting setup with one command over the bus. Users can't trigger scenes programmatically at all and I want to bring this up to par with the other device types.

So I need a new device class that takes a group address and a scene number, and when you activate it, it sends the scene number encoded as a single byte to that group address. The sync operation should just be a no-op since there's no state to read back from a scene. It also needs to plug into the existing generic action dispatch so it supports a "run" action, and for any unrecognized action it should log a warning instead of crashing or raising.

On top of that I need a proper KNX datatype encoder/decoder for scene numbers covering the valid range 0 to 63, and it's gotta raise a conversion error for anything out of that range or the wrong type. Oh and the YAML config format should be extended so scenes can be defined with a group address and scene number under their own dedicated scene section, right alongside all the other device types the config already knows about.
