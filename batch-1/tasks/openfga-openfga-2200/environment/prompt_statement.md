I'm digging into our authorization check system and hitting a wall with recursive hierarchical permission models. The case I care about is when a relation is defined as a union between one or more non-recursive branches doing algebraic stuff (intersection, exclusion) and a recursive tuple-to-userset traversal back to the same relation on a parent object. Think "you can view this doc if some intersection/exclusion rule says so, OR you have viewer on the doc's parent." Right now these don't trigger fast-path evaluation, so we either fall back to a slow path or straight up return wrong results.

First thing I want is a new method on the type system that recognizes when a relation qualifies for this new fast path: the relation has infinite weight, its single outgoing edge leads to a union node, and every non-recursive branch of that union has weight 1 (so terminal types, wildcards, intersections, and exclusions over simple sub-relations all count). Important invariant, anything the existing recursive fast-path classifier already recognizes has to be recognized by this new one too.

Then the check evaluator needs to actually call a new fast-path algorithm for these qualifying models. That algo takes the context, the check request, a tuple-to-userset rewrite describing the recursive branch, and an iterator over the recursive branch's tuples.

To back this, I need two new object-provider abstractions, both exposing a channel-based interface so results stream out. One's a simple provider reading directly-related objects from the store, it should error on nil inputs. The other's the more complex one handling the TTU traversal side, it errors on nil inputs too and specifically must emit an error saying the type system argument is nil, plus error when the rewrite isn't a tuple-to-userset. Both providers' streaming methods need to handle context cancellation and propagate iterator errors as messages through the output channel instead of panicking.

End to end, models using these recursive union patterns, including variants with wildcards, multiple non-recursive branches, and parenthesized intersections, have gotta return the correct boolean when checked. This pattern (propagating access through object hierarchies while also allowing direct access via compound criteria) is super common, so getting it right matters for both correctness and perf.
