I'm working on improving the authorization check system's ability to handle a specific class of recursive hierarchical permission models. Right now, when a relation is defined as a union between non-recursive algebraic operations (like intersection or exclusion) and a recursive traversal to the same relation on a parent object, the fast-path evaluation is not being used — which means these checks either fall back to a much slower code path or return incorrect results.

I need the type system to gain a method that can recognize when a relation qualifies for a new fast path: specifically, when the relation has infinite weight, its single outgoing edge leads to a union node, and every non-recursive branch of that union has weight 1 (covering terminal types, wildcards, intersections, and exclusions with simple sub-relations). This classification should also satisfy the invariant that any relation already recognized by the existing recursive fast-path classifier is also recognized by the new one.

I also need the actual check evaluator to invoke a new fast-path algorithm for these qualifying models. The algorithm should accept the context, the check request, a tuple-to-userset rewrite describing the recursive branch, and an iterator over the recursive branch's tuples.

To support this, I need two new object-provider abstractions — one simple provider that reads directly-related objects from the store, and one more complex provider that handles the TTU traversal side — both exposing a channel-based interface so results can be streamed. The simple provider should error on nil inputs; the complex provider should error on nil inputs and must emit an error indicating that the type system argument is nil, and must error when the rewrite is not a tuple-to-userset. Both providers' streaming methods should handle context cancellation and propagate iterator errors as messages through the output channel rather than panicking.

End-to-end, authorization models that use these recursive union patterns — including variants with wildcards, multiple non-recursive branches, and parenthesized intersections — must return the correct boolean result when checked.
