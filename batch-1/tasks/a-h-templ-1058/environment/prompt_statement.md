I'm trying to use dynamic, runtime-computed values for the style attribute on HTML elements in my templates, but the template engine currently rejects any expression in the style attribute at parse time. I have components where the styling needs to depend on runtime state — things like widths computed from data, colors based on validation status, or positions driven by user interaction — and I can't hardcode these as static strings.

I'd like the template engine to accept Go expressions in the style attribute, similar to how it already handles other attributes. Ideally it should support passing a variety of input types: plain CSS strings, pre-approved safe CSS values that skip sanitization, maps of property names to values, conditional pairs where a boolean controls whether a style is included, and zero-argument functions (including those that can return an error). Slices of these types should also be accepted so that multiple style sources can be composed together.

Plain strings and property names should be automatically sanitized against CSS injection. Safe types should bypass CSS sanitization but still apply HTML encoding. Maps should produce alphabetically sorted output so the result is deterministic. When a property name or value is unsafe or empty, it should be replaced with a recognizable placeholder rather than silently dropped or causing a crash. If a function input returns an error, that error should propagate. Completely unsupported types should produce a clearly marked placeholder value in the output.
