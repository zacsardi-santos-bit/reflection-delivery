I'm poking at the cross-compilation toolchain, specifically the Docker-based cross build path, and I've got a function whose name bugs me. It's the one that constructs the directory layout for the container environment, and the current name is too generic, doesn't tell you it's really about assembling all the path info the build container needs. I want it renamed to something that clearly signals that assembling intent (think "assemble directories" flavored).

The bigger thing though is the signature. Right now it borrows the project metadata and just hands back the directory structure. That's not enough. I want it to take ownership of the metadata and return both the assembled directories and the (possibly updated) metadata together as a pair, so any changes it makes during assembly flow back to the caller. The concrete reason: during assembly it updates fields like the target directory to its container-mounted path, and right now that update gets lost, so we end up using the wrong target path when pre-building inside a container-in-container setup, which causes build failures. Handing the updated metadata back fixes that.

Then, obviously, the old name shouldn't exist anymore, and every caller across the codebase needs updating to call the new name and destructure that returned pair correctly so they pick up the modified metadata.
