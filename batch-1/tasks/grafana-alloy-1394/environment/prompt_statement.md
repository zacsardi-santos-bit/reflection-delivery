I'm refactoring the cluster service in Grafana Alloy and I want to pull the peer discovery logic out into its own testable module. Right now the code that resolves peer addresses, whether from a static list of join addresses or from dynamic cloud-provider discovery, is buried inside the cluster service and I can't unit test it without real network infrastructure, which means bugs in port handling or partial-failure behavior only show up in integration environments and that's slowing me down.

What I want is a standalone peer discovery component that gets created from a set of options including a logger, a tracer, optional static join addresses, and an optional dynamic discovery config string. At creation time it should validate the required deps and return clear errors when the logger or tracer is missing, and it should reject configs that specify both static and dynamic discovery at once since those conflict.

For resolving static addresses it needs to handle a few cases: a bare IP gets the default port appended, an address that already has an explicit port passes through unchanged, and a hostname gets resolved via DNS SRV records using the default port for each resolved target (ignore whatever port the SRV record itself reports). Oh and if I pass multiple hostnames and some of the DNS lookups fail, it should keep going with the ones that succeed rather than bailing. If nothing valid can be resolved at all it should return an error saying no valid join addresses were found.

For dynamic discovery it should delegate to a pluggable cloud-provider discovery backend and add the default port to any addresses that don't already specify one. If the provider is unknown or the lookup fails, surface that error back to the caller.

Also, to make this actually testable, both the DNS lookup function and the dynamic discovery backend factory need to be injectable so tests can swap in fakes without hitting the network.
