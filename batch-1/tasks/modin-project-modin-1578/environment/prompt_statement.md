I'm working on Modin and I want to make the execution engine and partition format configurable at runtime instead of being baked in at import time. Right now those live as plain module-level strings that get set once when the library loads, so if a user wants to switch backends there's no way for anything to react. I want to fix that.

The core piece is a small publish-subscribe helper class that holds a named value, lets you update it, and notifies any registered callbacks whenever it changes. It needs two subscription modes: one where the callback fires immediately when you register it and then again on every subsequent change, and another where a callback fires exactly once when the value hits a specific target you're waiting for. Keep it general purpose, it's just a named observable value with listeners.

Then I want the execution engine and partition format settings to become instances of this class, exposed at the top level of the package so other components can subscribe. The engine dispatcher should subscribe to both so it automatically picks up the correct factory whenever either one changes, no restart or re-import needed. Oh and if someone tries to switch to an engine name that has no corresponding factory, raise a meaningful error, don't silently do nothing.

Also the new utility class should be part of the public package API. And there's a naming conflict I keep hitting: the distributed client variable in the dataframe submodule (over in the pandas dataframe code) should get renamed so it doesn't clash. Point is any component can register a callback and get notified when the engine or partition format changes, which makes the whole engine lifecycle way more flexible and testable.
