I'm working on the CloudNativePG operator and I keep hitting a gap with physical replication slots. Right now we only manage the slots the operator creates for high-availability, so if I manually create a physical replication slot on the primary it never makes it to the standbys, and it just vanishes after a failover which breaks any streaming replication clients that depended on it. I want the operator to automatically detect and replicate any physical replication slot it finds on the primary out to all standbys, whether or not the operator created it. It also needs a way to tell its own HA slots apart from user-created ones so it can apply different lifecycle rules to each category.

Also I want an optional list of regular expression patterns so specific slots can be excluded from synchronization, slots whose names match any pattern don't get synced. Any invalid pattern should be caught and rejected at the cluster admission webhook level with a clear error message, before it ever reaches runtime, so malformed regexes fail configuration rather than blowing up later. This user-defined sync feature should be independently toggleable from the HA replication slots feature, and when it's disabled the operator should clean up the synchronized copies from the standbys while leaving the user-created slots intact on the primary.

Oh and the existing test utilities and end-to-end tests reference only HA slots right now, so some of those helper functions and assertions need renaming to make clear they're specifically about HA slots, and I need new helpers to toggle the user-defined slot synchronization feature on and off in tests. The why here is that users rely on these slots to keep streaming consumers connected across failovers, so automating this cuts the manual operational burden and makes the cluster resilient to topology changes for all physical replication slots, not just the operator-managed ones.
