I'm in the store encryption crate for the Matrix Rust SDK and I hit a real gap. Right now our encrypted value type keeps the ciphertext and nonce as raw byte arrays, which is fine for a lot of backends but genuinely wasteful in browser storage like IndexedDB, storing big arrays of integers there is slow and bloated compared to plain JS strings. So I want a string-based variant.

Can you add a new public struct in the store encryption library that holds encrypted data with the ciphertext and nonce as base64-encoded strings instead of byte arrays? Alongside it I need new encrypt and decrypt methods on the cipher for this format. The new encrypt method should take any serializable value, encrypt it, and hand back the base64 string form, and the matching decrypt method takes that same form and gives me back the decrypted, deserialized value. Roundtrip has to be exact, encrypt then decrypt returns the original value untouched.

Oh and I also want lower-level variants of those methods that operate directly on raw byte vectors instead of typed serializable values, same idea just without the serde layer.

Then conversions both ways between the existing raw-bytes encrypted value type and the new base64 string one. The direction going from base64 back to raw bytes can fail, e.g. invalid base64 or a decoded nonce with the wrong length, so it needs its own dedicated error type that gives a clear message about what went wrong. The other direction (raw to base64) can't fail. Btw the base64 encoding should use the standard alphabet with no padding characters.
