I'm working on a Jenkins webhook proxy service (Go) and right now it only knows how to handle webhook events pushed from BitBucket, which means there's no way to kick off a pipeline build directly from a script or some other automation. I want to add a dedicated HTTP endpoint that accepts a POST with a JSON body where the caller specifies the branch, project, repository, and optionally a map of environment variables, and when it's valid the proxy creates the right pipeline config in OpenShift and returns a success response.

This new endpoint needs to be protected by a shared secret passed as a query parameter, so if the caller doesn't include the correct secret the request gets rejected with an unauthorized status. Oh and there should be an optional query param that lets the caller override the component name that's used when deriving the pipeline name.

On top of that I need env var passthrough everywhere, not just on the new endpoint. The pipeline template doesn't support this today so it needs updating so that any env vars from the request end up in the pipeline strategy configuration, and the generic webhook trigger config should get a flag enabling env var passing too. This matters because parameterized CI/CD is a common need and teams want to inject runtime behavior into builds.

Also, actually, requests hitting paths the proxy doesn't recognize should return a proper not-found response instead of silently doing nothing.
