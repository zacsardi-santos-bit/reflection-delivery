I'm extending the automated migration tool that wires up the accessibility addon with the test addon. Right now it only patches the Vitest setup file to import the accessibility addon annotations, and it just ignores the project preview config, which is a problem because the preview file also needs a specific tag added so accessibility tests actually run in CI. Users hit this all the time, they finish the migration and then wonder why accessibility checks never fire, since they missed the manual step of adding the tag that controls which stories get accessibility-tested.

So I want the tool to also check for and transform the preview config file. The tag should be added in a way that makes it easy to opt stories in or out, so if the preview already has a tags array, append the tag as a commented-out entry so the user can consciously flip it on. If there's no tags property at all, add it commented-out with an explanatory comment. If there's no default export, add the tag as a named export instead. And if the tag is already present anywhere in the file, don't change anything.

Also the tool should be smarter about detecting existing state. If the Vitest setup file already has the accessibility addon import, skip that transform. If the preview file already has the tag, skip that one too. Only when both files are fully configured should the overall check return the "nothing to do" result.

The user-facing prompt messages need work too, oh and they should be numbered steps, each showing either that we'll update it automatically or the manual instructions, depending on whether the transformation could actually be computed. The "for more information" docs link should show up whenever any step still needs manual action. And when a step is entirely skipped because the file's already correct, just leave it out of the prompt.

Last thing, the run phase should write the transformed preview code to disk exactly the way it already writes the transformed setup code.
