I'm working on the linkerd2 policy controller and I've noticed that gRPC routing configurations aren't being tracked in the outbound policy at all. Right now, only HTTP routes are indexed and included in the outbound policy that gets distributed to proxies. If I create a gRPC routing resource pointing at a backend service, nothing happens — those routes never show up in the policy.

I need the outbound policy indexer to support gRPC routes the same way it supports HTTP routes. Specifically, when a gRPC routing configuration is applied, the outbound policy should include those routes in a dedicated gRPC routes collection. The indexer should also track whether the services referenced as backends actually exist in the cluster, and it should reactively update the policy (notifying any watchers) when the existence status of a backend service changes — for example, when the backend service is created after the route was already applied.
