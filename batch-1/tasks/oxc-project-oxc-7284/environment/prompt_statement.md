I'm chasing down a bug in our JS transformer, the thing that lowers modern syntax to older equivalents based on a target browser or runtime. It's got this internal feature registry that maps each ECMAScript language feature to the year it got standardized, and we use that year to look up which browser versions natively support the feature so we know whether we need to downcompile.

The problem: the compound logical assignment operators (the ones combining logical or, logical and, and nullish coalescing with assignment, so `||=`, `&&=`, `??=`) are tagged with the wrong year. They actually landed in ES2021 but the registry has them classified as ES2020. Because of that the transformer consults the wrong browser/engine support data and thinks no transformation is needed even for environments that genuinely can't run this syntax, so we end up shipping broken output to older runtimes.

I want these operators associated with ES2021 in the registry, and when we evaluate a given target the correct year's support data should get consulted. So for a target that supports ES2019 and ES2020 but not full ES2021, the transformer should report that logical assignment operators require transformation, meaning that flag comes back enabled not disabled. And don't break the other flags while you're in there, ES2019 optional catch binding, ES2020 nullish coalescing, and ES2022 class static block all need to keep evaluating correctly.
