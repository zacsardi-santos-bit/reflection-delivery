I'm working on a JavaScript transformer that lowers modern syntax to older equivalents based on a target browser or runtime. The transformer has an internal registry that maps each ECMAScript language feature to the year it was standardized, which is used to look up which browser versions natively support that feature.

There's a bug where the compound logical assignment operators (the kind that combine logical "or", "and", and "nullish coalescing" with assignment) are registered under the wrong year in the feature registry — they're listed as an older standard than they actually were. This means when the transformer checks whether a given target environment supports these operators, it consults incorrect browser/version data and incorrectly decides no transformation is needed, even for environments that can't actually run this syntax.

The fix should ensure these operators are associated with the correct ECMAScript year in the feature registry, and that when determining transformation requirements for a given target, the correct year's support data is consulted. For a target that supports up to around ES2020 features but not ES2021, the transformer should correctly report that logical assignment operators require transformation.
