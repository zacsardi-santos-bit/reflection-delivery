So I'm hitting a wall with the ORM when it comes to UUID formatting. Right now I can use a plain UUID as an entity model field type and everything round-trips fine, but the moment I try to use one of the formatted wrapper types (the hyphenated one, braced, simple, or URN variant) the ORM has no idea how to read those values back out of the database. It only knows how to deserialize the plain UUID, so anything formatted just falls over.

What I want is for all four of those standard UUID format wrappers to work natively as entity model field types, exactly the way the plain UUID already does. I should be able to declare a field with, say, the braced or hyphenated format and then insert a record with it and pull it back with no manual conversion in between. And when I retrieve, the values I get back need to match what I put in, same format, no surprises.

The annoying part today is I'm forced to store plain UUIDs and convert by hand after every read, which is a bunch of boilerplate for something that should just be transparent. If my app always works in hyphenated UUIDs I want to model that directly and have the ORM enforce it.

Oh and one more thing, vectors of these formatted UUID types should also work as array column field types for the databases that support arrays, same as you'd expect a Vec of plain UUIDs to work. Basically treat the formatted types identically to the plain UUID everywhere they can show up in a model.
