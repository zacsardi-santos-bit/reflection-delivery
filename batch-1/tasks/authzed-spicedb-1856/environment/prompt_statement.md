I'm working on adding hover support to the SpiceDB schema language server. Right now, when someone hovers over a type or relation reference in a schema document, nothing useful comes back — the server doesn't handle hover requests at all. I'd like it to return the source code definition of whatever the cursor is pointing to, shown as SpiceDB schema syntax.

Related to this, the schema resolver currently returns positional information about referenced elements but doesn't include the actual source text of the target or where the name sits within that text. I need those two extra pieces of information so the hover handler can display rich previews. For definitions and caveats that have a body, the source snippet should use a summarized placeholder for the body rather than inlining the full content. For caveat parameter references, a target position isn't needed — just the source text.

There's also a bug in the parser where compound expressions (unions of relations, intersections, exclusions, and arrow expressions) report their starting position incorrectly — they point into the middle of the expression instead of its actual start. I need the starting position to reflect the beginning of the leftmost operand.
