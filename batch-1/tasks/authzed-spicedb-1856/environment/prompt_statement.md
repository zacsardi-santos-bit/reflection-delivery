I'm adding hover support to the SpiceDB schema language server and right now hovering over anything in a schema doc gives you nothing back, the server just doesn't handle hover requests at all. I want it so that when someone puts their cursor over a type reference, relation name, or permission reference, the server returns the source code definition of whatever's being pointed at, rendered as SpiceDB schema syntax like most modern language servers do. Oh and for definitions and caveats that have a body, the hover snippet shouldn't inline the whole body, it should show a summarized form where the body gets swapped for a comment placeholder instead of dumping the full contents.

This ties into the schema resolver, which today hands back positional info about where the referenced element lives but doesn't give you the actual source text of the target or where the name sits inside that text. I need both of those extra pieces added to each resolved reference: the source code snippet of the target, plus an offset marking where the name starts within that snippet, so the hover handler can build rich previews. For caveat parameter references specifically there's no target position needed, just the source text.

Also there's a parser bug I keep hitting where compound expressions (unions of relations, intersections, exclusions, and arrow expressions) report their starting position wrong, they point somewhere in the middle of the expression instead of its real start. I need binary expression nodes in the AST to report their start position as the beginning of their leftmost (first) operand.
