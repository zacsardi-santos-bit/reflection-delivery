I'm building a feedback system for the weave trace server that needs two utility modules to be created from scratch.

The first module needs to normalize emoji skin tones. Users can pick different skin-tone variants of the same emoji reaction, and I need to be able to map all of those variants back to the base emoji. This applies both to the raw emoji characters in a string (which may include simple emoji with a tone modifier, or complex multi-component sequences where several parts each carry their own tone) and to the shortcode representations of those emoji (which encode the tone as part of the shortcode name). The normalization should strip skin-tone information while preserving the rest of the emoji or shortcode unchanged.

The second module needs to provide a lightweight SQL building layer that works against both ClickHouse and SQLite databases. I need to be able to define tables and columns (where columns can be plain strings or JSON blobs with a separate internal storage name), generate table creation and deletion statements, and build SELECT queries. The SELECT builder should support limiting results, selecting specific fields (including nested fields inside JSON columns using dot notation), and producing the correct parameterized SQL for whichever database backend is being used — since ClickHouse and SQLite use different parameter placeholder styles. I also need a helper to combine SQL condition strings with AND or OR operators, and another helper to translate an external field name (which might be a dot-notation JSON path) into the appropriate SQL expression for the target database.
