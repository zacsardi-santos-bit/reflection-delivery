I'm building a feedback system for the weave trace server and I need two brand new utility modules from scratch, both small but load-bearing.

First up is emoji skin-tone normalization. Folks leave emoji reactions on traced objects, and they can pick different skin-tone variants of the same emoji, so a light-tone thumbs-up and a dark-tone thumbs-up end up looking like totally different reactions when they shouldn't. I want to strip skin-tone info so all the variants of one reaction group together for counting. This has to work two ways, on the raw emoji characters in a string (which might be a plain emoji with a single tone modifier codepoint, or a ZWJ sequence where an emoji is built from multiple codepoints joined by a zero-width joiner and several of those parts each carry their own tone), and also on the shortcode representations where the tone is baked into the shortcode name. In both cases I just want the tone bits removed while everything else about the emoji or shortcode stays exactly the same.

Second is a lightweight SQL building layer that produces correct queries for both ClickHouse (production) and SQLite (tests), since right now there's no shared abstraction and portable business logic is a pain to write. I need to define tables and columns, where a column can be a plain string or a JSON blob that has a separate internal storage name, and generate the create-table and drop-table DDL from those column definitions. I also want a SELECT builder that supports limiting results and selecting specific fields including nested fields inside JSON columns via dot notation, and it has to emit the right parameterized SQL per backend since ClickHouse and SQLite use different placeholder styles. Oh and I need a helper to combine SQL condition strings with AND or OR (with correct bracketing), plus another helper that translates an external field name, which might be a dot-notation JSON path, into the right SQL expression for whichever database I'm targeting.
