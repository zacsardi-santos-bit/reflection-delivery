I'm working on a JSX accessibility linter and I need to add a new lint rule that prevents developers from attaching interactive event handlers to static HTML elements. The problem is that elements like generic containers, text-formatting tags, and many structural HTML elements have no semantic meaning to assistive technologies — they're invisible as interactive controls to screen readers and keyboard navigation. If a developer attaches a click handler or keyboard handler to one of these elements without also giving it an appropriate accessibility role, it creates an inaccessible experience.

I need a rule that flags any static element with an interactive event handler (mouse events like click, keyboard events, and focus events), and tells the developer they need to add an appropriate accessibility role. The rule should be smart about what counts as "static": natively interactive HTML elements should be exempt, elements hidden from assistive technologies should be exempt, elements that already have an explicit interactive accessibility role should be exempt, and non-interactive event types (like scroll, media, clipboard, or animation events) should not trigger the rule. Custom components with capitalized names should also be ignored since their accessibility semantics are unknown. On the other hand, elements with a "presentation" role or any abstract accessibility role should still be flagged since those roles do not make an element interactive.

The rule should produce a clear error message indicating that static elements should not be interactive, with a note suggesting the developer assign an appropriate role value to signal interactive intent.
