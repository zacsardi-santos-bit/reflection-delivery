I'm hitting a compile bug with PRQL when I target Snowflake as the SQL dialect. Duration arithmetic just doesn't come out right. Say I write a query that adds 10 days to some start date column, basically doing date-offset math with PRQL's built-in duration syntax, the compiler generates interval syntax that Snowflake flat out rejects. Other targets each do intervals in their own format and that's fine, but Snowflake has this specific quoting requirement that isn't being handled, so date calculations break.

The thing Snowflake wants is that inside the interval expression the numeric value and the unit name get quoted together as a single string. So the value 10 and the unit DAY should show up together as one quoted pair, not split apart the way it's coming out now. Also the unit name needs to render in uppercase singular form, so DAY not days or DAYS. And while we're in there, Snowflake output should use double-quoted identifiers for column and table names.

What I want is for duration arithmetic in a PRQL query targeting Snowflake to compile to valid Snowflake SQL. The derived column that adds the duration to the existing column should land in the SELECT clause as an aliased expression sitting alongside all the other columns. Without this, anything doing date or time manipulation can't compile to Snowflake-compatible SQL, which makes PRQL kind of unusable for common date-offset work in Snowflake workflows. Can you fix the Snowflake dialect handling so interval arithmetic comes out in the format Snowflake actually needs?
