We're adding support for two major versions of Pydantic (the data validation library) in our model serving framework, and right now our data models module only handles the older major version but we need it to work with 2.x too. The annoying part is there's no exported flag anywhere telling us which major version is actually installed, so any code that needs to branch on version-specific behavior ends up re-implementing the detection logic itself, which is fragile.

Here's the concrete pain: with Pydantic v2 installed, boolean fields in server health responses get serialized as native JSON booleans, but with the older v1 they come back as stringified Python booleans (like the Python repr of the bool). Our health check endpoint test hardcodes one format and doesn't account for whichever version happens to be in the environment, so it fails depending on what's installed.

What I want is for the data models module to expose a boolean that's true when Pydantic v2 is active and false otherwise, so test code and application code can just check that flag instead of each doing their own version sniffing. Once that flag exists, I want the health check endpoint to respond with the right serialization format for whatever version is installed, and the health check test should import that flag and use it to assert the correct expected response format for the installed version. Supporting both majors matters for compatibility across different deployment environments, so let's centralize this properly rather than scattering detection everywhere.
