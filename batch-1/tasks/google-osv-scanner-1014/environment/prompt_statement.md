I'm adding CycloneDX SBOM output to osv-scanner. Right now it can emit table, JSON, Markdown, SARIF, and GitHub Annotations, but there's no way to get a CycloneDX bill of materials, and a lot of security and compliance workflows rely on CycloneDX as their interchange format so folks either convert output by hand or reach for another scanner. I want two new output format flag values, one for CycloneDX 1.4 and one for 1.5, both accepted by the CLI. Exit code stays 0 when no vulns are found and 1 when there are.

To build correct output I need helper parsers that split ecosystem-specific package identifiers into namespace and name. Java packages use a colon-separated "group:artifact" convention, so the group is the namespace and the artifact is the name. Go modules use slash-separated paths where the last segment is the package name and everything before it is the namespace, though some Go packages are just a bare domain with no slash, in which case the namespace should be empty and the whole string is the name. PHP Composer uses a slash-separated "vendor/package" form. Each of these should return an error if the name is empty or doesn't match the expected structure.

I also need a function that takes packages from multiple lock files and groups them by their standardized package URL so the same package showing up in different sources gets merged into one entry, and when merging, the dependency group annotations from all the occurrences get combined into the merged entry.

Oh and the new reporter should support the same verbosity levels the other reporters in that package already use, writing log messages to the right writer depending on the configured level.
