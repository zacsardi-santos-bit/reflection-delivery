I'm setting up a Pants plugin to cut down on the metadata boilerplate we keep repeating across every StackStorm Python dist. Right now if I want to ship a wheel each `python_distribution()` target has to spell out the same author, author_email, license, url, project_urls, classifiers, all of it, and it's error-prone and just noise in the BUILD files. Pants has that `SetupKwargs` plugin hook for auto-generating setup.py metadata when distributions get built, so I want to hook into that and centralize the common stuff.

What I'm after: the plugin should automatically inject `author="StackStorm"` and `author_email="info@stackstorm.com"` plus the standard url, license, and project_urls into every distribution when it's built, so I don't repeat myself. The version should get pulled automatically by reading a `__version__` variable out of a file the target points at via a `version_file` path. Oh and if there's a `README.rst` sitting in the distribution's directory it should get picked up as the `long_description` automatically, but only if it actually exists.

Also I want a batch of standard classifiers baked in (development status, intended audience, license, operating system, and the supported Python versions) and those should get prepended to whatever custom classifiers a package supplies, so individual packages can still add their own on top without losing the common ones. End goal is that a package author only has to give the name, description, the version_file path, and optionally their own extra classifiers, everything else comes from the plugin. That keeps metadata consistent across packages and stops the duplication and drift we get otherwise.
