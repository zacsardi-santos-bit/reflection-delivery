I'm hitting a bug in the connection removal logic where deleting a connection with the indexed removal assignment just doesn't work once the nodes involved live at multi-level paths. Here's the repro: I declare the same connection between two deeply nested nodes twice, then I try to delete each occurrence with an indexed deletion assignment, one using the full absolute path form for both source and destination, and the other using the parent-node-scoped syntax where the connection is expressed relative to a parent node. After compilation both connections are still sitting there in the diagram even though I explicitly removed both of them. So it looks like the removal path can match connections fine when endpoints are single-segment, but it chokes when the endpoints have multiple path segments, and it fails the same way whether you reference them by absolute path or through the parent-scoped shorthand.

What I want is for deleting a connection by index using the full absolute path for source and destination to actually drop that connection from the compiled output, and same deal for the parent-scoped form, it should remove the connection too. Once both deletions are applied the compiled graph should end up with zero connections remaining while the referenced nodes themselves stay in place, they shouldn't get removed. This matters because folks conditionally remove connections in scenarios or overlays and rely on indexed connection deletion, and when it silently no-ops for deeply nested connections the diagrams can't be built the way people expect and the whole deletion syntax stops being trustworthy for what are honestly pretty common cases.
