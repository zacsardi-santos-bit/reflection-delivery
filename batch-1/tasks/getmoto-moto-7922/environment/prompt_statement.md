I'm building ML workflows on top of SageMaker Model Cards and I can't write offline unit tests because moto doesn't mock these APIs at all yet, so right now I'm stuck either hitting real AWS (costs money, needs creds) or skipping test coverage entirely, which is no good for CI. Model Cards are that versioned, taggable SageMaker resource for documenting models (descriptions, intended use, performance, etc.) and I need the moto mock in the sagemaker backend to handle the full lifecycle.

So creating a card should hand back an ARN, and if a card by that name already exists it needs to raise a conflict error. Updating a card should spin up a new version, and updating (or describing, or deleting) a card that doesn't exist should raise a not-found error. Describing a specific version that isn't there should also be a not-found, with a message that names both the card and the version number. When I describe a card I want back the ARN, name, version number, content, status, security config, and the creator/modifier metadata, and it should let me fetch a specific version or default to the latest. Also all versions of a card share the same original creation time, but each newer version gets its own last-modified time that increases with the version.

For listing cards I need to filter by name-contains substring, by status, and by a creation time range, plus sort ascending or descending and sort by name instead of time. Listing versions of a single card should similarly support sort order and status filtering while exposing version numbers and timestamps. Deleting a card should drop it out of the listings. Oh and tags, I want to attach tags at creation time and manage them (add, list, delete) through the standard tagging operations.
