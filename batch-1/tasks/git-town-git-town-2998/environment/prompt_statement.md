I'm building out an alias configuration step for the Git Town setup wizard and need the data structures and logic under it before wiring up the actual dialog. The point is to let people interactively pick which Git Town commands get aliased as shorter git subcommands so they can type "git sync" instead of "git town sync", and this alias step should end up being the first thing the wizard walks you through.

What I need first is a way to classify existing aliases into three buckets, ones that already point to a Git Town command (default that entry to selected), ones pointing to some other external command (default to other), and ones that don't exist yet (default to none). Then there's logic to compute the dialog result, taking each per-command selection state and converting it back into the actual alias values to persist.

For the interactive model over in the config dialog code, selection state needs to be togglable per command entry, and the toggle should cycle through states sensibly based on what was originally configured, so like if a command had a custom non-Git-Town alias to begin with, cycling eventually brings that state back around so the user can restore it. I also want select-all and clear-all across every entry.

Over in the configuration domain layer I need a typed alias collection type with a method to convert it to plain strings, plus constructor functions that build this type from raw string input. The function returning all aliasable commands should hand back this typed collection instead of a plain slice (rename the accessor accordingly), and add a way to look up a single command by name.

Last thing, a helper that produces a readable summary of what's selected, showing "(all)" when everything's aliased, "(none)" when nothing is, and otherwise a comma-separated list of the command names.
