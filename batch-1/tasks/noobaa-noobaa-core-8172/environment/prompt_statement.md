I'm working on the IAM operations in our system — things like creating, updating, deleting, and listing users and access keys. Right now, when I call these operations with invalid or missing inputs, nothing catches the problem early. For example, if I omit a required field like a username or an access key ID, or if I pass an empty string where a value is expected, the operation just proceeds and fails later in an unclear way. Similarly, path values that don't follow the required format (must start and end with a specific delimiter) and access key IDs that are too short aren't caught at all.

I'd like to add up-front input validation to all these operation handlers so that malformed requests are rejected immediately with a descriptive error. I also need a set of reusable validation helper functions — one each for paths, usernames, access key IDs, pagination markers, and status values — so that each operation handler can use them consistently rather than duplicating validation logic. Each helper should return gracefully when the value is not provided (optional fields), return a success indicator when the value is valid, and throw an appropriate validation error otherwise.

The validation errors should have consistent message patterns: missing required fields should mention they're required, length violations should mention length, invalid path formats should mention path, and invalid status values should indicate the constraint was not satisfied. I'd also like a new constants module for the field name strings used in error messages so they're centralized in one place.
