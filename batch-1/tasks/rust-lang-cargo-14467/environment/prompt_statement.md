I'm poking at the experimental namespaced package names feature in Cargo, the one where a package name can carry a double-colon namespace separator in it, and I've hit a wall where several commands that take a package spec just don't recognize those names as valid targets. I can declare and build these packages fine, but the update command chokes when I try to selectively update one by name.

Concretely, if I run the update command and pass only the namespaced name (the one with the `::` in it), it fails because the spec parser seems to think the double-colon is part of a version specifier. Same deal when I hand it the full qualified package identifier, which embeds that namespaced name in its path fragment. I'd expect both forms to just work: the bare namespaced name as the update target, and the fully qualified package ID. And in either case, when nothing actually needs updating, it should report zero packages locked to newer versions with nothing on stdout.

The root cause is in the package ID spec parser, which treats a colon as the separator between name and version and so splits on the first colon it sees, mangling a name that legitimately contains `::`. Please fix it so it distinguishes double-colon namespace separators inside names from the single-colon or `@` separators that come before a version number. While you're in there, the command that prints a package's own identifier (the pkgid-style output) should emit the full qualified package ID with the namespaced double-colon name intact, in the standard package ID spec format. Basically I want all the normal Cargo workflows, especially selective dependency updates, to work for namespaced packages the same way they do for regular ones.
