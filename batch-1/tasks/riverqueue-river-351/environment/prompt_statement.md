So I'm adding tag validation to River's job insertion path and I keep hitting this gap where tags can be literally any string right now, no length checks, no character restrictions, nothing. The real problem is commas: they're used as delimiters in some internal operations so a tag with a comma gets silently accepted and then breaks downstream stuff in ways that are a pain to trace. Short tags and weird special characters cause similar surprises too.

What I want is a package-level regex variable in the river package (in the appropriate file there) that encodes a consistent tag format so we can apply it wherever tags get validated at insertion time. The rules are: a tag has to be at least 3 characters long, it has to start and end with a letter, digit, or underscore (specifically not a hyphen), hyphens and underscores are allowed in the middle, and commas or any other special characters are never allowed. Basically letters, digits, hyphens, underscores only, with the hyphen restricted to interior positions.

Point of all this is to catch bad values right at insertion with a clear error instead of letting them slip through and cause mysterious corruption later, so devs get immediate feedback. Can you drop in that package-level regex var that enforces these format requirements?
