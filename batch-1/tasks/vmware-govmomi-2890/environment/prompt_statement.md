I'm poking at the virtual machine simulator and hit a mismatch with how virtual disk capacity gets stored. A disk carries two capacity representations, one in bytes and one in kilobytes, and they're supposed to stay in sync, but right now they don't when I add a disk with only one of them filled in. If I set just the byte-level capacity before adding the disk, the kilobyte field stays at whatever it was initialized to instead of being derived from the byte value, and the reverse happens too, set only the kilobyte field and the byte field never updates. Worse, if I set both to conflicting values, neither gets reconciled, so a later query on the VM's devices hands back two numbers that disagree.

What I want is for the simulator to normalize both capacity fields automatically whenever a disk device is configured, no matter which combination the caller passed. So if only bytes is set, derive kilobytes by dividing by 1024, and if only kilobytes is set, derive bytes by multiplying by 1024. When both are given and they agree on the same logical capacity, keep both as-is. When both are given but disagree, the byte-precision field wins and the kilobyte field gets recalculated from it. Callers shouldn't have to babysit these two fields by hand, that consistency should just happen transparently at configure time so queries always come back coherent. Any valid fix needs to handle all four cases, only bytes, only kilobytes, both consistent, and both conflicting with bytes taking precedence.
