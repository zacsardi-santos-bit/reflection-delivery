I'm working with the virtual machine simulator and I've noticed that when adding a virtual disk, the two capacity fields — one expressed in bytes and one in kilobytes — are not being kept in sync. If I only set the byte-level capacity field before adding the disk, the kilobyte field ends up wrong (it stays at whatever it was initialized to rather than being derived from the byte value). The same happens in reverse: if I only set the kilobyte field, the byte field doesn't get updated. On top of that, if I set both fields to conflicting values, neither one is reconciled — I'd expect the byte-precision field to win and the kilobyte field to be recalculated from it.

Essentially, the simulator should automatically normalize both capacity representations when a disk device is configured, regardless of which combination of fields the caller provides. Any valid implementation of this normalization behavior should cover all the edge cases: only bytes set, only kilobytes set, both set consistently, and both set with a conflict (byte value takes precedence).
