I'm working with this blockchain library and it's got a nice way to fetch transaction details, but there's no built-in path for grabbing transaction receipts and I keep needing them. After I submit a tx I need to know whether it actually succeeded, how much gas it burned, what events it emitted, plus the contract address on deployments and the block placement info, all of which live on the receipt not the transaction itself. Right now I have to drop down to lower-level tooling outside the library to get any of it, which is annoying.

So I want a proper core action that retrieves a transaction receipt by its hash with optional chain targeting, following the same patterns as the existing transaction-fetching utilities. Alongside that I need the query cache helpers to match how the rest of the library does caching, so a query key helper and a query options helper that plug into the TanStack Query style patterns used elsewhere.

On the React side I need a hook that wraps this action with the library's reactive query system. Important bit: it should stay idle and not fire any network request when no transaction hash has been provided yet, because in a lot of flows the hash isn't known until after the tx is submitted. Once a hash shows up it should automatically fetch the receipt. Oh and the hook should automatically fold the active chain's identifier into its cache key even if I don't pass a chain explicitly.

And all of this (the action, the query utilities, the hook) needs to be reachable through the library's standard public exports so I can import it the same way as everything else. This matters because so many dApp flows depend on reading the receipt, like showing a success message, revealing a minted NFT, or unlocking the next step after a transfer, and I'd rather stay inside the library's consistent patterns than reach for something lower level every time.
