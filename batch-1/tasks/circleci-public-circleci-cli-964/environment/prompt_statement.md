I'm working on the policy evaluation side of the CircleCI CLI and there's a gap I want to close around config compilation. Right now when I run the policy `eval` or the raw evaluation command with an input config file, we ship the config straight to the policy decision API in its raw source form. Problem is, real CircleCI pipelines compile the config first (orb expansion and other transforms) and policies really should run against that compiled version, not just the source, otherwise I get misleading pass/fail results that don't match what actually executes.

So what I want is for both commands to compile the config through the CircleCI API by default before sending it off for evaluation. The compiled result should ride alongside the original source under a special sentinel key so a policy can inspect both forms. Oh and if the source config already has that sentinel key at its top level, strip it off the compiled output before embedding so the two don't get conflated.

I also need an opt-out flag on both commands to skip the compile step and just evaluate the raw source directly, handy for local dev or when I don't need compilation at all. Since compiling means an API call with org context, it needs an owner ID, so when compilation is on and I'm pointing at a local policy file without an owner ID, fail with a clear error that tells me about the opt-out flag if I don't actually need compilation. Also, actually, the existing restriction that blocks using a local policy path together with an owner ID needs to go, because that combo is genuinely useful now once compilation's in play.
