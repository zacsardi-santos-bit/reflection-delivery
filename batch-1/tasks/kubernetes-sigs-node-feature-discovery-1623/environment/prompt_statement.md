I'm working on node-feature-discovery and want to add a real feature-gating system so we can flip experimental capabilities on or off at runtime without editing code. Right now feature lifecycle (alpha → beta → stable → deprecated) is a mess because individual things like the Node Feature API get toggled through scattered one-off boolean flags with no shared contract around discoverability or locking. I want a proper utility package that gives me a feature gate abstraction where each gate has a name, a default enabled/disabled state, a maturity stage (alpha, beta, stable, or deprecated), and an optional lock that permanently pins the gate to its default. It's gotta be configurable via a command-line flag that takes a comma-separated list of name=value pairs to override defaults at startup. When I list known features for help text, only show the alpha and beta ones, hide stable and deprecated. Setting an unknown gate should return a descriptive error, and trying to set a locked gate to a non-default value should error out with the gate name, the value I attempted, and the locked value all in the message. The string representation should list only explicitly-set features in alphabetical order. Oh and I need a deep copy that produces an independent copy but still preserves any overridden defaults.

Alongside that utility, I want an NFD-specific features package that exposes a shared, global mutable feature gate, a map of NFD's default feature gate definitions, and a named constant for the Node Feature API gate, which is a beta feature enabled by default. Also the existing master and worker test setups need updating so they initialize this shared gate and disable the Node Feature API gate before creating test instances, that way the tests run against a predictable baseline instead of the production defaults.
