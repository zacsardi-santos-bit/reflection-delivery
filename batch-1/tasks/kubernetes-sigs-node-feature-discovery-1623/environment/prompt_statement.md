I'm working on node-feature-discovery and need to add a proper feature-gating system so we can enable or disable specific experimental capabilities at runtime without touching the code. Right now there's no consistent way to manage feature lifecycle — things like toggling the Node Feature API are done through scattered one-off boolean flags.

I need a utility package that implements a feature gate: each gate has a name, a default value, a maturity stage (alpha, beta, stable, or deprecated), and optionally a lock that prevents the default from being overridden. The gate should be configurable via a command-line flag that accepts comma-separated name=value pairs. When displaying available options, only alpha and beta gates should be listed — stable and deprecated ones should be hidden. Setting an unknown gate or violating a lock should produce clear error messages. The gate should also support deep copying in a way that preserves any default overrides.

Alongside that utility, I need an NFD-specific package that wires up a shared, global mutable feature gate, a map of NFD's default feature gate definitions, and a named constant for the Node Feature API gate (which is a beta feature enabled by default). The existing master and worker test setups need to be updated so they initialize this shared gate and disable the Node Feature API gate before creating test instances — that way the tests run against a predictable baseline rather than the production defaults.
