I'm working on a design system and we're introducing a new generation of layout components. The existing flex-based stack components need to be renamed to clearly mark them as "legacy" so developers know they're being phased out. As part of this rename, I'd also like to modernize how the components express their layout: instead of using inline styles for flex direction and alignment, these should use CSS module classes. The CSS custom property names used for sizing and spacing should also be updated to use a consistent, design-system-specific prefix.

The renamed legacy components should still work the same way externally — supporting horizontal and vertical directions, allowing individual items to override their alignment, applying spacing gaps to all but the first valid child element, and supporting common HTML customization props. Non-element children (like conditional renders that produce nothing or plain text nodes) should continue to be ignored when deciding which child receives the first-position treatment for spacing purposes.
