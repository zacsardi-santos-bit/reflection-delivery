I've got this Rust crate that knows how to apply structured patches to files on disk, all the logic lives in the library, but there's no actual binary I can run from a terminal. That's annoying because whenever I want to apply a patch from a shell script or a CI job I have to go through the whole larger hosting app, which is way too heavy for what should be a one-liner. So I want to add a standalone command-line executable to the existing Cargo package that just wraps the apply functionality directly.

The way I want it to work is pretty simple, it takes the patch content two ways. If I pass the patch as a command-line argument it should read it straight from there, and if I invoke it with no arguments at all it should fall back to reading the whole patch off standard input instead. Both paths need to behave exactly the same, no difference in how the patch gets parsed or applied. Once it has the patch text it applies it to the filesystem relative to the current working directory (so wherever I'm running from).

On success it should print a summary to stdout listing the files that changed, and each line needs a single-letter prefix showing the change type, like an A for a file that got added and an M for one that got modified. Then it exits with code 0. Basically I want to be able to do both `mytool "<patch text>"` and `cat some.patch | mytool` and have them do the same thing and tell me what happened. Can you wire this binary up in the existing package?
