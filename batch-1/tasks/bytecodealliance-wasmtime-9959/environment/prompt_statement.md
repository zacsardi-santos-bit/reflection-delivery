I'm working on the Winch compiler backend in Wasmtime and I keep hitting a wall with the SIMD byte shuffle instruction. Right now if I try to compile a Wasm module that uses `i8x16.shuffle` with Winch on x86_64, I just get a compilation error saying the instruction isn't implemented yet, which is a pain because Winch is supposed to be the fast-startup, low-latency JIT alternative to Cranelift and it needs to progressively cover more of the SIMD instruction set. Anyone relying on byte-level vector rearrangement (super common SIMD stuff) just can't run their programs through Winch at all right now.

What I want is for Winch to actually handle this instruction by emitting the right vector instructions. The shuffle takes two 128-bit source vectors and a 16-byte lane index pattern, and for each of the 16 output lanes it selects a byte from either of the two sources according to that pattern. On x86_64 with the required vector extensions, the implementation should produce correct native code doing exactly that selection, so compilation succeeds without errors instead of blowing up. This is a codegen change on the x86_64 side of the Winch masm/backend.

Oh and there's a new SIMD lane shuffle test file for Winch that needs to be registered as requiring the vector extension hardware, so the testing infrastructure knows to skip it gracefully on machines that don't have that support. Please make sure that registration lands too, otherwise it'll try to run on hardware that can't handle it.
