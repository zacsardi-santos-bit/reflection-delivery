I'm working on the Noir compiler's trait implementation checking. Right now, if I write a trait implementation where a method has extra "where" clause constraints that the original trait method doesn't have, the compiler accepts it silently. This is a bug — the implementation is more restrictive than the trait allows, which violates the trait contract and causes confusing errors elsewhere.

I need the compiler to detect when a trait implementation method introduces extra type constraints beyond what the corresponding trait method specifies, and report an error identifying the type and trait involved in the extra constraint. This should work correctly for all kinds of constrained types: plain generics, generic wrapper types, arrays, and tuples. The error should not fire for methods that correctly mirror the trait's own constraints (with renamed generics), nor for constraints that come from the implementation block itself rather than the method. When the implementation block's own constraints aren't satisfied at a call site, the existing "no matching implementation found" error should still be used.
