I'm using the tracing crate for structured logging in my Rust app and the brace requirement keeps tripping me up. Whenever I want to log structured fields plus a human readable message in the same event, I have to wrap the fields in curly braces, and if I forget them the macro just won't compile. It feels needlessly verbose and inconsistent with the simpler cases that don't need braces at all.

What I want is for all the tracing macros in `@tracing/src/macros.rs` to accept a no-braces syntax where I list named fields, local variable shorthands (including the ones with display or debug formatting sigils like `%` and `?`), and a format string message all together, just comma-separated, and the macro figures out where the fields stop and the message starts. This should work for the generic `event!` macro and also every level-specific convenience macro (`trace!`, `debug!`, `info!`, `warn!`, `error!`).

Some cases to handle: trailing commas after the final argument still need to be accepted, the message format string should still support format arguments, named arguments, and plain string literals, invocations with an explicit `target:` should work, and invocations that have fields but no message at all should work too. Basically the braces become optional across the board so I don't have to juggle two different syntaxes depending on whether there's a message. Oh and don't break any of the existing braced forms, they should keep compiling exactly as before.
