I'm working on pgvecto.rs and I want to add a way for the extension to call out to an external embedding service like OpenAI so we can turn text into vector embeddings right inside the database, no separate preprocessing pipeline needed. Right now there's just no path to reach a remote API at all, so I'd like a brand new crate in the workspace that owns all of this: building the HTTP request with the right auth headers, firing it off to whatever endpoint is configured, parsing the JSON that comes back, and handing me either the embedding vector or a sensible error.

The main entry point should take a text input, a model name, and connection options (basically a base URL plus an API key so it's configurable), send the request, and give back the resulting vector. Three cases matter here. When the service returns a valid response with embedding data, I get success with the vector. When it returns a valid response but the data array is empty (no embedding entries), then trying to pull the vector out should be an error. And when the service is unreachable or hands back something non-parseable like an HTTP error, that's also an error.

So please add the new embedding crate with all the types it needs (the request/response serialization structs, the connection options with base URL and API key, the client logic that does the send and parse) and wire it into the workspace so it actually builds as part of the project. Good error handling across all the failure modes (network errors, empty responses, malformed responses) is the whole point since this needs to hold up in production.
