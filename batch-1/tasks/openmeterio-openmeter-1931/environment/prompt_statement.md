I'm working on a billing service that integrates with external invoicing apps and I need to extend the integration to cover the full invoice lifecycle. Right now the system can validate invoices through connected apps, but it doesn't actually sync, finalize, or delete invoices through those apps — which means external systems never get updated.

I need the system to call through to the app at each stage: when an invoice is synced to draft, the app should be able to assign external identifiers to the invoice and to individual line items (specifically fee-type lines, not usage-based ones); when an invoice is finalized, the app should both sync and then finalize it, recording any payment reference the app returns; and when an invoice is deleted, the app should be notified.

There are some specific error-handling requirements too. If the deletion fails with a validation-level error, the invoice should be soft-deleted with a "delete failed" status and the error surfaced to the caller as a validation error. If deletion fails with a generic error and the caller retries, the error should appear as a validation issue on the returned invoice. When retrying a failed invoice more generally, the system should first demote any existing critical validation issues to a lower severity before reattempting — this ensures old blocking errors don't prevent the retry from proceeding.

Finally, the component name attached to validation issues should be updated to include the specific operation that was being performed (e.g. validate, sync, delete, finalize) using a dot-separated format. This makes it easier to diagnose exactly which step produced an issue.
