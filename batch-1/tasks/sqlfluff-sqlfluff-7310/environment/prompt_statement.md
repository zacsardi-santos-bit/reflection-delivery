I'm hitting a parsing bug in the BigQuery dialect of our SQL linter around type conversion expressions that carry a format specifier. You know how BigQuery lets you convert between types using a format pattern, like turning a date into a string with a date format template, or parsing a string into a time value with a time format pattern? The parser mangles these. Right now the format indicator inside the conversion (the `FORMAT` bit) gets treated as if it were a column reference instead of being recognized as its own SQL keyword, so the parse tree that comes out is just wrong and doesn't reflect the real structure.

I want the format specifier recognized as a keyword, and the format string that follows it to show up directly in the parse tree as a quoted literal rather than getting wrapped inside some expression node.

On top of the misidentification, a whole set of valid BigQuery conversion-with-format patterns don't parse at all, and I need all of these working: string to binary with a format pattern, a date value to string with a date format pattern, a time value to string with a time format pattern, a timestamp value to string with a format pattern plus the optional timezone clause that can trail the format string, a string to a time value using a time format pattern, a column reference to string using a numeric format pattern (including ones with special chars like currency symbols and thousands separators), and numeric literals both positive and negative to string using numeric format patterns. Oh and don't forget that optional timezone specification, it can appear after the format string in the timestamp case.

Basically BigQuery has this rich type conversion syntax and folks linting real BigQuery code expect the parser to actually understand it, so the grammar for these conversion expressions in the dialect needs to handle the keyword correctly and cover all the variants above.
