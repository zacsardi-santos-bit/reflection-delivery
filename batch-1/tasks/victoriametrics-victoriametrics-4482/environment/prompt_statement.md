I'm adding Loki-compatible log ingestion to VictoriaLogs so people can point Promtail or Grafana Agent at us without rewriting their shipping config. Right now we just can't accept Loki push requests at all, and I need handlers for both the JSON and the binary (protobuf with snappy compression) variants of the push protocol.

For the JSON side, the body is the standard Loki push shape where each stream carries label key-value pairs plus a list of entries, and every entry has a nanosecond timestamp and a message string. I want the handler to walk each entry and invoke a callback with that entry's timestamp and its fields, so the stream labels turn into individual named fields and the log line itself becomes a dedicated message field. It should hand back the count of entries it processed, and it needs to return an error on empty, malformed, or truncated input rather than silently doing nothing. Make sure the nanosecond-precision timestamps parse correctly, that part matters.

The binary handler does basically the same thing, oh it reads a snappy-compressed protobuf Loki push body and runs it through the same callback interface, also returning the processed count.

Also I need a small utility in the log storage layer that parses a tenant identifier from a plain string. It can be just an account number, or a colon-separated account:project pair, or either part omitted/empty, and an empty string maps to the zero-value tenant id. This is what lets us route logs to the right tenant from an HTTP header or query param.
