I'm hitting a crash in the Terraform plan JSON scanner whenever a plan has resource attribute values that look like template expressions, you know the ones with a dollar sign or percent sign followed by curly braces that Terraform uses for variable references and template directives. These are totally valid plans, the variable just hasn't been resolved yet at plan time so the planned value is literally that template string sitting there in the JSON. Right now the scanner either crashes or returns an error instead of just scanning the resources like normal, which is a real problem because tons of real-world plans include unresolved variable references in planned values, so any team that uses interpolation in their Terraform config basically can't rely on security scanning at all.

What I want is for scanning to succeed without error when a resource attribute (say an S3 bucket name) has a value like one of these template-style strings. And it's not enough to just not crash, the scanner needs to actually evaluate those resources and correctly detect policy violations against them even when the attribute values contain that template syntax. So the scan results should come back with the expected number of failures and report the right rule metadata off the associated policy, like the AVD ID, so downstream stuff can key off that. Basically treat the template string as an opaque literal value, parse the plan, run the checks, and give me back accurate violations instead of blowing up.
