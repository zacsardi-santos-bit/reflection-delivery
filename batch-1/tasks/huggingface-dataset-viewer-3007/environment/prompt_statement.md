I'm building out the dataset viewer statistics feature and hit a gap: the stats endpoint already handles numeric, string, categorical, boolean, list, audio, and image columns, but datetime and timestamp columns get nothing computed for them. Datetime data is everywhere in real datasets (event logs, medical records, financial transactions) so without temporal stats you can't tell the time range a dataset covers, the typical or average date, or how values spread out over time, which makes the whole feature way less useful for anything time-stamped.

So I want a new column type for datetime data that computes min, max, mean, median, and standard deviation of the datetime values, plus a histogram of how values are distributed over time. The min/max/mean/median should come back as human-readable datetime strings with precision up to seconds, the std dev as a human-readable time duration string, and the histogram bin edges should be datetime strings too, not numbers. Oh and timezone-aware timestamps need to keep the timezone offset in all the output strings. If a column is all nulls, every statistical field should just be null.

Also I want to catch string columns that actually store dates as text, right now those get treated as generic text and analyzed by string length which misses the point. When a string column consistently uses a single recognizable date/time format it should get auto-detected and processed as datetime instead, returning the same stats as a native datetime column. That behavior should be gated behind a feature flag on the string column handler, defaulting to off. And if a string column has mixed or unrecognizable date formats it should gracefully fall back to the regular string statistics.
