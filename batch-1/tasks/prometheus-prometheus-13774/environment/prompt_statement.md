I'm using Prometheus with the Linode service discovery in `@discovery/linode` and I keep hitting two walls. First one is regions. I've got Linode instances spread across a bunch of regions and for a given scrape job I usually only care about one of them, but right now the discovery just pulls back every instance from every region and I'm stuck cleaning it up with relabeling on the region label after the fact, which still means fetching and processing the whole instance list every refresh. I'd love a region option in the SD config so when I set it only instances in that region come back as targets, and when I leave it out it behaves exactly like today and discovers all regions (gotta keep that backwards-compatible so nobody's existing config breaks).

Second thing, IPv6 delegated prefix ranges aren't showing up in the discovery metadata at all. Linode lets you route whole IPv6 CIDR blocks to a single instance, separate from the instance's primary SLAAC address, and I want to reference those in relabeling rules the same way I can already reference the extra IPv4 addresses. So can we add a new metadata label on each discovered target listing all the IPv6 prefix ranges routed to that instance? It should use the same separator-wrapped comma-separated list format as the other list-valued labels like the extra IPs and tags. Oh and if an instance doesn't have any routed IPv6 ranges then it just shouldn't get that label at all, don't emit an empty one. That'd fill the gap for folks doing IPv6 prefix delegation in their network topology.
