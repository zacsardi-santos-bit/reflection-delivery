I'm using Prometheus with Linode service discovery to monitor my infrastructure, but I'm running into two limitations. First, I have Linode instances spread across multiple regions and I only want to monitor a specific region in each scrape job. Right now, the service discovery always returns all instances from every region, and I have to work around this with relabeling rules after the fact. It would be much cleaner to just specify a region in the service discovery configuration so only targets from that region are returned.

Second, I've noticed that IPv6 delegated prefix ranges aren't included in the discovery metadata. Linode allows routing entire IPv6 address ranges to specific instances (not just individual addresses), and I'd like to be able to reference those ranges in relabeling rules — similar to how extra IPv4 addresses are currently exposed. Could support for these IPv6 ranges be added as a new metadata label on discovered targets, using the same separator-wrapped list format as other list-valued labels?
