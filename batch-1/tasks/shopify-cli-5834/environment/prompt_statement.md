I'm hitting two parsing bugs in the Shopify theme dev server around Liquid section files and want them both fixed.

First problem: when any section file has Liquid syntax errors, the server blows up while it aggregates stylesheet and javascript content for the compiled asset endpoints. I don't want it to fail the whole thing. Instead, for files that can't be fully parsed, fall back to a simpler extraction approach, pull in whatever valid content it can, and log a debug-level warning about the parse failure rather than crashing. This needs to work for both the stylesheet aggregation and the javascript aggregation paths.

Second, the hot-reload change-detection logic for section files only tells apart stylesheet vs javascript block changes right now. It doesn't separately track whether the schema block or the remaining liquid content changed. I want all four parts (stylesheet, javascript, schema, and the leftover liquid) tracked independently so hot-reload events carry accurate info about exactly which parts of a file changed, and only the parts that actually changed should get flagged. Same fault-tolerance thing here too, if a file has syntax errors it should still attempt to figure out which parts changed via a fallback and log a debug warning instead of throwing.

Oh and on the flip side, hot-reload events for JSON files and pure asset files (CSS, JS) are currently carrying file-part change metadata that doesn't even apply to those types since they don't have the structured Liquid parts. Drop that metadata for those file types.

Also the per-file content cache the change-detection uses should be exported so it can be managed externally, like cleared between uses. It should store normalized versions of each content part with whitespace collapsed, and key off the file checksum to skip redundant processing.
