I'm cleaning up the release dashboard footer in our CMS and it's not handling every release state right. The main gap is archived releases, right now the footer still tries to render a primary action button for them but that makes no sense since you can't publish, schedule, or revert something that's archived. For archived releases I want the primary action button suppressed entirely so the footer actions area only shows the overflow menu button, nothing else.

The other states are mostly working already and I want to keep that behavior intact: an active ASAP release should show a publish button, an active release of the scheduled type that hasn't actually been scheduled yet should show a schedule option, a release that's currently scheduled for publishing should show an unschedule button, and a release that's already been published should show a revert button. So it's really just the archived case that needs the primary action stripped out, leaving only the overflow menu.

Oh and while I'm in there, the footer actions container needs a dedicated test attribute so we can target that exact region of the UI in tests. Showing irrelevant publish-related actions on archived releases is just misleading, so the footer should only ever surface actions that actually mean something for the current state.
