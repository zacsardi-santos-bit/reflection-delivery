I'm running into a couple of annoying gaps in our testgrid integration package that writes XML test results out to a file, and I want to clean them up. Right now the output filename lives as a private constant inside the package, which is a pain because anything outside the package that wants to reference that file (to read it, clean it up, validate it, whatever) has to hardcode the string itself. I want that filename exported so it's part of the public API and external callers can just refer to it by name.

The bigger issue is that the function which writes XML output to a file overwrites the whole thing every time I call it, so when a single run produces multiple test suites I only end up with the last one and silently lose the rest. I need it to append instead, so successive calls accumulate into one output file and everything that got written during a run is actually present. Writing XML multiple times to the same directory should leave me with all of the outputs in that file, not just the final one.

Oh and there's a helper that resolves the artifacts directory from an environment variable, but it's got no test coverage so I'm not confident about its fallback. I want its behavior verified and correct: return the env var's value when it's set, and fall back to a default of "./artifacts" when the variable is empty or missing. Without these fixes tools depending on this package can't reliably name the output file, and any multi-suite run quietly drops results, so I'd like all three sorted.
