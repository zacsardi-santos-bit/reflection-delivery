I'm extending the k8sgpt Bedrock integration to support Amazon's newer generation of hosted models, and right now the code only knows how to talk to the older Amazon families. The problem is the newer models want a totally different request shape, an inference configuration block plus a structured messages array, instead of the flat input text the older ones use, and on the way back the text comes buried in a deeply nested response structure that the current parser doesn't dig into. So requests get built wrong or responses come back malformed.

Could you add a dedicated completion method that builds requests in the newer format (inference config block and messages array) separate from the existing older-model method, plus a matching response parser that pulls the generated text out of that nested structure. Oh and if the response has no content the parser should just hand back an empty string, no error.

Then the general-purpose Amazon completion method needs routing so it picks the format based on the model name, newer-family names go through the new path and older names keep the existing one. And it should validate the model name upfront, so when it's something unrecognized I get a clear error saying which model isn't supported rather than it silently sending the wrong format. Also the model config struct should carry the model name field so it's available while building requests. This all lives in the Bedrock provider code under `@pkg/ai`, btw.
