I'm working with a Rust template engine and I want to add line-oriented template syntax to it, kind of like what Jinja2 does. Right now the syntax config builder only lets me customize the bracket-based delimiters for blocks, variables, and comments, but I can't do the cleaner script-like style where a whole line does the work. So what I'm after is two new configurable things on that builder: a line statement prefix and a line comment prefix.

The idea is if I set a hash character as the line statement prefix, then any line beginning with that character (optionally preceded by whitespace) gets treated as a block statement and should produce the exact same block tokens a normal block delimiter pair would. And if I set a double-hash string as the line comment prefix, then any occurrence of that string on a line strips everything from there to the end of the line, including the trailing newline, so it works fine as a trailing annotation too, not just at the start.

Couple of edge cases I care about: if the prefix shows up after other non-whitespace content mid-line, don't treat it as a line statement. Also line statements need to support multi-line expressions when brackets or parens are still open. Both prefixes should be configurable at the same time and actually work together in the same template. And like the existing delimiter customization, this whole thing should require the existing custom syntax feature flag to be enabled.
