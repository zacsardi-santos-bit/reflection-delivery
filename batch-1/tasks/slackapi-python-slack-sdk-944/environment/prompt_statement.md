I'm poking at the Slack SDK's audit log and SCIM (user directory) response model classes and it's driving me nuts that any field in the API response the SDK doesn't explicitly model just gets silently dropped. APIs evolve, Slack adds new fields all the time, and right now I've got no way to reach that data until the SDK ships explicit support, which makes everything feel fragile against API changes.

What I want is for these response model classes to hang onto unrecognized fields in a dedicated attribute so I can access new or unexpected data without waiting on an SDK update. For the audit log side this needs to work at every level, the top-level response object, individual log entries, and the response metadata section, each one preserving whatever unknown fields came back from the API.

Same deal for the SCIM user directory response objects, unknown fields should get captured in a dedicated attribute but with the keys stored in snake_case (standard Python naming). Oh and when I convert one of these SCIM objects back into a dictionary (to serialize it or whatever), the unknown fields need to come back out with their original camelCase key names restored so the output stays compatible with the API format. Also the existing field on SCIM user objects that already did something similar for extra attributes, that one should get renamed for consistency with this new approach. The whole point is forward-compatibility so I can actually use new API capabilities right away.
