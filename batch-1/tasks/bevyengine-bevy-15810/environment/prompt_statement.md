I'm poking at the math ops in Bevy and hitting a wall when I try to build it no_std with the alternative math backend (the libm-style path where the standard library is off). Basically the math operations module doesn't expose some of the plain floating-point helpers as standalone free functions in that config, and I really need to call them directly instead of as methods on the primitive types. In a normal std build everything's fine, but flip on no_std and drop std and it won't compile because these free functions just aren't there in the module's public surface. Under std these ops only exist as methods on f32/f64, not as free functions in the module, so no_std code that wants them can't build at all.

What I want is for the math operations module (over in `@crates/bevy_math/src/ops.rs`) to add free functions for computing an absolute value, a square root, and copying the sign from one value to another, wired up so they're available specifically when building without the standard library on the alternative backend. Same no_std build conditions apply to all three. And they should all come through when you do a glob import of the module, so pulling in everything from ops gets you abs, sqrt, and copysign alongside the rest.

The point here is folks targeting embedded or other no-std environments need these basic float ops to behave the same whether or not std is around, otherwise the module's unusable there and it blocks those targets entirely.
