I'm poking at the tablet manager in Vitess and want to fix how we verify the DBA user's database privileges during tablet startup. Right now there's a standalone function living in the tablet server package that checks whether the DBA user has the grants it needs, but the annoying part is it doesn't give anything else a way to wait until those permissions are actually confirmed. So privileged stuff like query execution and replication management can fire off before grant verification finishes, and we hit permission errors, especially during restore sequences where the ordering gets weird.

What I want is to move the grant verification logic out of the tablet server package and into the tablet manager itself, and add a signal mechanism so any operation needing elevated privileges blocks until grants have been verified. When the grant check completes successfully, or gets skipped (say the configured wait time is zero, or the tablet is externally managed), we should record a signal marking grants as applied, and skip cases should record that signal immediately. Any privileged op waits on this signal before proceeding, oh and if the caller's context expires while it's waiting it needs to return an appropriate cancellation/timeout error. Also if the DBA user doesn't pick up the required privileges within the configured wait time, the verification should return an error that clearly says how long we waited (the timeout duration).

And the old standalone function in the tablet server package should just get removed and replaced by this tablet-manager-owned approach. The whole point is killing the startup race so we stop seeing confusing permission failures when grants just weren't applied yet.
