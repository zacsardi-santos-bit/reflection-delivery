I'm working on the Cloud Foundry CLI and ran into a compatibility issue. The functions that retrieve organizations and spaces by their unique identifiers always send those identifiers as a server-side filter to the Cloud Controller API. The problem is that older versions of the Cloud Controller don't support this filter parameter at all, so when the CLI is used against an older deployment, it doesn't work correctly.

I need these functions to check the Cloud Controller API version at runtime and decide dynamically whether to use server-side filtering or do the filtering on the client side. If the server is new enough to support the filter, it should be used for efficiency. If not, the functions should fetch all records without any filter and then narrow the results locally to only include the records whose identifiers match the ones that were requested. If the API version string can't be parsed for some reason, the safe default should be client-side filtering — no error should be raised in that case.

In all scenarios, the caller should receive back only the records that match the requested identifiers, regardless of whether the filtering happened server-side or client-side.
