I'm adding encryption support to container image manifest handling in the containers/image library and hitting a bunch of gaps. Right now when I update OCI manifest layer infos with an encryption operation, nothing happens correctly, the media type doesn't get updated to mark the layer as encrypted. OCI does this by appending an encrypted marker to the layer media type, so an encryption op should set that and a decryption op should strip the marker back off. Please wire that up in the OCI layer info update path.

Docker-style formats can't represent encrypted layers at all, both the old schema1 and the current v2 schema2, so if I request encryption or decryption when updating their layer infos I want it to fail loudly with an error instead of silently proceeding with broken behavior. Add guards for both formats.

Format conversion is the other messy part. When I convert a Docker-format image to OCI and request encryption on the layers, that should succeed and produce the right encrypted media types. Converting a Docker image to another Docker format with encryption requested should fail. And if I've got an encrypted OCI image, a plain conversion to a Docker format should fail (the target can't represent encrypted layers), but it's gotta be possible to decrypt and convert in one shot, so converting an encrypted OCI image to Docker while simultaneously decrypting the layers should work.

Oh and one more thing, whatever conversion runs, the source image object itself must not be mutated as a side effect, so after a conversion with decryption the source should look exactly like it did before. Also you'll need to create test fixture files for encrypted OCI manifests to exercise this.

Without these fixes encrypted images are basically unreliable, encryption gets silently applied to formats that don't support it, encrypted images can't convert cleanly, and there's zero feedback when someone asks for an unsupported op.
