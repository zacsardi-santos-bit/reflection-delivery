I'm adding a batch authorization check feature to our API server. Right now every auth check needs its own separate request which is wasteful when a caller has to evaluate a bunch of decisions at once, so I want a batch check endpoint that takes multiple check items in one request and hands back per-item results keyed so the caller can match each result back to the check that produced it.

Each item in the batch needs a unique non-empty identifier for correlation, and the server has to validate the incoming batch before doing any work. That means rejecting empty batches (the request must contain at least one item), rejecting any batch with empty or duplicated identifiers, and rejecting batches that go over a configured max size. When it's too big the error should clearly say how many checks were received versus the maximum allowed, actual numbers in the message.

The key thing is individual check failures shouldn't blow up the whole request. Stuff like invalid relations, invalid tuples, resolution depth exceeded, evaluation failures, throttling, deadline exceeded, or generic internal errors all need to get captured as per-item errors mapped to well-defined per-item error codes rather than failing the batch. Oh and if the request context gets cancelled, each item should report the cancellation error individually while the overall request still succeeds.

Also if no authorization model is specified in the request, use the latest model, and the results should come out identical to an equivalent request that names that model explicitly. Last piece, wire the batch check operation into the existing authorization routing layer so it requires the same permissions as a regular check operation.
