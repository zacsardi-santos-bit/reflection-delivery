I'm adding a semantic syntax check to our Python parser and it's about `__debug__`, that special built-in read-only constant Python uses to signal whether it's running without optimizations. You're allowed to read its value anywhere, but Python's own compiler treats writing to it, naming things after it, or binding it in any way as a hard syntax error, and our semantic syntax checker in the ruff Python parser just lets all of that slide right now so code Python itself would reject passes clean with no diagnostic.

What I want is for the checker to catch every context where `__debug__` gets illegally bound and emit a clear error saying the name can't be assigned to. That means direct assignment, tuple unpacking, function and class definitions, function parameters, type parameters (including in type aliases), import statements that bind the name, with-statement aliases (the `as` target), exception handler names, match-statement capture patterns, and type alias names all need flagging.

Deletion is the tricky one because it's version-aware. Older Python allowed `del __debug__` but it was deprecated then fully removed, so I only want to flag deletion when the configured target Python version is new enough that the syntax was already gone. That deletion error message should name the target version and mention the release where the syntax got removed. Deleting on an older target stays valid, don't flag it.

Also reading `__debug__` as a value has to stay perfectly fine with zero errors, and imports where the identifier shows up as a source name (the module being imported from, or the thing being imported) rather than the bound name are legal too, so importing something under a different alias is fine, only the binding side matters.

Oh and there's a gap in the test setup, the semantic checker currently runs against a hard-coded default Python version instead of the one configured for the file being parsed, so version-specific checks misbehave in tests. Fix that so the configured target version actually gets passed through to the checker, otherwise the deletion diagnostics won't test correctly across versions.
