We have a set of storage and search packages for image vulnerabilities and image data that are currently nested under restricted internal directories. Because of how Go enforces directory-level import restrictions, these packages can only be imported by code within the same parent tree, which is blocking us from writing integration tests for a background process that automatically unsuppresses vulnerabilities after their suppression expiry passes.

I need to move these packages out of the restricted directories so they are accessible from anywhere in the codebase. Once that is done, I also need to update all the existing import paths that reference the old locations. The goal is that after the reorganization, an integration test can import the storage and search packages from a different part of the codebase, set up a full pipeline with a real database, run the unsuppression loop, and verify that vulnerabilities whose suppression has expired are correctly cleared.
