I'm building out CDS workflow v2 and I need the crafting phase to actually support reusable job templates, where one job in a workflow points at an external template that expands into a whole group of jobs at run time. Right now crafting doesn't handle template references at all, so even when a workflow job points to a template nothing gets instantiated and the full job graph never gets built, which means downstream jobs that were waiting on that placeholder have no valid target to wait on.

What I want is for crafting to detect when a job's definition references a template, fetch that template's job definitions, and inline them into the workflow in place of the placeholder. The tricky bit is the dependency rewiring. Template jobs that have no internal deps should automatically inherit the upstream deps of the placeholder job that referenced them, and any downstream jobs that were waiting on the placeholder should instead wait on the template's terminal jobs, meaning the ones that nothing else inside the template depends on (no successors within the template).

It also needs to handle chaining, so if one template's terminal jobs are the entry point for a second template's expansion, the whole chain gets wired correctly and the final downstream job ends up waiting on the second template's terminal jobs. Oh and if the same template gets referenced twice in one workflow, that'd produce duplicate job names, so instead of building a broken graph I want the run marked as failed with a clear message saying the conflicting job names already exist in the workflow. After everything expands cleanly the workflow run should transition to building status with the full expanded set of jobs in the workflow data.

This matters because without it teams can't share common multi-job patterns and have to manually duplicate job definitions everywhere, so this is really about genuine reuse of named job groups so complex multi-stage pipelines can be composed from templates.
