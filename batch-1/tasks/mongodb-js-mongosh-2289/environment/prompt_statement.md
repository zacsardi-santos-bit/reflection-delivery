I'm working on release tooling for our JS monorepo and I need to split package releases into two pathways, one for the main shell release packages and one for auxiliary packages that ride their own independent schedule. Right now nothing distinguishes them so I can't bump or publish just the auxiliary ones without dragging the main shell release along, and that's the whole point of this.

The publish function currently takes a bare boolean for dry run and I want it to take an options object instead so I can also pass a flag for whether we're only publishing auxiliary packages. When it's a full publish (not auxiliary-only), it should look up the version of the main "mongosh" package in the list and throw a clear error if it's not found, then after lerna finishes it should create an annotated git tag for that version and push it to the remote so downstream tools can track which commit maps to each release. In auxiliary-only mode no git tags or pushes should happen at all.

I also need two new exported functions on the bump side. One bumps only the main mongosh release packages by reading the target version from a well known environment variable (fail fast with a descriptive error if it's not set, this matches our CI conventions better than passing it as an arg). The other updates the version constant embedded in the shell API source file by reading that file, swapping the old version string for the new one, and writing it back.

Oh and the publish command invocation needs cleanup too, the flags that used to stop the tool from pushing and tagging on its own aren't needed anymore since we're doing git tags manually now. This all lays the groundwork for separate CI workflows that keep auxiliary packages current without coupling every release to the main cadence.
