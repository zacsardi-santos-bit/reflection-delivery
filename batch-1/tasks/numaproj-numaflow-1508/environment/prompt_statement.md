I'm refactoring the storage layer of the reduce pipeline's data-forwarding component and there's a few interconnected changes I want to knock out. Right now the persistent store manager is embedded inside the partition buffer queue manager instead of being passed directly to the data forwarder, which means both components can't cleanly share one instance. I want the store manager created independently and passed to the data forwarding constructor as its own separate parameter (distinct from the buffer queue manager) so both share a single instance without the awkward coupling.

The replay interface bugs me too. Currently replaying persisted messages needs a batch count upfront and hands back a slice plus an end-of-file flag, so callers have to guess batch sizes and manage looping. I'd rather replay stream messages asynchronously through a channel and close it when done, with errors coming through a separate error channel. An empty store's replay should just close its channels immediately with zero messages. Oh and the replay responsibility should move down from the buffer queue manager level to the individual store level.

Also store discovery (for crash recovery at startup) returns only partition identifiers right now, forcing extra lookups. I want it to return actual ready-to-use store instances directly so they can be replayed immediately. After creating stores, discovery returns them; after deletion it returns nothing.

Writing to the buffer queue needs a boolean flag saying whether the write should also persist to backing storage, so a regular write is persist = true and a replay write is persist = false since we don't want to re-persist during replay.

And the filesystem-backed write-ahead log implementation needs reorganizing: move its package from the old location to a new one, rename the constructor to match, and pull the sync duration and batch size fields out of the nested sub-struct so they're direct fields on the WAL object itself. Also add a dedicated constructor for opening a WAL in write-only mode given a file path and config params.
