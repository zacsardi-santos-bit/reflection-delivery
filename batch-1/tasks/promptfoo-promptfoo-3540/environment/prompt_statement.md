I'm working with Python providers in promptfoo and I'd like to be able to reference external files from the provider's configuration instead of having to inline everything. For example, I want to point to a YAML file for model settings, a JavaScript module for formatting options, or a Python script that returns configuration values dynamically. Right now there's no way to do this — everything has to be written directly in the config block.

I'd like the provider to automatically resolve these file references before the Python script runs, so the script receives the actual configuration values rather than the raw file path strings. This should work for JSON, YAML, JavaScript, Python, and text files, and it should support specifying a named function in JavaScript or Python files. References should be resolvable relative to a base path, and they should work at any nesting depth inside objects or arrays.

Additionally, the provider should call an initialization step before executing any API calls (regular, embedding, or classification), and this initialization should only run once even if the provider is called multiple times. If a referenced file can't be loaded, the initialization should fail with an appropriate error. The configuration passed to the Python script should always include a structured options object with the resolved config values — never absent or containing raw file path strings.
