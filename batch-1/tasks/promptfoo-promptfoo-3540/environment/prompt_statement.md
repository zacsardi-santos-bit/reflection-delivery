I'm working with Python providers in promptfoo and I keep hitting a wall where every config value has to be inlined directly in the config block. There's no way to point at an external file, so I can't share settings across providers or keep big configs manageable or generate values dynamically with code. I want the provider to support a file-reference URL syntax (the usual `file://` style pointing at an external file) and resolve those references to their actual content before the Python script ever runs.

This should work for JSON, YAML, JavaScript, Python, and plain text files. For JS and Python files I want to be able to name a specific function to call using a colon-separated suffix (like `file://formatter.js:getOptions`). References need to resolve relative to a configured base path, and they should work at any nesting depth, so a reference buried deep inside an object or an array should still get resolved.

Also the provider needs to call an initialization step before it does any actual work (regular API calls, embeddings, classification, all of them), and that init should only do the file resolution once even if the provider gets called a bunch of times. If a referenced file can't be loaded, init should fail with a clear error rather than silently passing through. Oh and the config that actually reaches the Python script should always carry a structured options object holding the resolved values, never missing and never still containing the raw file path strings.

The relevant provider logic lives around `@src/providers/pythonCompletion.ts`, so that's where the resolution and one-time init behavior should land.
