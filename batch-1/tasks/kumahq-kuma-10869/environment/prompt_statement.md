I'm adding fine-grained reachable backend references to our service mesh proxy config. Right now reachability only works at the level of service tag sets, but I want operators to declare which specific named backend resources a workload can reach, by kind and name, optionally by namespace, or by label selectors. Without this they're stuck either allowing all traffic (which tanks mesh performance at scale) or relying on coarse service tag matching, so this matters a lot for both perf and correctness in big deployments.

A few pieces here. First the dataplane config validator needs to validate a new list of backend references in the transparent proxy settings. Each entry can reference a backend by name (with optional namespace) or by label selectors, and the allowed kinds are the same three resource types we support elsewhere (things like individual services, external services, and multi-zone services). The validator should check that only valid kinds are used, that name and labels aren't both set at once, that namespace requires a name to be present, that either name or labels shows up, and that names are valid RFC 1123 subdomain strings.

Second, the reachability graph needs refactoring to support two separate reachability checks: the existing service-level one (tag sets identify destinations) and a new backend-level one (a specific resource kind and name identify the destination). The graph constructor should take both sets of precomputed rules. The backend-level check evaluates traffic permission policies matched against each named backend, handling allow, deny, and shadow-deny actions correctly through the existing policy rules engine.

Third, there's a new subpackage for building rules for named backends. It processes a list of mesh service resources plus traffic permission policies, matching policies to each service to figure out which sources are allowed to reach it. The matching has to filter out tags that don't apply to a given service's context, and it can't mutate the original policy objects. Oh and move the existing service-based rule-building logic into its own subpackage too, so the graph package is just the graph structure and the reachability methods.

Also the error message for an invalid backend kind in outbound references currently only lists two valid kinds, it needs updating to include the third supported resource type so configs referencing it don't get bogus errors.
