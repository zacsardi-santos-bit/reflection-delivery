I'm poking at our GraphQL language server and hitting a rough edge with missing config. When someone opens a workspace that has no GraphQL config file, or an empty one, the server just silently fails to activate and there's zero indication of why. I can't even tell from outside the processor whether init actually succeeded or whether the config is just missing. I want to fix that. The server should explicitly track and expose whether it initialized successfully and whether the config file is missing, and when there's no valid config found it needs to log a clear error saying the config file isn't available in the provided config directory (something a developer can actually read and act on). That way people troubleshooting can tell a config problem apart from a real server bug.

Separate thing while I'm in here: the logic that finds embedded GraphQL queries inside JavaScript and TypeScript source files is currently tangled into the main message processor, which makes it impossible to test on its own and honestly hard to reason about. I'd like to pull that document parsing out into its own dedicated module so it can be imported and tested in isolation. Oh and it needs to handle real-world junk gracefully, so empty files, whitespace-only files, files with unsupported extensions, and files that just can't be parsed should all return empty results instead of throwing. Same deal for files whose content produces no usable nodes (like a file that's only a comment), those should come back empty too without crashing. Basically better error visibility when config's missing, plus cleaner separation for the parsing.
