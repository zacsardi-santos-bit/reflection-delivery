I'm working on improving the GraphQL language server to handle missing configuration files better. Right now, when someone opens a project that doesn't have a GraphQL config file (or has an empty one), the server fails quietly — there's no clear error message and no way to tell from the outside whether initialization succeeded or whether the config is simply missing. I'd like the server to explicitly track this state and emit a clear diagnostic message when configuration is absent.

Also, the code that finds embedded GraphQL queries inside JavaScript and TypeScript source files is currently mixed into the main message processor, which makes it hard to test independently. I want to move this into its own dedicated module that can be imported and tested on its own. This parsing module needs to handle a range of real-world edge cases gracefully: empty files, whitespace-only files, files with unsupported extensions, and files that can't be parsed should all return empty results without throwing. Files with content that doesn't produce any usable structure (like a file that only has a comment) should also return empty results without crashing.

The goal is better error visibility for end users when their config is missing, and cleaner separation of concerns for the document parsing logic.
