I'm working on s2n-quic and need to add app-level tuning for the BBR and CUBIC congestion controllers. Right now both of them bake in fixed defaults for stuff like the initial congestion window, and BBR also has hard-coded internal values for loss detection sensitivity and how aggressively it probes for bandwidth. There's no way to tune any of this without editing the library source, which is annoying since different deployments run in wildly different network conditions.

What I want is a settings struct per controller that an application can fill in with optional overrides at construction time. When a field's set, the controller uses that value (clamped to a safe minimum), and when it's not set it just falls back to the existing default behavior, so nothing changes for code that doesn't touch the new settings. For BBR the settings should cover at least the initial congestion window, the loss threshold, and the congestion window gain used during bandwidth probing. For CUBIC I just need the initial congestion window configurable for now.

One important detail: if the provided initial congestion window is zero (or not set), fall back to the safe minimum rather than trusting the zero. Also I want the default loss threshold constant and the default congestion window gain used in bandwidth probing made public so callers can actually reference them by name instead of guessing.

The constructors for both controllers need to accept these settings, and a bunch of the internal methods need to be updated to accept and thread the settings through so the overrides actually take effect during operation, not just at init. Look at the BBR and CUBIC modules under `@quic/s2n-quic-core/src/recovery/` to wire this up. When no overrides are set, both controllers should behave exactly as they do today.
