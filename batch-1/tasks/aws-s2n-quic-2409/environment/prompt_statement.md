I'm working on the TCP stream server component and need to implement a worker manager that coordinates a fixed pool of connection handlers. The idea is that the manager holds a pre-allocated set of worker slots, each of which can handle one connection at a time. When a new connection arrives, the manager finds an available slot and assigns the connection to it. If all slots are busy, the manager should check how long each connection has been running — if any has exceeded a configurable maximum duration, the new connection should preempt the oldest overdue one. If no slot is free and none has exceeded the time limit, the insertion should be rejected.

The manager needs to drive workers asynchronously. Workers should only be polled when they signal they have work to do, not on every poll cycle. When a worker finishes handling its connection, its slot should become free and the active count should go down.

I also need a trait that worker types must implement, with associated types for the context, connection context, and stream, along with methods for being assigned a new connection, being polled for progress, reporting when it was last assigned a connection, and indicating whether it is currently active.

The pool's internal storage should keep each worker slot accessible by index and associate each slot with an async wakeup mechanism so that individual slots can be independently scheduled for re-polling. The manager should expose methods for its total capacity, the number of active slots, the maximum allowed connection duration, inserting a new connection, and polling all pending workers.
