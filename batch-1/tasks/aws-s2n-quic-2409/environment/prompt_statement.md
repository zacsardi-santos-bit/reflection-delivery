I'm building out the TCP stream server and need a worker manager that coordinates a fixed pool of connection handlers, one connection per slot. The whole point is bounding concurrency, reclaiming slots from connections that have run too long, and driving handlers without busy-polling every slot each cycle, because right now there's nothing that does any of this.

Here's how I want it to behave. The manager holds a pre-allocated set of worker slots with a fixed capacity set at construction. When a connection arrives it finds a free slot and assigns it. If everything's busy, it checks how long each connection has been running, and if any has passed a configurable maximum duration it preempts the oldest overdue one (replacing that connection without changing the active count). If no slot is free and none has exceeded the limit, the insert just gets rejected. When a worker finishes its connection its slot goes free and the active count drops.

Workers should only get polled when they signal they've got work to do, not on every poll cycle. I need a trait that worker types implement, with associated types for the context, connection context, and stream, plus methods for being assigned a new connection, being polled for progress, reporting when it was last assigned one, and saying whether it's currently active.

The pool's internal storage should keep each slot accessible by index and pair each slot with an async wakeup mechanism so individual slots can be independently scheduled for re-polling. The manager itself should expose its total capacity, the number of active slots, the max allowed connection duration, inserting a new connection, and polling all pending workers. This lives in the TCP server component so wire it in there.
