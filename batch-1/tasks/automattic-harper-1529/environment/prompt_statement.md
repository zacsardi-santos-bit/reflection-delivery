I'm building out the phrase correction side of a grammar linter (Harper) and I keep running into the same annoyance: related corrections that share one underlying pattern each need their own separate rule. Like fixing "have went" to "have gone" means I write one rule for "have went", another for "had went", another for "having went", one more for "has went", etc. Same fragmentation happens across tons of other categories, so I want a new dedicated correction module that groups related variants into single grouped rules instead of a pile of independent ones.

I want this module to cover a broad set of common writing errors. Off the top of my head: confusing "adieu" (the farewell) with "ado" (fuss) in stuff like "further adieu" or "much adieu"; the "client's side"/"server's side" thing where it should really be the hyphenated compound adjective forms; "definitive article" when they mean "definite article"; "explanation mark" vs "exclamation mark"; all the conjugated auxiliary forms of "have/had/having/has went" each correcting to the version with "gone"; the same past/passed confusion pattern; "hone in on" variants that should be "home in on"; "invest into" variants that should use "in"; a bunch of worse/worst confusions across many phrases; and other common idiom slipups.

Some of these need to offer more than one valid suggestion, oh and that's kind of the point of grouping. "a whole entire" should suggest both "a whole" and "an entire" as separate options, and "how it looks like" should give two alternatives, either drop "like" so it's "how it looks", or swap "how" for "what" giving "what it looks like". Also the corrected text has to match the capitalization of the original, so if they wrote it capitalized the fix stays capitalized.

Point is one cohesive module makes this way easier to maintain and extend, and users get consistent suggestions for every variant, not just the odd form that happened to have its own rule.
