I'm chasing down a keyboard nav bug in our popover component and could use a hand. Here's the deal: when a non-modal popover is open and someone presses Tab to move focus out of it into the rest of the page, the next Tab presses that wrap around the document (circular navigation) wrongly drop focus back inside the open popover instead of continuing naturally through the page. Same thing breaks going backward.

The root cause is that the popover's internal interactive elements stay part of the document's tab sequence even after focus has already left the popover area. So once you've tabbed past the trigger and keep going, wrapping from the last element back to the top lands you inside the popover instead of on the first element on the page like you'd expect.

What I want is for whatever component manages focus inside the popover to pull its internal elements out of the tab order when focus moves out, and restore them when focus comes back in. Also the boundary behavior needs to be right: pressing Tab on the last element inside the popover should move focus to the next element after the trigger, and Shift+Tab on the first element inside should move focus back to the trigger. And backward circular navigation from outside should still be able to re-enter the popover from its last internal element when you wrap around.

Net effect I'm after: circular forward tab wrapping from the last element goes to the first element on the page (not into the popover), backward wrapping works too and can land back inside the popover, and the whole cycle stays consistent. Right now the page is basically unusable for keyboard-only folks once a popover is visible, oh and it needs to keep working for both forward and backward directions. Thanks!
