I'm hitting a rough edge in the Scala MongoDB driver around operations that finish without giving back anything useful, think writing or uploading files to GridFS. Right now these lean on a Java void type that just doesn't feel right in Scala, subscribers get handed some empty meaningless value as the emitted item, and worse I can't chain these things in for-comprehensions or compose them with the usual monadic ops. It's a common friction point and people end up writing boilerplate workarounds just to react to a write completing.

What I want is an adapter that wraps these void-returning reactive publishers so they emit exactly one Scala unit value and then signal completion, basically making it behave like a single-element observable even when the underlying publisher emits no items at all. If the underlying publisher signals an error though, the adapter should just propagate that error straight through without emitting any items and without signaling completion. Oh and it needs to honor backpressure, so a subscriber that explicitly requests one item still gets the unit.

For GridFS uploads specifically there's an extra wrinkle, that publisher exposes file identifier accessors and the adapter needs to delegate those through so the method sets line up. Also please update the existing GridFS upload observable wrapper so it works against this new unit-emitting type instead of the old Java void-based one, keeping their interfaces aligned. End goal is these become first-class Scala observables that drop naturally into for-comprehensions.
