I'm building dashboards with the Perses Dashboard-as-Code SDKs and hitting a real problem with multi-select variables. Both SDKs have this utility that auto-generates PromQL label filter expressions from template variables, but it emits exact match operators. That's fine when a user picks one value, but the moment they select multiple values from a list variable, those get joined into a combined pattern that only works with regex matching, so the auto-generated queries break silently. No error, just invalid PromQL for any multi-value selection, which basically kills a core piece of dashboard interactivity for anything authored through the SDK.

What I want is for the filter auto-generation to use the regex match operator instead of the exact equality operator when it builds label matchers for template variables, and this needs to cover both text variables and list variables. On the Go side that means the variable builders that apply filters to their metric selectors, specifically the label-names and label-values builders. On the CUE side it's the filter composition utility that stitches together the matchers. Same behavior in both, just swap equality for regex.

Oh and separately, I'd like the example dashboard definitions updated to show how panel builders can take an optional aggregation grouping parameter, so the same panel template can be reused with or without a grouping clause depending on the context you instantiate it in. Makes the panel definitions way more flexible and reusable.
