I'm working on the batch matrix multiplication components in a GPU linear algebra library. Right now, the two batch-level matmul types each have a fixed number of type parameters and always use the same mapping from the launch grid's axes to the matrix dimensions: x always means rows, y always means columns, and z always means batches. This is fine for many cases, but it means I can't use a transposed grid layout (where x and y are swapped) or a swizzled traversal pattern that improves cache efficiency.

I want to add a pluggable dispatch abstraction that controls how the launch grid's cube positions are translated into matrix coordinates. There should be at least four concrete variants: a natural mapping, a transposed mapping (x and y swapped), and two swizzled variants (one that prioritizes the x-axis and one that prioritizes the y-axis), each parameterized by a swizzle width constant. All of these must produce correct numerical results for the matrix multiplication.

The batch matmul types need to be updated to accept the dispatch strategy as a new generic type parameter. All existing code that uses these types should continue to work by passing the natural dispatch strategy explicitly. The new dispatch types should be publicly exported from the batch module alongside the existing span types.
