I'm hitting a reactivity bug in the SolidJS output from our cross-framework component compiler, the thing that takes component definitions and spits out code for various target frameworks. Two related situations aren't wiring up correctly.

First, when a component has computed or derived state, the getter-style stuff that reads from other state values and derives a result, the generator emits these as plain function declarations. That's wrong for SolidJS. Its fine-grained reactivity needs these wrapped in a memoized reactive computation (createMemo) so the runtime tracks dependencies and notifies subscribers when the derived value actually changes. So I want getter-type state properties emitted as memoized computations instead of plain functions.

Second, when a component specifies a reactive effect that should only re-run when certain values change, the dependency expressions get handed straight into the effect tracking call as raw expressions. SolidJS wants each dependency in that list to be a stable memoized computation, not a raw expression, otherwise the change tracking may not fire. So each dependency in a reactive update hook should get extracted into a named intermediate memoized variable declared before the hook handler function, and the effect references those intermediate variables instead of the original expressions.

Both of these mean the memoization primitive isn't currently in the SolidJS import list even though it's now needed, so please add it to the imports for any component that has signal-based state or reactive update hooks. The fix lives in the SolidJS generator. Right now this can cause components to silently fail to update when their derived state or effect deps change, which leads to stale UI and annoying subtle bugs in production.
