I'm refactoring the coin management commands in the Chia blockchain CLI, the ones for listing, combining, and splitting coins, and right now they bypass the shared command framework and just hit the wallet RPC layer directly. Because of that they don't check whether the wallet is synced before acting and they crash instead of printing something friendly when a wallet ID doesn't exist. I want them built on the class-based transaction command base class so they behave like the other wallet commands, meaning when a wallet ID can't be found they print a user-friendly not-found message, and when the wallet isn't synced they print a message asking the user to wait rather than proceeding blindly.

Part of this is introducing new shared classes in the command class module that commands can embed to declare config needs, one for coin selection settings, one for full transaction configuration covering fees, push behavior, and timelocks, plus timelock parameters, all mapping cleanly to CLI options. There also needs to be a decorator that must be applied to the run method of any command extending the transaction endpoint base class, and instantiating such a command without it should raise a clear error at instantiation time.

Oh and the transaction file reader and writer classes currently live in the signer command module, move those into the shared command class module so other commands can reuse them, and rename their CLI flags from the short single-letter abbreviations to full descriptive names for input and output.

The listing command should support showing unconfirmed coins separately and optional pagination (5 coins per page, 'c' to continue and 'q' to quit), and print each coin's identifier and its amount in the smallest unit. Combine and split should require the user to confirm before sending and output appropriate messages when something goes wrong or when no transactions get produced. Also add a constant and a helper method in the test environment to easily build default and per-environment arguments for any transaction endpoint command. It's about making the whole CLI consistent and approachable.
