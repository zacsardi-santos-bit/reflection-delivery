I'm using the OpenAI Python client's newer Responses API in my app and none of those calls show up in my traces. The existing OpenTelemetry instrumentation for OpenAI only covers the older chat completions endpoint, so when I send a message or retrieve a response through the Responses API, no spans get created at all. It's a real gap in observability, developers on this thing have zero visibility into these requests, can't monitor or debug or analyze anything going through that endpoint.

I want the instrumentation to cover the Responses API with the same level of detail it already gives the completions API. So each API call should create a span that captures the system name, the requested model from the request plus the actual model version that comes back in the response. Input prompts need to be recorded whether the input is a plain text string or a structured list of conversation messages, and for multi-turn inputs each message in the list should be recorded with its index, role, and content (JSON-encode the complex content structures). The text output should land on the span as a completion.

Also when the request includes tool or function definitions I want those captured, function names, descriptions, and parameter schemas, and when the model responds with a tool call, record the call name, arguments, and its identifier on the span, plus store the overall response identifier from the API too. Basically bring this new endpoint to parity with what's already there.
