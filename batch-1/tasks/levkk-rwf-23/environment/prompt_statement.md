I'm building out a small Rust web framework and hit a wall with form parsing. Right now the request form data method only knows how to deal with URL-encoded bodies, so when a browser posts a form with a file input or someone sets the enctype to multipart explicitly, the content type comes in as multipart with a boundary param in the header and my form data call either blows up or just hands back nothing, which means I can't read any of the submitted fields at all. That's a real gap since multipart is what browsers use for anything with file uploads or mixed content.

What I want is to extend the existing form handling so it notices when the content type is multipart, pulls the boundary string out of the content type header, and uses it to split the body into parts. Each part in the standard format starts with a content disposition header naming the field, then a blank line, then the actual field value, and the whole thing wraps up with a closing boundary marker at the end. I need it to walk that structure correctly and make each field reachable by its name.

The important bit is that named text fields should come back as typed values through the same generic field accessor that URL-encoded forms already use today, so reading a multipart field feels identical to reading a URL-encoded one, no separate API. Btw keep it consistent with how the current form data path works so it's just a natural extension rather than a bolt-on.
