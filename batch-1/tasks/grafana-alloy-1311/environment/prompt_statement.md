I'm building out a dedicated peer discovery component for the cluster service in Grafana Alloy, over in the cluster code, because right now there's no clean testable abstraction for how peers get found when forming or joining a cluster and I need one that supports a few different strategies. Alloy keeps getting deployed in clustered setups across different infra providers so I want operators to get clear feedback on misconfig and predictable address resolution whether peers are static, DNS, or cloud-provider based.

The component takes a config with a list of static peer addresses, an optional cloud-provider discovery string, and a default port to use when addresses don't include one. It's gotta validate that config at creation time and return an informative error if a required dependency like a logger or tracer is missing, or if two mutually exclusive options (static list plus cloud discovery) are both set.

When discovery actually runs, here's the behavior I need. Static entries already in host:port form come back as-is, no lookup. Plain IP addresses without a port get the default port appended. Bare hostnames that aren't IPs and aren't host:port get resolved via DNS SRV records, and all the resulting addresses should use the configured default port, not whatever port the SRV record advertises. If every SRV lookup across all the hostnames comes back empty, return an error. But if some SRV lookups fail while others succeed, just return the successful results without erroring out.

Also cloud provider discovery (AWS, GCE, that kind of thing) needs to work through a pluggable factory function that creates the underlying provider client. Addresses the provider hands back keep their port if one's included, otherwise fall back to the default port. Oh and errors from the cloud provider lookup, or an unknown provider name, should surface straight to the caller, don't swallow them.
