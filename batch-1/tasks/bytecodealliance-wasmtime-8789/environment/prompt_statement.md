We've got a bunch of WebAssembly function-calling tests that only exercise the default compiler backend, and there's this separate standalone file where we've hand-copied a small subset of them so the alternative backend gets some coverage too. It's tedious and always drifting out of sync, plus any regression in the alternative backend just goes unnoticed for every scenario we didn't bother duplicating. I want to fix the duplication and the coverage gap in one go.

The plan is to lean on our shared test annotation macro so that any test marked with it automatically generates and runs a separate variant per supported compilation strategy (one variant per backend, basically), instead of us writing per-backend copies by hand. A lot of these function-calling tests also need particular WebAssembly features turned on, and right now they do that inline in the test body which is noisy. I'd rather the macro accept a declarative attribute where you just say which WebAssembly features the test needs, and then the framework handles enabling them for you. Oh and when a test declares required features, the macro should only spin up variants for backends that actually support those features, skipping the ones that don't so we don't get bogus failures.

So: convert the existing function-calling tests over to that shared annotation with the feature-flag attribute where needed, extend the annotation macro itself to support this declarative feature syntax and the per-backend variant generation, and once that's in place go delete the now-redundant alternative-backend duplicates from the standalone file since they'll be covered by the general suite. Basically every new test should just get cross-backend coverage for free after this.
