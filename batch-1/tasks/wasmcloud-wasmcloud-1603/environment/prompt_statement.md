I'm working on a wRPC transport library in Rust and I'm tired of hand-writing encode/decode impls for every custom type I want to send over the wire. Right now if I've got a struct or an enum that needs to cross the transport boundary I have to manually implement the encoding and decoding traits, and it's tedious and super error-prone, especially with optional fields or lists where I keep getting field order or the optional-vs-required encoding wrong. I want a derive macro approach instead so I can just annotate my types and get correct serialization for free.

What I need is a new crate that provides derive macros for the wRPC transport encoding and decoding traits, and it should plug into the existing transport traits so derived types work right alongside the ones I've implemented by hand. For structs I need fields that can be plain values (integers, strings), optional values, and lists of values. For enums I need the whole range: unit variants that carry no data, tuple-style variants with positional unnamed fields, and struct-style variants with named fields, plus enums that mix those variant shapes in one type.

The thing I really care about is roundtrip correctness. Anything I encode has to decode back to exactly the same value, no data loss. And oh, the decode has to consume exactly the bytes that were encoded, no leftover unconsumed bytes hanging around, so the encoding stays compact and exact. Without this every new type is a pile of boilerplate that slows me down and invites bugs, so getting the derive right is the whole point.
