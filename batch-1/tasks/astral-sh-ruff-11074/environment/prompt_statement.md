I'm working with a Python linter and found a case where the rule for detecting missing explicit return statements doesn't catch an important pattern. When a function has an if/else structure where the if branch returns a value, but the else branch uses a context manager block that doesn't have an explicit return at the end, the linter should flag that function — but it doesn't. The function implicitly returns nothing in that branch, which is exactly what the rule is supposed to warn about. I'd expect the lint rule to emit a diagnostic pointing to the last statement inside the context manager block, and to suggest adding an explicit return there as a fix.
