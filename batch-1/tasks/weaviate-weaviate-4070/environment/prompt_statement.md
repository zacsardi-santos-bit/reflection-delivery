I'm cleaning up the cloud cluster transport layer and hit a few things I want fixed together. First off there's a helper that grabs a free TCP port sitting inside a test file in one package, and now the transport layer tests need it too, so instead of copy pasting it I want it moved into a shared utility package where anything can import it.

Second, the gRPC server component got renamed from some internal type a while back but the actual code and its constructor never caught up, so the naming is stale and confusing. Please make the type and its constructor use the consistent updated name.

Third, the client methods that wrap address resolution and connection dialing just return bare errors right now with zero context, so when join, notify, remove, or apply blow up a caller can't tell whether resolution failed or the dial failed. I want those errors to clearly say which step went wrong, resolution vs dialing, so they're distinguishable.

Finally the server component has no tests at all, which means the error paths are totally uncovered. I'd like tests that start the server with an empty address (should fail with a clear error), start with an invalid address (should fail with a network error), and exercise the full request/response cycle for join, notify, remove, and apply, checking that specific internal conditions like store not open, leader not found, and not the leader get mapped to the right gRPC status codes so clients get structured errors back. Also want tests for the address resolver that computes the RPC port from a raft address, covering both the fixed-port mode and the increment-by-one mode plus their error cases for invalid input. Without this stuff debugging cluster comms is a pain since failures from different modes look identical, and centralizing the port helper kills the duplication too.
