I'd like to add a new lint rule to the correctness category that enforces symbol-level visibility annotations in JavaScript and TypeScript projects. Right now, developers can annotate their exports with documentation comments to signal that a symbol should only be accessible within the same folder, or is entirely private, but the linter doesn't enforce any of this. I want a rule that actually reads those annotations and raises a diagnostic whenever an import violates the declared visibility.

The rule should understand three levels of visibility based on documentation comment annotations: private symbols that cannot be imported by any other file at all, package-scoped symbols that can only be imported from within the same directory, and public symbols that can be imported from anywhere. The rule should also support a configuration option to set a default visibility for symbols that don't have any annotation, which lets teams opt an entire project into stricter access control without annotating every export.

There are a few nuances I want the rule to get right. When a package-scoped symbol is re-exported through a directory's index file, that re-export should be considered as intentionally widening the scope — importing via the index file path should be allowed from the parent level. Likewise, within a folder, importing a private symbol from the same folder's own index file should be allowed. The rule also needs to cover default imports and combined imports, not just named imports. And an explicit annotation on a symbol should always win over the configured default, whether the annotation is stricter or more permissive.

The diagnostic messages should clearly state whether the violation is due to private or package visibility, indicate that the developer may need to use an alternative symbol or relax the visibility, and tell them which file the symbol was actually defined in.

Additionally, an older experimental rule in the nursery category that served a similar but much simpler purpose should be removed as part of this work, since the new rule supersedes it.
