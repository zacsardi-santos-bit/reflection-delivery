I'm adding DigiTrust support to our prebid server and there's a gap I keep hitting. DigiTrust is that privacy/identity consent protocol in programmatic ads where the user carries a preference value telling us whether they've agreed to being identified/tracked. Right now our auction endpoint doesn't look at these signals at all, so if a bid request shows up with a DigiTrust object where the preference is non-zero (meaning they opted out), we just pass it straight through and never raise an error. That's bad, it could forward identity data for users who said no.

What I want is validation in the auction endpoint's user checking logic so a request with a non-zero DigiTrust preference gets rejected with an error before the auction runs. But if there's no user, no user ext, or the preference is zero (consenting), it should sail through fine with no error. So zero is good, anything else is a reject.

Also the Rubicon bidder adapter doesn't currently forward DigiTrust identity data downstream. When an incoming bid request has a DigiTrust object sitting in the user extension, the adapter should pass that along to Rubicon's endpoint so Rubicon can honor the privacy preference too and we keep the whole signal chain intact end to end.

Can you do both? The consent validation at the auction entry point (reject non-zero pref, accept zero or missing), and the DigiTrust pass-through in the Rubicon adapter.
