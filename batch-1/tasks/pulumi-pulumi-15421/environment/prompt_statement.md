I'm hitting a wall with Pulumi's Node.js dependency install when my project lives inside a monorepo set up with npm or yarn workspaces. When I run the install through Pulumi it doesn't notice the workspace at all, it just installs from my project's own subdirectory instead of the workspace root, so local packages from sibling workspace members can't be resolved and my program blows up at runtime. Monorepos with npm/yarn workspaces are super common for sharing code across packages, so this basically makes Pulumi unusable for anyone whose infra code imports from a sibling member.

What I want is for the Node.js install logic (over in `@sdk/nodejs`, wherever the dependency installation runs) to detect when a project is part of a workspace and install from the workspace root instead. It needs to handle both npm workspaces and yarn workspaces, including yarn's nohoist option, so a nohoist config still installs correctly.

The detection should walk up the directory tree from a given project path looking for a workspace root, and actually check that my project is listed as a member. Here's the tricky edge case: if there's a parent dir with workspace config but my project isn't listed as a member, don't treat it as part of the workspace, just install from the project directory like normal. And if no workspace membership turns up anywhere as it walks up, it should signal that with a distinguishable error (something the caller can recognize and match on) so the install path can fall back to regular behavior without erroring out. When there's genuinely no workspace, install should keep working exactly like before.
