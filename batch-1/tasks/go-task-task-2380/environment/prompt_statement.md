I'm working on the go-task/task codebase and need to make two improvements.

First, the function that searches for a task definition file currently returns both the resolved file path and a working directory together. I want to separate these: the search function should return only the resolved file path, and a new helper function should be responsible for computing the working directory from the original inputs (the unresolved entrypoint, the resolved file path, and an optional explicit directory hint). When both the original entrypoint and the directory hint are provided, the helper should resolve the directory hint to an absolute path. Otherwise, it should derive the directory from the parent of the resolved file path.

Second, I need a new top-level function for loading and merging user configuration from multiple filesystem locations. The function takes a working directory and should: check for a global configuration file under the XDG config home directory (as indicated by the standard XDG base directory environment variable), walk up the directory tree from the given directory collecting any configuration files it finds along the way, and then merge everything together so that more local configurations take priority over more global ones. When multiple configurations define the same setting, the most local file wins; settings only present in more global files should still be included. If no configuration files exist anywhere, the function should return nothing without reporting an error.
