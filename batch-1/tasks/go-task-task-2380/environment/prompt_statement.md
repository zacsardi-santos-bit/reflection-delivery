I'm hacking on the go-task/task codebase and hit two things I want to clean up. First, the function that hunts for a task definition file is doing too much, it currently returns both the resolved file path AND a working directory bundled together, and that's making edge cases annoying to handle. I want to split those concerns apart so the search function just returns the resolved file path and nothing else. Then add a separate helper that computes the working directory from the original inputs, meaning the unresolved entrypoint, the resolved file path, and an optional explicit directory hint. Logic there: when both the original entrypoint and the dir hint are given, resolve that dir hint to an absolute path, otherwise derive the directory from the parent of the resolved file path.

Second thing, config loading. Right now Task only reads config from a single spot but people want global defaults that projects can override. So I need a new top-level function that takes a working dir and pulls config from multiple filesystem locations, then merges them local-first. It should check for a global config file under the XDG config home dir (via the standard XDG base directory env var), walk up the directory tree from the given dir collecting any config files it finds, and merge everything so more local configs beat more global ones. When two files define the same setting the most local wins, but settings that only show up in a more global file still get included. And if there just aren't any config files anywhere, return nothing cleanly, no error. Project-level overrides home dir which overrides the XDG global, that's the priority chain.
