I'm adding AWS edge infrastructure support (think Local Zones) to our Kubernetes cluster provider and right now the whole thing is zone-type blind. When someone puts subnets from both regular availability zones and edge locations into their cluster network config, we treat them all the same, which breaks stuff. Edge-zone subnets end up getting picked for core infra that can't use them (load balancers, NAT gateways, control plane nodes) and routing for private edge-zone subnets is wrong because those zones can't host their own NAT gateways.

What I want is for us to query AWS for each subnet's zone type (standard AZ vs edge location) and its parent zone, and record that on the subnet object. Then the methods that hand back subnet IDs for core infrastructure need to exclude edge-zone subnets, and I want a separate method to grab all subnet IDs across every zone type for the cases where I do need the edge ones. Same deal for the public/private visibility filtering, edge subnets should drop out of the results used for core infra.

For routing, private subnets in edge zones should route through the NAT gateway in their parent AZ, or fall back to the first available NAT gateway if that's not around, instead of expecting a dedicated one in the edge zone. Public and private IPv4 edge subnets should still get their routes to the internet gateway and NAT gateway respectively. IPv6 in edge zones isn't supported though, so that should fail loud with a clear error. Oh and when we create subnets in a managed VPC, edge-zone subnets shouldn't get the load balancer role tags (the ones that make the cloud provider select them for LB creation), and trying to create an IPv6 subnet in an edge zone needs to fail with an informative error too. Also if we can't retrieve the zone type info for a subnet, the reconciliation should just fail with a sensible error message rather than guessing. This all lives in the AWS provider subnet and route reconciliation code. The point is operators can finally span a cluster across both normal AZs and Local Zones without silently misrouting traffic or grabbing the wrong infrastructure.
