I'm working on improving the docstring linter's section detection logic. Currently, if a developer writes a section header in all-lowercase — like "returns:" instead of "Returns:" — and that section appears after a blank line in the docstring, the linter completely ignores it as a section. It treats it as a subsection instead, so none of the section-related lint rules apply to it. The capitalization warning never fires, and neither do other checks like "missing blank line after last section."

The fix should make the linter recognize a lowercase section keyword followed by a colon as a proper section header when it appears after an empty line, rather than silently treating it as a subsection. Once recognized, all the normal section rules should apply to it — including flagging the improper capitalization. The existing behavior for true subsections (those that appear directly below another section's content, not after an empty line) should be preserved.

I also need the snapshot files that store expected linter output to be updated to reflect both the new violations reported for the lowercase section header, and the shifted line numbers that result from adding the new test case to the fixture file.
