I'm working on the zkSync commitment generator and I need a way to derive the events queue directly from the raw VM events stored in the database, rather than always reading it from a separate dedicated table. Right now there's no function for this conversion, but we need one so we can eventually verify — and later replace — the stored events queue.

The conversion has a specific encoding: each VM event maps to one or more log query records. The first record is a header that encodes the number of indexed topics, the length of the event's data value, and the event's contract address. Subsequent records carry the actual topic and value data, packed in pairs of 32-byte words. Events can have anywhere from one to four indexed topics, and the data value can span multiple records or be as short as a single byte (which should be padded to 32 bytes).

I need to add this conversion function to the event types module. To support it, the event module also needs to be reorganized from a single file into a directory module with a separate test submodule. The tests for the new function load their expected inputs and outputs from JSON test vector files, so those files need to be created alongside the implementation with the correct input events and their expected log query outputs.
