I'm building an operator that manages a static pod (think kube-apiserver) on Kubernetes nodes, and I keep hitting a gap when rolling out a new revision. Right now there's no automated way to get the config resources onto disk, so the certs and config files that live as secrets and configmaps have to be copied by hand or they're just missing when the pod starts, which is obviously terrible for revision-controlled rollouts.

What I want is a content-copying mechanism in the installer subpackage of the operator that, given a namespace, a deployment revision ID, lists of secret name prefixes and configmap name prefixes, a resource directory, and a pod manifest directory, pulls each resource down from the Kubernetes API and writes it out to the local filesystem in the right layout. The resource names follow a convention where you concatenate the prefix with the revision identifier, so it fetches each one by that combined name.

For layout, secret contents should land in a structured directory under the resource directory organized by resource type and resource name, and configmaps go into their own correct subdirectory the same way. Oh and the pod manifest itself lives in a dedicated configmap, and that one's special, it needs to get written both into the versioned resource directory and also into the pod manifest directory where the static pod manager picks it up at startup. So the pod can actually consume everything when it comes up.
