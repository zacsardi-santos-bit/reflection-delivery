## Description

The checksum verification tools have several bugs and missing behaviors that need to be fixed to match standard GNU coreutils behavior.

## Issues

**Error output routing:** When a file listed in a checksum file doesn't exist, the "file not found" error message is currently printed to standard output alongside verification results. It should go to standard error, so that scripts can cleanly separate errors from check results.

**Asterisk (binary mode) handling:** The interpretation of the asterisk prefix in checksum lines depends on the separator style. With a single-space separator, the asterisk should be treated as a binary-mode indicator and stripped from the filename. With a double-space separator (the standard format), the asterisk should be treated as part of the literal filename. Currently these cases are not handled correctly.

**Single-space separator:** Checksum files that use a single space (rather than two) as the separator between hash and filename should be accepted. This is supported by GNU coreutils and many existing checksum files use this format.

**Directory error:** When a checksum file references a directory instead of a regular file, the tool should fail and report an appropriate error to standard error rather than silently misbehaving.

**Wrong algorithm type:** When a tool (e.g. md5sum) tries to verify a checksum file generated by a different algorithm (e.g. SHA1), it should report that no properly formatted checksum lines were found, not warn about improperly formatted lines.

**Status and quiet modes:** The status flag should suppress all output on a successful check. The quiet flag should suppress success output but still show failures.

**Incomplete checksum entries:** A checksum file containing a partially written or truncated entry should cause the tool to report no properly formatted lines found.

## Expected Behavior

- File-not-found errors appear on stderr, not stdout
- Single-space separator format is accepted
- Asterisk stripping depends on separator width (one space = strip, two spaces = literal filename)
- Attempting to verify a directory causes a clear error message on stderr
- Mismatched algorithm types produce a clear "no properly formatted checksum lines found" error
- Status mode produces no output on success
- Quiet mode shows failures but suppresses successes
