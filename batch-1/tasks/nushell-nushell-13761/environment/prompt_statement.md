I'm working with the derive macros in the nushell codebase that automatically implement value conversion for Rust types. I'd like to add support for renaming individual struct fields and enum variants using a per-member attribute, so that developers can specify a custom string key for a specific field or variant without affecting all the others.

Beyond the new rename feature, there are some existing issues I need to fix. Right now, when an unrecognized attribute argument is placed on a named struct field or an enum variant, the macro reports the wrong kind of error — it should report an "unexpected attribute" error, not the "invalid attribute position" error that is reserved for cases where an attribute appears in a structurally invalid location (like on a field of a tuple struct). These two situations need to be clearly distinguished.

I also need the macro to detect naming conflicts at derive time. If two struct fields or two enum variants end up resolving to the same string key — for example, because one field was explicitly renamed to match the natural name of another field — the macro should return a "non-unique name" error rather than silently generating incorrect code. This conflict detection must work for both structs and enums, and must account for the interaction between per-member renaming and the default case conversion that applies when no rename is specified.
