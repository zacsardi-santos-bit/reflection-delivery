I'm hacking on the derive macros in the nushell codebase, the ones that auto-generate value conversion so Rust types can go to and from Nushell values. Right now the only renaming knob is at the container level, where you pick a case conversion and it hits every field or variant at once. I want a per-member rename attribute so I can give one specific struct field or one enum variant a custom string key without touching the rest, same idea as what serde and friends let you do. So if a field's Rust name doesn't line up with the Nushell record key I want, I don't have to restructure the type or write manual conversion glue.

While I'm in there, couple of existing bugs bug me. When someone puts an unrecognized attribute argument on a named struct field or an enum variant, the macro currently spits out the wrong error, it's reporting the invalid attribute position error which should really be reserved for when an attribute shows up somewhere structurally bogus like on a positional field of a tuple struct. In that unrecognized-key case on a named field or variant I want it to report the unexpected attribute error instead, and keep those two categories cleanly separated (tuple struct unnamed fields still get the invalid position one).

Also, actually the bigger correctness thing, there's no duplicate-name detection at all. If two fields or two variants end up resolving to the same string key, maybe because I explicitly renamed one to collide with another's natural name, or through case conversion, or some combo of rename plus the default case conversion that kicks in when no rename is given, the macro just silently generates broken code. I want it to catch that at derive time and return a non-unique name error instead. This needs to work for both structs and enums, and it's gotta account for the interaction between the per-member rename and the default case conversion. Without this you get subtle runtime collisions, so I'd rather it fail loudly at compile time.
