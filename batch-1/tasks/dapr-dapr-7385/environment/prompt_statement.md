I've been banging my head against the Dapr workflow engine and I think child workflows (sub-orchestrations) are just broken on the actor-based backend. Here's the setup: I've got a parent workflow that gets some input, hands that same input off to a child workflow by name, awaits the child, and then returns whatever the child produced as its own result. Simple delegation pattern. But it never completes, the parent just hangs or fails instead of getting the child's output back to me.

This is the whole point of composing workflows out of smaller reusable pieces, a root workflow receiving input should be able to invoke a nested child, wait for it to finish, and use the child's return value. Right now I can't do hierarchical composition at all so everything has to be flattened into one giant workflow, which defeats the purpose.

What I want is for a parent to invoke a child by name and pass input, the child receives that input, runs its logic, returns a result, and the parent picks up that output and returns it. The whole nested run should finish within a reasonable timeout, not hang. Oh and it needs to handle Unicode text in the input correctly too, so non-ASCII characters pass through and show up intact in the final output. Please dig into the actor backend and make sub-orchestrations actually work end to end.
