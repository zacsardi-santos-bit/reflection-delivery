I'm building out a CLI library that handles positional arguments, and honestly the type system feels half-finished. Right now I can only define positional args backed by 64-bit integers, there's nothing for plain `int` or the unsigned variants at any width, so I want the whole family filled in, signed and unsigned integers in all sizes, plus floats, strings, and timestamps. Each of those should come in two flavors, a single-value type that captures exactly one value and a multi-value type that captures a variable number.

The current base type is doing double duty for both cases using min and max count fields, which gets confusing fast, so I want to split that into two distinct base types, one for the single value case and one for the slice case. Also the multi-value types store their parsed results in a field whose name doesn't line up with what flags and the single-value arg types use elsewhere, so make that a pointer to a slice with a consistent name matching the existing convention.

Last thing, I'd love a type-safe way to pull a positional arg's parsed value straight off the command by name, like calling an accessor method with the arg name and getting back the right Go type directly, same ergonomic pattern flags already have. When the name isn't found or the type doesn't match, give me the zero value for scalars and nil for slices. Oh and when an arg got parsed but received no values, the slice accessor should hand back an empty non-nil slice, not nil. Basically I want the arg system to feel as complete as the flag system.
