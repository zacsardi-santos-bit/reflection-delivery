I'm working on the Prowler cloud security API and I want to add a new endpoint under the findings resource that gives back a quick summary of which cloud services and regions are actually affected by findings. Right now if a dashboard wants to know the scope of impacted services and regions it has to pull down every finding and process them one by one, which is slow and honestly wasteful, so I want something that just returns the distinct set directly.

The endpoint should support filtering by date and by severity, and it returns two lists, the distinct services and the distinct regions, from only the findings that match whatever filters were passed. So if I add a severity filter on top of a date, the services and regions I get back should reflect just the findings matching both.

A couple edge cases I care about, when no findings match the filters (like when I filter for a date way out in the future) I want empty lists back for both services and regions, not an error. And when someone passes an invalid date as the filter value, it should reject the request with a clear validation error message calling out the date format problem, don't just silently ignore the bad input.

This lives in the findings part of the API app (see `@api/src/backend/api/`), and it's basically so dashboards and reporting tools can summarize impact by date and severity without paging through the whole findings list.
