I'm chasing a flicker bug in Recharts scatter charts. When I swap the data key or point the scatter at a different dataset, I get a quick flash of wrong scatter point positions before the correct ones settle in. It looks like the point computation kicks off with the new props before the chart's internal registration state has caught up, so for one render the settings I passed in don't line up with what the chart actually has registered as a graphical item.

What I want is for the selector that computes scatter points (over in `@src/state/selectors/scatterSelectors.ts`, the one that builds the points off the scatter's settings and data) to hold off until things are in sync. On that very first render, before the scatter component has registered itself in chart state, the selector should return undefined, no points yet, nothing to draw. Only once the chart state confirms the scatter's current settings, meaning both the data key and the data reference match a registered graphical item, should it go ahead and compute and hand back the actual points. That way the chart only paints data when everything agrees, and there's no jarring intermediate frame of misplaced dots.

Also the points it computes should stay stable across re-renders when nothing about the config has actually changed, so I'm not recomputing or reshuffling on every tick. Basically: don't compute early, don't return bad intermediate results, and once we're synced the correct points show up and stick.
