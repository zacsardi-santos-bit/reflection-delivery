I'm working with Certificate Transparency pre-certificates and have a function that builds the to-be-signed (TBS) certificate data from a pre-certificate's raw TBS bytes. Currently the function is too restrictive — it fails whenever the pre-certificate or the pre-issuer certificate is missing an Authority Key Identifier (AKI) extension, even though this is a valid scenario.

I need the function to handle all combinations of AKI presence and absence. Specifically: if both the pre-certificate and pre-issuer have an AKI, the result should use the pre-issuer's AKI value. If the pre-certificate has an AKI but the pre-issuer doesn't, the AKI should be removed from the result. If the pre-certificate has no AKI but the pre-issuer does, the AKI should be added to the result using the pre-issuer's value. If neither has an AKI, the result should simply have no AKI. The function should also continue to correctly handle the case where no pre-issuer is provided at all, returning the TBS with the original AKI unchanged. An error should still be returned if a pre-issuer is provided but lacks the required Certificate Transparency extended key usage. The returned bytes must always be valid parseable TBS data with no trailing content, and the CT poison extension must be stripped from the result.
