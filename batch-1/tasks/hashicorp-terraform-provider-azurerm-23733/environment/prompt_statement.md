I'm working with Azure NetApp Files in Terraform and the provider just doesn't support customer-managed key encryption yet, so all my data is silently encrypted with Microsoft-managed keys and I've got no way to bring my own Key Vault key or say which identity accesses it. I need to fix that. First off I need to assign a managed identity to a NetApp account, both system-assigned and user-assigned, and I want to update the identity type after creation, not just at first apply. And I need to read that identity info back (type and principal ID) from both the account resource and its data source.

Then the actual encryption piece: give me a dedicated resource for managing the CMK encryption settings of a NetApp account that associates the account with a Key Vault key using either a system-assigned or user-assigned managed identity, and it's gotta be updatable so I can rotate to a new key later without destroying the account. Also a matching data source to read the current encryption settings back.

On volumes, I need to specify the encryption key source (customer-managed vs Microsoft-managed) plus a private endpoint to reach the vault securely, and the volume's data source should expose that key source so operators can verify what's configured. Oh and snapshot directory visibility, right now only hiding it works but I want to explicitly turn visibility on or off.

Last thing, the provider should validate NetApp account resource IDs properly, catching malformed stuff like missing path segments or wrong-cased paths so misconfigurations get caught early before any API calls fire. This is really about organizations with strict data security needs who have to control their own keys for compliance, and it brings us up to parity with what the Azure NetApp Files API already does.
