I'm adding monitoring links to the EMR Serverless job operator in Airflow because right now when a serverless job starts there's nothing clickable in the task details to get people to logs or the app UI, and it's annoying to have to manually grab job IDs and hand-build AWS console URLs. What I want is for the operator to auto-generate links based on whatever logging destinations the job is configured for. So if the job sends logs to S3, there should be a link that drops you straight into the right S3 console location filtered to that specific job run's output, and if CloudWatch logging is enabled, a link that points at the filtered CloudWatch log stream for that run. Both of those show up automatically, no extra config from the user.

Then there's an opt-in piece: one-time live dashboard links, one for the Spark or Tez application UI, and (only for Spark jobs) one for the Spark driver stdout logs. These need to default to off since they're ephemeral and anyone with DAG access can hit them, so users turn them on by passing a flag when they construct the operator. Generating the dashboard and log links means calling out to an AWS API to fetch a temporary authenticated URL, so the helper doing that should take either an existing client object or an AWS connection ID, not both and not neither, and raise a clear error if it gets the wrong combo. Oh and when it's handed a connection ID it should build a client configured with a single retry attempt so link generation fails fast instead of hanging around.
