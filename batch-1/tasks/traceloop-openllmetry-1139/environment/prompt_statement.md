I'm building out OpenTelemetry instrumentation for the Mistral AI client library, basically the same shape as the other AI provider instrumentation packages we already have in this repo. Right now there's just no way to auto-trace Mistral calls, chat completions or embeddings, and folks running these AI workloads in distributed systems can't observe, debug, or monitor them without hand-rolling spans. I want a new instrumentation package that wraps the client calls in spans automatically so developers get latency, token cost, input, and output visibility without touching their app code.

Here's what I need it to capture. For chat requests it should record the model used, the input prompt content, the generated response content, whether streaming was used, and token usage broken out as prompt tokens, completion tokens, and total tokens. When the response is streamed the span needs to collect all the streamed chunks and record the fully assembled response text, and it should reflect that streaming was actually used. For embeddings requests the span records the model, the input text (or just the first item if multiple inputs are passed), and flags that it was an embedding request.

Both streaming and non-streaming chat calls have to work, and it all needs to cover both the sync and async clients for chat as well as embeddings. Once the instrumentation is enabled it should just kick in for every Mistral request going through either client, no code changes on the caller side.
