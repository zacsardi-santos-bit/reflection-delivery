I'm poking at the obfuscation detection in our GitHub Actions security linter and hit two things that bug me. First, the diagnostics highlight way too much. Right now when a constant expression shows up inside a template placeholder, the reported span covers the whole thing including the surrounding delimiter characters, when really it should point at just the inner content that's obfuscated. So for a fully constant expression that can be swapped for a static value, I want the highlight to land on only the expression content, not the delimiters wrapping it, and the message should get shorter and more to the point. Same idea for an expression that contains a constant-reducible subexpression, the span should point directly at that subexpression rather than the entire enclosing expression, with a message that clearly says what can be reduced.

Second, there's a whole obfuscation case we just don't catch: when a dynamic, computed value gets used as an index key to look up data in an object or array. That hides what's actually being accessed at runtime and it's exactly the kind of thing security folks care about. I want this detected, but only in the strictest/most thorough analysis mode, and the finding should point at the index access bracket and the computed key and report that the index expression is computed rather than a literal.

Oh and for verifying this end to end, the test data should be a real GitHub Actions workflow that uses something like a collection accessed with a context-derived key so the new detection actually fires.
