I'm adding raw Kubernetes deployment support for inference graphs in KServe. Right now graphs only deploy in serverless mode which needs the whole serverless layer installed on the cluster, and teams running plain Kubernetes can't use inference graphs at all because of that. I want to fix that so it lines up with how inference services already do both raw and serverless.

Here's the gist: when an inference graph carries the annotation opting into raw deployment mode, the controller should detect that and create a standard Kubernetes Deployment and a Service (both named the same as the graph) instead of the serverless service and route resources. In raw mode it must not create any of those serverless service or route objects at all. The deployment gets one replica and a container running the router image with the serialized graph spec passed in as arguments.

I also need a few helpers to keep this clean. One builds the container pod spec, and it's gotta handle optional resource requirements (pull from the graph spec when set, otherwise fall back to the router config defaults) plus header propagation, so if the router config lists headers to propagate they get injected into the container as an env var with the header names joined comma-separated. Another helper constructs the Kubernetes object metadata for the deployment, preserving the graph's existing labels and annotations, always tacking on a standard inference-graph identification label, and making sure annotations are never nil. A third one propagates deployment readiness back onto the graph status, updating the ready condition and observed generation depending on whether the deployment reports an available condition.

Oh and the inference graph spec and CRD need four new scaling fields too, min replicas, max replicas, a scaling target, and a scaling metric that's one of cpu, memory, concurrency, or rps, and those should flow through into the metadata construction so they're usable for autoscaling.
