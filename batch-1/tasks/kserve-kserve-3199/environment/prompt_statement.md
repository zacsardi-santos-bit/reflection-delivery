I'm working on adding support for deploying inference graphs in raw Kubernetes mode. Right now, inference graphs can only be deployed using serverless infrastructure, but I need them to work on clusters that don't have that serverless layer installed.

When an inference graph is annotated to request raw deployment, the controller should create a standard Kubernetes Deployment and Service (with the same name as the graph) instead of serverless resources. It must not create any serverless service or route resources in this mode. The created deployment should have one replica and a container with the router image and the serialized graph specification passed as arguments.

I also need a few supporting functions to make this work cleanly. One function should build the container pod specification — it needs to handle optional resource requirements (using values from the graph spec when provided, falling back to router config defaults) and header propagation (if the router config specifies headers to propagate, they should be injected into the container as an environment variable with the header names comma-separated). Another function should construct the Kubernetes object metadata needed for the deployment: it should preserve the graph's existing labels and annotations, always add a standard inference-graph identification label, and ensure annotations are never nil. A third function should propagate deployment readiness back onto the inference graph status — updating the graph's ready condition and observed generation based on whether the deployment has an available condition.

Additionally, the inference graph spec and CRD need to support four new scaling fields: minimum replicas, maximum replicas, scaling target, and scaling metric (one of cpu, memory, concurrency, or rps). These should flow through into the metadata construction function so they can be used for autoscaling.
