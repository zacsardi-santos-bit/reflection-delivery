So we've got this task scheduling system that runs algorithm containers on a cluster, and I keep hitting a nasty silent failure. When the cluster rejects a job creation request because of a bad container config, like a sidecar whose resource requests exceed its declared limits, the error just gets swallowed. Pipeline nodes that depend on those algorithms never start and there's no message anywhere explaining why, so runs look like they're stalling forever with zero diagnostics.

What I want is for the code to actually detect when the job creation call comes back with a failure status code, capture that error instead of dropping it, and record it into the unscheduled algorithms tracking data with a proper failure reason and a user-friendly formatted message. The raw error coming out of the infra layer is ugly, it's got internal path expressions with numeric indexed container references (stuff like indexed lookups into the containers array) that mean nothing to an end user, so those need to be rewritten to use the actual container name, and while we're at it clean up the junk formatting artifacts like quoted numeric values. Oh and this failure should get flagged as one that's surpassed the scheduling timeout threshold, so the pipeline driver knows to immediately mark the affected nodes as failed rather than sitting there waiting.

There's also a naming thing that's bugging me. There's a boolean field in the scheduling warning objects that was named like it implied capacity checking, but what it really means is whether the scheduling timeout has been exceeded. I want that renamed consistently everywhere it shows up, including in the API specification so the surface actually reflects timeout behavior.

And finally, any scheduling failure with an invalid volume reference, or a job creation failure, should propagate its error message all the way down to the pipeline node so it gets marked failed with a descriptive message instead of being left in some ambiguous limbo state. Basically operators should be able to look at a stalled node and see exactly what went wrong.
