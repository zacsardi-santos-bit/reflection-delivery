I'm working on pd-ctl and the way it talks to the PD server is kind of a mess right now. The cluster subcommands just fire off raw HTTP calls that hand back untyped string blobs, and there's no actual structured client that gets initialized with server addresses and shared across commands, so when the tool exits there's nothing to cleanly close. I want to fix that properly.

First thing, the PD HTTP client interface needs typed methods for fetching cluster metadata (the cluster info) and cluster status, plus a data type representing cluster state that captures the initialization status, the replication status, and the bootstrap time. Right now none of that exists in typed form.

Then over in the command package I want a globally accessible exported client variable that any command or test code can reach, along with a setup function that takes a list of PD server addresses and initializes the client from them, and before it does that it should close out any previously existing client so we don't leak connections. Once that's in place the cluster subcommands should switch over to using this typed client to grab the cluster data and print it out as nicely formatted JSON instead of the raw string stuff.

Last piece, the test helper that runs pd-ctl commands needs to initialize this client using the server address that's passed in as an argument before it executes anything, and it should clean it up afterward with a deferred close. Without all this the integration tests for the cluster and ping operations fail, and honestly this also gives us a decent pattern for moving the other pd-ctl commands off raw HTTP onto the typed client later.
