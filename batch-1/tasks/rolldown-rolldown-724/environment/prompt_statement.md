I'm working on our bundler and I want to wire up source map support into the test fixture system so I can actually verify it. We already generate source maps in the output, but there's no way for a fixture to opt in, so nothing exercises it.

First thing, I want a plain boolean flag in the test fixture config that turns on source map generation for a given fixture. When a fixture flips that on, the build should emit source map files alongside chunk output, and each generated chunk should get the standard sourcemap URL comment appended at the end of the code, referencing the corresponding .map file by name. Right now there's no snapshot evidence of any of this so it's easy to regress silently.

Second, I need a sourcemap visualizer utility that takes generated code plus its source map and spits out a human-readable text representation of the token-level mappings. I want it grouped by original source file, with each file introduced by a labeled header line showing the source filename, then one line per token mapping. Each of those lines should show how a range of source text maps to a range in the generated output, including both the position coordinates (source and generated) and the actual text content of each segment, so I can read the snapshot and tell at a glance whether the mappings are right.

Then tie it together in the snapshots: when a fixture has source maps enabled, the test snapshot should include the sourcemap URL comment in the chunk code plus a dedicated section rendering that full token-level visualization, on top of the generated code. Oh and while I'm in there, fix the artifact snapshot rendering so the main code section only shows chunk outputs, not raw asset outputs (it's currently dumping both which is noise). This whole thing is really about being able to catch source map regressions and having an auditable record of how source maps through to generated output.
