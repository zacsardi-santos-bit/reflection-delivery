I'm working on a photonic layout tool and hit an annoying gap when I serialize component settings to YAML. The default waveguide cross-section isn't fully capturing its own config in the output. When I export settings the cross-section block just shows the function reference but it's missing the name identifier and the pin-drawing callback details that were set when the cross-section was actually defined. So the serialized cross-section is incomplete, you can see a cross-section function was used but not its name or how pins get drawn on it, which means you can't reconstruct the full cross-section from the saved YAML alone.

What I want is for the default waveguide cross-section to be defined with its name identifier and its pin-placement callback settings baked into the definition, so any component that uses it automatically serializes those details out. When any component's settings get serialized (regression snapshots, YAML netlists, whatever) the cross-section's name and pin config should show up and fully describe it so it's reconstructable from settings alone.

This matters because right now components look like they share the same cross-section even when they differ in pin config or name, so you can't tell cross-section variants apart from serialized settings, and it also throws off the component hash identifiers for anything whose cross-section was only partially captured. Oh and the regression snapshots for a bunch of components will need updating to reflect the more complete cross-section description.
