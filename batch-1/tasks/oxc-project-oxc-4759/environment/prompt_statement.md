I'm working with the oxc minifier crate and I need a plugin that can automatically inject import statements for globally-referenced identifiers. The idea is similar to how some bundler plugins let you map a global identifier name to an import source, and the tool automatically inserts the import declaration at the top of the file when it detects that identifier being used without a local binding.

I'd like the plugin to support injecting default imports, named imports, and namespace imports depending on configuration. It should also handle compound property access patterns — when a dotted identifier like a namespace property access is the target, it should generate a synthetic local variable, inject an import for it, and replace all usages of that expression in the code.

The plugin needs to be smart about when NOT to inject: if the identifier is already imported or declared locally, skip it. If it's shadowed by a local parameter or binding in the current scope, skip it. If the identifier appears in a position that isn't a value reference — such as an object property key, a class method name, or an export specifier — don't inject. Shorthand object property values should trigger injection, but shorthand destructuring binding keys should not. Default values used in parameter destructuring, however, are value references and should trigger injection.

When multiple configured patterns could match the same access (one being more specific than another), the more specific pattern should win. And if a module source string contains a single quote, the generated import declaration should use double quotes to avoid syntax errors.
