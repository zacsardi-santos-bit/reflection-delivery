I'm in the oxc minifier crate and I want to build a plugin that auto-injects import statements for globally-referenced identifiers, basically the same idea as Rollup's inject plugin where you map a global name to an import source and the tool prepends the import declaration at the top of the file the moment it sees that identifier used without a local binding. Right now the minifier has nothing like this and I keep hitting codebases that lean on a DOM helper or a Promise polyfill as bare globals, so I can't use oxc for them without manual workarounds.

I want it to handle default imports, named imports, and namespace imports depending on how each identifier is configured. It also needs to deal with compound property access, so when the target is a dotted thing like a namespace sub-property access, generate a synthetic local variable, inject an import for it, and swap out every usage of that expression in the code.

The tricky part is knowing when not to inject. If the identifier's already imported or declared locally, skip it. If it's shadowed by a local param or binding in the current scope, skip it in that scope. And if it shows up somewhere that isn't actually a value reference (an object property key, a class method name, an export specifier) leave it alone. Shorthand object property values should trigger injection, but shorthand destructuring binding keys shouldn't. Oh and default values in parameter destructuring do count as value references so those should inject.

Two more edge cases: when multiple configured patterns could match the same access, say a namespace and one of its sub-properties, the more specific one wins. Also if a module source string has a single quote in it, the generated import declaration needs to use double quotes so it doesn't blow up syntactically.
