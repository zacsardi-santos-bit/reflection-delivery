I'm building a Stan model where I do a bunch of preprocessing in the transformed data block, stuff like building my design matrix and munging the response vectors, and then I hand those off to GLM distribution calls (the generalized linear model likelihoods) over in the model block. When I compile this targeting the OpenCL GPU backend, the generated C++ doesn't use the GPU-accelerated representations for those transformed data variables, it just quietly falls back to the plain CPU versions. The annoying part is the exact same operations run on GPU fine if I declare the variables directly in the data block instead, so it's purely about which block they came from.

Looks like the compiler only promotes raw data block variables to their GPU-buffer equivalents and ignores anything defined or computed in transformed data. I want both handled the same way so I get GPU acceleration no matter where my matrices and vectors originate. Concretely, transformed data variables that are eligible (design matrices, response vectors, scalars) should get corresponding GPU buffer representations generated in the compiled model class, and those buffers should be initialized in the model constructor, and any GLM call receiving a transformed data design matrix or response should use the GPU-promoted version in the emitted OpenCL code. Oh and the standard non-GPU backend should keep using the transformed data variables directly like it does now, don't break that path. This preprocessing-in-transformed-data pattern is super common, so right now people silently lose acceleration and get mysteriously slow inference just because they factored their features out. Please fix the compiler so it treats transformed data consistently with data for GLM code gen.
